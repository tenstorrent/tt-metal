# Changelog: gated_delta_net

## Phase 0 — Core Implementation
- **Date**: 2026-11-15
- **What was done**: Initial implementation via incremental pipeline (planner -> implementer -> verifier). Regime R-STEP: one (sequence, value head) pair per work unit over the full grid, state resident per pair, one token per recurrence step, one `generic_op` dispatch per call.
- **SUPPORTED at Phase 0**: dtype=[float32], layout=[TILE], fp32_dest_acc_en=[True], alignment=[tile_aligned, h_non_aligned], sequence_mode=[decode, prefill, batched_prefill]
- **Accuracy achieved** (float32, 5 shapes, `test_gated_delta_net_precision_baseline.py`): output PCC >= 0.9999994, max_abs_err <= 1.5e-2, rel RMS <= 1.1e-3; recurrent_state_out PCC >= 0.9999992, max_abs_err <= 4.4e-3, rel RMS <= 1.5e-3
- **Golden suite at Phase 0**: 64 supported_pass, 35 xfail_expected (all bfloat16), 0 supported_fail / xpass_drift / xfail_wrong_mode (`verifier_report.json`)
- **Issues encountered** (verifier fixes): `batched_prefill` worked in the kernels but was refused by SUPPORTED (added); CB indices and spec constants restated in all three kernels (now host `GDN_*` defines); cb_conv_acc depth 2 -> 1; unused reader runtime arg removed; L1 ledger table and footprint brought in line with the build.
- **Tests added**: test_gated_delta_net.py (planner), test_gated_delta_net_precision_baseline.py, test_gated_delta_net_batched_prefill.py

## Refinement 1 — bfloat16 token tensors (lands the perf_decode_b1 contract)
- Date: 2026-11-15

## Refinement 2 — Cut the per-pair fixed cost of perf_decode_b1
- Date: 2026-11-15
- What was done: profiled per-core zones (compute 97 us = conv 37 + token step 20 + gates 16 + L2 12 + RMS 12; reader 39 us of window assembly and per-column barriers), then: (1) conv on the FPU for bf16 tokens: per column four `mul_tiles_bcast_rows` (srcB row index = tap) accumulated in one fp32 DEST tile, then silu in the same window; the reader loads raw conv_weight tiles (no 4x tap expansion, no cb_conv_acc); fp32 tokens keep the SFPU path (`CONV_ON_FPU = "auto"`). (2) Row scope: when a tile row's token rows sit in one 4-row band, the row-local SFPU ops (silu, gates chain, squares, rsqrt post-op, column/row broadcasts, binaries) run only on that band of both faces through the LLK bodies with ITERATIONS=2 or the LLK per-band broadcast bodies; rows outside the band are invalid rows that stay zero/finite. Squares moved from eltwise_chain to a raw DEST_AUTO_LIMIT-tile loop (the helper has no row scope). (3) alpha read once per token as a scalar (`read_tile_value`) for the state decay and the u term; the update batch fills DEST (4 tiles instead of 3). (4) `begin_loads` once per run of same-format CBs. (5) Reader: window assembled per uniform group of gcd(Kt, Vt) columns with one DRAM-read flush and one L1-shift flush per group; the writer zeroes cb_window once at kernel start (handshake CB cb_window_zeroed); the reader re-zeroes a slot only when its dirty rows are not covered; conv_state_out copy batches 10 columns per scratch tile. Knob kept off: DST_FULL_SYNC (slower).
- Reused: shared reader/compute/writer paths, CB plan, RowReader, existing helpers (matmul_block, reduce). Added: conv_block_fpu, RowScope + band helpers, cb_window_zeroed, CONV_ON_FPU / DST_FULL_SYNC / window-group knobs.
- Perf (device kernel ns, median of 3 launches): perf_decode_b1 101.6 -> 42.1 us; decode B=8 127.8 -> 87.3; B=16 264.5 -> 172.0; fp32 decode B=1 105.0 -> 62.6; bf16 prefill T=96 2150 -> 1714; batched B=2 T=40 1016 -> 833. Remaining: reader window ~10 us, then compute chain L2 7 + token step 12 + RMS 5 + state drain 2.6 us; next is R-VSPLIT (Refinement 3).
- Accuracy achieved: perf_decode_b1 output PCC 0.999999 / rel RMS 1.8e-3, state PCC 1.0000000 / rel RMS 1.7e-4; decode B=16 output 0.999998 / 1.8e-3, state 1.0000000 / 1.5e-4; prefill T=96 output 0.999998 / 1.9e-3, state 0.9999997 / 1.2e-3; fp32 decode output 1.000000 / 7.1e-4, state 1.0000000 / 1.8e-4.

## Refinement 3 — R-VSPLIT: spread each pair's state columns across cores for perf_decode_b1
- Date: 2026-11-15
- What was done: built regime R-VSPLIT. Work unit = (pair, piece), a piece owning `Vb = Vt / pieces` state columns; `_value_pieces` picks the largest divisor of Vt (<= MAX_PIECES = 4) with one unit per core (`V_BLOCK_TILES` forces it), else R-STEP (pieces = 1, unchanged schedule). Each piece runs the per-pair loop on its column slice (Kt x Vb state, Vb z / output / norm_weight columns, matmul block 2 x Vb) and re-preps the pair's q/k columns. M13 combine: compute reduces the piece's sum o^2 into cb_osum_part; the writer NoC-writes it into slot `piece` of cb_osum_gather on every piece core (same L1 address), bumps the peers' semaphore, waits for a cumulative count `rows * (pieces - 1)`; compute adds the slots in piece order before the rsqrt. Reader: weights and gate tiles read as aligned row spans in place (conv taps rows 0..3, rank-1 weights row 0, gate token rows), the weight/gate barriers folded into the first window group's flush, one window group per unit in R-VSPLIT (largest divisor <= 4 in R-STEP), conv_state history rows read as one aligned span per column (cb_hist_stage), cb_window zeroed slot by slot by the writer. Compute: FPU conv and kn transposes batched per DEST window. conv_state_out q/k columns copied by the first piece of the first head of each key head.
- Reused: the R-STEP reader / compute / writer and CB plan (Vt -> Vb), RowReader, reduce / matmul helpers. Added: `_value_pieces`, cb_osum_part / cb_osum_gather + one semaphore, cb_hist_stage, `read_row_span`, MAX_PIECES / WINDOW_GROUP_MAX_COLS knobs.
- Perf (device kernel ns, median of 3 launches): perf_decode_b1 42.1 -> 33.9 us (48 cores); decode B=8 87.3 -> 74.9; B=16 172.0 -> 150.4; fp32 decode B=1 62.6 -> 52.6; bf16 prefill T=96 1714 -> 589; batched B=2 T=40 833 -> 367. pieces = 2 measured slower than 4. Remaining (B=1): reader flush ~11 us bound by DRAM request rate (replicated q/k window reads), then conv 4.1 + L2 norm 8.2 + step 2.9 + RMS/combine 3.9 + drain 2.7 us; next lever is sharing the q/k prep across pieces / value heads (R-BCAST).
- Accuracy achieved: perf-test gates (output PCC >= 0.995 / rel RMS <= 0.04, state PCC >= 0.999 / rel RMS <= 0.01, conv_state_out bit-exact) hold on decode B=1/8/16 (bf16, fp32), prefill T=96, batched B=2 T=40, and on every forced split (vb 1 / 2 / auto) incl. inf padding.
- Golden test progress: targeted slice 62/62 (test_op_loose + decode B=1, B=3 small, 1x48-head decode, prefill cells); unit dir 81/81.
- Issues encountered: first build handed each core a block of `pieces` units (assert caught it). Staged row-granular weight reads were slower than whole tiles (reverted to unstaged aligned spans). A conv batch of DEST_AUTO_LIMIT columns could straddle the cb_window wrap; the batch is now a divisor of the window group.
- Tests added: test_gated_delta_net_vsplit.py (regime predicate; forced V_BLOCK_TILES 1 / 2 / auto on decode B=1 chip, prefill T=70 chip, batched B=2 small; clean and inf padding).

## Refinement 4 — Chunked recurrence for prefill (model_prefill_4096)
- Date: 2026-11-15
- What was done: built regime R-CHUNK. Multi-token calls on Blackhole (`_chunked`: T >= `CHUNK_MIN_TOKENS` = 2; decode keeps the token step) replace the token steps of every tile row by one closed-form chunk step (F1) on the same tile-row prep and resident fp32 state, on top of the R-STEP / R-VSPLIT work split. Per tile row: gates_block packs g instead of alpha; the writer writes g and beta of the pair into column 0 of two coefficient pages, exactly 0 on rows that are no token; compute builds c = cumsum(g) (`cumsum_tile`), c^T (`transpose_dest`, fp32), D = mask * exp(-relu(c[s'] - c[s])), exp(c), exp(c_last - c), beta exp(c); [Kn Kn^T; Qn Kn^T] via matmul_block; L and QD by fp32 SFPU products; U per column tile by `triangle_solve_tile` (fp32 forward substitution); O = exp(c) (*)col Rq + QD x U; S = exp(c_last) S (fp32 SFPU scalar, as in the token step) + Kn^T x (exp(c_last - c) (*)col U). The lower-triangular mask is built once by the reader (NoC zero + the 528 ones). Chunked builds run whole-tile SFPU scope (drops the row-band variants, which keeps the math thread inside the 70688 B kernel-config text budget). Reader: shifted conv taps are copied as row runs inside a face (6 L1 NoC copies per tap per column instead of one per row and half), and a tile row continuing its sequence stages the previous 3 mixed_qkv rows as one aligned span; a 1-row fast path keeps decode at parity.
- Reused: the tile-row prep (gates, conv, L2 norm, RMS norm), the state read matmul and the state update loop (factored out of token_step into read_state / update_state, shared by both steps), cb_tok_coef / cb_u / cb_u_f32 / cb_hist_stage, the R-VSPLIT o^2 combine. Added: chunk_vectors / chunk_step, cb_gram, cb_chunk_vec, cb_chunk_mat, cb_uw, cb_tri_mask, `copy_local_rows`, `CHUNK_MIN_TOKENS`.
- Perf (device kernel ns, 3 launches, one fresh run per variant): model_prefill_4096 (bf16, 48 cores) 22.94 ms at HEAD (89.6 ms on 12 cores before R-VSPLIT) -> 6.83 ms (R-CHUNK) -> 6.41 ms (reader row runs). Guard set: prefill T=96 589 -> 170 us, batched B=2 T=40 367 -> 230 us, decode B=8 74.9 -> 74.4, B=16 150.4 -> 148.3; perf_decode_b1 33.87 (R3 kernels, same session) vs 33.77-33.97 us now; fp32 decode B=1 52.8 vs 53.2 us (noise band).
- Where the time is now (prefill_t96 zones, per tile row per core): compute bound, about 50 us: gates 4, conv 13 (4 HiFi4 FPU taps + whole-tile SiLU on 9 column tiles), L2 norm ~11, chunk step ~16, RMS norm ~6; reader 14 us, writer 4.7 us, both off the critical path. The q/k conv and L2 norm (8 of 9 columns) are identical on the 12 cores of a key head (3 value heads x 4 pieces): sharing them (R-BCAST) is the next lever.
- Accuracy achieved: model_prefill_4096 (bf16) output PCC 0.999998 / rel RMS 1.9e-3, state PCC 0.9999997 / rel RMS 1.2e-3; state_carry_one_call_f32 (T=4096) output 0.999999 / 1.1e-3, state 0.9999997 / 8.7e-4 (gate 2e-3); chip prefill T=70 fp32 output 1.000000 / 8.5e-4, state 0.9999997 / 1.2e-3; conv_state_out bit-exact. A host emulation (tf32 matmul operands) predicted the chunk form at the token step's precision (state_carry state 5.7e-4 vs 5.6e-4).
- Golden test progress: targeted slice green: test_op_loose 14/14 (incl. model_prefill_4096, the three state-carry cases, prefill_then_decode), test_op prefill / batched_prefill cells (52 selected with the loose cases, all pass), test_regression.py 36/36; unit dir 123/123.
- Issues encountered: the chip-geometry chunked compute first overflowed the kernel-config text buffer by 3.9 KB (math thread); noinline wrappers made it larger (lost constant folding); dropping the band-scope variants in chunked builds fixed it. The margin is small: profiling zones fit only two compute zones.
- Tests added: test_gated_delta_net_chunk.py (chunk vs token step on T = 2, 5, 32, 33, 100, K > V, batched boundaries inside a tile row, Hv = 33, chip T = 70, clean and inf padding; state carried over three chunked calls and a decode call); model_prefill_4096 in test_gated_delta_net_perf.py.

## Refinement 5 — Decode B=1: remove the loopback copies and share the q/k preparation per key head
- Date: 2026-11-15
- What was done: built regime R-BCAST on decode R-VSPLIT (`_share_qk`: pieces > 1 and T = 1; knob `SHARE_QK_PREP`). Each (sequence, key head) group of r * pieces units sits on consecutive cores; unit 0 of the group (q injector) reads, convolves and L2-normalizes only the q columns, unit 1 (k injector) only k, every other core only its v column. Each injector packs qn / kn into cb_qk_stage and its writer multicasts the Kt fp32 tiles into cb_kq_rows of the whole group, itself included (two `ttnn.Mcast` channels, flag signal, no handshake: one hand-off per call into untouched CB slots at the same address everywhere). Every core then derives d = qn . kn (from a U2D alias of cb_kq_rows) and kn^T (`qk_finish_block`). The injector runs its q/k conv and L2 part before its v column. Loopback: the writer zeroes only the window groups its reader uses (147 KiB of self-addressed NoC reads per core -> 8 KiB on v-only cores, 40 KiB on injectors). Reader: every row span (conv taps, rank-1 weights, gate rows, history rows) is one DRAM request per 16-row band covering both face halves (was one per half), and a decode token row is read with one request per column into staging (was two staged half-row reads). R-BCAST builds compile the q/k path and band-only SFPU scope only (one token row per tile row), which keeps the fp32 48-head decode build inside the kernel-config text budget (math thread 32.9 -> 22.2 KB).
- Reused: R-VSPLIT work split, reader window / row-span machinery, l2_inverse_norm / row_sum / transpose of l2norm_block (split into kn_transpose_block), the conv blocks (now over a unit column range), the alias-pair CB pattern (cb_u / cb_u_f32). Added: `_share_qk`, two Mcast channels on the writer (`land_qk_rows`), cb_qk_stage, cb_kq_rows_f32 alias, qk_part_block / qk_finish_block, UnitCols, per-core window-zeroing RT args, compute CT arg QK_SHARED.
- Perf (device kernel ns, median of 3 launches, one fresh run per variant): perf_decode_b1 34.0 -> 25.7 us (steps: R-BCAST with one injector per key head 37.7 (slower: its serial 9-column read + conv + L2 + 3-round counter multicast gated every core); q/k split over two injectors 30.1; one request per row span + staged token row 27.8; flag-signal multicast, no local copy 26.7; injector v column after its part 26.2; final 25.7). Guard set: decode B=8 74.0 -> 62.9 us, B=16 148.4 -> 132.2 us, fp32 decode B=1 52.8 -> 34.4 us, prefill T=96 170 -> 168.5 us, batched B=2 T=40 230 -> 226.6 us, model_prefill_4096 6.41 -> 6.41 ms.
- Where the time is now (perf_decode_b1 zones, slowest core): injector reader to window push 6.8 us (DRAM round trips of ~25 small requests plus the per-row local copies), injector conv 2.2 + L2 part 3.2 us, multicast hand-off 1.3 to 2.9 us, d + kn^T on every core 2.3 us, token step ~3 + RMS norm with the o^2 combine ~4 us, output / state writes ~1.5 us. v-only cores idle ~10 us waiting for the hand-off.
- Accuracy achieved: shared and unshared q/k prep bit-identical (all three outputs). perf_decode_b1 output PCC 0.9999985 / rel RMS 1.81e-3, state PCC 1.0000000 / rel RMS 1.65e-4; fp32 decode B=1 output 0.9999998 / 7.1e-4, state 1.0000000 / 1.8e-4; decode B=8 output 0.9999985 / 1.75e-3, state 1.0000000 / 1.6e-4; conv_state_out bit-exact.
- Golden test progress: test_golden.py 72/72 (all test_op cells + 14 LOOSE_CASES), test_regression.py 36/36; unit dir 132/132.
- Issues encountered: the first build overflowed the kernel-config text budget (math thread +12 KB from a second q/k path); fixed by making the shared role compile-time (QK_SHARED) and, for R-BCAST builds, band-only row scope. A counter-signal multicast waited a write barrier per rectangle (3 rounds took 6.3 us); one flag-signal round per channel takes ~1.3 us.
- Tests added: test_gated_delta_net_bcast.py (predicate; shared vs unshared bit-identical on chip B=1 / B=2 bf16, 48-head fp32, Hv = Hk fp32; clean and inf padding).

## Refinement 6 — Prefill: take the per-row preparation off the ordered path
- Date: 2026-11-15
- What was done: built regime R-PREP on chunked R-VSPLIT (`_prep_layout`). The cores R-VSPLIT leaves idle become prep cores: per (sequence, key head) group up to `MAX_PREP_CORES_PER_GROUP` of them (groups take idle cores in turn, nearest first) take the group's tile rows round robin. A prep core reads the gate, window and z inputs of its rows and runs gates, conv, L2 norm, [Kn Kn^T; Qn Kn^T] once per key head, then per value head the chunk vectors, L, M = (I + L)^-1 (the fp32 SFPU solve on an identity tile, `cb_tri_mask` page 1), and folds the row scalings into the operands, packing one head block [beta exp(c) (*) kn, exp(c) (*) qn | kn^T (*) exp(c_last - c)^T | M, QD | exp(c) | beta (*) v]. Its writer multicasts each head block into inbox slot i % D of the head's pieces (row runs of consecutive cores in virtual coordinates, unicast for a one-core run), unicasts each piece its v columns, then bumps the slot's landed counter. Before that, every state core of the group must have granted the slot. A state core's reader grants each slot as soon as compute frees it (up to D rows ahead, a cumulative grant count per prep core) and hands landed rows to compute. The state compute (`chunk_state_prepped`) is R = [kq] x S, U = M (beta V - R0) (a matmul instead of the 5 us solve), O = R1 + QD x U, S = exp(c_last) S + kn^T' x U, with no broadcasts. It sends o back to the row's prep core, which runs the RMS norm one row later and writes the output. Prep and state run as separate kernel builds (ROLE CT arg: separate binaries per role, inside the kernel-config text budget). Buffers written by other cores are allocated first on every core; all others exist only on their role. Pieces are capped at `PREP_MAX_PIECES` = 2 under R-PREP, and short calls (< `PREP_MIN_TILE_ROWS` = 4 tile rows per sequence) keep the local chunk step.
- Reused: the reader's window / row-span machinery (strided tile rows, prep unit = key head with r Vt v columns), gates_block, conv blocks, l2norm_block, kn_transpose_block, the chunk-vector code (chunk_vectors split into gram_block / head_prep), read_state / update_state (now templated on the kq / knT buffers), rmsnorm_gate_block (generalized to r heads), the writer's coefficient expansion (push_chunk_coefs) and row store (store_rows). Added: ROLE CT arg and prep_main / state_main / prep_writer / head_block / chunk_state_prepped, cb_prep_send, cb_o_in, cb_in_kq / knt / mat / vec / v, cb_v_prep, the identity page, landed / grant / o-landed semaphores, `_prep_layout`, `_prep_cb_plan`, `_mcast_rects`, knobs PREP_OFFLOAD, MAX_PREP_CORES_PER_GROUP, PREP_SEND_NOC_1, PREP_MAX_PIECES, PREP_MIN_TILE_ROWS, INBOX_DEPTH, O_IN_DEPTH, O_ACC_DEPTH, PREP_SEND_HEADS.
- Perf (device kernel ns, one fresh run of 3 launches per variant): model_prefill_4096 6.41 ms (48 cores) -> 2.27 ms (R-PREP, state core still ran the RMS norm) -> 1.68 ms (RMS norm on the prep core, grant ahead: the first build granted one row at a time) -> 1.47-1.56 ms (multicast head data) -> 1.47 ms (M = (I + L)^-1 on the prep core: state step 8.1 -> 4.75 us, but prep-bound at 4 pieces) -> 1.27-1.31 ms (2 pieces: 84 prep cores, sends 27 -> 8.5 us) -> 1.06-1.13 ms on 108 cores (prescaled head blocks: 2-piece state step 8.1 -> 5.3 us; per-role buffers and inbox depth 8; groups take idle cores in turn; unicast for one-core runs). Measured null and kept as knobs: prep writer on NOC 0 vs NOC 1 (same), nearest-first vs strided prep placement (same), 4 pieces (1.34 vs 1.18 ms). Guard set: perf_decode_b1 25.7 -> 26.0 us (noise band), decode B=8 62.9 -> 63.1, B=16 132.2 -> 132.6, fp32 decode B=1 34.4 -> 33.9, prefill T=96 168.5 -> 169.1, batched B=2 T=40 226.6 -> 221.
- Where the time is now (model_prefill_4096 zones): state step 5.3 us per tile row (read 1.1, rhs + M x rhs, O, update) x 128 = 0.68 ms; pipeline fill ~120 us (a prep core's first tile row: gates 10, conv 29, L2 + gram 11, 3 x (head prep 7 + head block 10) us, plus its window reads); the rest is inbox waits. Two of the four key-head groups wait on late rows (prep writer send p50 9 us, p90 40-50 us, max ~140 us against 8 x 5.3 us of inbox slack), so their state cores end 150-250 us after the others.
- Accuracy achieved: model_prefill_4096 (bf16) output PCC 0.9999981 / rel RMS 2.0e-3, state PCC 0.9999994 / rel RMS 2.1e-3, conv_state_out bit-exact; (1,4096,640)/(1,3,128,128) bf16 output 0.9999979 / 2.1e-3, state 2.3e-3; small-geometry fp32 T=2048 output 1.4e-3, state 2.0e-3. State-carry generator (bf16, gate 0.002): R-PREP state rel RMS 1.09e-3 / 1.06e-3 (512 + 256 calls), 1.42e-3 (one call of 4096) vs 0.65e-3 / 0.63e-3 / 0.85e-3 on the local chunk step. The extra error is the 19-bit matmul operands (M x rhs and the prescaled kq / knT) that replace the fp32 solve; the carried state and exp(g) stay fp32 at every chunk boundary.
- Golden test progress: test_golden.py 72/72 (all test_op cells + 14 LOOSE_CASES incl. model_prefill_4096, state_carry_bf16, state_carry_one_call_f32), test_regression.py 36/36; unit dir 154/154.
- Issues encountered: the merged all-cores CB plan hid a role-list slip (prep-local buffers listed as state-only), which hung as soon as buffers became per role; the shared startup CBs had to become per role too. The state reader first waited for each row's landing before granting the next (one grant outstanding, so depth did nothing). pack_tile indices are relative to the reservation (the transposed decay vector landed outside its slot). A one-sequence call with 256 tile rows gave 104 prep cores, overflowing the 64-entry producer table and hanging the golden 1x8192 cell; MAX_PREP_CORES_PER_GROUP = 32 is now one host constant shared with the kernels. Short calls ran slower under R-PREP (prefill T=96 177-190 vs 168 us) until PREP_MIN_TILE_ROWS.
- Tests added: test_gated_delta_net_prep.py (predicate; forced R-PREP vs local on T = 2, 33, 200, batched B=2 T=33, chip T=70 fp32 (local), clean and inf padding; state carried over two R-PREP calls and a decode call).

## Refinement 7 — Decode B=8 and B=16: the input side at a full grid
- Date: 2026-11-15
- What was done: built regime R-QKCORE on decode R-STEP (`_qk_core_units`: T = 1, pieces = 1, B <= 32, 2 Hk idle cores; knob `SHARE_QK_CORES`). Per key head a q core and a k core read the key head's q (k) current-row and conv_state tiles whole, gather the window rows (tap 3 row p = x[p], tap j row p = conv_state[3p + j]) split between their reader and writer with stateful 32 B local NoC copies, hand each column to compute as soon as it is gathered, convolve and L2-normalize rows 0..B-1 at once (multi-band SFPU row scope, q / k cores only) and multicast qn (kn) to the key head's pair cores (`ttnn.Mcast`, explicit sender outside the group, flag signal). Pair cores take consecutive sequences of one value head (unit stride Hv), read and convolve only their v columns, receive the q/k rows once and re-push them for later units. After their send the q / k cores write all of conv_state_out as whole tiles (rows shifted in L1); the pair cores no longer copy it row by row (~19k tiny DRAM transactions at B=16). Multi-unit cores (B=16): per-unit inputs double-buffered (`UNIT_INPUT_DEPTH`, S0 / weights / gates), a same-head next unit copies the head's weights and the decode gate tile from the previous slot instead of re-reading page 0 of each small tensor (one DRAM bank), the reader reads every unit's inputs before any conv_state_out copy, the writer defers a unit's last barrier / pops to the next unit's store point and issues a non-last unit's state only after the next unit's coefficients and q/k rows (STATE_OUT_DEPTH 2). The last unit's state is issued before its output rows (overlaps the RMS norm).
