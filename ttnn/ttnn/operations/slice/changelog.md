# Changelog: slice

## Phase 0 — Core Implementation
- **Date**: 2026-11-21
- **What was done**: Initial implementation via incremental pipeline (planner → implementer → verifier). Regime `page_relay`: whole interleaved pages relayed through one DM→DM DFB ring per cluster over the full 8×4 grid, page map on the reader, contiguous output pages on the writer, one `ttnn.generic_op` (Metal 2.0 `ProgramSpec`) dispatch; implicit sync for pages ≤ 8 KiB, explicit block-batched sync above (implementer). Thread plan (R, W) = (1, 1), no compute kernel.
- **SUPPORTED at Phase 0**: dtype=[bfloat16], layout=[TILE, ROW_MAJOR], memory_config=[DRAM, L1], sharding=[interleaved], sliced_region=[outer, h], start_alignment=[tile_aligned], alignment=[tile_aligned, w_non_aligned, h_non_aligned], rank=[3]
- **Accuracy achieved**: bit-exact — PCC=1.000, max_abs_err=0.0, rms_err=0.0, got/true ratio ≡ 1 (measured on 5 shapes via test_slice_precision_baseline.py, incl. the explicit-sync path)
- **Golden suite at Phase 0**: 69 / 69 supported cells passing (68 PHASE0 + loose `bounds_as_lists`), 412 xfail_expected, 3 / 3 rejections, 0 loud (per `verifier_report.json`)
- **Issues encountered**: implementer — explicit sync for pages > 8 KiB (one NoC overlay packet). Verifier — no drift; DRY fix of the ring accessor name; added a session-order test after the explicit-sync path; recorded the 8 KiB cap and the implicit-sync txn-id batching rule (batch = half an even ring regardless of `RING_DEPTH_BLOCKS`) in `op_design.md`; ledger audit appended.
- **Tests added**: test_slice.py (generated acceptance), test_slice_plan.py (thread plan, session order, R7), test_slice_precision_baseline.py

## Refinement 1 — Row cuts: `rm_column_cut` + tile-layout W narrowing
- Date: 2026-11-21
- What was done: `"w"` added to `SUPPORTED["sliced_region"]` (both layouts, DRAM and L1; no EXCLUSIONS). TILE `w` from a tile boundary is validate-only: the page map already walks the W tile axis. ROW_MAJOR `w` builds the `rm_column_cut` regime by reusing the Phase 0 explicit-sync ring path. The host selects the regime with `regime_for` (the design's predicate). The ring entry is the output's aligned row slot, and two new common runtime args, `src_offset_bytes = w_start·e` and `transfer_bytes = W_out·e`, set every explicit-sync transfer: the reader reads the row's byte range straight from its byte offset (TensorAccessor `offset_bytes`), and the writer writes the same bytes to the output row. For `page_relay` the args are `0` and `entry_bytes`, so that path is byte-identical. The full-grid `out_page` split, the block batching (one reserve/push and one barrier per block per hart on both halves) and the thread plan (1, 1) are unchanged; explicit sync still needs R == W. Reused: page map, split, ring, explicit-sync loop of both kernels. Added: `regime_for`, `row_transfer`, 2 runtime args.
- No writer realign and no aligned-superset read: the Quasar NoC shifts data between differently aligned source and destination (`quasar/noc/noc_parameters.h:482-491`, all NoC L1/DRAM alignments 1 B). Measured bit-exact on ttsim at byte offsets 6, 14 and 34 B (not multiples of 16) with 64-, 66-, 2,000- and 16,794-B rows, DRAM and L1, plans (1,1) and (2,2). So the kernel already takes any `w_start`, as Refinement 2 needs. If silicon disagrees, the fallback is the design's first plan (16-B-aligned superset read plus a writer-hart realign).
- Data movement: the column cut reads and writes exactly `W_out·e` bytes per row, the minimum.
- Accuracy achieved: bit-exact (PCC=1.0, relative RMS=0.0) on [1,32,128] W 0–64 and 64–128, [4,128,512] (0,32,96)–(4,96,352), [1,32,4096] W 1024–3072, TILE and RM, DRAM and L1; also on the unaligned row cuts above.
- Golden test progress: 16/16 Refinement 1 cells (bf16, rank 3, `w`, `tile_aligned`) pass, plus 4/4 prior `h` cells on the shared paths (targeted slice; the harness's full run is the record).
- Issues encountered: None.
- Tests added: `test_slice_plan.py`: `test_w_narrowed_regime` (regime pin: TILE-`w` → `page_relay`, RM-`w` → `rm_column_cut`, per placement); `test_rm_column_cut_any_byte_offset` (4 unaligned row cuts × DRAM/L1 × (1,1)/(2,2), through `_dispatch`); `test_rm_column_cut_between_tt_metal_programs` (session order: untilize → slice → tilize → untilize); and two W-narrowed cases added to `test_every_thread_runs` (unequal plans expect the R == W refusal). Probe: `probes/probe_006.py`.

## Refinement 1b — Row cuts: `rm_column_cut` + tile-layout W narrowing (debug: fix gate violations)
- Date: 2026-11-21
- What was done: the gate's "85/169 responsible cells" was the `step` axis, not the kernels. The specification's stub gained `slice_step=None` (axis `step`, R9) after Phase 0; the entry point still took three arguments and `SUPPORTED` had no `step` key, so every `step=ones` cell counted as supported and failed with `TypeError: slice() takes 3 positional arguments but 4 were given` (84 cells; the 492 unsupported cells likewise failed in the wrong mode). Fix in `slice.py` only: the signature equals the stub, validate() derives the `step` axis with the specification's own `canonical_step` (imported, not copied) and refuses a malformed step with ValueError, and `SUPPORTED["step"] = [None]`, matching PHASE0. `"ones"` is Refinement 10's and is refused by name (NotImplementedError). No kernel or host-program change. Reused: validate()'s per-axis gate. Added: the `step` axis and parameter.
- Accuracy achieved: bit-exact (PCC=1.0, relative RMS=0.0) on every supported cell, unchanged.
- Golden test progress: full suite 88 passed / 0 failed / 0 hangs of 1156 (1068 xfail); `verify_supported`: supported 85/85 pass, 0 supported_fail, 0 xfail_wrong_mode, 0 xpass_drift. Unit directory 126/126.
- Issues encountered: the earlier Refinement 1 attempt ran only a `-k` slice with `step=None`, which hid the signature gap.
- Tests added: `test_slice_plan.py::test_slice_step_argument` (fourth positional `None` works; a non-unit step is refused by name).

## Refinement 10 — Rank 4 and the `slice_step` argument (Llama, Qwen, ResNet-50)
- Date: 2026-11-21
- What was done: `4` added to `SUPPORTED["rank"]` and `"ones"` to `SUPPORTED["step"]` (bfloat16, TILE and ROW_MAJOR, DRAM and L1, every `sliced_region` — `outer`, `h`, `w` — and `start_alignment=tile_aligned`, as SUPPORTED has after Refinement 1). Validate-only: no kernel, host-program or regime change. The entry point's signature already equalled the stub (Refinement 1b); validate() already derived `step` with the specification's `canonical_step`, so a step of 1 in every dimension is the same block and any other step reads as `"other"` and is refused by name (NotImplementedError). Reused: the 4-D page map (rank left-padded with 1s), both regimes (`page_relay`, `rm_column_cut`), validate()'s per-axis gate. Added: two SUPPORTED values, one test.
- Probe (operator's request, `probes/probe_007.py`): with the gate bypassed (`_dispatch`), every rank-4 `tile_aligned` INPUTS entry (15 entries, including the eight Llama / Qwen / ResNet-50 calls) × TILE/ROW_MAJOR × DRAM/L1 = 60/60 bit-exact on the Phase 0 + Refinement 1 kernels. The page walk does not care about the rank: N and C fold into the page map's two leading axes. ResNet-50's row-major unpaddings take `rm_column_cut` (W narrowed; `[1,1,64,64]` → `[1,1,30,62]` narrows H as well, through the same page map); Llama's head cut and Qwen's tile-row are `page_relay`.
- Accuracy achieved: bit-exact (PCC=1.0, relative RMS=0.0) on every rank-4 / `step=ones` cell, including [8,8,32,64] heads 0–7, [1,32,1,64], [1,1,128,512] rows 64–96, [1,1,1,128], [1,1,32,1024] and [1,1,64,1024] to 1000 columns, [1,1,64,64] to [1,1,30,62].
- Golden test progress: 204/204 targeted cells pass (bfloat16, rank 3 or 4, `tile_aligned`, with `rank=4` or `step=ones`; both layouts, DRAM and L1). Neighbour check: rank-4 `non_tile_aligned`, float32 rank-4 `step=ones` and rank-2 `step=ones` cells still xfail by name; 4 prior rank-3 cells pass. Unit directory 128/128.
- Issues encountered: None.
- Tests added: `test_slice_plan.py::test_model_calls` (DRAM and L1): Llama's head cut over all eight heads of an [8,8,32,64] TILE KV cache in one session, Qwen's tile-row and whole-tensor call, Llama's per-user call, ResNet-50's two row-major unpaddings; two calls pass `slice_step=[1, 1, 1, 1]` positionally.
