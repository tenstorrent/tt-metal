bank_coalesced_txn -- isolated DM bake-off, raw measurements
Box: Blackhole p150b, 11x10 = 110-core compute grid, reference AICLK 1350 MHz.
NB (DRAM banks) = 8, read from the device: dram_grid_size() = 8x1, and the kernel build
defines NUM_DRAM_BANKS=8 / LOG_BASE_2_OF_NUM_DRAM_BANKS=3 (power of two).
Metric: DEVICE KERNEL DURATION [ns].  bf16 TILE, DRAM interleaved in and out.
Every payload-carrying variant is gated BITWISE EXACT (out == in) -- the coalesced
reader's bank-major permutation and the coalesced writer's inverse compose to identity.

Reproduce:
  BC_ARGS="<group> <case> ..." [BC_REPS=3] scripts/tt-probe.sh rms_norm_ttnn < run_bank_bench.py
  groups: sweep | halves | domain | stagger | stagger_halves

VARIANTS
  base            MODE 0: one noc_async_read_tile / noc_async_write_tile per tile.
                  == the op's stage_tile_rows / write_block TILE branch.  WT_CHUNK txn/row.
  coal<PPT>[_rot] MODE 1: bank-major.  Residue class j of the run is `cnt_j = Q + (j<REM)`
                  CONSECUTIVE pages inside bank (tile_base+j)%NB; issued as ceil(cnt_j/PPT)
                  transactions of <= PPT pages.  PPT=1 is the ORDER-ONLY control (same txn
                  count as base, permuted L1).  PPT=0/8 = the whole run.  `_rot` rotates the
                  start bank by (core index % NB).  txn/row = NB * ceil(Q/PPT).
  stag            MODE 2: baseline transactions AND baseline (unpermuted) L1 -- only the
                  ISSUE ORDER rotates by (core index % NB).  WT_CHUNK txn/row.
  *_r / *_w       the same program with the WRITE / READ payload ablated (handshakes,
                  barriers and trip counts all kept).  Perf only, never a candidate.
  floor           both payloads ablated.

================ CONCLUSION ================
The coalesce is a REGRESSION on every bandwidth-saturated shape (all the prefill shapes,
including the focus shape) and a WIN only where a single core owns a long run of consecutive
tile ids AND the DRAM is far from saturated (1,1,32,1024): 1.20x, saturating at PPT=2.
Those two conditions are mutually exclusive in this op: a core only gets WT_CHUNK >> NB when
the tensor is large enough for `scheme=rows` to hand it a whole tile-row, and that is exactly
the regime where the DRAM is the constraint.  Coalescing needs WT_CHUNK > NB to exist at all
(WT_CHUNK <= NB gives Q = 0, i.e. every "run" is one page and the transformation is a no-op).
