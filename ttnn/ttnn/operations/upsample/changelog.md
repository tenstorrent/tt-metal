# Changelog: upsample

## Phase 0 — Core Implementation
- **Date**: 2026-11-21
- **What was done**: Initial implementation via incremental pipeline (planner → implementer → verifier). Regime `stick_stream`: one `ttnn.generic_op` (Metal 2.0 `ProgramSpec`, Quasar) with a reader and a writer and no compute kernel; input sticks split over the full grid, each read once into a STRIDED DM→DM ring and written `sh·sw` times. Thread plan (R, C, W) = (2, 0, 4).
- **SUPPORTED at Phase 0**: dtype=[bfloat16], layout=[ROW_MAJOR], memory_config=[DRAM, L1], sharding=[interleaved], mode=[nearest], channel_alignment=[tile_aligned], scale=[uniform] (= the specification's PHASE0)
- **Accuracy achieved**: bit-exact — PCC=1.0, max_abs_err=0.0, rms_err=0.0 (measured on 4 shapes via test_upsample_precision_baseline.py, incl. the YOLOv8 calls `[1,20,20,512]` and `[1,40,40,512]` by (2,2))
- **Golden suite at Phase 0**: 26 / 26 supported cells passing; 142 xfail_expected, 84 invalid_skipped, 0 supported_fail / xpass_drift / xfail_wrong_mode (per `verifier_report.json`)
- **Issues encountered**: no drift. Verifier added the missing R6 test (sharded input refused by name) and the DRAM half of R5. Verifier probe (`probes/probe_002.py`) showed float32, non-aligned C and per-axis factors already bit-exact on the RM path with the gate bypassed — SUPPORTED left at PHASE0, queued as Refinement 2.
- **Tests added**: test_upsample.py (harness acceptance), test_upsample_threads.py (thread plan, session order, regime predicate, R2, R5-L1), test_upsample_placement.py (R5-DRAM, R6), test_upsample_precision_baseline.py
- **Structural perf baseline** (for Refinement 3, `[1,40,40,512]` (2,2), no clock on ttsim): 50 sticks/cluster, `block_sticks` = 7, 8 blocks (last 1); max output pages per writer thread per cluster = 56 (writer threads 14/14/14/8 sticks); sticks read before a cluster's first write = 7; 1 input read per stick, 1 write per output page.

## Refinement 0 — The `memory_config` argument and a height-sharded input (the YOLOv8 sharded upsample)
- Date: 2026-11-21
- What was done: The entry point gains the keyword-only `memory_config=None` (signature = the spec stub; `eval.validate_contract upsample` clean). `validate()` derives the `memory_argument` axis with the specification's own `canonical_memory` (None / "input" / "other"; "other" refused by name, R7). SUPPORTED gains `sharding: "height"` and `memory_argument: [None, "input"]`. New `output_memory_config()` places the result by R5: an interleaved input's own config, or for a height-sharded input height-sharded in L1 over the input's shard grid and orientation with shard shape `[shard_h * sh * sw, C]`. Kernels and program artifacts unchanged: the `stick_stream` reader/writer reach the sharded input and output through `TensorAccessor`, which resolves sharded page addresses (probe 5 shapes/grids, all bit-exact). Reused: the whole `stick_stream` data path, split, ring and thread plan. Added: the gate values, the output memory config, the keyword.
- Accuracy achieved: bit-exact (PCC=1.0, relative RMS=0) on [1,4,4,64] (2,2) over 2 and 16 cores, [1,20,20,512] (2,2) over 25 cores, [2,8,8,128] x3 over 32 cores, [1,16,16,32] x1, and every golden cell of the slice.
- Golden test progress: 70/70 of the slice (all 42 L1 cells with `sharding=height` or `memory_argument=input` at the Phase 0 values of the other axes, and all 28 Phase 0 DRAM cells with `memory_argument` None/input); a sample of 10 unsupported sharded/`input` cells xfails or skips as expected.
- Issues encountered: None. Finding (not in scope, per the operator's notes): the sharded path still moves data through the NoC over the full grid like the interleaved one — each core's input shard is not consumed in place. The design's deferred `sharded_in_place` regime (ring borrowed from the shard, output shard written locally, zero input NoC traffic) is the performance refinement that would close it.
- Tests added: test_upsample_placement.py — `test_model_sharded_call` (the model's call with and without `memory_config=x.memory_config()`: values, and result height-sharded in L1 over the input's two cores, shard [32, 64]), `test_other_memory_config_refused_by_name` (R7), `test_width_sharded_input_refused_by_name` (R6; replaces the Phase 0 "height-sharded refused" test).
