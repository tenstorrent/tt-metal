# Verification Report: rms_norm

Phase 0 verification of `ttnn.operations.rms_norm` (registry model). Device: Blackhole p150b, 13 × 10 compute grid (130 cores). All tests run through `scripts/run_safe_pytest.sh --dev` / `eval/eval_test_runner.sh`.

## Code Review

Everything below was **fixed in code** during this pass; nothing was left as a suggestion unless marked *advisory*.

1. **Ragged (padded) last WIDTH shard was refused** — `derive_blocking()` required `len(shard_cores) * shard_w_tiles == Wt`, so any `WIDTH_SHARDED` input whose grid does not divide W (the eval harness's `auto_shard_config(Split.PAD)` for `W = 11008` → 115 cores × 3 tiles = 345 > 344; the production corpus's `W = 96` over 2 × 64 and `W = 224` over 3 × 96) raised `ValueError` inside a claimed-supported cell. Fixed natively: the host now accepts exactly one ragged last shard (`(n − 1)·Ws < Wt ≤ n·Ws`), gives the last core `core_w_tiles = Wt − i·Ws` (it gets its own compute build through the existing per-`core_w_tiles` kernel grouping), and the R3 compute path walks the resident shard with `TileOffset::Strided` (`StridedTileRange{block_idx·B·Ws, Ws}`) over `rows × core_w_tiles` valid tiles instead of a contiguous `TileOffset::Set` walk — so the padded columns never enter Σx² and are never written. Reader publish / compute reserve / final push count `Rt · Ws` (the shard) instead of `Rt · Wc`. New named CT `SHARD_W_TILES`. Regime-pinned test: `tests/ttnn/unit_tests/operations/rms_norm/test_rms_norm_ragged_width_shard.py` (poisoned padding, logical-width reference; 6 cells incl. the 115-core non-rectangular bbox with passive cores). This turned 4 `test_translated.py` `supported_fail` cells green and pre-empts the ~50 `_RESILIENCE_SHAPES` sharded cells that Refinement 1 unlocks.
2. **DRY: writer argument bases were restated literals** — `MCAST_RT_BASE = 15` duplicated the writer's RT-list length, `[0] * 6` / `[0] * 4` duplicated the `McastArgs` CT/RT block sizes, and the kernel hard-coded `TensorAccessorArgs<mcast_ct_base + 6>`. Now `mcast_rt_base = len(op_rt)` is derived from the list actually built, `MCAST_CT_ARGS` / `MCAST_RT_ARGS` are asserted against the real `Mcast2D` helper whenever one exists, and the kernel chains the accessor off `McastArgs::next_compile_time_args_offset()`. Adding an RT arg can no longer silently shift the mcast decoder.
3. **`alignment` axis added to the registry** (`INPUT_TAGGERS["alignment"]`, `SUPPORTED["alignment"] = ["tile_aligned"]`). The kernel gates on tile alignment (there is no edge-tile mask/pad path), but the gate was a `ValueError` in `_shape_errors`, invisible to the registry. Registry conformance says every axis the kernel gates on appears in SUPPORTED; the golden harness's own conftest expects exactly this pattern (shape-derived refusals surface as a typed `SupportRefusal`, converted to a lenient xfail for translated tests). Effect: the 28 non-tile-aligned `test_translated.py` cells (H = 24, W = 42, rank-2 `(1, 4096)`) moved from `supported_fail` / `xfail_wrong_mode` to `xfail_expected`. `rank < 2` and gamma-shape errors remain `ValueError` per the prompt contract (acceptance tests match on "rank" / "gamma"). Note for the feature-spec owner: `alignment` is not in `TARGET` — see Recommendations.
4. **Design doc corrected where the implementation had already (correctly) diverged**: `op_design.md` still sized `cb_gather` and the combine extent by `num_w_splits` (the multicast rectangle) — the implementer's root-caused fix uses `num_partials` (active W slices; summing rectangle-sized slots read never-written L1 on non-rectangular shard grids). Patched the `w_split` axis row, the mechanism-cap row, the CB table row and the API-mapping call, and added the ragged-shard mechanism cap. `l1_ledger.md` updated for `Ws = shard_w_tiles` (R3 capacities, symbol table, total).

*Advisory (not defects)*: the reader's RM path uses `read_sticks_for_tilize<TILE>` (one barrier per 32 sticks) where the design wrote `ROW` granularity (one per stick) — strictly better, documented in the reader header. RM gamma's rows 1..31 are zeroed by the DM engine (`noc.async_write_zeros`) instead of a RISC store loop — also better. Both are the implementer's realization choices, inside the scope boundary.

### Helper usage
- Compute: `sum_of_squares` (A), `reduce<…ReduceTile>` (B), `reduce<…AccumulateViaAdd, Skip>` with the fused `·1/W, +ε, rsqrt` post-op (C), `mul<BroadcastDim::Col>` (D), `mul<BroadcastDim::Row>` (E), `tilize` / `untilize` for RM legs — one helper call per phase per block, `compute_kernel_hw_startup` exactly once. R3 uses `eltwise_chain` directly for the strided in-shard walk (the convenience wrappers cannot express `TileOffset::Strided`) — a legitimate realization choice.
- Dataflow: `calculate_and_prepare_reduce_scaler`, `read_sticks_for_tilize` / `write_sticks_after_untilize`, `mcast_pipe` `SenderPipe`/`ReceiverPipe` via `McastArgs` + host `ttnn.Mcast2D` for the rstd broadcast. The many-to-one partial gather is raw `noc_async_write` + counting semaphore — the design's "helpers considered and rejected" entry is correct (`mcast_pipe` is a one-to-rectangle broadcast; the rotating-sender all-gather is regime R6's traffic).
- Correctness checklist: CB push/wait counts match per CB per block (incl. the `rows`/`rows·Np` ragged-tail counts and the R3 `Rt·Ws` publish); `TensorAccessor` everywhere (no `InterleavedAddrGen`); `void kernel_main()`; `api/dataflow/dataflow_api.h` includes; broadcast dims verified (rstd is a REDUCE_ROW column → `Col`; gamma is a `[1, W]` row → `Row`); no redundant full-tile fills (the scaler is one tile, gamma is resident once).

## Registry Conformance
- Confirmed: `INPUT_TAGGERS` (`rank`, `alignment`; both `(inputs, axes)`), `SUPPORTED` (every gated axis: dtype, fp32_dest_acc_en, layout, rank, alignment, gamma_mode, gamma_dtype, gamma_layout, memory_layout), `EXCLUSIONS` (`{float32, fp32_dest_acc_en=False}` — permanent by the precision convention), `validate()` (structural `ValueError`s → SUPPORTED per-axis `UnsupportedAxisValue` → EXCLUSIONS `ExcludedCell`), and `rms_norm()` calls `validate()` first and dispatches exactly one `ttnn.generic_op`. The op file does **not** declare `INVALID`. `default_compute_kernel_config()` is the single exported default (the golden axis tagger reads it).
- Auto-fixes to SUPPORTED: none from XPASS evidence (`xpass_drift = 0`); one axis added (`alignment`, item 3 above).
- **INVALID audit** (`eval/golden_tests/rms_norm/feature_spec.py`): `bf8b + ROW_MAJOR` present for the activation **and** for gamma (single-tensor coupling each) ✓; the `"none"`-sentinel canonicalization couples `gamma_mode` ↔ `gamma_dtype`/`gamma_layout` both ways so exactly one `no_gamma` cell survives ✓ (the norm-like no-weight canonicalization). One entry is **mis-categorized by the rules**: `{layout: ROW_MAJOR, memory_layout: WIDTH_SHARDED}` is annotated by its author as "for now, NOT structural impossibility" — that is `EXCLUSIONS` semantics (a kernel improvement could enable it), parked in INVALID to keep it out of the backlog. It is consistent with the prompt contract ("ROW_MAJOR_LAYOUT with sharded memory is not supported") and `validate()` refuses it with `ValueError`, so no runtime harm; recommend the golden-tests owner either move it to the op's `EXCLUSIONS` or keep the explicit "author-scoped" annotation. Not edited here.

## Design Conformance
- **Algorithm** ✓ — Σx² accumulated in DEST per tile-row, within-tile collapse, cross-core sum of collapsed partials, `rsqrt(mean + ε)` fused as a reduce post-op, `x ⊙ rstd`, `⊙ gamma`; `1/W` is the full tensor width; x is read once and stays resident A→D (no second pass — regime R5 correctly absent).
- **Data pipeline topology / RISC ownership** ✓ — reader: scaler, gamma slice, x block (or R3 publish); compute: A–E (+ tilize/untilize); writer: gather send / root gather, rstd `SenderPipe`/`ReceiverPipe`, store. Passive bounding-box cores run only the writer's `receive()`. Handoff CBs (`cb_partial_collapsed`, `cb_rstd_handoff`) keep every CB single-producer/single-consumer per build.
- **Parallelization** ✓ (performance-conformance checked, not just correctness): rows spread over the full grid (130 row-groups on prefill), the W-split occupancy term engages when rows under-fill it (26 cores on decode 7168, 52 on 64 × 12288, 120 on 8192 × 7168), reader and writer both batch a whole block per barrier, `DEPTH_X = DEPTH_OUT = 2`. Two places where the grid is deliberately *not* filled are the planner's stated lamps, not defects: `W_TILES_PER_CORE_TARGET = 16` (decode 1024 runs on 2 cores, `(2, 4, 128, 512)` on 32) and one-block-per-core on narrow prefill (no intra-core overlap) — both are perf refinements (R2, R3).
- **Inter-core communication** ✓ — root gather (unicast + counting semaphore) + `Mcast2D` rstd broadcast with loopback, one round of `cb_gather`/`cb_rstd` (address-stable slots), semaphore reset ordering as designed, `noc_async_atomic_barrier()` before exit.
- **Blocking-model fidelity** ✓ — every knob is a §H0 host constant or derived (`block_rows`, `core_w_tiles`, `num_w_splits`, `num_partials`, depths, `W_TILES_PER_CORE_TARGET`); CB page counts, loop bounds and kernel args are all computed from them; no CB scales unconditionally with a whole-op dimension (`Rt` appears only in the zero-copy shard CBs, which are the caller's buffers). No half-turned split: compute helpers take the whole `rows × core_w_tiles` block as a shape; TILE reader/writer issue `rows·Wc` transfers per barrier. The RM legs handshake per tile-row inside `read_sticks_for_tilize` / `tilize` / `untilize` / `write_sticks_after_untilize` — helper-internal traversal that the design itself specified (the stick quantum is 32 sticks per tile-row), not a main-schedule unit loop. The one DRY violation found (writer arg bases) is fixed.

## L1 Ledger Audit
- **Ledger currency** ✓ — every declared CB has a row and every row a live CB; size expressions match `create_program_descriptor` (per-W-group sizing, `B·Np` gather, aliased `cb_gamma_sticks` on `cb_normed`). Updated the R3 rows for the ragged shard (`Rt·Ws`).
- **Capacity vs live set** — over: `cb_x_tiles`/`cb_output_tiles` (depth 2, stated), `cb_gather` on non-root cores (uniform address-stable descriptors, stated), `cb_normed` sized to the block (fp32 D→E intermediate; the in-place alternative is the `normed_roundtrip` lamp, gated on precision, stated). Under: no CB spans an axis its capacity does not scale with; `cb_out_sticks` correctly streams `row` with a fixed 2-tile-row window.
- **Page format vs DEST width** ✓ — `fp32_dest_acc_en = True` in Phase 0 and every accumulated intermediate is `Float32`; tensor-format CBs are relayout-only. **Refinement 1 must re-derive these from the config** (a `Float32` page under 16-bit DEST becomes an audit-3 finding) — filed in R1's notes.
- **Disjoint lifetime, no justification** ✓ — `cb_gamma_sticks` shares `cb_normed`; `cb_sumsq_partial` vs `cb_normed` non-aliasing is justified (≤ 0.4 % saving, would couple builds).
- **Bounds and closed form** ✓ — symbol table bounds `B`, `Wc`, `Cw`, `Np`, `Ws`, `Rt` (shard CBs only), `L1_CB_BUDGET` (device query, further bounded by the largest contiguous free L1 block at build time); total footprint is closed-form; `block_rows_max_l1 ≥ 1` asserted else the refusal names the inventory.
- **Data-movement budget** ✓ present and consistent with the implemented split (x 1×, out 1×, gamma once per active core, cross-core `(Np + Cw)·rows·4 KiB` per block per group). Cheapest-traffic split implemented; the only cheaper decomposition (gamma broadcast, R4) is a `deferred` regime row with a positive reason. **One correction to its magnitude**: the "≤ ~14 % of x" figure holds at W = 7168; at 8192 × 1024 every one of 130 cores reads the full 64 KiB gamma → 8.3 MB against 16 MB of x (+52 %). That makes R4 a first-class perf refinement for narrow prefill (queued as Refinement 4).
- **Block-size defaults** ✓ — interleaved: full grid first, then the coarsest block that fits (`block_rows = min(core_row_tiles, block_rows_max_l1)`; `B = 1` only where W is wide); sharded: one block = the whole shard unless the intermediates do not fit. No split away from the defaults was taken. Per-core footprint: `F = Wc·B·(DEPTH_X·T_in + HG·4096 + DEPTH_OUT·T_out) + HG·Wc·T_g + 4096·B·(Np + 2 + 2·[Cw>1]) + 2048` — the first term scales with the block, the second with `Wc`, the third with `B` and `Np`.

This is the FPU's tf32 truncation on every FPU stage (x·x, the two multiplies, the matmul-reduce; truncation biases down), which the design's risk table predicts at ~5e-4 relative per stage; it is a documented precision characteristic, not a structural bug (a wrong scaler/`1/W` would show a median far from 1.0 and identical across dtypes). Levers exist if a tighter fp32 baseline is ever required (`ReduceFp32Mode::Accurate` on the reduces; fp32 chain mode on the multiplies) — no failing cell points at them, so this is a recommendation, not a refinement.

**Recommended tolerances**: PCC ≥ 0.9999 (both dtypes); relative RMS ≤ 0.005; `comp_allclose` rtol = 1e-2, atol = 5e-2 (bf16) / 4e-2 (fp32).

## Recommendations
- **Refinement queue** (`op_requirements.md`): R1 numeric bundle (16-bit DEST + bf8b, `/numeric-formats-metal`) — the only generality gap and the unlock for every perf case; then perf on the 2:1 cadence collapsed to all-perf: R2 flagged decode 32 × 7168, R3 prefill overlap/placement knobs, R4 gamma column broadcast (scheme-change, stands alone), R5 sharded decode latency.
- **feature_spec `TARGET` lacks `alignment`**; the op now declares `SUPPORTED["alignment"] = ["tile_aligned"]` so the registry is honest about a gate the kernel has. `verify_supported` and the cartesian harness handle a SUPPORTED-only tagger axis fine (taggers add it to every cell), but the dashboard's `TARGET − SUPPORTED` view will not show it. Suggest adding `"alignment": ["tile_aligned", "non_tile_aligned"]` to TARGET only if non-aligned support is ever wanted (it would need non-aligned INPUTS and an in-kernel edge-mask refinement); otherwise document it as a contract exclusion.
- **Gamma DRAM traffic is +52 % of x at W = 1024 prefill** (every core re-reads the full gamma). The design's "≤ 14 %" is a W = 7168 figure. This is the strongest single lever for the one perf case currently slower than its reference — filed as Refinement 4 (R4 regime).
- **Program-cache determinism**: `create_program_descriptor` bounds the CB budget by `largest_contiguous_bytes_free_per_bank` at build time (needed to avoid CB/L1 clashes in a suite with live L1 tensors). It makes `block_rows` a function of transient allocator state — two calls with identical shapes can compile different programs (cache miss + perf variance). For perf measurement, warm the cache and measure in a clean allocator state; longer term consider quantizing the budget so small free-space changes do not move `B`.
- **Numerical bias** (−0.12 % fp32 / −0.07 % bf16 systematic, tf32 truncation): well inside tolerance; revisit only if a model demands an unbiased fp32 path (`ReduceFp32Mode::Accurate`, fp32 chain mode).
- **`cb_normed` fp32 round trip** costs `B·Wc·4 KiB` L1 and lowers `core_w_tiles_max_l1` (raising Cw on very wide W): the `normed_roundtrip` lamp (fuse D+E in DEST or pack-then-transform-in-place on `cb_output_tiles` with `PushPolicy::None`) is precision-gated; measure inside R2/R3 if L1 becomes the limiter under 16-bit DEST (where the intermediate would already be bf16 and the round trip buys nothing).
- Untouched infra in the working tree (`scripts/run_safe_pytest.sh` build-wait wrapper, `.build_complete`, `.venv_complete`, `.device_timing.jsonl`, `tt_metal/third_party/tt_ops_code_gen`) is the run harness's — not committed with the op.
