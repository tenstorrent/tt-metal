# Changelog: groupnorm_sc_N_1_HW_C

## Phase 0 — Core Implementation
- **Date**: 2026-09-16
- **What was done**: Initial implementation via incremental pipeline (planner → implementer → verifier). GroupNorm over `(N, 1, HW, C)` as one native dispatch: 2-D `(hw_splits × c_splits)` tile split over the full grid, per-channel column sums (`reduce<SUM, REDUCE_COL, AccumulateViaAdd>`), on-device 0/1 membership matmul for the group aggregation (groups may straddle 32-channel tiles from day one), centered two-pass variance, root-reduce + `mcast_pipe` broadcast of the per-group statistics, fused affine apply; TILE and ROW_MAJOR legs (tilize/untilize helpers); `resident_2d` / `streaming_2d` regimes selected on the host from the L1 closed form.
- **Verifier changes (same phase)**:
  - Layout-aware, residency-first split search (`config.SPLIT_PREFER_RESIDENT{,_RM}`, `SPLIT_COST_TOLERANCE_{TILE,RM}`, `SPLIT_RM_STICK_K_TARGET`, `FORCE_C_SPLITS`), chunk `Q` shrunk toward residency — measured: RM `(1,1,16384,320)` 405 → 144 µs, RM `(1,1,16384,640)` 452 → 235 µs, TILE `(1,1,65536,512)` 733 → 499 µs, RM `(1,1,262144,256)` 3.36 → 1.95 ms; TILE 4096-row shapes +9–18 %.
  - Kernel-config-ring fit for the `--dev` build (RM `K = 10` cells overflowed by 1.7 KB): root combine is the aggregation matmul against `1/n` rows (no second `reduce`, no raw SFPU post-op, single gather region), transposed membership copy so every matmul is one `row_matmul_block` body, `rsqrt(var + eps)` on the `Ng` group tiles into `cb_group_rstd`, grid-wide constants as common runtime args, membership waits at first use. Compute binary 57.2 KB → 42–50 KB (dev).
  - `l1_ledger.md` reconciled with the implementation; `verification_report.md`, `op_requirements.md` written; `verifier_report.json` archived next to them.
- **SUPPORTED at Phase 0**: dtype=[bfloat16], layout=[TILE, ROW_MAJOR], memory_layout=[INTERLEAVED], in_place=[False], alignment=[tile_aligned], groups_alignment=[group_aligned, group_straddling], affine=[gamma_beta, gamma_only, no_affine], affine_dtype=[bfloat16, "none"], affine_layout=[ROW_MAJOR, "none"]; EXCLUSIONS=[]
- **Accuracy achieved**: PCC=0.999999, max_abs_err=0.031–0.063 (1 bf16 ulp), rel_rms_err=0.0015 on zero-mean data; at `mean = 10σ`: PCC=0.999895, max_abs_err=0.125, rel_rms_err=0.0145 (tf32 statistics rounding, documented) — measured on 5 shapes × 2 layouts via `test_groupnorm_sc_N_1_HW_C_precision_baseline.py`; got/true ratio centred on 1.0000 (no scale bug).
- **Golden suite at Phase 0**: 346 / 346 supported cells passing; 10 784 xfail_expected; supported_fail = xpass_drift = xfail_wrong_mode = 0 (per `verifier_report.json`); 0 hangs.
- **Perf at Phase 0** (Blackhole, 110 cores, interleaved bf16, device kernel µs): TILE 16384×320 88.6 (ref 600), 4096×640 54.7 (225), 1024×1280 43.9 (97), 1024×2560 79.0 (120), 4096×1920 143.9 (336), 16384×960 235.5 (818), 16384×640 164.0 (474), VAE 65536×512 498.5 (1015), 262144×256 1402 (2931); RM 16384×320 143.9, 4096×640 91.1, 16384×960 321.2, 16384×640 235.3.
- **Issues encountered**: design's flat all-gather combine measured ~5 µs/sender/round at 110 cores (implementer replaced it with the design's root-reduce + mcast lamp); `reduce<REDUCE_COL>` multi-output on fp32 `of(1, Wt>1)` left page 1 unwritten (implementer worked around with single-column calls; now moot — the combine is a matmul); `DestReuseBinary` DEST_TO_SRCA unpacker-format assert (DEST_TO_SRCB used); loopback multicast to a 1×1 rectangle never acks; end-of-kernel atomics assert without `noc_async_atomic_barrier()`; kernel-config ring overflow in `--dev` (verifier, fixed as above); `-Os` on TRISC breaks LLK inline asm and `opt_level` is not in the JIT hash.
- **Tests added**: `test_groupnorm_sc_N_1_HW_C.py` (acceptance, 78), `test_groupnorm_sc_N_1_HW_C_debug.py` (13), `test_groupnorm_sc_N_1_HW_C_perf.py` (18, `--profile`), `test_groupnorm_sc_N_1_HW_C_precision_baseline.py` (10), `probes/probe_ksweep.py` (verifier K/Q sweep, not collected by pytest).

## Refinement 1 — L1 block-sharded placement + in-place output (native CB placement)
- **Date**: 2026-09-16
- **What was done**: `ttnn.TensorMemoryLayout.BLOCK_SHARDED` and `in_place=True` added to SUPPORTED, natively (regime `block_sharded_resident`, now **built** in `op_design.md`). Reused unchanged: the resident regime's credit discipline, the root-reduce + `mcast_pipe` combine, every compute helper/chain, the membership and affine-row builds. Added:
  - Host: `(hw_splits, c_splits, K, Hs)` read off the shard spec (`_shard_geometry`, no split search); per-core `(c0, c_valid, s0, sticks_valid)` valid-lane/stick pairs (a 40-channel model shard is `K = 2` with 40 valid lanes; the membership rows and gamma/beta slices are built from them); `Q` shrinks only if the fixed CBs (+ the RM tiled copy) miss the L1 budget; host-derived `hw_mask` knob.
  - TILE shards: `cb_input_tiles` / `cb_output_tiles` placed on the shard buffers with `ttnn.cb_descriptor_from_sharded_tensor` (zero-copy; the reader pushes credits only, block offsets are shard-absolute); `in_place` = a second buffer index on the input shard's CB region.
  - RM shards: stick-page CBs on the shard buffers; the reader stages each tile-row's valid sticks L1 → L1 at the tilize's `K·64 B` stride (pad lanes / pad sticks zeroed), compute tilizes image n's rows once into the resident tiled CB, the writer copies the valid `c_valid·elem` bytes of each untilized stick into the output shard.
  - Shared per-image geometry header (`kernels/groupnorm_sc_N_1_HW_C_geometry.hpp`): every kernel intersects the core's stick range with each image, so **N > 1 shards land in full** — per-image sub-rectangles, ragged auto shards, and shards straddling two images mid tile-row; a core without work in an image unicasts a zero row (uniform root count) and drains the broadcast stats.
  - Partial tile-rows (RM shard heights not multiples of 32, straddles): pass-2 row mask through the **expansion matmul** — the writer copies the landed group-mean tiles with the rows outside the image zeroed (`cb_masked_mean`), `(32×Ng)@(Ng×1)` yields `mean_full[r][c] = mask[r]·mean_c`; `cb_inv_rows` fills all 32 rows in those programs. Replaces the design's `cb_hw_mask` chain element, which overran the kernel-config ring in `--dev` (+10 KB as a second chain, +1.1 KB fused).
  - Code size: `pass2_segment` / `root_combine_block` as `noinline` bodies, pops via `noinline pad_pop`; every sharded config fits the 70 656 B ring in `--dev` (tightest ~1 KB under); interleaved RM K = 10 canary unchanged.
  - Gamma/beta slices at non-64 B offsets (model shards) land at the source's 64 B residue in the scratch face (NoC alignment rule = equal residue).
- **Accuracy achieved**: sharded error identical to interleaved on the same data — bf16 RMS 0.0028 (gamma+beta) / 0.0020 (gamma) / 0.0019 (no affine), PCC ≥ 0.9995; `mean = 10σ` on 4-stick-high RM shards passes (pass-2 masking before squaring). Unit gates: PCC ≥ 0.995 **and** RMS ≤ 0.02 on all 51 sharded cases.
- **Golden test progress**: targeted bf16 BLOCK_SHARDED slice (12 shapes incl. N ∈ {2, 4, 8}, ragged and wide-C, SDXL straddling; cartesian + loose model/auto shards): **167 pass / 0 fail**, 1716 xfail/skip as expected. Full suite is the harness's run after exit.
- **Perf (device µs, first measurement of the sharded contract)**: 8×8 model grid, `in_place`: RM 16384×320 `[2048,40]` **181** (achievable_ns 337), RM 4096×640 `[512,80]` 66 (105), TILE 1024×1280 `[128,160]` 31.5 (42.5), RM 1024×1280 `[128,160]` 39 (44.5); `in_place` vs out-of-place within 0.3 µs. Interleaved guards unchanged within noise: TILE 4096×640 55.0–55.5 (54.7), RM 4096×640 90.0 (90.6), TILE 16384×320 88.4–89.2 (89.4), RM 16384×320 140.6–140.9 (145.5), TILE/RM 1024×1280 44.1 / 58.9 (43.4 / 59.0).
- **Issues encountered**: (1) reader pushed shard credits for every image while compute pops only images with work → hang on N = 8 shards (fixed: credits follow the per-image geometry); (2) kernel-config ring overflow in `--dev` for RM sharded configs (fixed as above — three iterations, measured per symbol with `riscv-tt-elf-nm`); (3) **stale-stats race on N > 1 shards**: skipping `cb_reserve_back` of the landing CBs on cores without work removed the flow control, so the next image's broadcast landed while pass 3 was still reading the mean (PCC 0.9995 but RMS 0.03–0.045; grid rows 1..6 wrong, root and last rows exact; recovered per-core beta offsets = next mean × scale) — fixed by reserving/pushing for every image and draining on compute; (4) harness plumbing: `-k` grammar (no `=`/quotes) and Tracy's `/bin/sh` command line (no parentheses).
- **Tests added**: `tests/ttnn/unit_tests/operations/groupnorm_sc_N_1_HW_C/test_groupnorm_sc_N_1_HW_C_sharded.py` (51 cases: TILE 1×1/model/ragged row+col/N = 2 straddle/N = 8; RM model widths 40…320 + 4×8 attention shard + SDXL perf anchors; RM ragged heights 4/7/103/205; N = 2 mid-tile-row straddles; affine variants; large-mean stability) with PCC + RMS gates; probes `probes/probe_002.py` / `probe_003.py` (race diagnosis).

## Refinement 2 — Non-tile-aligned HW and C (in-kernel masking / trimming)
- **Date**: 2026-09-16
- **What was done**: `"hw_non_aligned"` and `"c_non_aligned"` added to `SUPPORTED["alignment"]`, natively, on the shared kernels — no new kernel file, CB, helper instantiation or program-descriptor branch. **Reused**: Refinement 1's per-core `(c0, c_valid)` valid-lane pair (membership rows / gamma-beta lanes beyond `c_valid` are zero, so channels `≥ C` drop out of every group sum and the expansions yield zero output lanes), the `hw_mask` masked-mean pass-2 path (`cb_masked_mean`, `push_masked_mean`, `pass2_segment`), the shared `image_work_*` geometry and every compute chain. **Added**:
  - Host: interleaved cores get `c_valid = min(K·32, C − c0)`; `hw_mask = HW % 32 != 0` for interleaved programs and `_has_partial_rows` sees TILE shards through the padded image stride (`hw_stride = HWt·32` for TILE, `HW` for RM — the pitch between images the kernels intersect their block with); the core owning an image's last tile-row gets `row_hi = HW − 32·(HWt − 1)`; `cb_masked_mean` is allocated iff `hw_mask` (`fixed_footprint(..., hw_mask)`); both tensors' `buffer_aligned_page_size()` travel as common args (a `C = 17` RM stick is a 64 B page).
  - `geometry.hpp`: `image_work_interleaved(H_core, row_hi)`, `image_work_sharded(..., HW, hw_stride)`, and `pass2_segments` — the `[head][body Q-chunks][tail]` pass-2 chunk order compute and the streaming TILE reader now both derive from.
  - Reader: interleaved RM reads exactly `c_valid·elem` B of each of the row's `sb` valid sticks (`read_sticks_for_tilize` pads the L1 stride to `K·64 B`) into a stick CB whose pad lanes are zeroed once and whose pad sticks are re-zeroed before a ragged row; streaming TILE pass 2 pushes its nominal `Q·K` chunks in compute's segment order.
  - Writer: interleaved RM writes the `sb` valid sticks × `c_valid·elem` B per tile-row (`write_sticks_after_untilize`); `push_masked_mean` / full `1/n` rows now serve any `hw_mask` program.
  - Compute: `centered_sq_chunk` is one body whose mean operand is `BroadcastDim::Row` (Phase 0) or a full masked tile (`hw_mask`) and whose `x` policy follows the regime — the streaming + `hw_mask` combination now compiles (no `static_assert` on the sharded RM path).
  - Latent Refinement-1 bug fixed on the way: `fill_affine_rows` copied `nv·elem/4` whole words, dropping lane `C − 1` for odd valid-lane counts (`C = 17, 47`); it now copies `ceil(nv·elem/4)` words (the half-word past `nv` is zero scratch).
- **Accuracy achieved**: zero-mean bf16 — PCC ≥ 0.9999, RMS 0.0017–0.0023 on every non-aligned shape in both layouts and both placements (identical between interleaved and sharded, identical to the tile-aligned neighbours). At `mean = 10σ`: PCC 0.9998, RMS 0.0235–0.0303 — the documented tf32 statistics rounding (aligned `(1,1,64,128)` measures 0.024 with the same metric; the error is uniform across tile-rows — tail 0.0303 vs body 0.0304 — an unmasked tail would inflate the variance ~36× and collapse the PCC). Unit gates: PCC ≥ 0.995 and RMS ≤ 0.02 (0.05 for the large-mean cases).
- **Golden test progress**: targeted slice (all 15 `hw_non_aligned` / `c_non_aligned` INPUTS shapes incl. `(1,1,64,200)` G=8 and N=2 cases, plus `(1,1,64,64)` and `(1,1,4096,320)` as aligned representatives) — **329 passed / 0 failed / 0 xpass** across both layouts, both memory layouts, `in_place` both ways and every affine variant; 2 646 xfail on the other axes as expected. Regression net: 142/142 (acceptance 78 + sharded 51 + debug 13); 114/114 under `--dev` on the ring-tightest RM sharded / non-aligned cells (kernel-config ring still fits).
- **Perf guard (interleaved, device µs, vs Refinement 1)**: TILE 4096×640 54.76 / 54.77 (55.0–55.5), TILE 16384×320 89.59 (88.4–89.2), RM 16384×320 141.8 (140.6–140.9), RM 4096×640 92.25 / 92.51 (90.0 R1, 90.6–91.1 Phase 0: +1.5–2.8 %, on the noise band; the aligned RM path issues the same NoC operations per tile-row and skips the new zeroing when `c_valid % 32 == 0`).
- **Issues encountered**: (1) odd `C` lost its last channel in both layouts — the affine word-copy truncation above; (2) the first `--profile` invocation with four ops in one session produced no `ops_perf_results` CSV (re-measured one shape per run, as the baselines were taken); (3) sharded `c_non_aligned` RM shapes shard into 8-channel-wide columns (`(1,1,64,17)` → 3 cores of `K = 1`, `c_valid = 8/8/1`, `c0` not a tile multiple) — worked unchanged because the sharded path never assumed `c0 % 32 == 0`.
- **Tests added**: `tests/ttnn/unit_tests/operations/groupnorm_sc_N_1_HW_C/test_groupnorm_sc_N_1_HW_C_non_aligned.py` (124 cases: the corpus `hw_non_aligned` / `c_non_aligned` shapes + both-ragged shapes, interleaved and auto-like L1 block shards, `in_place` both ways, affine variants, forced streaming regime, `mean = 10σ`); probes `probe_005.py` (aligned page sizes / TILE padding contents), `probe_006.py` (per-tile-row error attribution at `mean = 10σ`).

## Refinement 3 — Speed up the SDXL sharded ROW_MAJOR GroupNorms (perf-competitive target)
- **Date**: 2026-09-16
- **What was done** (perf; no SUPPORTED change). **Reused**: the whole compute kernel (its `input_resident && is_rm` tilize-once / untilize path runs unchanged), the shared geometry header, `_shard_cb` placement, the sharded fit loop, the perf-file harness. **Added**:
  - **RM direct view** (`config.RM_SHARD_DIRECT_VIEW`, CT knob `rm_direct`): a ROW_MAJOR block shard whose stick page is exactly `shard_w·elem` B is one contiguous byte array, so it is ALSO the row-major block `[shard_rows/m, lcm(shard_w, 32)]` — a `[2048, 40]` bf16 shard is byte-identical to a `[512, 160]` block (`K' = 5`, 16 tile-rows, no pad lanes). The host places the shard itself as `cb_input_sticks` re-paged to tile pages (the tilize reads it zero-copy) and the output shard as `cb_output_sticks` (the untilize packs straight into it; `in_place` = one region — pass 1 tilizes image n's rows out of it before pass 3 untilizes over them). The reader pushes `rows·K'` credits per image; the writer stores nothing. The per-stick L1 → L1 staging (2048 × 80 B reads + 2048 × 80 B writes per core on the 16384×320 shard) is gone and the tile count drops 128 → 80. View lane `j` is channel `c0 + j % shard_w`: a `c_period` common arg makes the membership build and `fill_affine_rows` periodic (runs of consecutive channels per tile; `c_period = K·32` — the identity — on every other path). Gate `_rm_direct_view`: page = `shard_w·elem`, `K' ≤ MAX_CORE_C_TILES`, `shard_rows` and `HW` multiples of `32·m` (so no view row is partly outside its image — `hw_mask` programs keep the staged path), `shard_w·elem % 4 == 0`; the direct view falls back to the staged one when its K'-proportional CBs miss the budget. Ragged / N > 1 / auto shards take the Refinement-1 staged path unchanged.
  - **Honest sharded CB ceiling** (`config.L1_CB_SAFETY_MARGIN_BYTES`): the shards sit in the same L1 (allocated top-down), so the sharded fit uses `min(L1_CB_BUDGET_BYTES, lowest shard address − ttnn.get_allocator_base_address(L1) − margin)`. `(1,1,16384,960)` RM `[2048,120]` (a flagged cell) had been failing with a static-CB / L1-buffer clash (972 928 B of CBs vs a 969 728 B ceiling, both before and after this refinement's view); it now shrinks `Q` 8 → 4 and runs.
  - **Chain block size** `b = min(K, DEST_AUTO_LIMIT)` (was the largest divisor of `K ≤ 4`, i.e. 1 for `K ∈ {1, 5, 7, …}`): the chain blocks within a K-tile row with a valid-remainder tail (`chain.inl`), and every chunked CB is a whole number of rows, so no block can straddle the ring whatever `b` is. Applies to every path (the Phase-0 lamp filed for this refinement).
  - CT arg layout: knob 8 = `rm_direct`; every CB-id index shifted by one in the three kernels (`accessor_ct_base` 15, `mcast_ct_base` 24).
- **Perf (device µs, 8×8 model grid, `in_place`, gamma+beta, G = 32; `achievable_ns` at 1350 MHz in brackets)**: RM 16384×320 `[2048,40]` **181.5 → 70.5** [337]; 4096×640 `[512,80]` 68.2 → **47.4** [105]; 1024×1280 `[128,160]` 38.7 → **33.8** [44.5]; 4096×1920 `[512,240]` 123.6 → **121.6** [139] (K' = 15 vs staged K = 8: the K-proportional expansions / row chains offset the staging saved); 16384×640 `[2048,80]` 214.6 → **111.4** [382]; 16384×960 `[2048,120]` **FAIL → 245.3** [390] (staged, `Q = 4`). Chain block: 16384×320 72.6 → 70.5 alone. Guard set unchanged within noise: interleaved TILE 4096×640 54.3 (54.8–55.5), interleaved RM 16384×320 141.1 (141.8), streaming TILE 262144×256 1396 (1402), sharded TILE 1024×1280 31.3 (31.5).
- **Accuracy achieved**: unchanged — the unit gates (PCC ≥ 0.995 and RMS ≤ 0.02, 0.05 at `mean = 10σ`) hold on every sharded cell; the SDXL perf cells pass the sharded test's PCC + RMS gates on the direct view (the math is the same tiles in a different order; the golden soft gate is 0.9995).
- **Golden test progress**: not re-run (perf refinement; the harness's full run is the record). Regression net: whole unit dir 276/276 (plain), sharded 51/51 + non-aligned block-sharded 68/68 under `--dev` (kernel-config ring still fits), new perf cases 24/24.
- **Issues encountered**: (1) the K' = 15 view of a 120-channel shard misses the L1 budget (K-proportional CBs) — fixed by ordering candidates [direct, staged] and skipping a view that does not fit; (2) `L1_CB_BUDGET_BYTES = 1 000 000` ignored the shard in the same L1 → the pre-existing 16384×960 clash above; (3) `-k` in `run_safe_pytest.sh` takes no spaces (`in_place-rm_model_sdxl_16384x320`), and zsh does not word-split unquoted loop variables (one silent no-op batch).
- **Tests added**: `test_groupnorm_sc_N_1_HW_C_perf.py::test_perf_sdxl_sharded_rm` (12 SDXL model shards × {direct, staged} — the staged variant pins `RM_SHARD_DIRECT_VIEW = False` so the baseline stays measurable), `probes/read_perf_csv.py` (host-only Tracy CSV reader).
- **Remaining headroom (finding, not a task)**: the sharded TILE 1024×1280 cell (20 tiles/core) runs 31 µs, so ~30 µs of every sharded cell is the per-image fixed floor (two combine rounds, membership build, the 3·K expansions) — Refinement 6's scope. The 4096×1920 / 16384×960 wide-view cells are limited by the K-proportional fixed work (K' = 15) and, for 16384×960, by the 1.5 MB L1: a direct view that re-tilizes per pass from the shard (streaming chunks, N = 1 only, since the ring pointer must return to image n's rows) would drop the 480 KB resident tiled copy and make K' = 15 fit; not built here because the staged fallback already lands the cell 1.6× under its target.

## Refinement 3 (debug) — Speed up the SDXL sharded ROW_MAJOR GroupNorms: fix the golden regression

- **What was done**: the harness's full golden run after Refinement 3 regressed two prior-passing cells — `(1,1,1024,2560)` and `(1,1,1024,1920)`, ROW_MAJOR BLOCK_SHARDED `in_place`, the AUTO-shard geometry on the 11×10 live grid (`[103,240]` K = 8 / `[103,176]` K = 6; staged path with `hw_mask`, the direct view is not exact for a 103-row shard) — to pcc ≈ 0.004 with |y| ≈ 1e17 and `median_abs = 0`. No SUPPORTED / EXCLUSIONS change, no CB change (l1_ledger unchanged).

- **Golden test progress**: FULL suite re-run locally: **1316 passed / 0 failed / 0 hangs** (46833 skipped, 9849 xfailed; 6:31) — the harness's R3 run was 1314 / 2. Regression net: `test_..._sharded.py` + `test_..._non_aligned.py` + the new debug file 179/179.

## Refinement 4 — Numerical configurability expansion + TILE-layout affine weights
- **Date**: 2026-09-17
- **What was done**: `ttnn.float32` and `ttnn.bfloat8_b` added to `SUPPORTED["dtype"]` and `SUPPORTED["affine_dtype"]`, `ttnn.TILE_LAYOUT` to `SUPPORTED["affine_layout"]`, and `compute_kernel_config` (a `ttnn.WormholeComputeKernelConfig` / `BlackholeComputeKernelConfig`) exposed on the entry point with the Phase-0 defaults (HiFi4, fp32 DEST, exact SFPU — `default_compute_kernel_config()` in the descriptor is the single source). No compute or writer change; no new CB. **Reused**: `ttnn.tile_size(dtype)` was already the page-size source of truth (`TB` / `TA`), every compute helper / chain re-arms its data formats, the fp32 intermediates are governed by `fp32_dest_acc_en`, and the reader's `fill_affine_rows` run walk (identity / `c_valid`-clipped / periodic `c_period`) is unchanged. **Added**:
  - Reader: `fill_affine_rows<tile_src, bf8_src>(pages, tile0, …)` — the run walk resolves the source of channel `c` per run: ROW_MAJOR weight → byte `c·elem` of the stick page; TILE weight → row 0, lane `c%16` of face `(c%32)/16` of tile page `c/32` (a run is split at the 16-lane face rows so every NoC read stays contiguous; the `(1,1,1,C)` TILE tensor's rows 1..31 are zero padding). `kernel_main` resolves the ≤ K + 1 page NoC addresses this core touches once, in one gamma/beta loop, with ONE `TensorAccessorArgs` block for both weights (the host asserts their placement CT args are equal). The NoC + store body is one `noinline copy_affine_run<bf8_src>`; bf8b TILE weights are decoded lane by lane (shared exponent at header byte `face·16`, mantissa at `64 + face·256 + col`, normalized exactly as the host's `convert_bfp_to_u32`) into a **bf16** rows CB — exact (bf8b has a 7-bit mantissa), and the only way a block format can serve the periodic / non-tile-aligned channel maps of the RM shards. Two reader-only CT knobs (`affine_tile`, `affine_bf8`, indices 15/16; `accessor_ct_base` 17) and one common arg (`affine_page_bytes = weight.buffer_aligned_page_size()`).

## Refinement 5 — Two-pass streaming statistics for the DRAM-bound VAE shapes
- **Date**: 2026-09-17
- **What was done** (perf; no SUPPORTED change). The `streaming_2d` regime read the input once per pass (three passes: 4 tensor volumes of DRAM traffic for a 2-volume problem). **Reused**: the whole three-pass machinery stays as the `hw_mask` streaming path and the measurable baseline (`config.STREAMING_TWO_PASS = False`); the resident and sharded programs are untouched; the ONE `row_matmul_block` body (now also the per-channel shift: `(1×1)@(1×K)` inv32-row × chunk-0 tile-row 0), the ONE accumulate-reduce instantiation (now carrying two accumulators), the Phase-0 `stage_chunk` / `centered_sq_chunk` chains (their offset-addressed variants read the resident chunk twice without a pop), the combine rounds, pass 3, the reader's chunk loop (`passes = 2`). **Added**:
  - CT knob 9 `two_pass` (host-derived: interleaved streaming without a ragged tile-row); every CB-id CT index in the three kernels shifted by one (`accessor_ct_base` 18, `mcast_ct_base` 26).
