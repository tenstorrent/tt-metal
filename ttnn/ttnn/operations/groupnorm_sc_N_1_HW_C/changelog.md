# Changelog: groupnorm_sc_N_1_HW_C

## Phase 0 — Core Implementation
- **Date**: 2026-09-15
- **What was done**: Initial implementation via incremental pipeline (planner → implementer → verifier). GroupNorm over a channel-last `(N, 1, H*W, C)` tensor with a kernel-generated 0/1 membership matrix per channel tile (group-straddling `(C/G) % 32 != 0` handled from day one), lane-form per-group statistics (`2·ceil(G/32)` Float32 tiles), 2-D `hw × ct` multi-core split with one image rectangle per image, unicast gather + `Mcast2D` combine at an image root, resident / streaming regimes selected on the host from the L1 ledger predicate, in-kernel tilize for RM input. One `ttnn.generic_op` dispatch per call.
- **SUPPORTED at Phase 0 (after verification)**: dtype=[bfloat16, float32, bfloat8_b], layout=[TILE, ROW_MAJOR], alignment=[tile_aligned, hw_non_aligned, c_non_aligned], groups_alignment=[group_aligned, group_straddling], affine=[gamma_beta, gamma_only, no_affine], affine_dtype=[bfloat16, float32, bfloat8_b, "none"], affine_layout=[ROW_MAJOR, TILE, "none"]. EXCLUSIONS=[{layout: ROW_MAJOR, alignment: hw_non_aligned}]. `compute_kernel_config` honoured; `fp32_dest_acc_en=False` refused (precision convention).
- **Accuracy achieved** (bf16 in/out, `randn`, measured on 4 shapes via `test_groupnorm_sc_N_1_HW_C_precision_baseline.py`): PCC=0.999999, max_abs_err=0.0065–0.037, mean_abs_err=0.0011–0.0016, rel_rms_err=0.0015–0.0019, got/true ratio median 1.000 (no scale offset). Offset-heavy row (x = randn + 8): PCC 0.99972, rel_rms 0.028 (tf32-class cancellation in the apply — documented limitation, see verification_report.md).
- **Golden suite at Phase 0**: 3597 / 3685 (3597 pass + 88 xfail-expected) executed cells passing (per `verifier_report.json`, final run); 88 xfail_expected (all = the RM × hw_non_aligned exclusion); supported_fail / xpass_drift / xfail_wrong_mode = 0 / 0 / 0; 0 hangs. Acceptance suite 54/54 + precision baseline 5/5.
- **Issues encountered** (verifier fixes — see verification_report.md → Code Review):
  1. Missing CB credit between the `a_T` and `b_T` chains in pass 2 (`cb_wait_front(cb_a_full, tl + 1)`) — non-deterministic per-element errors on RM × gamma_only (golden rms 0.021 → 0.0018).
  2. Uninitialised pad lanes in the RM affine rows for `c_non_aligned` corrupted bf8b output tiles through the shared exponent (PCC 0.957 → 0.99997); pad lanes now zeroed in the reader.
  3. bf8b weights: whole-page read (`g_is_bfp`), host `element_size()` replaced by a dtype map.
  4. Writer stored one tile per NoC barrier whenever `Ct_core = 1` (every SD/SDXL shape on the 11×10 grid); store block is now the `OUT_BLOCK_TILES_TARGET` knob (`out_block = largest divisor of chunk ≤ 8`), `cb_out = 2 · out_block`.
  5. SUPPORTED widened to all TARGET dtypes / affine dtypes / alignments after probing + full golden confirmation; RM × hw_non_aligned excluded (stick reader overruns the image → Refinement 2).
  6. `validate()` gained the `compute_kernel_config` argument and the `fp32_dest_acc_en=False` refusal.
  7. `l1_ledger.md` brought in line (cb_out, cb_scaler, symbols, BH grid, dtype note).
  Implementer deviations from `op_design.md` reviewed and kept: `WaitUpfrontNoPop` reduce policy, separate streaming pass-2 ring, `cb_stats_row` not aliased, `handshake=False` without a gather-ready signal, `DEST_TO_SRCB` in the apply. Deviation **not** kept: the `Pr | Ht`, `Pc | Ct` divisor-constrained split (80 / 110 cores on the flagship shapes) → Refinement 1.
- **Tests added**: `test_groupnorm_sc_N_1_HW_C.py` (planner's acceptance suite, 54 cases incl. regime pins and ValueError contract), `test_groupnorm_sc_N_1_HW_C_debug.py` (implementer's deterministic hand-calculable cases), `test_groupnorm_sc_N_1_HW_C_precision_baseline.py` (verifier: PCC / abs / rel-RMS / bf16-ULP / got-true ratio on 5 rows), probes 008 and 010–013 under `probes/` (race localisation, dtype / alignment / compute-config sweeps).
- **Performance at Phase 0** (bf16 TILE, median device time, 11×10 BH grid): `(1,1,16384,320)` 85.3 µs on 80 cores, `(1,1,1024,640)` 22.0 µs, `(1,1,32,32)` 6.9 µs floor. Per-dtype scaling and the per-transaction-bound reader signature are in verification_report.md → Performance baseline.

## Refinement 1 — Fill the grid: ragged 2-D split + grid-synchronisation lamp
- **Date**: 2026-09-15
- **What was done**: implemented the design's ceil/floor-balanced ragged core split instead of Phase 0's divisor-constrained one. Host (`groupnorm_sc_N_1_HW_C_program_descriptor.py`): `_split_2d` maximises `Pr·Pc` over `Pr ≤ min(P_n, Ht)`, `Pc = min(P_n // Pr, Ct)` with a per-layout tie-break knob (`SPLIT_TIE_BREAK`: TILE → largest `Pc`, ROW_MAJOR → largest `Pr`), `_axis_range` gives every core `rows [i·Ht // Pr, (i+1)·Ht // Pr)` / `cols [j·Ct // Pc, (j+1)·Ct // Pc)` as RT args (`Ht_core`, `Ct_core`), `_balanced_block` picks `cols` / `chunk_rows` on the max extents, CBs and the resident predicate size on `blk_max`; `SHRINK_TO_CRITICAL_EXTENT` (RM only) drops the cores that do not shorten the max extent; `MIN_TILES_PER_CORE` measured and kept at 1. Kernels: new shared `kernels/groupnorm_sc_N_1_HW_C_ragged.hpp` (per-axis `split` / `valid` accounting, `pad_push` / `pad_pop`); reader reads only the valid `valid_rows × valid_cols` tiles (dense at the front of the nominal `chunk` quantum), fills only the valid membership / affine tiles, RM ragged column groups are read one tile-row at a time with a pad push; compute reduces `ReduceInputBlockShape::of(valid_rows, valid_cols)`, squares / applies `IterationShape::tiles(valid)` / `grid(valid_rows, valid_cols)`, zero-fills the `cols − valid_cols` colsum pad slots (FillScalar chain) so the `K = cols` membership matmul stays exact, pad-pops the unused membership / affine tiles and pad-pushes `cb_out` to the nominal chunk, tilizes RM ragged groups with a per-width `tilize<W>` dispatch; writer stores only the valid tiles (counter walk, no runtime division). Every CB quantum stays nominal so no ring ever straddles its wrap point. Reused: all Phase-0 kernels / host paths; Added: the ragged header, the per-core extent RT args, three host knobs.
- **Performance** (bf16, 11×10 BH grid, `--profile` device kernel time, baseline = verifier commit): `(1,1,16384,320)` TILE gamma_beta 86.2 → 78.5 µs (110 cores); `(1,1,1024,640)` TILE gamma_beta 23.9 → 19.3 µs, no_affine 22.4 → 18.2 µs (110 cores); `(1,1,1024,1920)` 77.8 → 40.7; `(1,1,256,1280)` 20.8 → 14.2; `(1,1,4096,320)` 29.2 → 26.2; `(1,1,4096,640)` 52.5 → 47.7; RM `(1,1,1024,640)` 27.4/28.8/28.3/33.2 → 28.0/28.1/29.5/33.1 (80 cores); floor `(1,1,32,32)` 6.97 → 7.49 µs; `single_core_per_image` pin `(8,1,64,160)` TILE 29.9/34.9 → 31.2/35.0, RM 30.8/34.7 → 32.4/38.3. Attribution and the levers tried (constexpr dual path, reader unrolling, ablations, lamp sweep, tie-break sweep, 80-vs-110 cores) are in the refinement's **Outcome** line in op_requirements.md and the implementer breadcrumbs.
- **Accuracy achieved**: unchanged — acceptance `_check` (PCC ≥ 0.999 bf16) on all 51 acceptance cases; precision baseline 5/5; golden cells at the same tolerances as Phase 0 (no numerics changed: the pad slots are exact zeros, the valid tiles are the same data).
- **Golden test progress**: targeted slices run here: `1x1x16384x320`, `1x1x1024x640`, `1x1x4096x640` (RM ragged column group), `2x1x1024x640` (multi-image rectangles), `1x1x256x1280` (wide ragged `5×22` split), `1x1x64x17` (c_non_aligned), `1x1x17x64` (hw_non_aligned, RM cells xfail as before): 55/55 executed cells passing for each of the first six slices (161 INVALID skipped per slice); `1x1x17x64`: 33 passed + 22 xfailed (the RM × hw_non_aligned EXCLUSIONS entry, unchanged); `test_regression.py` (numerics) green. Full-suite confirmation is the harness's run after this refinement.
- **Issues encountered**: (1) first ragged version regressed `(1,1,4096,{320,640})` 1.8× — the verifier-recommended taller-`Pr` tie-break widens `Ct_core` and the per-core cost scales with `Ct_core` (affine build per channel tile + membership generation); fixed by the wide tie-break for TILE. (2) RM regressed +27…+61 % under the wide split (per-stick reader ∝ `Ht_core`) — fixed by the tall tie-break + shrink-to-critical-extent for RM. (3) Small shapes carry +0.3–0.5 µs from the generic runtime-extent block loops (see Outcome); attempts to restore compile-time shapes on the full path regressed the multi-tile shapes and were reverted. (4) `MIN_TILES_PER_CORE` 4/8 badly hurt the tiny shapes (kept at 1). (5) `run_safe_pytest.sh` word-splits `-k` expressions and takes one path — node ids / single-token `-k` used instead.
- **Tests added**: `tests/ttnn/unit_tests/operations/groupnorm_sc_N_1_HW_C/test_groupnorm_sc_N_1_HW_C_perf_guard.py` (the guard set + target shapes + lamp shapes, one op per test for `--profile`), `probes/compare_perf_guard_csv.py`, `probes/per_risc_kernel_time.py`, `probes/zone_times.py` (per-RISC / per-zone attribution from the Tracy device log).

## Refinement 2 — Padding-independent non-aligned paths: lift the RM × hw_non_aligned exclusion
- **Date**: 2026-09-16
- **What was done**: `EXCLUSIONS == []` — the RM × `hw_non_aligned` cell is lifted in-kernel and the statistics of every non-aligned cell no longer depend on what the padding holds. **Reader** (`load_x_chunk_sticks`): a tile-row is `row_ragged` when it is the image's last tile-row of an `HW % 32 != 0` tensor (only on the core whose rows end at `Ht`, last row chunk, last tile-row) and `lane_ragged` when its column group holds the last channel tile of a `C % 32 != 0` tensor; such a block is zero-filled over the NoC (`noc.async_write_zeros` on the reserved `cb_x_rm` pages + `write_zeros_l1_barrier`) and then only the valid `hw_tail` sticks × `(C − 32·T_first)` bytes are read over the zeros through `read_sticks_for_tilize` (which pushes the full `valid_cols` tile pages), so the tilized pad rows / lanes are exact zeros and the reader never touches rows ≥ HW (previously the next image's rows / past the buffer). Pass 2 (streaming) skips the fill (pad rows/lanes of the output are sliced off) but never over-reads either. Aligned blocks keep the one-call fast path unchanged. **Scaler / compute**: `cb_scaler` is the `[full, partial]` REDUCE_COL pair when `HW % 32 != 0` (`calculate_and_prepare_partial_reduce_scalers<cb_scaler, SUM, REDUCE_COL, HW % 32>`), the host passes `hw_tail` (CT) and `owns_last_row` (RT) to compute, and `colsum_chunk` hands `ReducePartialScaler::with_partial()` to both column-sum reduces (x and x²) of the chunk holding the image's last tile-row — the dense valid block makes that row tile `valid_rows − 1` of every column, exactly the helper's "last reduce-dim tile of this call". Applies to both layouts, so a TILE producer's garbage pad rows cannot enter `S`/`Q`. Reused: the whole Phase-0/R1 block schedule, `read_sticks_for_tilize`, the reduce helper's partial-scaler contract, the `pad_push` ragged accounting. Added: the two ragged predicates + NoC zero-fill in the stick loader, one CT + one RT arg, `scaler_tiles` on the host, `EXCLUSIONS = []`.
- **Accuracy achieved**: acceptance `_check` PCC ≥ 0.995 (bf16) on all 51 cases; layout matrix PCC ≥ 0.995 / 0.999 (bf16 / fp32) on 9 shapes × 2 layouts incl. `(1,1,17,64)`, `(1,1,50,128)`, `(1,1,47,50)`, `(2,1,100,80)`; RM ≡ TILE bit-for-bit on the two-image hw_non_aligned cases (`(2,1,100,128)`, `(2,1,17,64)`, `(3,1,50,96)`, PCC 0.99995–0.99998 vs torch at per-image offsets −2/+4/−6); TILE with `pad_value ∈ {1000, −333}` on `(1,1,17,64)`, `(2,1,50,80)`, `(1,1,100,200)` passes at the same PCC as zero padding. Precision baseline unchanged (5/5).
- **Golden test progress**: targeted slices — `1x1x17x64` and `2x1x100x128` (hw_non_aligned): 33 passed + 22 xfailed → **55/55 passed** each (161 INVALID skipped); `1x1x64x17` and `2x1x64x48` (c_non_aligned, RM lane-ragged path): 55/55 each. Expected full-suite delta: the 88 former xfail_expected cells become supported_pass (3685/3685 executed); confirmation of record is the harness's run after this refinement.
- **Issues encountered**: (1) the first two-image test used per-image offsets of 20/40/60 × std and failed identically on TILE and RM (PCC 0.34 on `(3,1,50,96)`); probe_009 showed the same collapse on the tile-ALIGNED `(3,1,64,96)` — it is the documented one-pass `E[x²] − mean²` cancellation (var ≈ 3600 − 3600 → Relu-clamped → rstd = rsqrt(eps)), not the ragged path; the test now uses offsets −2/+4/−6 (PCC 0.99998). Recorded as a finding in the refinement's Outcome line (lever: the design's deferred `shifted_two_pass_variance`). (2) The compile farm's best-effort precompile failed on a dispatch kernel link (`l1_to_local_mem_copy` undefined on the remote toolchain) — unrelated to the op; local JIT compiled everything.
- **Tests added**: `tests/ttnn/unit_tests/operations/groupnorm_sc_N_1_HW_C/test_groupnorm_sc_N_1_HW_C_layout_matrix.py` — `/memory-layouts` §7 matrix (9 shapes × {bf16, fp32} × {TILE, RM}), `test_rm_hw_non_aligned_two_images` (the verifier's `N = 2` RM hw_non_aligned case, plus N = 3 and TILE twins, with a per-image output-mean check), `test_tile_padding_garbage_independent` (TILE `pad_value` garbage); `probes/probe_009.py` (offset-heavy precision, aligned vs non-aligned, both layouts).
