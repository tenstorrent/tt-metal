# L1 Ledger: groupnorm_sc_N_1_HW_C

Schema and audits: `.claude/references/l1-footprint-discipline.md`. Block axes (from `op_design.md` → Blocking Model): `n`, `hw`, `ct`, `g`, `lane`, `c_affine`. `fp32_dest_acc_en` is a SUPPORTED knob (Refinement 3): every compute-produced statistic page follows the DEST width — `Float32` under fp32 DEST (default), `Float16_b` under 16-bit DEST (`_statistic_page_dtype`); the cross-core record CBs (`cb_partial`, `cb_gather`, `cb_totals_*`) and the matmul K-spill `cb_agg_interm` (must match `cb_partial`) stay `Float32`. With 16-bit DEST `DEST_AUTO_LIMIT` is 16 (full sync), so `cols ≤ 16` and the fixed footprint of the `stat` CBs halves.

Symbols: `x_page` input tile bytes (2048 bf16 / 4096 fp32 / 1088 bf8b — all three dtypes are SUPPORTED after verification); `y_page` output tile bytes; `g_page` affine tile bytes; `F32 = 4096`; `cols = cols_per_group`; `chunk = chunk_rows · cols`; `Kg = ceil(G/32)`; `P_max = max_images(P_used)`; `blk_max = num_col_groups_max · num_row_chunks_max · chunk` (nominal pages of the largest per-core block — Refinement 1: per-core extents are ragged, every block pushes its nominal quantum); `out_block = largest divisor of chunk ≤ out_block_tiles_target (8)` (writer store block, independent of `cols`).

## Total per-core footprint

```
fixed_bytes = chunk·F32                                   # cb_xsq            (∝ chunk_rows·cols)
            + 2048 · (1 + [HW % 32 != 0])                 # cb_scaler (Refinement 2: [full, partial] pair for hw_non_aligned; padding-independent)
            + 2·cols·F32                                  # cb_colsum         (∝ cols)
            + membership_depth·cols·Kg·F32                # cb_membership     (∝ cols·Kg)
            + 2·Kg·F32 · (1 + 1 + [combine != LOCAL]·(ceil(P_max/32) + 1) + [combine == ROOT])   # agg_interm, partial, gather + totals_recv (not LOCAL), totals_src (ROOT only)  (Perf 2: stats_g_full deleted)
            + has_gamma·cols·g_page + has_beta·cols·g_page       # gamma/beta rows
            + 2·cols·F32                                  # stats_T (row-0 form; Perf 2: beta_full deleted)
            + 2·cols·F32                                  # a_row + b_row   (∝ cols; row-0 form, same page count)
            + out_depth_factor·out_block·y_page           # cb_out
            + is_rm·x_rm_depth·cols·x_page                # cb_x_rm
x_bytes     = resident ? resident_depth·blk_max·x_page : 2·x_depth·chunk·x_page   # resident_depth ∈ {1, 2} (2 only for multi-image cores, if it fits); streaming: cb_x_pass1 + separate cb_x_pass2 ring
            + 2·Kg·F32                                           # cb_stats_row (own region, not aliased)
total       = fixed_bytes + x_bytes
```

Implemented block extents (Refinement 1 — ragged 2-D split, `op_design.md` → Work Distribution): per core `rows [i·Ht // Pr, (i+1)·Ht // Pr)`, `cols [j·Ct // Pc, (j+1)·Ct // Pc)` (RT args `Ht_core`, `Ct_core`); `cols = ceil(Ct_core_max / ceil(Ct_core_max / DEST_AUTO_LIMIT))`, `chunk_rows = ceil(Ht_core_max / ceil(Ht_core_max / (chunk_tiles_target / cols)))` (balanced blocks on the max extents, so every core needs ≤ the same block count); the last chunk / column group of a core may be ragged: it keeps the nominal CB quantum (`chunk`, `cols`, `cols·Kg`) and only the valid `valid_rows × valid_cols` tiles (dense at the front of the quantum) are read / reduced / applied / stored. The ragged column group's `cols − valid_cols` colsum pad slots are zero-filled so the `K = cols` membership matmul stays exact. Core split: `Pr·Pc` maximised (`Pr ≤ min(P_n, Ht)`, `Pc = min(P_n // Pr, Ct)`), tie-break per layout (`SPLIT_TIE_BREAK`: TILE → largest `Pc`, RM → largest `Pr`), RM additionally shrunk to the fewest cores with the same max extents (`SHRINK_TO_CRITICAL_EXTENT`). Worked default (bf16 in/out, `cols = 8`, `chunk_rows = 4` ⇒ `chunk = 32`, `Kg = 1`, `P_max = 64`, gamma+beta bf16, TILE input): `fixed ≈ 128 KiB (xsq) + 2 KiB + 64 KiB + 32 KiB + 6·8 KiB… (48 KiB + 8 KiB gather extra) + 32 KiB + 12 KiB + 64 KiB + 32 KiB ≈ 422 KiB`; streaming `x` ring `128 KiB` → `≈ 550 KiB`; resident regime accepts `blk ≤ (1 000 000 − 432 000) / 2048 ≈ 277` tiles — every `feature_spec.INPUTS` shape is resident at ≥ 56 cores (largest: `(1,1,16384,320)` → 80 tiles/core at 64 cores; on the 11×10 BH grid after Refinement 1: `11 × 10` split, `Ht_core_max = 47`, `Ct_core = 1`, `cols = 1`, `chunk_rows = 24`, `blk_max = 48` nominal for 47 tiles). fp32 input: `x` ring `256 KiB`, resident `blk_max ≤ 138` tiles ✓.

Refinement 4 (perf, no CB added): the many-core chunk shrank `32 → 4` tiles, so `cb_xsq` (= `chunk` pages) and the streaming `x` rings (`x_depth · chunk`) shrink by 8× on every ≥ 32-core shape — the resident predicate only gets easier; `cb_membership` doubled (`2 · cols · Kg` pages, ≤ 64 KiB at `cols = 8`, `Kg = 1`). The recorded-but-not-taken aliases (`cb_xsq` ↔ `cb_a_full + cb_b_full`, `cb_agg_interm` ↔ `cb_stats_T`) stay untaken: L1 is looser than before, not tighter. The data-movement knobs of that refinement (`DM_NOC_SPLIT`, `OUT_STORE_FLUSH_PER_BLOCK`) move no bytes into L1.

Terms scaling with knobs: `chunk_rows·cols` → `cb_xsq`, streaming `x` ring; `cols` → `cb_colsum`, `cb_membership`, `cb_gamma/beta_row`, `cb_stats_T`, `cb_a/b_row`; `out_block` → `cb_out`; `Kg` → all statistic CBs; `P_max` → `cb_gather` only; `blk` → resident `x` only (predicate-guarded); `RESIDENT_IMAGE_DEPTH` → the resident `x` ring of multi-image cores only (Refinement 5; the predicate is re-evaluated per depth, falling back to one block, then streaming).

Perf 2 (perf, two CBs deleted): `cb_stats_g_full` (`2·Kg` stat pages) and `cb_beta_full` (`cols` stat pages) are gone — the pass-2 affine build runs in row-0 (lane) form straight off `cb_stats_row` and the row-0 gamma / beta tiles, and the apply broadcasts the row-0 `a_row` / `b_row` tiles in the FPU (`−(2·Kg + has_beta·cols)·4 KiB` per core at fp32 DEST). `cb_stats_row` now lives until the end of pass 2 (retained in0 of the expansion matmul; it never aliased anything).

Refinement 5 (perf, no new CB): the combine CBs are allocated per scheme (`LOCAL` drops `cb_gather` / `cb_totals_*` entirely — 16 KiB at `Kg = 1`; `ALL_GATHER` drops `cb_totals_src`), and `cb_stats_row` rows 1..31 are no longer meaningful under `FINALIZE_LANE_MODE` (row-0-only SFPU finalize) — its only consumer, `unary_bcast<Row>`, reads row 0.

## Data-movement budget (chosen split: 2-D `hw × ct` per image rectangle, lane-form combine — `LOCAL` / `ALL_GATHER` / `ROOT` by rectangle size, Refinement 5)

| Tensor | DRAM crossings | Why that many | Cross-core traffic added |
|--------|----------------|---------------|--------------------------|
| `x` (input) | **1** in `resident_2d`; **2** in `streaming_2d` | resident: the aliased ring keeps the whole per-core block through both passes; streaming: the block exceeds `l1_budget_bytes`, pass 2 re-reads it | none (`x` varies along both cut axes) |
| `y` (output) | 1 | each core writes only its own block's tiles | none |
| `gamma`, `beta` | `Pr` reads of each `Ct_core` slice per image (`≤ 128 B` per tile for bf16/fp32; 1088 B for bf8b tiles) | reuse-shared by construction of the `hw` cut; the broadcast regime is rejected on payload size | none |
| statistics | 0 | never touch DRAM | per image — `LOCAL` (`P_used = 1`): **nothing** (compute finalizes its own partial); `ALL_GATHER` (`2 ≤ P_used ≤ ALL_GATHER_MAX_CORES = 8`): `P_used · (P_used − 1)` unicast records of `2·Kg·128 B` + `P_used · (P_used − 1)` semaphore increments, no totals broadcast (every core reduces its own gather); `ROOT` (larger rectangles): `P_used` unicast records of `2·Kg·128 B` (+ `P_used` semaphore increments), one totals multicast of `2·Kg·4096 B` to `P_n` cores |

Totals per tier (per image, bf16, `Kg = 1`, 64 cores, `(1,1,16384,320)`): DRAM `10 MiB` read + `10 MiB` written (resident) vs `20 MiB + 10 MiB` (streaming); gamma/beta `64 × 10 × 128 B ≈ 80 KiB`; cross-core `64 × 256 B + 8 KiB ≈ 24 KiB` plus two multicast flags and 64 semaphore increments.

> NoC assignment (Refinement 4, `DM_NOC_SPLIT`): the crossings above are unchanged, but on rectangles of ≥ 32 cores the odd logical rows run the swapped pair (reader on NoC1, writer on NoC0) so each pass's single DRAM stream (pass 1 reads only, pass 2 writes only in `resident_2d`) is carried by both NoCs' disjoint link sets instead of one — measured 77.9 → 67.8 µs on `(1,1,16384,320)` from this knob alone.
>
> Cheapest-traffic split considered: 2-D `hw × ct` with residency — `x` once, `y` once, `+≈24 KiB` cross-core. Implemented: the same split (`resident_2d` when the predicate holds; `streaming_2d` adds one input read when it does not). The implemented split is also the cheapest; the only deferred alternative on the traffic axis (`shifted_two_pass_variance`) would *add* a read.
