# Operation Requirements: groupnorm_sc_N_1_HW_C

## Definition
- **Formula**: `mean[n,g] = Σ_{h<HW, c∈g} x[n,0,h,c] / (HW·Cg)`; `var[n,g] = Σ_{h,c∈g} (x − mean[n,g])² / (HW·Cg)` (centered, two-pass — never `E[x²] − mean²`); `y[n,0,h,c] = (x − mean[n,g(c)]) · rsqrt(var[n,g(c)] + eps) · gamma[c] + beta[c]`, `Cg = C/G`, `g(c) = floor(c / Cg)`.
- **PyTorch Reference**:
  ```python
  def torch_groupnorm_n_1_hw_c(x, num_groups, *, gamma=None, beta=None, eps=1e-5):
      xf = x.to(torch.float32); N, _, HW, C = xf.shape
      x_nchw = xf.squeeze(1).permute(0, 2, 1)                       # (N, C, HW)
      w = gamma.float().reshape(C) if gamma is not None else None
      b = beta.float().reshape(C) if beta is not None else None
      y = torch.nn.functional.group_norm(x_nchw, num_groups, weight=w, bias=b, eps=eps)
      return y.permute(0, 2, 1).unsqueeze(1).to(x.dtype)
  ```
- **Import Path**: `from ttnn.operations.groupnorm_sc_N_1_HW_C import groupnorm_sc_N_1_HW_C`
- **Function Signature**: `groupnorm_sc_N_1_HW_C(input_tensor: ttnn.Tensor, num_groups: int, *, gamma: ttnn.Tensor = None, beta: ttnn.Tensor = None, eps: float = 1e-5, in_place: bool = False) -> ttnn.Tensor`

### [x] Refinement 1 — L1 block-sharded placement + in-place output (native CB placement)

### [x] Refinement 2 — Non-tile-aligned HW and C (in-kernel masking / trimming)

**Goal**: add `"hw_non_aligned"` and `"c_non_aligned"` to `SUPPORTED["alignment"]` natively. `HW % 32 != 0`: the last tile-row of each image carries padded rows — pass 1 is unaffected (zeros), pass 2 must **mask the padding before squaring** (`(0 − mean)² ≠ 0`): multiply the centered value by the design's `cb_hw_mask` full tile (1 in valid rows, 0 in padding; writer-built once) in the tail chunk only, and all counts use the true `HW` (`inv_bits = 1/(HW·Cg)` already does). `C % 32 != 0`: membership rows for channels `≥ C` are already zero (stats correct for free); the TILE leg's padded output lanes come out as `0·scale + shift` and must be irrelevant (they are — ttnn ignores padding) or zeroed; the RM leg must read `min(K·64 B, (C − c0)·elem)` bytes per stick into a pre-zeroed stick CB and write only the valid bytes. Includes the hardest corpus sub-case: `c_non_aligned` **and** `group_straddling` with `num_groups > 1` (e.g. `(1,1,64,200)` G=8, `Cg = 25`).

**Implementation skill**: /memory-layouts

**Verifier notes**: Second because it is the "tricky non-tile-alignment" tier and because Refinement 1 already builds the per-core `(c0, c_valid)` valid-lane machinery for 40-wide RM shards — reuse it here for the interleaved leg rather than writing a second trimming path. The pass-2 mask multiply is a **fourth chain instantiation only if written as a separate chain**: prefer a runtime-selected variant of the existing `centered_sq_chunk` (a `DestReuseBinary<Mul, cb_hw_mask>` element on the tail-chunk path) or apply the mask to the *expanded* squares via the reduce's existing `Accumulate` path — check the ring headroom (`verification_report.md` "Code size") before adding instantiations. `HWt = ceil(HW/32)` per image is already how the host counts tile rows; the reader's page ids for TILE inputs are already correct for padded shapes. **Done when**: every `hw_non_aligned` / `c_non_aligned` cell in `feature_spec.INPUTS` passes at the bf16 gate (PCC ≥ 0.995) in both layouts and both memory layouts, `verify_supported` clean, no device-ns regression on the tile-aligned guard set.

**Outcome** (Refinement 2, 2026-09-16): both alignment values added to SUPPORTED on the shared kernels with no new CB / instantiation / descriptor branch. `c_non_aligned` reuses the per-core `(c0, c_valid)` pair (interleaved cores now clip at `C`; RM reads/writes `c_valid·elem` B per stick, pad lanes zeroed once); `hw_non_aligned` reuses the `hw_mask` masked-mean path (host `hw_mask = HW % 32 != 0`, per-core `row_hi`, TILE shards seen through the padded image stride `HWt·32`); the streaming regime chunks pass 2 in compute's `[head][body][tail]` order via the shared `pass2_segments`. The verifier's suggested chain-element mask was not needed — the Refinement-1 expansion-matmul mask covers every placement and regime with the ring untouched (114/114 `--dev`). Fixed a latent odd-`C` affine word-copy truncation. Golden slice 329/0 over all 15 non-aligned INPUTS shapes × layouts × placements × in_place × affine; regression 142/142; guard set within noise (RM 4096×640 92.3–92.5 vs 90.0–91.1 µs, +1.5–2.8 %; the others ±1 %). Precision at `mean = 10σ` on ragged shapes equals the aligned neighbours' tf32 baseline (RMS 0.024–0.03).

### [x] Refinement 5 — Two-pass streaming statistics for the DRAM-bound VAE shapes

**Type**: perf

**Goal**: the `streaming_2d` regime reads the input **three** times (one per pass) — on the VAE decoder shapes in `LOOSE_CASES` (`(1,1,262144,256)` TILE 1.40 ms, `(1,1,262144,512)` 2.69 ms, `(1,1,1048576,256)` 5.5 ms, `(1,1,1048576,128)` 2.7 ms; all at 340–375 GB/s aggregate, i.e. DRAM-bound) that is 4 tensor volumes of traffic for a 2-volume problem. Replace the three-pass schedule in the streaming regime with a **two-pass** one that keeps the centered form: pass A streams each chunk once, computes the chunk's per-channel mean *from L1* and then its centered squares (two sub-passes over the resident chunk — the chunk *is* in L1), accumulating per-channel `(sum, M2)` and combining chunks with the parallel-variance identity `M2 = Σ M2_i + Σ n_i·(mean_i − mean)²` (Chan et al.; never `E[x²] − mean²` — the prompt's stability rule is satisfied because every square is of a centered value); pass B applies. Traffic 4V → 3V, so the DRAM-bound ceiling is 1.33×. Patterns: `master.md` `row_reduce_accumulate` / `reduce_block` (accumulate-then-finalize), `double_buffer` (`STREAM_DEPTH` ≥ 3 so the reader prefetches through the combine). Also raise `config.L1_CB_BUDGET_BYTES` toward the real 1.5 MB L1 (minus the ~70 KB kernel-config ring and firmware) so `(1,1,262144,256)` at 596 tiles/core becomes resident on this grid. No SUPPORTED change.

**Done when**: measured device-ns improves on the VAE TILE and RM cells above (target ≥ 1.25× on the streaming ones), PCC ≥ 0.9995 holds at `mean = 10σ` (the `test_large_mean_stable_variance` cases must stay green — the chunk-mean centering is what protects them), the golden suite is green, and no regression across the guard set (Refinement 3's list, plus the resident VAE `(1,1,65536,512)` TILE at 500 µs).

**Outcome**: landed as the `two_pass` schedule (CT knob 9, host-derived `streaming && !hw_mask`; `config.STREAMING_TWO_PASS`, False = the Phase-0 three-pass baseline). Pass A takes S = Σx and U = Σ(x − s)² from ONE read of each chunk — s = the per-channel column means of the chunk-0 tile-row 0 (the ONE matmul body against a writer-filled 1/32 row tile), S and U alternating on the ONE accumulate-reduce instantiation in a 2K-page `cb_colsum_rows` ring ([S, U] order) — then, after round 0, ONE two-DEST-slot chain forms v_c = U + 2(s − m)(S − (n/2)(m + s)) = Σ(x − m)² per channel (all squares of centered values; never E[x²] − mean²) and the group aggregation / round 1 run unchanged; pass B applies. Measured (Blackhole, 110 cores, bf16 gamma+beta G = 32, device µs, three-pass → two-pass, one fresh run each): TILE 262144×256 **1402 → 1072 (1.31×)**, RM 262144×256 **1908 → 1436 (1.33×)**, TILE 262144×512 **2687 → 2100 (1.28×)**, TILE 1048576×128 **2720 → 2096 (1.30×)** — each is the 4V → 3V traffic ratio: both schedules move ~380 GB/s aggregate, so these cells stay DRAM-bound and the remaining lever is bytes, not compute (a resident two-pass is impossible at 596–1200 tiles/core; the remaining 3V is the floor of any centered algorithm that cannot hold the input). Precision identical to the three-pass schedule on every pinned cell (zero-mean rel RMS 0.0014–0.0015; `mean = 10σ` PCC 0.99990–0.99993 / RMS 0.012–0.014; TILE + RM, single partial chunk, ragged chunks, N = 2, K ∈ {1, 8, 10, 16}). L1 budget: 1 440 000 B (the real ~1.46 MB above the allocator base) makes the 262144×256 TILE cell resident (K = 4, Q = 1: 149 four-tile chunks × 3 passes) at **1070 µs — a wash** against the 1072 µs two-pass stream (that resident schedule is per-chunk-overhead-bound at ~250 GB/s), so `L1_CB_BUDGET_BYTES` stays 1 000 000 as a live knob with both values pinned in `test_perf_vae_262144x256_budget_depth`; `STREAM_DEPTH = 3`: 1069 µs (noise). Kernel-config ring (`--dev`): the first two-pass build overran by 5.9 KB on the RM streaming programs; one reduce instantiation (−3.2 KB), reconfig-free fp32 operands and the fused single chain (variance combine 8.2 → 5.65 KB) leave the tightest streaming program ~1.9 KB under. Not done, and why: dropping the pass-A staging copy (reduce the bf16 input directly) needs a second reduce instantiation (+8 KB --dev) and compute is not the binding stage; `hw_mask` streaming shapes (HW % 32 ≠ 0) keep three passes (the per-core n and the chunk shift assume whole tile-rows — a masked variant is a Refinement-6-sized item nobody measured a need for: no such shape is in the VAE set).
