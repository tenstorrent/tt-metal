# Derived TTNN ops (bring-up forks)

When a model bring-up needs a change to an existing TTNN op, the op is forked here and changed here. The original op
is never edited. Each fork registers as `ttnn.bringup.<op>`, alongside the original.

Before forking, check this list. If the op is already here, reuse the fork, and put any new change behind an option
whose default keeps the fork's current behaviour. Each fork's `CHANGELOG.md` lists its source path and SHA, and every
change made to it (what, why, which model and task).

Python ops (a ProgramDescriptor op in a subfolder, no C++ build) are listed in `PYTHON_OPS` in `__init__.py`;
`ttnn.bringup.<name>` loads and registers them on first use. Their own unit suite lives in `<fork>/tests/unit/`; the
model cases (bring-up task O.1) are the top-level `tests/test_*.py`.

How to fork: `models/demos/common/bringup/skill/bringup-fork-op/SKILL.md`. In short: `python
ttnn/ttnn/bringup/fork_op.py <source op folder> --model <model> --task <task>`, then make the change, fill the
changelog, `./build_metal.sh`, and run the fork's tests (`<fork>/tests/`). Each fork also carries a best-effort selection of its
source op's own tests (`tests/source.yaml`, run in place with `testing/fork_source.py`; baseline in
`tests/source_baseline.json`). Every model that calls a fork adds a
random-input case to those tests for each call it makes: `models/demos/common/bringup/skill/bringup-fork-tests/SKILL.md`
(bring-up task O.1).

A person decides later whether a fork is ported back to the original op. When it is, the fork is deleted and its
users are switched back.

## Ops

Each folder's `README.md` has what the op does, its options, measured numbers, limits, a sample call and the models
that use it. Its `CHANGELOG.md` has the source path and SHA and every change.

- `ttnn.bringup.unified_routed_expert_moe` (unified_routed_expert_ffn): all local experts' gated FFN (down(act(x Wg, x Wu))) over the flat dispatched buffer in one program; adds GeluTanh, weights_transposed ([N, K] weights); precision only (rule 7): opt-in high_precision.
  Consider instead of: ttnn.experimental.deepseek_prefill.unified_routed_expert_moe; a per-expert ttnn.linear + activation loop. -> unified_routed_expert_ffn/README.md
- `ttnn.bringup.dispatch` (dispatch): MoE token dispatch of each token's rows to its top-k experts' chips into a flat per-chip buffer + metadata; adds a 1-device dispatch axis (no fabric).
  Consider instead of: ttnn.experimental.deepseek_prefill.dispatch; ttnn.all_gather + per-expert gathers. -> dispatch/README.md
- `ttnn.bringup.combine` (combine): inverse of dispatch, expert outputs back to [token, top-k slot] on the origin chip (unweighted; the caller does the weighted sum); adds a 1-device dispatch axis.
  Consider instead of: ttnn.experimental.deepseek_prefill.combine; per-expert insert + all-to-all. -> combine/README.md
- `ttnn.bringup.offset_cumsum` (offset_cumsum): expert histograms -> dispatch offsets, total counts, expert region offsets and every device's offsets row; skips the all_gather on a 1-device dispatch axis.
  Consider instead of: ttnn.experimental.deepseek_prefill.offset_cumsum; ttnn.all_gather + ttnn.cumsum + host math. -> offset_cumsum/README.md
- `ttnn.bringup.rms_norm` (rms_norm_ttnn): AI-generated perf-optimized drop-in for ttnn.rms_norm (residual add, weight, bias, any placement, TILE / ROW_MAJOR), opt-in returned residual sum; at fp32 DEST also accuracy fixes (no option); opt-in split program: a norm over rows split across chips (`stats_out` partials, all_gather, `partial_stats`), a column window of a wider input, the output dtype.
  Consider instead of: ttnn.rms_norm; ttnn.add + ttnn.rms_norm; ttnn.rms_norm_pre_all_gather + all_gather + ttnn.rms_norm_post_all_gather; ttnn.slice (+ ttnn.typecast) + ttnn.rms_norm of a column block. -> rms_norm_ttnn/README.md
- `ttnn.bringup.scaled_dot_product_attention`, `chunked_scaled_dot_product_attention`, `sparse_sdpa`, `ring_mla` and the rest of the SDPA family (sdpa): SDPA fork: V narrower than K, ring_mla / ring joint with kv_actual_isl=0; precision only (rule 7): sparse_sdpa high_precision / fp32_output / fp32_scores / bf16_probs, ring_mla at fp32 DEST. sparse_sdpa kv_format ROW_BFP4 + kv_window: bfloat4_b row records (ckv_bfp4) gathered by NoC reads and turned into bfp4 tiles by the unpacker, a bf16 window tensor (or 576 B bfloat8_b window records, or bfloat8_b window blocks of 32 consecutive rows a page) for the first k_chunk (deepseek_v41_flash_d_p 4-bit compressed KV); kv_format ROW_BFP8: a window-only layer's bfloat8_b records. Sparse attention (DSA / MLA, DeepSeek-V4.1's window attention with its sink): the stock ttnn.transformer.sparse_sdpa is the realistic choice, not this fork.
  Consider instead of: ttnn.transformer.* SDPA ops (with V zero-padded to K's width), ttnn.transformer.ring_mla; not for ttnn.transformer.sparse_sdpa (the fork's options are precision only). -> sdpa/README.md
- `ttnn.bringup.indexer_score_dsa`, `ring_indexer_score_dsa`, `indexer_score_msa`, `IndexerScoreProgramConfig` (indexer_score): lightning-indexer scorer fork: key_compression_ratio 2, ring natural_query_blocks over a block-cyclic key cache, an opt-in block epilogue in the ring op (a 0 / -inf per-block bias, per-block max of the scores with the own block pinned); bfloat4_b q / k (the reference's fp4 index query / keys); precision only (rule 7): opt-in fp32 DEST for DSA scoring.
  Consider instead of: ttnn.experimental.indexer_score_dsa / ring_indexer_score_dsa; ttnn.all_gather + ttnn.experimental.indexer_score_dsa; strided ttnn.slice + ttnn.maximum block pools or ttnn.repeat_interleave + ttnn.add block biases of the scores. -> indexer_score/README.md
- `ttnn.bringup.mhc_pre`, `mhc_pre_xing`, `mhc_pre_xing_pack` (mhc_pre_ttnn): fused mHC pre step (RMS statistic, projection, pre / post / Sinkhorn coefficients, collapse sum of pre_i x_i) in one program; the xing entries work from a mesh-reduced partial row (Xing4.0 or DeepSeek-V4 math); opt-in `collapse_pre` (coefficients + a collapse with a given / previous pre in one program), `partials` (a TP group's gathered partial rows summed in the op, exact fp32) and an engram mode of `mhc_pre_xing_pack` (per-stream sum h w k, h^2, k^2 in one pass, exact fp32); the xing entries take bf16 streams (exact fp32 sums, bf16 y).
  Consider instead of: matmul + sigmoid + Sinkhorn op chains + mul / add collapse; ttnn.experimental.deepseek_prefill.mhc_split_sinkhorn; ttnn.multiply + ttnn.slice + ttnn.sum chains of per-stream dot products / sums of squares. -> mhc_pre_ttnn/README.md
- `ttnn.bringup.mhc_post` (mhc_post_ttnn): fused mHC residual mix X' = post * F + comb^T X (or comb as stored) over n streams in one program, fp32 accumulation; opt-in `stats_weight` also returns the next hc step's partial row (X' @ W + sum X'^2) from the same pass (fp32 or bf16 F); `post_col` / `comb_col` read post / comb from the packed mixes; bf16 streams with `stats_weight` (bf16 F).
  Consider instead of: per-stream ttnn.mul + ttnn.addcmul chains (an identity comb: residual adds h_k + g_k v); mhc_post + ttnn.matmul + mhc_pre_xing_pack on the new streams; ttnn.slice of post / comb out of the mixes; ttnn.typecast of a bf16 F to fp32. -> mhc_post_ttnn/README.md
- `ttnn.bringup.flat_routed_expert`, `flat_routed_expert_plan`, `flat_routed_expert_with_program`; Python `flat_expert.FlatRoutedExpert` (flat_routed_expert_ttnn): every local expert's gated FFN in one spatially pipelined Blackhole program per chip, weights streamed once, counts read on device; typed layout options (`layout=`, presets in flat_layouts.py: default DRISC-only / even split, `LEGACY` the older plan every model here pins); opt-in weights_nk, hidden, down_fp32, max_y_writers (at most N y writers: an appended combine's L1 hand-off on any Galaxy harvesting); flat_routed_expert_with_program with math_fidelity / weights_nk, and patch_addresses (no buffer address in its program-cache key, every one patched on a hit; DeepSeek-V4.1 FIX.5); any intermediate with a gate/up split, unpadded (I 576 / 1152 at H 5120 on one subgrid, FIX.1); 2 / 3 subgrid plans (TP4 / TP2 at H 7168) in the plain op; precision only (rule 7): x_bf16 / h_bf16 / y_bf16 tiles, pack_stochastic_rounding.
  Consider instead of: ttnn.bringup.unified_routed_expert_moe, a per-expert ttnn.linear loop. -> flat_routed_expert_ttnn/README.md
- `ttnn.bringup.combine_rf.<module>` (combine_rf; Python ProgramDescriptor builders, not registered ops): token-split MoE pieces around the flat expert: weighted fp32 fabric combine (sparse_combine_rf, runs with flat_routed_expert_with_program), sparse 2D all-gather dispatch + prep, device combine planner, fabric all-gather, small-M 2D matmuls, router top-k, fused sums, tilize / untilize, L1 zeroing, routing all-to-all planner, routing pack, clamped GLU, sparse KV push planning (Marko's MoE block); per-call landing pools in the combine; opt-in column-axis combine (tokens replicated over the mesh row), passes, a deterministic one-core column planner and its multi-core port (cores=, bit-identical tables, 1573 -> 69 us at 1024 tokens a chip), bf16 running sums (acc_dtype: half the accumulator L1; the realistic sum precision); precision only (rule 7): fp32 output, acc_unpack_fp32.
  Consider instead of: ttnn.experimental.deepseek_prefill.combine / combine_fabric2d + post_combine_reduce, ttnn.all_gather, ttnn.linear at ~320 rows, ttnn.topk chains, ttnn.sum + ttnn.add, ttnn.tilize / untilize. -> combine_rf/README.md
- `ttnn.bringup.moe_ag_route_plan`, `moe_ag_local_reduce`, `moe_ag_sum_rows_tiled`, `moe_ag_add_rows`, `moe_ag_untilize_active`, `moe_ag_untilize_x` (moe_ag): device programs of the all-gather MoE block (route plan, weighted local reduce with fused send-back, row sums / adds, untilizes): MoE without dispatch / combine.
  Consider instead of: ttnn.bringup.dispatch + expert compute + ttnn.bringup.combine; ttnn.mul + ttnn.sum weighted combine. -> moe_ag/README.md
- `ttnn.bringup.fabric_all_gather` (fabric_all_gather_ttnn): drop-in for high_bw_all_gather (same contract and output) with a link-rate program (NoC1-placed port cores, counter-gated relays); Python prototype + `plan()` alongside.
  Consider instead of: ttnn.experimental.high_bw_all_gather, ttnn.all_gather. -> fabric_all_gather_ttnn/README.md
- `ttnn.bringup.fabric_reduce_scatter` (fabric_reduce_scatter_ttnn): Python reduce-scatter over the fabric on fabric_all_gather's groups (mesh axis or whole-mesh snake; line, ring or two Hamiltonian cycles), row or column blocks, descriptor cache (opt-in `program_hash`: no per-call kernel-source hashing; opt-in `prepared`: dispatched through prepared_program), load-time `prepare()`; precision only (rule 7: cross-chip sums in bf16): opt-in exact fp32 adds.
  Consider instead of: ttnn.reduce_scatter, ttnn.experimental.reduce_scatter_minimal_async, ttnn.all_gather + ttnn.add for exact fp32 sums (precision only). -> fabric_reduce_scatter_ttnn/README.md
- `ttnn.bringup.prepare_program`, `run_prepared`; Python `prepared_program.generic_op` (prepared_program): a generic_op program prepared once and dispatched with only its io tensors' runtime-arg slots and CBs patched on a cache hit (host time only; Marko's MoE block and token-split exchange); opt-in `value_slots`: plain runtime args (a write offset) patched from per-run values.
  Consider instead of: ttnn.generic_op with one descriptor object reused every call. -> prepared_program/README.md
- `ttnn.bringup.prepare_chunk_recurrence` (prepare_chunk_recurrence): KDA chunk preparation with opt-in precise_gate_factors (exact anchored gate exponents, no TF32 bias near the -5 gate bound; a bias fix, realistic).
  Consider instead of: ttnn.experimental.kda.prepare_chunk_recurrence. -> prepare_chunk_recurrence/README.md
- `ttnn.bringup.moe_grouped_topk` (moe_grouped_topk): fused MoE gate after the gate matmul (activation, selection-only bias, grouped / single-group top-k, gather, normalize, route scale) in one program, with the source's fp32_selection; adds opt-in fp32_activation (the fp32 softplus for sqrtsoftplus routers: keys bit-identical to stock ttnn.sqrt(ttnn.softplus) on fp32; a fix, realistic).
  Consider instead of: ttnn.experimental.deepseek_prefill.moe_grouped_topk; a router chain ttnn.softplus / ttnn.sigmoid + ttnn.sqrt + ttnn.add + ttnn.topk + ttnn.gather + ttnn.sum + ttnn.multiply + ttnn.div. -> moe_grouped_topk/README.md
- `ttnn.bringup.update_padded_kv_cache` (update_padded_kv_cache): the stock KV cache write; ROW_MAJOR copy calls may write per-chip stripes / cache depths that are whole rows, not 32-row tiles (TP-dedup ratio-2 caches over 4 columns).
  Consider instead of: ttnn.experimental.deepseek_prefill.update_padded_kv_cache (ROW_MAJOR caches with non-tile stripes). -> update_padded_kv_cache/README.md
- `ttnn.bringup.ckv_bfp4`, `bfp_round` (ckv_bfp4_ttnn): bf16 TILE rows [.., n, 512] -> 320-byte bfloat4_b (or 576-byte bfloat8_b) row records (32 exponents twice + the values, written by the packer) written in place into a uint8 row table at row0 (or, blocks=True, bfloat8_b blocks of 32 rows a page), rounded to nearest even like the host packer (SFPU round before the pack; the packer alone truncates bfp4 in effect); optional bf16 output of the rounded values. bfp_round: bf16 TILE -> bfloat4_b / bfloat8_b TILE by the same rounding, new or in place at a tile row. Opt-in `prepared` (ckv_bfp4 and bfp_round): the program built once per shape, row0 / the first page patched (prepared_program value slot).
  Consider instead of: ttnn.typecast to bfloat4_b (truncates in effect) / bfloat8_b (half away) (+ a tile -> row reshuffle); host-side packing. -> ckv_bfp4_ttnn/README.md
- `ttnn.bringup.topk_large_indices` (topk_large_indices): per-row top-k ids (uint32) of a bf16 ROW_MAJOR tensor, Blackhole; carries upstream's split LLK (#62035 / #62488 / #62411: row split across MATH / PACK and core pairs) with its own LLK copy, plus the K' 512 split segmented body (k 512 rows past 32 x 512: Classic -> fused, 1.8-2.4x).
  Consider instead of: ttnn.experimental.topk_large_indices. -> topk_large_indices/README.md
