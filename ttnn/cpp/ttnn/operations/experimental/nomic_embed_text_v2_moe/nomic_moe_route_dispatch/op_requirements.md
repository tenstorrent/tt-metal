# Operation Requirements: nomic_moe_route_dispatch

## Definition
- **Formula**: `p[t,:] = softmax_E(x[t,:] @ W)` (fp32); `sel[t,0..1]` = top-2 of `p[t,:]`, ties to the lower expert; `wgt[t,k] = p[t,sel[t,k]]` (not renormalized); `counts[e]`; `start_e = sum_{e'<e} 32*ceil(counts[e']/32)`; slot (t,k) with `sel[t,k]=e` -> row `start_e + #{slots of e with token < t}`; `dispatched[row] = x[t]` (bit-exact; rows holding no slot are a bit-exact copy of some x row); `combine_index[k,t] = row`; `combine_weights[0,k,t,0] = wgt[t,k]`; `expert_counts[0,e] = counts[e]`; padded tokens `t in [T, T_pad)` get index 0 / weight 0.
- **PyTorch Reference**: `nomic_moe_route_dispatch_ref` in `eval/prompts/nomic_moe_route_dispatch.txt` (golden: `eval/golden_tests/nomic_moe_route_dispatch/helpers.py::pytorch_nomic_moe_route_dispatch`).
- **Import Path**: `from ttnn.operations.nomic_moe_route_dispatch import nomic_moe_route_dispatch`
- **Function Signature**:
  ```python
  nomic_moe_route_dispatch(
      input_tensor: ttnn.Tensor,            # x, (B, 1, S, 768) bf16 TILE
      weight: ttnn.Tensor,                  # W, (768, 8) fp32 TILE DRAM
      *,
      spare_tile_rows: int = 0,
      compute_kernel_config: ttnn.ComputeConfigDescriptor = None,
      memory_config: ttnn.MemoryConfig = None,   # placement of `dispatched`; None -> L1
  ) -> tuple[ttnn.Tensor, ttnn.Tensor, ttnn.Tensor, ttnn.Tensor]  # dispatched, combine_index, combine_weights, expert_counts
  ```

> **Refinement ID + follow-up naming (mandatory - the runner parses this)**: Primary refinements are `Refinement N` (e.g. `Refinement 1`, `Refinement 2`). (never `Refinement 1.5`, `Refinement 1 (follow-up)`, or a fresh number). Order follow-ups immediately after their parent so the queue runs them before later refinements - a partial's remaining-blocker follow-up must be picked next, not leapfrogged. The runner's parser matches exactly `Refinement \d+[a-z]?`; any other shape is invisible to the queue and silently skipped.

> **Perf-anchor note (verifier)**: every perf-flagged `LOOSE_CASE` runs the production contract (`in_placement = nd_norm`, `out_buffer_type = L1`, `tile_aligned`, bf16, default compute config = HiFi4 + `fp32_dest_acc_en=True`, model L1 occupancy). That contract is fully in Phase 0 SUPPORTED, so Refinements 1 and 2 have nothing to unlock for perf 1; they are ordered hardest first instead. Both touch kernels the production regime shares, so each must keep the production rows' device ns within noise (`test_nomic_moe_route_dispatch_perf.py`).

### [x] Phase 0 - Core Implementation

- **SUPPORTED dtype**: [bfloat16]
- **SUPPORTED layout**: [TILE]
- **SUPPORTED shape-derived axes**: alignment = [tile_aligned]
- **SUPPORTED op-specific axes**: fp32_dest_acc_en = [True], in_placement = [nd_norm], out_buffer_type = [L1]
- **Regime**: R1 `nd_push_l1` (op_design.md). x read in place from the layer norm's ND shard (G hidden slices per token group), W sliced from DRAM by G senders and multicast, intra-group partial-logit exchange, redundant softmax + top-2 per member, count-table gather + multicast, per-(row, slice, piece) NoC pushes into the owners' `dispatched` shards, landing barrier, in-place tilize on all 110 cores.
- **Cores**: all 110 (token work on x's `G*num_groups` shard cores, tilize on every core)
- **Compute config**: caller-provided honored (`fp32_dest_acc_en=False` refused); default HiFi4 + fp32 acc + approx off
- **Golden baseline**: 21 supported_pass (14 INPUTS + 7 LOOSE_CASES), 82 xfail_expected, 0 supported_fail / xpass_drift / xfail_wrong_mode (`verifier_report.json`)
- **Perf baseline (device kernel ns, warm, model L1 occupancy)**: 8x512 58.7 us (stock 45.6), 6x512 31.4 (32.6), 8x384 31.9 (32.6), 4x512 29.5 (30.3), 8x256 32.3 (30.1), 2x512 24.7 (22.6), 4x256 22.2 (23.5). **Slower than stock on 8x512, 8x256 and 2x512**: the contract ("must beat stock on every row") is not met yet.

### [x] Refinement 1 - DRAM-interleaved `dispatched` (output-side scheme change)

**Goal**: add `ttnn.BufferType.DRAM` to `SUPPORTED["out_buffer_type"]`: with `memory_config` of buffer type DRAM, `dispatched` is DRAM interleaved (`output_memory_config(R, device, DRAM)` already returns `ttnn.DRAM_MEMORY_CONFIG`). This is design regime `R4 dram_output`, a scheme change on the output side only: output ownership becomes a balanced split of the `R/32 x k` (row block, piece) shards over all 110 cores (`split_work_to_cores`, row-wise), the pushes keep targeting the owner's `cb_gathered_rows` staging exactly as R1 does, and each owner tilizes its blocks into a streaming output CB (depth >= 2, whole-tile blocks of `w` tiles) that the owner's writer drains to DRAM with a TensorAccessor (batched writes, one barrier per block, not per tile). Unlocks the `out_buffer_type = DRAM` cells for every in_placement already supported.

**Verifier notes**: stands alone (scheme change: the ownership map and the tilize sink change; no input-side work). Ordered first because it changes how output ownership is derived; Refinement 2 then adds input placements on top of a settled output side. The output-side work must spread over the full grid and batch the DRAM writes from the start (the performance-conformance bar applies to the new path). The `_l1_room` check must stop reserving `dispatched` bytes in L1 when the output is in DRAM, and `circular_buffer_bytes()` must reflect the streaming output CB. No skill covers the output ownership remap; `/interleaved-parallel` covers the `split_work_to_cores` plumbing for the owner split.

**Implementation skill**: /interleaved-parallel

**Done when**: every golden cell with `out_buffer_type = DRAM` and an already-supported `in_placement` / `alignment` passes; production rows (`nd_norm`, L1 out) show no device-ns regression.

**Outcome**: 14/14 tile-aligned nd_norm DRAM golden cells pass. DRAM-out device us (warm, model L1 occupancy): 8x512 101.7, 6x512 66.1, 8x384 69.9, 4x512 55.5, 8x256 52.8, 2x512 35.2, 4x256 34.5. The DRAM tail over the L1 path (~44 us at 8x512) matches 12.9 MB written at ~290 GB/s: DRAM write bandwidth bound and serialized behind the global landing barrier. L1 rows unchanged within noise. Next lever: per-owner counted arrival (Refinement 5) would let DRAM writes overlap the push phase.

### [x] Refinement 2 - Interleaved input placements + ragged token counts

**Goal**: add `"l1_interleaved"` and `"dram_interleaved"` to `SUPPORTED["in_placement"]` and `"ragged"` to `SUPPORTED["alignment"]`.
- **Interleaved x** (design regime `R2 interleaved_input`, a knob-turn): `G = 1`, so every token core is a one-member group holding whole rows (no partial exchange, W slice offset 0, one slice = the whole row, `k` push writes per row). Token tile rows are spread over the full grid with `split_work_to_cores` (row-wise), each core's block = all its tile rows (coarsest block that fits L1, `rps` bounded by the packed count table / DEST cap, or the cap lifted with the cap's reason re-checked). The reader replaces the zero-copy sharded publish with batched TensorAccessor tile reads of its rows into a real `cb_x_tiles` (one barrier per block, not per tile), from L1 or DRAM. Group count / leader / coordinator bookkeeping follows from `G = 1`.
- **Ragged** (design regime `R3 ragged_tokens`, B = 1, T % 32 != 0, both `nd_norm` and interleaved x): the last tile row holds `T % 32` real tokens; selection, counts and pushes run over a per-core RT real-token count; padded tokens get `combine_index = 0`, `combine_weights = 0.0` and are never counted; pad rows carry real tokens only (`r mod T`). The tile-padding rows of x are never selected and never pushed.

**Verifier notes**: bundled because both re-derive each core's token range (interleaved: a `split_work_to_cores` range instead of the shard map; ragged: a real-token count inside it) and touch the same reader, selection and push code. Interleaved is a knob-turn on the blocking model (G collapses to 1, the count exchange already exists), not a new topology. The L1-resident x of `l1_interleaved` must still be read through the TensorAccessor (it is not a local shard); `dram_interleaved` crosses DRAM once. `circular_buffer_bytes()` is documented on the nd_norm plan; keep it so and add the interleaved CBs to `cb_bytes(plan)` for the L1 check. If the interleaved token split leaves cores without token work, they still own output shards; fill the grid with token work (the design's performance-conformance bar).

**Implementation skill**: /interleaved-parallel, /memory-layouts

**Done when**: every golden cell with `in_placement in {l1_interleaved, dram_interleaved}` and every `ragged` cell (B = 1, `1x1000_ragged`, `1x3000_ragged`) passes for every supported `out_buffer_type`; production rows show no device-ns regression.

**Outcome**: 68/68 targeted golden cells pass (all interleaved x and ragged cells, L1 and DRAM out). Interleaved-in device us (L1 out, model occupancy, single run): 8x512 55.9 dram / 50.0 l1, 6x512 41.7 / 39.9, 8x384 41.2 / 41.7, 4x512 35.1 / 28.9, 8x256 34.7 / 32.7, 2x512 29.0 / 25.8, 4x256 28.9 / 25.8. Production nd_norm L1 rows A/B against the pre-change commit (2 runs each) overlap within the +-3 us run-to-run noise.

### [x] Refinement 3 - Speed up the row-push phase on the primary perf shape

**Type**: perf

**Goal**: `feature_spec.LOOSE_CASES` flags 8x512 (T = 4096, R = 8416, model L1 occupancy) as the primary PERF FOCUS: stock 45.6 us, target <= 5.6 us; Phase 0 measures 58.7 us, slower than stock. Zone profile of the Phase 0 kernels at 8x512 (profiler build, 85.7k cycles total): the push phase alone is ~38k cycles (45%), with a 2.1x max/median spread across token cores (R_push median 17.9k, max 37.7k cycles; W_push median 11.9k, max 24.7k). Two visible causes: (1) all `R - 2T` pad rows carry tokens `r mod T`, i.e. tokens 0..~350, so the first few groups' cores push every pad row; (2) with G = 3, k = 2 the middle member straddles both output pieces and issues twice the writes of members 0 and 2 (design lamp L2 / regime R5). The base rate is also low (~90 cycles per 512-768 B write at `PUSH_BYTES_IN_FLIGHT = 4096`). Levers, from `ttnn/ttnn/operations/examples/master.md` and the design's lamps: spread pad rows evenly over the token cores (the contract allows any x row in a pad row), balance per-core write counts across members and across the two DM RISCs (`split_reader`, lamp L2), co-tune `PUSH_BYTES_IN_FLIGHT` (bytes in flight), stagger each core's walk so cores do not hit the same owners in lockstep (`bank_stagger`, lamp L7), and NoC choice per destination (`noc_placement`, lamp L8). No SUPPORTED change.

**Verifier notes**: T2 levers, several fit one phase. Measure with `tests/ttnn/unit_tests/operations/nomic_moe_route_dispatch/test_nomic_moe_route_dispatch_perf.py` under `scripts/run_safe_pytest.sh --profile` (with `TT_METAL_HOME` pointing at another checkout, the CSV lands under `$TT_METAL_HOME/generated/profiler/reports/`). Must also run on the paths Refinements 1 and 2 add (DRAM output, interleaved input) without regressing them.

**Done when**: measured device ns on 8x512 improves materially (at minimum below stock 45.6 us), the golden suite is green, the soft precision bars still hold, and no regression across the config-spanning guard set (one representative per kernel path: nd_norm/L1-out at rps = 1, 2, 4; DRAM-out; l1- and dram-interleaved input; ragged).

**Outcome**: 8x512 (L1 out, model occupancy) 57.7 -> 45.9 us median (runs 45.1 / 45.9 / 46.3 / 45.9, best 43.9 with zones), i.e. at stock parity (45.6), not decisively below it; DRAM out 104.1 -> ~91; 2x512 22.8 -> ~19.7; no guard-set row slower (interleaved rows A/B'd against the pre-refinement commit back to back: equal or faster). Push phase, slowest RISC: ~30k -> ~16.6k cycles. Landed: pad rows spread over every pushing RISC; whole-piece push (G=3,k=2 and G=2,k=3: the member holding most of a piece gathers the rest from its peers' x shards and pushes one write per piece; 2 writes a row instead of 4 at 8x512); leaner issue path (local ack accounting, unrolled pieces, no escaping state); bytes-in-flight cap per RISC's average write. Measured nulls, kept as knobs at their no-op default: PUSH_BYTES_IN_FLIGHT 2-16 KB flat (not credit-bound), PUSH_STAGGER_TOKENS flat, PUSH_CMD_BUFS = 2 slower. NoC swap (reader on NOC1) helps L1-out 8x512 by ~4 us but costs DRAM out ~30 us, not adopted. Bottleneck now: the pre-push critical path (push starts at ~37-39k of ~60k cycles, +-4 us run to run), Refinement 4's scope; the push itself is issue-bound at ~90 cycles a 768 B write (~35 software). Next push lever: stage full rows on every member and round-robin pieces by row (2/3 write a row a member; member 1 is idle during the push now), worth ~5k cycles, but its 96-tile untilize (~100 cycles a tile) overruns the W-fetch shadow (~10k cycles), so it needs the untilize moved off the compute critical path first; not done here.

### [x] Refinement 4 - Shorten the pre-push critical path on every perf-flagged row

**Type**: perf

**Goal**: all flagged rows must beat stock (2x512 is 24.7 us vs 22.6 stock; 8x256 32.3 vs 30.1) and move toward their targets (8x512 5.6 us, 4x512 / 8x256 2.9 us, 2x512 / 4x256 1.5 us). Before the first push starts, the 8x512 zone profile shows ~45k cycles of serial phases: W slice fetch + multicast (compute waits up to 13.9k cycles; `R_wwait` max 11k), partial exchange (ends ~20.5k), logits + softmax over `rps` fp32 tiles (~11.5k cycles), scalar top-2 selection + count row (~10k cycles for 64 tokens per RISC), table gather + multicast (~2k). Levers: take the W fetch off the front (fewer bytes per lamp L5: faces 0 and 2 only; issue it before anything else on the sender cores; `mcast_topology`), cut the fixed per-phase cost of the softmax chain on few tiles (fuse the logits/mask/softmax chains, `compute_fusion` / `sfpu_tile_scope`; keep HiFi4 + fp32 acc), speed the scalar selection (unrolled register-resident top-2, fewer volatile L1 loads), and re-place the untilize per lamp L1. Profile the rps = 1 rows (2x512, 4x256) separately: their fixed costs dominate. No SUPPORTED change; the default precision must not be lowered.

**Verifier notes**: mostly T2 levers on the same shapes as Refinement 3, but disjoint code regions (compute chain, W delivery, selection) from the push phase, so it is a separate phase. Lowering fidelity or turning off fp32 accumulation does not count (prompt Rules).

**Done when**: every perf-flagged row (8x512, 4x512, 8x256, 2x512, 4x256) and the 6x512 / 8x384 rows beat their stock ns at model L1 occupancy, the golden suite is green, the soft precision bars hold, and no regression across the guard set.

**Outcome**: device us at model L1 occupancy (median of 3, before = this run's pre-change measurement, stock in parentheses): 8x512 46.0 -> 39.6 (45.6), 6x512 31.0 -> 27.2 (32.6), 8x384 30.8 -> 26.9 (32.6), 4x512 30.5 -> 24.9 (30.3), 8x256 26.9 -> 24.3 (30.1), 2x512 18.9 -> 16.4 (22.6), 4x256 21.1 -> 17.2 (23.5): every row beats stock. DRAM out 8x512 ~90 -> 85.3, 2x512 ~32 -> 29.0; interleaved x equal or faster (A/B against the R3 commit). 8x512 push start ~40.3k -> ~30.4k cycles. Landed: W senders issue first and odd slices go out on the writer / NOC1 (`W_SLICE_NOCS = 2`; full-grid linked multicasts on one NoC serialized at ~1.3-2.5k cycles each, and the whole-piece stage gather on NOC0 delayed them further: last slice 7.7-11.5k -> ~6k); stage gather moved to the writer (NOC1); untilize moved after the softmax into the select shadow (matmul runs as soon as W lands); exp on faces 0/2 only (VectorMode::C custom chain element) with an 8-column sum scaler and a finite -1e30 mask (8x512 exp 4.3k -> 2.3k cycles; columns 0..7 unchanged); register-resident select (packed u32 counters, face-stride walk: 9.3k -> 7.2k cycles at 64 tokens a RISC). Measured null, reverted: W faces 0/2 only as 16 unlinked 1 KB multicasts (each multicast ~550 cycles fixed, 60.8 us). Bottleneck now (8x512): logits chain ~4.7k cycles (copies + 2 SFPU adds + Where over full tiles; neither binary add nor Where exposes a vector mode through the compute API), selection ~7.2k (L1-load bound, redundant on every group member), table gather + scan ~3k. Next: split selection across the G members with a slot/count exchange (~3k cycles at 8x512, adds a NoC round and per-segment rank bases in the push walk); not done here because it restructures the slot-page contract shared by the push and combine_index paths.

### [x] Refinement 5 - Overlap tilize with the pushes (per-owner counted arrival)

**Type**: perf

**Goal**: replace the global landing barrier (every owner waits for the slowest pusher, then tilizes) with per-owner counted arrival (design lamp L3): each pusher RISC atomically adds the number of rows it wrote into each owner shard's counter (or per-owner semaphore), and owners tilize each block as soon as it is complete, overlapping tilize with the tail of the push phase. Target the flagged 8x512 shape first, then the remaining flagged rows. Pattern references in `ttnn/ttnn/operations/examples/master.md`: `double_buffer`, `tensix_all_reduce` (semaphore-counted arrival). No SUPPORTED change.

**Verifier notes**: T3 (synchronization restructure), so a whole phase. Ordered after Refinement 3 because balancing the pushes first shrinks the tail this overlap can hide; measure whether the remaining tail justifies it before building. Atomic increments per row must not swamp the NoC: count per block or per RISC batch.

**Done when**: measured device ns improves on 8x512 and on the other flagged rows, the golden suite is green, and no regression across the guard set.

**Outcome**: device us at model L1 occupancy (3 runs, before -> after): 8x512 39.7/39.9/40.6 -> 38.9/38.8/39.2; 6x512, 8x384, 4x512, 8x256, 2x512, 4x256 unchanged within noise (27.1-27.5, 27.1-28.0, 23.8-27.4, 23.5-25.4, 16.5-16.6, 16.4-17.2 -> 27.1-27.5, 27.4-28.0, 24.1-25.2, 23.7-25.4, 16.5-16.6, 16.6-16.7); DRAM out 8x512 and interleaved x 8x512 / 2x512 equal (A/B). Built per-owner counted arrival as the `ARRIVAL_PER_BLOCK` knob (semaphore per owned block counting 64 B row granules, one atomic per (tile row, piece) run after each RISC's write barrier, owners publish blocks as they complete): correct (unit + golden slice green), parked off because it is slower: Blackhole atomics are non-posted INCR_GET at ~160-200 cycles each, 15-20 a RISC = 2.8-3.4k cycles after every push, more than the ~2.4k-cycle coordinator hop + ~1.5k-cycle tilize overlap it removes (8x512 ~parity, every rps <= 2 row +1-2 us). Full-grid multicast atomics (one per RISC) measured 160+ us; alternating two command buffers for the atomics hung. What the barrier hid at 8x512 was the leaders' 1 MB of combine_weights DRAM writes (8 x 4 KB a leader, ~5-10k cycles to inject under push traffic); `WEIGHTS_SPREAD` (member c writes tiles c, c+G, ...) is the lever that landed. Bottleneck now (8x512): last push ends ~48.5k cycles, the landing go reaches owners ~51.0k, tilize ends ~53.3k; the push itself and the pre-push path (push start ~31k, +-2k run to run) dominate. Next: cheaper arrival signalling (reader and writer of a core split one core-level atomic set after a local handshake, contiguous pad chunks per unit: ~halves the atomics) would make `ARRIVAL_PER_BLOCK` worth re-measuring; not done because the measured margin (<= ~1.5k cycles at 8x512, negative at rps <= 2) is inside the run-to-run noise.
