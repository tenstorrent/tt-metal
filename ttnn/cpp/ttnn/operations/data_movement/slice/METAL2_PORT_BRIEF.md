## Construct — to do

**Tensor bindings.** Twelve bindings across five factories. Ten are **Case 1** and two are **clean**. There is no Case 2 anywhere in this op: no kernel does hand-rolled address arithmetic on a buffer base, so you never need the `get_bank_base_address` bridge.

Every Case-1 binding arrives today by the same route: the factory pushes a `Buffer*` into runtime-argument **slot 0** of the kernel (or into common-argument slot 0/1/2 for the two tile readers), and the kernel builds `TensorAccessor(args, addr)` from it. Express each as a `TensorParameter` / `TensorBinding`; the kernel then builds `TensorAccessor(tensor::name)`, and both the `Buffer*` argument and the `TensorAccessorArgs(...).append_to(...)` plumbing disappear.

## Watch for

- **Cross-op / shared kernels.** One borrowed kernel file, and a **`_metal2` fork already exists beside it**: bind the fork, do not create a second one.

  `SliceTileTensorArgsProgramFactory` instantiates `ttnn/cpp/ttnn/operations/eltwise/unary/device/kernels/dataflow/writer_unary_interleaved_start_id.cpp` by file path ([device/slice_program_factory_tile_tensor_args.cpp:132-133](device/slice_program_factory_tile_tensor_args.cpp#L132-L133)). Point `KernelSpec::source` at the sibling `writer_unary_interleaved_start_id_metal2.cpp` in that same directory and adopt its names: `dfb::out`, `tensor::dst`, `args::num_pages`, `args::start_id`. The fit is exact: slice's writer arguments are already the destination buffer plus exactly the two scalars the fork reads, `num_pages` and `start_id` ([:168](device/slice_program_factory_tile_tensor_args.cpp#L168)). The fork keeps `#ifdef OUT_SHARDED` and `#ifdef BACKWARDS`; slice defines neither, so add no `compiler_options.defines`. Do not edit the fork: it already has consumers.

  *Other ops binding the legacy copy: about 30 factories, tracked in issue [#52228](https://github.com/tenstorrent/tt-metal/issues/52228). That set is a **sunset list, not authorization to convert the kernel in place.*** The full list is in `METAL2_PREPORT_AUDIT.md`; record in your port report that slice is now off the legacy copy.

  None of slice's own nine kernel files is bound by any other non-quasar op, so they convert in place with no fork.

- **`ccl/mesh_partition` calls this op's factory entry points from its own host code, and it cannot co-migrate.** It calls `SliceOp::validate_on_program_cache_miss`, `SliceOp::select_program_factory` and `Factory::create_descriptor` inside its `create_at`, and `ttnn::prim::patch_slice_program_addresses` inside its own `override_runtime_arguments` ([../../ccl/mesh_partition/device/mesh_partition_program_factory.cpp:117-158](../../ccl/mesh_partition/device/mesh_partition_program_factory.cpp#L117-L158)). It also stores a `prim::SliceDeviceOperation::program_factory_t` in its cached shared variables ([../../ccl/mesh_partition/device/mesh_partition_device_operation.hpp:45-50](../../ccl/mesh_partition/device/mesh_partition_device_operation.hpp#L45-L50)). The readiness sheet lists it as `legacy (MeshWorkload)` with `Is able to port? = no`, so it stays on the legacy path. Renaming `create_descriptor` to a spec-returning method, or changing the signature of `patch_slice_program_addresses`, breaks its build. Plan for it before you start, and record the outcome as an open item for downstream.

- **Two host helpers exported from this op's header are called by four other ops.** `get_rm_start_offset` and `get_tiled_start_offset` ([device/slice_device_operation.hpp:23-25](device/slice_device_operation.hpp#L23-L25), defined at [device/slice_device_operation.cpp:59-91](device/slice_device_operation.cpp#L59-L91)) are pure host-side index arithmetic and are called from `experimental/padded_slice`, `experimental/slice_write` and `experimental/transformer/nlp_kv_cache_load_slice`. Leave both the declarations and the definitions where they are.

- **RTA varargs: six kernels, one of them unusually strong.** Reach for the vararg mechanism rather than trying to name each element. In every case the fixed scalars come first and the variable-count block comes last, so there are no nameable trailing scalars to rescue from the varargs.

  The rank ≤ 4 stride kernels are **not** varargs, even though they look similar: they read a fixed run of 25 and 9 arguments through a running `rt_args_idx++` ([reader_multicore_slice_4d.cpp:52-77](device/kernels/dataflow/reader_multicore_slice_4d.cpp#L52-L77), [writer_multicore_slice_4d.cpp:52-61](device/kernels/dataflow/writer_multicore_slice_4d.cpp#L52-L61)). Name each of those. Both stick-layout writers and both tile writers are likewise all-named.

  **No CTA varargs.** No kernel reads `get_compile_time_arg_val` at a varying index, so you need no `compile_time_varargs`.

- **The `id_per_dim` vararg is written by the kernel, not just read.** Four readers use their runtime-argument region as mutable per-core scratch: `id_per_dim[j]++` and `id_per_dim[j] = 0` write straight back into argument memory ([slice_reader_unary_unpad_dims_rm_interleaved_start_id.cpp:77-79](device/kernels/dataflow/slice_reader_unary_unpad_dims_rm_interleaved_start_id.cpp#L77-L79), [reader_unary_unpad_dims_interleaved_start_id.cpp:45-47](device/kernels/dataflow/reader_unary_unpad_dims_interleaved_start_id.cpp#L45-L47), [reader_unary_unpad_dims_interleaved_start_id_tensor_args.cpp:124-127](device/kernels/dataflow/reader_unary_unpad_dims_interleaved_start_id_tensor_args.cpp#L124-L127)). Two consequences: the vararg has to be writable on the kernel side, and the host has to re-emit the initial values on **every** dispatch, not only on a cache miss. The legacy code already does the re-emission ([device/slice_program_factory_tile.cpp:268-271](device/slice_program_factory_tile.cpp#L268-L271)); keep it in the translated `override_runtime_arguments`.

- **Two tile kernels already read their CB index through a named compile-time argument.** [device/slice_program_factory_tile.cpp:139](device/slice_program_factory_tile.cpp#L139) and [:161](device/slice_program_factory_tile.cpp#L161) set `named_compile_time_args = {{"dfb_id_in", …}}` / `{{"dfb_id_out", …}}`, and the kernels read them with `get_named_compile_time_arg_val` ([reader:12](device/kernels/dataflow/reader_unary_unpad_dims_interleaved_start_id.cpp#L12), [writer:19](device/kernels/dataflow/writer_unary_interleaved_start_id.cpp#L19)). Those two are already part-modernized: the port is a binding-layer change there, replacing the named index with the `dfb::name` token, not an idiom rewrite. Note that the slice-owned `writer_unary_interleaved_start_id.cpp` differs from its `eltwise/unary` namesake **only** in this respect (its own header comment says so at [:5-7](device/kernels/dataflow/writer_unary_interleaved_start_id.cpp#L5-L7)); do not confuse the two files, and do not point the tile factory at the `eltwise/unary` fork, since the tensor-args factory is the one that borrows from there.

- **A `const`-versus-`constexpr` declaration that decides token form.** In the tensor-args reader, `tile_width` and `tile_height` come from `get_compile_time_arg_val` but are declared `const uint32_t`, while every neighbouring compile-time read in the same function is `constexpr` ([reader_unary_unpad_dims_interleaved_start_id_tensor_args.cpp:12-19](device/kernels/dataflow/reader_unary_unpad_dims_interleaved_start_id_tensor_args.cpp#L12-L19)). Decide deliberately whether each becomes a `constexpr` token or a member getter; do not copy the inconsistency forward without looking.

- **The row-major kernels rely on the accessor's implicit page size, and the factory asserts that.** Both `SliceRmProgramFactory` kernels build the two-argument accessor, so they stride by whatever aligned page size `TensorAccessorArgs` bakes in. `check_accessor_page_size` ([device/slice_program_factory_rm.cpp:292-308](device/slice_program_factory_rm.cpp#L292-L308), called at [:337-340](device/slice_program_factory_rm.cpp#L337-L340)) asserts host-side that the per-shard page size and the accessor's aligned page size agree, so a caller that skips `slice.cpp`'s resharding guard fails loudly instead of mis-addressing. Metal 2.0 supplies the same aligned page size implicitly from the binding, so the assertion's premise is unchanged. Keep it.

- **Kernel index 0 is the reader and index 1 is the writer, and the current cache-hit path depends on it.** `patch_slice_program_addresses` addresses kernels by hardcoded index ([device/slice_program_factory_rm_sharded.cpp:371](device/slice_program_factory_rm_sharded.cpp#L371)), and all four two-kernel factories push the reader before the writer. `SliceTileTensorArgsProgramFactory` is the one to look at twice: it *builds* the writer descriptor first ([:131-137](device/slice_program_factory_tile_tensor_args.cpp#L131-L137)) but *pushes* it second ([:188-190](device/slice_program_factory_tile_tensor_args.cpp#L188-L190)). Named bindings remove the dependence on the ordering, which is the point, but check it before you rely on the new naming.

- **The quasar copy of this op is out of bounds.** `ttnn/cpp/ttnn/operations/experimental/quasar/slice/` holds a full pre-port copy of all five factories and every one of these kernels, including `_metal2`-suffixed files. Grepping any slice kernel basename will hit it. It is not a template, not a naming source, and not evidence that any construct ports. Skip those hits.

- **One binding you will carry exists only to feed a dead variable.** `SliceTileTensorArgsProgramFactory`'s `end_tensor` binding is fully wired (accessor arguments, a common runtime argument, a per-hit address patch, a whole CB staging read) and the value it produces, `end_indices`, is never used; the kernel marks it `[[maybe_unused]]` ([reader_unary_unpad_dims_interleaved_start_id_tensor_args.cpp:49](device/kernels/dataflow/reader_unary_unpad_dims_interleaved_start_id_tensor_args.cpp#L49), written at [:80-82](device/kernels/dataflow/reader_unary_unpad_dims_interleaved_start_id_tensor_args.cpp#L80-L82)). **Port the binding anyway.** Removing it would be a functional change and is out of port scope; the audit has raised it with the ops team.
