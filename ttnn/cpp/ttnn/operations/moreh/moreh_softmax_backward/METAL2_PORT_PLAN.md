# Port Plan — `moreh_softmax_backward`

Port plan for `ttnn/cpp/ttnn/operations/moreh/moreh_softmax_backward`, ported from
`ProgramDescriptorFactoryConcept` (`create_descriptor`) to Metal 2.0
(`ProgramSpecFactoryConcept` / `create_program_artifacts`).
Written during the inventory and planning steps; committed alongside the port for review.

**Assignment:** all five factories in one change (invoker-confirmed). That settles the
shared-kernel rung — see [Shared kernels](#shared-kernels).

## Legacy Inventory

### Legacy factory shape

- Concept: `ProgramDescriptorFactoryConcept` — five `static tt::tt_metal::ProgramDescriptor
  create_descriptor(...)` declarations generated by the `DEFINE_SOFTMAX_BACKWARD_FACTORY` macro,
  `device/moreh_softmax_backward_device_operation.hpp:50-63`.
- Variants: five factories in one `program_factory_t` variant
  (`...device_operation.hpp:65-70`): `CLarge`, `HLarge`, `WLarge`, `HSmall`, `WSmall`.
  Selected by `get_parallelization_strategy` (`...device_operation.cpp:119`).
- Custom `compute_program_hash`: **none** — default reflection-based hash. Nothing to leave
  intact, nothing to touch.

Three math variants (`SOFTMAX` / `SOFTMIN` / `LOGSOFTMAX`→`LOG`) plus `FP32_DEST_ACC_EN` are
carried on one kernel set through `defines`, not through separate sources.

The five factories are near-identical in shape. The `W`/`H` pairs differ from each other only in
which axis is reduced; within a pair, `Small` differs from `Large` only in DFB depths, the extra
`c_27` buffer, the reader's `LOG` define, and the kernel sources. `CLarge` is the outlier: no
scaler/mask buffers, and a different RTA set.

### Flags

- **Two unreferenced kernel files** in `device/kernels/`: `writer_moreh_softmax_backward_h.cpp`
  and `writer_moreh_softmax_backward_w.cpp`. Bound by no factory in the repo, so **not audited and
  not ported**. They are near-name-twins of the two writers that *are* bound; the port leaves them
  untouched on the legacy API.
- **Dead reader RTA in both W factories.** `std::bit_cast<uint32_t>(scaler)` is pushed at reader
  RTA index **5** (`softmax_backward_w_small.cpp:240`, `softmax_backward_w_large.cpp:256`) but
  `reader_moreh_softmax_backward_w.cpp:19` and `..._w_large.cpp:19` read `mask_w` from index **6**
  and never touch index 5 — the W readers get their scaler on-device from
  `dataflow_kernel_lib::calculate_and_prepare_reduce_scaler`. See [Dropped Plumbing](#dropped-plumbing).
- **Unused kernel locals** carried by the legacy sources: `uint32_t l1_write_addr_in;` in all four
  H/W readers, `constexpr uint32_t onetile = 1;` in the two W/H writers. Out of port scope; noted
  in the report.
- **Same-FIFO aliasing in the compute kernels** — one buffer reached through several kernel-side
  names. Not a legacy defect; it needs a specific Metal 2.0 shape. See
  [Applied Patterns](#applied-patterns).
- The op's `unpack_to_dest_mode` vector is all-`Default` in every factory, but Metal 2.0's
  validator *requires* an explicit entry in a case legacy defaulted silently. See
  [Planned Spec Shape](#planned-spec-shape).

## TTNN ProgramFactory

- **Concept (inherited from audit)**: `ProgramSpecFactoryConcept` (plain — no op-owned tensors).
- **Custom `compute_program_hash`**: none.
- **Implementation notes**: the five factories live in five `.cpp` files in one unity-built CMake
  target (`TT_ENABLE_UNITY_BUILD(ttnn_op_moreh)`, `ttnn/cpp/ttnn/operations/moreh/CMakeLists.txt:7`),
  and they need the same spec-name constants and the same three or four small helpers. Per
  *Pattern: Unity-build hygiene for anonymous-namespace symbols*, those go in one shared header —
  `device/moreh_softmax_backward_metal2_common.hpp` — with `inline` linkage, rather than in five
  anonymous namespaces that the unity build would merge into one scope.

  The `DEFINE_SOFTMAX_BACKWARD_FACTORY` macro in the device-op header changes its declared method
  from `create_descriptor` to `create_program_artifacts`; the five factory structs are otherwise
  untouched, and the `program_factory_t` variant is unchanged.

Uniform across all five factories except where noted. `X` denotes the factory's reduction extent
(`Wt` for the W pair, `Ht` for the H pair).

### DFB endpoint dispositions (census re-derived, not transcribed)

Per node each factory runs exactly one reader, one writer, and one compute instance — the two
compute `KernelSpec`s cover **disjoint** core groups. Counting distinct touchers per node:

| DFB | touchers on a node | census | disposition |
|---|---|---|---|
| `y`, `dy` | reader (`reserve_back`/`push_back`), compute (`wait_front`/`pop_front`) | 2, one locked to each role | plain 1P+1C — reader PRODUCER, compute CONSUMER |
| `scaler` | reader (via `generate_bcast_scaler` / `calculate_and_prepare_reduce_scaler`), compute (`wait_front` inside `compute_kernel_lib::reduce`) | 2 | plain 1P+1C |
| `mask` | reader (via `generate_mask_h` / `generate_mask_w`), compute (`wait_front` inside `mask_tile_to_cb`) | 2 | plain 1P+1C |
| `dx` | compute (`reserve_back`/`push_back`), writer (`wait_front`/`pop_front`) | 2 | plain 1P+1C — compute PRODUCER, writer CONSUMER |
| `ydy`, `sum`, `dy_m_sum`, `add` | compute only | **1** | **self-loop** — compute bound PRODUCER *and* CONSUMER |

This agrees with the brief. `scaler` and `mask` are waited once and held (`popm=0` at every mask
call site), which is a legal held 1:1 FIFO, not a missing endpoint. No DFB reaches ≥3 touchers or
≥2 kernels locked to the same role, so **`allow_instance_multi_binding` is not set anywhere**, and
no DFB is both self-looped and multi-bound. No DFB has zero endpoints, so nothing is dropped.

### Compute `hw_config`

Style A: the op resolves a TTNN `ComputeKernelConfig` and feeds its fields to a legacy
`ComputeConfigDescriptor`. Ported with `to_compute_hardware_config(device->arch(),
operation_attributes.compute_kernel_config)`, which applies the two non-1:1 transforms
(`math_approx_mode` bool → `sfpu_precision_mode` enum; `dst_full_sync_en` → **inverted**
`double_buffer_dest`). `get_compute_kernel_config_args` is a pure field unpack with no arch
fixups, so feeding the attribute config directly is exact.

`bfp_pack_precision_mode`: legacy never set `bfp8_pack_precise`, so it stays at its default —
the defaults coincide.

**`unpack_modes` — the one place the port must add something legacy did not have.** Legacy set
`unpack_to_dest_mode` to all-`Default`, which maps to `UnpackMode::UnpackToSrc`, normally
expressed by omitting the entry. But Metal 2.0's validator *requires* an explicit entry when a
compute kernel **consumes a Float32 DFB with `enable_32_bit_dest = true`**
(`tt_metal/impl/metal2_host_api/program_spec.cpp:1049-1078`). Under `fp32_dest_acc_en` the four
intermediates are Float32 by construction, and the data-format DFBs are Float32 too when the
tensor dtype is `FLOAT32`. So: for every DFB the compute kernel **consumes**, emit
`UnpackMode::UnpackToSrc` when `fp32_dest_acc_en && format == Float32`. That is the legacy value
(`Default` → `UnpackToSrc`), derived, not guessed. Consumed DFBs are `y`, `dy`, `scaler`, `mask`
and the self-looped intermediates (a self-loop binds CONSUMER, so the consumer rules govern it);
`dx` is producer-only and gets no entry.

### `opt_level`

`grep -n opt_level` over the op directory returns **zero** hits — no factory sets the field on any
`KernelDescriptor`. Resolved legacy levels are therefore `O2` for the reader/writer descriptors
and **`O3`** for the `ComputeConfigDescriptor`s. Metal 2.0's `CompilerOptions::opt_level` defaults
to `O2` for both kinds, so:

- reader / writer `KernelSpec`s: leave `opt_level` alone (`O2` matches).
- **every** compute `KernelSpec` — both `compute_g1` and `compute_g2`, in all five factories —
  sets `.compiler_options.opt_level = KernelBuildOptLevel::O3` explicitly.

## Preserved Multiplicity

| legacy KernelDescriptors | same-source KernelSpecs | WorkUnitSpecs | shared DFBs (endpoint role each binds) |
|---|---|---|---|
| `compute_desc_1` (`core_group_1`) + `compute_desc_2` (`core_group_2`), same source, differing only in the leading CTA (`num_tiles_per_core_group_1` vs `_2`) | `compute_g1`, `compute_g2` of the same source, each carrying its own group's CTA | `wu_g1` (`core_group_1`), `wu_g2` (`core_group_2`) | `y` CONSUMER, `dy` CONSUMER, `scaler` CONSUMER, `mask` CONSUMER, `dx` PRODUCER, and PRODUCER+CONSUMER on each self-looped intermediate — **identical bindings on both specs** |

The node sets are **disjoint**, so each node still sees exactly one compute instance: two
`KernelSpec`s bound to one endpoint role is legal here precisely because their coverage does not
overlap (`dataflow_buffer_spec.hpp` endpoint invariant). This is **not** the same-grid two-toucher
work-split, and it is **not** the multi-binding flag. Collapsing the pair into one `KernelSpec` by
demoting the per-group CTA to an RTA is the *Demoting per-group CTA to RTA* anti-pattern and is
not done.

Repeated identically in all five factories.

## Applied Patterns

- **[Self-loop DFB binding](../../../../../../docs/source/tt-metalium/tt_metal/apis/host_apis/metal_2.0/ai/shared/port_patterns.md#pattern-self-loop-dfb-binding)** —
  the compute-local intermediates (`ydy`, `sum`, `dy_m_sum`, and `add` in the two `*Large` W/H
  factories) are touched by the compute kernel alone. Each is bound PRODUCER **and** CONSUMER on
  the compute `KernelSpec` under a single shared `accessor_name` (the validator's explicit
  self-loop-pair relaxation, `program_spec.cpp:298-303`).
- **[Same-FIFO aliasing (one DFB, multiple kernel-side names)](../../../../../../docs/source/tt-metalium/tt_metal/apis/host_apis/metal_2.0/ai/shared/port_patterns.md#pattern-same-fifo-aliasing-one-dfb-multiple-kernel-side-names)** —
  the compute kernels reach one buffer through several names, and the legacy code backs each name
  with its **own** `DataflowBuffer` object: `c_24` is `cb_ydy` / `cb_exp` / `cb_inter0`, `c_25` is
  `cb_sum` / `cb_inter1`, `c_26` is `cb_inter2` / `cb_dy_m_sum` (with an inner redeclaration
  shadowing the outer one). These are *not* aliased DFBs — it is one buffer with one set of FIFO
  pointers. The port keeps **one `DataflowBufferSpec`, one `DFBBinding` pair, and one
  `DataflowBuffer` object** per index, and expresses the alternate names as `constexpr auto`
  handle aliases over the single binding. The validator enforces this directly: a second binding
  of the same role under a different accessor name is rejected
  (`program_spec.cpp:355-368`). Role comments on the deleted duplicate objects are relocated,
  not dropped (whitelist rule 8).
- **[Pass DFB handles directly to LLKs and kernel-lib helpers](../../../../../../docs/source/tt-metalium/tt_metal/apis/host_apis/metal_2.0/ai/shared/port_patterns.md#pattern-pass-dfb-handles-directly-to-llks-and-kernel-lib-helpers)** —
  `dfb::name` is passed straight to `compute_kernel_hw_startup(...)`, to
  `compute_kernel_lib::reduce<..., dfb::ydy, dfb::bcast_scaler, dfb::sum, ...>` and
  `dataflow_kernel_lib::calculate_and_prepare_reduce_scaler<dfb::scaler, ...>` in **template**
  position (`DFBBindingToken::operator uint32_t()` is `constexpr`), and to the
  `generate_bcast_scaler` / `generate_mask_*` / `*_to_cb` donors that take a `DataflowBuffer` by
  value (non-explicit converting constructor). No `.id` extraction, no temporary wrappers, no
  donor-side change.
- **[Multi-variant factories](../../../../../../docs/source/tt-metalium/tt_metal/apis/host_apis/metal_2.0/ai/shared/port_patterns.md#pattern-multi-variant-factories)** —
  the five variants stay five separate factory structs in the existing `program_factory_t`
  variant, one `create_program_artifacts` each. No branching inside a single factory is needed.
- **[Unity-build hygiene for anonymous-namespace symbols](../../../../../../docs/source/tt-metalium/tt_metal/apis/host_apis/metal_2.0/ai/shared/port_patterns.md#pattern-unity-build-hygiene-for-anonymous-namespace-symbols)** —
  `TT_ENABLE_UNITY_BUILD(ttnn_op_moreh)` is on, and all five factory `.cpp`s need the same
  spec-name constants and helpers. They are hoisted into
  `device/moreh_softmax_backward_metal2_common.hpp` with `inline` linkage.
- **Not applied — [Conditional / optional DFB bindings](../../../../../../docs/source/tt-metalium/tt_metal/apis/host_apis/metal_2.0/ai/shared/port_patterns.md#pattern-conditional--optional-dfb-bindings)**:
  every DFB a kernel names is bound on **every** config path. Under `LOG` the W/H readers skip the
  first `y` read but still read `y` in the second loop, and the compute kernels' `#ifdef LOG` /
  `#else` arms both reference the same DFB set. `c_27` exists only in the two `*Large` factories,
  but that is a per-factory difference, not a per-path one within a factory. So no `#ifdef`-gated
  binding, and no define promoted from a CTA gate. The existing `SOFTMAX`/`SOFTMIN`/`LOG`/
  `FP32_DEST_ACC_EN` defines move verbatim from `KernelDescriptor::defines` to
  `KernelSpec::compiler_options.defines`.

- **New findings during planning: none that block.** The audit's inventory, endpoint census, and
  Case-1 binding classification all reproduce from the code. The one item the audit did not name
  is the **same-FIFO aliasing** in the compute kernels — the audit correctly counted `c_24`/`c_25`/
  `c_26` as single-toucher self-loops, but did not flag that each is reached through two or three

  legacy descriptor did not.
