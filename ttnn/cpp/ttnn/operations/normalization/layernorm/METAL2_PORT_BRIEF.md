### Aliased DFBs — the headline construct

The op uses a legacy pattern six times that has an exact Metal 2.0 home but no one-to-one syntax: a **single `CBDescriptor` carrying two `CBFormatDescriptor`s**, i.e. two `buffer_index` values over one SRAM allocation, each with independent FIFO pointers, so the two indices can carry different `unpack_to_dest_mode` settings on the compute kernel.

The destination is **`DFBAdvancedOptions::alias_with`** ([tt_metal/api/tt-metalium/experimental/metal2_host_api/advanced_options.hpp](../../../../../../tt_metal/api/tt-metalium/experimental/metal2_host_api/advanced_options.hpp)), documented as *"logically distinct, but physically share the same backing memory."* Its three rules are already satisfied by the legacy code: every member lists every other, all members have the same total size (they share one `CBDescriptor::total_size`), and all target the same node set.

Three things to get right:

1. **Each alias index is its own DFB for endpoint purposes.** The two indices have separate FIFO pointers and the kernels push to both — see [device/kernels/dataflow/reader_unary_interleaved_ln.cpp:183-186](device/kernels/dataflow/reader_unary_interleaved_ln.cpp#L183-L186), which pushes `dfb_x_welford` by the same amount it pushed `dfb_in0`, precisely because they are distinct FIFOs over one allocation. Census and bind them separately; the audit's table already does.
2. **The alias exists only to carry a different `unpack_to_dest_mode`.** The mode itself stays on the compute kernel spec, not on the DFB ([device/layernorm_op_multi_core.cpp:516-535](device/layernorm_op_multi_core.cpp#L516-L535), [device/sharded_layernorm_factory_helpers.cpp:1073-1078](device/sharded_layernorm_factory_helpers.cpp#L1073-L1078)). The DFBs are aliased; the *mode* is per-index on the kernel.
3. **The alias is conditional.** When the gate is false, `cb_x_welford` falls back to naming whatever `cb_x` is on that path (`c_0` non-fused, `c_23`/`c_24` fused) and the kernel's `welford_fp32_alias` named CTA is 0, which suppresses the duplicate push. So in the inactive case there is no second DFB and no alias group at all — the named arg just points at the primary. Do not emit an alias group unconditionally.

Separately, and *not* an `alias_with` group: `c_0` and `c_14` in the sharded PRE-with-residual path are both `borrowed_from` the **input** tensor ([device/sharded_layernorm_factory_helpers.cpp:1147, 1173](device/sharded_layernorm_factory_helpers.cpp#L1147-L1173)), which is how the pre-add result gets written back over `a`'s own shard. Two DFBs borrowing the same `TensorParameter` expresses this directly; you should not need `alias_with` for it.

**The flag is correct here, and it is worth knowing why**, because the usual advice is to treat it as a last resort. In all five cases a *single* kernel is locked to **both** roles on one DFB: its `reserve_back`/`push_back` locks the producer side and its own `wait_front` locks the consumer side. That leaves no open side for the second toucher, so no relabelling helps — these are genuine legacy multi-endpoint FIFOs. Do not spend time hunting a 1P+1C assignment for them. Equally, **do not generalise**: the many CBs where compute does `reserve_back`/`push_back`/`wait_front`/`pop_front` with *no other toucher* are plain self-loops, not multi-bindings.

**No hidden second writer exists in this op.** The hunt was run over every kernel that touches every CB: each raw `get_write_ptr()` / `get_read_ptr()` belongs to a kernel already bound to that DFB, and there is no semaphore-gated co-fill of a CB whose FIFO producer is a different kernel. You do not need to re-run that search.

**Conditional DFBs** — present in some configs, absent in others, so the spec must be conditional rather than unconditional-with-a-dead-CB: multi-core `c_27` / `c_28` (`input_is_row_major` only), `c_29` / `c_30` / `c_31` (alias gates); sharded `c_19`-as-`cb_col_mask` (`do_col_mask`), `c_14` (two different DFBs on one index — the PRE pre-add input under `has_b`, and the ND mask scratch under `do_legacy_layernorm_col_mask`), `c_17` (POST without `skip_write_back`).

**Per-node kernel count is 3 in both factories** — one reader, one writer, one compute. The sharded factory's several descriptors per role cover **disjoint** node sets (reader over `sender_cores` / `all_to_all_workers_except_sender` / `not_all_to_all_workers`; writer and compute over `all_to_all_cores` / `not_all_to_all_workers`; plus an idle triple over `inactive_cores`, [device/sharded_layernorm_factory_helpers.cpp:836-893](device/sharded_layernorm_factory_helpers.cpp#L836-L893)). That is the disjoint-node-sets case — ordinary 1:1 per node, **not** the dual-instance work-split, so do not go looking for a work-split assignment question here.

**CTA varargs: none.** Every `get_compile_time_arg_val` in the op reads a literal index or a `constexpr` computed offset (`beta_args.next_compile_time_args_offset() + N`), which is a fixed set — name each one. Do not reach for `compile_time_varargs`.
