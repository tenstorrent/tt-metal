KDA direct ND-sharded cache

Final report · 2026-09-10 · bead tt-metal_tracker-s91 · base 3f254861838 · branch momcilo/kda-nd-cache

Verdict: KDA now accepts and returns recurrent and convolution state directly in the migration-ready ND-sharded DRAM layouts, with no KDA cache adapter. Real Kimi-K3 accuracy matches main across SP1×TP8, SP2×TP4, and SP4×TP2. Performance is neutral at SP1, +2.49% at SP2, and +4.59% at SP4; SP4 exceeds the existing LoudBox gate by 0.129 ms.

Delivered behavior

StateLogical shape per deviceStorageND shardSemantics
Recurrent[1,Hlocal,128,128]FP32 tile, DRAM[1,128,32]TP-local, replicated across SP
Convolution[1,3,Qlocal+Klocal+Vlocal]BF16 row-major, DRAM[1,3,64]Channel-sharded across TP, replicated across SP

The layer derives both layouts from the runtime DRAM grid, allocates them canonically, validates the exact ND contract at entry, and returns independent replacement buffers. Persistent-state payloads are 16,384 bytes per recurrent shard and 384 bytes per convolution shard.

The production pytest result is therefore 2 passed / 1 failed: all three accuracy checks complete successfully, and the sole failure is the SP4 performance assertion. Profiling identifies the added SP recurrent-state broadcast at about 172 µs. It is required because direct generic ttnn.add output to this ND DRAM grid resolves an invalid ninth bank on the harvested device. A KDA-native distributed-prefix final-state writer is the clearest follow-up if SP4 performance must return inside the current gate.

Residual risk and recommendation

Accuracy and state-contract goals are complete. The known residual is SP-scaled latency from recurrent final-state replication. Do not relax the benchmark threshold. If the +4.59% SP4 result is unacceptable, extend a KDA-owned affine-prefix operation to emit the already-identical local carry directly through a layout-aware ND writer, then repeat this exact matrix.
