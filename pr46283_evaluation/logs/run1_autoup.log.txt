The 26-layer decoder backbone itself (RMSNorm/Attention/MLP) is standard, well-understood territory.

  risks (7):
    - flow_matching (occ=1, leaves=1) is an opaque black-box module with no discovered submodules -- it almost certainly implements an iterative ODE/Euler sampling loop with time-conditioning, which doesn't map to any REUSE/ADAPT/NEW bucket op_emitter knows; the loop has nothing to decompose automatically.
    - codec_decoder (occ=1, leaves=1) is likewise opaque and very likely implements FSQ (finite scalar quantization); quantization code assignment is a discontinuous op where small precision errors flip discrete codes and can crater e2e PCC even when the underlying arithmetic is 'close enough' -- this already produced one false 'cannot be driven to 0.99' verdict before it was traced to a matmul/reduction precision bug.
    - This is a clean-slate re-run, so the previously-found precision fixes (hand-composed reductions instead of fused rms_norm/softmax, fp32_dest_acc_en on RMSNorm, matmul splitting) are not guaranteed to be rediscovered by the loop and may need to be reapplied manually before PCC gates pass.
    - 53 RMSNorm instances default to ttnn.rms_norm's fused kernel, which loses ~2% magnitude without fp32_dest_acc_en enabled -- a scale error too small for per-component PCC to catch until it compounds across 26 layers.
    - Backend match is 'category-default' (hf_eager universal (TTS)), not a voxtral_tts-specific profile -- initial RoPE/attention config for VoxtralAttention may not match the model's actual conventions on the first pass.
