## Interpretation

- A field-RMW call maps to the exact `_RMW` define, or to every field
  intersecting its explicit address/mask.
- `SETC16` maps to every field in the addressed 16-bit Thread word.
- `WRCFG`, CFG shift/mask, and `cfg[...]` stores map to every field in each
  addressed 32-bit Tensix word. A 128-bit `WRCFG` covers four words.
- `condition` is the lexical C/C++ and preprocessor guard at the call site.
  `unconditional` means unconditional within the named function, not that the
  function itself is always called.
- A ternary used to select the written value is appended as `value-select`.
- `<dynamic/unresolved>` is retained as an audit item. It commonly means the
  CFG address is held in a runtime variable; the invocation is not omitted.
- Comments and setter macro/function definitions are excluded. Generic
  implementation calls in `llk_lib/`hal/cfg.h` are excluded because they
  do not name a concrete `cfg_defines.h` field.
