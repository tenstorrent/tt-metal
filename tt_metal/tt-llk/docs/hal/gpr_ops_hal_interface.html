namespace hal::gpr_ops

Blackhole scalar GPR HAL

Set and transform scalar-unit general-purpose registers with typed operands and semantic operation names.

Architecture BlackholeLanguage C++17Header hal/gpr_ops.hRegisters GPR 0–63
Include the scalar GPR operation interface#include "hal/gpr_ops.h"

Quick start

#include "hal/gpr_ops.h"

using namespace hal::gpr_ops;

// Compile-time path
set<0x12345678>(hal::gpr<0>());
add(
    hal::gpr<1>(),
    hal::gpr<0>(),
    immediate<7>());
compare<Compare::LessThan>(
    hal::gpr<2>(),
    hal::gpr<1>(),
    immediate<16>());

// Runtime path
shift_right(
    hal::gpr(destination_index),
    hal::gpr(lhs_index),
    hal::gpr(rhs_index));

The destination is always first. Binary operations read a GPR lhs and either a GPR or explicitly typed immediate rhs.

Functional model

// Binary operations
GPR[destination] = operation(GPR[lhs], rhs);

// Comparison
GPR[destination] = predicate(GPR[lhs], rhs) ? 1 : 0;

// Full-width set
GPR[destination][15:0]  = value[15:0];
GPR[destination][31:16] = value[31:16];

Each GPR is 32 bits and is selected by an index in [0, 63]. An rhs can name another GPR or use the public HAL's immediate range of [0, 63]. Emitter functions issue the instruction; functions ending in _operation return its encoded 32-bit word without issuing it.

Compile time versus runtime

The operand objects determine the path. Fully compile-time operands emit an immediate Tensix instruction. If any index or immediate is runtime-selected, the HAL validates the values, constructs the same instruction word, and writes it through the instruction buffer. One exception: the compile-time-value setters (set<Value>, set_low<Value>, set_high<Value>, and their *_operation forms) accept only a compile-time gpr<N>() destination — no overload combines a compile-time value with a runtime gpr(index), so that call shape is a compile error, not a runtime path.

Shared types and enum

struct · namespace hal

Gpr

template <std::uint32_t Index>
struct Gpr
{
    static constexpr std::uint32_t index = Index;
};

// Compile-time path
template <std::uint32_t Index>
constexpr auto gpr();

// Runtime path
constexpr auto gpr(const std::uint32_t index);

Gpr identifies one register; it does not describe an operation. Index is the compile-time register index. The runtime factory stores index in a runtime-specialized operand.

Constraints
  • The consuming operation validates the index in [0, 63].
  • hal::gpr<N>() selects the compile-time path; hal::gpr(index) keeps the index runtime.
// Compile-time path
const auto fixed_source = hal::gpr<3>();

// Runtime path
const auto selected_source = hal::gpr(source_index);
struct and factories · namespace hal::gpr_ops

Immediate and immediate

template <std::uint32_t Value>
struct Immediate
{
    static constexpr std::uint32_t value = Value;
};

// Compile-time path
template <std::uint32_t Value>
constexpr auto immediate();

// Runtime path
constexpr auto immediate(const std::uint32_t value);

Immediate<Value> marks an rhs as a constant rather than a GPR index. A bare integer is deliberately not accepted, preventing an index from being confused with an immediate value.

Constraints
  • Public binary operations accept immediate values in [0, 63].
  • The compile-time factory produces a compile-time diagnostic; the runtime factory is checked with LLK_ASSERT when consumed.
// Compile-time path
add(hal::gpr<0>(), hal::gpr<1>(), immediate<5>());

// Runtime path
add(hal::gpr<0>(), hal::gpr<1>(), immediate(runtime_value));

set

// Compile-time value path
template <std::uint32_t Value, std::uint32_t Index>
void set(const hal::Gpr<Index> destination);

// Runtime value path; destination may be compile-time or runtime
template <std::uint32_t Index>
void set(
    const hal::Gpr<Index> destination,
    const std::uint32_t value);

Value or value supplies all 32 destination bits. Index identifies the destination GPR. The function emits low-half SETDMAREG followed by high-half SETDMAREG.

No set_operation()

A full-width set is an ordered pair of instructions, so it cannot be represented by one operation word.

// Compile-time path
set<0x12345678>(hal::gpr<5>());

// Runtime path
set(hal::gpr(destination_index), runtime_value);

These interfaces replace only bits [15:0] or [31:16]. Value and value must fit in 16 bits.

// Compile-time path: emit low-half write
set_low<0x5678>(hal::gpr<5>());

// Runtime path: emit high-half write
set_high(hal::gpr(destination_index), runtime_half);

// Compile-time path: encode without issuing
constexpr std::uint32_t load_high =
    set_high_operation<0x1234>(hal::gpr<5>());

bit_and, bit_or, and bit_xor write the corresponding 32-bit bitwise result. They map to different operation selectors of BITWOPDMAREG.

// Compile-time paths
bit_and(hal::gpr<0>(), hal::gpr<1>(), immediate<15>());
bit_or(hal::gpr<2>(), hal::gpr<2>(), hal::gpr<3>());
bit_xor(hal::gpr<4>(), hal::gpr<4>(), immediate<63>());

Performs a logical left or right shift of lhs. The shift amount comes from a GPR or an explicit immediate operand.

// Compile-time path
shift_left(
    hal::gpr<0>(),
    hal::gpr<1>(),
    immediate<4>());

// Runtime path
shift_right(
    hal::gpr(destination_index),
    hal::gpr(lhs_index),
    hal::gpr(rhs_index));
Use shift amounts 0–31

The pinned scalar-unit specification defines a five-bit immediate and masks a GPR shift count with 0x1f. Blackhole instruction metadata and the current HAL validator accept six encoded bits, through 63. Until that discrepancy is reconciled, keep immediate shift amounts in [0, 31]; do not rely on bit 5.

Predicate uses the Compare enum. The function compares the unsigned 32-bit operands and writes 1 when the predicate is true, otherwise 0.

// Compile-time path
compare<Compare::GreaterThan>(
    hal::gpr<0>(),
    hal::gpr<1>(),
    immediate<7>());

// Mixed path: runtime rhs immediate
compare<Compare::Equal>(
    hal::gpr<0>(),
    hal::gpr<1>(),
    immediate(runtime_value));

Interface boundary

This package covers instructions whose public meaning is a GPR value transformation. CFG and address-counter transfers remain in their existing HAL packages. Packer status reads, memory loads and stores, MMIO address construction, L1 atomics, scalar flush, and scalar NOP are outside this interface.
