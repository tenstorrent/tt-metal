hal::dst

Blackhole Dest Zeroing HAL

Mark Dst rows undefined through their zero flags, or re-arm them as initialized data.

Architecture Blackhole Header hal/dst.h Instructions ZEROACC
Include the package#include "hal/dst.h"

Quick start

#include "hal/dst.h"

// Re-arm the zero flags of one Dst face after an unpack-to-dest (budabackend#2730).
hal::dst::run(hal::dst::Zero {
    .scope        = hal::dst::ZeroScope::Face,
    .index        = face_index,
    .flags        = hal::dst::ZeroFlagAction::ClearFlags,
    .width        = hal::dst::DestWidth::Bits32,
    .address_mode = ADDR_MOD_3,
});

// Compile-time path
constexpr hal::dst::Zero clear_all {.scope = hal::dst::ZeroScope::All};
hal::dst::run<clear_all>();

Functional model

ZEROACC does not write datums — it marks the targeted Dst rows through their zero flags: undefined rows read as zero to the packer and as the identity to the FPU. With ZeroFlagAction::ClearFlags the action inverts and previously-zeroed rows are re-marked as initialized data. Instruction bits 23:22 clear SrcA/SrcB data valid as an undocumented side effect; they are always encoded zero — releases go through hal::src or the consuming operation.

Zero descriptor

struct Zero
{
    ZeroScope scope;              // SingleRow / Face / Half / All
    std::uint32_t index       = 0;
    ZeroFlagAction flags      = ZeroFlagAction::MarkUndefined; // or ClearFlags
    DestWidth width           = DestWidth::Bits16;             // or Bits32
    std::uint8_t address_mode = 0;                             // hardware applies it for SingleRow

    constexpr std::uint32_t get_operation() const;
};

// Compile-time path
template <Zero Operation>
void run();

// Runtime path
void run(const Zero operation);
