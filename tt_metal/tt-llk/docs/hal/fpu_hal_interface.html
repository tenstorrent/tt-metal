namespace hal::fpu

Blackhole FPU HAL

Describe, encode, and issue the seven Blackhole matrix-unit compute instructions — elementwise math, matrix multiply, dot product, and pooling reductions — without exposing raw instruction fields at each call site.

Architecture Blackhole Header hal/fpu.h Instructions ELWADD · ELWSUB · ELWMUL · DOTPV · MVMUL · GAPOOL · GMPOOL Status Implemented (additive)
Include the complete typed FPU compute interface#include "hal/fpu.h"

The interface is additive. It does not change an LLK function signature or migrate existing instruction call sites. Data formats, fidelity phases, Dest bases, and post-issue counter stepping remain hal::cfg and ADDR_MOD preconditions. Quasar uses a different instruction family and is outside this Blackhole interface.

Quick start

#include "hal/fpu.h"

using namespace hal::fpu;

constexpr Elementwise multiply_final_block {
    .operation = ElementwiseOperation::Multiply,
    .address_modifier = 3,
    .release = SourceRelease::Both,
};

// Compile-time path: return one encoded instruction for MOP or replay.
constexpr std::uint32_t multiply_word =
    get_operation<multiply_final_block>();

// Compile-time path: issue one immediate ELWMUL instruction.
run<multiply_final_block>();

The operation above multiplies one 8x16 SrcA/SrcB block into Dest, steps the counters through ADDR_MOD register 3, then releases both source banks back to the unpackers.

Source release is intentionally mandatory

Every descriptor's release defaults to Unset. The compile-time encoder rejects that sentinel, and LLK assertions diagnose it on the runtime path. State None for an instruction inside a longer sequence, or SrcA, SrcB, or Both on the instruction that finishes consuming a source bank.

Functional model

The seven instructions share one encoding skeleton — opcode, source release, modifier bits, ADDR_MOD index, and a Dest row offset — and split into four typed descriptors.

TypeInstructionsEffect
ElementwiseELWADD 0x28, ELWSUB 0x30, ELWMUL 0x27Combine an 8x16 SrcA block with an 8x16 SrcB block (optionally broadcast) into eight Dest rows.
DotProductDOTPV 0x29Accumulate Dest(8x16) += SrcB(8x16) × SrcA(16x16); MVMUL-equivalent legacy form without row broadcast.
MatrixMultiplyMVMUL 0x26Accumulate Dest(8x16) += SrcB(8x16) × SrcA(16x16).
PoolGAPOOL 0x34, GMPOOL 0x33Sum: accumulate Dest(4x16) += SrcB(4x16) × SrcA(16x16). Maximum: reduce each SrcA column to its maximum into one Dest row.

A compute instruction does not select data formats, fidelity phase counts, integer/FP32 Dest width, or how the SrcA/SrcB/Dest counters step afterwards. Those remain ALU configuration and ADDR_MOD preconditions. Every instruction waits for both SrcA and SrcB banks to hold valid data before executing, and the effective Dest row is the sum of the instruction's dest_row_offset, the Dest counter, and the configured Dest base offsets.

Encoding policy for metadata gaps

The local instruction metadata omits the elementwise SrcB row-broadcast value, describes the MVMUL modifier with stale datapath-bandwidth wording, claims a pool-shape field the ISA does not define, and gives DOTPV elementwise fields the hardware never reads. This interface follows ckernel_ops.h for bit positions and the ISA functional model for behavior. Positions without a public semantic selector are fixed rather than exposed: zero where the ISA syntax hardcodes zero, and the established Blackhole LLK compatibility value for the pooling shape position. The raw macros remain available for low-level compatibility.

Shared types

These types describe the choices shared by the four operation descriptors. Defaults below are the defaults stored by the C++ aggregate; required or invalid defaults are called out explicitly.

ElementwiseOperation

ValueInstructionEffect
AddELWADDDest receives SrcA + SrcB, overwritten or accumulated per DestWriteMode.
SubtractELWSUBDest receives SrcA − SrcB, overwritten or accumulated per DestWriteMode.
MultiplyELWMULDest always accumulates SrcA × SrcB; see the warning under DestWriteMode.

operation has no declared member initializer. If it is omitted from an aggregate, C++ value-initialization produces zero, which currently maps to Add; set it explicitly so the selected arithmetic is visible at the call site.

SrcBBroadcast

ValueDefaultEffect
NoneYesConsume SrcB rows as addressed by the SrcB counter.
ColumnNoReplicate each SrcB row's column-0 datum across all sixteen columns.
RowNoReplicate the counter-selected SrcB row onto all eight consumed rows; row broadcast lets the SrcB counter select an exact row.
ScalarNoReplicate the counter-selected SrcB row's column-0 datum onto the whole 8x16 block.

SrcBRowBroadcast

ValueDefaultEffect
NoneYesConsume an eight-row-aligned 8x16 SrcB block and accumulate all eight result rows. Every current LLK MVMUL call site uses this value.
RowNoReplicate the counter-selected SrcB row — the SrcB counter picks an exact row, free of the usual eight-row alignment — across the multiply, and accumulate the product into the even rows of a seven-row Dest block; odd rows stay unchanged. In this mode the composed Dest row keeps its lowest bit instead of aligning to eight rows. Not exercised by LLK today.

The instruction metadata describes this bit as a "compute 4 rows / compute 1 row" throughput selector; that wording is identical to the Wormhole metadata and describes internal datapath bandwidth, not the architectural result above.

DestWriteMode

ValueDefaultEffect
OverwriteYesReplace the addressed Dest rows with the result.
AccumulateNoAdd the result to the existing Dest values.
Multiply ignores this selection

ELWMUL accumulates onto Dest regardless of the encoded bit — every LLK call site passes zero while relying on a prior ZEROACC for overwrite semantics. MVMUL, DOTPV, and the pools have no overwrite mode at all, which is why the other descriptors do not carry this field. The bit is honored only by Add and Subtract.

PoolFunction

ValueInstructionEffect
SumGAPOOLFour-row matrix multiply: Dest(4x16) += SrcB(4x16) × SrcA(16x16), with SrcB read from the top half of the eight-row-aligned block and all four Dest rows accumulated. Participates in fidelity phases like a multiply.
MaximumGMPOOLScale the sixteen-row SrcA block by one SrcB scaler row, reduce every column to its maximum, and combine the 1x16 result with the existing Dest row.

IndexTracking

ValueDefaultEffect
DisabledYesWrite only the pooled values.
EnabledNoAlso record each column's winning row index in the low bits of the same pooled Dest datum. Valid only with Maximum and usable only with a 32-bit Dest — a 16-bit Dest write discards the index bits.

Index tracking has precise, non-obvious semantics:

  • Packing — with an integer-style Dest the datum holds only the index result; with a 16-bit float format in a 32-bit Dest the maximum lands in the high sixteen bits and the index result in the low bits.
  • Row range — only SrcA rows 0–7 can record an index. Rows 8–15 still participate in the maximum value but never update the index, so place argmax candidates in the first eight rows and pad the rest with negative infinity.
  • Index transform — the recorded row index is permuted by {0, 3, 6, 1, 4, 7, 2, 5} (row i records (3×i) mod 8). The table is an involution, so applying it again decodes the row.
  • Phase counter — each issue increments a four-bit phase in the datum, so chained pools onto the same Dest row yield distinct index bases; initialize the Dest low bits to zero and decode the winning issue from the phase bits.
  • Ties — rows are visited in the order 4, 5, 6, 7, 0, 1, 2, 3 with a greater-or-equal compare, so the last-visited equal value wins.

SourceRelease

ValueStatusEffect
UnsetDefault; invalid sentinelHas no supported instruction meaning. Compile-time validation rejects it; runtime LLK assertions diagnose it.
NoneValidKeep both source banks; following instructions continue consuming the same data.
SrcA / SrcBValidFlip the named bank and clear its data-valid flag so the producing unpacker can refill it.
BothValidRelease SrcA and SrcB together; typical on the last instruction of a tile.

The per-thread CLR_DVALID disable configuration downgrades a release to a bank flip that keeps data-valid set, which is useful when a kernel ping-pongs both banks itself.

Scalar fields

FieldDefaultRangeEffect
address_modifier00–7Selects the ADDR_MOD register applied after the compute: SrcA/SrcB/Dest increments and clears, fidelity-phase stepping, and bias.
dest_row_offset00–1023Ten-bit row offset added to the Dest counter and the configured Dest base offsets. Hardware aligns the composed row down to eight rows (elementwise, matrix multiply) or four rows (pools).

Elementwise

Declaration

struct Elementwise
{
    ElementwiseOperation operation;
    SrcBBroadcast broadcast = SrcBBroadcast::None;
    DestWriteMode dest_write = DestWriteMode::Overwrite;
    std::uint8_t address_modifier = 0;
    std::uint16_t dest_row_offset = 0;
    SourceRelease release = SourceRelease::Unset;
};

// Compile-time path
template <Elementwise Operation>
constexpr std::uint32_t get_operation();

template <Elementwise Operation>
inline __attribute__((always_inline)) void run();

// Runtime path
inline constexpr __attribute__((always_inline)) std::uint32_t get_operation(
    const Elementwise operation);

inline __attribute__((always_inline)) void run(
    const Elementwise operation);

get_operation returns one encoded word and does not issue it. Compile-time run emits one immediate instruction. Runtime run checks the description when LLK assertions are enabled, constructs the word, and writes it through ckernel::instrn_buffer[0].

Face loop with a final release

constexpr Elementwise add_block {
    .operation = ElementwiseOperation::Add,
    .release = SourceRelease::None,
};

constexpr Elementwise add_final_block {
    .operation = ElementwiseOperation::Add,
    .release = SourceRelease::Both,
};

run<add_block>();
run<add_final_block>();

Column-broadcast subtract for a MOP body

constexpr std::uint32_t subtract_broadcast_word = get_operation<Elementwise {
    .operation = ElementwiseOperation::Subtract,
    .broadcast = SrcBBroadcast::Column,
    .release = SourceRelease::None,
}>();

Each issue processes one 8x16 block; a full 16-row face takes two issues. Fidelity phases for Multiply come from looping the same instruction with ADDR_MOD entries that step and finally clear the fidelity counter.

DotProduct

Declaration

struct DotProduct
{
    std::uint8_t address_modifier = 0;
    std::uint16_t dest_row_offset = 0;
    SourceRelease release = SourceRelease::Unset;
};

The compile-time and runtime get_operation/run overloads match the other descriptors. DOTPV computes exactly what MatrixMultiply computes without row broadcast — Dest(8x16) += SrcB(8x16) × SrcA(16x16), always accumulating — at the same documented throughput.

Legacy instruction — prefer MatrixMultiply

DOTPV is the restricted legacy-compatible form of MVMUL and has no call site in the Blackhole LLK. The generated macros carry the elementwise accumulate and broadcast arguments, but the ISA gives those bit positions no DOTPV field — accumulation cannot be disabled and broadcast cannot be enabled — so this descriptor omits them and encodes the positions as zero. The raw macros remain available for low-level compatibility.

MatrixMultiply

Declaration

struct MatrixMultiply
{
    SrcBRowBroadcast broadcast = SrcBRowBroadcast::None;
    std::uint8_t address_modifier = 0;
    std::uint16_t dest_row_offset = 0;
    SourceRelease release = SourceRelease::Unset;
};

MVMUL always accumulates Dest(8x16) += SrcB(8x16) × SrcA(16x16); zero the target rows first for overwrite semantics. The instruction is the preferred matrix-multiply primitive.

Matmul face sequence for replay recording

constexpr MatrixMultiply advance_within_face {
    .address_modifier = 0,  // srcb += 8, dest += 8
    .release = SourceRelease::None,
};

constexpr MatrixMultiply advance_to_next_face {
    .address_modifier = 1,  // srca += 16, dest = 0
    .release = SourceRelease::None,
};

constexpr MatrixMultiply finish_tile {
    .address_modifier = 2,
    .dest_row_offset = 8,
    .release = SourceRelease::Both,
};

run<advance_within_face>();
run<advance_to_next_face>();
run<finish_tile>();

The comments show typical ADDR_MOD programming; the stepping itself lives in the ADDR_MOD registers, not in this descriptor.

Pool

Declaration

struct Pool
{
    PoolFunction function;
    IndexTracking indices = IndexTracking::Disabled;
    std::uint8_t address_modifier = 0;
    std::uint16_t dest_row_offset = 0;
    SourceRelease release = SourceRelease::Unset;
};

Every pool consumes the full sixteen-row SrcA block and targets an aligned four-row Dest block. Sum consumes four SrcB rows and accumulates all four Dest rows of the block; Maximum consumes one SrcB scaler row, combines the block's first row, and zeroes (or phase-stamps, when index tracking is on) the other three. The ISA defines no pool-shape field — the bit the instruction metadata calls a single-row selector is encoded at its only characterized value, and the raw macros remain the escape hatch for experimenting with the other value.

Column sums are a SrcB layout convention

Sum is architecturally a four-row matrix multiply, so a row of scaled column sums requires preparing SrcB: fill one SrcB row with the scaler (1/N for an average) and read the matching Dest row. The other three Dest rows of the block are also accumulated from whatever the remaining SrcB rows hold — do not reuse them, and do not leave those SrcB rows undefined.

Column reductions

// Column maximum of one tile face, then hand both banks back.
run<Pool {
    .function = PoolFunction::Maximum,
    .release = SourceRelease::Both,
}>();

// One high-fidelity phase of a scaled column sum, encoded for a MOP body.
constexpr std::uint32_t sum_phase_word = get_operation<Pool {
    .function = PoolFunction::Sum,
    .address_modifier = 1,  // fidelity += 1
    .release = SourceRelease::None,
}>();
Zero the Dest row before a maximum pool

Uninitialized Dest rows behave as negative infinity for Maximum, and with index tracking the phase counter reads the old datum. Clear the target rows with ZEROACC before the first pool of a reduction.

Validation and diagnostics

constexpr bool is_valid(const Elementwise operation);
constexpr bool is_valid(const DotProduct operation);
constexpr bool is_valid(const MatrixMultiply operation);
constexpr bool is_valid(const Pool operation);

is_valid exposes the complete descriptor predicate. Compile-time encoders enforce it with static_assert. Runtime encoders check each field with a descriptive LLK_ASSERT; when LLK assertions are disabled, those validation helpers are compiled out. The predicate checks:

  • all enum values and the mandatory source release;
  • the ADDR_MOD selection in the range 0–7;
  • the Dest row offset within its ten-bit architectural field; and
  • index tracking only on Maximum pools.

With LLK assertions enabled, invalid runtime input reaches a field-specific diagnostic. With assertions disabled, the runtime path deliberately has raw-instruction semantics: call is_valid explicitly when untrusted values must be rejected in a production build.

Configuration preconditions stay with hal::cfg

The descriptors cannot inspect ALU formats, FP32/INT8 Dest modes, zero-flag state, fidelity base phase, or the Dest base offsets. Configure those through hal::cfg before issuing compute instructions.

Performance and hardware mapping

The compile-time path lowers to the same single immediate instruction used by existing TTI_ELWADD-family, TTI_MVMUL, and TTI_GAPOOL/TTI_GMPOOL call sites. It performs no runtime dispatch or hot-path word construction. With LLK assertions disabled, the runtime path contains only the opcode selection and field arithmetic required by the equivalent raw TT_* operation, followed by one instruction-buffer write. Enabling LLK assertions intentionally adds diagnostic checks.

After any of these instructions writes Dest, the written aligned 8x16 block is unreadable for a few cycles; hardware stalls automatically, but sequences that cycle across several distinct Dest blocks avoid the stall. Fidelity-phase counts, format conversion, and Src bank contention continue to come from CFG and ADDR_MOD state.
