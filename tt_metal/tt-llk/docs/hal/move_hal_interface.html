namespace hal::move

Blackhole transfer HAL

Describe movement by source and destination, let the backend derive instruction modes, and issue one native operation or a compile-time-expanded sequence.

Architecture Blackhole Header hal/move.h Instructions MOVA2D · MOVB2D · MOVD2B · LOADIND · STOREIND · LOADREG · STOREREG · XMOV Status Implemented
Include the transfer interface#include "hal/move.h"

Quick start

inline constexpr hal::move::Transfer<
    hal::move::SrcA,
    hal::move::Dst>
move_face {
    .source_row = 0,
    .destination_row = 0,
    .address_mode = ADDR_MOD_2,
    .number_of_rows = hal::move::rows::Face,
};

// Compile-time path: two straight-line eight-row MOVA2D instructions.
hal::move::run<move_face>();

The endpoint pair selects the instruction family. Semantic members select row count, broadcast, address formation, and completion. Raw modifier bits are private to the Blackhole encoder.

Functional model

RouteBackend operationCompletion
SrcA → DstMOVA2D or MOVDBGA2D; 1/8-row native fragments.The instruction's source-validity policy.
SrcB → DstMOVB2D or MOVDBGB2D; 1/4 rows, or one row broadcast to 8.The instruction's source-validity policy.
Dst → SrcBMOVD2B; 1/4-row native fragments, with normal or low-16 Dst source selection.ADDR_MOD-controlled RWC progression.
L1 ↔ GprLOADIND or STOREIND with 16/4/2/1-byte size.Posted; optional ScalarIdle wait.
Gpr → SrcA/SrcBFixed four-BF16 STOREIND.Waits for source-bank ownership.
Gpr ↔ MmioSTOREREG/LOADREG for immediate addresses; STOREIND for indirect writes.Posted/asynchronous; optional ScalarIdle wait.
L1 → L1Three grouped THCON writes followed by XMOV.Optional MoverIdle wait.

Large matrix transfers repeat the same encoded source and destination rows. The selected address modifier advances the live RWCs between fragments. A distinct final_address_mode can wrap or jump the counters on the last fragment.

} // namespace dst_layout

enum class RowAddressing : std::uint8_t { Absolute, CounterRelative };

// Compile-time path
template <std::int32_t Offset>
constexpr std::uint32_t relative_row();

// Runtime path
constexpr std::uint32_t relative_row(std::int32_t offset);

enum class Broadcast : std::uint8_t { None, Column0, Row, Scalar };
enum class SourceValidity : std::uint8_t { Wait, Ignore };
enum class ScalarSize : std::uint8_t { Bytes16, Bytes4, Bytes2, Bytes1 };
enum class OffsetIncrement : std::uint8_t { None, Bytes2, Bytes4, Bytes16 };
enum class Completion : std::uint8_t { IssueOnly, Wait };
enum class GprHalf : std::uint8_t { Low, High };

rows::faces<N>() accepts a positive whole number of faces, subject to the eight-instruction expansion limit. Indirect addresses contain a base GPR, a low/high half-register offset, and an optional offset-register increment.

dst_layout::tile_row(tile, face, row) is pure constexpr Dst geometry — the row holding one face row of one 32x32 tile (tile * 64 + face * 16 + row) — shared by every kernel that addresses Dst by tile and face.

RowAddressing selects how the hardware consumes a ten-bit Dst row field: Absolute rows are validated against the register span, while CounterRelative fields hold a masked signed offset that the hardware adds to the live row counter modulo 1024. Build relative fields with relative_row — the compile-time form rejects out-of-range offsets at compile time; the runtime form masks to ten bits and diagnoses out-of-range offsets while LLK assertions are enabled. Where the effective counter-plus-offset row lands is the caller's contract, exactly as with the raw instruction forms.

SrcA to Dst

template <>
struct Transfer<SrcA, Dst>
{
    std::uint32_t source_row;
    std::uint32_t destination_row;
    RowAddressing destination_addressing = RowAddressing::Absolute;
    std::uint8_t address_mode;
    RowCount number_of_rows;
    std::uint8_t final_address_mode = SameAddressMode;
    bool destination_32bit_low = false;
    SourceValidity source_validity = SourceValidity::Wait;

    constexpr std::uint32_t get_operation() const;
};

One and eight rows are native. Four rows expand to four one-row moves; each face expands to two eight-row moves. The eight-instruction limit permits up to four faces. SourceValidity::Ignore selects MOVDBGA2D explicitly.

inline constexpr hal::move::Transfer<
    hal::move::SrcA,
    hal::move::Dst>
move_eight_without_client_wait {
    .source_row = 8,
    .destination_row = 32,
    .address_mode = ADDR_MOD_2,
    .number_of_rows = hal::move::rows::Eight,
    .source_validity = hal::move::SourceValidity::Ignore,
};

hal::move::run<move_eight_without_client_wait>();

SrcB to Dst

template <>
struct Transfer<SrcB, Dst>
{
    std::uint32_t source_row;
    std::uint32_t destination_row;
    RowAddressing destination_addressing = RowAddressing::Absolute;
    std::uint8_t address_mode;
    RowCount number_of_rows;
    Broadcast broadcast = Broadcast::None;
    std::uint8_t final_address_mode = SameAddressMode;
    bool destination_32bit_low = false;
    SourceValidity source_validity = SourceValidity::Wait;

    constexpr std::uint32_t get_operation() const;
};

None and Column0 use native one/four-row fragments and permit up to two faces. Row and Scalar use native one-row-to-eight-row broadcast fragments when divisible by eight, otherwise one-row fragments, and permit up to four faces. A one-row scalar request becomes the native column-zero form; a one-row row broadcast is rejected as a no-op request.

inline constexpr hal::move::Transfer<
    hal::move::SrcB,
    hal::move::Dst>
broadcast_scalar {
    .source_row = 7,
    .destination_row = 64,
    .address_mode = ADDR_MOD_4,
    .number_of_rows = hal::move::rows::Eight,
    .broadcast = hal::move::Broadcast::Scalar,
};

hal::move::run<broadcast_scalar>();

Dst to SrcB

template <>
struct Transfer<Dst, SrcB>
{
    std::uint32_t source_row;
    RowAddressing source_addressing = RowAddressing::Absolute;
    std::uint32_t destination_row;
    std::uint8_t address_mode;
    RowCount number_of_rows;
    std::uint8_t final_address_mode = SameAddressMode;
    bool source_32bit_low = false;

    constexpr std::uint32_t get_operation() const;
};

MOVD2B natively moves one or four rows. A face expands to four straight-line four-row instructions, so the eight-instruction bound permits at most two faces. source_32bit_low selects the low 16 bits of each 32-bit Dst row; the default selects the normal half.

hal::move::Transfer<
    hal::move::Dst,
    hal::move::SrcB>
extract_face {
    .source_row = hal::move::dst_layout::tile_row(dst_index, face),
    .destination_row = 16,
    .address_mode = ADDR_MOD_0,
    .number_of_rows = hal::move::rows::Face,
    .final_address_mode = ADDR_MOD_3,
};

// Runtime row addresses, compile-time-known face shape: four unrolled MOVD2B instructions.
hal::move::run(extract_face);

inline constexpr hal::move::Transfer<
    hal::move::L1,
    hal::move::Gpr>
load_word {
    .source = {
        .base = hal::gpr<1>(),
        .offset = {.gpr = hal::gpr<2>(), .half = hal::move::GprHalf::High},
    },
    .destination = hal::gpr<3>(),
    .size = hal::move::ScalarSize::Bytes4,
    .completion = hal::move::Completion::Wait,

Sixteen-byte transfers require the first GPR to be four-aligned. Narrow loads preserve the unselected high bits of the destination GPR; narrow stores consume its low bits.

Immediate addresses use STOREREG or LOADREG and must be four-byte aligned in 0xffb11000..0xffbffffc. Indirect writes use STOREIND. There is no indirect MMIO read.

    hal::move::Gpr,
    hal::move::Mmio>
write_register {
    .source = hal::gpr<8>(),
    .destination = {
        .addressing = hal::move::MmioAddressing::Immediate,
        .byte_address = 0xffb11000,
    },
};

hal::move::run<write_register>();

L1 to L1 XMOV

template <>
struct Transfer<L1, L1>
{
    L1Address16B source;
    L1Address16B destination;
    BlockCount16B size;
    Completion completion = Completion::IssueOnly;

    constexpr std::uint32_t get_operation() const = delete;
};

Addresses and sizes are in 16-byte blocks. The backend programs THCON section 0 source, destination, buffer size, and direction 3 through hal::cfg, then emits XMOV(0, 0). Completion::Wait appends an all-instruction MoverIdle wait.

inline constexpr hal::move::Transfer<
    hal::move::L1,
    hal::move::L1>
copy_l1 {
    .source = {.block = 0x100},
    .destination = {.block = 0x200},
    .size = {.value = 64},
    .completion = hal::move::Completion::Wait,
};

hal::move::run<copy_l1>();
Blackhole route limit

Only direction 3, L1-to-L1, is exposed. The Blackhole THCON descriptor labels it as the only legal mover direction. Zero-fill, backend-CFG, and NCRISC-IRAM routes remain unavailable until Blackhole semantics are authoritative.

run() and get_operation()

// Compile-time path
template <auto Operation>
void run();

// Runtime path
template <
    typename Source,
    typename Destination>
void run(
    Transfer<Source, Destination> operation);

run<Operation>() statically validates and emits immediate instructions. Matrix expansion is a straight-line template expansion. run(operation) retains runtime selection, but its matrix path is also compile-time-unrolled into eight forward-guarded slots. Neither path contains a runtime matrix loop.

Bounded expansion

MaxMatrixTransferInstructions is eight. Split a larger semantic transfer into multiple descriptors; there is no loop or slow fallback inside the HAL. Runtime oversize is diagnosed before issue when LLK assertions are enabled and is a caller-contract violation when they are disabled.

get_operation() returns one word only when the complete descriptor has exactly one operation. It rejects multi-fragment matrix transfers and scalar descriptors with Completion::Wait. XMOV always rejects it because configuration plus launch is inherently composite.

Production datacopy pattern

// One face extraction expands to four straight-line MOVD2B instructions.
hal::move::Transfer<
    hal::move::Dst,
    hal::move::SrcB>
extract {
    .source_row = hal::move::dst_layout::tile_row(dst_index, face),
    .destination_row = datacopy_detail::HighHalfSrcBRow,
    .address_mode = ADDR_MOD_0,
    .number_of_rows = hal::move::rows::Face,
    .final_address_mode = ADDR_MOD_3,
};

hal::move::run(extract);
extract.destination_row = datacopy_detail::LowHalfSrcBRow;
extract.source_32bit_low = true;
hal::move::run(extract);

// One semantic operation expands to eight straight-line MOVB2D instructions.
const hal::move::Transfer<
    hal::move::SrcB,
    hal::move::Dst>
scalar_high_half {
    .source_row = datacopy_detail::HighHalfSrcBRow,
    .destination_row = hal::move::dst_layout::tile_row(dst_index),
    .address_mode = ADDR_MOD_2,
    .number_of_rows = hal::move::rows::faces<4>(),
    .broadcast = hal::move::Broadcast::Scalar,
    .final_address_mode = ADDR_MOD_3,
};

hal::move::run(scalar_high_half);

// Noncontiguous destinations reuse the same semantic face descriptor.
hal::move::Transfer<
    hal::move::SrcB,
    hal::move::Dst>
row_high_half {
    .source_row = datacopy_detail::HighHalfSrcBRow,
    .destination_row = hal::move::dst_layout::tile_row(dst_index, 0),
    .address_mode = ADDR_MOD_2,
    .number_of_rows = hal::move::rows::Face,
    .broadcast = hal::move::Broadcast::Row,
    .final_address_mode = ADDR_MOD_3,
};

hal::move::run(row_high_half);
row_high_half.destination_row =
    hal::move::dst_layout::tile_row(dst_index, 2);
hal::move::run(row_high_half);

The Blackhole unary-datacopy workaround programs the intermediate address mode through typed hal::cfg::AddrMod fields, advances the live SrcB/Dst RWCs, and uses a clearing final mode. Its column path extracts each Dst face with one reusable Transfer<Dst, SrcB> per 16-bit half. Scalar broadcast represents all four faces with one faces<4>() transfer. Row broadcast reuses one face descriptor because its destination faces are noncontiguous; column broadcast likewise reuses one face descriptor so SrcB progression restarts for the right face. Each run expands into one, two, four, or eight native TT instructions with no loop, helper call, or descriptor storage in optimized code. The normal datacopy MOP obtains its singular MOVA2D or MOVB2D word from get_operation().

Validation and caller preconditions

is_valid(...) covers every implemented descriptor. Compile-time run uses static_assert. Runtime checks are present only with LLK assertions enabled and compile away completely otherwise.

Row fields are full-width std::uint32_t and are encoded unmasked, exactly like the raw instruction macros: an out-of-range row is rejected by validation, never silently truncated, and building a descriptor from runtime values adds no masking instructions.

Selecting RowAddressing::CounterRelative on the ten-bit Dst-side field replaces its absolute-span validation with a ten-bit fit check; the six-bit SrcA/SrcB rows stay absolute. The in-face quad shuffle from llk_math_transpose_dest.h, written raw today as TTI_MOVB2D(…, (0x3ff & (-16 + 4))), becomes:

// Compile-time path
constexpr hal::move::Transfer<
    hal::move::SrcB,
    hal::move::Dst>
quad_shuffle {
    .source_row             = 16,
    .destination_row        = hal::move::relative_row<-16 + 4>(),
    .destination_addressing = hal::move::RowAddressing::CounterRelative,
    .address_mode           = ADDR_MOD_1,
    .number_of_rows         = hal::move::rows::Four,
};

hal::move::run<quad_shuffle>();

Rejected descriptors

  • Missing required fields; unsupported enum values; GPR indices outside [0, 63]; or half-register indices outside [0, 127].
  • SrcA/SrcB rows outside [0, 63], Dst rows outside [0, 1023], noncanonical row counts, semantic spans crossing either register file, or descriptors expanding beyond eight native TT instructions. For Dst → SrcB, those source and destination ranges are reversed.
  • Blackhole address modes outside [0, 7]; a distinct final mode on a one-instruction transfer; or a total one-row Broadcast::Row.
  • A 16-byte LOADIND/STOREIND or fixed-width Src store whose GPR base is not four-aligned.
  • An immediate MMIO address that is unaligned or outside 0xffb11000..0xffbffffc; any indirect MMIO read.
  • An XMOV size outside [1, 65535] blocks, a span outside L1, or overlapping source and destination spans.

Live-state preconditions

  • Configure effective SrcA/Dst rows eight-aligned for eight-row A2D fragments, SrcB/Dst rows four-aligned for four-row B2D or D2B fragments, and Dst rows eight-aligned for row/scalar broadcast fragments.
  • Configure each address mode to advance the RWCs by its native fragment width; row/scalar broadcast must hold SrcB while advancing Dst, while D2B face extraction advances both Dst and SrcB.
  • Before MOVD2B, own or explicitly mark SrcB valid; MOVD2B does not automatically wait for SrcB bank ownership. On Blackhole, disable implied SrcA-format inference while using Dst-to-SrcB extraction.
  • Use source_32bit_low only when Dst is configured for a 32-bit representation; selecting the low half for a 16-bit Dst representation is undefined.
  • Do not use destination_32bit_low while effective TF32, FP32, or UseDst32b operation makes the Blackhole low-half erratum applicable.
  • Ensure indirect effective addresses name valid L1, source-bank, or writable MMIO locations; the descriptor cannot inspect runtime GPR contents.
  • Respect live data-format behavior, including integer-16 source zero substitution unless the corresponding zero flag is disabled, and schedule consumers only after the selected completion point.

Hardware mapping and zero overhead

A native compile-time matrix or scalar descriptor emits the same single .ttinsn as the matching raw TTI_* macro. Compile-time multi-row transfers contain only their native instruction sequence; they have no loop, branch, descriptor storage, load, or call. A requested completion adds exactly the corresponding STALLWAIT.

Runtime matrix descriptors compute their count and intermediate/final instruction words once, then issue through eight compile-time-instantiated guarded slots. There is no loop or control-flow backedge. Runtime MMIO addressing requires one route-selection branch. With LLK assertions disabled, validation contributes no code. XMOV retains only the CFG writes, launch, and requested mover wait required by the composite itself.
