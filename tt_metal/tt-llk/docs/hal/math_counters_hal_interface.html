Blackhole Math Counter HAL

Build one typed SrcA, SrcB, Dest, and Bias register-word-counter update, inspect a single encoded word, or issue the minimal instruction sequence.

Architecture Blackhole Header hal/math_counters.h Instructions SETRWC · INCRWC · SETIBRWC Path compile-time immediates
Include the fluent math-counter builder#include "hal/math_counters.h"

Quick start

#include "hal/math_counters.h"

using hal::rwc::Counters;

// Compile-time path: one SETRWC sets both counters to 4.
constexpr auto reset_sources =
    hal::math_counters
        .set<Counters::SrcA | Counters::SrcB, 4>();

constexpr std::uint32_t reset_word =
    reset_sources.get_operation();

reset_sources.apply();

The counter mask selects both SrcA and SrcB, so the builder copies the same immediate into both instruction fields and emits one SETRWC.

// Compile-time path: SETRWC first, then SETIBRWC.
hal::math_counters
    .set<Counters::SrcA | Counters::SrcB, 4>()
    .set<Counters::Bias, 0x120>()
    .apply();
Do not call get_operation() on the combined form

Bias has a separate instruction family. apply() may emit the required two instructions; get_operation() statically rejects any description that cannot be represented by exactly one instruction word. Instruction count depends on the selected families, not the number of builder calls: set<Counters::SrcA | Counters::Bias, 4>() also requires both instructions.

Functional model

Descriptionapply() resultget_operation()
Set normal counters, release and switch source banks, clear fidelity, or advance Dest and save to carryOne SETRWCAvailable
Increment SrcA, SrcB, and/or DestOne INCRWCAvailable
Set or increment Bias onlyOne SETIBRWCAvailable
Bias plus any normal-counter stateNormal instruction first, then SETIBRWCCompile-time error

Repeated set() or increment() calls for disjoint masks are folded into one description. A single entry can select several counters when they share a value; separate entries can assign different values. Set and increment entries cannot be mixed.

Bias is normalized into the public counter mask

Counters::Bias uses bit 3 in the HAL. The encoder remaps that selection to the independent SETIBRWC fields. Counters::All remains the one-instruction SrcA/SrcB/Dest mask; use AllIncludingBias when two-family behavior is intentional.

Counter-slot examples

Each normal math counter has two hardware values: a live counter used for addressing and a carry/reset shadow retained for relative stepping and reload. The diagrams name these conceptual slots live and CR; they are hardware state, not C++ objects or memory addresses.

Shared types

Counters

enum class Counters : std::uint8_t {
    None, SrcA = 1, SrcB = 2, Dest = 4, Bias = 8,
    All = 7, AllIncludingBias = 15
};

operator| composes masks. All deliberately excludes Bias so it stays encodable as one SETRWC or INCRWC.

FidelityPhase

enum class FidelityPhase : std::uint8_t { Keep, Clear };

The builder normally preserves fidelity phase. clear_fidelity() selects Clear and therefore the SETRWC family.

Set and increment

// Compile-time path
template <Counters SelectedCounters, std::uint32_t Value = 0>
constexpr auto set() const;

// Compile-time path
template <Counters SelectedCounters, std::uint32_t Value = 0>
constexpr auto increment() const;

SelectedCounters must be nonempty and disjoint from earlier entries. SrcA, SrcB, and Dest values are 4-bit immediates; Bias is a 12-bit immediate.

constexpr auto set_three_values =
    hal::math_counters
        .set<Counters::SrcA, 1>()
        .set<Counters::SrcB, 2>()
        .set<Counters::Dest, 3>();

constexpr auto increment_sources_together =
    hal::math_counters
        .increment<Counters::SrcA | Counters::SrcB, 4>();

Source-bank handoff

release<Sources>() means that Math has finished consuming the selected current SrcA and/or SrcB bank. The SETRWC release field switches Math to the paired bank. With the normal CLR_DVALID configuration, it also clears the consumed bank's data-valid state, returning that bank to the corresponding unpacker so it can be refilled.

// Before: Math consumes the current SrcA bank.
hal::math_counters
    .release<Counters::SrcA>()
    .apply();

// After: Math selects the paired SrcA bank. Normally, the consumed
// bank's data-valid state is clear and its unpacker may refill it.

A standalone release emits one SETRWC and leaves all live and CR counter slots unchanged. Selecting Counters::SrcA | Counters::SrcB performs both source-bank handoffs in that same instruction. A release can also be folded into a normal set() description without adding an instruction.

Bank switching is independent of data-valid clearing

If the per-thread CLR_DVALID.SrcA_Disable or SrcB_Disable bit is set, SETRWC still switches the selected Math bank, but it preserves that bank's data-valid state. In that configuration, release() is a bank switch rather than a return-to-unpacker handoff.

Counter and fidelity modifiers

advance_carry_and_reload() adds each matching assignment's immediate to the selected carry shadow, then reloads the live counter from that result. advance_dest_and_save_to_carry() performs the reverse flow: it advances live Dest by Value, then saves the result to the Dest carry shadow. A zero value copies the current live Dest. These two directions cannot select Dest together.

hal::math_counters
    .set<Counters::SrcA | Counters::SrcB, 4>()
    .advance_carry_and_reload<Counters::SrcA | Counters::SrcB>()
    .release<Counters::SrcA | Counters::SrcB>()
    .apply();

The example computes SrcA_CR += 4 and SrcB_CR += 4, then reloads both live counters from their updated shadows. Its release() also switches both Math source-bank selections and, under normal configuration, returns both consumed banks to their unpackers. Increment descriptions cannot release, clear fidelity, or advance Dest and save it to carry.

Encode and issue

// Compile-time path: exactly one instruction word
static constexpr std::uint32_t get_operation();

// Compile-time path: one or two immediate instructions
inline void apply() const;

get_operation() is intended for MOP, replay, and other fields that hold one encoded Tensix instruction. It accepts every description that encodes as one instruction, including normal-only and Bias-only descriptions. It rejects only descriptions that need both a normal RWC instruction and SETIBRWC. apply() handles both one- and two-instruction descriptions.

// One word: legal for a MOP field.
constexpr std::uint32_t bias_word =
    hal::math_counters
        .increment<Counters::Bias, 1>()
        .get_operation();

// Two words: direct issue only.
hal::math_counters
    .increment<Counters::Dest, 8>()
    .increment<Counters::Bias, 1>()
    .apply();

Validation

  • An empty description, empty entry mask, repeated counter assignment, unsupported mask bit, or mixed set/increment chain fails at compile time.
  • Normal values must be below 16; Bias values must be below 4096.
  • Carry advances must correspond to assigned counters. Dest cannot advance from carry and save to carry in the same description.
  • get_operation() requires exactly one emitted instruction; only the combined normal-plus-Bias form is rejected.
SETIBRWC runtime semantics are not simulator-validated

The Blackhole raw headers and instruction metadata expose the encoding, but the current simulator marks SETIBRWC unsupported and the repository has no production call sites. Tests therefore verify the exact operation word and emitted instruction count, not Bias-counter functional behavior.

Performance

All state is carried in template parameters and every dispatch uses compile-time selection. Normal-only and Bias-only apply() paths emit the same single immediate instruction as their raw TTI_* equivalents. Combining Bias with normal state necessarily emits two instructions and no runtime branch, call, load, store, or persistent builder state.
