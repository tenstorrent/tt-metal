hal::src

Blackhole Source Register HAL

Operate on the SrcA/SrcB register files as a resource: fill, data-valid handoff, gating reset, transpose, shifts, and masks.

Architecture Blackhole Header hal/src.h Instructions ZEROSRC · CLEARDVALID · SETDVALID · GATESRCRST · TRNSPSRCA/B · SHIFTXA/B · SETASHRM* · RAREB
Include the package#include "hal/src.h"

Quick start

#include "hal/src.h"

// Publish the math-filled SrcB bank, consume it, hand it back.
hal::src<hal::SrcB>.publish();                       // SETDVALID {B}
// ... SrcB-to-Dst moves ...
hal::src<hal::SrcB>.release();                       // CLEARDVALID {B}

// One instruction fills both registers' current math banks with zeros.
hal::src<hal::BothSources>.fill();                   // ZEROSRC {A, B}

// Every operation also has a constexpr encoder for MOP/replay embedding.
constexpr std::uint32_t release_b = hal::src<hal::SrcB>.release_operation();

Functional model

SrcA and SrcB are double-banked register files owned alternately by an unpacker (producer) and the math thread (consumer). hal::src gathers every instruction that manipulates them as a resource: filling banks, publishing and releasing bank data-valid, resetting pipeline clock gating, and the in-register features (transpose, shifts, shift masks, rarefication). The entry point is the src variable template over a SourceMask selection — mask operations issue one instruction covering the whole selection, single-register features require exactly one register.

Release in hot loops

The standalone release() costs one instruction. Inner loops should release through the consuming operation instead — hal::fpu SourceRelease or hal::math_counters.release<…>() — which is free.

Selection vocabulary

// hal/utils/source.h
enum class SourceMask : std::uint8_t { SrcA = 0x1, SrcB = 0x2, Both = 0x3 };
inline constexpr SourceMask SrcA, SrcB, BothSources;

// hal/src.h — per-selection entry point; operation types live in hal::src_ops
template <SourceMask Sources>
inline constexpr SourceRegisters<Sources> src {};

Constrained and legacy operations

SETDVALID (publish)

The ISA marks SETDVALID unsupported on Blackhole because the published bank's implied Src format becomes unpredictable. Every live call site publishes a math-filled SrcB bank with implied-format inference disabled. The sanctioned general-purpose publish is the unpacker-side handoff (UNPACR / UNPACR_NOP — see hal::unpack).

SHIFTXA

Blackhole erratum: the shifted row-block selection reuses the last SrcA address and cannot be chosen; the ISA discourages use. The hardware supports a shift amount of one datum only.

Encoding-completeness wrappers

TRNSPSRCA, SETASHRMH/H0/H1/V, and RAREB have no ISA documentation and no LLK call sites; validation is limited to field widths — validate on hardware before first use.
