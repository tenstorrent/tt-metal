namespace hal::unpack

Blackhole unpack HAL

Describe, encode, and issue the three documented Blackhole UNPACR modes without exposing raw instruction fields at each call site.

Architecture Blackhole Header hal/unpack.h Opcode UNPACR 0x42 Status Implemented (additive)
Include the complete typed UNPACR interface#include "hal/unpack.h"

The interface is additive. It does not change an LLK function signature, migrate existing instruction call sites, or model UNPACR_NOP. Quasar uses a different instruction family and is outside this Blackhole interface.

Quick start

#include "hal/unpack.h"

using namespace hal::unpack;

constexpr DataTransfer unpack_srca {
    .engine = Engine::Unpacker0,
    .increments = {.channel0 = {.z = 1}},
    .handoff = SourceHandoff::FlipAndSetDataValid,
};

// Compile-time path: return one encoded instruction for MOP or replay.
constexpr std::uint32_t unpack_srca_word =
    get_operation<unpack_srca>();

// Compile-time path: issue one immediate UNPACR instruction.
run<unpack_srca>();

The operation above selects unpacker 0, advances channel-0 Z by one, explicitly selects configuration context 0 and address-counter context 0, then flips and publishes the completed source bank.

Handoff is intentionally mandatory

DataTransfer::handoff defaults to Unset. The compile-time encoder rejects that sentinel, and LLK assertions diagnose it on the runtime path. State Keep for a partial sequence or FlipAndSetDataValid for the transfer that hands data to the consumer.

Functional model

Opcode 0x42 has three disjoint typed forms. The HAL never emits a mixed special-mode word.

TypeMode selectionEffect
DataTransferBits 13 and 1 clearMove, decompress, and convert configured L1 data through unpacker 0 or 1.
ContextCounterIncrementBit 13 set; bit 1 clearAdvance one unpacker's per-thread configuration context counter without transferring data.
RowStartCacheFlushBit 1 set; bit 13 clearClear compressed-row-start cache state for the current thread or all physical entries.

A data-transfer instruction does not select format, dimensions, base address, compression, transpose, or SrcA-versus-Dst. Those remain configuration and address-counter preconditions. Unpacker 0 targets SrcA or Dst according to configuration; unpacker 1 targets SrcB.

Reserved fields stay private

Bits 5 and 14 always encode zero. Bit 5 has conflicting local Wormhole/Blackhole metadata and no portable ISA semantics, so the typed interface fixes it to zero. The raw macros remain available for low-level compatibility.

Shared types

These types describe the choices shared by the three operation descriptors. Defaults below are the defaults stored by the C++ aggregate; required or invalid defaults are called out explicitly.

Engine

ValueSelected hardwareEffect
Unpacker0Physical unpacker 0A DataTransfer writes SrcA or Dst, as selected by unpacker configuration. Special operations modify unpacker-0 state.
Unpacker1Physical unpacker 1A DataTransfer writes SrcB. Special operations modify unpacker-1 state.

engine has no declared member initializer. If it is omitted from an aggregate, C++ value-initialization produces zero, which currently maps to Unpacker0; set it explicitly so the selected engine is visible at the call site.

AddressCounterPostIncrements

The four fields are independent two-bit increments applied after the transfer. Every field defaults to zero and accepts values from 0 through 3.

FieldDefaultCounter effect
channel0.y0Advance input channel Y. Channel 0 supplies the input/decompressor row position.
channel0.z0Advance input channel Z, contributing to selection of the next input Z plane or face.
channel1.y0Advance output channel Y. The configured channel-1 Y stride converts this counter into an output-register address.
channel1.z0Advance output channel Z. The configured channel-1 Z stride converts this counter into an output-register address.

In multi-context mode, hardware updates both the issuing thread's counters and the selected address-counter context when they differ. UNPACR cannot post-increment X or W; use the address-counter HAL when another dimension must change.

Hardware adds the configured context offset to an explicitly selected or counter-selected configuration context. For unpacker 1, ensure the resulting context remains below two.

SourceHandoff

ValueStatusEffectWhen to use
UnsetDefault; invalid sentinelHas no supported instruction meaning. Compile-time validation rejects it; runtime LLK assertions diagnose it.Never pass it; it exists to detect a missing handoff decision.
KeepValidKeeps the current source bank with the unpacker and does not publish or flip it. Configured source-row auto-update can still advance row state.Use while more transfers will contribute to the same logical source task.
FlipAndSetDataValidValidPublishes the completed SrcA or SrcB bank to the matrix unit, records its implied format on Blackhole, flips the unpacker to the other bank, and resets the per-thread source row to its configured base.Use on the transfer that hands the completed source data to its consumer.

The generated instruction field is named SetDatValid; the ISA functional model calls the same bit FlipSrc. FlipAndSetDataValid names both observable parts of the operation.

DatumOverride

ValueDefaultEffect
NoneYesWrite the input values after normal decompression and format conversion.
ZeroNoForce emitted datums to zero regardless of input. Address generation, search, L1 reads, conversion, and post-increments still occur; this is not a zero-source UNPACR_NOP.

SearchMode

ValueDefaultEffect
DatumRangeYesUse normal per-datum or range selection. Channel-0 X/Y selects the input start, and channel-1 X contributes the end or datum count.
RowNoLocate selected row or blob boundaries using configured tile geometry and row-start metadata. It is especially relevant to compressed row-start tables, but does not itself enable compression.

AccumulationAction

ValueDefaultEffect
ContinueNoClear the instruction's Last bit and keep the unpacker's accumulation buffers open for following transfers in the same assembly task.
FlushYesSet Last, mark this as the final transfer in the assembly task, and flush accumulated or buffered unpack data.

This selection is independent of SourceHandoff. Accumulation flush finishes buffered transfer work; source handoff controls whether the completed source bank is published and flipped.

CacheScope

CacheScope is used only by RowStartCacheFlush; it does not affect a normal DataTransfer.

ValueDefaultEffect
CurrentThreadYesClear the issuing thread's decompression row-start cache entry in the selected engine.
AllEntriesNoClear every physical decompression row-start cache entry in the selected engine.

A row-start-cache flush transfers no data. Use it when compressed backing memory is changed or rapidly reused and cached row boundaries may be stale.

Advanced mode adoption

Non-default context selection, context-counter selection, and row search follow the documented instruction encoding but have no current LLK consumers. When adopting one of these modes, validate its configured context offsets and row-search state end to end in the calling kernel.

template <DataTransfer Operation>
constexpr std::uint32_t get_operation();

inline __attribute__((always_inline)) void run();

// Runtime path
inline constexpr __attribute__((always_inline)) std::uint32_t get_operation(
    const DataTransfer operation);

inline __attribute__((always_inline)) void run(
    const DataTransfer operation);

get_operation returns one encoded word and does not issue it. Compile-time run emits one immediate instruction. Runtime run checks the description when LLK assertions are enabled, constructs the word, and writes it through ckernel::instrn_buffer[0].

Delayed source handoff

constexpr DataTransfer partial {
    .engine = Engine::Unpacker0,
    .increments = {
        .channel0 = {.z = 1},
        .channel1 = {.z = 1},
    },
    .handoff = SourceHandoff::Keep,
};

constexpr DataTransfer final {
    .engine = Engine::Unpacker0,
    .increments = {
        .channel0 = {.z = 1},
        .channel1 = {.z = 1},
    },
    .handoff = SourceHandoff::FlipAndSetDataValid,
};

run<partial>();
run<final>();

Runtime force-zero transfer

// Runtime path: the context ID remains selected at runtime.
run(DataTransfer {
    .engine = Engine::Unpacker0,
    .context = ContextSelection::explicit_context(context_id),
    .handoff = SourceHandoff::Keep,
    .datum_override = DatumOverride::Zero,
});

Zero override does not skip address generation, row search, or input reads. It zeroes data after read and conversion and is not equivalent to a zero-source UNPACR_NOP.

Validation and diagnostics

constexpr bool is_valid(const DataTransfer operation);
constexpr bool is_valid(const ContextCounterIncrement operation);
constexpr bool is_valid(const RowStartCacheFlush operation);

is_valid exposes the complete descriptor predicate. Compile-time encoders enforce it with static_assert. Runtime encoders check each field with a descriptive LLK_ASSERT; when LLK assertions are disabled, those validation helpers are compiled out. The predicate checks:

  • all enum values and the mandatory source handoff;
  • each address increment in the range 0–3;
  • configuration context in the range 0–7 and address-counter context in the range 0–2;
  • explicit unpacker-1 configuration context below two; and
  • canonical special modes with unrelated bits cleared by construction.

With LLK assertions enabled, invalid runtime input reaches a field-specific diagnostic. With assertions disabled, the runtime path deliberately has raw-instruction semantics: call is_valid explicitly when untrusted values must be rejected in a production build.

Configuration precondition for unpacker 1

Explicit or counter selection combines with the configured context offset, which the instruction description cannot inspect. Ensure the final unpacker-1 configuration context remains below two.

Performance and hardware mapping

The compile-time path lowers to the same single immediate instruction used by existing TTI_UNPACR call sites. It performs no runtime dispatch or hot-path word construction. With LLK assertions disabled, the runtime path contains only the context selection and field packing required by the equivalent raw TT_UNPACR operation, followed by one instruction-buffer write. Enabling LLK assertions intentionally adds diagnostic checks.

The interface does not change configured format conversion, compression, upsampling, throttling, or dual-unpacker contention. Those characteristics continue to come from CFG and address-counter state.
