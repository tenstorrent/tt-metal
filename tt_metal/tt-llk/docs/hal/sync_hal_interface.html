namespace hal::sync

Blackhole synchronization HAL

Typed mutex, semaphore, Wait Gate, and NoC stream primitives mapped directly to the Blackhole SYNC ISA.

Architecture BlackholeLanguage C++17Header hal/sync.hBackend SYNC / Wait Gate
Include the complete synchronization interface#include "hal/sync.h"

Quick start

#include "hal/sync.h"

using namespace hal::sync;

// Compile-time path
// Producer: wait for capacity, then publish one token.
wait::semaphore<
    StallTarget::Sync,
    SemaphoreMask::MathPack,
    SemaphoreCondition::WhileMaximum>();
semaphore::post<SemaphoreMask::MathPack>();

// Consumer: wait for a token, then consume it.
wait::semaphore<
    StallTarget::Sync,
    SemaphoreMask::MathPack,
    SemaphoreCondition::WhileZero>();
semaphore::get<SemaphoreMask::MathPack>();

get() is the ISA's atomic decrement operation; it does not return a value. Use semaphore::read() for an MMIO value read.

Functional model

The SYNC unit owns four mutexes and eight semaphores shared by the three Tensix threads. STALLWAIT, SEMWAIT, and STREAMWAIT install one wait instruction in the issuing thread's Wait Gate. The thread continues until an instruction selected by the block mask reaches that gate; that instruction and everything behind it stop until the condition is satisfied.

issue wait instruction:
    current_thread.wait_gate.latched_wait = instruction

each cycle:
    evaluate the latched condition
    if condition is active and next instruction matches block mask:
        pause in-order issue
    else:
        remove the block mask after one cycle
One latched wait per thread

A later wait cannot pass an active wait's gate and replace it. StallTarget::Sync extends the block to ordinary mutex and semaphore operations.

A zero block mask is not “block nothing”: hardware substitutes Math. For STALLWAIT, a zero condition mask substitutes ScalarIdle | Unpacker0Idle | Unpacker1Idle | PackerIdle. The HAL names both zero encodings HardwareDefault.

StreamSlot, StreamTarget, and StreamId

    Phase,
    MessagesReceived,
};

Type/valueEncodingMeaning and constraints
StreamSlot::S0 … S30 … 3Select one of four thread-private STREAM_ID_SYNC entries.

Mutex interface

acquire() issues ATGETM. It completes if the mutex is free or already owned by the issuing thread; otherwise that thread waits. release() issues ATRELM. Reacquisition is not recursively counted.

Declarations

}
NameTypeMeaning
MMutex template valueCompile-time-selected physical mutex or semantic alias.
mutexMutexRuntime-selected mutex. Valid physical values are 0, 2, 3, and 4.

The *_operation() overloads return an encoded instruction without issuing it. The other overloads issue one instruction.

Example

mutex::release<Mutex::RegisterRmw>();

// Runtime path

mutex::release(runtime_mutex);

Semaphore interfaces

Each semaphore contains four-bit Value and Max fields. Tensix mask operations modify every selected semaphore atomically.

InterfaceEffectAccess
initAssign Value and Max.Tensix only
postIncrement Value, saturating at 15.Tensix mask or one MMIO index
getDecrement Value, saturating at zero.Tensix mask or one MMIO index
readReturn current Value.MMIO only
Saturation applies to the hardware, not to assert builds on the MMIO path

The Access::MMIO overloads route through ckernel::semaphore_post / ckernel::semaphore_get, which LLK_ASSERT that the semaphore is not already at its maximum before a post and not already at zero before a get. With assertions enabled, an MMIO post at 15 or an MMIO get at 0 traps instead of saturating; only the Tensix path (and assert-disabled builds) exhibits the pure saturating behavior in this table.

MMIO ordering is a RISC concern

The PC-buffer window exposes atomic semaphore accesses but does not turn a Tensix wait into a RISC memory fence. Apply the memory-ordering rules required by surrounding loads and stores.

Stream-wait interfaces

STREAMWAIT is Blackhole-only. A StreamSlot chooses one of four thread-private selector entries; that entry stores the six-bit tile-local overlay stream ID to observe.

Feature declaration

inline constexpr bool supports_stream_wait = true;

Blackhole exposes the stream-wait interfaces. Consumers can use this constant when sharing code with architectures that do not.
