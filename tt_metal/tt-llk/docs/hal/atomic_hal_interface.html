namespace hal::atomic

Blackhole L1 atomic HAL

Atomically update shared L1 protocol state: counters, FIFO read/write pointers, locks, and selected parts of a 16-byte line.

Quick start

// Locate: GPR[AddressIndex = 10] * 16 bytes + word 2 * 4 bytes.
// Update: WidthBits = 16 controls wrapping; it does not affect the address.
constexpr hal::atomic::Counter<16, 10> packets {
    hal::gpr<10>(), // AddressIndex 10: GPR 10 contains L1 byte_address / 16.
    2,              // Select 32-bit word 2: the third word, at byte offset +8.
};

// Build a FetchIncrement descriptor. Nothing executes.
constexpr auto fetch = packets.fetch_add(hal::gpr<11>());

// Read its encoded instruction word. Nothing executes.
constexpr std::uint32_t instruction = fetch.get_operation();

// Issue one posted ATINCGET; see the Functional model below.
hal::atomic::fetch_add<packets>(hal::gpr<11>());

Read the type as Counter<WidthBits, AddressIndex>:

ArgumentParameterMeaning in this example
16WidthBitsCounter width, valid in [1, 32]. The low 16 bits of the selected 32-bit word wrap modulo 2^16; the upper 16 bits are preserved. It is not the L1 line size.
10AddressIndexHardware address-GPR index, valid in [0, 63]. AddressIndex == 10 makes the address member have type hal::Gpr<10>. The expression hal::gpr<10>() calls the lowercase factory function to construct a value of that type: Gpr is the type name and gpr() is the factory function. The runtime contents of GPR 10 select the L1 line; 10 is not itself an L1 address.
The two uses of 16 are unrelated

Do not read the 16 in Counter<16, 10> as the address multiplier. That template argument is the counter width chosen by software. The separate multiplication by 16 is fixed by the ISA because the address GPR names a 16-byte L1 line.

The final initializer 2 is a zero-based word selector, not a number of words. At execution, the selected word starts at byte address GPR[10] * 16 + 2 * 4. This identity names the low 16 counter bits of that word: fetch_add wraps them modulo 2^16, preserves the upper 16 bits, and returns the complete old 32-bit word.

The execution boundary

Identity member functions build descriptors. A descriptor's .get_operation() encodes one word. Neither action issues hardware. Only run(...) and the namespace verbs such as fetch_add(...) issue instructions. fetch_add is posted, so drain ScalarIdle before reading or reusing GPR 11. Descriptors intentionally have no .apply().

Functional model

Every operation starts from shared state in one 16-byte-aligned L1 line. The address operand is a GPR whose runtime value is multiplied by 16 to select that line. “Atomic” means the shared Scalar Unit reads the state, makes its decision, and performs the listed update as one indivisible L1 transaction. It does not make surrounding payload loads or stores part of that transaction.

These are four different L1 atomic primitives, not four operations on one FIFO. Only FifoAcquire interprets its L1 state as FIFO control counters; the other descriptors operate on an independent counter, lock word, or masked line.

Every public verb follows the same path: combine an identity with the call arguments to build one descriptor, then pass that descriptor to run. In the pseudocode, gpr_index(operation.address) or gpr_index(operation.data) extracts the hardware GPR number held by the corresponding hal::Gpr field. GPR[index] then means that register's runtime contents. L1.u32[byte_address] and L1.u16[byte_address] are conceptual notation, not HAL APIs: they mean a 32-bit word or 16-bit granule at that L1 byte address. The HAL emits the atomic instruction; it does not dereference an L1 C++ object. posted marks work that can finish asynchronously after the instruction sends its L1 request and releases the issuing Tensix thread.

Fetch increment — ATINCGET

// operation is the FetchIncrement descriptor from the table above.
address_index = gpr_index(operation.address);
data_index = gpr_index(operation.data);

target = GPR[address_index] * 16
       + operation.word_select * sizeof(std::uint32_t);
addend = GPR[data_index];
counter_mask = operation.counter_width == 32
    ? 0xffffffffu
    : (1u << operation.counter_width) - 1u;

posted {
    atomic {
        old_word = L1.u32[target];
        incremented = old_word + addend;
        L1.u32[target] =
            (old_word & ~counter_mask)
            | (incremented & counter_mask);
    }

    // Written later than the L1 request; the complete old word is returned.
    GPR[data_index] = old_word;
}

For Counter<16, 10> {hal::gpr<10>(), 2}.fetch_add(hal::gpr<11>()), the descriptor fields become {address = gpr<10>, data = gpr<11>, word_select = 2, counter_width = 16}. The mask is therefore 0x0000ffff: the expression preserves the old upper 16 bits and replaces the low 16 bits with the wrapped sum. The data GPR is both input and output. Drain ScalarIdle before reading or reusing it.

Concrete counter-wrap example

FIFO pointer operation — ATINCGETPTR

// operation is the FifoAcquire descriptor from the table above.
// Public mapping: pop_slots/Empty use Read; push_slots/Full use Write.
address_index = gpr_index(operation.address);
result_index = gpr_index(operation.data); // This field is the result GPR here.

control = L1.fifo_control_at(GPR[address_index] * 16);
capacity = 1u << operation.capacity_log2;
counter_mask = 2u * capacity - 1u; // capacity_log2 + 1 low bits
increment = 1u << operation.increment_log2;

retry:
atomic {
    read_pointer = control.rd;
    write_pointer = control.wr;
    distance = uint32(write_pointer - read_pointer);
    empty = distance == 0;
    full = !empty && (distance % capacity) == 0;

    if ((operation.pointer == FifoPointer::Read && empty)
        || (operation.pointer == FifoPointer::Write && full)) {
        goto retry;
    }

    old_pointer = operation.pointer == FifoPointer::Read
        ? read_pointer
        : write_pointer;

    if (!operation.probe_only) {
        incremented = old_pointer + increment;
        new_pointer =
            (old_pointer & ~counter_mask)
            | (incremented & counter_mask);

        if (operation.pointer == FifoPointer::Read)
            control.rd = new_pointer;
        else
            control.wr = new_pointer;
    }
}

GPR[result_index] = old_pointer;

For Fifo<8, 30> {hal::gpr<30>()}.push_slots<2>(hal::gpr<31>()), the descriptor contains {address = gpr<30>, data = gpr<31>, pointer = Write, capacity_log2 = 8, increment_log2 = 2, probe_only = false}. Thus capacity == 256, counter_mask == 0x1ff, and a successful operation returns the old write counter in GPR 31 and advances its low nine bits by four. Calling wait_while<FifoState::Full> instead selects the same write counter but sets probe_only = true: it waits while full, returns the current write counter, and does not advance it. Neither form moves FIFO payload data.

Compare and set — ATCAS

// operation is the CompareSet descriptor from the table above.
address_index = gpr_index(operation.address);
target = GPR[address_index] * 16
       + operation.word_select * sizeof(std::uint32_t);
expected = zero_extend_32(operation.compare);
replacement = zero_extend_32(operation.set);

retry:
atomic {
    if (L1.u32[target] != expected)
        goto retry;

    L1.u32[target] = replacement;
}

For Lock {hal::gpr<40>(), 0}.acquire(), the descriptor contains {address = gpr<40>, word_select = 0, compare = 0, set = 1}: it targets GPR[40] * 16 + 0, waits for the complete 32-bit word to equal zero, and writes one. release() changes only the descriptor values to {compare = 1, set = 0}. Nothing is returned.

Masked line write — ATSWAP

// operation is the MaskedWrite descriptor from the table above.
address_index = gpr_index(operation.address);
data_index = gpr_index(operation.data); // Must be divisible by four.
target_line = GPR[address_index] * 16;

// Capture four consecutive GPRs as eight consecutive 16-bit granules.
for (i = 0; i < 8; ++i) {
    source_word = GPR[data_index + i / 2];
    source_granule[i] =
        (source_word >> (16 * (i % 2))) & 0xffff;
}

posted {
    atomic {
        for (i = 0; i < 8; ++i) {
            if (operation.granule_mask & (1u << i))
                L1.u16[target_line + i * 2] = source_granule[i];
        }
    }
}

What CounterIdentity means

template <
    auto CounterIdentity,
    std::uint32_t DataIndex>
void fetch_add(
    hal::Gpr<DataIndex> data);

CounterIdentity is a template-parameter name, not a type and not another struct. It means “the complete constexpr Counter supplied inside angle brackets.” In the quick start, packets is the CounterIdentity in fetch_add<packets>(...). There is no separate counter-cell type.

Shared types

enum class FifoState : std::uint8_t
{
    Empty, // wait while the FIFO has no readable units
    Full   // wait while the FIFO has no writable units
};

// Low-level FifoAcquire descriptor field; semantic FIFO calls hide it.
enum class FifoPointer : std::uint8_t
{
    Read  = 0, // retry while empty
    Write = 1  // retry while full
};

template <std::uint32_t Index>
struct hal::Gpr;

FifoState names the condition that keeps wait_while blocked. FifoPointer mirrors the instruction encoding and appears only when constructing a low-level FifoAcquire descriptor directly; wait_while, pop_slots, and push_slots select it for the caller.

hal::Gpr<Index> identifies a hardware GPR; constructing it does not read the register. Use hal::gpr<Index>() for a fixed register or hal::gpr(index) for a runtime-selected register. An AddressIndex or DataIndex template parameter is therefore a GPR number, not a memory address.

Names ending in Log2 are base-two exponents. CapacityLog2 == 8 gives a capacity of 2^8 == 256 FIFO units and a nine-bit wrapping read/write counter. IncrementLog2 == 2 advances the selected counter by 2^2 == 4 units. A unit is whatever the surrounding protocol chooses: a slot, tile, packet, byte, or another fixed quantity. The atomic instruction manages counters; it does not know the payload element size.

State being manipulated

The payload ring and its element size belong to the caller. This interface operates only on a separate FIFOControl line in L1. For capacity C = 2^CapacityLog2, initialize both counters to the same value and keep each value in the low CapacityLog2 + 1 bits:

16-byte FIFOControl line                    Separate caller-owned payload ring
+0x0  32-bit read counter (rd)             C units: [0] [1] ... [C - 1]
+0x4  32-bit write counter (wr)
+0x8  not used by this FIFO operation       payload index = returned_counter % C
+0xc  not used by this FIFO operation

occupancy = (wr - rd) modulo (2 * C)
empty     = occupancy == 0
full      = occupancy == C

The extra counter bit distinguishes an empty ring from a full ring when rd and wr point at the same payload index. Thus a capacity-eight FIFO uses four-bit counters that wrap modulo 16, while the payload index wraps modulo 8. Bits above the counter width must remain zero. Constructing a Fifo only names this state; it does not allocate or initialize either the control line or the payload ring.

What the primitive is for

A normal load followed by a fullness check and a later store can race with another FIFO user. ATINCGETPTR performs the read/write-counter check, captures the selected pointer, and updates that pointer as one atomic transaction. It changes only FIFO bookkeeping; software still moves the payload and supplies any required ordering around that movement.

What each FIFO operation does

FifoIdentity is the complete constexpr Fifo passed in angle brackets. State names the condition that blocks wait_while; pop_slots and push_slots select the read and write counters directly. ResultIndex is inferred from the GPR that receives the old counter. The descriptor's AddressIndex and DataIndex are likewise inferred from its GPR operands.

OperationCondition retried by hardwareValue returnedAtomic state changeFIFO meaning
wait_while<FifoState::Empty>Wait while empty.Current rd.None.Readable data exists; inspect the next read position without popping it.
pop_slots<M>Wait while empty.Old rd.rd = (rd + 2^M) % (2*C)Pop 2^M units from FIFO bookkeeping.
wait_while<FifoState::Full>Wait while full.Current wr.None.Writable space exists; inspect the next write position without pushing it.
push_slots<M>Wait while full.Old wr.wr = (wr + 2^M) % (2*C)Push 2^M units into FIFO bookkeeping.

IncrementLog2 == 0 means advance by one unit, not “do not increment.” Only wait_while leaves the selected counter unchanged. Consequently, a wait does not reserve the returned position against another FIFO user. If a readiness check fails, that attempt makes no state change; the issuing Tensix thread remains blocked while hardware retries.

“Blocking” is a Tensix execution property

The C++ verb pushes the instruction asynchronously. Once the instruction reaches the Scalar Unit, later instructions from that Tensix thread cannot pass until the condition succeeds. Apply the documented ScalarIdle synchronization before the RISC reads the result GPR.

Worked producer-to-consumer flow

For a single-producer, single-consumer FIFO, or one protected by an external lock, suppose Fifo<2, AddressIndex> describes four payload slots and starts with rd = wr = 0:

StepAction and resultControl stateWhat happened to the data
1. Producer waitswait_while<FifoState::Full> returns 0.rd = 0, wr = 0 (empty)No data moves and no slot is reserved. With this protocol, payload index 0 & 3 == 0 is the producer's next position.
2. Producer writesSoftware writes payload slot 0 and completes the ordering required by its protocol.rd = 0, wr = 0The payload changes; the atomic primitive is not involved.
3. Producer publishespush_slots<0> returns old wr == 0.rd = 0, wr = 1The atomic write-counter advance records one pushed unit.
4. Consumer waitswait_while<FifoState::Empty> returns 0.rd = 0, wr = 1Slot 0 & 3 == 0 is readable; no unit is popped yet.
5. Consumer readsSoftware reads payload slot 0 and completes the ordering required by its protocol.rd = 0, wr = 1The payload is consumed outside the atomic primitive.
6. Consumer releasespop_slots<0> returns old rd == 0.rd = 1, wr = 1 (empty)The atomic read-counter advance records one popped unit and makes the slot reusable.

After four pushes without a pop, rd = 0, wr = 4: both counters select payload index 0, but the phase bit differs, so the FIFO is full. After four matching pops, rd = wr = 4, so it is empty again. Both counters wrap after 8.

The example relies on its ownership protocol

wait_while does not reserve a position. Multiple producers or multiple consumers need an additional ownership protocol; otherwise another user can act on the same returned position before the pointer advances.

Batched increments need a protocol check

Keep the increment no larger than the capacity. Before advancing by more than one, the surrounding protocol must also establish that the FIFO contains the complete read batch or has room for the complete write batch; hardware checks only empty/nonempty or full/nonfull.

Usage

The host or surrounding runtime must reserve a 16-byte-aligned control line and a non-overlapping payload buffer in L1, then pass their byte addresses to the kernel. A Fifo object does not allocate either region, and hal::gpr<30>() only names GPR 30—it does not put a value into that register. The following kernel-side setup initializes an empty FIFO and loads the control-line address into GPR 30:

#include "hal/atomic.h"
#include "hal/gpr_ops.h"

constexpr hal::atomic::Fifo<8, 30> output_fifo {
    hal::gpr<30>(), // GPR 30 contains FIFOControl byte_address / 16.
};

void initialize_output_fifo(const std::uint32_t control_byte_address)
{
    // The host/runtime must provide a 16-byte-aligned L1 address.
    LLK_ASSERT(
        (control_byte_address & 0xfu) == 0u,
        "FIFOControl must be 16-byte aligned");

    volatile std::uint32_t* control =
        reinterpret_cast<volatile std::uint32_t*>(control_byte_address);

    // Initialize the shared control state once, before any FIFO user starts.
    ckernel::store_blocking(&control[0], 0u); // rd at byte offset +0.
    ckernel::store_blocking(&control[1], 0u); // wr at byte offset +4; rd == wr means empty.

    // ATINCGETPTR computes control_byte_address = GPR[30] * 16.
    // Each Tensix thread that issues FIFO operations must set its own GPR 30.
    hal::gpr_ops::set(
        hal::gpr<30>(),
        control_byte_address >> 4);
}

// Separately, the host/runtime supplies 256 payload slots because
// CapacityLog2 == 8. It chooses each slot's byte size and layout.
// ATINCGETPTR is not given the payload address and never moves payload data.

// Encode only: push four units in the FIFO bookkeeping.
constexpr auto descriptor = output_fifo.push_slots<2>(
    hal::gpr<31>());
constexpr std::uint32_t word = descriptor.get_operation();

// Issue the same protocol operation.
hal::atomic::push_slots<
    output_fifo,
    2>(hal::gpr<31>());

// Block for readable data without advancing the read pointer.
hal::atomic::wait_while<
    hal::atomic::FifoState::Empty,
    output_fifo>(hal::gpr<31>());
Do not apply L1_ADDRESS() to this control address

ATINCGETPTR uses the exact 16-byte line address, so load control_byte_address >> 4. The Blackhole L1_ADDRESS() helper additionally subtracts one for other LLK address fields and would therefore select the wrong line here.

Compare and set: Lock and CompareSet

Declarations

template <std::uint32_t AddressIndex>
struct CompareSet
{
    hal::Gpr<AddressIndex> address;
    std::uint8_t word_select = 0;
    std::uint8_t compare;
    std::uint8_t set;

    constexpr std::uint32_t get_operation() const;
};

template <std::uint32_t AddressIndex>
struct Lock
{
    hal::Gpr<AddressIndex> address;
    std::uint8_t word = 0;

    constexpr CompareSet<AddressIndex> acquire() const;
    constexpr CompareSet<AddressIndex> release() const;

    template <
        std::uint8_t Compare,
        std::uint8_t Set>
    constexpr CompareSet<AddressIndex> compare_set() const;

    constexpr CompareSet<AddressIndex> compare_set(
        std::uint8_t compare,
        std::uint8_t set) const;
};

// Compile-time issuing paths
template <auto LockIdentity>
void acquire();

template <auto LockIdentity>
void release();

template <
    auto LockIdentity,
    std::uint8_t Compare,
    std::uint8_t Set>
void compare_set();

// Mixed issuing paths
template <std::uint32_t AddressIndex>
void acquire(
    Lock<AddressIndex> lock);

template <std::uint32_t AddressIndex>
void release(
    Lock<AddressIndex> lock);

template <std::uint32_t AddressIndex>
void compare_set(
    Lock<AddressIndex> lock,
    std::uint8_t compare,
    std::uint8_t set);

LockIdentity is the complete constexpr Lock passed in angle brackets. Compare and Set are the four-bit immediate values on the compile-time generic path. AddressIndex is inferred from lock.address on the mixed path.

ATCAS means atomic compare-and-set. It repeatedly reads the selected 32-bit word until the entire word equals the zero-extended four-bit compare value. It then atomically replaces that word with the zero-extended four-bit set value. Lock::acquire() creates {compare 0, set 1}; Lock::release() creates {compare 1, set 0}.

ATCAS compares the complete word

Nonzero upper bits or a compare value that can never occur make the instruction retry indefinitely.

Usage

constexpr auto lock = hal::atomic::Lock {
    hal::gpr<40>(),
    0, // Select 32-bit word 0: effective byte address = GPR[40] * 16 + 0 * sizeof(std::uint32_t).
};

// Encode only.
constexpr auto acquire_descriptor = lock.acquire();
constexpr std::uint32_t word = acquire_descriptor.get_operation();

// Issue the lock protocol.
hal::atomic::acquire<lock>();
// Critical section.
hal::atomic::release<lock>();

// Wait for whole-word value 3, then replace it with 4.
hal::atomic::compare_set<lock, 3, 4>();

Masked write: MaskedWrite and store_masked

Declarations

template <
    std::uint32_t AddressIndex,
    std::uint32_t DataIndex>
struct MaskedWrite
{
    hal::Gpr<AddressIndex> address;
    hal::Gpr<DataIndex> data;
    std::uint8_t granule_mask;

    constexpr std::uint32_t get_operation() const;
};

// Compile-time mask
template <
    std::uint8_t GranuleMask,
    std::uint32_t AddressIndex,
    std::uint32_t DataIndex>
void store_masked(
    hal::Gpr<AddressIndex> address,
    hal::Gpr<DataIndex> data);

// Runtime mask
template <
    std::uint32_t AddressIndex,
    std::uint32_t DataIndex>
void store_masked(
    hal::Gpr<AddressIndex> address,
    hal::Gpr<DataIndex> data,
    std::uint8_t granule_mask);

data is the first register in a four-aligned GPR quad: 0, 4, 8, ..., 60. Requiring both data < 64 and data % 4 == 0 guarantees that the implied four-register source remains in range; base 60 uses the final valid quad, GPRs 60–63. The address GPR may be any index in [0, 63]. Mask bit i enables 16-bit granule i of the 16-byte line. Nothing is returned; “swap” in the ISA name means replacement of selected granules, not an exchange.

What validation guarantees

Compile-time issuing rejects an out-of-range or misaligned GPR with static_assert. Value-selected issuing diagnoses it with LLK_ASSERT only while LLK assertions are enabled; disabling assertions deliberately removes those runtime checks. The mask is already a std::uint8_t, so every representable value 0x00..0xff is valid: zero writes no granules and 0xff writes all eight. If a wider runtime integer is passed, C++ converts it to std::uint8_t before the function executes, potentially discarding upper bits; range-check wider inputs before calling.

Usage

// Encode only. Source data occupies GPRs 56 through 59.
constexpr hal::atomic::MaskedWrite descriptor {
    hal::gpr<50>(),
    hal::gpr<56>(),
    0xa5,
};
constexpr std::uint32_t word = descriptor.get_operation();

// Issue with a compile-time mask.
hal::atomic::store_masked<0xa5>(
    hal::gpr<50>(),
    hal::gpr<56>());

// Issue with a runtime mask.
hal::atomic::store_masked(
    address,
    aligned_data,
    runtime_mask);

Issuing descriptors directly

Declarations

// Compile-time path
template <auto Operation>
void run();

// Runtime path: one typed overload for each descriptor
template <
    std::uint32_t AddressIndex,
    std::uint32_t DataIndex>
void run(
    FetchIncrement<AddressIndex, DataIndex> operation);

// Equivalent overloads exist for FifoAcquire, CompareSet, and MaskedWrite.

Use a semantic verb when an identity exists; it communicates the protocol better. Use run when code already owns a complete descriptor. run<Operation>() emits an immediate instruction, while run(operation) writes the value-selected word through ckernel::instrn_buffer[0].

constexpr auto descriptor = packets.fetch_add(hal::gpr<11>());

// Immediate issue.
hal::atomic::run<descriptor>();

// Value-selected issue: construct the descriptor from runtime GPR indices and fields.
const auto address = hal::gpr(address_index);
const auto data = hal::gpr(data_index);
const hal::atomic::FetchIncrement runtime_descriptor {
    address,
    data,
    word,
    counter_width,
};
hal::atomic::run(runtime_descriptor);

Validation

is_valid(...) overloads cover all four descriptors and all three identities. Compile-time run<Operation>() rejects invalid descriptors with static_assert. Value-selected .get_operation() checks every field with a descriptive LLK_ASSERT. When LLK assertions are disabled, the validation helpers are compiled out and emit no runtime code. Enable LLK assertions while diagnosing invalid runtime inputs.

  • Every resolved GPR index must be in [0, 63].
  • Counter width is [1, 32]; word selection is [0, 3].
  • FIFO capacity and increment exponents are [0, 15]; probes cannot increment.
  • ATCAS compare and set values are four-bit values.
  • ATSWAP data begins at a four-aligned GPR index in {0, 4, ..., 60}; every eight-bit granule mask is valid.

Hardware mapping and completion

The immediate path matches raw TTI_AT*: compile-time validation and encoding leave exactly one embedded .ttinsn, with no descriptor storage, branch, call, or runtime encoding. With LLK assertions disabled, the value-selected path matches raw TT_AT*: it performs only the field arithmetic required to form a runtime instruction word and one write through ckernel::instrn_buffer[0]. It adds no validation branch, trap, allocation, or descriptor storage in optimized builds. Enabling LLK assertions intentionally adds diagnostic checks.

A genuinely runtime instruction word cannot use INSTRUCTION_WORD, whose immediate constraint requires a constant. Therefore “zero overhead” means parity with the corresponding raw macro: TTI_AT* for immediate selections and TT_AT* for value-selected fields. The HAL fixes the ISA memory selector and reserved fields to zero because these operations target L1.

FetchIncrement and MaskedWrite are posted. Wait for ScalarIdle, while gating the actual dependent consumer, before consuming a fetch result, reusing its GPR, or relying on updated memory. FifoAcquire and CompareSet instead hold the issuing thread until success.

Blocking atomics require eventual progress

An impossible FIFO condition or compare value can block all following instructions from the issuing thread and occupy the shared Scalar Unit.
