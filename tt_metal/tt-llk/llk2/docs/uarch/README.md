# LLK 2.0 microarchitecture

Status: **draft for review**.
These documents specify the LLK 2.0 compute stack on Blackhole.
Once reviewed, they are the input for generating the ops, kernels and stack code.
Where the code and these documents disagree, the review decides which one changes.

| Doc | Covers | Rule prefix |
|-----|--------|-------------|
| [stack.md](stack.md) | The layers, how a call crosses them, threads, sync, Dest ring | `STK-` |
| [tensor.md](tensor.md) | The operand type: shape, spec, owner, release | `TEN-` |
| [resolver.md](resolver.md) | Compile-time planning: `OpApi`, `OpConfig`, `Work`, `Plan` | `RES-` |

## Evidence

The rules are taken from the prototype on `ncvetkovic/llk2-matmul` ([PR]).
Every code link is pinned to commit `972eb4d`, so line numbers stay right while the branch moves on.
To re-pin, change `SHA` in `gen_links.py` and, from this directory, run `python3 gen_links.py <repo root> *.md`.
It rewrites the link block at the end of each doc and prints the source line each tag points at, so a stale tag shows up in review.

## How to read a rule

```
- **TEN-OWN-3** · A tensor under a given owner is always the same C++ type. [tensor.h:318-325]
```

- **ID**: `<DOC>-<AREA>-<n>`.
  IDs are never reused or renumbered.
  A rule that is dropped is struck through and stays in place.
- **Contract** sections hold normative rules: what the generated code must do.
- **Rationale**, **Examples** and **Open items** are descriptive.
  Review comments on them do not change the contract unless a rule changes.
- One sentence per line, so each review comment lands on one claim.

## Provenance tags

Every claim carries one of these tags:

| Tag | Meaning |
|-----|---------|
| `[file:line]` | Stated by, or read directly from, the prototype code at that line. Rendered as a pinned link. |
| `[PR]` | Stated in the PR description, not in code. |
| `[derived]` | Computed from code-tagged rules; the working is shown next to it. |
| `[open]` | Not settled by the code or the PR. A question for reviewers, never a rule. |

Code tag prefixes: `tensor.h`, `thread.h`, `settings.h`, `kernel.cpp`, `README.md`, and directories `api/` (`inc/common/compute_api`), `lib/` (`inc/blackhole/llk_lib`), `res/` (`inc/common/resolver`), `bh-res/` (`inc/blackhole/resolver`), `hal/` (`tt_llk_blackhole/llk_lib/hal`), `tests/` (`tests/python_tests`).

## Reviewing

- Comment on a rule by its ID, for example "TEN-SYNC-6: also allow unpack → math".
- A test that checks a rule names the rule ID in its docstring, so a regenerated stack can be checked rule by rule.
- Open items are numbered (`TEN-OPEN-n`); resolving one either adds a rule or closes the item with a reason.
