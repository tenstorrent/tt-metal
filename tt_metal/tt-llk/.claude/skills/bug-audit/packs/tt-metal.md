Reviewer checks were mined from inline review threads on the most-reviewed quarter of PRs (a bounded sample; see the last section). Class weights are approximate: a post-mortem of benchmark picks found about 12% of triage "code bugs" were not defects (cleanups, lint fixes, feature enablement), so read the table as an ordering, not exact shares.

## Classes, by weight

### `contract-mismatch`: Producer and consumer re-derive one fact differently

Two sides must agree on one fact: a credit or page count, a size, an address or stride, a layout, a register or valid choice, a protocol flag, an encoding, a shape rank. Instead of reading it from one shared source, each side works it out on its own, and the two drift apart. Four shapes keep coming back.

- For every quantity used on both sides of a handshake (initial credits vs. returned or max credits, expected completions vs. faked acks, semaphore or CB page counts, slot strides), trace each side back to its host source. Flag it unless both read the same config object or function over the same set of devices or cores, or an assert ties them together. Then evaluate each formula under every topology, CQ count, arch and subset/superset device set.
- Wherever a size is computed in one pass and consumed or emitted in another (calculator vs. populator, hand-summed sizeof headers, size field vs. laid-out bytes, copy length vs. advance length), line the two up per branch, including pinned/inline/large-page branches and alignment calls. Check that copy lengths come from the SOURCE extent, never the padded destination. Check that the equality check is TT_FATAL, not a Release-stripped TT_ASSERT.
- For every CB/DFB entry, stride or alignment a factory computes for data moved by the NoC, check that it comes from the actual buffer's alignment for its memory type (buffer->alignment(), aligned_page_size, HAL), not a literal 32 or max(L1,DRAM). Check that the alignment is taken from the buffer that is the NoC source for reads or the destination for writes. Re-evaluate for small row-major pages on the arch with the largest DRAM alignment (64B).
- *Seeds:* MemoryConfig{} or MemoryConfig(x.memory_layout(), x.buffer_type(), x.shard_spec()) inside compute_output_specs / host tensor ops (tt_metal/impl/tensor/*, ttnn/cpp/ttnn/operations/data_movement/{tilize,untilize*,fold}/device) | round_up_to_mul32\( or align\(.*, *32\) sizing CB/DFB page_size for row-major DRAM data in ttnn/**/program_factory.cpp (embedding, moreh_getitem, argmax)
- *Clusters in:* tt_metal/impl/dispatch/kernel_config + kernels/cq_prefetch/cq_dispatch (credit counts, command framing, sizes); tt_metal/impl/buffers/dispatch.cpp and tt_metal/impl/tensor (calculator vs. emitter, copy sizes, per-core addresses, spec rebuilds); tt_metal/fabric builders and ttnn/**/ccl kernels (per-endpoint link protocol, NoC coordinate systems, scatter-write preconditions); ttnn/cpp/ttnn/operations/conv (conv_transpose2d lowering, weight/bias prep, sliding_window config)

### `missing-case`: Unhandled enum, dtype, shape and topology cases

A dispatch (an if/else-if chain, an if-constexpr ladder, a ternary, a boolean routing predicate) lists the cases its author had in mind and ends in a silent default: the Float16_b/bf16 kernel flavour, the signed Int32 branch, an empty fall-through that leaves Dest unchanged, a metadata-only view, the composite fallback. A new or rare value then takes a path with the wrong semantics and produces no error. Typical cases are UINT32/UINT16/UINT8, a second ERISC, a new storage variant, HYBRID allocator mode, a service core, or an idle ethernet core.

- For every dispatch that maps an enum or DataType to a kernel template argument, a file name or a code path, list every value the upstream API or the kernel's static_assert admits, and confirm each one has an explicit arm. The chain should end in static_assert, TT_THROW or an exhaustive switch with no default, never a silent default to a bf16/Float16_b/Int32 flavour or an empty else. Pay special attention to UINT8/UINT16/UINT32 reaching a signed or 16-bit branch.
- When the same decision exists in more than one place, put the copies side by side and diff the handled set. Places to compare: WH/BH/Quasar copies, legacy tt-llk vs metal llk_api, unary/binary_ng/ternary entry points of one op, single- vs multi-device loaders, dump vs load, routing predicate vs op-config switch vs init selector, a validator whose comment says 'same as X', and experimental/quasar forks. Any value one copy handles and another does not is a finding.
- For wraparound or neighbour arithmetic ((x+1)%n, (x-1+n)%n, Ring/Torus topology), work through n==1 (self-neighbour) and n==2 (forward == backward peer). Check whether results go into a destination-keyed map where one direction overwrites the other. If an entry point demotes Ring to Linear, confirm the validators and program factory downstream accept the demoted value and do not TT_FATAL on the original.
- *Seeds:* `else { defines[...] = "...<DataFormat::Float16_b>"; }` or `: "Float16_b"` / `: "Int32"` as the tail of a dtype chain: ttnn/cpp/ttnn/operations/eltwise/{unary,binary_ng,ternary}/**/*_utils.cpp and the experimental/quasar copies | `else if constexpr (operation == SfpuType::` chains with no trailing `else { static_assert(`: tt_metal/tt-llk/*/common/inc/sfpu and tt_metal/hw/ckernels/*/metal/llk_api/llk_sfpu
- *Clusters in:* ttnn/cpp/ttnn/operations/eltwise (unary/binary_ng/ternary dtype-to-kernel dispatch, composites); tt_metal/hw/ckernels/*/metal/llk_api/llk_sfpu and tt_metal/tt-llk/*/common/inc/sfpu (per-arch op/format ladders, domain edges); ttnn/cpp/ttnn/operations/ccl and experimental/ccl plus tt_metal/fabric (Ring/Torus on extent-2 axes, fallback selection); tt_metal/impl/{allocator,program,dataflow_buffer,sub_device,buffers} (multi-allocator, HYBRID, service-core cases)

### `validation-gap`: Guards checking the wrong thing, or only some paths

A precondition the consumer depends on is either missing, checked against the wrong reference, or checked on only some of the paths into the consumer. The common wrong-reference cases: an aggregate bound where the consumer needs a per-unit one (total buffer size vs per-bank/per-shard size, L1 core count used for DRAM shards), a padded shape where the logical one matters (a tile-padded seq=1 tensor looks like 32 rows), the product of axes instead of each axis, a strict-vs-inclusive off-by-one, or a comparison that reads back the value it is meant to check (compute_output_specs returning the preallocated output's own spec, or a "configured correctly" assert that reads the table holding the bad value). The common coverage cases: a check that lives in one wrapper, one factory, one arch copy, or only the first element (front() of a tensor list, the unicast but not the multicast command path, the constructor but not the offset/update/cache-hit mutator), so other entry points skip it.

- Per-unit vs aggregate: for every capacity check on a per-core, per-bank or per-shard resource (CB size, shard count, scratch region), confirm the bound is the per-unit size of the resource set that actually backs the value (L1 compute cores for L1, DRAM banks for DRAM). Test the 'use every unit' edge case to settle < vs <=.
- Every mutator re-applies the bound: list every constructor, setter, offset setter, update/rebind API and cache-hit override path that changes a base address or size. Each must re-derive the same bound as (unit size - offset). Any unsigned `x -= offset` must be preceded by `offset <= x`, or it wraps and disables the check that follows.
- Self-referential validation: in validate(), if the expected value comes from compute_output_specs, another derived table, or the same config entry, check whether that source short-circuits to the value under test (for example `if (preallocated) return preallocated.spec()`). If it does, the check is a tautology. Recompute the expected value from inputs and attributes only.
- *Seeds:* `compute_output_specs(.*tensor_args)` used inside validate* and compared against `optional_output_tensor`/`preallocated_output`, where compute_output_specs begins with `if (tensor_args.<out>.has_value()) return ...tensor_spec()` (ttnn/cpp/ttnn/operations/**/device/*_device_operation.cpp) | `max_size_ -= ` / `set_address_offset(` followed by `set_globally_allocated_address(`; `buffer.size()` or `aligned_size()` used as a CB bound instead of `aligned_size_per_bank()` (tt_metal/impl/buffers, tt_metal/impl/host_api/tt_metal.cpp)
- *Clusters in:* tt_metal/impl/buffers (Buffer/ShardSpec validation, circular_buffer_config) and tt_metal/impl/allocator; tt_metal/impl/host_api/tt_metal.cpp (legacy APIs: CreateDevice, UpdateDynamicCircularBufferAddress, runtime args); ttnn/cpp/ttnn/operations/data_movement (tilize/untilize/reshard/gather/scatter/bcast sharded fast paths); ttnn/cpp/ttnn/operations/experimental/transformer (rotary_embedding*, nlp_create_qkv_heads*)

### `index-math`: Offset, stride and index-space arithmetic mismatches

An index, offset or size gets computed in the wrong space or unit, and the code still runs. The recurring mistakes: using a count where a start index is needed; using nominal capacity (per_shard - remaining, idx * per_core) instead of a running sum of what earlier partitions took; tiles vs heads vs bytes vs pages; bank index added to a byte offset; request order vs physical slot; logical vs padded vs folded rank; a range or offset relative to (0,0) or the grid width when it should be relative to the range's own start; a bank-relative operand given an absolute base. Chunk and ring arithmetic breaks at the edges: per-chunk size derived from the iteration index when the first chunk can be partial, so the unsigned subtraction wraps; a transfer that is not clamped to what is left in the current unit; a cursor advance missing the count factor; ptr == limit wrap tests with stride > 1; capacity that is not a multiple of the push size; producer and consumer charging different credits on the wrap or resize paths.

- Give every offset, index and size term a space and a unit (bytes/pages/tiles/heads, logical/padded, request order/slot, bank-relative/absolute, range-relative/grid-relative). Flag any +, - or * that mixes two of them, e.g. `limit - ptr / size`, `base + bank_id + offset`, `per_risc0_heads * single_tile_size`, or `count % shard_pages` used as a start id.
- For every work split across cores, links or RISCs, walk the LAST, uneven partition by hand. Its start offset must be a running sum of what earlier partitions actually took, or be derived from its global start index via div/mod, including secondary indices like batch or mask row. It must not be derived from nominal capacity, from count, or from zero. Test with a split that does not divide evenly (3 links, odd tile counts).
- When a core list for runtime args is built separately from the CoreRangeSet the kernels were created on, both must come from the same set in the same order. Flag `bbox.end_coord + 1` passed to an origin-based enumerator (grid_to_cores), coordinate wraps using the grid width or 0 instead of the range's start/end, inclusive CoreRange ends built from a count without `- 1`, and x/y counts bounded by one grid axis but used on the other.
- *Seeds:* `bounding_box()` ... `end_coord.[xy] + 1` ... `grid_to_cores(` -- ttnn program factories (kv_cache, rotary_embedding*, nlp_create_qkv_heads, any sharded path) | `inter_shape = .*logical_shape();` followed by `inter_shape[0] *= 2` or other scaling before padding -- ttnn/cpp/ttnn/operations/ccl/** intermediate sizing
- *Clusters in:* ttnn/cpp/ttnn/operations/ccl (all_gather/reduce_scatter/broadcast/mesh_partition, ccl_common slicers); ttnn/cpp/ttnn/operations program factories with sharded/sub-grid core enumeration (kv_cache, experimental/transformer, reshard, sort, concat); tt_metal/impl/dispatch kernels and tt_metal/impl/buffers (paged writes, prefetch relay credits, distribution spec); circular/dataflow/remote buffer cursor and credit code (tt_metal/hw/inc/api, tt_metal/hw/inc/internal/tt-2xx, ckernels/quasar llk_io)

### `tt-shard-layout`: Shard geometry diverges between host, kernel, and buffer

Host code rebuilds shard-to-core placement or shard geometry from a shortcut, and that shortcut disagrees with how the sharded buffer actually lays data out. Common shortcuts: bounding-box or origin-rooted arithmetic (i % grid_x, bbox.end_coord+1, grid_to_cores), the full allocated grid instead of the data-holding cores, the device grid instead of the tensor's shard grid, the other tensor's orientation, a uniform shard size, or a hand-sized CB. The bug surfaces only on non-default layouts: multi-range or holed grids, grids not anchored at (0,0), COL_MAJOR orientation, uneven or partial last shards (in width and block sharding as well as height), over-provisioned grids, padded vs logical shapes, row-major rows that are not L1-aligned, and DRAM instead of L1.

- Find every place a shard/work index becomes a CoreCoord (runtime args, remote source/dest core, mcast range, override callback). It must index corerange_to_cores(tensor's own grid, that tensor's own orientation). Flag bbox.start + i%W, bbox.end_coord+1 used as a size, grid_to_cores(n, W, H), or {i % num_cores_x, i / num_cores_x}. Test with a holed multi-range grid, an offset grid, and input/output orientations that differ.
- Check that per-core loops, the 'last/partial core' choice, and cache-hit override loops cover exactly the data-holding cores (ceil(extent/shard) per dim), not the allocated grid. Check this for HEIGHT, WIDTH, BLOCK and N-D. A used-core recompute that has only HEIGHT/WIDTH branches leaves BLOCK open. Replace 'core == end_core' remainder logic with per-shard clipping min(chunk, total-offset).
- For partial last shards, the transfer count must use the partial extent, while the L1 row stride uses the FULL (aligned) shard width. Core walks must use >= and not == against the total width. The inverse op (to-sharded vs from-sharded vs reshard) and the host page mapping must apply identical rules.
- *Seeds:* bounding_box\(\)\.end_coord\.[xy] \+ 1 and core = \{i % num_cores_x, i / num_cores_x\} in ttnn/cpp/ttnn/operations/**/*sharded*program_factory*.cpp, kv_cache, transformer factories | grid_to_cores\(num_cores, num_cores_x, num_cores_y in a factory whose all_cores = shard_spec.grid (kv_cache, groupnorm-style factories)
- *Clusters in:* ttnn/cpp/ttnn/operations/data_movement (pad, slice, transpose, sharded i2s/s2i/reshard, move, indexed_fill); ttnn/cpp/ttnn/operations/experimental/quasar/* (stale copies of pre-fix factories); ttnn/cpp/ttnn/operations/kv_cache/device; ttnn/cpp/ttnn/operations/eltwise/unary (row-major sharded CB sizing)

### `build-config`: Build flags, globs, linker scripts silently misconfigure artifacts

The build or link configuration says one thing and the artifact gets another, usually with no error. (1) A preprocessor or feature macro guards correctness code, but the macro is never emitted for that target or caller. It may be missing from the HAL/JIT define list, defined only in a generated textual prolog the firmware TU never sees, set by only one of several program factories, or stale after a rename inside an arch-only block that the default build never compiles.

- For every #ifdef / #if defined() / if constexpr guard around correctness code (hardware enables, barriers/drains, cache flushes, pointer-wrap masks), find where the macro is defined and confirm it is visible in every TU and every caller that needs the code. Check the HAL/JIT define lists per core type (-D flags vs a generated textual prolog), and check each host program factory that builds that kernel. A guard whose macro is never set for a reachable path is dead code.
- Flag every per-core or per-thread resource selector that ends in a silent `#else <default>`. Require an #error or static_assert there, and check that its macros come from -D flags, not from a per-kernel prolog that firmware TUs never include.
- Preprocess or compile every arch/core-only block (Quasar DM, ERISC, 2-ERISC mode) for its real target. After any rename of a template parameter or identifier, grep inside the inactive #if branches for the old name.
- *Seeds:* grep -rn 'GLOB_RECURSE[^)]*/\*\s*)' --include=CMakeLists.txt ttnn/cpp/ttnn/operations tt_metal  (bare trailing-* install globs) | GLOB_RECURSE ... device/kernels/*.cpp in ttnn op CMakeLists, cross-checked with `grep -rn '#include "[^/]*\.hpp"' device/kernels` for local headers not captured
- *Clusters in:* ttnn/cpp/ttnn/operations/**/CMakeLists.txt (FILE_SET kernels globs, especially experimental/ and deepseek_prefill/); tt_metal/hw/toolchain (main.ld, erisc-*.ld linker scripts); tt_metal/hw/inc/internal/*/dev_mem_map.h (fixed firmware regions, pads); tt_metal/hw/firmware and tt_metal/llrt/hal (per-core define lists vs firmware #ifdefs)

### `tt-tile-shape`: Tile geometry and padding assumed, not derived

Code assumes a full 32x32, 4-face tile, or a tile-aligned logical shape, when it should take the geometry from the operand or the tensor. In the LLK and compute-API layers this shows up in several ways. Init or getter overloads fill num_faces, face_r_dim or partial_face with constants.

- For every LLK/compute-API init, short-init, reinit, uninit and execute wrapper, check that num_faces, face_r_dim, tile_r/c_dim, partial_face and narrow_tile come from the operand (CB id or descriptor). Flag literals such as 4 faces, 16-row faces or DEFAULT_TENSOR_SHAPE. Flag parameters that are accepted but not forwarded. Flag sibling wrappers in the same file that disagree on whether they pass operands.
- Build a table: geometry-derived config state -> {hw_configure, reconfig, init, uninit} writers. Flag any register or MOP field that only hw_configure writes. Flag any old-vs-new operand reconfig shortcut whose skip condition compares only the data format and not face_r_dim, num_faces, tile dims or partial/narrow flags. This applies to the unpack AND pack sides.
- Diff each per-arch copy (WH/BH/Quasar) of the metadata accessors, reduce, tilize and matmul LLK wrappers. Any accessor that returns a constant where a sibling arch indexes the generated per-CB array is a stub. Where an operand is routed to the other source register (in0->SrcB), check that init and execute resolve every per-operand attribute through the same swap.
- *Seeds:* tt_metal/tt-llk/*/llk_lib and hw/ckernels/*/metal/llk_api: `outerloop = 4`, `num_faces = 4`, `/*not used*/`, `DEFAULT_TENSOR_SHAPE`, `partial_face = 0` / `const bool partial_face = 0` | hw/ckernels/*/metal/llk_io: `get_(operand|output)_(num_faces|face_r_dim|tile_r_dim|tile_c_dim|partial_face|narrow_tile)\(.*\)\s*\{\s*return [0-9]+;`
- *Clusters in:* tt_metal/tt-llk/tt_llk_blackhole/llk_lib (datacopy/B2D, matmul, reduce, unpack untilize/tilize) and the BH metal llk_api/llk_io layer: the BH copy lags WH in shape handling; tt_metal/hw/ckernels/*/metal/llk_api reconfig paths (llk_unpack_common_api.h, llk_pack_common_api.h); ttnn/cpp/ttnn/operations/normalization (layernorm, layernorm_distributed, groupnorm) and experimental/transformer pre-all-gather norm variants; ttnn/cpp/ttnn/operations/reduction (generic, prod, argmax) and pool2d

### `tt-format-resolution`: Data format resolved from the wrong source

A buffer's data format, Dest width, unpack mode or signedness is taken from the wrong place: another operand, the output tensor, the last configured CB, a shared hardware load/store mode, a JIT global default, or a catch-all bfloat16 branch. The format that is actually in the buffer is not used. The hardware then quietly reinterprets the bits.

- Program factories: for every compute kernel, find where fp32_dest_acc_en comes from. It must be true whenever any CB it touches can be Float32/Int32/UInt32 under the op's validate(). This includes the case where the caller passes no compute config (a default ComputeConfig{} or ComputeConfigDescriptor{}). It also includes the case where only an INPUT is 32-bit, not just the output. The flag must agree with every CB marked UnpackToDestFp32.
- Kernels: for every reconfig_data_format*/pack_reconfig_data_format(old,new) and every *_init(cbA,cbB), trace the actually programmed srcA/srcB/pack format along every path: first iteration, loop back-edge, each #if/FUSE_*/untilize_out variant, and scalar-first operand swaps. Confirm that 'old' is the CB configured last and 'new' is the CB the next unpack/pack really touches. Resolve ternary aliases such as 'untilize_out ? partials : out' before comparing.
- Find every kernel that spills fp32 partials and reloads them into Dest (copy_tile, copy_block_matmul_partials). The factory must mark that CB unpack-to-Dest-fp32 when fp32 Dest is on. Then list EVERY factory that launches the same kernel, including Metal-2 ports, Quasar copies and fused-CCL copies, and confirm each one does. A fix in one factory does not fix its siblings.
- *Seeds:* grep -rnE 'fp32_dest_acc_en\s*=\s*[^;]*(output|src0)[a-z_]*data_format\s*==\s*tt::DataFormat::Float32\s*;' ttnn/cpp/**/device/*factory*.cpp. Keep hits whose kernel unpacks to Dest or transposes, and hits where the same function sets UnpackToDestFp32 from input dtypes. | ComputeConfig\{\}|ComputeConfigDescriptor\{\}|ComputeConfig\{\s*\.compile_args in ttnn/cpp/**/device/*program*.cpp (CCL reductions, tilize/untilize, transpose kernels), where validate() admits FLOAT32.
- *Clusters in:* ttnn/cpp/ttnn/operations/matmul/device/factory and matmul compute kernels (plus *_metal2 and CCL-fused copies); ttnn/cpp/ttnn/operations/eltwise/{binary_ng,ternary,unary} host dispatch and program factories; ttnn/cpp/ttnn/operations/data_movement/{transpose,permute,untilize,concat} factory variants; ttnn/cpp/ttnn/operations/experimental/ccl reduction program factories

### `tt-arch-divergence`: Code ported or shared across WH/BH/Quasar keeps the old arch's assumptions

Code written for one arch, or copied from it (Grayskull to WH, WH to BH, WH/BH to Quasar), keeps that arch's hardware facts as constants, literals or unstated preconditions. The usual ones are DRAM/NoC alignment (32 B on WH, 64 B on BH/Quasar, L1 16 B), PCIe/DRAM endpoint coordinates and which NoC they belong to, register bit-field layouts, resource counts, thread/slot enums, core-type macro sets, and instruction semantics such as a Dest clear's region and bank select, a mode register's reset default, sign-magnitude versus two's-complement compares, errata-affected config writes, and posted versus CPU-blocking waits. The code keeps compiling and passing on the original arch, then silently corrupts data, hangs, faults or fails to build on the new one.

- Sub-page NoC transfers (face rows, sticks, index elements, 16*elem_size, SUBTILE_LINE_BYTES): the source and destination must agree modulo the alignment of the buffer being READ FROM, taken from the HAL for that memory type (DRAM 64 B on BH/Quasar), or the transfer must be staged through an aligned scratch buffer. Flag literal 32/16 'minimum read size' constants and gates computed from the other endpoint's buffer.alignment().
- When a host factory allocates a scratch/staging buffer and the kernel decides to use it, both must evaluate the same expression (same alignment source, same element size or line size). Also check that the op's dtype validation does not admit dtypes the kernel's hard-coded byte geometry (bf16 face or line sizes) cannot handle.
- CB page stride must equal the DRAM page stride (tile size rounded up to the arch's DRAM alignment) on the read AND write sides, for every dtype and tile shape. Build a tile-size x dtype x arch table: bfp8/bfp4 tiny tiles (for example 544 B) are 32 B-aligned but not 64 B-aligned.
- *Seeds:* ttnn/cpp/**/kernels, ttnn/cpp/ttnn/kernel/dataflow: `#define NOC_MINIMUM_READ_SIZE|MINIMUM_READ_SIZE\s*=?\s*\(?32`, and noc_async_read/noc.async_read of `SUBTILE_LINE_BYTES|FACE_WIDTH \* .*element_size|16 \* ELEMENT_SIZE` into a CB offset that advances by the same amount | ttnn program factories: `dst_buffer->alignment()` or output-buffer alignment used to gate a READER-side misalignment/staging path; `alignment > FACE_WIDTH \* .*element_size()` on the host paired with a kernel `constexpr .*MISALIGNED = ALIGNMENT > 32`

### `numeric-formula`: Wrong math in SFPU approximations, host converters and composites

### `data-race`: Unordered publish, reset and reuse across agents

Two agents touch the same word, register, buffer or container, and nothing orders them. The agents can be host threads, RISCs, TRISC threads, cores, devices or processes. On device the same few shapes keep coming back.

- Semaphore reset or RMW vs remote increments: for every counter or semaphore that another core or device increments with a NoC or fabric atomic, find every local plain store (set(0), `*p = 0`, `+=`). - Credit after data: for every handshake, the credit (semaphore inc, CB push, flag write) must be issued after the data is committed. A NoC write needs a write barrier BETWEEN the write and the atomic inc, not after the inc. RISC L1 stores need a same-address load-back before cb_push_back. A host message needs the flag written last in a separately ordered write (fence, strict mapping or barrier). Never rely on one struct write staying atomic once the struct can exceed the transport's write size.

### `ordering`: Signal published before payload is visible

Most bugs in this class have one shape. ### `identity-collision`: Distinct things share one key, id or slot

### `lifetime`: Device addresses and handles that outlive their owners

Most lifetime bugs here are one mistake: something saves a device address, raw pointer, reference or view, and nothing ties it to the owner of the storage. ### `tt-cb-balance`: CB push/pop counts diverge across paths

A circular/dataflow buffer is a single shared FIFO, and it only works if every page reserved/pushed by the one producer is waited/popped exactly once by the one consumer, on every core, for every compile-time variant and runtime shape. ### `copy-paste`: Cloned sibling bodies that kept the wrong token

A function, struct, config block or asm sequence is cloned from a near neighbour. The copy keeps one token from the original that should have changed: the memory-kind table (DRAM offset array indexed by an L1 bank index), the core-flavour macro (active-eth MAP_END in an idle-eth map), the concrete template argument (multicast sub-command inside a body templated on the sub-command type), the forwarded callee (a `_with_fabric` binding that still calls the plain function), the union member written (a field of header A set inside the populate function for header B), a bit immediate (an LUI value copied from the neighbouring CSR routine, so it sets that routine's bit), or a loop variable (a container name one underscore away from the element name). A second shape is drift between N parallel bodies that must all do the same thing: one of four hand-written copy/move members skips a field, the write path of an address generator drops the non-power-of-two divisor and the per-bank offset that the read path has, a series term is duplicated both outside and inside the precise branch, or one physical size is passed through two symbols that are set in different scopes of one switch.

- For every family of sibling functions or specializations (read/write/get_addr, DRAM/L1, unicast/multicast, active/idle eth, TRISC0..3, fused/non-fused), diff the bodies token by token. Every token that names a memory kind, core flavour, table, macro family, template type or union member must match the sibling's own identity. A token that belongs to the neighbour is the bug.
- In templated bodies, every inner call's explicit template argument and every sizeof() must be the template parameter or derived from it. A concrete type name that matches only one instantiation is a finding. Pair each size calculator with the writer it mirrors and check that both use the same element type in every instantiation.
- For classes with user-written copy/move ctors or assignment operators, list the non-static data members and confirm that every one of the four bodies transfers each member. Treat a body that is shorter than its siblings as suspect, and give priority to members whose default is a valid mode (replicate, interleaved, 0).
- *Seeds:* grep -nE 'bank_to_dram_offset\[' in functions whose bank index comes from get_bank_index<false> or l1_* helpers; and '& \(NUM_(DRAM|L1)_BANKS ?- ?1\)' outside an is-power-of-two guard (tt_metal/hw/inc/internal/dataflow/) | get_noc_addr_from_bank_id / get_*_noc_addr pairs: compare which per-kind offset (dram vs l1) each <DRAM>/<false> path adds (dataflow_api_addrgen.h)
- *Clusters in:* tt_metal/hw/inc/internal/dataflow/ (address generators, DRAM vs L1 sibling paths); tt_metal/llrt/hal/ per-arch and per-core-type memory maps (active/idle eth, tensix, Quasar TRISC variants); tt_metal/fabric/hw/inc/api_common.h (union-backed packet header populate helpers, stateful masked APIs); tt_metal/impl/dispatch/ (templated command sizing vs writing, hand-written special members)

- `resource-leak`: Ownership gaps across host, device-buffer and exit lifetimes. Resources leak where the ownership handoff is not atomic with the acquire.
- `precision`: Silent narrowing: TF32 source regs, bf16 intermediates, truncation. Precision is lost when a value passes through a narrower representation than the one the code assumes, and nothing raises an error.
- `tt-host-kernel-args`: Host runtime-arg builders drift from the kernel's arg contract. The host program factory and the device kernel share an implicit contract: word order, word count, what each word means and how it is encoded, and bounds on counts or slot indices.
- `tt-cb-access`: CB window, wrap and release-ordering violations. Kernels touch circular-buffer (CB/DFB/remote-CB) pages outside the window they actually own.
- `error-handling`: Swallowed failures become silent wrong defaults. A probe or getter hits an error or a false negative, and the code reports it as a normal outcome ("not present", nullopt, 0, empty) instead of raising or logging.
- `tt-reconfig-drain`: Config/mode rewrites racing in-flight Tensix consumers. A config register or global mode bit (format fields, Dest width or remap/swizzle, integer-math enable, packer/unpacker base or destination addresses, per-tile offsets) gets rewritten while an engine that reads it (UNPACK, MATH/FPU, SFPU, PACK, or another TRISC) still has work in flight.
- `units`: Bytes, words, tiles and banks silently mixed. A quantity is produced in one unit and consumed in another, and nothing in the type system notices: bytes are passed where the callee counts 32-bit words or 16-byte address units; a per-bank size is checked as if it were a per-device total; an absolute index is used as a relative count; or a value that is already encoded (packed NoC XY, pre-shifted address) gets shifted a second time.
- `uninitialized`: Unwritten bytes, registers and init steps consumed. Something reads memory, a register or a member that its own path never wrote.
- `tt-noc-index`: NoC address resolved in the wrong space. A NoC address or index is built in one coordinate or numbering space and consumed in another.
- `cache-key`: Cache keys that miss inputs or collide. A cache or memo stands in for "this artifact is the same thing".
- `tt-shared-scratch`: Shared L1 scratch, slots and tokens without ownership. A fixed or reused scratch resource has more than one writer, or more than one live lifetime, and nothing enforces which one wins.
- `tt-noc-exit`: Kernels exit with NoC transactions still undrained. A data-movement kernel returns, or publishes a "terminated" status, while NoC transactions it issued are still outstanding.
- `missing-exit`: Missing or wrong early-exit and return paths. Code either lacks an exit it needs or has an exit in the wrong place, and the result is one of three failures.
- `tt-dest-capacity`: Dest tile indices exceed half-sync fp32 capacity. Compute kernels and the host factories that size them assume 8 or more Dest tiles are available.
- `deadlock`: Circular waits across dispatch, fabric, semaphores and hosts. Hangs in tt-metal come from five recurring mechanisms.
- `dead-guard`: Guards that compile but can never fire. A check is present and compiles, but by construction it never changes behaviour.
- `rounding`: Floor/truncate where ceil or round-to-nearest-even is required. The same mistake shows up in three forms.
- `tt-approx-guard`: SFPU approximations missing range, domain and mode guards. Fast SFPU math builds floats from integers with bit tricks: Schraudolph or fixed-point exp shifted into the exponent field, 2^k built with setexp or (k+127)<<23, a quotient converted to int16 for argument reduction, and LUT segments of the form A*|x|+B.
- `tt-noc-fanout`: Multicast destination count and routing mismatches hang. A multicast or fan-out signal is described by several separately maintained numbers: the destination rectangle or hop range, the destination count sent to the hardware or ack counter, the software barrier credit, and the receiver's wait target.
- `tt-noc-data-before-credit`: Credit or semaphore overtakes the data it announces. A producer writes data (a NoC or fabric payload, a posted inline write, a loopback multicast, or plain RISC stores to L1), then publishes a credit: a semaphore inc, a CB push, a slot or free-pages pointer, or a stream-register write.
- `container-misuse`: Host containers: dangling pointers, fill mismatches, ordering assumptions. Host-side C++ code in the dispatch, runtime, device-pool and ttnn op layers breaks an unstated invariant of a standard container.
- `atomicity`: Torn multi-word publishes, fake locks, clear-on-write RMW. One logical state change gets split into several memory operations that another agent can see partway through.
- `tt-l1-poll`: Stale data-cache reads in remotely written L1 polls. On architectures where each RISC has a small non-coherent, write-through L1 data cache (Blackhole ERISC/BRISC/NCRISC/TRISC), `volatile` does not bypass the cache.
- `test-blind-spot`: Tests that pass without checking the thing. In these bugs the test runs green but cannot fail for the regression it is named after.
- `tt-sfpu-const-clobber`: SFPU programmable constants unloaded or clobbered between ops. SFPU compute bodies read persistent programmable constant registers (vConstFloatPrgm0-2 / vConstIntPrgm0-2, i.e.
- `tt-test-arch-split`: Tests hardcode one arch's grid, bank or L1 geometry. Tests and microbenchmarks take one architecture's device geometry and write it in as a literal: the DRAM bank count (12 on WH, 8 on BH), the extent of a shard grid, shard widths computed by dividing by a constant, L1 capacity, or a fixed L1 base address.
- `tt-test-param-drop`: Swept or model parameters never reach the op. A test names a parameter value in its ID, sweep vector or "reproduces model X" docstring, but that value never reaches the code under test.
- `other`: Accidental-correctness, degenerate-shape and unguarded-budget bugs. This class is a mixed bag, and most of its bugs follow one of four patterns.

## Reviewer checks (what human reviewers catch before merge)

These are the checks tt-metal reviewers apply most often. They are distilled from about 420 defects that reviewers caught on the most-reviewed PRs, and about 87% of those led the author to change the code. It is a bounded sample, not all reviews. Groups are ordered by support.

### 1. Validation that actually rejects (about 80 items)
- Op preconditions belong in `validate()` as always-on fatal checks. A debug-only assert compiles out in Release and CI, so check for asserts guarding user input, config, or fixed-capacity lookups. Checks only in a wrapper or factory are bypassed by direct callers. (ttnn device ops, program factories)
- Every layout, dtype, shard strategy, or memory config the validator accepts must have a factory that implements it, and every hardcoded shape, core coordinate, or grid in a factory must have a check that rejects inputs that break it.
- The routing predicate and the validator must admit exactly the same inputs, and they must read the same shape: logical versus padded, input versus output dtype after conversion. Ideally they share one function.
- Guard the degenerate cases: zero stride or divisor, checked before any helper divides (including routing helpers called before validate); rank 0 or rank below k; zero-iteration loops; empty optionals (`.value()` without `has_value()`); empty containers indexed at 0; and non-tile-aligned sizes that a kernel integer-divides.
- Fixed-capacity device arrays and command pages (MAX_RANK buffers, core lists, tile lists) need a host-side bound check with a clear error. Otherwise an overflow silently drops entries or returns index 0.
- A switch or lookup over enum-like input must fail on an unknown value. It must not fall through to a default or permissive branch: a looser tolerance, a default topology, or a valid broadcast type for incompatible shapes.
- Check a preallocated output's spec against the one that selected the program, and return that same tensor.

### 2. Cross-layer contracts: host to kernel, caller to callee (about 70 items)
- When a factory picks paired kernels (reader and compute, or compute and writer) by separate conditions, the conditions must come from one shared predicate. Every host planner or eligibility option must produce a plan the kernel can actually run. (normalization, pool, conv, wavelet)
- Values that both sides derive must come from one host source: batch and page counts, buffer sizes, tile counts, DRAM or L1 location, and physical core coordinates. Do not let the reader, writer, and factory recompute them independently, and never hardcode them in a kernel.
- Check argument binding. Per-operand arrays must be indexed by the operand or CB id in scope, not a literal 0. Operand order matters for non-commutative and broadcast APIs. Pass the right tensor to each per-position define generator. Decode packed float bits by bit reinterpretation, not `static_cast<float>`. Thread a mode or config parameter into every consumer instead of replacing it with a literal.
- After a signature or return-type change, diff every call site: dropped arguments, keyword arguments the callee no longer accepts, callers still expecting the old type. Keep external-integration signatures and output shapes exact.
- When a conversion or metadata step is removed or rebuilt, the recorded dtype, layout, ids, and config fields must still describe the actual data. Carry every field of a rebuilt config object, such as the N-D shard spec and allocation flags. An equality or no-op gate must compare the field that governs allocation, not construction provenance.
- Internal layout conversions must be undone on output, and early-return or fast paths must still honor requested parameters (memory config, pad value).
- Host/device shared structs must be packed, every host-decoded field must be device-written, and arithmetic must not mix bytes with 16-byte words.

### 3. Numerics, integer width and index math (about 50 items)
- Unsigned arithmetic: `rank - k`, `n - 1` loop bounds, a signed index compared with a negated unsigned size, `(a + b - 1) / b` overflow near the type maximum, and 32-bit volume or element counts. Also 64-bit NoC address fields truncated to `uint32_t`.
- Rounding direction: shapes and per-core counts derived by division usually need ceil, because floor gives 0 when the count is below the divisor. A "nearest" op must round, not truncate.
- `& (N-1)` wraparound needs a power-of-two N, an index-to-enum cast needs a dense enum, and staged dst slots must not overlap across iterations.
- Check reference semantics at the edges: floor versus truncating remainder sign, half-open RNG intervals, every branch of a piecewise activation, an empty product equal to 1, `x or default` treating 0 as missing, and top-k tie-breaking.
- Precision: reductions need fp32 dest accumulation and exact math, not the defaults; apply bf16 rounding only when Dest is not fp32; values feeding a hard selection need enough precision by default.
- A host-computed reciprocal must not overflow to inf for tiny inputs, and a zero divisor in size math must fail, not return 0.

### 4. Stale state, caching and lifecycle (about 50 items)
- A program-cache hash or trace key must include every input that shapes the program or the captured branch: the actual core grid behind a sub-device id, host-side booleans baked into a trace, and behavioral flags. Factory selection must not read live allocator state. (device-operation adapters, traced generators)
- A cached command stream or program must patch per-enqueue values (ring offsets, runtime args), and the override-runtime-args callback must actually be returned. Auxiliary device tensors must survive a cache hit (run twice, another op between).
- Ring-buffer allocators: trace allocation sequences across wraparound. Do not treat offset 0 as empty or assume a live block sits at 0, and bound the eviction loop to the needed region. (dispatch caches)
- `Reset()`, uninit, and teardown must clear every member, flags included. Paired register/unregister must act on the set captured at registration. Close must drop only this owner's reference to a shared handle, and scope-exit cleanups must be idempotent on failure paths.
- Mode state held in a global or default that outlives init (sort direction, tracked config equal to the reset DEFAULT) should be an explicit parameter, or an UNCONFIGURED sentinel.
- Reset per-run state between batches or tests: page tables, trace handles, env vars, and both peers of a fabric handshake.
- Lifetime: no `std::forward` of one argument inside a retry loop, no moving from an lvalue-reference parameter, no detached thread touching caller state.

### 5. Device protocol: CB, NoC, semaphores, init (about 45 items)
- CB credits: on every path, each `cb_wait_front` pairs with a `cb_pop_front` of the same count, and each `cb_push_back` or `pack_tile` follows a `cb_reserve_back`. Place them per block, not per tile. Aliased CB ids must not double-count, and a helper's wait/pop policy must not repeat the caller's.
- Access windows: `get_write_ptr` and `get_read_ptr` only inside a reservation or wait. The tile index read must be below the count waited for, and a wait count must not exceed what the producer pushes per step. Wait even on a CB the same kernel produced.
- NoC: barrier async reads and writes before popping or reusing an L1 source slot, and before every early return. A drain must load the last-written location. A multicast rectangle must be exactly filled by the participating cores.
- Polls and barriers: a hand-rolled L1 spin must invalidate the L1 cache each iteration (on Blackhole), or use the library wait. An ethernet spin must yield to routing. Reusable semaphore barriers need monotonic targets, not reset-and-reuse.
- Handshakes: both sides must do the same iteration count, including zero. A barrier token count must equal the real participant count on every arch. A completion signal must stay asserted until it is sampled. A primary core must wait for every subordinate's init before it reports ready.
- Init order: run `hw_configure` before op init, run each op's `*_init` (and its helper's init) after any other op reconfigures the unit, and match the init face count to later calls. Do per-op sync setup in each op's init, not once globally. Dest follows acquire -> compute -> commit -> wait -> pack -> release, and release covers every client (FPU and SFPU).
- Shared resources: no hardware registers as scratch, bound copies from fixed regions (zeros), compare aliasing by L1 address not CB id, one owner risc per channel.

### 6. Tests and goldens that cannot fail (about 40 items)
- A harness must assert the metric it computes. Watch for thresholds loosened far below target, asserts turned into warnings, comparators forced to pass, and a vacuous pass on an empty tensor.
- Use exact comparison for bit-exact or discrete ops (max/min, sign, selection). A per-format tolerance must catch an fp32 to bf16 downgrade. Convert emitted ULP budgets back to relative error to sanity-check them.
- The golden must be independent of device outputs. It must reproduce every conversion the kernel always does (bf16 RNE, NaN packing on format narrowing, per-dtype and per-dest-mode subnormal flush), and it must model the kernel's algorithm, not a similarly named op's.
- Stimuli must stay distinct after casting to the device format. Mutation-check: delete the code under test and confirm the test fails.
- Coverage tests must enumerate subjects from the canonical source across every key dimension. Key xfail markers per probe or lane.

### 7. Sibling drift and copy-paste (about 30 items)
- When fixing one copy, grep for its twins: per-arch forks (WH/BH/Quasar kernels, experimental op trees), sibling call sites of the same refactor, sibling classifiers, and private copies of capability tables. Mirror guards, clamps, and compute-config changes into each one.
- After moving or deduplicating files, check that every path, include, import, and caller was updated. After a rebase, check for resurrected code and duplicate definitions.
- Copy-paste markers: identical if/else bodies, enum cases dispatching a sibling's op, `TILE_HEIGHT` on the width path, literal 0 for a thread id.

### 8. Arch, platform, mesh and build divergence (about 30 items)
- Query hardware counts and limits (DRAM banks, cores, L1 free space, L1 and NoC alignment) from the device or allocator. Never hardcode one arch's value, and size L1 from space above the allocator base, including outputs and halo.
- NoC addresses must go through the arch-aware helper, not a fixed `xy << 32`. A size helper must be correct for every protocol variant (1D versus 2D fabric headers). Per-arch dispatch must cover every supported arch, and a per-arch variant config must fail loudly rather than fall back to defaults.
- A re-implemented LLK sequence must keep every arch-specific workaround step (zero-flag clears, preserve-zero mode around MOVB2D).
- Mesh: keep physical device ids and fabric chip ids apart, iterate only host-local coordinates, and derive ownership from the full mesh shape, not one axis or the dev topology.
- Build: keep compute APIs declared on every TRISC pass (guard inside the body), guard thread-specific calls in shared headers, and build with watcher on.

### Lessons from rejected approaches
- A bulk mechanical accessor sweep is unsafe: each site needs a padded-versus-logical judgement.
- Put conversion logic at the layer every caller passes through, such as the tensor constructor. Instrumentation must hook the level that every path reaches, including internal constructors and command-queue paths, not just the public entry points.
- Acceptance means the shipped tests pass as-is, perf thresholds are at target, and reference data exercises the claimed path. Loosened bounds do not count.
- Features for immature subsystems go in an experimental namespace, not a second competing API.
- Do not bundle perf features into a refactor; L1-heavy modes need full-model L1 validation.
- Keep inference-only mechanisms (KV cache) out of training paths, because cached tensors are detached from autograd. Keep model-specific code out of the framework core.
