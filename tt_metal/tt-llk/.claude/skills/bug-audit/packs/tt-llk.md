## Classes, by weight

### `numeric-edge`: SFPU special values: signed zero, NaN, INT_MIN, poles

SFPU float compares look at the raw bits. They are not IEEE compares: '== 0' means all bits are zero and '< 0' / '>= 0' test only the sign bit. So -0.0 is treated as nonzero and negative, and a NaN is ordered by its sign bit.

- For every float predicate against zero or a scalar in SFPU code (==0, !=0, <0, >=0, >0, <=0) and every helper that wraps one, compare the result for +0, -0, +NaN, -NaN, +inf and -inf with the torch/IEEE truth table. Ordered compares with NaN must be false, != must be true, and ±0 must compare equal. Flag ge/le written as the complement of lt/gt, and any test that looks only at the sign bit or at an all-zero bit pattern.
- In range-classifying kernels (exp, pow, other transcendentals) that pick an overflow, normal or underflow arm from a derived integer or a clamped value, send ±NaN through on each arch. Flag any arm that writes a literal constant without first excluding NaN. A NaN's sign bit steers integer and sign-magnitude compares, clamp and min/max.
- Wherever an integer is ordered by SFPSWAP or a float compare, or is converted from two's-complement to sign-magnitude (the INT32_2S_COMP load mode, or a manual 'sign | -x'), test INT32_MIN (it becomes -0 and ties with 0), pairs of negative values (the order reverses) and UInt32 values at or above 2^31 (they read as negative). Flag host code that computes min as -max(-x), and abs or negation of INT_MIN in any width, including in test helpers.
- For arithmetic-built reciprocal, rsqrt, sqrt or divide (bias minus exponent, setexp/exexp, a magic seed plus NR), evaluate both ends of the exponent range: ±0 and denormals must give ±inf, ±inf must give ±0/inf, and NaN must propagate. Trace each NR step for inf*0, inf-inf and denormal flush-to-zero. Require that non-finite lanes are excluded with a bit-level exponent test or is_finite, not a float compare such as 'val != 0'.
- *Seeds:* grep -nE 'v_(else)?if\s*\(\s*\w+\s*(==|!=|>=|<=|<|>)\s*-?0(\.0*)?[fF]?\s*\)' in ckernel_sfpu_*.h where the operand is a vFloat (metal llk_api/llk_sfpu and tt-llk common/inc/sfpu, all arches) | _sfpu_is_fp16_zero_ call sites: comp.h zero-compare and the generic comparison, mask.h, and anything else that treats -0 as nonzero | v_if(v < s) {0} v_else {1} or 'v - s >= 0' in ckernel_sfpu_unary_comp.h and apply_unary_float_comp: complement-of-strict compares with no NaN filter
- *Clusters in:* tt_metal/hw/ckernels/{wormhole_b0,blackhole,quasar}/metal/llk_api/llk_sfpu/ (comp, unary_comp, binary_comp, exp, sqrt_custom, rsqrt, recip, typecast, reduce, max_min, logical_not, mask); tt_metal/tt-llk/tt_llk_{wormhole_b0,blackhole}/common/inc/sfpu/ (comp.h, is_fp16_zero.h, relu.h: stale tier copies that keep old raw forms); Quasar ports of WH/BH SFPU routines (fixes are often deliberately left out of them); ttnn/cpp/ttnn/operations/eltwise/binary and binary_ng dispatch (scalar-first and mixed-dtype fallback paths)

### `tt-init-uninit`: Init/uninit and reconfig pairs leave stale state

Hardware state persists across ops in a kernel and across programs on a core. Examples: ALU and unpacker format fields, tile-descriptor X/Y/Z dims, strides, x-end counters, packer counters and L1 offsets, sticky mode bits (transpose/haloize, the source zero-substitution flag, pack/tilize mode, the Dest remap), SFPU programmable constants and the SFPCONFIG control word, and the Src dvalid/bank pointers. Bugs arise when no code clearly owns a field, in four ways.

- For every init/uninit pair, per architecture, diff the set of registers and fields each one writes. They must be equal. Each restored value must come from the operand's own metadata (face_r_dim, num_faces, format) or from a snapshot the init took. Flag an uninit that writes a hard-coded 16x16 / 4-face / y=1 value, one that ignores a saved scratch register, one that writes a register its init never touches (an accidental repair hiding another op's leak), and one that takes a geometry parameter with a default value.
- For every short-init or reconfig entry point, list every field the matching full hw_configure derives from each input (format, datum size, face_r_dim, num_faces, tile size). Confirm that every compile-time branch, including the default template path and the non-int8 path, rewrites each of those fields, and writes it to the correct operand's address, mask and shift (for example, SrcB data must not go to the SrcA address). An empty else branch is a finding.
- For every conditional 'reconfigure only if changed' wrapper, the skip decision must be the OR of every property the skipped work consumes. Flag an if/else-if chain where an earlier, narrower branch (for example, on a format change) hides a later branch (for example, a geometry change) when both change together. Flag skip keys that compare only the destination format.
- For each sticky global mode (the src zero-substitution flag, transpose/haloize, tilize/pack mode, Dest remap, SFPCONFIG control, implied-format or Fp32 mode), list the inits that set it to a non-default value. Then confirm that every other init that can follow in the same kernel explicitly re-establishes the value it needs, including *_init_short paths that skip hw_configure and experimental/custom LLKs. Diff each experimental init against its canonical counterpart for missing reset or assert calls.
- *Seeds:* TTI_RDCFG(p_gpr_unpack::SR_UNPACK_* in an *_init_ with no TTI_WRCFG of the same GPR in the paired *_uninit_; also different ops (untilize, fast-tilize, reduce_custom) sharing the same SR_UNPACK_UNTILIZER_STATE_* GPRs (tt_llk_*/llk_lib, including experimental/) | FACE_DIM_16x16, MAX_FACE_R_DIM, or `TileDescriptor_ADDR32 + 1 ...>(<literal>)` inside *_uninit_ bodies; uninit signatures with `face_r_dim = FACE_R_DIM` or `[[maybe_unused]] ... face_r_dim` (llk_lib, metal llk_api wrappers, tests/helpers wrappers) | `if constexpr (` in `_llk_math_reconfig_data_format*` / `_llk_unpack_reconfig_*` with an empty or missing else; `SrcB_MASK`/`SrcB_SHAMT` used with a `SrcA_ADDR32` address
- *Clusters in:* tt_metal/tt-llk/tt_llk_{wormhole_b0,blackhole}/llk_lib/llk_unpack_tilize.h / llk_unpack_untilize.h (init/uninit teardown geometry); tt_metal/hw/ckernels/*/metal/llk_api/llk_unpack_common_api.h and llk_pack_common_api.h (conditional reconfig wrappers); tt_metal/tt-llk/tt_llk_*/llk_lib/experimental/ (custom mm/eltwise/sdpa/moe inits that skip the canonical zero-flag and mode resets); tt_metal/tt-llk/tt_llk_wormhole_b0/llk_lib/llk_math_common.h and the unpack reconfig impls (format reconfig branches)

### `tt-arch-divergence`: Code copied across arches, not re-derived

Code is copied from one arch (usually WH to BH, or WH/BH to Quasar) and keeps the source arch's assumptions, while the target arch differs. The differences seen so far: which config word a field lives in, how thread and mailbox slots are numbered, what an instruction's operand means under a new mode register (for example ZEROACC choosing the Dest bank itself and treating the index as bank-relative), which implicit registers an instruction reads (LUT tables), how much a clear or move covers, which config-write instructions have errata on that arch (REG2FLOP on BH, dummy UNPACR side effects, lo16 Dest<->Src moves while fp32 ALU mode or a Tf32 SrcA format is set), and whether a "blocking" sync primitive really blocks the CPU or only posts a Tensix wait. Other bugs come from a step done in different places on different arches (row transpose in math on one arch, in the unpacker on another), so the init on one arch never programs the required state.

- For every instruction whose operand meaning depends on a mode register or arch semantics (ZEROACC addressing/bank auto-detect, CLR_16 coverage, fp32 flag, Dest<->Src hi/lo16 move width), derive the region it actually touches on THIS arch. Check three things: every caller encodes the index in that mode's units without adding the bank base twice; the maximum of (current Dest row offset + index) cannot cross a bank or half-Dest boundary at the largest tile count; and every kernel entry path programs the mode before the first use.
- Diff each per-arch copy of a function (WH vs BH vs Quasar), and each per-arch llk_api wrapper against the shared compute-API call site. Any argument one arch forwards to _llk_*_init_ and another omits (formats, face counts, dst_format) is a finding. So is any template or function parameter an arch accepts but ignores without a static_assert pinning it to its default. So is a guard or fix present on one arch copy and missing from the other.
- For every hi/lo16 (DEST_32B_LOW) Dest<->Src move, or any move while Dest is 32-bit, check which ALU control bits and SrcA format that arch requires during the move (on BH: Fp32_enabled cleared and SrcA not Tf32). Confirm they are set before the moves and restored after, including in replayed or runtime variants. Confirm the tests feed values whose lo16 half is non-zero, or a zeroing bug stays invisible.
- For each masked config-register RMW that ORs several field masks or computes its address as base+N, look up every field's word address in THIS arch's generated register map. They must all equal the word the call writes, and a compile-time assertion should say so.
- *Seeds:* grep -rn 'TT_ZEROACC(p_zeroacc::CLR_16\|TTI_ZEROACC(' tt_metal/tt-llk/tt_llk_blackhole tt_metal/tt-llk/tt_llk_quasar -- pair each with the preceding TT_SETC16(DEST_TARGET_REG_CFG_MATH_Offset_ADDR32, ...) / get_dest_buffer_base() and compute offset+index against DEST_ROWS_PER_BANK; compare to the crosses_bank/zeroacc_face_by_row fallback in BH llk_math_eltwise_binary.h | TTI_MOVD2B|TTI_MOVB2D with p_mov::DEST_32B_LOW in a function that has no ALU_ACC_CTRL_Fp32_enabled RMW toggle, or that sets ALU_FORMAT_SPEC_REG0_SrcA to Tf32 before the lo16 moves (BH llk_lib, especially experimental/) | cfg_reg_rmw_tensix< whose MASK argument contains '_MASK |', or whose address is '_ADDR32 + N' (all per-arch llk_lib/common/inc)
- *Clusters in:* tt_metal/tt-llk/tt_llk_blackhole/llk_lib/experimental/ (reduce_custom, sdpa_custom_mm, custom_mm unpack: newest code, where arch workarounds are applied least consistently); BH Dest addressing: ZEROACC / MOVD2B / MOVB2D in llk_math_eltwise_binary.h, llk_math_eltwise_unary_datacopy.h, llk_math_transpose_dest.h; tt_metal/tt-llk/tt_llk_quasar/common/inc and tt_metal/hw/ckernels/quasar/metal/{llk_io,llk_api} (enums, mailbox, posted sync primitives, LUT placement); per-arch metal llk_api wrappers under tt_metal/hw/ckernels/{wormhole_b0,blackhole,quasar}/metal/llk_api (signature and argument drift, missing headers)

### `tt-format-resolution`: Format-derived hardware modes resolved wrongly or stale

A hardware mode bit or operand whose correct value depends on the data format and the Dest width (32-bit Dest mode in ZEROACC, packer Dest-read width/int8/unsigned bits, SrcA ALU format for hi/lo16 Dest<->Src moves, the src zero-flag denormal flush, ELWADD vs MOVA2D datapath, the SFPU load/store layout) is left as a literal, derived from only one axis, or set once at configure and never recomputed on reconfig/short-init. Formats get collapsed onto a shared mode or a truncated field, and the code then infers semantics from that collapsed value: UInt32 and Int32 share the INT32 load mode, so signedness is lost; 4-bit masked enums alias (UInt32 vs Int32, UInt8 vs Int8, Fp8 vs Lf8); one family member is special-cased and its sibling is not (UInt8 handled, Int8 not). Workaround writes to shared format registers leak because nothing restores them in uninit, or because a later raw write gets around a software state cache.

- For every instruction operand or config bit that encodes Dest width or row layout (ZEROACC use_32_bit_mode, tiles-per-bank/face-index math, packer Read_32b_data/Read_int8), confirm the value comes from the fp32-Dest template flag or a predicate covering every 32-bit format (Float32/Int32/UInt32). A literal is acceptable only if the function cannot run with 32-bit Dest and has an assert or no fp32 parameter by design. Check that the flag is actually plumbed into the enclosing init.
- For every multi-field config word written by a masked RMW, diff the fields assigned in the value union/struct against the field MASKs passed. A computed field missing from the mask is silently dropped. Also check that the full configure path and the incremental reconfig path program the same field set, and that the adjacent 'fields share one word' static_asserts list every field.
- For any mode bit that depends on format (zero-flag flush, int8 math enable, packer int8/unsigned, Round_10b_mant), check that EVERY format-changing path recomputes it from the NEW format: hw_configure, each reconfig overload, each short init that takes a data type, and mid-kernel fp32-Dest toggles. Where a software cache or state tracker shadows the register, grep all raw writes to that register and require each one to update or invalidate the cache.
- Whenever code branches on a load/store mode, instruction modifier, register width or masked enum to decide a data property (signedness, int vs float, element width), list every DataFormat that maps to that value. If two formats with different semantics collapse onto it, the branch must take the format itself. Test the unsigned formats at bit 31.
- *Seeds:* TT[I]?_ZEROACC\(p_zeroacc::CLR_(16|SPECIFIC|HALF), *0\b in tt_llk_*/llk_lib (especially experimental/*custom_mm.h) and Quasar llk_lib | cfg_reg_rmw_tensix<PCK_DEST_RD_CTRL_Read_32b_data_ADDR32, ..., <mask list>> where the mask lacks a field assigned in dest_rd_ctrl.f.* just above: tt_llk_*/common/inc/cpack_common.h reconfig_packer_data_format | cfg_reg_rmw_tensix<ALU_ACC_CTRL_Zero_Flag_disabled_src_RMW> outside cmath_common.h with no _invalidate_src_zero_flag_state_() nearby: tt_llk_*/llk_lib/experimental/*reduce*custom*.h, *unpack_AB_reduce_custom*.h, common/inc/sfpu/experimental/ckernel_sfpu_topk_xl.h
- *Clusters in:* tt_metal/tt-llk/tt_llk_{wormhole_b0,blackhole}/common/inc/cpack_common.h (packer Dest-read control, configure vs reconfig); tt_metal/tt-llk/tt_llk_*/llk_lib/experimental/ (custom matmul/reduce kernels with hardcoded Dest-width literals and raw zero-flag writes); tt_metal/hw/ckernels/{blackhole,wormhole_b0}/metal/llk_api/llk_sfpu/ (integer SFPU reduce/comp/shift, where signedness is inferred from the load mode); tt_metal/tt-llk/tt_llk_*/llk_lib/llk_math_eltwise_unary_datacopy.h and llk_unpack_A.h (A2D datapath predicate, unpack-to-dest vs Src transforms, ZEROACC flags)

### `numeric-formula`: SFPU approximations drift from their math and each other

The SFPU transcendental and activation kernels are hand-built approximations: range reduction, polynomial or rational fits, lookup tables, and Newton iterations. They break in a few ways that keep coming back. (1) The formula is wrong at the points that matter: cancellation where two terms nearly cancel (k*ln2 + poly(m) just below 1, 1+erf or 1-tanh^2 when the function saturates, v - q*s once the fp32 ULP is larger than the modulus), a fit used outside its fitted interval, a half-range helper given the signed x instead of |x|, or a region boundary or saturation constant that was derived for bf16 but is also used with fp32 Dest.

- Find every SFPU helper that reads programmable constant registers (reciprocal, log, exp, sqrt). Check that each consumer's *_init calls the helper's own init, with the same approx/fp32 template args the compute path uses. Check that no init writes literal vConstFloatPrgm*/vConstIntPrgm* values the helper owns, or writes them AFTER the helper's init (a clobber). Do this for EACH arch, because the register set a helper uses differs between arches.
- Recompute every hard-coded coefficient and math constant from its own comment or derivation and from the true float32 value. Flag values rounded to fp16 or bf16 (ln2 = 0.692871) in paths that produce fp32 results. Then grep for every other copy of the literal: no-init bodies, binary/fused ops, other arches.
- Evaluate each approximation at its cancellation and anchor points, not just on random [-1,1] inputs. Check log near 1, 1 +/- f(x) where f saturates to +/-1, value and slope at 0, tails and asymptotes, and modulo at magnitudes where the fp32 ULP is larger than the divisor. Where fp32 Dest is supported, require an exhaustive bf16 ULP sweep plus fp32 samples.
- For kernels templated on is_fp32_dest_acc_en, check that saturation thresholds and 'result = const' regions were derived for the precision actually in use. A kernel that uses the flag only to skip the final bf16 rounding, while keeping bf16-derived boundaries, is a finding.
- *Seeds:* grep -rn 'vConstFloatPrgm[012] *= ' tt_metal/hw/ckernels/*/metal/llk_api/llk_sfpu/ — in any *_init that also uses sfpu_reciprocal_iter/_sfpu_reciprocal_, or that calls a helper init earlier in the same body | grep -rnE '0\.692871|0\.7166' tt_metal/tt-llk/tt_llk_*/common/inc/sfpu/ tt_metal/hw/ckernels/ — fp16-rounded ln2 and mis-derived log coefficients | grep -rn 'setexp(.*127)\|exexp(' next to '* .*[Ll]n2 +' in log/pow/xlogy/lgamma/digamma bodies — the old [1,2) reduction that cancels just below 1
- *Clusters in:* tt_metal/hw/ckernels/{wormhole_b0,blackhole,quasar}/metal/llk_api/llk_sfpu/ (log, binary pow/xlogy, lgamma, digamma, gelu, fmod/remainder, dropout, tanh); tt_metal/tt-llk/tt_llk_{wormhole_b0,blackhole}/common/inc/sfpu/ckernel_sfpu_log.h and ckernel_sfpu_recip.h (shared helpers other kernels copy); tt_metal/hw/ckernels/blackhole/metal/llk_api/experimental/llk_sfpu/ (fused silu/sigmoid variants with no init of their own); ttnn/cpp/ttnn/operations/eltwise/unary_backward/ and experimental/dropout (composite formulas and per-core seeding)

### `contract-mismatch`: Two sides of one fact disagree silently

One fact gets encoded in two or more places, and they drift apart. The pairs involved are a producer and a consumer, a host and a device, a wrapper and its LLK, or a hand-written table and the hardware or ISA definition. The recurring mechanisms:
(a) An immediate-form instruction macro (an asm constant constraint) gets a runtime argument.

- For every TTI_* (immediate-encoded) macro, check that each operand is a literal, constexpr or template parameter at the macro site, not a function parameter or local. The only exception is a force-inlined helper whose every caller passes constants. The runtime form is TT_*. For TT_* with runtime operands, check the value cannot overflow its bitfield, because encoders do not mask.
- Decode every numeric modifier literal (instr_mod, format-select code, enum value) bit by bit against the ISA definition for the mode it selects. Flag bits that are set but only defined for other modes, literals that differ from the named constant used for the same conversion elsewhere, enums that cover only part of the spec's codes, and signed and unsigned formats that map to the same code. This includes backdoor LOADMACRO setup, where comments often repeat the same misreading.
- For every hand-written bit-field struct or union overlaying config words, compare each field's offset and width with the generated SHAMT/MASK defines, per arch and per bank the word is written to or read from. One struct reused for a bank with a different layout is a bug on both write and readback.
- For each unpack+math pairing in a compute API, derive which source register the unpack stage fills and which data-valid it posts for EVERY template enum value, including NONE/pass-through. Confirm math reads that register and waits on that valid. Sibling functions (init, exec, reconfig) and every arch branch, Quasar included, must use the same mapping.
- *Seeds:* TTI_[A-Z0-9_]+\( whose args name a non-constexpr function parameter (idx, addr, addrmod, dest, upper16, lower16, row_addr, alpha, x_end). Applies to tt_llk_*/common/inc/*.h, sfpu/*load_config*.h and quasar cmath_common.h. | SFP_STOCH_RND\([^;]*, *(8|9|1[0-5])\)|SFP_STOCH_RND\([^;]*\(1 *<< *3\). Applies to hw/ckernels/*/metal/llk_api/llk_sfpu/*exp*.h, *typecast*.h and quasar sfpu typecast kernels. | llk_math_eltwise_unary_datacopy(_init)?<DataCopyType::B2D paired with llk_unpack_A<bcast_type> where bcast_type may be NONE, especially in ARCH_QUASAR #else branches of hw/inc/api/compute/*.h.
- *Clusters in:* tt_metal/hw/inc/api/compute/ (unpack/math pairing, especially ARCH_QUASAR branches of bcast.h and tilize.h); tt_metal/hw/ckernels/*/metal/llk_api/ (wrapper-to-LLK forwarding, sanitizer args, SFPU scalar handling, exp LOADMACRO setup); tt_metal/tt-llk/tt_llk_*/common/inc/sfpu/ (modifier literals, TTI_ with runtime args, bit-pattern vs float scalars); tt_metal/tt-llk/tt_llk_*/common/inc/cpack_common.h / cunpack_common.h (hand-written register overlays)

### `stale-state`: Persistent hardware state inherited across ops and kernels

Tensix state that nothing resets between ops or kernels is written by one op and then consumed by a later op that assumed a default. This state includes cfg register fields, mode and debug bits, GPRs, packer and unpacker counters, the unpacker config-context selector, SFPU constant LREGs, replay-buffer contents, hardware semaphores and Dest contents. Four mechanisms keep recurring.

- Configure/reconfig write-set diff: for every hw_configure and reconfig pair (pack, unpack, math), list each cfg field, GPR and cached value that configure writes, with the input it comes from (src/dst format, num_faces, face_r_dim, tile size, tile_c_dim, partial_face, relu, l1_acc). Check that reconfig rewrites each one from the new operand's full descriptor, or that a named init owns it and every path runs that init. A field that configure writes and reconfig leaves unwritten, and that something consumes, is a finding.
- Skip-if-unchanged guards: every 'old vs new operand' wrapper, and every cache comparison of the form flag != key, must compare ALL inputs that feed the state it skips. That means src and dst format plus geometry, and for replay caches every runtime value the recorded body captures. A guard that compares only pack_dst_format is the usual failure.

### `arg-binding`: Defaulted or hard-coded args bind the wrong operand

Most bugs in this class come from a defaulted parameter that quietly supplies the wrong value. A CB/operand id defaults to 0 or 16, a build-mode flag (fp32 dest accumulation) defaults to false, a thread id defaults to the math thread, a rounding mode defaults to stochastic, or an activation parameter defaults to 0. When a caller leaves the argument out, or a port from another arch leaves it out because it was implicit there, the code still compiles, and the unpacker, packer, math or SFPU resolves format, geometry, mode or register slot from the wrong source.

- For every LLK, llk_api or compute-API parameter that names a CB, operand, output or DFB (operand, icb, ocb, cbid, input_operand, pack_output), flag it if it has a literal default (0, 16, c_0, c_16). Then check two things: whether the body indexes per-CB tables with it (formats, face/tile dims, get_operand_id, unpack_src_format[]), and whether any caller omits it. Include uninit, restore and cleanup functions, experimental/ and 2_0 layers, and newly added wrappers.
- For every parameter that encodes a global build mode (fp32 dest accumulation, sync mode, approx mode, unpack-to-dest), check that the default is the build macro (DST_ACCUM_MODE etc.) or that there is no default at all, never a literal false or 0. Flag any arch or experimental copy that keeps a default its sibling arch removed.
- When a register bank that is per-thread on one arch is a shared, thread-indexed region on another, check every setter that takes the thread or core index. The default must come from the calling thread's compile-time identity, and a missing identity must fail the build. Watch for sentinel defaults that mean 'all threads' and loop over fewer threads than exist.
- Diff argument lists across sibling call sites of the same helper: bias vs no-bias epilogues, sharded vs interleaved, per-arch copies, init vs execute. ### `tt-reconfig-drain`: Config rewritten under in-flight Tensix consumers

A config register or global mode bit (unpacker or packer base address, tilize or format fields, Dest width, remap or swizzle, INT8 math enable, source-bank contents) gets rewritten while a Tensix unit that reads it is still queued or running. That unit might be a MOP or replay from this call or the previous one, the other half of a two-pass MOP, or math or pack on another thread. The usual mechanism is a drain primitive that does not order the write path actually used.

- For every RISC MMIO store to a Tensix config register (`cfg[X] =`, `regfile[...] =`), list the Tensix instructions or MOP/replay slots that read X. Check that (a) any UNPACK_SYNC semaphore_post or context release comes AFTER the stores, (b) a STALLWAIT(..., TRISC_CFG) whose stall mask covers the consumer's class (UNPACK for UNPACR, CFG for WRCFG or replayed cfg ops) sits between the last store and the first consumer, and (c) for WAR, something RISC-blocking (wait_for_next_context on a double-buffered context, wait_for_idle, tensix_sync) keeps the store from landing while earlier queued consumers still use the old value. A Tensix STALLWAIT placed before the store orders nothing.
- Check each ordering both within one call (between two MOP runs, or mid-loop before a SETC16 context-offset switch) and across successive calls of the same function. The previous call's trailing MOP is the usual unguarded consumer, especially on paths that force context 0 via reset_config_context and never call wait_for_next_context.
- For every in-stream config write (WRCFG, REG2FLOP, cfg_reg_rmw_tensix, SETC16), check two separate fences. One is the GPR-producer fence (STALLWAIT on THCON after SETDMAREG/ADDDMAREG). - For every write to a global mode bit that changes how another engine reads a shared resource (Dest remap/swizzle, 32-bit Dest mode, debug-feature bits, INT8 math enable, formats), confirm every engine that could be in flight has drained, not only the writer's own thread (both math AND pack). ### `precision`: Silent narrowing, truncation and cancellation in LLK math

Values that should stay at fp32 get narrowed without anyone noticing, in four recurring ways. (1) Round-trips through narrow registers: an fp32 value in Dest is moved through SrcA/SrcB (19-bit, TF32) for a transpose, broadcast or second pooling stage. The same happens when an FPU op (bcast multiply, eltwise add, reduce) reads fp32 CB data through a source register ahead of a step that is sensitive to cancellation.

- Trace every accumulated Dest value that goes through SrcA/SrcB (MOVD2B/TRNSPSRCB/MOVB2A/MOVB2D) in a function templated on is_fp32_dest_acc_en. If 32-bit Dest is allowed, the path must split hi/lo (DEST_32B_LOW-style moves) or avoid the round-trip. A flag that is accepted but never read on that branch is a finding. Check every stage of a multi-stage reduce (scalar = row then column, or MAX vs SUM branches), because fixes often cover only one stage.
- For every SFPU kernel that writes a computed float to dst_reg: does it know the Dest width (an is_fp32_dest_acc_en template or equivalent)? On the 16-bit path, does it round to nearest-even explicitly (convert<vFloat16b>(.., RoundMode::Nearest), float32_to_bf16_rne, or a stochastic-round FP32->FP16B step) before the store? Compare every BinaryOp/branch in the same function: if DIV rounds and MUL does not, or mul rounds but XLOGY does not, you have a candidate.
- Diff the WH, BH and Quasar copies of the same SFPU op and LLK math file for a rounding step, an fp32 branch, a Newton-iteration count or a 32-bit move flag that one arch has and another lacks. Arch divergence is the most common form an unfixed sibling takes.
- Flag SFPU intermediates written to dst_reg and read back within one computation (log body, reciprocal spilled to Dest). On a 16-bit Dest each round trip truncates, so the result can be wrong even when the final store rounds.
- *Seeds:* tt_llk_*/llk_lib/llk_math_reduce.h and experimental/*reduce*: `TTI_MOVD2B(0, ...)` followed by `TTI_TRNSPSRCB` / `TTI_MOVB2A` with no `p_mov::DEST_32B_LOW` counterpart, inside a template taking is_fp32_dest_acc_en | grep -n 'is_fp32_dest_acc_en' in LLK math files, then check each template that declares it but never reads it on some `if constexpr` branch (REDUCE_SCALAR, MAX vs SUM) | hw/ckernels/*/metal/llk_api/llk_sfpu/*.h: `sfpi::dst_reg\[.*\] = result;` in functions whose template lacks is_fp32_dest_acc_en, or that have it but no `float32_to_bf16_rne` / `convert<sfpi::vFloat16b>(..., RoundMode::Nearest)` on the !fp32 branch

### `ordering`: Handoff published before the effect completes

Most bugs in this class are a signal that becomes visible before the work it announces has finished. (1) Cross-thread release: a thread queues Tensix-side work (config-unit RMWs, WRCFG, MOPs) or makes an MMIO store to one unit (the semaphore/sync block), then releases a peer with a RISC store to a different target (mailbox, L1 flag). A STALLWAIT only gates later Tensix instructions and never holds a RISC store.

- For every cross-thread release (mailbox_write, L1 flag store, semaphore post), find the effect it announces and the primitive that guarantees that effect is complete, not just issued. Accept only a RISC-blocking drain (tensix_sync/mop_sync), a read-back of the same address whose value is then used, or a fence that covers that target. Reject a STALLWAIT, a NOP count, or source-line order on its own.
- For every STALLWAIT, check that its wait condition matches the real producer (RISC-MMIO cfg writes vs config-unit instructions, own thread vs another thread) and that its block mask covers the consumer's instruction class. A consumer that waits on its own thread's RISC-MMIO condition cannot see another thread's queued RMWs.
- In any protocol that pairs a counting semaphore with a separate wake-up, check that the consumer can never decrement or SEMGET while the value is still zero. Saturating or flooring decrements drop silently and turn a race into a hang in the producer's wait_on_zero or wait_on_max.
- For every hand-written barrier or blocking-read idiom, check three things. A later instruction must consume the loaded register, and its destination must not be x0 or an unused volatile local. The asm that performs the access must carry its own "memory" clobber, not rely on a separate trailing asm. Every copy of the idiom across the WH, BH and Quasar trees and the firmware headers must have been upgraded.
- *Seeds:* cfg_reg_rmw_tensix<...>(...); ... ### `data-race`: Cross-thread config, source-bank and shared-state races

Three TRISC threads (unpack, math, pack), and on Quasar several cores running the same image, share config words, source and Dest banks, per-core registers and memory. The code usually assumes an ordering that nothing enforces. (1) Ownership mismatch: a config field that one thread's engine reads is written from a different thread.

- For every config field or register write, work out which engine reads it and which thread drives that engine, then list every writer (masked RMW, WRCFG, REG2FLOP, SETC16, direct MMIO stores). A write from a non-consumer thread is a race unless an explicit handshake or drain orders it before every consumer. Include consumers that do not wait on the writer's data: SFPU-only ops, constant fills, ZEROACC, pack-only flows.
- Flag writes to a field whose owning thread keeps a software shadow or 'already configured' cache (zero-flag state, format-config-set). A write from elsewhere makes the cache wrong, so the owner's later configure call returns early and leaves the hardware stale.
- For every Dest->SrcA/SrcB move, and every other instruction that WRITES a source bank without an ownership gate, check the STALLWAIT in front of it. It must include the bank-valid condition AND the MATH-idle condition if an earlier instruction on this thread can still flip or release that bank (CLR_AB, CLEARDVALID, SETRWC clear). It must also include WAIT_SFPU if the SFPU may have just written the Dest rows being moved or accumulated.
- Check that a dummy or NOP unpack that sets data-valid or zeroes a source gates on its OWN bank and is ordered after every earlier UNPACR on that thread. Removing a stall before it lets valid be published before the data exists.

### `tt-tile-shape`: Non-32x32 tile geometry dropped, stubbed or hardcoded

A large share of the LLK stack was written for a full 32x32 tile (4 faces of 16x16), and support for tiny, narrow or partial-face tiles was added later, one arch and one layer at a time. Bugs of this class share three mechanisms. (1) Loop counts, MOP outer/inner counts, face offsets and strides come from num_faces, face_r_dim or narrow_tile through expressions such as num_faces/2, a literal 2/32/64, TILE_C_DIM or a face_r_dim-1 loop.

- For every loop count, MOP outerloop/innerloop, replay length or address stride derived from num_faces, face_r_dim, narrow_tile or tile dims, evaluate it over num_faces {1,2,4} x narrow_tile {0,1} x face_r_dim {1,2,4,8,16}. ### `integer-width`: Fixed-width counters, fields and integer ranges silently overflow

A value outgrows the bit width it is actually stored, encoded or computed at, and nothing catches it. Four shapes keep coming back. (1) Free-running producer/consumer counters are really 16-bit, but one copy of the credit math widens them to 32 bits, so after a wrap the free-space result is off by 2^16.

- For every pair of free-running counters (tiles_received/acked, pages pushed/popped, semaphores), find the width each side is really stored and updated at. The final difference must be truncated or compared at that width. Diff every copy of the calculation across arches and across dataflow vs compute. Capacity must be capped below 2^width on EVERY path that sets it, including device-side reconfiguration, not only in the host validator.
- For every TT_/TTI_ macro call with literal or constexpr operands, look up each field's width for THAT arch and confirm the value fits. Watch for a value whose meaning comes from another arch (a 2-bit mode used where this arch has a 1-bit flag, or address-mode indices above 3). Also compare the is_valid(field, N) widths in ckernel_ops.h with the per-arch encoding: a validator wider than the field hides the bug.
- Where a hardware address is base + counter*stride, or a stride is shifted into a config field, find the largest value any legal shape can produce: rows*stride*datum_size, with FP32 doubling it. Compare it with the field width and any carry window. Require a range assert or a rebase when it can overflow.
- Wherever integer math goes through float (cast to fp32, op, cast back), or a float is narrowed to int16/int32/uint16 as a floor/trunc step, bound the largest intermediate for extreme inputs (0xFFFF*0xFFFF, tiny divisors, big dividends). ### `build-config`: Duplicated constants, headers and paths drifting apart

### `missing-case`: Unhandled dtype, domain or mode branches

A dispatch over formats, dtypes, modes or template slots handles the cases the author had in mind. Every other case falls into a default branch whose meaning is wrong for it, and nothing fails at compile time or at run time. The recurring shapes:

### `index-math`: Dest/L1/ring index base and scaling errors

Index and address expressions get their base or their units wrong. (1) Bank base: an instruction either applies the current Dest bank or offset itself (auto-detect, per-thread offset register, hardware-tracked section) or expects an absolute index. Code passes a value that already includes the bank base to a relative instruction, or omits the base for an absolute one, and the mismatch changes with sync scheme (semaphore vs dvalid, SyncHalf vs SyncFull) and with arch.

- For every instruction that takes a Dest index, tile, face or block index (pack/unpack source index, ZEROACC, MOVB2D, SETC16 dest offset), write down per arch what base the hardware adds: absolute, per-thread offset register, auto-detected sync bank, or the current RWC row. Then check that the operand at each call site matches that base under every sync scheme (semaphore/dvalid) and buffering mode (SyncHalf/SyncFull). If the operand includes get_dest_buffer_base() and feeds a bank-relative instruction, that is a bug. So is a bank-relative operand feeding an absolute instruction.
- When hardware adds a row offset to a block or face index for bank selection, compute the maximum of (dest row offset + index) over all valid dst_index, face and fp32/16-bit combinations. The worst case is the last face of the last tile of a full bank. Flag any case where the sum can reach the rows per bank, especially when both the dest pointer and the index advance per face.
- Treat a bug that alternates between even and odd iterations or sections under half-sync Dest as a double-counted or missing bank base until proven otherwise. Look for sibling paths (strided, tiny-tile, sparse face, unpack-to-dest) that set the same index without the same bank correction.
- In blocked kernels where block_dim < full_dim, check three things. The L1 row stride must come from the FULL width. The per-block start must include block_index*block_dim. The block index must reach the address math at every tier (compute API -> llk_api -> LLK). A block-index parameter that defaults to 0 is a red flag on any multi-block path.
- *Seeds:* TT_ZEROACC\(.*CLR_16 operands derived from a variable that includes get_dest_buffer_base() or from dst_index when SETC16 DEST_TARGET_REG_CFG_MATH_Offset was also set from dst_index (tt_llk_blackhole llk_lib + experimental) | TT_ZEROACC\(.*CLR_16.*(face|dst_face|face_index) inside a loop where the dest offset or RWC also advances per face (eltwise_binary dest-reuse, rmsnorm, datacopy, topk) | TT_SET_SRC_TILE_FACE_ROW_IDX\(.*PACK0 whose index does not involve dest_register_offset / dest bank offset (tt_llk_quasar pack untilize, strided and sparse branches)

### `stale-sibling`: Fix lands in one copy; twins stay stale

tt-llk keeps many near-identical copies of the same logic: one per arch (WH, BH, Quasar), experimental and TTNN-private forks, the metal llk_api tier next to the vendored tt-llk tier, and sibling golden generators in the Python tests. A correctness fix, a new template parameter (most often the Dest accumulation mode), or a stronger guard (for example adding the FPU-pipeline drain to a source-bank wait) goes into one copy, and the twins keep the old behaviour. A second form of the same problem is a contract that drifts: a helper's init or signature changes (new init function, different programmable constants, a module renamed in a package split) while callers still use the old one.

- Diff the template parameter lists and guard conditions of every per-arch copy of a kernel or helper (WH/BH/Quasar, and experimental/ forks). If a parameter exists in one copy but not another (especially is_fp32_dest_acc_en / Dest mode), or one copy has a stronger STALLWAIT condition than another, treat it as a lead until the missing copy is shown to be unreachable or unnecessary on that arch.
- For every instruction that writes a double-buffered source register from somewhere other than the unpacker (MOVD2A/MOVD2B), find the guard on the target bank's valid bit. If a bank-flipping or clearing FPU instruction (CLR_A/CLR_B/CLR_AB on SETRWC/ELW*/MVMUL/pool, or a MOP end_op) could still be in flight when the guard runs, including from the previous call, the guard must also carry the MATH drain. - For every SFPU kernel that narrows explicitly (FP32_TO_FP16B stochastic/RNE round, float_to_fp16b, a 16-bit store mode), confirm the Dest mode is a template parameter and the narrowing sits under `if constexpr (!is_fp32_dest_acc_en)`. - For composite SFPU ops whose body calls another helper (reciprocal, exp, log, sqrt), confirm the op's init calls that helper's CURRENT init with the same variant/iteration choice the body uses, and that the vConstFloatPrgm/vConstIntPrgm registers the two inits write do not collide. - *Seeds:* grep -rnE 'STALLWAIT\([^)]*(SRCA_VLD|SRCB_VLD)' tt_metal/tt-llk tt_metal/hw/ckernels | grep -v 'MATH *|' and keep hits whose next instructions are MOVD2A/MOVD2B (cmath_common.h, llk_lib/experimental dest-reuse, reduce/transpose_dest) | TTI_MOVD2[AB] with no preceding STALLWAIT within a few lines (reduce_runtime_custom, sdpa/moe dest-reuse experimental files) | grep -nE 'SFPSTOCHRND_MOD1_FP32_TO_FP16B|float_to_fp16b|convert<sfpi::vFloat16b>' in common/inc/sfpu and metal/llk_api/llk_sfpu; check each hit is inside `if constexpr (!is_fp32_dest_acc_en)`

### `tt-approx-guard`: SFPU numeric guards lost across modes, ranges, arches

SFPU transcendental kernels are piecewise approximations. Each one quietly depends on guards: the input is inside the math domain, the range-reduction quotient fits the integer conversion, the reconstructed biased exponent stays in 1..254, and NaN/inf/-0 take the right branch. Bugs show up in four ways.

- For every kernel that builds 2^k by integer bit construction (setexp with a computed exponent, (k+127)<<23, i<<23, adding to the exponent), work out the input range where the biased exponent leaves 1..254. Confirm a guard covers both ends with the correct inclusive/exclusive boundary (inf on overflow, 0 on underflow, NaN still propagated), or that every caller provably bounds the input. Test boundary values such as +/-88.03, -88.72 and 88.72 on each arch and each Dest precision.
- For every variant named _unsafe_, or any unguarded fast helper, list its callers and confirm each one clamps into the documented safe range BEFORE the call. Also confirm that no new caller has joined without a clamp.
- When a kernel exists in several arch copies (WH/BH/Quasar metal llk_api and the tt-llk common/inc/sfpu tree), diff the guard structure: v_if bounds, special-value branches, template 'unsafe' flags. A guard present in the source arch but missing in the port is a finding.
- For every range reduction (trig by pi or pi/2, exp by ln2, pow by integer part), find the instruction that produces the quotient k and its saturation range (SMag16/int16 caps at 32767). Compare that with the input range the op accepts. Also check that x - k*C splits C into hi/lo parts (Cody-Waite) and does not use a single constant.
- *Seeds:* setexp\(.*(k|i|exp|int_part) and as<sfpi::vFloat>\(\(?[a-z_]+ *\+ *127\)? *<< *23\) or (i << 23) with no v_if on the exponent. ### `rounding`: Floored counts and non-RNE narrowing in LLK

Two mechanisms recur. (1) Integer-granularity rounding: an instruction, loop or replay count comes from right-shifting or dividing a row or datum count by a per-instruction granularity (8 rows per ELW or MOV, rows per face). It floors where it should round up, so tiny tiles and faces (face_r_dim 1/2/4, or fewer than 8 total rows) get a count of 0.

- For every count derived as `size >> log2(G)` or `size / G` (rows per instruction, rows per face, datums per word), enumerate the smallest shapes the validator or LLK_ASSERT admits (face_r_dim 1/2/4/8, num_faces 1/2/4, and 4-row math variants). Confirm the result is never 0 while work remains. Floor where ceil was intended is the bug; the fix is `(size + G - 1) >> log2(G)` or an assert that pins the shape.

- Compare sibling overloads of the same helper (template vs runtime, e.g. load_replay_buf) for guards that one has and the other lacks. A zero-length or zero-count guard present only on the compile-time version is a latent hole.
- For every path that narrows an fp32 value to bf16/fp16 on store (SFPSTORE, FPU output, dst_reg write under `!is_fp32_dest_acc_en`), determine the rounding actually applied. Check that RNE is applied consistently across all sibling BinaryOps and across WH/BH/Quasar, and that it matches what the compute-API documentation promises.
- *Seeds:* `>> rows_log2(` or `/ ELTWISE_MATH_ROWS` / `>> 3` applied to face_r_dim, rows_per_mop_run, total rows or num_rows_inner_loop without a `+ N - 1` round-up, in tt_llk_quasar/llk_lib/llk_math_*.h (also check the WH/BH llk_lib math/pack MOP configs) | `len - 1`, `REPLAY_BUF_LEN - 1`, `set_inner_loop_len(X - 1)`, `(face_r_dim >> 1) - 1` on std::uint32_t, in llk_lib MOP/replay setup code | `ckernel_template temp(OUTER, INNER, ...)` where OUTER or INNER comes from a shift of a shape field. ### `platform-divergence`: Per-arch assumptions leaking across boot, link and errata paths

Code that is right on one arch or boot path is silently wrong on another, because an invariant holds only under one platform's conditions. There are three recurring forms. (1) Address identity: a link-time address differs from where the object really lives at run time, for example data placed in a code section that one arch relocates into instruction RAM.

### `loop-bounds`: Shape-derived MOP/SFPU loop counts reaching zero

Hardware loop counts (MOP outer/inner loop, replay length, SFPU ITERATIONS) are computed with arithmetic on tile geometry, such as `face_r_dim - 1`, `num_faces - 1`, `num_faces >> 1` or `block_ct_dim / 2`. - For every value passed to ckernel_template(outer, inner, ...), load_replay_buf/replay_insn length, or ckernel_unpack_template, evaluate the expression at every value the function's own LLK_ASSERT/static_assert/doc accepts, not just the default. ### `other`: Stale state, dead guards and incomplete keys

This bucket holds mixed defects that share one habit: code assumes some state or invariant that nothing enforces. (1) A parameter or piece of state is silently dropped.
