## `resource-leak`: Ownership gaps across host, device-buffer and exit lifetimes

Resources leak where the ownership handoff is not atomic with the acquire. An object gets registered in a global table or slot, a fallible call runs, and only afterwards does a setter or flag transfer ownership, so a throw or an empty result leaves an orphan that blocks every later acquire. Teardown is often tied to an object whose destructor never runs (never-destroyed singletons that own driver handles, threads or files), or to an attach/detach or clear/re-open path that overwrites a handle member without closing the old one. Bulk "free everything" routines on allocators free only one layer of bookkeeping (bank free lists) and leave higher layers (handle sets, per-object status) marking the memory as live, so a stale owner later frees a newer allocation at the same address. In Python and tests, footprint grows with the iteration count (device tensors appended to lists for the whole test, framework model objects and dequantized fp32 copies kept alive during weight load), and monkey-patched attributes on native-bound classes form type->function->globals->type cycles that survive to the binding library's exit leak check.

**Checks**

- Acquire-then-handoff: wherever something is created into a global, registry or slot table and ownership is recorded later (set_*_on_close, owns_=true, env_owned_=true, release()), walk every statement in between for throws or early returns, including non-throwing skips such as an empty result or a null parent. Require a scope guard with release-on-success, or record ownership at acquisition.
- Bulk-free completeness: for every deallocate_all/reset/'free everything' on an allocator or pool, list every layer that records a live allocation (free-list blocks, per-bank address sets, allocator-level handle sets such as unordered_set<Buffer*>, each object's allocation status). Confirm the bulk path clears or invalidates all of them, or can only run when no owners remain. Also confirm the single-item free erases the item from every set the bulk path later walks.
- Never-destroyed singletons (Indestructible, NoDestructor, a leaked static new): check whether they own, directly or transitively, OS or driver resources (device handles, hugepages, mmaps, threads, files, locks). Each such owner needs an explicit teardown that is guaranteed to run once (a single atexit, or caller-owned lifetime), and nothing may call instance() after that teardown.
- Re-open paths: for every member FILE*/fd/ofstream/thread assigned in create_*/clear_*/reconfigure_*/attach, confirm the previous handle is closed or joined first, and that detach, error and destructor paths close it too. A stop flag must be followed by a join before a new thread starts or shared state is torn down.
- Iteration-scaled test footprint: in loops over num_iters, flag device tensors (inputs, outputs, persistent buffers) that are appended to lists kept until the end with no per-iteration deallocate or move to host. When adding deallocations around trace execution, confirm a traced output is not freed while a non-blocking execute_trace may still write it, and that every run is still compared.
- Host weight-load peak: for checkpoint loads (especially quantized ones dequantized on CPU), check the materialized dtype ('auto' or default fp32), whole-dict conversions that copy instead of rebinding, and whether the framework model object is still referenced (needs del plus gc) after its tensors are extracted.
- Raw-owning containers: for vector<T*> or graphs of raw new'd nodes, check for a destructor that frees each element, a delete before every erase/clear/reassignment, frees on every branch for allocations made in loops, and copy deleted or implemented. Commented-out delete lines are a red flag.
- Python monkey-patching of native-bound classes: `Cls.attr = property(fn)` or `Cls.__op__ = lambda` holds module globals that reference the class, forming a cycle the binding's shutdown leak check reports. Prefer defining the attribute in the native binding.

## `precision`: Silent narrowing: TF32 source regs, bf16 intermediates, truncation

Precision is lost when a value passes through a narrower representation than the one the code assumes, and nothing raises an error. There are four ways this happens. (1) Hardware-path narrowing. FP32 operands that go through the FPU source registers (eltwise binary, bcast, reduce, matmul) are cut to TF32 even when fp32_dest_acc_en is on. Integers carried as float32/uint32 through FPU-routed min/max/sum come back rounded, and a later equality or index lookup then silently matches nothing. (2) Intermediate narrowing. Multi-stage ops (per-axis reduce loops, W-then-H splits, composite unary chains, RISC read-modify-write accumulation loops) pack each intermediate back to bf16. Rounding errors compound, and the subtractions 1 - f^2 and 1 + f collapse to 0 once f saturates to +/-1 in bf16. (3) Conversion narrowing. Host float-to-bf16 code truncates with >>16 instead of rounding to nearest even. Runtime scalars reach the SFPU as bf16-precision immediates. floor/trunc/range reduction go through int16/sign-magnitude-16 conversions that saturate. Coarse 3-entry 8-bit SFPU LUTs have tail errors of tens of ULP and return NaN at +/-inf. (4) Implicit-state narrowing. A model that sets no compute_kernel_config relied on precision mode leaked from an earlier op. Reference/golden models cast to bf16 corrupt derived buffers such as rotary inv_freq, so the error shows up as drift that grows with sequence length and gets blamed on the device.

**Checks**

- Trace each FP32-capable operand from its CB to the first math consumer. If any FPU op (add/sub/mul_tiles, *_bcast_*, reduce_tile, matmul) reads it through the source registers before a cancellation-sensitive step (variance, x-mean, a difference of large values) or an exact comparison, the value is TF32, not FP32. Accurate FP32 needs UnpackToDest plus SFPU math. List every flag, arch or op combination that silently falls back to the FPU path (fp32_dest_acc_en off, Quasar, the negate-lowered MIN).
- For every multi-stage decomposition (per-axis reduce loops, NC then HW, W then H, composite ops built from several ttnn calls or several Dest ops), write down the dtype of every intermediate. Flag stages that accumulate in FP32 but hand off in the user dtype (bf16/bfp8). Then check that EVERY reduce type that lowers to the same accumulating path (sum, mean/avg, var/std) gets the same FP32 carry, and that select-type ops (max/min, whose negate lowering depends on the intermediate format) do not.
- For expressions of the form 1 - f(x)^2, 1 - f(x) or 1 + f(x) where f saturates (tanh, sigmoid, erf), check whether f is rounded to bf16 (16-bit Dest, BF16_ROUNDING_MODE, or a composite-op boundary) before the subtraction. If it is, the result is 0 across the saturation region. Require per-point ULP tests over that region; an atol larger than the true value hides the bug.
- Find every host float-to-bf16/fp16 conversion: hand-rolled bits>>16, bfloat16::truncate, custom pack helpers. Compare the rounding mode with the torch reference (round to nearest even), or require a comment saying truncation is intentional. In numeric wrapper types, list every constructor overload and flag any integer overload that stores raw bits. A 'fix' that only rewrites static_cast<T>(x) as T(x) or T{x} changes nothing for a class type.
- Find every SFPU floor/trunc/round/parity/range-reduction that goes through a narrow integer conversion (float_to_int16, vSMag16, stochastic round to INT16). Work out the input magnitude at which it saturates, and check whether user-reachable inputs exceed it (x/s with a tiny scalar, large angles, large exponents). Also confirm that runtime scalars reach the SFPU at full fp32 (programmable constants or two-part loads), not as a bf16-precision immediate.
- For each approximation-mode SFPU kernel, find the LUT or polynomial it evaluates and sweep every finite bf16 input, plus fp32 points near segment joins and saturation, against a float64 reference. Check the invariants: sign/odd symmetry, range bound, monotonicity at joins, and +/-inf/NaN handling when no clamp follows the LUT. Any kernel still using the 3-entry vLut8si form is a candidate.
- For reductions, argmax or comparisons whose result is compared for exact equality or used as an index, find the hardware path the dtype actually takes. Only int32 is routed to the exact SFPU reduce. Flag integer data held in float32/uint32, and library ops whose validation accepts an integer dtype that is then computed on the truncating path.
- When a kernel change stops leaking config state (fp32 Dest mode, a format, a math-fidelity bit), audit every caller that does not set that state explicitly, especially softmax/norm/SDPA callers with no compute_kernel_config. Flag PCC thresholds lowered with a comment pointing at a 'proper fix' tracker, and check the tracker is still open.
- In golden/reference models, find where derived constants come from (inv_freq, cos/sin caches, scale factors). If they are read from a module after a blanket .to(bf16) cast, or built with arange(dtype=buffer.dtype), flag them: .float() afterwards cannot restore the lost bits. Prefer tests whose accuracy stays flat as sequence length grows.
- For kernels that accumulate repeatedly into a narrow buffer, e.g. out = to_bf16(to_f32(out) OP x) in per-element loops in dataflow kernels, require a wide accumulator held across the whole reduction and a single round-to-nearest-even at writeback.

## `tt-host-kernel-args`: Host runtime-arg builders drift from the kernel's arg contract

The host program factory and the device kernel share an implicit contract: word order, word count, what each word means and how it is encoded, and bounds on counts or slot indices. Nothing checks that contract, and bugs come from the host side breaking it. (1) Rank and count args for a multi-worker barrier or signaling protocol get hardcoded (count 1, index 0) instead of coming from the loop that enumerates links x directions x workers. Every worker then thinks it is master and the semaphore counts never match, so the op hangs. (2) The host emits a variable-length list, or a count, that the kernel consumes into a fixed-size staging array or a fixed number of CB slots. The only bound is a debug-only assert, so Release builds index out of bounds silently. (3) The encoding follows the C++ type of the argument rather than what the kernel reads. For example, integer scalar bits get packed where the kernel reads an IEEE float. This shows up when a parameter type is widened to a variant and the Python binding starts picking the int alternative. (4) Vector-building mistakes: a reference to an element is kept across a later push_back, so it dangles and the real slot is never patched. Or args are appended or conditionally pushed without updating the numeric indices that override callbacks use to patch buffer addresses. Also, a hang that disappears when args are removed or a reservation is enlarged points to an unguarded fixed-region overflow somewhere else.

**Checks**

- For every multi-worker barrier or signaler setup (fused CCL+matmul, ring/halo signalers), check that the per-worker (num_workers, worker_index, master flag) args come from the same loop variables that enumerate the workers. A literal 1 or 0 is acceptable only on a path that is provably single-worker or is documented as ABI-only. Also check that the index the device uses into its coordinate list matches the order the host used to build that list: link-major insertion order vs a row-major set from corerange_to_cores.
- For every kernel array or CB set that is fixed-size (e.g. `uint32_t x[2]`) and indexed by a runtime count or slot id, find the host builder that produces that count. Prove the count is bounded on every shape/layout path by a TT_FATAL (not TT_ASSERT, which compiles out in Release) placed in the builder itself, not only in an upstream predicate.
- Diff the host push order against the kernel's get_arg_val/get_common_arg_val sequence for EVERY compile-time define combination: sharded/interleaved output, bias, fused op, sparsity, forward/backward. Args pushed conditionally must use the same condition that sets the kernel define.
- Every override_runtime_arguments callback that writes by numeric index (args[7], args[18]) must be re-derived from the current push sequence whenever any arg is inserted before it. Also check sibling factories (1D vs 2D, sender vs receiver) that hardcode the same index.
- For each scalar packer (a std::visit over a variant, an overload set, or a template), enumerate every C++ alternative against every tensor dtype. The bits must match what the kernel reads (float vs integer), keyed on the output dtype. Flag bit_cast of integers not gated on dtype, and gates that list only INT32/UINT32 while other integer dtypes (UINT16/UINT8) exist.
- In any host function that builds a runtime-arg vector, flag a reference, pointer or iterator to an element (auto& x = v.emplace_back(), &v[i], v.back()) that is used after a later push_back/emplace_back/insert/resize/append on the same vector. The fix is an index.
- When a parameter's type is widened (float -> variant, int -> optional), audit how the Python binding now resolves int vs float, and every place that packs that parameter into kernel args.
- If a hang or corruption goes away by shrinking the arg list, adding padding, or enlarging an L1 reservation, treat the arg change as a workaround. Look for the missing capacity assert on the fixed L1 region (L1-small, config tensors, per-core runtime-arg space).

## `tt-cb-access`: CB window, wrap and release-ordering violations

Kernels touch circular-buffer (CB/DFB/remote-CB) pages outside the window they actually own. Four mechanisms account for most cases. (1) Release before the data movement that uses the slot has finished: a writer pops, or a reader pushes to compute, while async NoC writes or multicasts sourced from that slot are still in flight. The slot then gets refilled or repacked under the DMA. The same bug shows up when in1 is released inside an inner subblock loop instead of after it. (2) Writes outside the reservation: headers, preambles, orphan or wrap fragments, or read-ahead blocks are written before the credit acquire or reserve_back that covers them, or before the reservation has been widened. A variant is an aligned NoC read (rounded up to the buffer's alignment, which is larger on Blackhole DRAM) that clobbers neighbouring rows packed at a smaller pitch in the same page. (3) Pointer-wrap arithmetic: the WH/BH dataflow CB pointer wraps only on an exact hit of the limit. So a multi-page or variable-size push, pop or reserve (partial last chunk, larger first step, 2*K pop, indexed read at tile > 0) whose running offset is not a multiple of the ring size runs past the end. Related errors are mixing an absolute address with a size in wrap math, a page size that does not divide the CB size, and a missing wrap after a fragment advance. (4) Wait/pop and produce/consume count mismatches: a cumulative per-row wait_front followed by a pop of the full padded block, compute indexing tiles past what the producer pushed because the host padded a dimension, same-kernel pack-then-unpack of one CB with no wait_front (UNPACK/MATH/PACK have no shared program order), or a manual rd/wr pointer rewind over a CB that is aliased to the output.

**Checks**

- For every pop_front or push_back of a slot that is also the SOURCE of an async NoC write or multicast, check that a writes_flushed, TRID-scoped flush or write barrier sits between the last write sourced from those pages and the release. A single flush after a loop that pops on every iteration does NOT count. Check the mcast, unicast and forwarding-receiver paths separately.
- When a fix for the pattern above exists in one helper, grep every fork of that helper (experimental/, ccl/ fused variants, fabric_bound_*, *_metal2, quasar/, tt-train, model-local copies) and diff the pop/flush ordering. Fixes routinely reach only the main copy.
- Simulate rd/wr pointer position modulo the CB page count across the WHOLE loop nest, including outer row, block and work loops and more than one block per core. Every reserve, push, pop or wait size, and every indexed tile read (index plus current offset), must land at or before the ring end, never straddle it. Pay special attention when step sizes vary (a partial last chunk, a first iteration that differs, an odd tail, adaptive increments). If they vary, the CB size must be a multiple of every reachable sequence of steps, or the steps must be one page.
- For every producer, check that EVERY byte written into a slot (headers, preambles, orphan or wrap fragments, padding, read-ahead blocks in trid pipelines) is written AFTER the reserve_back or credit acquire that covers that slot. Also check that the pre-loop reservation already covers the first read-ahead block. Walk the wrap branch separately, and check that each pointer advance, fragment paths included, is followed by a wrap check.
- For consumers that wait incrementally (a cumulative wait_front per row or subblock, possibly with early break or continue) and then pop a block, check that the maximum wait on every path is at least the pop count. Also compare the producer's push granularity with the consumer's pop granularity on partial or remainder blocks.
- Where the host pads a compute dimension (subblock or block width rounded up) past what the producer pushes, check that the last-iteration unpack or read tile range stays within the produced count. If the fix narrows a block dim at runtime, check that the new value agrees with what init was configured with.
- In a compute kernel that packs into a CB and then reads the same CB (or an alias view of it) by tilize, untilize, reduce or copy, check that there is a wait_front for the exact pushed count before any unpack-side init, uninit or read, and that space is freed only through pop_front. Program order across TRISC threads is not synchronization.
- For NoC reads that stage into a CB page, compare [dst, dst+len) against rows already filled in that page. A read rounded up to the alignment into slots packed at a smaller pitch clobbers neighbours; evaluate it with the largest alignment of any arch and memory kind. Flag hardcoded alignment masks (0xF, 15, 16, 32, 64) used where the buffer's own alignment belongs.
- For manual fifo_rd_ptr/fifo_wr_ptr save and restore (in-place accumulation), list every configuration in which the CB is aliased to another CB (for example partials == out without bias), then trace the final iteration so it never overwrites already-finalized output. For remote or global CB wrap math, check the units: the pattern must be fifo_start + fifo_size - ptr, never fifo_size - ptr. The page size must divide the CB size for every layer or tile size that will be used.
- For multicast senders that also release the source slot, compute num_dests on the host. A non-loopback multicast must exclude the sender even when the sender lies inside the rectangle; otherwise the barrier waits forever. Also check that no comment or struct doc still describes the old counting rule.

## `error-handling`: Swallowed failures become silent wrong defaults

A probe or getter hits an error or a false negative, and the code reports it as a normal outcome ("not present", nullopt, 0, empty) instead of raising or logging. The caller then quietly takes a fallback branch: it skips an optional weight, uses a default memory config, or reserves nothing. So the failure shows up much later as lost accuracy or wrong placement, never as an exception. There are two ways the false negative arises. (1) A name or path built at runtime is fed to a matcher that treats some characters as special. For example, glob reads the brackets in a mesh-shape repr as a character class, so an existence check always returns False. (2) A catch-all or broad handler (catch(...), except Exception) turns every failure into the "absent/unknown" value. A third, related mechanism: code serializes or copies an object by reflecting over dir()/__dict__ with a name heuristic, and breaks when a native binding or a later change adds a method or internal hook the filter did not anticipate. Multi-device and async tensors often take the throwing path that single-device tests never exercise.

**Checks**

- For every existence/presence probe (helpers named *_exists, has_*, any(glob...), bool(glob...)), check whether a runtime value is interpolated into the PATTERN rather than kept as a literal directory. If that value can contain [ ] * ? (str(MeshShape), list/tuple reprs, user paths), the probe silently misses. Require glob.escape, Path(literal_dir).glob(simple_pattern), or listdir plus startswith.
- When a negative result selects a fallback that changes numerics or placement (optional weight treated as absent, default memory config, zero-byte reservation), require at least a warning log or an assert in cache-only/production mode. A silent fallback turns a detection bug into a silent accuracy loss.
- Find catch(...) or except Exception handlers that return nullopt/None/0/false/{} instead of rethrowing, then trace every caller's value_or(default) or 'if not x' branch. Decide whether 'error' and 'genuinely absent' should be distinguishable. If they should, the handler is a bug.
- For catch-all handlers that assume a single failure cause (e.g. 'pin limit exceeded, evict and retry'), check whether other exceptions (invalid args, fatal asserts, allocation failures) are also caught and wrongly handled as that cause. Examples: draining a cache, retrying forever, or returning null with no diagnostic.
- Check that multi-device, mesh and async (not-yet-populated) tensors reach getters such as memory_config/dtype/layout on the same non-throwing path as single-device tensors. The swallowed-exception fallback usually fires only on the multi-device path.
- When an object is serialized or copied by iterating dir()/__dict__ with a name filter ('__' in name, startswith('_')), check whether the object is a native binding, or a class that can gain methods/properties/metaclass hooks. Require an explicit field list or a value-type filter (not callable, not a descriptor).
- For helpers copy-pasted across model demos, grep for byte-identical copies of the pre-fix version whenever one copy is fixed.

## `tt-reconfig-drain`: Config/mode rewrites racing in-flight Tensix consumers

A config register or global mode bit (format fields, Dest width or remap/swizzle, integer-math enable, packer/unpacker base or destination addresses, per-tile offsets) gets rewritten while an engine that reads it (UNPACK, MATH/FPU, SFPU, PACK, or another TRISC) still has work in flight. The drain that comes before it is missing, too narrow, or on the wrong path. There are four recurring shapes. (1) The wait covers the writer's own producer, such as THCON for a GPR or SRCx_VLD, but not the consuming unit (PACK, MATH, UNPACK). A related case: a bank-flip from the previous MOP iteration's end op is still in flight when the replayed start op's wait is evaluated. (2) The wait mechanism does not order the write path. A Tensix STALLWAIT does not order a posted RISC MMIO cfg[] store unless it waits on TRISC_CFG. STALL_CFG does not gate ThCon-path writes. A context-release semaphore_post placed before or next to the store can let the consumer overtake it. (3) A call-once full hw_configure/hw_startup is re-run in the middle of a kernel, per thread and with no cross-thread barrier. The same happens with a global mode bit that is set but never restored, or toggled between ops. The state then leaks into later ops or kernels, or changes under running ones. (4) A partial reconfig recomputes a shared bit from one operand only, or a per-entry separator such as a format-switch clear is keyed on the "previous" entry of the same call, so transitions across calls or across operands go unguarded. The symptoms are usually nondeterministic PCC, results that depend on test order, and failures that vanish with the watcher on, with an added sleep, or with a different fidelity.

**Checks**

- For every write that changes state a Tensix unit reads while it runs (WRCFG, REG2FLOP, cfg_reg_rmw_tensix, RMWCIB, cfg[...]= MMIO), name the consumer unit(s). Then confirm that a STALLWAIT on THAT unit (UNPACKn/PACK/MATH/WAIT_SFPU), or a documented latch-at-start guarantee plus a draining instruction, sits between the consumer's last in-flight use and the write. A GPR-producer fence (THCON) alone is not enough.
- For every RISC MMIO store into unpacker/packer config (cfg[THCON_SEC*_REG3_Base*] = ...), find the first UNPACR/PACR/MOP/replay that consumes it. Require (a) that any semaphore_post or context release comes after the stores, and (b) a STALLWAIT(..., TRISC_CFG) whose stall mask covers the consumer's class (STALL_UNPACK for UNPACR, STALL_CFG for replayed cfg ops). Check mid-loop rewrites of double-buffered contexts too, not just the entry writes, and the WAR direction (a context's address overwritten while queued instructions still use it).
- At every wait that guards a Dest-to-Src move (MOVD2A/MOVD2B) or any write into a double-buffered source bank, check whether a bank-flipping op (ELW*/MVMUL with CLR_A/B, SETRWC CLR_AB, CLEARDVALID) can still be in flight, including the previous MOP iteration's end op when the wait is the replayed start op. If one can, the wait needs p_stall::MATH, not only SRCA_VLD/SRCB_VLD.
- Diff per-arch twins and op-local vendored copies (tt-llk experimental vs ttnn .../kernel_includes/tt_llk) of the same LLK file. Look for wait-condition bits present in one copy and missing in another. A BH file that is otherwise byte-identical to WH but lacks MATH in a condition list is a strong lead.
- Grep compute kernels for full-configure calls (compute_kernel_hw_startup, deepseek_compute_kernel_hw_startup, *_hw_configure*) anywhere except once at kernel entry, especially inside loops or under 'if constexpr (flag != DST_ACCUM_MODE)'. Each one needs a drain and barrier across all three TRISCs, or should be replaced by the targeted reconfig or init pair.
- For every short or partial reconfig API, list each field the full hw_configure derives from the operand formats, including shared bits such as INT8_math_enabled, signedness and FP32-accumulate. Confirm the reconfig rewrites each field, from ALL operands that contribute (using cached formats), on the thread that owns the field, and behind a drain of that field's readers.
- For global mode bits (Dest remap/swizzle, Dest 32-bit mode, debug-feature bits), check two things. Some per-kernel entry path must set the value unconditionally, so it cannot leak from a prior kernel. Every mid-kernel toggle must go through a helper that drains both MATH and PACK and is paired with a restore. Order-dependence hacks in tests, such as renamed 'run last' files, signal leaked state.
- Decode both operands of every STALLWAIT against the arch enum. The first operand must be a STALL_* mask, and the rest must be wait-condition indices. Confirm the wait condition actually tracks the producer: TRISC_CFG tracks RISC stores, not Tensix RMWCIB. Resolve what a helper such as cfg_rmw expands to on that arch before you judge a stall needed or redundant.
- For per-tile/per-face format tables that insert a clear or stall only when consecutive entries differ, check what the FIRST entry of a call is compared against. Also check that a call either ends in a neutral state or that the context release waits for its in-flight unpacks.
- When host code sizes Dest-resident blocks from get_dest_reg_count(compute_kernel_config), confirm that dst_full_sync_en (and fp32_dest_acc_en) is also forwarded into the kernel's ComputeConfig/ComputeConfigDescriptor, so host sizing and the kernel's Dest mode agree.

## `units`: Bytes, words, tiles and banks silently mixed

A quantity is produced in one unit and consumed in another, and nothing in the type system notices: bytes are passed where the callee counts 32-bit words or 16-byte address units; a per-bank size is checked as if it were a per-device total; an absolute index is used as a relative count; or a value that is already encoded (packed NoC XY, pre-shifted address) gets shifted a second time. The same unit is also often re-derived in several places (reserve vs. budget check, page-table width vs. ring modulo, the stride field vs. the base/limit fields), and one site keeps the old derivation. Hard-coded per-datum or per-tile widths (64 B per tile row, element_size()==1 for block-float, rand()%8 for a grid or bank count) fix one dtype or part as an assumption. Word-typed staging buffers sized with a truncating byte/4 overflow when the size is not a multiple of 4. These bugs stay hidden when the scaling factor happens to be the identity: one bank, core 0 or base 0, shift 0 on one arch, a single tile that never reaches the wrap, or bf16-only tests. When they surface, the result is a hang (CB producer and consumer disagree on a count), heap or L1 overrun, garbage NoC coordinates, or wasted memory and bound checks that never fire.

**Checks**

- For every copy/fill/read/write helper, work out the unit of each length parameter from the callee body (loop stride or pointer type). Then at each call site, check how the argument was derived: a difference of integer-cast addresses or a sizeof is bytes, and a typed-pointer difference is elements. Flag any mismatch, and any bare integer length where a strong type (like the typed word-count used in firmware init) would stop the mix.
- Where one struct or init block holds several address-like fields (base, limit, rd/wr ptr, stride, entry_size), confirm that every field is converted to the same unit for each target core type. A shift applied to some fields but not their siblings is the bug. Treat an `==` wrap check on a ring pointer as fragile, because it hides stride errors by never firing.
- When a size or budget knob is read in more than one place (reservation, capacity check, error text, docs), write down the unit at each read: per bank, per core, per device or per mesh. Check that the capacity check charges exactly what the allocator charges. For interleaved buffers that is ceil(pages/num_banks)*page_size in every bank, not the raw total.
- Host staging buffers typed as std::vector<uint32_t> but filled by byte-count reads or memcpy must round up with (n+3)/4. Their row offsets must be computed in bytes, not in truncated word counts. Exercise every host read and write API with sizes that are not a multiple of 4 or of the alignment.
- Flag any tile, page or CB byte size computed as elements*element_size() (or sizeof) on a path that accepts block-float dtypes (bfloat8_b/bfloat4_b). These need the data-format tile-size helper because of the exponent section. The same applies to per-face and per-row byte math.
- In dataflow kernels, look for literal byte widths (64, 128, >>6, >>7, 'assuming 2 bytes per datum') that turn bytes into tile or element counts, and for bool flags that pick between two widths. Enumerate every dtype the op's validation admits (1-, 2-, 4-byte, block-float), and check that the count equals what the paired compute kernel pushes or waits on. A mismatch hangs.
- When a variable named for valid, unpadded or logical data feeds a kernel, check that it comes from the logical shape and not from padded_shape, page_size or aligned_page_size. Compare the same op's single-core, default, block and sharded factories: all must use the same source.
- Where a debug, sanitizer or logging path rebuilds an address that the real path computes, confirm it uses the same encoder, and that it does not re-shift or re-pack an already-encoded value such as a bank-to-NoC-XY table entry. Watch for encodings that are the identity on one architecture.
- Label every position variable as either an absolute index or a relative count, then check each use: `start + x` and `x <= CONST` both need x to be relative. Mentally substitute a nonzero base (core/user/batch > 0). If a test only uses core 0, it cannot catch this.
- For NoC transfer sizes, CB page sizes and capacity constants: a rounded-up work-unit count (div_up of chunks or tiles) must not size a write into a real tensor or shard. A CB bound to a sharded or row-major buffer must use the aligned stick stride. A table indexed by id must be sized in ids, not in bytes divided by a magic number.

## `uninitialized`: Unwritten bytes, registers and init steps consumed

Something reads memory, a register or a member that its own path never wrote. The value it gets is whatever the previous op, program, firmware owner, stack frame or power-on state left behind. In the device-side cases, L1, CBs, DRAM output slots, SFPU programmable constants and NoC command-buffer registers are all assumed to be zero, or assumed to hold what this op set. They are not reset between programs, so results depend on run order (flaky PCC that alternates pass and fail), you get hangs (a wide aggregate compare over a never-written padding byte, a leftover length or tag word), or L1[0] gets overwritten (a local that shadows a member). Kernels also often write only part of a buffer (only valid tiles out of a padded reservation, only the first column of a synthesized tile, only local expert slots) while the consumer reads all of it, through a reduce, a max or a multiply by a zero weight. On the host side the same class shows up as: structs partly filled and then copied whole, so padding and stack garbage reach the device; a member set only in an initialize() that one construction path skips; a placement-new into a buffer declared after the pointer whose initializer does the write, so the buffer's own `{}` later wipes the object; runtime args written before offsets are finalized; and variables bound only in some config branches. Fixes often move the guarantee somewhere else instead of closing it: a zero-init hidden behind an env flag that defaults to off, a fill that is correct for only one dtype, a register left dirty and covered only by a minimum-firmware-version check.

**Checks**

- For every producer that does reserve_back(N)/push_back(N) or allocates an output region, prove that all N tiles/slots are written on EVERY path: partial chunks, padding, dropped or overflowed entries, non-local routing. If a path skips some, prove the consumer never reads them. Multiplying by 0 does not clear a stale NaN/Inf. When paged and non-paged, or sharded and interleaved, helpers share a padding contract, diff them.
- When a kernel builds a tile or scratch region by hand with partial writes (first column, diagonal, selected faces), find the consumer. If it reduces, maxes, sums or matmuls over the whole tile, every unwritten element must be pre-set to the identity value (-inf for max, 0 for sum). The fill's element width, element count and per-tile stride must also match every dtype the host validator accepts for that CB, including block-float.
- Never assume L1, CBs, DRAM, mailboxes or simulator memory are zero. Any CB used as a 'zeros' or padding source must be written in the same program before its first read. Padding along a reduction axis must be real identity values, not just outputs that get discarded.
- For every firmware image or core type, build a matrix of init steps (noc_init, local state init, packet-tag clear, counter init, register scrub) against the post-condition asserts in the matching kernel epilogue. ## `tt-noc-index`: NoC address resolved in the wrong space

A NoC address or index is built in one coordinate or numbering space and consumed in another. The most common case is a CCL/fabric writer that resolves a DRAM destination for NoC 0 or for its own NoC. It then hands the raw 64-bit address to a fabric packet header, and the remote router issues the write on a different NoC. On arches where DRAM banks have a separate endpoint per NoC, the write lands on the endpoint reserved for the other NoC and the NoC hangs. Related mismatches:
- A device helper does its own bank math and leaves out terms the canonical helper adds: per-bank base offsets for banks that share a channel, or per-view DRAM offsets. Shards then alias onto each other.
- Harvested (physical) channel numbers are mixed with compacted logical indices, so a mid-grid harvested channel shifts every later lookup.
- A page-size contract disagrees with the tensor's real page, for example per-element get_noc_addr on a single-row page.
- The x/y traversal order disagrees with the shard orientation.
- A range check that is correct for NoC 0 is not inverted for the mirrored NoC 1.
- Counters or alignment are treated as per-kernel when the hardware tracks them per core or per load span. Examples: co-resident kernels sharing a dedicated NoC's transaction counters, and linker sections not aligned to the NoC write granularity.

**Checks**

- When a kernel builds a NoC address that a different agent will issue (fabric router, mux, relay, another RISC), check that it was resolved for the NoC that agent uses: the fabric router writes on its fixed local-chip NoC, not NoC 0 and not the kernel's NOC_INDEX. DRAM destinations matter most. Prefer APIs that take (page id, accessor) and resolve at the point of issue.
- After an API migration or workaround lands for some ops, grep every remaining use of the legacy raw constructor (NocUnicastCommandHeader{addr}, to_noc_unicast_write) across all CCL/fabric kernels, including kernels added later. An unenforced migration regresses when new ops copy old code.
- Where device code computes (bank id, offset) -> NoC address with its own math, diff it against the canonical bank-address helper term by term: per-bank base offset (banks sharing a channel), DRAM view offset, and a coordinate space that matches what the host packed (logical, virtual or translated).
- For every (core, address) API that can target DRAM cores, check that the per-channel offset is applied exactly once in fast and slow dispatch, for both read and write. Bounds checks must use the same offset window and include a lower bound.
- Whenever an index crosses layers that number hardware differently (physical with harvest gaps vs compacted logical, UMD-logical vs framework-logical), check that the producer and consumer use the same space. A `channel >= size -> break` guard only handles trailing harvest, so test with a mid-grid harvest mask.
- Check that an address generator's page_size equals the host tensor's real page size (for row-major, the whole last-dim row). Also check that each L1 landing buffer covers the transfer rounded up to the source memory's per-arch alignment, not a hard-coded 32B.
- For any linear index -> (x,y) core traversal, check that the innermost axis matches the host's shard orientation (row-major means x innermost) in every duplicated copy: sender/receiver and pre/post variants.
- For coordinate range checks after a per-NoC transform that mirrors on NoC 1, check that the lo/hi comparisons are inverted for the mirrored NoC and that refactors kept both branches.
- For a kernel that owns a NoC in dedicated mode, list every co-resident processor that issues on that NoC index. The owner's software counters must include them before any barrier or exit assert. Also grep for exit-idle asserts that are compiled out, and check whether the justification in their comment is still true.
- Check that every region dispatch writes over the NoC (ELF load spans, mailboxes, debug buffers) starts at the NoC write alignment: each linker output section needs ALIGN, and no .srodata/.sdata input may be left as an orphan. Treat any newly enabled or previously compiled-out ASSERT as untested, and check its polarity.

## `cache-key`: Cache keys that miss inputs or collide

A cache or memo stands in for "this artifact is the same thing". Its key leaves out an input that changes the artifact, so the wrong artifact gets reused. This happens in the JIT build key, per-kernel config_hash, program-cache hashes, static singletons, skip-if-unchanged reconfig guards, tuned-config tables, profiler op-info caches and weight/golden caches. There are three ways the key goes wrong. (1) Omission: a config field, runtime option, device-topology attribute (MMIO vs remote, CQ count, device id) or geometry field (tile/face dims, rank, K/N) reaches the generated code, flags or programmed state but not the key. It is often an option that can be flipped in the middle of a process, or a field that one sibling variant (another arch, kernel type or factory) does hash. (2) Lossy or weak hashing trusted as equality: identity std::hash plus xor/shift or boost combiners, `seed =` written over the running seed instead of folded into it, variable-length strings or vectors streamed with no length prefix, and containers normalized (padded) before they are hashed. Any of these makes distinct inputs collide in a cache that has no exact-key check. (3) Keys built from the wrong identity: a sentinel hash (0 when the feature is off), a display string (a pytest node id), a hash made for another purpose (program hash reused by the profiler), or a cached payload that bakes in a per-call field (the cache-hit flag, device). A related case is on-disk caches that take a directory's existence as proof that every output inside it is complete.

**Checks**

- For every build, program, binary or memo cache, list everything that changes the produced artifact: every field of the config struct, every value copied in set_build_options or genfiles, -D defines, linker script, opt level, rtoptions, and device topology such as MMIO/remote, num_hw_cqs and dispatch core type. Trace each one into the key. Any field that reaches generated code or compiler flags but not the hash is a stale-binary bug.
- Diff the hash or config_hash functions of sibling variants (per arch, per kernel type, live vs offline/mock factory). A field one variant hashes or sets and another leaves out or leaves at its default is the strongest single signal of an omission.
- For every 'skip if unchanged' reconfig guard, compare the fields in the condition with every parameter the guarded reconfigure programs (formats on both sides, face_r_dim, num_faces, tile size, partial/narrow flags). Check every sibling unit (unpack/pack/math) and every arch copy of the same guard.
- In hand-written std::hash and combine code, check that each field is folded into the running seed (seed ^= / mix(seed, h)) and never assigned over it. Flag weak leaves such as x ^ (y << 1) and identity integer hashes, especially where the hash is the whole key with no equality comparison.
- Where a streaming hasher consumes strings, vectors or maps, check that each variable-length element is length-prefixed or delimited and that the container size is hashed. Otherwise ['ab','c'] and ['a','bc'] collide, and so do {"AB":"1"} and {"A":"B1"}.
- For types whose attribute_values() or to_hash feed a cache key, compare the fields they expose with what operator== compares. A constructor that pads or normalizes (for example padding a rank-2 shape to 4 dims) merges distinct values in the hash even when equality separates them.
- For long-lived static variables or singletons keyed by device id, check whether their contents also depend on arguments or options that can change within one process (re-open with a different CQ count, fast-dispatch toggles, fixtures that flip rtoptions). Any such input missing from the key is a stale-state bug.
- For caches that emit a full record once and short references afterwards (profiler op-info), check that each field that can differ between occurrences (device, cache-hit flag, shapes, runtime attributes) is either in the key or re-emitted on every hit. Check that the key can never be a sentinel such as 0 when the producing feature is disabled.
- For tables of tuned program configs, list the dimensions the config depends on (K, N, M, grid, head dims). Check that each is part of the key or validated against the live tensor shapes, and that the validation is not skipped when a shape lookup returns None.
- For on-disk caches and test weight/golden caches, check that a cache hit means all final artifacts exist and were published atomically, not just that a directory exists. Check that the cache is tied to the source identity it was built from (checkpoint revision or hash) and not to a cosmetic string such as a test node id.

## `tt-shared-scratch`: Shared L1 scratch, slots and tokens without ownership

A fixed or reused scratch resource has more than one writer, or more than one live lifetime, and nothing enforces which one wins. The resource can be an L1 staging slot, a sideband mailbox word, a CB carved at a hand-computed offset in a backing tensor, a replay-buffer slot range, a hardware sync-semaphore index or a global debug/control register. Four mechanisms keep recurring. (1) The slot key leaves out an agent. A slot is indexed by NoC id only, or chosen by a COMPILE_FOR_* #if chain that covers some core types, so two RISCs, or a new core type that falls to the default branch, share bytes. (2) A buffer is overwritten while an async NoC transaction still reads it. The NoC reads the source when the packet leaves, not when the call returns, and a drain check that covers only non-posted writes (or only one command buffer or mode) is not enough. (3) Two host-side layout sources of truth disagree. The address passed to the kernel comes from a separate formula (base rounded up) rather than the allocator. Reserved sizes are smaller than sizeof() of the device struct. Running offsets are reset to 0 while earlier regions are still live. A host-side ring-buffer mirror is not updated when trace replay uses device memory. (4) The lifetimes are assumed disjoint but only host call order enforces it. Remote (NoC or fabric) writers, peers running at different speeds on skewed cores or mesh columns, a producer/consumer widened to N-deep buffering while a data word stays single, one kernel source running on both DM RISCs with per-source offsets that restart at 0, and instrumentation that borrows a semaphore it assumes is idle.

**Checks**

- For every fixed L1 scratch/staging/mailbox address in device code, list every agent that can run that code: BRISC, NCRISC, each ERISC variant, DRAM-core RISC, Quasar variants, dedicated and dynamic NoC modes. The index must include a component unique to the processor wherever two agents share a key, and every core type must have its own #if branch whose address is valid in that core's own memory map. A MEM_*_<purpose>_BASE macro that nothing uses means a branch is missing.
- Wherever a local buffer is staged and then sent with an async NoC write, find the next CPU store to the same bytes. It needs a flush or barrier in between that covers EVERY transaction kind that could still be reading: posted and non-posted, all command buffers, both NoC modes. A stage/write/overwrite sequence with no flush in between is a race.
- When an emulation replaces a native primitive (for example an inline write emulated as stage-then-async-write), check that it keeps every semantic of the native call: byte-enable, multicast ack count (num_dests), posted/ack behaviour, counter bookkeeping. An ignored parameter or a hardcoded 1 is a finding.
- For every L1 layout computed on the host, check that each address handed to a kernel (CT/RT/named args) comes from the same allocator that assigns its neighbours. Compare each reserved size with sizeof() of the device struct written there, and assert that live regions are pairwise disjoint and fit the backing size.
- Where CBs are carved from a shared backing tensor at running offsets, record each region's [offset, offset+size), core set and live phase. Flag overlaps in address and core set where either side is written remotely (NoC, fabric, CCL) and no device-side semaphore orders the remote write after the local reader finishes. Also flag a running offset reset to 0, or a second running offset on the same tensor.
- For every buffer that a collective writes remotely (broadcast destination, all-reduce receive, gather target), find the other phases or collectives that use the same tensor. If two share it, a device-side handshake must order them; host call order is not ordering, because mesh rows/columns and cores progress independently.
- When a kernel source is instantiated on both DM RISCs, or a handshake is widened from single to N-deep, check that every scratch region and every sideband word (address, size, count) is per-instance or per-slot. Each copy must be written only after its slot's free wait and rotated in lockstep with the semaphore index.
- Treat small shared hardware resources as allocated: replay buffer slots, sync-semaphore indices, global debug/control register bits. List every client across library, kernel, compiler-generated code and instrumentation, check each stays in its partition, and give each register bit one owner. Prefer poison or static_assert exclusions over 'unused elsewhere' comments.
- For host-side mirrors of device state (config ring-buffer allocators, launch-message pointers, prefetcher caches), check that every path that uses device memory outside the normal reserve path invalidates, resyncs or stalls: trace replay, capture, counter wrap, reset, sub-device switch.
- For a TensorAccessor or address generator given an explicit page size, the value must be the aligned bank page size, not the logical row bytes. Otherwise pages after the first in each bank alias or misaddress on the arch with the larger alignment.

## `tt-noc-exit`: Kernels exit with NoC transactions still undrained

A data-movement kernel returns, or publishes a "terminated" status, while NoC transactions it issued are still outstanding. The usual case is a non-posted atomic (noc_semaphore_inc, Semaphore::up, inc_multicast, or a fused-op signaler's increments) followed only by a write barrier. Writes and atomics have separate ack counters, so the write barrier does not retire the atomic. The same gap shows up for writes left undrained on early-return paths, posted inline writes never flushed, traffic on a second NoC while the barrier drains only the default NoC, packet tags not cleared, and early-exit macros inside helpers that return only to the caller's loop instead of out of kernel_main. With the watcher on, the exit check asserts and aborts, which often hides the real multichip error. Without the watcher the stray ack can throw off the next kernel's counters on that RISC, so the next kernel hangs in its own atomic barrier and gets blamed. A separate shape in this class: a one-packet or stateful NoC read whose size goes past the arch's max burst. Nothing on the host bounds that size, so the op completes but the device hangs at teardown.

**Checks**

- List every non-posted atomic a kernel can issue, including ones inside helpers such as fused-op signalers, remote-CB pointer updates and synchronize_workers_and_signal_op. On EVERY exit path and in EVERY compile-time variant, confirm that an atomic barrier or full barrier runs after the last atomic. A write barrier or writes_flushed alone does not count.
- Look for the barrier under #ifdef / if constexpr (for example a global-CB-only block). Find out which program factories never set that define. The atomic barrier must not depend on unrelated config.
- List every return in kernel_main, including 'last page' early returns inside nested loops, idle/hop-core early-outs and the fall-through end. Check that each write or atomic issued since the last drain gets its own barrier on that path.
- Don't treat a trailing semaphore wait or a fabric close as the drain unless the wait provably depends on a response that comes causally after the atomic's ack. Flag cover that is conditional, such as fabric close only when logically connected or a wait only when wait_output_semaphore is set. Record incidental drains as latent.
- In kernels that use more than one NoC (upstream_noc_index, a second noc), check that the barrier drains each NoC used, for each transaction type. A no-argument noc_async_full_barrier() drains only the default NoC, and the watcher exit check only looks at NOC_INDEX.
- Before any status_ptr = TERMINATED or kernel return in fabric/dispatch code, check that posted writes are flushed (posted_writes_flushed), reads are drained and packet/TRID tags are cleared. write_barrier plus atomic_barrier does not cover posted writes.
- For early-exit macros (IDLE_ERISC_*RETURN, early_exit()) used inside helper wait loops, check that kernel_main tests the exit condition after the helper returns. Otherwise the command loop keeps running on stale state with no drain.
- When one kernel of a family gets an exit-drain fix, grep for its forks in experimental, non-experimental, metal2 and Quasar dirs, and in fused ops. Diff the tails of each copy.
- For every one-packet or stateful read/write (set_state/with_state with NOC_MAX_BURST_SIZE as max_page_size), trace the size back to the host factory. It must be bounded by hal::get_noc_max_burst_size_bytes() for every allowed shape, and not by a hard-coded per-arch constant.

## `missing-exit`: Missing or wrong early-exit and return paths

Code either lacks an exit it needs or has an exit in the wrong place, and the result is one of three failures. (1) A validator returns early because one input is absent (an empty optional, no allocations, an empty list) and skips checks that never depended on that input, so bad configurations are accepted without an error. A validator that claims to mirror another one also falls behind when checks are added to the original. (2) An op frees its input and then allocates its output, but has no exit for the degenerate case where the allocator hands back the same or an overlapping address. It then copies onto itself or frees the input twice, and paths that should be siblings (interleaved vs sharded) handle "cannot relocate" or "still referenced" differently. (3) Device error handlers spin forever with `while(1)` to report an error. That only works on cores that the next program load resets. A core that shares its CPU with base firmware, such as an active Ethernet core, stays wedged. The fix needs a "done" signal to the host plus a return to base firmware, and it is copied into several handlers, some with per-arch or per-core exclusions. A related form: a non-void function runs off its end with no return because a merge or diff hunk cut its tail. This is undefined behavior, and the build only warns about it.

**Checks**

- In any validate_*/check function that does several independent checks, find each early `return`/`continue` triggered by one input being absent (`!opt.has_value()`, `empty()`, no allocations). Confirm it skips only the checks that use that input. Bound checks like 'region end <= max size' must still run.
- When a function is commented 'Same as X' or 'Mirrors X', diff it against X in the current tree. Every mode-specific branch in X (hybrid/per-core allocator recompute, service-core or reserved-core handling, per-device loops) must exist in the copy too.
- In ops that free the input before allocating the output (move, reallocate, in-place helpers), look for an explicit exit when the output address equals or overlaps the input. The address comparison must also compare buffer type/device. Check that the input is released exactly once on every path.
- Check that sibling implementations (interleaved vs sharded, single vs multi-core) respond to the same degenerate condition the same way. If one fatals and the other silently returns the input, one of them is wrong.
- List every device-side 'report and spin forever' path: watcher assert, NoC sanitizer, link-down, pool exhaustion, unimplemented branch. ## `tt-dest-capacity`: Dest tile indices exceed half-sync fp32 capacity

Compute kernels and the host factories that size them assume 8 or more Dest tiles are available. The real per-acquire budget depends on the ComputeConfig. Dest holds 16 tiles of 16-bit data. fp32_dest_acc_en halves that, and the default half-sync mode (dst_full_sync_en=false) halves it again, so fp32 with half-sync leaves only 4 tiles. Factories often turn on fp32_dest_acc_en implicitly whenever any operand is FLOAT32/Int32/UInt32. After that, a literal batch of 8, a fixed layout with five scratch or accumulator slots, or a scratch index like 8 writes into the half the packer owns. The result is silently wrong tiles: often only tile 4 and later, only in mixed-dtype or multi-core cases, and never a NaN or a hang. The same kernels often have related state bugs on the same shapes. A format-only reconfigure can drop the tile geometry, and a reconfigure or init call can wipe raw packer counter/ADC settings made before it. The fixes then get copied into only some of the forked copies of a helper (per-arch fallback paths, experimental forks, model-local copies). Some of those copies also alias a scratch slot between an input and an output and write it before reading it.

**Checks**

- Derive the Dest budget for every (fp32_dest_acc_en, dst_full_sync_en) pair the host can select: start at 16 tiles of 16-bit data, halve it for fp32 accumulation, and halve it again for half-sync (the default). Check that the kernel's highest Dest index, counting accumulators, temps and the whole batch, stays below that budget in every case.
- Trace where fp32_dest_acc_en gets set. If it is forced from an operand or output dtype (FLOAT32/Int32/UInt32), check that every Dest batch size or tile count is computed AFTER that flag and depends on it. Test with mixed fp32/16-bit operands and a remainder shape larger than 4 tiles.
- Flag hard-coded Dest limits (8, 16, a 'fp32 dest holds 8' comment, or TT_FATAL(n <= 8)) in program factories and kernels unless the same config also sets dst_full_sync_en=true. Also flag wrappers like create_compute_kernel that leave sync at the default while a caller's guard assumes full sync.
- List every Dest index in a kernel: copy_tile's third argument, SFPU/binary-SFPU operands, copy_dest_values, Dst::Dn template args, and constexpr dst_reg_N. Check that each one sits under a static_assert against DEST_AUTO_LIMIT or an equivalent budget. Where the host picks between a 16-bit and an fp32 kernel variant, check both variants.
- When a helper aliases one Dest slot for both an input and an output to fit in 4 tiles, check EVERY implementation of that helper (fused fast path, decomposed per-arch fallback, experimental/Quasar forks, model-local copies). Each one must read the aliased input before any op writes that slot.
- For a reconfigure between CBs whose tile shapes can differ, check that the tile-dim-aware variant is used (for example reconfig_full_operand_srca(old,new)), not the format-only reconfig_data_format_srca(new).
- For a raw packer/unpacker config write (pack counters, reads-per-xy-plane, SETADCXX, strides), check that no pack_reconfig_data_format or *_init call sits between that write and the pack it serves, and that the default is restored before the next CB.
- Make sure an LLK_ASSERT/debug build actually runs the fp32 + half-sync configuration. The Dest bounds assert is the only thing that turns this silent corruption into a failure.

## `deadlock`: Circular waits across dispatch, fabric, semaphores and hosts

Hangs in tt-metal come from five recurring mechanisms. (1) A waiter's expected value does not match what producers actually post. An exact-equality semaphore wait on a monotonic or multi-producer counter gets overshot by a next-round or second-signal increment. Or a wait-count addend is applied where the matching signal is emitted only conditionally. Or a software transaction counter bumps once for a transfer the hardware splits into several packets. Either way the counter never equals the target. (2) Resource cycles through shared or bounded buffers. Examples: a shared queue or router channel where one consumer's back-pressure blocks a message a peer needs (head-of-line blocking across collectives); a forwarder that spin-waits on downstream space inside its multi-channel service loop; a single-RISC reader+writer that fills an input CB for every batch before draining an output CB sized for one batch; a sole drain agent whose busy-waits don't service the buffer that producers are blocked on. (3) Serialized fan-out. A blocking call inside a loop over devices or peers means device N must finish before device N+1 launches, which deadlocks when they depend on each other through CCL, fabric or shared semaphores. (4) Deferred or staged sends that are never committed before a wait on the remote reply, typically on the zero-work path where the only send is a sync message. The same happens when a host program is launched through one dispatch path and waited on through another (CQ Finish on a tunneled chip, mixed with slow-path writes). (5) NoC-level hazards: multicasts built without path reservation or the multicast VC, and overlapping unlinked multicasts from one core. Also multi-host handshakes where only one side enforces a timeout, so a peer's clean exit leaves the other side blocked forever in a synchronous send.

**Checks**

- For every exact-equality wait (noc_semaphore_wait, Semaphore::wait, `while (*sem != N)`), list every producer that increments or sets that address, and every phase or loop iteration it is waited in. If the value is monotonic (k+1, a counter stepping by 2), or more than one logical signal shares it, or nothing back-pressures the producer before its next increment, the value can overshoot. Require wait_min (>=), one semaphore per signal, or a reset+ack handshake per round. Check each loop variant or factory path separately, because back-pressure is often hoisted out on one of them.
- For every 'wait until counter reaches N' (dispatch wait commands, completion streams, done semaphores), derive N from the signals this same command stream will actually cause. If signal emission depends on a flag, a per-queue role (which CQ sends the reset/go), or a subset of core types, the addend must be gated by the same condition.
- In any loop that fans an operation out over devices, CQs, peers or links, check whether the per-element call can block until completion (blocking=true, finish, synchronize, push_work(...,blocking)). If the elements can depend on each other, the correct shape is issue-to-all, then wait-on-all. Also check that one 'blocking' flag isn't read with two meanings (host thread vs device completion).
- In forwarding agents with a cooperative service loop (router, mux, relay, dispatch_s, anything that drains a buffer others block on), flag every spin-wait inside a per-channel step or command handler that does not also service the other channels, the drain duty (prints, profiler, telemetry) and termination/teardown polling. A forwarder must check, record a pending state and return. Only leaf producers may block.
- For a data-movement kernel that is both the producer of a compute input CB and the consumer of the compute output CB on the same RISC, check the loop nesting. If all input iterations come before the first output pop, the output CB's page count must cover every iteration's output, or you get a single-RISC circular wait.
- For senders with deferred commit (eager-staging fabric mux, batched credits, buffered writes), prove that a flush/commit happens between every send and any following wait on a remote response, on every control path. Pay particular attention to the worker that the host split gave zero pages, whose only traffic is the sync increment.
- For every NoC multicast construction (broadcast bit, mcast=true init_state), check that path reservation and the multicast VC are set as the legacy API sets them. Diff the control-word construction of new stateful or fast APIs against the one they replace. Also check that an earlier unlinked multicast from the same core is barriered before a new unlinked one starts, and that locally batched issued/acked counters are flushed into the global counters before any barrier.
- For any raw *_with_state NoC transfer whose size is a variable, check whether the size can exceed the max burst. If it can, the hardware may packetize while software counts once, and a counter-based barrier then never completes. For ring buffers, check that full and empty are not both wp == rp.
- In multi-process or multi-host handshakes, check that every blocking call on BOTH sides (ssend, send, recv, collectives) falls under the same timeout or abort policy. Flag 'run on thread, detach on timeout, throw' helpers whose lambda captures locals by reference, and 'abort' parameters that are accepted but unused.
- For tool or infra programs launched during init or teardown (profiler sync, debug), confirm the launch path and the wait path match: slow dispatch with a mailbox poll, or CQ with Finish/event. Also confirm the host does not also touch the same core over a different path, especially on remote tunneled chips.

## `dead-guard`: Guards that compile but can never fire

A check is present and compiles, but by construction it never changes behaviour. The recurring ways this happens: (1) Numeric correction branches compare a value against the quantity it was derived from, so the condition cannot be true. A truncated value is never greater than its source, and a value after abs() is never negative. Repair loops placed after a sign restore only fix one sign. (2) Assert or fatal macros get a condition that is always truthy, such as a lone string literal, a pointer or a constant. Or the macro compiles its condition out in release builds, so side effects inside it vanish. (3) Compile-time detection silently takes the default branch. A `requires { Concept<T>; }` only checks that the expression is well-formed, so it is always satisfied. A `requires { T::hook(...) }` fails when the hook has a deduced `auto` return type defined in another TU, or when the signature differs slightly. The fallback then returns a plausible default (1, empty, first element), so nothing fails. (4) A compile-time size or fast-path guard tests a different quantity from the one actually passed at the call, for example it leaves out a mode multiplier. Or a specialised object (MOP or replay template) is built in an inner scope that shadows the outer one and is never programmed. Near-copy sibling kernels (per-arch, scalar vs tensor, fmod vs remainder) usually keep the dead guard after one copy is fixed.

**Checks**

- For every correction or repair branch, work out how the compared values were derived and ask whether the condition can ever be true. Truncated <= source, abs() >= 0, and a clamped value stays inside the clamp range. Then run the kernel on adversarial inputs (nextafter(n*s, 0), negative dividends, exact multiples), not random tiles.
- Diff guard conditions and sign handling across near-copy sibling kernels: per-arch (WH vs BH), scalar vs tensor-tensor variants, and op pairs like fmod and remainder. A guard fixed in one copy is usually still dead in the others.
- Check where a repair loop sits relative to sign restoration (copysgn or setsgn). A `v >= s` fixup after the sign is restored never corrects negative results. Compare it with the variant that repairs both signs.
- Scan every assert, fatal or throw macro call for a first argument that is always truthy: a string literal, std::string, fmt::format, true or a non-zero literal. Also check that the macro signature makes a lone message argument a compile error.
- For each assert-like macro, find what it expands to in every build mode (empty, unevaluated sizeof, or evaluated void cast). Then grep its conditions for side effects: calls that close, pop, push, lock or write; ++/--; assignment. Device ASSERT and LLK_ASSERT still compile to an unevaluated sizeof when disabled.
- Wherever `if constexpr (requires { T::hook(args) })` picks a custom path over a silent default, check every provider. Is the return type explicit, not a deduced auto defined in a .cpp? Do the parameter list, const-ness and static-ness match the probe exactly? Look for a static_assert or test proving that at least one real op takes the custom path.
- Grep for `requires { SomeConcept<T>; }`. A concept-id inside a simple requirement is always satisfied. The intended form is `requires SomeConcept<T>`.
- In recursive find-first or visit template families, compare sibling specialisations. Does one search every element while another searches only std::get<0>? Does one exclude an overlapping trait and another not? Does every path return an explicit not-found value?
- For single-packet or max-burst NOC read and write fast paths, find the largest byte count actually passed at the call, including mode multipliers (Welford x2, fp32 tiles, last-block size). Confirm the compile-time guard tests that same expression against the per-arch max burst.
- Flag hardware-program objects (ckernel_template, replay descriptors, config builders) declared in an inner scope under an outer name (-Wshadow), or constructed but never programmed or returned. When porting instruction macros between arches, check each argument position against the target arch's signature.

## `rounding`: Floor/truncate where ceil or round-to-nearest-even is required

The same mistake shows up in three forms. (1) Integer sizing. A count, capacity, page number or staging-vector length comes from floor division (total/ncores, dim/TILE, bytes/sizeof(uint32_t), n/2) when the numerator is not guaranteed to be a multiple of the divisor. The last partial unit gets dropped, a buffer comes out zero-sized for tiny inputs, or a worker that takes the ceil half writes past a slice sized from the floor half. (2) Alignment arithmetic. Padding is applied to a sub-length instead of the running offset, since align(a)+align(b) != align(a+b). Or a hardcoded 16/32-byte round-up is used where the target arch needs a larger alignment. The bug stays hidden on the arch where the header size or alignment happens to line up, and appears on the arch with 64B alignment. (3) Floating-point narrowing. fp32 is narrowed to bf16 by truncation (the top 16 bits, bfloat16::truncate, native SFPU/FPU store) instead of RNE. Conversion helpers that fall back to a stochastic default rounding mode give run-to-run drift. Results built from an approximation (reciprocal then multiply) round twice. A related case is batched or threshold-triggered completion (a credit ISR every K transactions) with no tail flush when the total is not a multiple of K, which hangs at kernel end.

**Checks**

- For every size derived by division (total / num_cores, shard_dim / TILE_*, bytes / sizeof(elem), n / 2), prove the numerator is an exact multiple of the divisor through validation or an earlier round_up. Otherwise require div_up/ceil, and check the tiny-input edge (total < divisor, n = 0 or 1) so no CB, stride or allocation comes out zero-sized.
- When a range of n items is split between two workers as floor(n/2) and n - floor(n/2), check that every capacity, stride, sentinel-init count and CB size for the second worker uses the ceil half. Reader and writer agreeing with each other proves nothing, because both can be undersized. Then find copy-pasted forks of the kernel in sibling ops and check that each has the fix.
- Wherever a byte-count API is backed by a wider element container (vector<uint32_t>, uint16 arrays), check that the element count rounds UP and that the downstream byte count is the original size. A helper that resize()s to floor(size/4) and then reads or writes size bytes overruns the heap by 1-3 bytes.
- Where a serializer and a separate size calculator must agree, check that both round the SAME quantity (the running offset versus an isolated sub-length) in the same order. Re-evaluate every alignment constant with each arch's value (PCIe/DRAM alignment 64B on Blackhole versus 32B on Wormhole).
- For every multi-page CB or scratch buffer filled from or drained to DRAM by NoC, check that the page stride uses the arch DRAM alignment (hal/buffer alignment), not round_up_to_mul32 or a literal. Check kernels that compute the second page address as base + raw_size.
- For every fp32-to-bf16 narrowing (host scalar packed into a runtime/compile arg, CB fill, SFPU store in a !is_fp32_dest_acc_en branch), identify the rounding actually applied. Native store and >>16 truncate. Require RNE and check it is consistent across arches and sibling ops. Test ties (low half exactly 0x8000), low-bit NaN payloads, overflow to inf, signed zero, and special-value overrides such as 0*x.
- For every SFPU conversion intrinsic or stochastic-rounding encoding, find the effective rounding mode, including the library default when the argument is omitted. A stochastic mode outside an intentional stochastic-round op is a bug. Hash outputs across repeated runs and after a device reset to catch drift. Also check that the integer width of any intermediate conversion covers the whole range the input guard admits.
- For threshold-batched completion (ISR or credit every K transactions or pages), check for an explicit end-of-stream tail flush on both producer and consumer when the total is not a multiple of K. Check that the flush uses a rendezvous that is safe when several agents share the batch, compares wrapping hardware counters modulo their width, and uses the threshold the hardware was actually programmed with.
- Where a result is computed as a product with an approximate reciprocal, check whether the refinement step runs in every precision branch. If it runs only in fp32, the bf16 path double-rounds.
- Treat 'fixed by shrinking the test matrix' or 'passes after warm-up but fails on first run after reset' as unresolved rounding or PRNG nondeterminism, not as a fix.

## `tt-approx-guard`: SFPU approximations missing range, domain and mode guards

Fast SFPU math builds floats from integers with bit tricks: Schraudolph or fixed-point exp shifted into the exponent field, 2^k built with setexp or (k+127)<<23, a quotient converted to int16 for argument reduction, and LUT segments of the form A*|x|+B. Each trick is valid only over a bounded input range. At the edges the integer wraps into the sign or exponent bits, or saturates, and returns silent garbage (negative exp outputs, NaN near -88, -inf from sin(5e5)) instead of 0, inf or NaN. Common causes are an off-by-one clamp boundary, a guard present on only one side (low but not high), a guard lost when the code is ported to another arch, and a "no-clamp" fast variant whose caller does not provide the compensating mechanism (packer ReLU). A second mechanism is mode plumbing. The precise path is built on an approximate primitive, or an accuracy knob (EXP_APPROX_MODE, fast_and_approx) is ignored because a kernel hard-codes `<true>`, or an arch wrapper drops the template argument. A precision step such as bf16 rounding is also sometimes applied in modes it was never designed for, which changes approximate-mode numerics that models were tuned against. A third mechanism is special values: NaN goes into a saturating sub-function or a SFPSWAP min/max clamp and comes out finite, 0*inf in a LUT tail gives NaN, a multiply loses -0 because nothing restores the sign afterwards, and out-of-domain inputs (asin with |x|>1, log with x<0) get a finite polynomial value.

**Checks**

- For every SFPU routine that turns a scaled integer into float bits (exponent-field shift, setexp with a computed exponent, (k+127)<<23, a 7.3 fixed-point trick), work out the exact input range where the biased exponent stays in 1..254 and the fixed-point value fits its field. Check that BOTH ends are guarded: 0 or subnormal on underflow, inf on overflow. Check that inclusive and exclusive boundaries are correct (-127 vs -128), and test x just above and just below each threshold (for example -88.03, -88.72, 88.72, 89.4) on every arch and with both Dest precisions.
- Enumerate every call site of a guard-dropping variant (InputClamping::None, CLAMP_NEGATIVE=false, *_unsafe_ helpers). Confirm each one provides the documented compensation, such as packer ReLU zero on the same pack thread, or an input already known to be in range. Confirm the state is restored afterwards. Include model-local copies of the kernels.
- Follow each user-visible math knob (exp_approx_mode, fast_and_approx, math_approx_mode, fidelity) from the program config through the define or compile arg to EVERY kernel call site and EVERY dispatch variant: streaming vs standard, sparse, decode, the partial-face vector modes R/C, per-arch forks. ## `tt-noc-fanout`: Multicast destination count and routing mismatches hang

A multicast or fan-out signal is described by several separately maintained numbers: the destination rectangle or hop range, the destination count sent to the hardware or ack counter, the software barrier credit, and the receiver's wait target. The failures come from these numbers drifting apart. The count can come from a logical worker or bank count, or from a rows*cols product, instead of from the rectangle or core list actually built. The -1 for exclude-self can be wrong. A dest-count register may never be programmed on one path, such as a stateful init/with_state split or an inline variant. A line multicast may not physically reach every device the waiter counts, for example a logical line folded onto a 2D mesh. Degenerate grids make it worse: a zero-destination multicast, or a loopback-only multicast that never sets the local flag, hangs. So do asynchronous injectors (profiler flush, tracing) that slip a write into a linked or path-reserved multicast chain, and multicasts issued with path reservation off. The usual symptom is a barrier or semaphore wait that never completes. Sometimes the output is silently wrong instead, because bounding-box logic reads or writes phantom cells.

**Checks**

- For every multicast write, semaphore multicast or multicast atomic, work out the destination count from the same start/end coordinates the call uses: (ex-sx+1)*(ey-sy+1), minus 1 only when the sender is inside the rectangle and the call is not loopback/INCL_SRC. Confirm that the host-supplied count arg is computed from that rectangle, not from a worker count, bank count, shard num_cores() or rows*cols product.
- Follow each group signal/wait participant count from kernel back to host. The receiver's wait_min target must equal the number of increments that can actually arrive: the length of the core list or route really built, not a quantity derived again separately.
- Check the degenerate grid. If the count is N-1 and N can be 1, or the only destination is the sender itself, the zero-destination multicast must be skipped under a guard (if constexpr num_cores > 1), and a loopback-only semaphore multicast must be replaced by a local write of the flag or data. If the host guarantees N>1, find the code that does so.
- In low-level command-buffer or descriptor NoC APIs, list the registers the hardware reads for each transaction kind: unicast, multicast, inline, atomic, and each set_state/with_state or init_state split. Any function that can set the multicast bit, through a bool, a template flag or a cmd_flags mask, must program the destination-count register on that path or in its paired init, and credit the software ack counter with the same count. A function that accepts a multicast flag but has no ndests parameter is a finding even with no callers today.
- For CCL barriers and handshakes built on a fabric line multicast, check that the hop range is physically routable in every allowed topology and fabric config: 1D vs 2D, and a logical line folded or turning on the mesh. A per-direction full-range multicast paired with wait_min(ring_size-1), or with a count of the total targets, and no 2D-fabric branch is suspect.
- Anything that injects NoC traffic asynchronously (profiler quick_push, noc tracing, debug print, watcher) must not land inside a linked or path-reserved multicast chain. Its 'chain in progress' check must read the cmd buffer and NoC the chain really uses. Every macro call site must pass a cmd-buffer id, not a VC number, and must use the caller's `noc`, not noc_index.
- Whenever the multicast/broadcast bit is set, path reservation must also be set. Treat 'rectangles don't overlap, so it's safe' as a defect justification.
- Core sets that get kernels, CBs or multicasts must come from the real shard CoreRangeSet, not be rebuilt from bounding-box dims. Per-row or per-column loops (num_cores_x stages, two-stage reduce) must be gated on the grid being rectangular whenever validation allows non-rectangular grids.
- A kernel that issues remote semaphore increments or other NoC atomics must end with an atomic barrier, not only read/write barriers.

## `tt-noc-data-before-credit`: Credit or semaphore overtakes the data it announces

A producer writes data (a NoC or fabric payload, a posted inline write, a loopback multicast, or plain RISC stores to L1), then publishes a credit: a semaphore inc, a CB push, a slot or free-pages pointer, or a stream-register write. Nothing orders the two, so the consumer can read stale or partial data. The ordering is usually lost in one of four ways. (1) The sender waits with the wrong kind of drain: writes_flushed/posted_writes_flushed only prove the request left, while an ack barrier proves it landed. The flush can also be the wrong mode for how the write was issued (posted vs non-posted chosen by a template flag), or there is no drain at all after a CPU store fill. (2) Data and credit take different paths: different command buffers, VCs, L1 vs register destinations, or different fabric arcs picked by a stateful ring tie-breaker that the payload and the credit each evaluate on their own, sometimes on different RISCs. (3) Block-release and ring counters count the wrong things: boundary-straddling writes get charged to the next block, a receiver acks pages that were never sent, a sender claims alignment-skip pages that are not free, and an unsigned sent-minus-acked subtraction wraps. (4) A cross-device startup barrier is skipped (for example "persistent output ⇒ no barrier"), so a fast peer's writes or incs from the next call land in L1 the peer still owns, or get wiped by the peer's wait-then-reset.

**Checks**

- At every semaphore inc/atomic, CB push_back/pop_front, slot-pointer or free-slots update aimed at a consumer, walk back along EVERY control-flow path to every write the consumer will read (including noc_inline_dw_write and conditional final writes). Require an ack-type write barrier on the same NoC between them. writes_flushed / posted_writes_flushed only show the request departed, so they are not enough unless both go on the same ordered path.
- For each fabric completion credit, prove it leaves on the same connection/direction/EDM as every payload it covers. Flag any route that comes from a stateful selector (ring shortest-path tie toggling, round-robin link choice) or is computed separately for the payload and the credit, or in a different RISC/kernel. A flush bit on the credit only orders writes that reach the same receiving router. Acceptable fixes: send the credit on all arcs, fuse it into the last payload, or pin the route per destination.
- When data and credit go on different command buffers, VCs or destination kinds (L1 write vs register inline write), find the documented ordering guarantee for that exact pair. If there is none, require the data to commit before the credit. Treat a 'non-blocking'/'flush_non_blocking' header send followed right away by a credit as suspect.
- Where a buffer is filled by CPU/RISC stores (loops, memcpy/memmove, pointer writes) and then published (push/pop, semaphore, flag, or a NoC op on that buffer), require a store-completion step: a blocking load of the last word, a fence, or a cache flush/uncached alias on cached arches. A CPU fill gets no NoC barrier for free.
- For multicast with the source included (loopback), the sender's own use of its destination slot (push_back, local read, locally-set valid semaphore) must follow a write barrier. The loopback is ack-counted and non-posted, and a local semaphore set does not order the landing. Check that comments calling a write 'posted, no ack' match the API.
- Before freeing/popping the source buffer of a NoC write, check that the flush/barrier matches the write's actual posted/non-posted mode, which is often a template or constexpr flag. At kernel exit and before any counter reset, match the drain to the last ops on every path: write barrier for writes, atomic barrier for atomics, full barrier if mixed. Local fast paths that use only writes_flushed are the usual hole.
- In block/page-release rings, trace every boundary-crossing path (orphan/remainder/zero-length splits). A write that reads block N must be counted before block N's release snapshot. Mid-stream credits must count only fully written pages (no ceil-rounded partial tail), and a page acquired by an earlier partial write must not be acquired twice.
- In sent/acked credit rings, neither side may advance past the other. The receiver must never ack unsent pages, and the sender must never claim alignment-skip or resize pages without first waiting for free space. Any unsigned 'capacity - (sent - acked)' must be unable to underflow or must be clamped.
- When a cross-device init barrier is skipped conditionally (persistent buffers, cached program, a flag), list every remote write and remote inc. The skip is safe only if all targets outlive the call AND semaphores are rotated per call or accumulate with no local wait-then-reset. Writes into peer CB/L1 scratch need a peer-entered handshake.
- When a refactor moves or rewrites a shared send helper, check that an earlier blocking/flush workaround survived. Watch for default template arguments (blocking=false) quietly reintroducing the unsafe variant.

## `container-misuse`: Host containers: dangling pointers, fill mismatches, ordering assumptions

Host-side C++ code in the dispatch, runtime, device-pool and ttnn op layers breaks an unstated invariant of a standard container. (1) It keeps raw pointers, spans or iterators into vector elements, or into buffers those elements own, and then keeps appending. The reserve was a heuristic, so the vector reallocates, and because the element's move constructor is not noexcept the buffers get copied and freed. (2) The construction and fill methods disagree: a sized constructor followed by push_back gives 2n entries with phantom defaults; reserve(n) followed by a loop bounded by dst.size() gives an empty result; a source of rank N is copied into a destination normalized to fixed rank 4 with the source bound, which overflows the heap. (3) Ordering and keying assumptions: sorted-range algorithms get vectors that were never sorted; unordered_map iteration order ends up defining ring, shard or device order; a sparse external id (chip or device id) is used as a vector index, or a position is used as an id. (4) Paired accumulators (destination list plus payload list, or a per-consumer settings struct) are reset or copied at different granularities. One gets re-emplaced or cleared every iteration while its partner accumulates, a single emit sits after the loop, or a struct reused for the next consumer carries a stale per-consumer field. The asserts that would catch these are often debug-only.

**Checks**

- Where code saves &vec.back(), vec.back().data(), a span or an iterator into a vector's element (or into a buffer the element owns) and then keeps appending, check two things. The reserve count must come from the same logic that drives the appends, not an estimate or a 'x2' heuristic, and a check that survives release builds must confirm size() <= reserved. The element type's move ctor and move assignment must also be noexcept, otherwise reallocation copies and frees the owned buffers.
- For every local container, match the construction method to the fill method. vector<T> v(n) must be filled by index or assignment, never push_back/emplace_back. After reserve(n), fill by append, with a loop bounded by the SOURCE size, never by the destination's size(). Serializer/deserializer pairs need a round-trip length+content test.
- When a variable-rank shape or padding is normalized to a fixed rank (squeeze/unsqueeze to 4D), take every copy loop's bound and index offset from the fixed-rank destination size, not from the original-rank source.
- At every set_difference/set_intersection/set_union/includes/merge/binary_search/lower_bound/unique call, prove at the call site that each input is sorted by the same comparator the call uses (an explicit std::sort, or a std::set). Lists from descriptors, maps, SoC files or users are not sorted just because they look ordered.
- Flag every unordered_map/unordered_set keyed by device, chip, core or rank id that is iterated to build an ordered output (a ring, a shard split, a worker list, per-index results). Hash order must not define topology or order. Also flag vec[id] / resize(id+1) where the id space can be sparse, and any loop over that vector that dereferences an element without a null check.
- In loops that build (destinations, payload) pairs for later command generation, check that both halves are reset and consumed at the same granularity: no container re-emplaced or cleared per iteration while its partner accumulates, and no single emit after the loop when one per iteration is needed. Check that bookkeeping or stats after the loop do not iterate containers that were cleared inside it.
- When one settings/config struct is filled step by step and pushed for several consumers, reset or recompute every per-consumer field (semaphore lists, counts, ids, sizes) before each push. Derive each count from that consumer's own topology level. Make sure the consumer-side count check is not compiled out in release builds.
- Read each 'must be multiple of X in A and B' validation and confirm the boolean connective matches the message (&& for 'and').

**Seeds** (code shapes to hunt for)

- `.reserve(<estimate>)` then `emplace_back`/`push_back` in a loop whose trip count is computed elsewhere, where the body stores `vec.back().data()` / `&vec.back()`: tt_metal/impl/program/dispatch.cpp (runtime-args command sequences, rta_updates), device_command.*

## `atomicity`: Torn multi-word publishes, fake locks, clear-on-write RMW

One logical state change gets split into several memory operations that another agent can see partway through. There are four recurring shapes. (1) A ring's position and its wrap/toggle bit are published or polled as separate words over PCIe or NoC, so the peer pairs a new pointer with an old toggle and decides the queue is empty or full, and both sides hang. (2) Sub-word ring entries are written through a mapping that can widen or merge writes, which brings back a neighbouring entry the other side already consumed and zeroed. (3) Locks are built from plain stores (store own id, read it back, assume ownership) on an arch with no atomic RMW. The "cache invalidate" or "fence" helpers these locks lean on can be empty on that arch, so mutual exclusion depends on store latency. (4) Clear-on-write interrupt or status registers are cleared by writing back a value derived from an earlier read, which clears events that arrived in between (lost interrupts, hangs). The same class also shows up as instrumentation injecting NoC writes into an open multi-transaction hardware sequence (a linked multicast chain), and on the host as mutex-wrapped containers whose check-then-act spans several separately locked calls or returns references or iterators that outlive the lock.

**Checks**

- For every producer/consumer ring shared across agents (host<->device, core<->core, ethernet), list every field in the consumer's full/empty test (pointer, wrap/toggle bit, count, sequence number). Flag it if the producer publishes those fields with more than one store, or the consumer reads them with more than one load, unless a fence plus a documented order makes one field imply the other. Also check that the full test and the empty test agree at wrap (>= versus >).
- For rings or mailboxes where one side writes entries and the other clears consumed entries to zero, find each side's store width. Flag entries narrower than the bus word when the two sides write different entries in the same word, unless the host mapping is proven strictly ordered, non-write-combining and exact-byte-enable. Re-check this every time the entry width or the host window/TLB type changes.
- For every hand-rolled lock or flag protocol, name the hardware atomic or ordering primitive it relies on, per arch. Flag 'store my id, re-read N times, assume ownership' schemes, and any protocol whose cache-invalidate or fence helper compiles to nothing on some arch (check the per-arch definition, not the call site). Check that release publishes the protected writes with a real hardware ordering guarantee, not only a compiler barrier.
- For every write to an interrupt-pending or status register, find out whether it is W1C, W0C or RW. Flag a clear value computed from an earlier read of the same register (read, mask, write back): in W0C every bit that read 0 gets rewritten as 0, and every untouched bit must be written in its no-op state (0 for W1C, 1 for W0C). Also flag a 64-bit register shared by two sources that is cleared using the other source's half of a snapshot.
- Where instrumentation (profiler, tracing, debug print) issues its own NoC transactions inside user kernels, check that it cannot land inside a multi-transaction hardware sequence (linked multicast, stateful write setup, transaction-id window) on a shared command buffer. It must check in-progress state on every command buffer it could collide with, or save and restore that state.
- For helpers that take an integer cmd_buf / noc / vc / trid parameter, compare each call site's argument with the resource the wrapped transaction actually uses. A virtual-channel constant passed as a command-buffer index compiles cleanly and reads a garbage register. Also flag helpers that hard-code the global noc_index when the caller has an explicit noc argument.
- For mutex-wrapped containers, flag callers that compose separately locked accessors (find then end then at, size then get(i), contains then insert) into one decision. That decision must hold one lock. Also flag any locked accessor that returns a reference, pointer or iterator into the guarded container, and any mutation made through such a returned reference after the lock is released.

## `tt-l1-poll`: Stale data-cache reads in remotely written L1 polls

On architectures where each RISC has a small non-coherent, write-through L1 data cache (Blackhole ERISC/BRISC/NCRISC/TRISC), `volatile` does not bypass the cache. Any CPU read of an L1 word that a different agent writes can keep returning an old cached copy. Other writers include the NoC, ethernet, fabric, the host and a sibling RISC. The recurring shapes:
- Hand-rolled spin loops (`while (*sem < v);`, relaxed atomic loads, `eth_*` or `ncrisc_dynamic_noc_*` predicates) with no invalidate in the loop body.
- Non-blocking predicate or state-machine helpers that do not invalidate, called repeatedly by a scheduler.
- An invalidate placed only on the success path or after the loop.
- Consumer reads of recycled CB slots after `cb_wait_front`, which does not invalidate.
- Barriers that compare a hardware status against the other RISC's counter held in L1.

The result is a hang (spinning on the stale word, or two RISCs disagreeing on a count), or lost performance when an unrelated later invalidate eventually refreshes the line. Because the data cache is now OFF by default and only opted into by dispatch, fabric mux and some fabric builds (compile-time flag), most remaining instances are latent. They come back when the cache is enabled via `set_l1_data_cache<true>` or the per-RISC enable env var.

**Checks**

- For every loop whose exit condition reads an L1 word another agent writes (NoC or fabric semaphore increment, ethernet send, host write, sibling RISC store or atomic), confirm the data cache is invalidated on EVERY iteration BEFORE the load: `do { invalidate_l1_cache(); } while (cond)`, or use a shared wait helper (noc_semaphore_wait/_min, eth_wait_*) that does. An invalidate only after success or only before the loop does not count, and `volatile` alone is not enough.
- For small non-blocking query helpers (return a bool or state from an L1 word) that a polling scheduler or state machine calls in a loop, check that the helper invalidates or that EVERY caller loop invalidates. The invalidate usually lives in the blocking wait-helpers of the same file and is missing from the non-blocking siblings.
- Compare each hand-rolled poll with the same file's own helper-based or atomic-acquire polls of the same semaphore. If two sites in one file poll the same word differently, that is the strongest signal.
- After cb_wait_front / a semaphore handshake, if a RISC CPU-reads data that another agent filled into a recycled CB slot or scratch buffer (indices, metadata, headers, counts), check that an invalidate or an invalidating barrier sits between the handshake and the loads. Otherwise the reader sees the slot's previous contents.
- In any kernel that calls set_l1_data_cache<true>() or has an opt-in cache define, enumerate every read of remotely written L1: credits, packet headers in receive buffers, connection and termination flags, other-RISC counters. Check each read one by one. Also check that a compile-time flag that removes the invalidations also turns the cache off, and that every early return or exit path restores set_l1_data_cache<false>.
- Barrier and flush paths that combine a hardware status with a counter the other RISC keeps in L1 (dynamic-NoC mode) must invalidate per iteration. Check the low-level inline-write, spoof-write and flush helpers too, not just the public barrier APIs.
- Separate L1 from MMIO. Stream registers and NIU status registers are uncached and need no invalidate, so an invalidate there is a fence or timing side effect, not the fix. Do not credit it as the fix, and do not flag its absence.
- Classify severity by what refreshes the line: a loop that spins only on the stale word is a hang, while a loop that another invalidating operation refreshes is a performance bug. State whether the site is latent (cache off by default) and which switch enables the cache.
- When auditing hardware-id loops next to these barriers (transaction ids), check that the range covers exactly 0..MAX_ID inclusive and that shared counters are drained and all RISCs synced before a reset.

## `test-blind-spot`: Tests that pass without checking the thing

In these bugs the test runs green but cannot fail for the regression it is named after. Five mechanisms recur. (1) The oracle is too weak for the output. PCC or correlation is used on exact integer, index or saturating ops, where it cannot see constant, shifted, clamped or sparse off-by-one outputs. The PCC helpers also replace inf/NaN with zero, so an output that is mostly non-finite compares as zeros against zeros. A one-element or constant output makes PCC undefined, and it falls back to default tolerances that do not suit the dtype. (2) The golden or the stimulus misses the real semantics or the real shape. The golden follows the docstring instead of the kernel's actual condition and ignores flags forwarded to the op. Input ranges never reach the clamp, bit-31 or 2^32 boundaries. Fixtures use a shape that is easy to generate rather than the production per-device shape. Multi-device tests compare only device 0. (3) Markers and guards drift. Non-strict xfails outlive their defect and XPASS forever. Skip guards use a proxy such as the arch name instead of the real precondition (dispatch mode, bank count), so a simulator or slow-dispatch CI lane crashes in setup. (4) Arch-gated helpers and parametrize lists do not apply to newer arches. A positive "if wormhole" check with a legacy else branch means a newer arch silently runs a config other than the one the test id claims, or never generates the case at all. (5) Test infrastructure hides failures. A threshold dict object shared across several arch keys lets one arch's overrides lower another's thresholds. A seeded input generator depends on thread count or pulls from unseeded OS randomness. A reference is computed and never asserted.

**Checks**

- Mutation check on the oracle. Replace the device output in your head with a constant, the clamp value, all zeros, or the input off by one on a few lanes. If the assertion still passes, the test is blind. This applies most to any PCC, corrcoef or allclose on int/uint/index outputs, which need exact (or ULP-bounded) equality.
- For every parametrized special input (divisor 0, log 0, overflow, INT_MIN/UINT_MAX), work out the golden. If it is mostly inf/NaN, confirm the comparison helper does not nan_to_num or mask non-finite values. Require exact checks on non-finite masks and signs, and flag tolerance asserts applied to boolean masks.
- List every kwarg the test forwards to the device op. Confirm the golden branches on each one that changes semantics. Derive the golden from the kernel's actual condition, not the op docstring.
- Check that generated inputs cross every boundary the op defines: below min, above max, the exact limits, +/-inf, and for 32-bit targets values at or above 2^31 and 2^32. Bounds dicts that cap 32-bit dtypes near 16-bit scale, and identities chosen to dodge a known kernel limitation, are blind spots unless a separate test pins that limitation.
- Enumerate xfail and skip markers, non-strict ones especially. Check CI history for whether each still fails. A permanent XPASS asserts nothing, so prefer strict=True or retire the marker. When retiring a marker or removing an import, grep the whole file on the merge target for remaining users.
- For multi-device and CCL tests: the input fixture must reproduce the production per-device shape and sharding (for example full-width partials, not slices). Every device shard must be compared against a golden indexed by its mesh coordinate, not just get_device_tensors(...)[0], even when the output is 'replicated'.
- Derive each test's runtime preconditions from the APIs it calls (fast vs slow dispatch for sub-device managers, device count, fabric, DRAM bank count). Check that the skip guard tests those preconditions directly, then cross-check every CI lane or SKU that runs the directory, including simulator and slow-dispatch lanes.
- Arch branches in test helpers and parametrize lists: a positive single-arch check with an else that falls back to a legacy config or drops a parameter means newer arches silently lose the case. Verify that the config handed to the op carries what the test id claims on every arch.
- If an output can be a single element or constant, PCC is undefined and falls back to allclose with default tolerances. Check those tolerances suit the dtype (block-float especially). When the same test file exists under unit_tests/ and nightly/, confirm a fix landed in both copies.
- Test-infra hygiene: per-arch or per-config tables must not reuse one mutable dict under several keys and then mutate it (use deepcopy). Seeded generators must be a pure function of (seed, shape), with no seed+thread_id, no hardware_concurrency()-derived chunking and no unseeded random_device/getrandom. Every computed reference must reach an assert.

## `tt-sfpu-const-clobber`: SFPU programmable constants unloaded or clobbered between ops

SFPU compute bodies read persistent programmable constant registers (vConstFloatPrgm0-2 / vConstIntPrgm0-2, i.e. LREG11-14), and only an init function is supposed to load them. The bug appears in three ways. (1) The init the compute API actually binds never loads them, because the init is empty, or a wrapper copied from another op points at another op's init (or one that doesn't exist), or the init's template flags pick a different coefficient set than the body uses. (2) An inline helper deep in the call graph writes one of those registers per call inside the tile loop and overwrites a constant another routine in the same op depends on, e.g. a sqrt seed written over the ln2 that the log uses. (3) A fused kernel runs op B without B's own init and relies on the side effect that op A's init happens to load the constants B needs. When A's init is rewritten, B silently runs on stale constants. The failure is wrong numbers or low PCC, not a crash, and a test that narrows the input range to make it pass can hide it.

**Checks**

- For every SFPU compute body, and every sfpi_inline/inline helper it calls transitively, list which programmable constant registers it reads and which it writes. Flag (a) any write outside an *_init function when some other routine reachable in the same op or the same fused tile loop reads that register, and (b) any read whose value is not loaded by an init on the op's actual init path.
- Follow the compute-API init wrapper (llk_math_eltwise_unary_sfpu_<op>_init / SFPU_UNARY_INIT_FN / *_tile_init) to the function it really calls. Confirm the function belongs to the same op, is non-empty, and uses the same template flags (approx, fp32-dest, fast/accurate) that select the coefficient set the body reads. Copy-pasted wrapper names and flag mismatches both count.
- In fused compute kernels (sdpa, softmax, layernorm, sampling, binary_ng with activations), list the SFPU ops each tile loop runs in order. Each op's own init, or an init explicitly documented to load the exact registers it reads, must run after the last init or per-call writer that could overwrite those registers. An init hoisted above a loop that alternates two ops sharing LREG11-14 is a finding unless every intervening body is shown not to write them.
- Treat comments like 'can omit X init because Y init already programs it' or 'exp_tile_init already sets ...' as findings to verify. Each one encodes a cross-op dependency that breaks silently when Y's init changes. Read Y's current init and every body in between.
- Look for ops that load their parameter into a programmable constant inside the compute call (not in init), e.g. unary max/min scalar, topk masks. Any other op sharing that tile loop and reading that register must re-init after it runs.
- When a test for an SFPU op narrows the input range or loosens PCC on one arch only, check whether the narrowing hides unloaded or clobbered constants on that arch.

## `tt-test-arch-split`: Tests hardcode one arch's grid, bank or L1 geometry

Tests and microbenchmarks take one architecture's device geometry and write it in as a literal: the DRAM bank count (12 on WH, 8 on BH), the extent of a shard grid, shard widths computed by dividing by a constant, L1 capacity, or a fixed L1 base address. Any other arch, or a harvested SKU (a BH p100a has 7 DRAM banks, not 8), then gets an invalid shard grid, a TT_FATAL, or a raw write past usable memory that hangs the device. Fixes that replace the literal with a device query often add an off-by-one, because CoreRange/CoreCoord ends are inclusive while grid_size(), dram_grid_size() and num_banks are counts. That extra core can stay silent until a later validation change turns it into a hard error. Per-arch parametrize tables also get rows copied from another arch (the BH row reusing the WH L1 value), and size gates compare against total capacity while ignoring the fixed offset the write starts at. Nightly-only tests also drift: they keep calling ops that moved namespace.

**Checks**

- Wherever a CoreRange or CoreCoord END is built from a device-reported count (dram_grid_size(), compute_with_storage_grid_size(), grid_size, num_banks, num_cores), check that it subtracts 1. Ends are inclusive and sizes are counts. Code that passes the count to a helper that takes a count (num_cores_to_corerangeset) is correct as it is.
- Flag literal core, bank or grid extents in test shard specs, especially DRAM-buffer ranges ending at (11,0) or (7,0) and shard widths written as W/12 or W/8. Each one must be derived from the device query, or the test must skip or gate when the device has fewer banks or cores (for example a check that grid.num_cores() <= dram_grid_size().x). Assume harvested SKUs exist: a BH part can have 7 banks.
- When a hardcoded value is replaced with a derived expression, evaluate the expression on every supported arch and SKU and confirm that it reproduces the old constant where the old constant was right (for example dram_grid_size().x - 1 == 11 on WH).
- For any test or benchmark that writes raw device memory at a fixed address, the size bound must be (usable region end - base address) for the current arch, taken from the HAL or device. A gate like `size < L1_size` that ignores the write base is a bug even when the current test vector happens to miss the gap.
- In per-arch parametrize tables (arch, L1_size, ...), flag rows whose values are identical to another arch's row. They were usually copied, and they should be HAL or device queries.
- Flag randomized or fixed target cores chosen with a literal bound (rand() % 8, core (7,7)). Check the bound against the device's actual worker grid on harvested or smaller parts.
- After an op moves namespace (for example under ttnn.experimental), grep nightly-only and model tests for stale call sites under the old name. Post-commit CI does not run them.

## `tt-test-param-drop`: Swept or model parameters never reach the op

A test names a parameter value in its ID, sweep vector or "reproduces model X" docstring, but that value never reaches the code under test. This happens in three ways. (1) A shared test-config object normalizes, promotes or clamps a swept field after parametrization, e.g. it forces dest_acc to Yes for exponent-B-input to Float16-output format pairs on non-Quasar arches. Two generated cases then build the same kernel. Results keyed on the post-normalization value collide and get averaged or deduplicated, and the ID advertises coverage that does not exist. (2) An op wrapper in a sweep harness accepts dtype/layout/memory_config but does not forward all of them. It may also pass optional arguments positionally to a binding whose signature has since changed to keyword-only or been reordered. Either way the op runs on its defaults while the golden assumes the swept value, which shows up as shape/dtype mismatches or silently unswept axes. (3) A model-derived unit test copies a model's op config through a shared helper that has no argument for some field the model sets, most often a memory-placement field like config_tensors_in_dram. The test then runs a different configuration, which fails or passes for the wrong reason.

**Checks**

- Wherever a test config constructor or helper rewrites a parametrized field (a `self.<param> = <literal>` under a condition, or clamp/promote/normalize logic), enumerate every parametrize/sweep that feeds that field. Check whether one generated case can be mapped onto another case's value. If it can, flag duplicate runs, test IDs naming a value that never executes, and result/perf keys built from the post-normalization value that collide. Compare the number of generated cases with the number of distinct result keys.
- For every op wrapper in a sweep or test harness, diff the parameters it receives (dtype, layout, input/output mem config, extra kwargs) against the arguments it actually forwards to the op. Flag any swept axis that is accepted but never forwarded, and any case where the input memory config is forwarded where the output one was meant.
- Flag calls that pass optional arguments positionally to a binding. Check each against the CURRENT binding signature for keyword-only or reordered parameters, and check that list-typed sweep params (dtype, layout) are indexed ([0]) rather than passed as whole lists.
- When a wrapper exists in both the legacy and the new harness (tt_lib_ops vs ttnn_ops, or old and new sweep frameworks), check that a param-forwarding fix reached both copies.
- For unit tests that claim to reproduce a model's op configuration, diff every config field the model sets (Conv2dConfig, compute kernel config, memory config) against what the test sets or forwards through its shared helper. A field the helper cannot accept is always dropped. Prioritize fields that change memory placement or residency: config tensors in DRAM, double-buffering, shard layout.
- Check that a validity filter guarding one sweep (e.g. a distinct-modes or valid-modes helper applied in perf tests) is also applied to the functional sweeps that cross the same axes.

**Seeds** (code shapes to hunt for)

## `other`: Accidental-correctness, degenerate-shape and unguarded-budget bugs

This class is a mixed bag, and most of its bugs follow one of four patterns. (1) Accidental correctness. The code uses a primitive that only matches the right one by chance: in this arch, mode or toolchain. Examples: a read barrier used to complete zero-fills, which only works where zero-fill is done as a read; a posted-writes flush after non-posted writes; a write barrier after async reads; a std:: symbol that arrives through an unrelated header; raw fixed-register SFPU instructions mixed with compiler-allocated vector variables; a bit-scan intrinsic applied to a value that may be zero; a cache flush that covers only the line holding the struct's first byte; a hardware-defective instruction that is still used on one arch. Any change to the arch, compiler or headers exposes the latent bug. (2) Degenerate-shape and index arithmetic. The code uses padded rank where logical rank is meant, so rank-1 tiled tensors grow an axis or read vec[1]. A scalar (1x1) matches a 'row broadcast' predicate. A +1 meant for a length gets copied into a 0-based position. A count gets rounded up to satisfy alignment and leaks into the logical shape. An operator-precedence or chained-comparison mistake (a<<16+b, a<b<c) goes unnoticed. A hardcoded CB 0 is passed where the caller's operand belongs. (3) Fixed budgets sized by hand with no check against the real region end. Examples: per-thread code regions, stack-local arrays of channel/queue state sized by compile-time maxima, per-object tables that reserve the worst case inline, queues placed at base + n*size that were only checked against total memory, and collectives that move every slot of a multi-slot cache. They overflow only at the largest configuration, which CI rarely builds. (4) Identity and ordering invariants. A cache hash leaves out a build-affecting field. A cache counts as hit when a directory exists, not when every artifact is present. A std::hash recurses into itself. An in-place update runs before the reads of arguments that may alias it. The accumulation order depends on how the work is split rather than on absolute element position. A RISC config store is not ordered against the Tensix instruction that consumes it.

**Checks**

- Barrier/flush kind must match the operation it drains, not what happens to work today: async reads need a read barrier before CB push/pop, semaphore signal or exit; async_write_zeros/fill_zeros_async need the zeros-specific barrier before the next NoC write on that RISC; the flush after writes whose posted/non-posted mode comes from a template flag must poll the matching counter (follow the flag into the helper); a local buffer that was the SOURCE of async writes must not be popped, refilled or overwritten (including the next loop iteration) until a writes-flushed/barrier on EVERY path. A drain present on only one branch of a loop is the tell.
- Copy drift after a fix: when a fix lands in a shared helper or one kernel variant, grep for inlined copies of the helper, sibling variants (dim-0 vs non-dim-0, line vs ring, fused vs non-fused, FSDP vs plain, per-arch and Quasar copies, models/ kernel_includes forks) and confirm each got the same change.
- Shape-driven host logic: derive dim/axis expansion, bounds checks and per-dim vectors from logical rank, never padded rank; any fixed index ([1], [rank-2]) into a rank-sized vector needs a rank>=2 guard or validation. Enumerate 1x1, 1xN, Nx1, rank-0, rank-1 against every shape predicate that routes to a different implementation and confirm each predicate matches exactly the class its name claims and that the fallback preserves the dtype's precision (fp32 through FPU loses bits without unpack-to-dest).
- Fixed-size regions and arrays: for code regions, stack locals in kernel_main, per-object tables in local memory and buffers placed at base+count*size, compute the footprint at the LARGEST supported config on the smallest-memory RISC and compare to the region END (not total memory). Require a static_assert/TT_FATAL that does this arithmetic, and a host-side check whose counting rule matches the device-side population rule exactly (device ASSERTs vanish in release).
- Every RISC MMIO store into unpacker/packer config (base addresses, formats, tile descriptors) must be ordered before its first Tensix consumer by a same-thread TRISC_CFG stall or RISC-blocking drain, including consumers inside a MOP/replay issued EARLIER and released by a later semaphore_post. Also check the WAR case: a context rewritten while queued instructions may still read it. NOP padding or 'unrelated work in between' does not count.
- Cache/identity keys: every build-affecting config field must appear in the kernel/program hash (diff the hash fields against the fields passed into build options, per arch); a persistent cache hit must test final artifacts written via temp+rename, not a directory's existence; std::hash specializations built on a reflection helper must hash fields/attribute_values(), not the object.
- In-place and aliasing: for any composite/op writing a caller-supplied tensor in place (running stats, optimizer state, preallocated output), order all in-place writes after every read of other arguments, or reject aliasing by buffer address.
- Reduction determinism: which agent/direction/order accumulates each element must be a function of the element's absolute index, not of remaining-count halving, per-iteration toggles, num_workers/num_links or per-worker start; reader, writer and compute must share one mapping.
- Toolchain-luck hazards: grep bit-scan intrinsics (__builtin_clz/ctz/ffs) and prove nonzero BEFORE the call (a power-of-two check accepts 0); flag unparenthesized shift with +/- and relational chains; in JIT device code require direct headers for every std:: symbol; in SFPU code with live sfpi vectors, every hard-coded LREG touched by raw TTI must be declared in_use.
- Test-tree integrity after moves/renames: AST-resolve every `from tests.X import Y` / `from models.X import Y` repo-wide (sweeps/perf/nightly lanes break silently); for cached artifacts confirm the loader regenerates on miss rather than depending on another entry point.
