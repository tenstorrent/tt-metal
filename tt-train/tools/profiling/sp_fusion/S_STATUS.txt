DESIGN (tt-train only, uncommitted; ops/distributed/sp_overlap.hpp has the full contract)
* AutoContext: open_device(..., num_command_queues=2); enable_ccl_sub_device(columns, rows) = sub-device manager
  {compute rectangle, CCL rows/columns} + MeshDevice::set_compute_with_storage_grid_size_override(compute rect);
  backward depth counter (Tensor::backward brackets its loop); backward-end hooks (run when the OUTERMOST backward has
  run its last node) and teardown hooks (reset_graph / close_device). close_device also drops CCLResources (its pool
  count is per queue) and the sub-device state, so a test can reopen with 1 queue.
* CCLResources: per-command-queue pools of 8 rotating semaphore sets, allocated on the full grid.
* ttnn_fixed::distributed: a collective runs on the sub-device of the queue it is issued on (queue 1 -> CCL sub-device,
  queue 0 -> compute, never mixed: a sub-device is owned by the queue that last launched on it); all_gather takes a
  persistent output, reduce_scatter takes its buffers (reduce_scatter_buffers() allocates {interm, output(, penult)} in
  the op's own layout: ring via reduce_scatter_minimal_async_create_intermediate_buffer, line = [2B,1,S,K] tiled);
  on queue 1 the buffers are mandatory (the op's own temporaries are freed by the host under the running collective).
  Per-site policy: set_sp_linear_impl(both sites) / set_sp_linear_backward_impl(backward only), SPLinearSite passed by
  the backward closures; sp_linear_matmul() exposes the Composed matmul.
* SPOverlap (ops/distributed/sp_overlap.{hpp,cpp}): issue() = compute drain (record q0 on the compute sub-device, wait
  on q1) -> collective under with_command_queue_id(1) -> event on q1; wait() = q0 waits, buffers retained until 2 later
  collectives were waited (host allocation is not device-ordered across queues); defer()/drain_one()/drain_all() for
  weight gradients; backward-end hook drains; teardown drops. Schedule in the Composed backward: column linear = dgrad
  matmul (q0) -> RS (q1) -> drain ONE deferred wgrad (q0) -> defer own wgrad -> q0 waits RS; row linear = AG (q1) ->
  drain one -> q0 waits AG -> dgrad -> defer own wgrad. So per block: w2-AG hides behind the previous block's qkv
  wgrad, gate_up-RS behind w2's, out_proj-AG behind gate_up's, qkv-RS behind out_proj's. Same ops, other order =>
  bitwise vs one queue on the same grid. NoComm backward goes through the same path with empty outputs (measures the
  machinery alone). Modes: sp_overlap off | split (CCL region reserved, one queue = the reference) | backward.
* Config/CLI: device_config sp_overlap, sp_ccl_rows (1), sp_ccl_columns (0), sp_linear_backward_impl (same); train.py
  opens 2 queues + splits when sp_overlap != off. Python: ttml.ops.distributed.set_sp_overlap / get_sp_overlap /
  set_sp_linear_backward_impl / get_sp_linear_backward_impl / sp_overlap_stats; AutoContext.enable_ccl_sub_device etc.
  conftest: TTML_SP_OVERLAP=backward [TTML_SP_CCL=rows=1] runs any tp_mesh module under the overlap.
