01

Oversized DEST footprints can make the device loop non-terminating

Missing slot validation combines with a zero-valued block clamp.

High

Problem

The CRTP bases validate their DEST slots, but hand-written elements such as Where, LgammaAdjusted, Lerp, SnakeBeta, Addcmul, and Addcdiv only compute a lane_width. They do not assert that the referenced slots fit DEST_AUTO_LIMIT.

Failure path

  • An element reports lane_width > DEST_AUTO_LIMIT.
  • chain_max_block_value() performs integer division and returns zero.
  • The runtime clamp assigns block_size = 0.
  • The inner walk uses wt_base += block_size, so it never advances.
Recommended fix

Add a central compile-time assertion that every chain has a positive chain_max_block_v and that its lane footprint fits DEST. Keep per-element assertions for precise diagnostics, but do not rely on every future element remembering them. 

// Valid type syntax, invalid physical footprint:
Where<DF, Dst::D0, Dst::D1, Dst::D2, Dst::D8>

max_block = DEST_AUTO_LIMIT / lane_width; // 8 / 9 == 0
block_size = max_block;                   // becomes 0

for (...; wt_base < Wt; wt_base += block_size) {
    // never advances
}

02

BulkDrain bypasses duplicate upfront-reader validation

Two definitions of “upfront” disagree inside the same planner.

High

Problem

BulkDrain is defined as an upfront wait followed by per-tile pops. The execution path recognizes the upfront wait, but the metadata used by ct_reader_collide() omits BulkDrain from is_upfront.

Impact

Two reader elements can therefore share the same CB under BulkDrain. Each emits a full-window wait and each pops one page per iteration. The second element reads from the already-advanced front, and the chain attempts to consume twice the supplied number of pages. Depending on producer timing, this is a wrong-result or hang.

Recommended fix

Eliminate the separate hand-maintained is_upfront list. Derive collision behavior directly from wait_policy and pop_policy, which are the actual execution facts. 

BulkDrain = {
    WaitPolicy::Upfront,
    PopPolicy::PerTile
};

// Execution:
waits_upfront() == true

// Collision planner:
is_upfront == false  // BulkDrain omitted

UnaryBcast accepts strided addressing but cannot receive a stride

The public configuration compiles and silently produces repeated tile indices.

High

Problem

A UnaryBcast input configured with TileOffset::Strided and CallerManaged passes the current validation. Unlike the other reader types, however, UnaryBcastImpl has no constructor taking StridedTileRange. The inherited row_stride remains zero.

Resulting indices

  • Block indexing becomes base + row * 0 + column, repeating each row.
  • Col indexing becomes base + row * 0, always selecting the base tile.
  • No compile-time or runtime error signals that the requested addressing was ignored.
Recommended fix

Add the missing StridedTileRange constructor and the same explicit Strided/CallerManaged assertion used by the other readers, or reject Strided for UnaryBcast until it is implemented. 

static_assert(
    Offset == TileOffset::Unset ||
    is_legal_input_lifecycle_with_base(Policy));

// Only these exist:
UnaryBcastImpl();
UnaryBcastImpl(uint32_t base);

// But exec consumes row_stride, which stays 0:
idx<IndexMode, Offset>(..., row_stride);

04

Pack collision detection checks the source slot, not the output address

Different DEST slots do not make same-CB output windows distinct.

Medium-high

Problem

Two PackTile elements are considered colliding only when both their CB and DEST slot match. For walk-addressed lifecycles, the output index is based on the chain position and optional tile offset—not the source DEST slot.

Risky cases

  • Bulk: both writers reserve the same CB upfront and pack the same index range.
  • CallerManaged: both write the caller-owned window at identical indices.
  • ReserveNonePushEnd: both can overwrite the same pre-reserved pages.

L1/DEST accumulation may intentionally combine writes, but ordinary output lifecycles need a different collision rule.

Recommended fix

Model collisions using CB identity plus output addressing/lifecycle. Conservatively reject same-CB writers for walk-addressed ordinary outputs, with narrowly defined exceptions for supported accumulation modes. 

// Current rule:
same_pack_cb && same_pack_dst_slot

// But for Bulk/CallerManaged:
out_idx = base + i_flat;

// Two different source slots still write
// the same (CB, out_idx).

05

Init hoisting assumes type equality implies equal runtime initialization

That assumption is false for seeded, instance-stateful operations.

Medium

Problem

Hoist uniformity compares operation types using std::is_same_v. Yet the design explicitly permits instance methods for initialization, and both Dropout and RandTile seed hardware state from runtime object members.

Failure scenario

Two same-type Dropout<Dst::D0> elements with different seeds are considered uniform. Both init calls run before any compute, so the second seed is active when the first operation executes. RandTile is excluded from the SFPU-uniformity predicate but is still selected by the broader DEST-only hoist condition, allowing the same last-init-wins behavior.

Recommended fix

Introduce an explicit element trait such as boot_hoistable_init, defaulting conservatively. Seeded or otherwise stateful elements should initialize immediately before their execution stage unless their state equivalence is provable. 

// Planner considers only type identity:
std::is_same_v<Rep, E>

// But init reads instance state:
void Dropout::init() const {
    dropout_kernel_init(seed);
}

// Hoist fold runs every selected init before walk.

06

DestReuseBinary::DstOut is exposed but never used for output

The public API promises a two-slot operation over an intrinsically in-place LLK.

Resolved

Problem

The alias accepts separate DstIn and DstOut template arguments. The underlying binary_dest_reuse_tiles operation reads and writes the same DEST index, and exec() passes only DstIn. DstOut affects nothing except the calculated lane width.

Impact

A caller using different input and output slots receives a successful compilation but the value remains in DstIn. A later operation or PackTile<..., DstOut> reads stale data.

Implemented

DstOut was removed from the public alias and packed configuration. One DstSlot now identifies the slot that is both read and overwritten.

Original reviewed code
DestReuseBinary<Input, Op, Reuse, DstIn, DstOut>

// Execution only uses DstIn:
binary_dest_reuse_tiles(
    Cb, in_idx, to_u32(DstIn) + slot_offset);

// DstOut appears only in lane_width.

07

Exp exposes an approximation parameter that deliberately does nothing

The signature suggests control that the implementation does not provide.

Resolved

Problem

Exp<approx, fast, Slot> exposes two Approx parameters, but the second one is intentionally ignored. Neighboring wrappers use similarly named parameters to control generated LLK behavior, so callers have little reason to expect this one to be inert.

API cost

  • Call sites such as Exp<Fast, Fast> imply two independent choices.
  • Different instantiations generate different C++ types despite identical behavior.
  • Type-based hoisting can treat behaviorally identical operations as non-uniform.
Implemented

The inert fast parameter was removed. The canonical signature is now Exp<approx, Slot>, and all migrated call sites use it.

Original reviewed code
template <Approx approx,
          Approx fast,  // accepted
          Dst Slot>
struct Exp {
    // only approx is forwarded
    exp_tile<approx == Approx::Fast>(...);
};

Follow-up

The requested changes remove the composite input/output lifecycle API, derive ownership from the policies returned by each element’s input()/output() metadata, and bring UnaryBcast back onto the canonical LLK path.

Pair-wrapper predicates such as input_policy_is/output_policy_is were also removed; branches compare the fields directly.
