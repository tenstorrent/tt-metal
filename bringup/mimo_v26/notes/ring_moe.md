# Ring decode MoE (moe agent): how to use it, what it costs, what was verified

Default is `MIMO_MOE_DECODE=ring` (since this flip; `MIMO_MOE_DECODE=unified` is the fallback; ring needs the integ library and falls back to unified automatically if headroom < 1 GiB per chip); code `tt/moe_ring.py`, hook in `tt/layer.py moe_decode` (live-mask path). `MIMO_ROUTER=fast` is the default for the ring path (the unified path keeps its own default).
* Pipeline: router_select -> dead-slot routing (weight 0, balanced) -> all_to_all_dispatch_metadata -> moe_compute (ring matmul, fused combine; bfp8 weights, HiFi3 + fp32 accumulate) -> tilize + fast_reduce
  (score-weighted sum over k) -> reduce_scatter over the mesh columns -> all_gather (full hidden, replicated). Input `x [1,1,T,4096]` bf16 tile per device (T = tokens of a mesh row, 1..32; T = 8U for the verify path), output same shape.
* Library: `artifacts/moe_C_<commit>/lib` (moe_compute env knobs patched: MOE_COMPUTE_BFP8_WEIGHTS=1, MOE_COMPUTE_FP32_ACC=1, MOE_COMPUTE_FIDELITY=HiFi3; moe_ring.py sets these defaults at import). LoFi/HiFi2 are NOT accurate (alpha/rel L2).
* Weights: a SECOND copy, ring layout, bfp8, ~214 MB per chip per layer (27 MB/bank): ~10.15 GiB per chip at 47 layers next to the unified prefill copy. Built from the same bf16-dequantised experts, cached on NFS
  `/mnt/tt-data/ssinghal/mimo-wcache/ring_L<L>/` (build once: `pytest -s tests/build_ring_cache.py`, ~60 s/layer cold, 1-2 s warm). Per-(mesh, T) scratch buffers and semaphores are shared by all layers (L1 ~13 KB/bank per T).
* Measured (4x8, real layers 1/5/16, alternating traced, ms/layer unified -> ring): T=1 0.842 -> 0.416; 2 1.083 -> 0.615; 4 1.241 -> 0.789; 8 1.450 -> 0.964; 16 1.608 -> 1.153; 32 1.693 -> 1.188.
  Numerics vs the gated unified path: alpha 0.994-1.0003, rel L2 0.0046-0.0064, PCC >= 0.99999. Gates: 48-layer deep trace 1000 replays no hang at T=1/8/32; bitwise glitch stress 90000 layer-calls, 0 glitches.
* Full model (48 layers, paired unified -> ring step ms): U=1 71.2 -> 47.9; U=8 90.0 -> 66.3; U=32 105.8 -> 86.9. GSM8K n=128 110/128, all completions token-identical across runs. test_verify_decode with ring (4 and 48 layers, U=1,2,4): argmax 100% exact vs sequential, features bit-identical, verify repeat bit-identical.
* Automatic fallback: `moe_ring.ring_enabled(mesh)` enables ring only if free DRAM minus the ring copy (MIMO_RING_LAYERS, default 47) >= 1 GiB per chip (MIMO_RING_MIN_HEADROOM_GIB; MIMO_RING_FORCE=1 overrides); else unified.
* Device-resident mask (no host updates in the trace): `mask_from_flags(flags)` (device tensor, last dim = slots <= 32, any dtype/layout, nonzero = live) or `mask_from_count(count)` ([1,1,1,1] live count per mesh row) return the [1,1,64,1] bf16 tile mask; both inherited by MiMoRingMoEDecode. Host API (make_mask_host/alloc_mask/update_mask) remains as fallback. Forward is bit-identical with device-derived vs host mask, eager and traced (tests/test_moe_mask_device.py).
* Library for everyone: `artifacts/integ_e4ff6c137d3/lib` (C++ identical to merged 20dff715ad7).
* Open: B>=64 with 64k ISL (see DRAM cells), accurate-fidelity ring kernel.

## ONE weight copy (MIMO_UNI_RING=1, default): the unified prefill op reads the ring weights in place
* The unified prefill op `unified_routed_expert_moe` has a RING_WEIGHTS mode (port of DSV4 bd3c0c7bc5d, `unified_routed_expert_ffn/device/kernels/weight_runs.hpp` RingWeights, program factory, device-op validation): selected by the weight tensors (rank-6 DRAM HEIGHT_SHARDED bfp8 TILE = the moe_compute `w0_w1` [8,1,E,G,R*32,128] / `w2` [8,1,E,GD,RD*32,128]; the same tensor is passed EPC times in the gate/up/down lists). The model builds NO per-expert copy then: `tt/layer.py _moe_weights` builds `RingExpertWeights` at LOAD time (NFS cache ring_L<L>) and shares them with `MiMoRingMoEDecode` (`layer.ring_ex`).
* Policy (`tt/moe_prefill.py uni_ring_active`): MIMO_UNI_RING=1 (default) when the expert op is `unified`, the mapped _ttnncpp has the RING_WEIGHTS mode (scan of /proc/self/maps for the validation string) and the chip has 8 live DRAM banks (`effective_matmul_ring_size`); otherwise one log line '[moe_prefill] one-copy ring weights OFF ...' and the per-expert copy. MIMO_UNI_RING=0 restores two copies. With one copy ring_enabled() needs no headroom (the weights are resident); MIMO_MOE_DECODE=unified still works (the unified decode MoE reads the ring weights too).
* MiMo shapes: gate/up K=4096 (128 tile rows, R=133), N=2048 (64 tiles = 8 per ring core, G=4 groups of 2); down K=2048 (64 -> RD=70), N=4096 (128 tiles = 16 per ring core = 4 groups of 4); w2 K rows are stored per 8-row chunk (= N tiles per ring core), rotated per hidden-core: logical chunk ch of core c at stored chunk (c-ch) mod 8. The factory infers N=64 uniquely from the stored shapes.
* DIFFERENCE TO DSV4: the DSV4 port tied the op's N columns to the 8 ring cores (GRID_X=8, 64 cores) and the experts op got 33% slower (MiMo measured: experts op 2.22 -> 2.95 ms at N=2048/row, TTFT +7-11%; GRID_Y=9 no gain, GRID_Y=10 hangs as in DSV4; set-state/with-state tile reads no gain: compute-bound on per-core N, 8 vs 6 gate tiles). This port addresses every N tile individually (`RingWeights::read_gu` maps global tile n -> ring core n/8, group, half; `read_d` reads the 4-tile groups of the core's hidden slice), so the op keeps the SAME 11 x 8 grid, blocking and numerics as the copy: output BIT-IDENTICAL to the per-expert copy (all layers/N/decode tested) and experts op 2.21 vs 2.20 ms. Needs per-core down N % 4 == 0 and N_down % 4 == 0 (TT_FATAL).
* Memory: free DRAM per chip after the first decode grows by ~9.7 GiB (see LOG); the ring decode now fits at B=32/64k.
