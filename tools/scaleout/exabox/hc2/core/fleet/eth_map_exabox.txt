# fleet/eth_map_exabox.txt: the in-box ETH cabling of an exabox node (bh-glx-*), same format as
# fleet/eth_map.txt (tray asic chan; asic 1-8 = bus low nibble, tray 1-4 = bus 0x00/0x40/0xC0/0x80). Built from UMD's link
# map of one exabox galaxy (tests/fleet/disc_exabox_b02u08_pre.json, md5 ad8c68b4d801b0367da95053937d7306, 2026-10-24): every link with
# both ends on the box. A second node's run of the same day shows the same set of linked and unlinked ports
# 0-7 under C3 (only ports 0,1 of asic 4 unlinked); its peers were not recorded. fleet_py.py ethlinks and ethback read
# this file instead of eth_map.txt where ethext's platform is exabox (FLEET_PLATFORM=exabox, else a bh-glx-* hostname
# not in fleet/eth_peers.txt). 36 of the quad map's 120 links differ here, and 40 of this map's 124 links are not in
# the quad map (e.g. 04:00.0 ports 4,5 go to
# 44:00.0 ports 4,5, not c4; ports 0,1 of asic 1/2 link tray 1 <-> 3 and 2 <-> 4), and the quad's QSFP ports (asic 1, 5
# ports 2, 3) are in-box links here, so there are no Q lines.
# L: an in-box link, channels 0-7 (124 links). Channels 8, 9 are not listed (not judged by C3, as on quad hosts), though
# on exabox 16 of them are in-box links too: 03/04 tray 1 <-> 3, 07/08 tray 1 <-> 2, 03/04 tray 2 <-> 4, 07/08 tray 3 <-> 4.
# X exabox tray asic chan: a port that is not an in-box link (ports 0,1 of asic 4, trays 1-4).
# W exabox axis tray asic chan: a wrap port of the 4x8 mesh, i.e. an L link that
# closes a ring. axis 8: ch 2,3 of asic 1, 5 (tray 1 <-> 2, 3 <-> 4); axis 4: ch 0,1 of asic 1, 2 (tray 1 <-> 3, 2 <-> 4) (the
# axis-4 wraps on ch 8,9 are not judged, as above). A box cabled without one axis's wraps (partial torus) shows every
# port of that axis down: when all of them are down at pre and still down after C2, ethlinks says ETH NOT-CABLED (INFO)
# instead of FAIL; a group only partly down stays FAIL. fl_bb_step runs the bus-bar CCL linear unless every wrap is up.
