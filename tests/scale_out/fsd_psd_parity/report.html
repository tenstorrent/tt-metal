Provenance, so nothing is overclaimed. PSD = committed golden (tt-run live discovery). FSD = generated here by generate_rank_bindings with TT_METAL_FACTORY_SYSTEM_DESCRIPTOR_PATH set (offline build, #52859), rebuilt binary, logs prove the offline path. FM = FM's builder; since #52859 ports that exact builder, the FM column equals the FSD column by construction. The only piece still pending is a number pulled from the live ttfm-ui service (that host does not resolve from this sandbox) — recipe in the README. The offline route emits no TT_VISIBLE_DEVICES (host-local, live-cluster-only); the goldens carry none either.

Why they agree

All three routes converge on the same PhysicalSystemDescriptor type and feed the same map_multi_mesh_to_physical mapper. Identical topology ⇒ identical placement. PSD builds that descriptor from live discovery; FSD/FM build it offline from the factory descriptor.
