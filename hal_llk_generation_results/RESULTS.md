## 6. Limits (read before using the numbers)

- Static counts are counts in the compiled code, not executed instructions. TT = stores proven to reach the Tensix instruction buffer on every path (static analysis); 'unresolved' stores could not be settled, so TT is an estimate. TTI and code size are the main static measures; TT is secondary.
- The default test build compiles LLK asserts (`-DENABLE_LLK_ASSERT`) unless `TT_LLK_DISABLE_ASSERTS=1` (tt-llk `tests/python_tests/helpers/test_config.py`, ~line 553). Section 2 removes that effect from both sides.
- The perf test does not check results. Only 4 of the 16 Elwadd perf variants have formats / dest_acc that the functional test (and therefore the agent) verified.
- One kernel (eltwise add). 7a–7e are 5 repeats with `prompt-run6b.md`; 8a–8e are 5 repeats with `prompt-run6b-cfgcost.md` (adds a section on the instruction cost of per-tile code). No statistical test is applied between runs.
- `harness_logs/SUMMARY.txt` of 7a–7e quotes metrics.py v1 numbers (first full pass, pytest runs); section 5 uses v2 (`metrics_v2.json`; `harness_logs/metrics.md` is its rendering), so iteration numbers can differ.
- The harness of runs 7a–8a wrote its outputs in Serbian (team convention at the time). Their files in `runs/run*/harness_logs/` are English copies; `harness_logs/translation_check.txt` records for every file that its numbers are identical to the Serbian original and that no Serbian words are left. Runs 8b–8e used the English harness; their files are copied as they are.
