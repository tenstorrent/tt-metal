## What the columns mean

- **Tests passed:** `test_eltwise_binary -k add` must give 1660 passed, 0 failed in every check: original (harness baseline), HAL after a card reset, original right after HAL without reset (harness), and the 4 postcheck steps (reset→HAL, no reset→original, no reset→HAL, reset→HAL). Sources: `harness_logs/SUMMARY.txt`, `postcheck/checks_*.txt`.
- **Code size, TTI, TT:** average per build over the 10 builds of `-k add`, unpack + math + pack, both sides compiled without LLK asserts (`TT_LLK_DISABLE_ASSERTS=1`). Source: `static_counts/assert_off/tt_tti_counts.md`. TTI = Tensix instructions embedded in the code; TT = Tensix instructions built at run time and written to the instruction buffer (static estimate). Counts in the compiled code, not executed instructions.
- **Cycles:** LLK perf test `perf_eltwise_binary.py -k Elwadd`, L1→L1 cycles per tile, asserts off, original and HAL alternating on the same board; median of 3 runs per variant, then median of the per-variant HAL ÷ original ratios over 16 variants. Source: `perf/perf_summary_hal.json`. HAL was faster than the original in 0 of 80 measured variants. Per run, HAL ÷ original for the whole kernel (L1→L1) and for each thread measured alone (unpack / math / pack isolate): 8a 1.32 (1.18 / 0.99 / 1.46); 8b 3.49 (1.18 / 1.00 / 4.37); 8c 1.42 (1.00 / 0.99 / 1.50); 8d 1.32 (0.98 / 0.99 / 1.46); 8e 1.45 (1.67 / 0.99 / 1.46).

## Limits

- One kernel (eltwise add) on one board type.
- The perf test does not check results. Only 4 of its 16 Elwadd variants use formats that the functional test (and therefore the agent) verified.
- TT is an estimate: some stores to the instruction buffer could not be resolved statically (column 'unresolved' in `tt_tti_counts.md`).
- 8a ran with the harness version that writes Serbian messages, 8b–8e with the English one (`scripts/harness/VERSIONS.md`). The agent-visible difference is the language of five spec marker comments; the deny list was adapted to the reorganised folders on bh-30.
- Runs 7a–7e did the same task with an earlier prompt (without the section on instruction cost of per-tile code); they are in `RESULTS.md`.
