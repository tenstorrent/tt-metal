## Summary

The four Wormhole packers can run in a fast rhythm or in a slow rhythm with a DEST bank conflict in every tile. Both rhythms repeat exactly, so a pack loop keeps the rhythm it starts in until something pushes one packer by a cycle. The slow rhythm costs 1 to 10 cycles per tile (up to about 28% of a PACK_ISOLATE window). This is the mechanism behind most of the "two values" (bistability) results on Wormhole. The things that push the packers are separate issues (see the umbrella).

## Hardware

The packers read DEST through one crossbar with 4 banks. The bank is bits 1:0 of the DEST row address. Each bank serves one packer per cycle, in fixed priority (packer 0 first, not round robin).

Each packer reads two times per row, so it asks for banks 0, 0, 1, 1, 2, 2, 3, 3. The four packers run 2 cycles apart and ask for four different banks. If packer 0 loses one cycle (for example, its L1 write is refused on the shared L1 write path), it lands on packer 1's bank, packer 1 is refused, and the refusal moves down to packer 3. In the slow rhythm this happens once per tile, and it repeats every tile.

## Evidence

Versim and the card give the same cycle counts:

| Case | Card | Versim | Packer 3 refused (Versim) |
|---|---|---|---|
| matmul 1×3 PACK_ISOLATE, 0 / +1 nop | 107,622 / 110,705 | 107,622 / 110,705 | 3,101 / 12,297 |
| eltwise_binary pack pad 1 / pad 0 | 4,669 / 4,741 | 4,669 / 4,741 | 209 / 281 |
| repro, no L1 read / one math L1 read | 9,070 / 9,323 | 9,070 / 9,323 | 266 / 1,005 |
| PR head, math_matmul PACK_ISOLATE, 0 / +4 B per function | 71,873 / 92,263 | 71,873 / 92,263 | 1,714 / 14,666 (per 60k cycles) |

Proof that the rhythm is the cause (card): `TTI_STALLWAIT(p_stall::STALL_PACK, p_stall::PACK)` every N tiles makes all four packers start the tile together. For N = 1 to 64 it removes every effect above (matmul +1 nop: 24 of 41 configs moved → 0; K probe flat; eltwise pads flat). It costs +2–6% at N = 32 and up to +57% at N = 1, so it is a proof, not a fix. A resync on the first tile only does not remove it when the trigger comes later (see {{T2}}: the pack core's code fetch in tile 1).

Versim with resync every tile: 168,995 cycles for both builds; card 168,993 / 168,991.

Blackhole has one packer (`PACK = PACK0`) and shows none of this (0 points move with nops at TILE_LOOP).

## Where it shows

Both problems. Every run type that packs on Wormhole. Production kernels have the same exposure.

## Fix status in #58068

#58068 does not change the rhythm itself. It removes or fixes the pushes: L1 traffic during the window, start timing, code fetch. The drain at each section (73e829efa99) was the direct fix and was removed again in c16630eb8a0 (up to 60% slower).

## Open

- L1_TO_L1 (the merge gate) runs all three threads together, so any timing change can pick the rhythm. Averaging over a few start offsets (#59199) is one option.
- Hardware: round-robin arbitration in the DEST read crossbar should stop a lag from repeating.
