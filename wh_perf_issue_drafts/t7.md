## Summary

On an earlier version of #58068 (17 commits, 75669afc17a, warm-up pass off), the first kernel of a test depended on the kernel that ran before it on the core. The value of a test then depended on the test order and on how pytest workers split the tests. At #58068 head this no longer happens, with or without the warm-up pass, so the warm-up pass (b7747df1b7d, 75669afc17a) can be removed.

## Evidence (card)

eltwise_binary X = Float16_b → Float16, Elwmul, HiFi2, dest_acc Yes, L1_TO_L1 TILE_LOOP:

| What ran before X | 17-commit #58068 | PR head, barrier off | PR head |
|---|---|---|---|
| a kernel that ran only L1_TO_L1 | 12,347 | 12,345 | 12,345 |
| a full test (its last kernel is L1_CONGESTION) | 10,573 | 12,344 | 12,345 |

The b7747df1b7d text names the cause: arbiters with round-robin pointers that only a chip reset clears. The barrier of 054096d8efa makes BRISC read L1 64 times before each release, so that every L1 bank arbiter last granted BRISC. But the effect is also gone at PR head with the barrier off; we did not find which change removes it there.

PR head, warm-up pass off, 323 test cases from all Wormhole perf modules (1,346 values): the same values as with the warm-up, in forward and in reverse test order (0 values move by more than 0.5%).

## Versim

The simulator version of the 17-commit tree did not finish in Versim: four runs stopped and never completed (three at exactly the same point in the waveform, whichever test was running). At PR head the effect is gone, so there is nothing to simulate there. This issue rests on the card.

## Fix status in #58068

Fixed at PR head. The warm-up pass costs about 5% run time and is not needed any more.
