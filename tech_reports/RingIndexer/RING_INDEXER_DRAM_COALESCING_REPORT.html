Engineering report · August 2026

Making ring all-gather feed compute faster

The final change coalesces Ring Attention All-Gather traffic by giving each direct worker a disjoint set of destination DRAM banks. Pages that are far apart in logical interleaved order become contiguous inside one physical bank, so the workers can move larger packets, amortize synchronization, and keep more DRAM banks in flight.

Original bottleneck

The ring was delivering data, but DRAM traffic was too fragmented

Interleaved tensors distribute consecutive logical pages across DRAM banks. Walking those pages in logical order is convenient, but it produces small or scattered transactions and frequent synchronization in the AG reader/writer pipeline. The first ring iterations are especially visible because compute cannot hide their readiness latency yet.

Before

Logical-order traversal

page 0→bank 0→page 1→bank 1
  • Bank changes from page to page.
  • Forwarded reads have little physical contiguity.
  • Small packets expose barrier and Fabric-header overhead.
  • Compute sees more bubbles while waiting for usable K data.
After

Bank-owned traversal

worker 0→banks 0,2,…→contiguous packets
  • Each direct worker owns non-overlapping bank classes.
  • Pages separated by the DRAM-bank count are contiguous inside a bank.
  • Four packets are issued before the read barrier.
  • Full packets rotate across the worker's banks.
Final architecture

Coalesce at the DRAM boundary; keep the ring topology stable

Partition ownership

Each link worker receives a disjoint residue class of destination banks. Reader and writer derive the same ownership.

Build bank slices

For each owned bank, calculate the first valid page and page count inside the current gathered prefix.

Prefetch packets

Issue four reads per prefetch window, rotating across banks. Forwarded pages use physically contiguous NOC reads inside a bank.

Write and signal

The writer drains the identical schedule to interleaved output and preserves the existing consumer readiness protocol.

Local input

Correct over convenient

Local input pages are not guaranteed physically contiguous under destination-bank ownership, so the reader uses accessor-based per-page reads.

Forwarded output

Exploit physical layout

In interleaved DRAM, logical pages b, b+B, b+2B are consecutive within bank b, enabling large contiguous NOC reads.

Buffering

Deadlock-safe depth

The circular buffer holds 2 × prefetch_packets × pages_per_packet: two prefetch windows with four packets each.

The speedup is not from adding cores. Mux cores and variable worker counts were removed. This isolates the win to better DRAM transactions, bank parallelism, and less synchronization overhead.
With a 14 KiB Fabric payload limit, each 1088-byte BFP8 tile page yields floor(14336 / 1088) = 13 pages per packet: 14144 bytes of data and 192 bytes left over. The remainder is expected because a page is the indivisible transport unit.

The same BankOwnedPacketSchedule drives the reader and writer. Owning packet size inside the schedule prevents the two sides from silently disagreeing about packet boundaries or circular-buffer counts.

Program-cache contract

One strategy across runtime sequence lengths

Trace replay requires 55K, 512K, and intermediate valid prefixes to hit the same cached program when tensor capacity is unchanged. Selecting the strategy from runtime kv_len would violate that contract. The final heuristic therefore uses only compile-time/configured properties.

What may change on a cache hit

Acceptance

Symmetric ±2%

Both regressions and implausibly large deviations fail. The targets sit at the center of the accepted range.

Why separate measurement windows?
Captured replays reuse a runtime identifier. Combining repetitions into one profiler window can merge records and select the maximum rather than produce independent samples. A profiled warm-up also prevents an asynchronous stale record from leaking into the measured callback. These changes stabilized the 55K gate without loosening its margin.
Decision history

What was tried, learned, and deliberately removed

The branch passed through several latency-hiding ideas. They were useful experiments, but the final patch keeps only the mechanism that improved all measured Ring Indexer cases while preserving a fixed trace topology.

Experiment only

Phased slab readiness and P=1 / KC=7

The first approach tried to expose partial slabs sooner and alternate compute between halves arriving from opposite directions. The P=1/KC=7 point was an earlier branch baseline, not a final knob or the mainline comparison.

Removed

Mux cores and expanded worker topologies

Muxing helped a narrow large-ring case by decoupling routing and sometimes enabling more workers, but it was not a universal win: the 6-worker + 2-mux setup regressed 512K in ablation and the 55K benefit was unclear. A worker cannot simply double as a persistent mux because the roles have different lifetimes and resources.

Rejected variants

Extra packet and prefetch schemes

Staged prefetch, static packet layouts, grouped Fabric sends, and other packet-count variants were swept. Unstable or negative variants were dropped instead of accumulating workload-specific gates.

Kept

Bank-owned DRAM traversal

This was the general win: it improved SP4 and SP8 at both 55K and 512K without changing worker count or selecting from runtime length.

Integrated from latest main

Correct even-ring split forwarding

The branch rebased over mainline's restored diametric split and second-half wait. Bank ownership was extended to split directions. Ring Indexer disables the split because its consumer lacks that second-half wait; Ring Joint enables it only for compatible dense consumers.

Final cleanup

Smaller, named, reviewable interfaces

Magic runtime slots became named constants, worker placement is derived from link and direction, duplicated helpers were consolidated, packet size has one owner, and anonymous namespaces use the repository's jumbo-build wrapper.

Protocol safety

Consumer owns split compatibility

The AG helper accepts a named split-forwarding capability. A fused consumer may enable it only if it implements the diametric shard's second-half wait.

Boundaries and follow-up

What this optimization does not claim

Not a universal CCL rewrite

The fast path currently targets Blackhole, sequence-dimension gathers, and aligned interleaved DRAM output. Unsupported cases retain the existing path.

Not dynamic device selection

The device does not choose between strategies from runtime KV length. Instead, one capacity-based host choice deliberately covers every length in the trace class.

Not the final SP=32 topology

Galaxy's planned 32-device slab sharding and larger all-gather may change traffic balance. Mux/core topology should be reevaluated after that path lands.

  • The 20 MiB threshold is an empirical, trace-stable amortization boundary—not a universal hardware law.
  • Every bank-owned worker rotates full packets across its banks; only the unsupported legacy scatter path retains its two-page cap.
  • The LoudBox targets cover Ring Indexer because that is where the 14 KiB end-to-end improvement is locally established. QuietBox needs native CI measurement, and other ops retain their targets unless their own measured gates justify a change.
  • FPU utilization differs between native QuietBox/SP4 and LoudBox/SP8 paths because topology and critical-path behavior differ; core count alone does not determine the result.
