## Findings (written by hand after the run; the sections above are the tools/pipeline_overheads.py output)
- Blocking send (push + lease_out) is 0.6-1.2 ms per chunk at every W: 0.7/0.8/0.9 ms at W=2048/4096/8192, against
  Pavlo's 7.5/14.5/28.5 ms fit. The sender is not held for the transfer. Host gap outside the timed pieces is
  0.3-0.6 ms per stage.
- Hop (sender push return -> receiver has the input, when the receiver is already waiting) is 4.9-7.8 / 9.5-10.8 /
  18.7-20.9 ms at W=2048/4096/8192, about 2.4 ms per 1k tokens. This matches Pavlo's "send" magnitude, but it is
  latency on an idle receiver, not time the sender is busy.
- The old SP2 Part B cold gap (-12.4%: open loop 15.7k vs 17.9k predicted from a 228 ms standalone sparse stage) is
  NOT the blocking send (0.3% of a stage). It is stage compute: in the pipeline the sparse stages take 247/261/247 ms
  (sync, W=4096 cold), which alone gives 15.7k tok/s. The un-synced lease pipeline runs at 15.2k steady (cycle 269 ms,
  -3.1% vs the sync compute bound); the rest of that -3% is input wait / handoff on the bottleneck stage (sync cycle
  272 = compute 261 + recv 9.7). Producer-side tok/s (push wall + ack drain) reads 3-4% above the runner steady
  rate because layer acks are host-side and the stream is short.
- 1d fabric is not an option for the 4-rank runner: PREFILL_FABRIC_MODE=1d dies at startup with
  TT_FATAL control_plane.cpp:859 `!is_1d_fabric || !is_multi_mesh` (d_w4096_sync1_fab1d). All sessions use 2d, as
  E7 / SP2 Part B did.
- PREFILL_D2D_SHARE_FABRIC_LINKS=0 (OWN, async handoff) deadlocks on the first chunk: stage 0 computes and pushes
  chunk 0, stage 1 never receives it, no further PP_TIMING line on any rank; watchdog HANG after 300 s. Reproduced
  once (pcc_own_w4096_sync0), not retried further. No timing or correctness numbers for OWN mode.
- KV read-back check (merged mock migration, producer PREFILL_PRODUCER_CHECK_PCC=1 with the four rank device maps
  merged) works on the 4-rank runner. Lease-mode control: both slots identical, K 0.9999 -> 0.965, V 0.9997 -> 0.885
  decaying smoothly over layers 0-59 with no step at the stage boundaries (15/30/45), so the handoff is clean; the
  0.93 default threshold is too tight for 60 layers with this config (bf4 experts). The un-synced lease timing
  sessions themselves are timing-only.
