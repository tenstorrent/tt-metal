Implementation overview · prefill only

GLM-5.2 KV memory now grows with active context.

A capacity-sized physical pool replaces the model-side assumption that every user owns a maximum-context cache. Indexer and sparse attention resolve logical tokens through a compact page table.

03 · Runtime lifecycle

Allocation is explicit, coordinated, and reusable.

1 · Admit chunkAligned 5K start + exact actual end
2 · Reserve IDAtomically take one free physical bundle
3 · Sync tablePublish the mapping to a persistent device tensor
4 · Run modelPass slot, layer, table, and valid end
5 · ReleaseInvalidate first, then return the bundle
  • Exact prefix continuity is checked
  • Primary and index caches share ownership
  • Exhaustion is reported explicitly
  • Rollback protects allocation state
There is currently no eviction policy. The pool provides allocation and release primitives; scheduling policy remains outside this change.
04 · Cache writers

New tokens land directly in their physical bundle.

The existing padded KV update operation gained a paged mode. Its writer reads the compact mapping, folds physical bundle and layer into the pool batch, and writes the current SP-local slab.

05 · Index selection

Keep queries in place; read paged K directly.

Reusable score + TopK composition

Every SP/TP query shard remains local. The page-aware reader translates each logical K tile, reads it directly from its position-dependent SP owner, and scores one bounded 5,120-token bundle. Existing large-index TopK folds those bundle results without gathering Q, weights, K, or owner candidates.

No SP gatherExisting TopKLogical UINT32 IDs5,120-token windows
Important: returned indices stay in natural logical-token space. Physical bundle IDs never leak into sparse attention’s model-visible contract.
