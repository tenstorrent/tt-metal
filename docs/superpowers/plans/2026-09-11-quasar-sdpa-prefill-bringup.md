**MULTI-CHUNK fix (79473ada4b3): correction-path `pack_reconfig_out(exp_max_diff)`.** After the emulator passed seq128 (single-chunk), seq512 (multi-chunk) failed PCC ~0.03. Root cause: the correction path (`if processed_k_chunks>0`) called `sub_exp_block(...,dfb_exp_max_diff,...)` — which packs its EMD result via a BARE `pack_tile` with no internal `pack_reconfig_out` — while the Quasar sticky-dest packer was still latched to `alias_mm2_cur_out` from the QK@V matmul (the line above only reconfigures the UNPACKers). So EMD was written to the OUT_IM ring, never to `dfb_exp_max_diff`; every downstream correction consumer (fma sum merge, MM2 rescale) read garbage, compounding per chunk. seq128 (no correction) was untouched → passed. Fix = one line `pack_reconfig_out(dfb_exp_max_diff)` before the `sub_exp_block`, mirroring the sdpa_decode flash preamble. WH-gated no-op (WH pack_tile re-derives dest from the DFB, so WH was always green — couldn't catch it). Two red herrings on the way, both reverted/inert: a 2-deep-vs-3-deep fma gate (16701638de3, REVERTED — WH ran the 3-deep path green on multi-chunk, disproving its premise) and an MM2 fused→two-op rescale (bc45e530f1b, proven bit-identical/inert — EMD was garbage upstream of it). ## The DFB-merge finding (the big lesson)
`kt` pushed the STANDARD non-streaming path to 9 compute self-loop DFBs > Quasar's cap of 8. Final = merge sum → 8: `qk_im, kt, out_im_A, out_im_B, max_A, max_B, sum_A, exp_max_diff`.

- **DO NOT merge MAX**: the multi-chunk flash's `reduce_c<MAX>(do_eltwise=true)` with `prev_dfb==out_dfb` on the merged ring breaks it — it copies prev into DST via a transpose reconfig (`sdpa_reduce_copy_tile_to_dst_init_short`) then packs cur back onto the *same* buffer, a `prev==out` interaction the ring-pointer model doesn't capture. **NOT curable by the sum rebase discipline** — the peer proved it: applying the full rebase (pop-both + move_block on correction chunks, rd_ptr==base each chunk) to decode's max-merge still failed the multi-chunk flash (PCC 0.06), while the tree path passed (its max eltwise runs in DST via `correction_block`, front-reads only, no cur offset-read). So the earlier "offset-read ring-wrap" framing was a red herring for max. Sum dodges this entirely (its `reduce_c<SUM>` runs `do_eltwise=false`). Multi-chunk-broken (WH PCC 0.955; peer decode 0.748/0.06). Committed max-merge `bf7466bffa0` was **REVERTED**; sum-merge alone reaches 8 so max stays split.
- **Merge SUM** (discipline matches peer's decode fix): merged `sum_A` keeps prev@ring-front `[0,Sq)`; the producer (`sub_exp_block_bcast_cols_inplace`, out-of-order `pack_tile<true>` = reserve-relative → no offset) appends cur `[Sq,2Sq)`. The correction's `mul_tiles_bcast_cols_inplace(prev)`+`add_block_inplace` pair → one `fma_block_merged_sum` (`cur + prev·emd`, re-bases running sum to front; no `std::swap`, no extra `move_block`). Gated by path not arch: `merged_sum=(sdpa_type==STANDARD)&&!use_attention_sink`; factory `merge_sum=!use_streaming_compute&&!use_attention_sink`. JOINT/RING/streaming/sink keep two sum DFBs; **max stays separate on every path**.
- **Two prefill gotchas vs decode's fma** (decode: column-reduced + bf16 sums → hits neither): (a) prefill sums are FULL tiles at correction (final `matmul_reduce` after the K-loop), emd is a column vector → prev·emd MUST be `mul_tiles_bcast_cols` (plain `mul_tiles` pulls emd's junk cols into the later reduce → catastrophic). (b) **DST overflow**: WH runs `fp32_dest_acc_en=true` → `dst_size=4` (factory:411); a fma holding `num_tiles+1`=5 DST tiles overflows → silent corruption. **Fix = DST-frugal fma**: two single-tile L1-accum passes (`reserved[i]=cur[i]`; `reserved[i]+=prev[i]·bcast(emd[i])`) on a **3-deep** `sum_A` (`prev|cur|running`) + `move_block` running→front. 1 DST tile/op; correct on WH-fp32 (4) and Quasar (fp32-off → 8).
- **LESSON:** both ops' committed merges shipped multi-chunk-broken behind weak tests (WH used the separate path via an ARCH_QUASAR gate; Quasar walled on the sim before compute). **Any DFB-merge must run + validate on WH multi-chunk (seq≥256), never Quasar-gated-only.**
