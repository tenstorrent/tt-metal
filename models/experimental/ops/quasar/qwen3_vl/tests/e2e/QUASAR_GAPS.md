# Qwen3-VL e2e: Quasar gaps and other failures

Gaps that still affect the Qwen3-VL e2e bring-up on Quasar. Section 1 is the main output: ttnn ops/paths that work on
WH/BH but not on Quasar. Gaps fixed upstream, gaps this model does not hit, and base ops that the e2e routes to their
`ttnn.experimental.quasar` ports (`op_overrides.py`) are not listed.

Status values: `open` (not fixed in ttnn), `worked-around` (harness/model avoids it; still open in ttnn),
`fixed` (fix landed; workaround removed), `unverified` (suspected from precedent, not yet reproduced on Quasar).

## 1b. Small-grid limits (any arch; block the 2-core emulator grid)

| # | Op / config | Failure on a 2x1 grid | Workaround in this branch | Status |
|---|---|---|---|---|
| G1 | `ttnn.experimental.nlp_concat_heads_decode` | `work_split.cpp:99: Target number of cores 32 is greater than total number of available cores 2` — one head per core | workaround `concat_heads_decode_small_grid`: device-only deshard → untilize → reshape → pad → tilize (same approach as llama32_1b_quasar `_install_quasar_concat_heads_grid_agnostic`) | worked-around |
| G2 | `tt_transformers` prefill matmul program configs sized for 8x8 (QKV, WO, FF1/3, FF2) | `compute_with_storage_grid_size (8, 8) must fit within device grid (2, 1)`; then `per_core_M (8) exceeds Mt (4)`; then L1 overflow (1.9 MB > 1.5 MB) | `fit_matmul_config`: grid clipped, per-core blocks from real M/N tiles, `in0_block_w=1`, `out_block_h/w` blocking | worked-around (config, not op) |
| G3 | LM head width-sharded input/output configs | prefill: sharded input clashes with matmul CBs in L1; `Unsupported op for output sharding` with interleaved input | LM-head input (prefill) and outputs DRAM interleaved on grids < 8x8 | worked-around (config) |
| G4 | decode linears fed by L1 width-sharded norm outputs with no program config (DRAM-sharded configs dropped, Q2) | `Statically allocated dataflow buffers ... clash with L1 buffers on core range [0-0 - 1-0]` (decode FF1 2560 → 9728) | workaround `small_grid_unshard_linear`: unshard input to DRAM, matmul to DRAM, reshard to the requested sharded output (completing a missing shard spec, which ttnn's default matmul cannot do: `Unsupported op for output sharding`) | worked-around (config) |
| G5 | `ttnn.untilize` (multicore, interleaved) of the decode logits `[1,1,32,151936]` | `Statically allocated dataflow buffers ... clash with L1 buffers on core range [0-0 - 0-0]`: the L1 check (`is_enough_space`) sizes CBs for a full 4748-tile row without counting live L1 buffers | workaround `small_grid_untilize_single_core`: `use_multicore=False` (single-core factory caps CBs at half of L1) | worked-around (config) |

## 3. Bugs found in the Quasar model copy (fixed here)

| # | Bug | Symptom | Fix |
|---|---|---|---|
| M1 | `tt/vision_mlp.py` cached weight and bias under the same file name; `as_tensor` keys only on name+dtype+layout, so with bf16 weights the bias load returned the weight | `binary_ng ... Invalid subtile broadcast type` in fc1 (bias was `[1024, 4096]`) | `.weight` / `.bias` cache suffixes (as `patch_merger.py` already does) |
| M2 | Vision patches were always padded to the next multiple of 2048, plus a whole extra 2048 when already aligned (e.g. 2048 → 4096). Only partly over-padding: up to 1024 patches a multiple of 128 suffices, but above 1024 the MLP/WO reshape into 1024-row chunks and above 2048 the QKV matmul into 2048-row chunks, so 2048-multiples are required there | 256 tiny patches padded to 2048 (8x vision work) | `vision_padded_seq_len`: multiple of 128 up to 1024, of 2048 above (demo 11008 → 12288 unchanged) |
| M3 | `DropInVisionTransformer.forward[_single_user]` slices `[:, 0:1, :, :out_hidden]` + reshapes the merger/deepstack outputs, then deallocates the sources. On a 1-device mesh the full-range slice and reshape are views of the same buffer (verified: identical `buffer_address`), so the returned tensors read freed memory (same family as the existing `_mesh_partition_and_free` fix) | deepstack embeddings garbage (PCC 0.27, 10x too small) once the next allocation reused the buffer → `text.layer1` PCC 0.83; image embeddings survived only by read order | `_free_unless_aliased`: free the source only if the view does not share its buffer |
| M4 | `models/tt_transformers` `ModelArgs.find_prefill_grid` returns `(rows, cols)` but every consumer (`matmul_config`, `MinimalMatmulConfig`, `VISION_WO_PREFILL_PROGCFG`) reads it as `(x, y)`; invisible on the square 8x8 grid (shared code, not fixed there) | on a 2x1 grid: `compute_with_storage_grid_size (1, 2) must fit within device grid (2, 1)` in vision WO | `_QuasarArgsMixin.find_prefill_grid` returns `(x, y)` |
| M5 | harness: `run_craq.sh` / `run_emu.sh` did not pass `--qwen-quasar-config`. The Quasar args classes still applied (`model_args_classes` falls back to `is_quasar()`), but the runner's text `dtype` and the cache key follow the flag | prefill LM head weights were bfloat8_b on Quasar: `TT_FATAL ... program_spec.cpp:2287: DFB 'in1' has data format 'Bfp8_b' which is not supported on architecture quasar` | both scripts pass the flag; the test fails at start on a Quasar device without it |
