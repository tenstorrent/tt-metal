## Context

Spatial Cross Attention prepares both `key` and `value` in the layout expected by deformable attention. Deformable attention samples only `value`, so preparing `key` is unnecessary device work.

Prototype profiling shows that deleting this dead path reduces layer kernel time by 4.0% without changing output.

## Problem

- [SCA permutes and reshapes `key` before calling deformable attention](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L251-L255).
- [`TTMSDeformableAttention.forward` has no `key` parameter](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_ms_deformable_attention.py#L171-L181), so `key` is accepted through `**kwargs` and never read.
- [The encoder defaults `value` to `key`](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L186-L194), causing the same camera tensor to be permuted twice.

## Proposed direction

- Remove the unused `key` permute and reshape from SCA.
- Derive the spatial length from `value` so `key` is not needed by this path.
- Check other tensor-valued `**kwargs` pass-throughs for similarly unused preparation.

## Acceptance criteria

- [ ] SCA does not dispatch a permute or reshape for an unused `key`.
- [ ] The profile shows a net reduction in permute time and total layer kernel time.
- [ ] Operation removal does not introduce a replacement conversion elsewhere.
- [ ] Existing SCA, MSDA, layer, and encoder PCC suites pass at their configured thresholds, including PCC >= 0.997 for the base encoder.
