## Context

L1 can reduce DRAM traffic only when an operand fits in available on-chip memory and is reused enough to repay the placement cost. BEVFormer's largest SCA tensors do not fit in usable L1, and fused MSDA reads each operand once per call, so the expected opportunity is small.

## Problem

- Current profiles do not provide a complete size, buffer-type, reuse, and bandwidth inventory for hot operands.
- The [multi-level SCA value path](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_ms_deformable_attention.py#L70-L82) operates on a camera-feature tensor that is too large for broad L1 placement.
- Smaller tensors, such as [SCA rebatch buffers](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L188-L199) and [BEV reference points](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L155-L158), may fit, but copying a single-use operand into L1 can cost more than reading it from DRAM once.

## Proposed direction

- Record logical and padded byte size, current placement, access count, and consumer for each hot operand.
- Discard operands that do not fit safely alongside kernel buffers and allocator overhead.
- Keep only operands with demonstrated reuse or a consumer shown to be DRAM-bandwidth-bound.
- Benchmark the complete path, including any DRAM-to-L1 copy, against the unchanged DRAM path.

## Acceptance criteria

- [ ] The investigation publishes an operand inventory with size, placement, reuse, and fit decision.
- [ ] Each benchmark includes copy cost and reports end-to-end consumer time, not only kernel time after placement.
- [ ] Any accepted L1 placement shows a repeatable net percentage win without memory-allocation regressions.
- [ ] If no operand produces a net win, the measured no-win result and size constraints are documented.
- [ ] Any production change passes existing layer and encoder PCC thresholds, including PCC >= 0.997 for the base encoder.
