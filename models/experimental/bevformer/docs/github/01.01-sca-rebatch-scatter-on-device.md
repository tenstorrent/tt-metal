## Context

Spatial Cross Attention keeps only the BEV queries visible to each camera. This filtering and the later scatter-back are performed in Torch on the host, forcing large query and reference tensors across the device boundary.

## Problem

- [Per-camera gather loops convert query, reference points, and rebatch buffers to Torch](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L202-L230).
- [Scatter-back converts the attention output to host, updates slots, and uploads it again](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L295-L310).
- Gap attribution in the baseline profile is noisy, but the prototype removes the large tensor transfers and reduces same-harness layer wall time by 76%. This percentage is a prototype result, not the current implementation.

## Proposed direction

- Build compact per-camera row indices from `bev_mask`.
- Use `ttnn.embedding` for row gathers to avoid broadcasting gather indices across the embedding dimension.
- Use `ttnn.scatter_add` for device-side accumulation back into BEV slots.
- Cover empty-camera and multi-batch cases explicitly because index counts differ per batch and camera.

## Acceptance criteria

- [ ] Query/reference rebatch and slot accumulation execute without converting those tensors to Torch.
- [ ] Outputs match the existing Torch path for regular, empty-camera, and `batch_size > 1` inputs.
- [ ] Existing SCA, layer, and encoder PCC suites pass at their configured thresholds, including PCC >= 0.997 for the base configurations.
- [ ] A same-configuration profile reports wall time, device time, host gap, and transfer-count changes.
- [ ] Wall-time results use repeated measured iterations so queue-entry cost is not presented as steady-state host work.
