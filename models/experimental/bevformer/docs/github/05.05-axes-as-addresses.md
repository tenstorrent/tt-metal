## Context

The fused op's contract is expressed in axes, so every axis it names must exist as a real dimension. BEVFormer reshapes, permutes, untilizes and slices its native tensors into that shape on every call, and #55200 owns removing that.

A profiling branch found a route past it that beat both of #55200's: **stop moving the axis and make it an address.** Widen the operand and let the reader reach head `h` at a byte offset inside the row it already reads, so the head-major tensor is never produced.

That is also the argument against a fused head-reshape op: it still has to *write* 92.6 MB and read it back. The permute ran at 14 GB/s because both its pages were 64 bytes, not because there were four calls.

Applied across grid, value and attn, layout plumbing went **60.5 to 15.4 ms**, the op paying under 1.5 ms total for offset reads. N150 figures from `ctr-ikasic/bev_former_kernel_optimizations` — evidence, not a Blackhole result.

## Problem

- Producing the contract tensors is the layout cost; a head permute rewrites the full 92 MB `value` tensor purely to reorder it.
- Narrow trailing dimensions make it worse twice over: a ROW_MAJOR page is the last dimension rounded up to the 32-byte DRAM alignment, so a 2-wide tensor spends 32 bytes per 4 bytes of data; and a `(4, 4)` trailing pair pads to a full tile, 64x.

## Proposed direction

Four additive op-contract extensions, one per child issue, each keeping the current form working: fold the grid's point axis into its page; address the value head behind a `num_heads` argument; address the attn level run behind `num_points`/`point_offset`; pack head and level into a rank-3 grid.

Two rules belong to the shared contract, both learned expensively on the profiling branch:

- **A NoC source offset must be 32-byte aligned.** Where it is not, the reader rounds down to the boundary, indexes from there, carries the lead-in in scratch, and clamps at the page end.
- **An offset belongs to the input that packs the axis, never to the call.** Applied to an unpacked operand it reads past the page end — which did not fail a test, it hung the kernel and took the chip off the PCIe bus.

## Sequencing

- **#55200** keeps what this cannot reach: the `value` untilize, genuinely bandwidth-bound movement, and the output pack. Its specialized-preparation-op route should be re-priced against this, not pursued alongside it.
- **#55201** wants a contract change to the same op. One upstream conversation, two asks.

## Acceptance criteria

- [ ] Each child change is additive; the existing operand form still runs, selected by shape or by an argument default.
- [ ] `models/experimental/vadv2` is unaffected, verified by running its tests.
- [ ] Every packed path has unit-test coverage against the equivalent permuted form of the same data, including misaligned offsets and the unpacked-operand-with-offset case that hung the device.
- [ ] Layout-preparation device time is reported per child change against the preceding configuration.
- [ ] BEVFormer MSDA/TSA/SCA/layer/encoder PCC suites pass at their configured thresholds, including PCC >= 0.997 for the base encoder.
- [ ] Blackhole figures are measured directly; N150 numbers are not carried over as results.
