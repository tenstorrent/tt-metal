## Context

The encoder uses several tensors whose values depend only on model configuration, BEV grid shape, or other inputs shared by all encoder layers. Recreating and uploading those tensors in every layer or attention call repeats the same setup work.

## Problem

- [`reference_points_3d` is regenerated for every encoder forward](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L420-L432), although it is determined by BEV shape, batch size, point-cloud range, and pillar configuration.
- [Each layer extracts and uploads the same 2D BEV reference points](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L155-L158).
- [The same BEV shape tensor is recreated inside every layer iteration](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L476-L483).
- [TSA creates and uploads `level_start_index=[0]` when it is not provided](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_temporal_self_attention.py#L157-L164).
- [MSDA uploads the same spatial-shape values during each call](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_ms_deformable_attention.py#L282-L284).

## Proposed direction

- Cache `reference_points_3d` by BEV shape, batch size, point-cloud range, and pillar configuration.
- Create and upload 2D BEV reference points once per encoder forward, then pass the same device tensor to every layer.
- Create BEV shape metadata once before the layer loop.
- Create constant TSA metadata during module initialization.
- Cache MSDA's device representation of spatial shapes by their values and reuse it across calls.
- Rebuild a cached tensor when any input that determines its value, shape, dtype, or device changes.

## Acceptance criteria

- [ ] Every cached tensor documents which inputs determine its value and when it must be rebuilt.
- [ ] Profiling confirms that each tensor is constructed or uploaded only once per required lifetime, rather than once per layer or attention call.
- [ ] Different BEV shapes, batch sizes, dtypes, and devices select the correct cached value or trigger a rebuild.
- [ ] Cache memory growth is bounded and reported.
- [ ] Existing TSA, SCA, point-sampling, layer, and encoder tests pass at their configured PCC thresholds, including PCC >= 0.997 for the base encoder.
- [ ] Before/after profiles report device-operation count, host gap, wall time, and persistent memory use.
