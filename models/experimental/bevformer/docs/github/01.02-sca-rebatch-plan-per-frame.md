## Context

All encoder layers process the same camera visibility mask and projected reference points for a frame. The corresponding SCA indices, lengths, and reference-point rebatch are derived inside each layer call.

## Problem

- [bev_mask readback, max_len, camera indices, and helper tensors are rebuilt inside each SCA call](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L152-L170), six times per frame.
- [Reference-point rebatching is repeated inside each layer](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L194-L230) even though it does not depend on the layer's query.
- Repeating the plan adds host work and prevents the encoder loop from becoming a clean device-execution region.

## Proposed direction

- Introduce a frame-level rebatch plan [immediately after point sampling and before the layer loop](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L464-L497).
- Store camera query IDs, common lengths, scatter indices, contributor counts, and rebatched reference points in the plan.
- Reuse the plan in every layer; keep only the query gather and attention result accumulation layer-dependent.

## Acceptance criteria

- [ ] Frame-invariant planning and reference-point rebatching run once per encoder forward.
- [ ] Every layer consumes the same plan without changing SCA semantics.
- [ ] Existing SCA, layer, and encoder PCC suites pass at their configured thresholds, including PCC >= 0.997 for the base encoder.
- [ ] Encoder-level profiling demonstrates reduced repeated host work using the same input and configuration.
