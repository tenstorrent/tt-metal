## Context

Fusing the MSDA sample-weight-reduce chain can remove many surrounding kernels without guaranteeing that the fused sampling kernel itself is efficient.

After applying the fused integration and the data-movement prototypes, fused MSDA accounts for 59.9% of the resulting layer kernel time. This percentage describes the prototype branch, not the current implementation. The fused operation is approximately 45% slower than bare `grid_sample` for the same sampled points, although deleting its surrounding stack, multiply, and reduction path still produces a net win.

## Problem

- [BEVFormer's current path uses `grid_sample` rather than `ttnn.experimental.multi_scale_deformable_attn`](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_ms_deformable_attention.py#L78-L124), so fused-op behavior at model shapes is not covered by this model.
- [The fused op requires specific ROW_MAJOR, INTERLEAVED shapes and `D % 16 == 0`](https://github.com/tenstorrent/tt-metal/blob/main/ttnn/cpp/ttnn/operations/experimental/multi_scale_deformable_attn/device/multi_scale_deformable_attn_device_operation.cpp#L11-L79).
- Kernel cost must be separated from the larger benefit of deleting concat, reshape, multiply, and reduction work.

## Proposed direction

- Build a standalone benchmark at TSA and SCA per-level shapes, including `N=48, Q=2496, P=4, D=32`.
- Compare fused MSDA with equivalent bare grid sampling and with the complete decomposed path.
- Compare four single-level SCA calls with one multi-level call over the same sampled points to establish the value of ticket `05.03`.
- Break down fixed launch/packing overhead versus work that scales with `N*Q`.
- If the gap reproduces, localize it to an op-level optimization and report it with a minimal reproducer.

## Acceptance criteria

- [ ] The benchmark reports fused, bare-sampling, and complete-path device time over representative shapes.
- [ ] The benchmark separately reports the percentage difference between four single-level calls and one equivalent multi-level call.
- [ ] Results include warm-up, repeated samples, variance, device/configuration, and exact input layouts.
- [ ] Any proposed kernel change passes the fused-op unit tests and BEVFormer MSDA/layer/encoder PCC thresholds, including PCC >= 0.997 for the base encoder.
- [ ] The issue concludes with a measured op-level next step or evidence that no upstream change is needed.
