## Context

SCA sizes its per-camera rebatch buffers from the largest number of visible BEV queries in the current frame. This data-dependent `max_len` changes with camera projection and prevents reuse of one fixed execution shape.

The direct host-work opportunity is less than 1% of prototype layer kernel time. The primary value is a shape that remains stable across trace replays, not a material eager-mode speedup. These measurements describe the prototype path, not the current implementation.

## Problem

- [`max_len` is derived from the device-resident `bev_mask`](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L154-L164) and [defines the shape of the rebatched query and reference-point tensors](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L188-L199). TTNN needs this value on the host before allocating these tensors and dispatching shape-dependent operations, so obtaining it requires a device-to-host read and queue synchronization.
- A worst-case bound reserves and processes unnecessary padding on most frames. A smaller statistical bound may not fit all visible queries, requiring some queries to be dropped and changing model output.

## Proposed direction

- After [`bev_mask` is created](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L464-L470), use TTNN reductions to count visible queries per camera and calculate `max_len` on device, instead of copying the full mask to host for Torch processing.
- Cache a per-rig high-water mark that grows when a larger value is observed and never shrinks.
- Use ticket #55190 to validate initialization, reuse, monotonic growth, and reallocation with deterministic synthetic frame sequences.
- Using a representative frame sequence for each supported camera rig, record `max_len` and the high-water mark per frame. If no representative dataset is available, leave stabilization and steady-state cost measurements blocked.
- Record when a larger high-water mark changes the rebatch tensor shapes. The follow-up ticket #55210 will use this signal to discard a trace captured for the old shapes and capture a new one.
- Do not claim that the high-water mark removes synchronization: Python still needs a scalar result before it can choose or resize host-managed buffers.

## Acceptance criteria

- [ ] Device and host reductions over the same `bev_mask` produce exactly the same integer `max_len`.
- [ ] No frame allocates less space than its observed visibility count.
- [ ] Synthetic sequences verify monotonic growth, shape reuse, and reallocation when `max_len` exceeds the cached mark.
- [ ] With representative data, per-rig stabilization, memory use, and steady-state device cost are reported; otherwise this measurement is explicitly marked as blocked.
- [ ] Existing SCA, layer, and encoder PCC suites pass at their configured thresholds, including PCC >= 0.997 for the base encoder.
