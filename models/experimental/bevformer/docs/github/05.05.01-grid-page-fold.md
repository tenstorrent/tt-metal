## Context

The fused op takes the grid as `(N, Q*P, 1, 2)`. A ROW_MAJOR page is the last dimension, allocated rounded up to the 32-byte DRAM alignment, so a 2-wide grid spends 32 bytes per 4 bytes of data:

```
(N, Q*P, 1, 2)   page  4 B -> 32 B allocated   8x
(N, Q, 1, P*2)   page 16 B -> 32 B allocated   2x, and a quarter of the pages
```

The SCA grid is 3.83 M points: at one point per page that is **122 MB of DRAM for 7.67 MB of data**, with P four-byte NoC reads per query. Folded, it is 30.6 MB and one read.

Profiling branch, N150: −12.9 ms kernel, both 4-byte-page reshapes gone, and the op itself −1.8 ms from issuing a quarter as many reads. Evidence, not a Blackhole result.

## Problem

- [The grid reaches the op at width 2](https://github.com/tenstorrent/tt-metal/blob/main/ttnn/cpp/ttnn/operations/experimental/multi_scale_deformable_attn/device/multi_scale_deformable_attn_device_operation.cpp#L27-L55), so the 4-byte page is written no matter which op writes it.
- Sorting layout ops by effective bandwidth sorts them by page size, not tensor size: the two slowest move the least data, at 2.1 and 1.5 GB/s against a 288 GB/s roof.
- A Python-side rewrite cannot fix this — the page width is set by the contract. An earlier attempt to drop the 6-D reshape for a column-range slice correctly measured as a wash.

## Proposed direction

- Accept `(N, Q, 1, P*2)` alongside the existing `(N, Q*P, 1, 2)`, taking any divisor of `P` per page.
- Derive points-per-page host-side from the grid's last dimension and pass it to the reader as a compile-time argument, so the existing form compiles to today's behaviour.
- Stop spelling `sampling_grids` out into six dimensions on the BEVFormer side.

## Acceptance criteria

- [ ] Both grid forms are accepted; the existing one is selected by shape and behaves as before.
- [ ] A page width not dividing `P` is rejected with a clear error.
- [ ] Unit tests cover points-per-page 1, 2 and 4 against at least two values of `P`.
- [ ] `models/experimental/vadv2` is unaffected, verified by running its tests.
- [ ] The profile shows the 4-byte-page grid reshapes gone, with page size and effective bandwidth reported before and after.
- [ ] BEVFormer MSDA/TSA/SCA/layer/encoder PCC suites pass at their configured thresholds, including PCC >= 0.997 for the base encoder.
