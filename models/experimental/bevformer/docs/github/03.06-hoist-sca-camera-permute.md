## Context

Every encoder layer receives the same camera feature tensor. SCA converts that tensor from camera-first to batch-first layout inside each layer, so a six-layer encoder repeats the same device data movement six times.

The current prototype profile identifies this as the largest remaining model-side operation outside fused MSDA.

## Problem

- [SCA permutes `value` from camera-first to batch-first layout during every call](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_spatial_cross_attention.py#L251-L255).
- [The encoder passes the same `value` through every layer without modifying it](https://github.com/tenstorrent/tt-metal/blob/main/models/experimental/bevformer/tt/tt_encoder.py#L476-L497).
- A one-layer benchmark pays the permute once before and after hoisting, so it cannot measure the encoder-level benefit.

## Proposed direction

- Permute camera features once before entering the encoder layer loop.
- Pass SCA a value tensor that is already batch-first.
- Derive the spatial length from `value` after the unused `key` path is removed.
- If practical, update the upstream producer to emit the required layout directly and remove the permute instead of only hoisting it.

## Acceptance criteria

- [ ] A six-layer encoder dispatches the camera-layout permute at most once per forward.
- [ ] Every layer consumes the same preformatted value tensor without copying it.
- [ ] End-to-end encoder profiling reports the percentage wall-time change; the layer harness is explicitly excluded from the performance claim.
- [ ] The profile confirms that no equivalent conversion was introduced at each SCA call.
- [ ] Existing SCA, layer, and encoder PCC suites pass at their configured thresholds, including PCC >= 0.997 for the base encoder.
