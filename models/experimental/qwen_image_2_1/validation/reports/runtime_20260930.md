# Qwen-Image 2.1 integrated runtime report

Measured 2026-09-30, raw prompt **the quick brown fox jumps over the lazy dog**, seed 42, 384 × 256, batch one, 20 denoising steps, BF16, prompt expansion off. Both full runs computed their own encoder output and initial noise without activation injection. Checkpoint `790c92633540aa0cb11d9abf19eb46d861714758`; Diffusers commit `5ff8e59ff9fe81c6e2df4fb4c6ea0d97a5df5ab2`. Source: local `ert` commit `483ed75`, with the native runner and timing changes. Results describe a prototype, not a production latency guarantee.

## Full independent generation

| Backend | Hardware | Completed steps | Recorded elapsed |
|---|---|---:|---:|
| CUDA | One RTX A6000, local GPU 2, model CPU offload | 20 | 36.152 s |
| TT | One Blackhole P150, f02cs02, 0000:81:00.0 | 20 | 568.455 s |

CUDA elapsed starts before checkpoint/pipeline loading. TT elapsed starts before device open, after tokenization and CPU request metadata construction. Both end after PNG writing. Neither includes process import time. These starts differ, so the table is a report of measured elapsed time rather than an exact speedup ratio.

TT's 20 step durations total **538.633 s**, mean **26.932 s/step**, median **25.209 s/step**, range **24.822–39.211 s**. The remaining **29.822 s** combines initialization, encoding, initial noise, final decoding, and bookkeeping. Step 10 took 39.211 s; its cause was not profiled. These are steps within one generation, not 20 independent requests.

## Synchronized module wall times

The instrumented CUDA repeat completed all 20 steps in **28.683 s**. The TT diagnostic used the same 20-step schedule but stopped freshly after step 0 and decoded that intermediate latent, finishing in **54.634 s**. No in-process warmup was performed; existing filesystem/JIT caches may be reused. Each module boundary synchronizes device completion. Values include host work within the boundary and are not pure device execution times.

| Module boundary | CUDA | TT |
|---|---:|---:|
| Prompt encoder | 3.800 s | 24.689 s |
| Text projection | Included in DiT | 0.029074 s |
| Initial noise | Not separately measured | 0.043196 s |
| Step input and conditioning | Included in DiT | 0.101424 s |
| 32 DiT blocks, step 0 | Included in DiT | 24.574 s |
| Output head, step 0 | Included in DiT | 0.037709 s |
| Euler update, step 0 | Not separately measured | 0.018899 s |
| First whole DiT call | 14.263 s | See block/input/head breakdown |
| Subsequent DiT calls, steps 1–19 | Mean 0.081317 s | Each step reloads block weights |
| Decoder hook / TT decoder | 0.068573 s | 3.286 s |

The CUDA first DiT call includes initial model offload transfer; later calls retain its weights on GPU and reuse the prefix KV cache. TT block timings include host weight loading and tensor preparation each step and recompute the prefix. The decoder boundaries also differ: CUDA hooks only `vae.decoder`, while TT includes latent preprocessing and post-quant convolution. Consequently the decoder row does not establish a kernel-level speedup.

## Migrated fork hardware verification

The fork package passed **12 tests**, with one optional oracle case skipped, in **175.34 s** on the same reserved TT card and its own Python environment. This includes a raw-prompt native one-step/TT-VAE smoke with CUDA unavailable, the existing paired first-step denoiser PCC regression, and metadata tests. The native smoke PNG was byte-identical to the workspace timing diagnostic PNG. Cold JIT compilation occurred; pytest suite duration is a validation time, not inference performance. The complete native 20-step result remains the separate reference reported above.
