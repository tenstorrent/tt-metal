# Stage 09 cache and scheduler contract investigation

Source-only investigation, 2026-09-27. No device execution, server launch, dependency installation, or performance measurement was performed. The inspected vLLM base is `5ffebf4128f81ea5cf8413175eabde52cd8c8d75`. Findings below explain source-level failures; they do not prove device correctness.

## Diagnosis

1. **Per-layer routing is missing in the generated stack.** `tt/model.py:217` and `:233` send one `page_table` to every attention layer. `tt/generator.py:203`, `:271`, and `:327` upload, retain, compare, and refresh only one table. The plugin already creates distinct group tables, expands them into layer order at `model_runner.py:463`, and passes `page_tables_per_layer` from both `model_runner.py:2674` and `async_decode.py:582`. Ignoring that argument routes sliding layers through the wrong allocator blocks.
2. **HF head counts cannot be used unchanged with the plugin's current shape calculation.** The pinned HF config contains sliding heads 8/head dimension 256 and global heads 2/head dimension 512. `multichip_decoder.py:840` produces device-local heads 2 and 1 on TP4. Both device-local 32-token K pages therefore hold 16,384 elements. Upstream `vllm/v1/core/kv_cache_utils.py:905` equalizes page bytes by increasing the smaller group's token block size. Specs using the HF counts 8/2 become sliding block32/full block64. `optimized_decoder.py:648` explicitly rejects non-32-token pages. Conversely, specs using the correct local heads 2/1 currently encounter a second division in `model_runner.py:428`, producing one sliding head instead of two.
3. **Allocator page growth is not a decode reset.** `model_runner.py:683` appends `new_block_ids` without setting `persistent_batch_layout_changed`. `input_batch.py:907` has the equivalent omission in the lane path. `async_decode.py:249` accepts such scheduler steps as steady decode. A model which refreshes only for `reset_batch=True` then retains stale device pages. Simply setting reset without draining is also wrong: pending sampled tokens may not yet have reached the host state used to rebuild token/position inputs.
4. **Shared tensor storage needs an explicit per-layer view.** `_build_per_layer_specs` returns triples `(shape, dtype, tensor_idx)` and groups sharing `tensor_idx` share allocator storage. The common transformer allocator reuses the same tensor handles, regardless of shape. This autoport's fused cache update and `NativePagedAttention` consume the tensor shape directly, so handing the sliding allocation view `[N,2,32,256]` to a full layer expecting `[N,1,32,512]` is unsafe. Equal page bytes alone do not prove kernel geometry correctness.
5. **Logprobs remain a separate required serving gap.** `generator.py:99` rejects every logprob request on TP4. This must be repaired in the generator/common sampler contract or exposed through an explicit verified compatibility path; suppressing the request is not a passing sampling gate.

## Minimum proposed changes

- Add optional `page_tables_per_layer` to the generated generator/model low-level methods. Validate length against the selected layer list, retain one persistent device table per distinct group/shape, route layer `i` to its table, and refresh changed contents even while token/position feedback remains device-owned. Retain the uniform-table fallback for standalone callers. Test group order independently of layer order and reduced-layer original indices.
- Emit real `SlidingWindowSpec(sliding_window=1024)` for sliding layers and `FullAttentionSpec` for global layers. Emit device-local heads 2/1, block size 32, head dimensions 256/512. Add an explicit adapter capability `kv_cache_specs_use_local_heads=True`; make the plugin skip its legacy head division only for this capability. Legacy models retain their current allocation calculation. Equal local page sizes then prevent the upstream unifier from changing token block size.
- Set `_HYBRID_KV_CACHE_GROUPS_ENABLED=True` for allocator headroom accounting. Keep selected BFP8 device-cache dtype; torch dtype in a spec is host/accounting metadata and does not establish the allocated TT dtype. The plugin uses a block-count override and dummy available memory (`worker.py:289`), so neither successful spec construction nor its nominal byte count proves maximum-context capacity.
- Allocate/cache vLLM-owned buffers according to `tensor_idx`, with a verified per-layer shape view or explicit geometry override for every writer/reader. An independent buffer per layer can isolate correctness, but forfeits hybrid buffer sharing and needs an honest capacity assessment before final serving. A reshape must be proven to preserve the underlying buffer/address and page layout; a copying reshape silently defeats sharing.
- For the minimal safe page-growth repair, reject steady overlap when any cached request receives a nonempty block list in any cache group, mark persistent decode layout changed when such IDs are appended, and reuse the existing drain-before-`_prepare_model_inputs` path at `model_runner.py:1395`. Make the same change in lane `apply_step_plan`, whose caller already drains at `model_runner.py:2224`. `None`, `()`, and tuples of empty per-group lists must leave unchanged-table steady decode enabled. A later page-only refresh optimization may avoid token reload, but needs independent proof that device token/position state remains intact.

## Focused discriminating checks

Host checks (no accelerator required):

1. Construct local-head full/sliding specs, run the actual upstream page-size unifier, then actual plugin `_kv_cache_shape`; expect `[N,2,32,256]` and `[N,1,32,512]`. Check opt-in false/missing preserves legacy shapes and check TP/DP division.
2. Drive actual `_update_states` and `build_model_input` using allocator-style per-group block deltas. Assert a pending decode is finalized/applied before host token/position preparation, both for a group-0 append and an append only in a later group. Check `None` and all-empty group lists do not drain or reset.
3. Exercise the actual lane `apply_step_plan` for nonempty and empty group deltas; ensure the caller sees layout changed only when appropriate.
4. Verify scheduler steady-decode eligibility rejects growing pages before state mutation. Cover multiple requests, with growth on only one request and one non-first group.
5. Check mapping with intentionally reordered hybrid groups and different table values; after an allocator append, only changed persistent group tables should refresh. Check per-layer cache ownership, reduced-layer indexing, and inactive slots.

Required device/serving checks still outside this investigation:

- Reduced target with one real layer of each kind, same terminal norm/head/sampler/trace path; distinct requests with staggered prompt lengths crossing multiple automatic allocator page boundaries and the 1024-token sliding window.
- Compare overlapped output against a trustworthy non-overlapped control with identical token IDs, positions, and allocator tables. Force no manual resets; assert unchanged-table steps perform no table copies, and verify sampled token N is consumed exactly once by step N+1.
- Include request completion/removal/reordering and new prefill while another request decodes, plus a valid non-aligned prompt and shared-buffer shape alias tests. Instrument buffer identity and allocation size for per-layer views.
- Final all-layer full sampling/logprobs, prompt-correct controls, advertised context 262144, larger concurrency, lifecycle memory checks, and required serving artifacts remain stage gates. Host tests alone do not authorize `supports_async_decode=True`.
