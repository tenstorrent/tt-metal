# Final profiler evidence

Hardware: P300, device 3, Blackhole, 110 available worker cores.

## Prefill

Minimal one-repeat Tracy collections were made separately for sliding and full
attention. The modern join dropped device markers even in this reduced case,
so the exact failure logs are retained as `final_ops_*_b1.log`. Forced legacy
device-log parsing recovered the complete op streams. Architecture and worker
metadata absent from the legacy join were restored in the derived CSV from the
authoritative `cpp_device_perf_report.csv` generated by the same collection.

| Layer | Report CSV | Rows | Architecture/workers | Modeled DRAM roofline |
| --- | --- | ---: | --- | ---: |
| sliding | `tracy/final_ops_sliding_b1/prefill_report.csv` | 523 ops | Blackhole/110 | 15.1%, 82 GB/s |
| full | `tracy/final_ops_full_b1/prefill_report.csv` | 523 ops | Blackhole/110 | 15.1%, 83 GB/s |

The corresponding human conversion logs are `prefill_report.txt`; both state
`Architecture: blackhole, Worker cores: 110` and select only the case-specific
prefill signposts.

## Traced decode

Retained-trace replay emits no new TTNN op rows, so `tt-perf-report` cannot
produce a per-op replay table. The accepted device-profiler equivalent is the
raw `cpp_device_perf_report.csv` under each `tracy/final_*` directory. It
records Blackhole, 110 workers, and nonzero whole-trace firmware/kernel
durations for both the warm replay and measured replay:

| Layer/batch | Measured replay firmware ns | Kernel ns |
| --- | ---: | ---: |
| sliding/b1 | 2,997,031 | 2,996,276 |
| full/b1 | 3,182,439 | 3,181,678 |
| sliding/b32 | 68,875,995 | 68,875,239 |
| full/b32 | 68,588,196 | 68,587,459 |

These device values agree with the synchronized host-latency regime and are
not capture-op times. The modern join then fails while attempting to match
host TTNN op identifiers that replay does not emit; each failure is retained
in `final_full_b1.log`, `final_sliding_b32.log`, and `final_full_b32.log`.
The sliding-b1 raw device report is retained and hashed, but its initial
modern-join console stream was not saved as a separate log. Capture topology,
traced replay device duration, and warmed
host replay latency are therefore reported as separate evidence.

## Commands

Prefill collection used:

```bash
GEMMA4_DECODER_IMPL=fused GEMMA4_FUNCTIONAL_DECODER_PERF=1 \
GEMMA4_RANGE_DOWNLOAD=1 GEMMA4_PERF_PREFILL_REPEATS=1 \
GEMMA4_PERF_DECODE_REPEATS=1 python -m tracy -r -p \
  -o <case-dir> -m pytest -q '<exact perf-profile parameter node>'

python tools/tracy/process_ops_logs.py -o <case-dir> \
  --force-legacy-device-logs
```

Decode-equivalent collection added `--device-trace-profiler` and used one
exact parameter node for each of sliding/full x b1/b32.
