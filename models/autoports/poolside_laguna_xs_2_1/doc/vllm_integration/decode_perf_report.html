01 Latency & E2EL — vllm bench serve

Single-user (conc 1, OSL 1024), vllm bench serve, APC off, weight-cache off, measured E2EL. E2EL = TTFT (prefill) + decode; it is prefill-dominated at long context (tracks TTFT), while decode throughput stays flat to ~32k.

Single-user latency — COLD (prefix caching OFF, conc 1, OSL 1024)

These are cold — prefix caching OFF, so every request prefills the full context from scratch (~1,040 tok/s). This is the worst-case first touch of a new context, not a typical agent turn. E2EL ≈ decode time at short ISL (1,024 ÷ ~25 t/s/u ≈ 41 s); at 130k it is ~80% TTFT (299 s prefill).

Cold vs warm TTFT — the number depends entirely on caching

ISLTTFT cold (from scratch)TTFT warm (cache hit)ratio
32,76829.8 s~0.36 s *~83×

For a coding agent, the warm number is the representative one. An agent's context grows incrementally and is ~95% prefix-cache hit, so its per-turn TTFT sits near the warm column (cache-hit suffix prefill) — not the cold worst case. Cold ≈ a fresh 130k context from scratch; warm ≈ what an incremental turn actually pays. A 1-second "prefill" of 131k tokens is only possible as a cache hit — real cold prefill is ~1,040 tok/s (≈126–299 s). * warm = prior measurement (2026-07-31, pre-bounded-prefill); a fresh warm sweep on current code is pending (see Open items). The cold column is measured today with APC off.

Aggregate throughput scales with concurrency at short ISL — ~25 → 63 → 83 tok/s across conc 1/8/16 at ISL 1k, so the decode path has real aggregate headroom. The 32k rows are an all-at-once prefill-saturation artifact, not steady-state — the ladder fires all prompts simultaneously, so many full 32k prefills collide and E2EL/TTFT balloon to 430–880 s. A ramped-arrival measurement is the follow-up for a clean long-ISL steady-state number.
