# Precision propagation audit

CPU-only implementation/evidence audit, 2026-11-16. No TTNN import, device access, runtime edit, or vLLM integration. This supersedes the preliminary plumbing findings in `initial_precision_capacity_audit.md`; those findings were fixed in the current implementation. This is not the independent stage-review verdict or a P1 acceptance decision.

`precision_propagation_audit.json` records **6,078 successful equality checks and zero mismatches** across the recorded actual construction summaries in `inherited_e4_lofi_v3.json`, `e8_two_hifi4_v1.json`, and `e8_three_hifi2_v1.json`. Each artifact has 48 ordered layer summaries. These checks compare constructed tensor dtypes and compute configs with `load_policy` plus resolved `layer_policy`, including both `decode` and `rows` projection paths. They do not merely compare requested JSON copies.

At this audit snapshot `selected_precision_config.json` was absent. Default-loading plumbing exists and is CPU-tested, but actual selected-default construction and its post-selection token-out measurement remain the parent's finalization work. Explicit-policy candidate runs prove candidate construction, not that the eventual selected artifact has already been exercised.

## Actual precision in the measured candidates

| Artifact | Expert gate/up/down storage | Expert fidelity on all 48 layers | Other named projection fidelities |
| --- | --- | --- | --- |
| `inherited_e4_lofi_v3.json` | BFP4 throughout | LoFi | HiFi4 |
| `e8_two_hifi4_v1.json` | BFP8 on layers 0 and 47; BFP4 on the other 46 | **HiFi4, including BFP4 layers** | HiFi4 |
| `e8_three_hifi2_v1.json` | BFP8 on layers 0, 1 and 47; BFP4 on the other 45 | HiFi2 | HiFi4 |

For all three: shared/shared-down and QSA QKV/output weights are BFP8; GR, GDN Z/A/B and LM head are BF16. Projection inputs, residual stream, model CCL transport, KV cache, logits and sampling canvas use BF16. Expert compute has FP32 DEST disabled, packer accumulation disabled, approximation disabled. DRAM projection groups have FP32 DEST enabled and packer enabled; shared-down and LM head have FP32 DEST enabled and packer disabled. Those accumulation choices are fixed implementation contracts, separate from the selected math fidelity.

No material configurable policy field was found silently ignored in the reviewed construction/execution paths. Configurable fidelity names are the explicit projection/expert roles, not every matmul in the model. Fixed QSA attention HiFi2 and fixed exact-operation compute remain outside that set. The runtime summary is strongest for actual weight/compute operands and weaker for fixed numerical assumptions; its `requested` values alone must not be presented as tensor-readback evidence.

`fixed_numerics` correctly distinguishes BF16 GDN QKV/output, BF16 router weights, FP32 hyperconnection norm/mixer weights, BF16 GDN output norm, FP32 routing logits/top-k **scores**, BF16 routing weights, BFP8 shared router and PLE key/value weights, FP32 GDN recurrent state, BF16 token embeddings and UINT32 token IDs. Router indices are integer metadata, not FP32 scores. Packed PLE table encoding is the fixed group10/scale8 Lloyd UINT32 format. Exact projection FP32 accumulation does not imply FP32 storage for every exact-projection weight. These assumptions come from their existing kernel/source contracts rather than separate dtype fields in the candidate telemetry.

## Public selected-default construction and cache planning

`tt/generator.py:build_generator(model_dir, mesh_device, **kwargs)` calls `load_policy(model_dir, kwargs.pop("precision_config", None))`. With no override, `load_policy` reads `doc/datatype_sweep/selected_precision_config.json` if present; it only falls back to inherited policy when absent. It passes the resolved policy to `QwenModel`. Direct default `QwenModel` construction also calls `load_policy` using the autoport root. Unsupported fields fail rather than silently falling back.

`QwenGenerator.get_max_tokens_all_users` loads that same selected artifact, adds `static_weight_delta(policy)` to `KNOWN_STATIC_BYTES`, and passes `kv_cache_dtype` to `plan_shared_kv_cache`. The planner charges the actual BFP tile bytes before determining shared-pool capacity; it rejects infeasible requests rather than silently lowering the advertised 262144 context. The cache declaration, explicit pool spec, allocation, caller-owned cache validation and actual QSA gather path agree on dtype. Explicit experimental builder overrides are not arguments to the static public planning method; experiments requiring a different policy must call the pure planner with that policy's delta/dtype. This limitation does not affect the selected-default path.

There is **no tested vLLM adapter** in this stage. A future adapter must construct through the public builder and use the selected-policy public planning/cache interfaces; constructing an independent hard-coded model would not inherit this guarantee. This audit makes no claim of vLLM construction or serving tests.

## Weight-memory arithmetic against observed allocations

Per EP4 rank, each expert role has 128 local matrices of 2560 × 640 elements (the down matrix is transposed but has the same tile count): `128 × (2560/32) × (640/32) = 204800` tiles. Three roles give 614400 tiles per layer. BFP4 tiles occupy 576 bytes and BFP8 tiles 1088, so one upgraded layer adds exactly **314572800 bytes per rank**. DRAM projection counts include eight-bank column padding; `test_static_weight_delta_projection_shapes_and_bank_padding` independently derives all role counts from geometry. The static helper charges persistent weights only, not guessed trace/workspace savings.

| Candidate | Predicted persistent delta / rank | Observed loaded delta / rank | Observed prepared delta / rank | Prepared excess over prediction |
| --- | ---: | ---: | ---: | ---: |
| Two BFP8 expert layers | 629145600 | 629145600 | 629194752 | 49152 |
| Three BFP8 expert layers | 943718400 | 943718400 | 943767552 | 49152 |

Observed deltas use `(candidate.memory_<phase>.total_bytes_allocated_per_bank - inherited.memory_<phase>.total_bytes_allocated_per_bank) × 8`. Both loaded values match exactly, independently confirming that layer exceptions change real resident storage. The prepared phase adds the same 49152 bytes per rank (6144/bank) beyond the weight change in both candidates; this small preparation difference is not an ignored weight field. Its precise allocation owner was not isolated by this CPU audit, so it must remain runtime overhead rather than be folded into weight arithmetic.

The three-upgrade run completed all four numerical rows but failed later trace inventory capture. Exact agreement of persistent memory accounting does not establish trace-capacity acceptance; `completed=false`, `passed=false` and the recorded trace-overlap error remain a rejection. The two-upgrade artifact has `completed=true`, `passed=true` and successful trace inventory. Neither status substitutes for the selected candidate's P1 or post-selection benchmark.

## Host validation

Re-ran `tests/test_precision_policy_cpu.py` and `tests/test_cache_pool_cpu.py` as direct unittest modules (21 tests), and `tests/test_cache_budget.py` with pytest confined to the model tests directory (28 tests): **49 passed**. `TT_VISIBLE_DEVICES=0,1,2,3` was set, pytest plugin autoload disabled, and a `sys.meta_path` guard raised on any attempted `ttnn` import. None occurred. Tests cover selected-file defaults, policy immutability, unsupported fields/layer overrides, fused dtype constraints, independent padded-weight arithmetic, BF16/BFP8 byte costs and admission boundaries, dtype mismatch/alias rejection, and no silent context shrink.
