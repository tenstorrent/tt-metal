HF reuse was audited from source rather than inferred from the manifest label. At commit `86130b35`, `tests/run_vllm_quality_controls.py` used 1,024 at lines 51–52 and 91–92 to guard request length, recorded it at line 115, and passed it to the **TT** generator at line 156. The HF branch at line 139 called `load_exact_text_model()` without a context argument. The [HF loader](../../tests/full_model_hf_reference.py) is unchanged since `8d53247c2b8b552c1f04efc7336bc5ec9db74349`: it loads the pinned checkpoint's `text_config` (line 67), changes only `_attn_implementation` to `eager`, constructs `Qwen4ExpForCausalLM(config)`, and reconstructs rotary embeddings from the same config (line 95). It does not reduce maximum positions or modify RoPE parameters.

The pinned checkpoint's local `config.json` has `text_config.max_position_embeddings=262144`, default RoPE, theta 10,000,000, partial rotary factor 0.25, and the checkpoint's original mRoPE section `[11,11,10]`. The [HF loader evidence](../../readiness_vllm/quality_hf_v1/hf_reference_loader/loader.json) records all 48 layers, original per-tensor checkpoint dtypes without casts/quantization, and exact checkpoint PLE row lookup with the original forward computation. It does not separately dump runtime maximum positions: the 262,144 HF model configuration conclusion follows from the audited loader and pinned configuration, not from a nonexistent runtime dump. Therefore the old HF `context=1024` label is a request-length guard, not a reduced model/RoPE configuration, and reuse is valid for these unchanged short prompts and settings.

Fresh TT uses all 48 layers, mesh 1×4, context 262,144, `combined_shared4_mixed`, and canonical split sampling with traced decode and `host_sampling=False`, as recorded by the runner and manifest. Preserving the selected datatype-sweep configuration is the comparison policy for this stage; it should not be described as an explicit user prohibition on every possible future datatype experiment.

Limitations: this is six prompts and one seed per profile, reviewed with backend labels visible. It is not a blind, ten-seed failure-rate study, a model-card sampling assessment, a long-context quality evaluation, or a statistical equivalence claim. The sampled haiku form defect is recorded as an observed control limitation, not proven to be equally frequent in HF. Code examples were inspected, not executed. Longer explanations and stories require a larger matched output budget to judge completion. Fresh vLLM outputs must still be compared with this same-code, same-chip generator control at the served token count; this document alone does not establish HTTP-path quality, async correctness, or serving performance.
