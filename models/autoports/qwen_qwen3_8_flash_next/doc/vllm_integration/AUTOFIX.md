# AutoFix — serving config translation

Failing contract: the pinned standalone plugin/upstream pair must construct the same QSA/GDN decoder as the completed standalone generator. Reduced_v1 failed at layer3 with Unsupported layer kind: full_attention, before requests or warmup. AutoDebug inspection confirms old checkpoint labels are normalized by standalone Transformers5.22.2 but preserved by bundled vLLM config under recommended Transformers5.14.1.

Hypotheses: (1) missing canonical label translation; (2) different numeric/indexer/RoPE fields; (3) cache allocation defect. Config dumps and source-attribute audit discriminate1 from2: layer_types is the only differing consumed field. The failure precedes allocation, excluding3 for this failure. Independent diagnosis: AUTODEBUG.md.

Repair: QwenModel accepts an optional loader config, deep-copies its text config and normalizes full_attention to indexed_attention with complete QSA metadata. Standalone semantics remain intact. Adapter spec and allocation classifiers accept raw/canonical labels and retain twelve logical attention specs, projecting reduced diagnostic layer selections only at model allocation. No plugin or vLLM source changes. Private normalization also keeps generator.model.config introspection consistent with its actual layer kinds; patching one decoder dispatch branch alone would leave config-driven consumers inconsistent.

Validation: seven host adapter tests pass (`logs/adapter_cpu_v4.log`). Reduced_v2 opened all devices, prepared traces, and served seven non-aligned/concurrent requests successfully.
