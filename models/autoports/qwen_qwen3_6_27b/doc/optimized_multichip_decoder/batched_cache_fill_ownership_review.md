# Independent CPU review: batched cache-fill ownership

The proposed lease is a conservative way to preserve mutable public `PagedState.page_table`: private, setup-certified injective tables can use bulk eager fill; exposing the raw table permanently revokes that lease; an externally constructed PagedState always uses the ordered loop. Public table replacement must revoke the old shared lease before installing an uncertified replacement. Fresh host upload is the only recertification route. Host-side uniqueness checks remain setup-only. This adds no device readback to forward.

**Fix required:** `copy.deepcopy(state)` can create independent certification while the device wrapper still aliases device storage. Add `_TableLease.__deepcopy__` returning the same lease, as in `page_table_ownership_reviewed.py`. This conservatively shares revocation even if some device wrapper implementations instead duplicate storage. The CPU stand-in test reproduces the original flaw and passes the revision; it is not device evidence. Shallow copy and fresh replacement are covered too. Pickling device states is not claimed supported.

**Runner finding:** the initial PCC/cache check actually occurs before the first public table exposure in the current runner. Therefore it should execute bulk fill after integration; the claim that only performance exercises bulk is not established by source. The existing proposed runner patch nevertheless lacks proof: add explicit initial bulk/ordered deltas and require initial bulk work when eligible. `batched_cache_fill_runner_reviewed.patch` contains the proposed performance re-arm plus those counters and exact full output/cache comparisons after each timed sample (readback outside the timing interval). This proves every reported timed sample reproduces the PCC-checked initial execution. Do not cite the final timing counters alone as correctness evidence.

Retain ordered fill during prefill trace capture: public raw exposure after capture cannot retroactively alter a captured bulk branch. Decode traces remain mutable-table compatible because they retain the existing update-cache operations. Trace-safe bulk prefill would require an immutable table contract for the entire trace lifetime; this patch intentionally does not claim it.

## Required cumulative device coverage before keeping the integration

1. Run full attention B2/B3/B17/B32 at logical lengths 1, 31, 32, 33, 257, 513 with explicit bulk dispatch counters. Whole-output, contribution, per-user, full KV state and following decode gates remain unchanged. Length 1 may use token update and is exempt from bulk requirement. Compare repeated timed outputs and complete KV state exactly with the initial forward.
2. Normal private state must use bulk; reading `.page_table` then mutating it must use ordered fill. Compare resulting full K/V caches with an independently run ordered reference. Cover both a new disjoint permutation and cross-user aliasing pages (the latter must retain deterministic existing row-order behavior). Exercise mutation through a retained shallow-copy and deepcopy alias. Use sentinel-filled unused physical pages so unintended writes are detected.
3. Replace `state.page_table` with an external device tensor and require ordered fill. Fresh host replacement with disjoint rows may re-enable bulk; duplicate rows must remain ordered. Include -1 skipped pages and remapped page IDs. Explicitly verify old aliases remain revoked after replacement.
4. Cover aligned resumed starts 32 and 512 and nonaligned starts 1, 31, 33, 257 through the public scheduler, comparing cumulative output and complete state with the existing ordered decoder. Focused `probe_batched_cache_fill` can validate the aligned primitive but cannot prove the nonaligned public scheduler.
5. Capture prefill with a private lease and require zero bulk calls inside capture; replay after changing inputs, after exposing/mutating the table, and after cache reset, comparing ordered eager output and full cache. Replay of an old trace after fresh table replacement is outside the documented address contract and requires release/recapture. Preserve changed-page decode trace checks already present in the runner.
6. Run focused fill with `--reverse-users --skip-page`, B1/3/17/32, lengths 33/513, starts 0/32/512, watcher and allocation tracking enabled separately from performance. The focused helper's disjointness boolean is a caller assertion; these tests do not replace owner-lifetime tests above.
