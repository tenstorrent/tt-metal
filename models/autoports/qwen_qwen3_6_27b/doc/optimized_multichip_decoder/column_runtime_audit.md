# Static exact-column recurrence runtime wrapper

2026-11-13. CPU-only change. No TTNN/Torch import, device execution, native build,
new performance measurement or main-decoder hook was performed by this task.
The two task-owned files are `tt/column_recurrent_runtime.py` and this audit.
Existing candidate/probe/model/native files are unchanged by this task.

## Interface and integration

```python
from .column_recurrent_runtime import column_recurrent

output = column_recurrent(
    qkv, qkv, qkv, g, beta, state,
    packed_qkv=True,
    variant="cumulative_exp_scalar",
    grain=1,                 # 1 = columns; 2 = pairs
    cores=selected_cores,     # None means available grid, bounded by work
    grouped_qk=True,
    output=output_buffer,    # optional; otherwise allocate normal FP32 output
)
```

Full signature:

```python
column_recurrent(
    q, k, v, g, beta, state, *,
    normalized=False, packed_qkv=False, output=None, cores=None,
    grouped_qk=True, variant="baseline", source_overrides=None, grain=1,
)
```

Only raw packed QKV is accepted. The input is one BF16 row-major DRAM
`[B,1,2560]` tensor aliased by q/k/v; B is 1–32. State is unchanged BF16 or FP32
TILE DRAM `[B*12,128,128]` and is updated in place. Gates retain the existing
`[B,1,12]` logical / `[B,32,32]` padded tiled contract. Result remains FP32 TILE
DRAM `[1,B*12,128]` with the exact existing padding rules. This preserves the
old generated wrapper's admitted input/output contract; it does not add a new
fallback or change recurrent precision.

`source_overrides=None` resolves grouping through the pure `column_partition`,
then calls the existing `recurrent_variants.sources(reader, compute, variant,
grouped=resolved_group)` and pure `column_sources(reader, compute, writer)`.
Explicit overrides must already be the complete column-aware R/C/W tuple, as
in the tested probe. Production integration should pass
`variant="cumulative_exp_scalar"`; the default argument stays compatible with
the old interface. Grain is explicitly limited to the two tested choices 1/2.

Imports of TTNN and declared kernel/config constants occur inside the device
wrapper. The reader is imported by name from `multichip_decoder` only when
automatic source assembly is needed; this import occurs when the already-loaded
model invokes the function, avoiding an import-time circular dependency. The
module itself is safe to import for CPU partition/source inspection.

No model-global function patching, `FunctionType` cloning, Python AST parsing,
`exec`, `eval`, `compile`, reflection, or reading Python source files occurs in
the runtime module. String transformations operate only on explicit existing
kernel strings and fail closed if an expected anchor changes.

## Exactness and ownership

The checked-in wrapper is the static host function previously generated by
`recurrent_column_candidate.host_source`, with explicit imports, a grain
argument, an early raw-packed assertion and optional automatic source assembly.
After normalizing these documented interface differences, its Python AST is
identical to that generated host function. `replace_once` and `column_sources`
are AST-identical copies of the old pure transformations.

The pure partition still owns contiguous value-column units. Each owner keeps
all four K-row tiles of each owned value column. `first_n/last_n` apply only to
the boundary heads. The reader fetches only owned state columns; compute loops
only over owned value columns; the writer persists only owned state and output
columns. The last-head output padding uses the same ownership mask. No two
workers own a state page or padded output write, and no state/output page is
omitted. Grouped Q/K behavior stays `grouped_qk and B>=3`.

All recurrence instructions and packing remain byte-identical to the old
column candidate. Removing only the two column-bound declarations/loop edits
restores the selected `cumulative_exp_scalar` compute string exactly. CB counts,
state BF16/FP32 page sizes, accessor argument order, scalar flags, compute flags,
HiFi4 configuration, FP32 direct-unpack modes, reader/compute/writer runtime
arguments and kernel order retain the tested descriptor ABI.

## CPU validation

The offline harness embedded below performs source/AST inspection and executes
both host wrappers against descriptor-only stand-ins. Its custom import hook
returns a plain namespace for the name `ttnn`; it never imports or loads the
real TTNN module. AST/execution in this **offline comparison harness** is not
part of the new runtime wrapper. The harness finishes by asserting neither
`ttnn` nor `torch` exists in `sys.modules`.

Validation scope:

- Pure partition equality plus exact/disjoint column, state-page and padded
  output ownership for all B1–32, both grains, grouped on/off, available cores
  1/7/64/110/128, and every core cap 1 through available+1 plus default.
- Exact R/C/W source equality with the old candidate for grouped on/off and
  dead-padding poison on/off. Compute restoration verifies unchanged math.
- Full normalized wrapper AST equality after documented interface changes.
- Full descriptor equality for B1–32, grains 1/2, every core cap 1–110 plus
  default, both state dtypes, allocating and preallocated outputs. Grouping
  toggles by core cap; all four BF16/FP32 gate/beta dtype combinations are
  exercised. Inputs, outputs, sources, core maps, runtime args, compile-time
  args, compute config and all 19 CB descriptors are compared recursively.
- Each descriptor case also builds sources automatically and compares that
  result with the old wrapper's explicit source tuple.
- CPU-only import, forbidden runtime source-generation/read checks, AST parse
  and Black formatting check.

**PASS:** 40,960 partition/ownership cases, 14,208 explicit descriptor cases,
14,208 automatic-source descriptor cases, four grouped/poison source cases and
normalized wrapper AST equality. The process exited 0, with neither TTNN nor
Torch loaded. Formatting and AST parsing passed.
