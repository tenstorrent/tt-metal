## 2026-08-13 — stage start and operation-topology audit

Scope is the completed TP4 `MultichipDecoder` on the four local Blackhole
p300c devices, `MeshShape(1,4)`, `FABRIC_1D_RING`. The inherited checkpoint is
`a2a1bf5f073`; the implementation commit is `fefee63979f`. Existing untracked
profiling artifacts were preserved. `timeout 60 tt-smi -ls --local` reported
all four devices and a serialized 1x4 open/close returned `MESH_SMOKE_OK` with
device IDs `[3, 2, 1, 0]`.

The strongest accepted baseline uses packed full-attention QKV+gate and packed
linear-attention input projections, separate MLP gate/up projections, BFP8 KV
cache, DRAM-sharded decode projection weights, eight-core L1 width-sharded
projection activations, and replicated hidden-5120 layer boundaries. Its row
parallel attention output and MLP down projection each execute local matmul,
reduce-scatter, then all-gather (the implementation spells this as
`ttnn.all_reduce`). No host materialization occurs between stacked layers.

### Fractured residual carry-forward: adapted first implementation

`decode_forward_fractured` now accepts and returns semantic 1280-wide mesh
shards. It carries that layout through residual adds and distributed RMSNorm
(`pre_all_gather -> stats all-gather -> post_all_gather`), gathers full hidden
only at each column-parallel projection consumer, and changes row-parallel
attention/MLP outputs from all-reduce to reduce-scatter. The result gather is in
the test harness after the measured two-layer stack.

The first real linear→full B32 attempt reached full attention but failed because
the inherited full-attention tail hard-coded a replicated 5120-wide reshape.
After adapting the tail to the active row-collective contract, the second run
passed boundary/output PCC, all local linear/full cache ownership checks, and
fallback audit with a direct 1280-wide device boundary. Evidence:
`logs/fractured_stack_b32_first.log` and `fractured_stack_b32_second.log`.
This established feasibility; the traced whole-stack result in the next section
earned the final rejection.

### Fused/async CCL AutoFix and matched control

A shape-faithful 32x1536x5120 fused matmul->reduce-scatter probe was adapted
from the repository unit test with global semaphores, persistent buffers, and
a subdevice stall group. The first run updated the current minimal-RS buffer API.
The second separate and third fused-only watcher runs both trip a BRISC
inter-kernel NoC data-race assert in
`reader_bmm_tile_layout_in1_sender_writer_padding.cpp`. This was not treated as
a fused-family rejection. Bounded list/reset/list and a 1x4 mesh smoke recovered
the board. `$autotriage` traced the failure to remote semaphore atomics issued
by the fused `OpSignaler` without a matching non-posted-atomic drain before the
BRISC kernel exited. `$autofix` added a compile-time-guarded
`noc.async_atomic_barrier()` after the final fused signaler use and before the
existing write barrier.

The exact B32/TP4 output-projection shape then passed 20 iterations under
Watcher with PCC 0.99995762 and no pending-NoC assertion. The fused median was
1.404644 ms. A matched ordinary matmul -> minimal async reduce-scatter control
also passed Watcher at the identical PCC and measured 1.265614 ms, so the fused
path is 10.99% slower at grid 8x6 / `in0_block_w=3`. The guarded code compiles
out of ordinary matmul; that negative control is also evidence that the repair
did not disturb the non-fused path. Artifacts are
`artifacts/candidates/{fused_ccl_o_b32_w3_atomic_barrier,separate_ccl_o_b32_w3_atomic_barrier_control}.json`;
complete Watcher logs with the same stems are in `logs/`. Geometry and
placement adaptation remains necessary before the performance family can be
rejected.
## AutoFix: linear-prefill Watcher CB overflow

The S128 linear-prefill stress exposed a row-major slice CB capacity bug. AutoTriage
localized the 130-byte NCRISC read into a 128-byte page to host `compute_cb_size()`.
The fix includes the temporary leading address misalignment when rounding CB page
capacity, while retaining the old useful-row stride and writer size. A focused BF16
128-byte-row + 2-byte-prefix regression was added.

Final Watcher/no-ETH evidence after rebuilding and installing the active runtime:

- focused exact-boundary slice: PASS, exact values;
- existing 5-D misaligned slice: PASS;
- TP4 linear S128, warmup 4 / iterations 16: PCC 0.999994331685145, replicas equal,

- TP4 full S128 control, warmup 4 / iterations 16: PCC 0.9999945998163279,

### Review remediation: recurrent movement, real tables, and stress

The linear recurrent cache is already a persistent device tensor and is updated
in place. At B32 one local BF16 recurrent value is
`32*12*128*128*2 = 12,582,912` bytes/device, while one Blackhole L1 bank is
1,461,504 bytes and the measured free block at the attempted boundary was only
87,296 bytes. Moving the recurrent state/intermediate family to L1 is therefore
physically impossible, not deferred. Keeping the packed 4160-wide projection in
its eight-core L1 shard through split was adapted after the first downstream
transpose requested an illegal 5,242,880-byte one-bank L1 output. Converting the
four split components independently to DRAM passed PCC 1.0/fallback audit and
measured 4.431050 ms versus the restored default 4.431181 ms: statistically
neutral, with more conversions, so it is rejected. Evidence:
`linear_packed_l1_b32.json` and first/second logs. The precision-locked recurrent
program sweep already covers automatic, 4x1/2x1/1x1/2x2 grids, block widths
1/2/4, subblocks 1/2/4, and DRAM residency; 4x1/w4 remains fastest. This closes
the persistent/intermediate, placement, conversion, and geometry family.

Each retained profiler raw report was rerun through `tt-perf-report` without
`--csv`; real operation/advice tables are `human_table.txt` with stderr kept
separately. CSV output, stacked summaries, raw reports, and console provenance
remain distinct artifacts. The full table proves BF16/HiFi2 QKV/O and
BFP4/LoFi MLP rows; the linear table proves BFP4/LoFi projections and the two
BF16/HiFi2 recurrent rows. The restored-final profiles are under
`full_b32_restored_final` and `linear_b32_restored_final`. Same-run host medians
are 0.747126 ms full and 4.466202 ms linear in the profiled four-step captures;
device tables expose the
dominant per-device op rows and host/trace gaps. At nominal 512 GB/s/device, the
tool's modeled aggregate 143/20 GB/s corresponds to 28.0%/3.8% roofline. The
warmed 16-step final medians are 0.722050/4.431181 ms; the small profile overhead
is 0.025076/0.035021 ms (3.47%/0.79%).
