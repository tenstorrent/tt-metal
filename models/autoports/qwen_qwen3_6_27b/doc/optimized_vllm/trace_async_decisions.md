## Shared split sampling

[generator.py:171](../../tt/generator.py#L171) constructs the existing `SamplingGenerator` with TP4, `max_top_k=64` and power-of-two local-logit padding. [generator.py:407](../../tt/generator.py#L407) normalizes a greedy request to semantic `k=1,p=0,temp=1`; physical candidate width 64 is not a request to draw a generic stochastic top 64 token. Public temperature is inverted exactly once for the low-level sampler. The full padded parameter signature caches uploads; slot remapping invalidates that signature because device parameters moved.

[generator.py:361](../../tt/generator.py#L361) calls the common sampler's `_run_sampling` inside a generator-owned `sample` or `sample_penalties` trace, with `tt_out_tok=self.tokens`. This is a traced wrapper around the canonical implementation, not an eager serving call to an independent sampler. [models/common/sampling/generator.py:417](../../../../common/sampling/generator.py#L417) delegates to `TTSampling` and updates counted penalty history when applicable. The model and sampling traces remain separate.

In [tt_sampling.py:366](../../../../common/sampling/tt_sampling.py#L366), the absence of a model `SAMPLING_AG_CONFIG` leaves force-argmax disabled; this Qwen constructor supplies no such configuration. The candidate pipeline masks invalid vocabulary IDs and pads local logits where configured, performs local candidate selection, and communicates candidate values/IDs rather than full vocabulary logits. [tt_sampling.py:1464](../../../../common/sampling/tt_sampling.py#L1464) compacts the gathered candidates to global64 with corresponding IDs; [tt_sampling.py:1499](../../../../common/sampling/tt_sampling.py#L1499) executes the repaired width 64 `ttnn.sampling` into the persistent token tensor. The common code's comment calling tie breaking “Host-side” is misleading: `_adjust_values_for_tiebreak` uses device TTNN operations, not torch argmax or logits readback.

The selected policy, full-model and adapter use this same terminal/sampling path. The existing stage9 width 64 repair evidence is in `../vllm_integration/p2_repair/`. This source audit does not claim the remaining device TopK work is free or newly profiled; canonical candidate selection and index untilization remain real device work. Removing all tilize/untilize operations is not an accurate description of the sampler.

“Change-only refresh” means scheduler-authorized transitions, not a claim that every reload compares and skips identical page contents. Decode intentionally passes `force=True` on authorized reloads. C2 preserves that behavior. The unchanged resident step performs no token/position/RoPE/page-table host upload. C3 makes page-detail telemetry unavailable when disabled; use telemetry-enabled functional traffic for detailed page-growth evidence and uninstrumented logs for performance.

`supports_async_decode=True` at [generator_vllm.py:41](../../tt/generator_vllm.py#L41) requires the launched server to use `--async-scheduling`, with the plugin draining/applying pending outputs before authoritative scheduler resets. Code configuration alone does not prove overlap was exercised. The final adapter and all-layer lifecycle receipts below exercise concurrent determinism, automatic page growth, reorder and stale inputs. Host `start_pos` may lag resident device state on steady async decode.

## External cache and host compatibility

[generator_vllm.py:96](../../tt/generator_vllm.py#L96) creates the scheduler-sized cache once and passes that same object into `QwenGenerator`; `_check_cache` rejects a different object. [generator.py:727](../../tt/generator.py#L727) also enforces cache identity. Attention pages belong to vLLM; fixed-size GDN state belongs to the model. B1 views borrow scheduler-owned KV and recurrent storage. C1/C2/C3 introduce no standalone-cache allocation assumption and do not replace captured backing buffers.

[generator_vllm.py:150](../../tt/generator_vllm.py#L150) records `mode=device` when sampling parameters are supplied. `sampling_params=None` records `mode=host_compatibility` and requires explicit `QWEN_VLLM_HOST_COMPATIBILITY=1`. Full sampling compatibility tests deliberately request unsupported device features, including logprob/other routing cases, and may exercise this explicit host path. They must not be described as wholly device-only. Conversely, device-mode primary/CI/eval benchmarks require byte-scoped log evidence of zero host-sampled forwards and valid output IDs, even if the compatibility environment is enabled for the test server. The device token path does not enter the adapter's full-logits composition branch.
