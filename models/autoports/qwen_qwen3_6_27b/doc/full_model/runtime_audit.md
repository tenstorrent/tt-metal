`build_generator(model_dir, ...)` deliberately does not treat `model_dir` as the HF weight directory. The installed readiness contract defines it as the autoport directory containing `tt/generator.py`; checkpoint loading uses the pinned local snapshot or explicit `checkpoint` override. No exception handler in the inspected model/generator redirects inference to Torch, HF, a different mesh, a replicated decoder, or a lower-precision policy. `_capture` cleans up an incomplete capture and rethrows. ## Preserved decoder and numerical policy

The authoritative policy/rejection ledger is `doc/optimized_multichip_decoder/{final29_selected_overrides.json,final29_candidate_decisions.md,final29_selection.md,final29_interlayer_contract.md}` plus the linked raw candidate receipts. No entry is removed or reclassified here.

- Residuals remain BF16 hidden-sharded `[B,S,1280]` in prefill and compact `[1,B,1280]` in decode. Layers receive the previous layer's output directly. There is no extra boundary all-gather, reduce-scatter, host concatenation or conversion to5120 replicated channels. Terminal normalization/head is outside the decoder boundary.
- Weights retain the accepted BFP8 families and narrow GDN correction. GDN attention-role fidelity is HiFi4, GDN MLP HiFi2, and full-attention projections retain LoFi; common accumulation/normalization configuration retains HiFi4 with FP32 destination. Embedding and LM head are BF16; terminal matmul uses `io.ckc`. No lower-fidelity full-model override is introduced.
- The selected packed GDN primary/correction, QKVG projection, fused SwiGLU, flat prefill finish, DRAM-sharded decode matmuls, local recurrence, compact attention and fused QK norm/RoPE remain selected. Rejected BFP4 KV, lower-fidelity GDN attention, global GDN L1 MLP, and distributed minimal decode norm are not re-enabled.
- Layer-local CCL manager/semaphores and persistent decode CCL buffers remain private. `ccl_decode_memory='DRAM'`, flat collectives and distributed-decode-norm off are retained. No `ccl_dtype` override is supplied. Bounded preparation allocates equivalent **distinct** buffers for representative-equivalent layer signatures; it does not share mutable buffers between layers.
- Paged cache remains BFP8_B `[physical_pages,1,32,256]` per rank. Prefill explicitly repacks K/V to the cache dtype before raw tile fill. Decode keeps the accepted projected activation/update input path and lets paged update repack into BFP8 cache; it does not accidentally feed prequantized prefill K/V into decode. Page32, one local KV head and shuffled physical page addressing remain intact.
- GDN published state remains BF16: convolution `[B,3,2560]` row-major and recurrence `[B,12,128,128]` tiled. `BoundedPrefill` imports recurrence into a private FP32 workset and publishes once at the end of a public call, not after each internal512-token chunk. Both `_local12_recurrent` and `column_recurrent` explicitly support FP32 and BF16 state; a length1 tail does not force BF16 live-prefill recurrence.

## Bounded prefill integrity

`BoundedPrefill.chunk_intervals` covers a possible unaligned head, aligned512-token bodies and exact logical tail. It allocates/prepares lengths1..512 for B1 and the configured batch only. Mixed request rows use the B1 engine at their fixed slots; equal-length/all-slot batches retain the accepted flattened batch path. `_flat_chunk` is called directly for eligible GDN, including packed correction and `flat_packed_gdn`; full attention preserves packed QKV and `_finish_flat`. B1 and one-token dispatch match the accepted `_legacy_chunk` arithmetic families.

Aligned attention uses a stable full page table, fixed16-entry fill table and runtime `chunk_start_idx_tensor`. Unaligned attention uses the inherited compact one-token attention operation, with runtime device gather/position values. CPU iteration over this prefill head updates metadata, not logits or token predictions; it is distinct from forbidden Python feedback in steady decode. The accepted native decoder also handles unaligned attention heads one token at a time. GDN stays bulk/FP32 live across that head.

Tile padding occurs internally; causal SDPA and logical output slicing exclude padded prompt tokens. The generator consumes the entire helper iterator so final GDN publication runs, even when only final logits are requested. The helper's `allow_unprepared` path is explicitly limited by the generator to the period before its traces are prepared. Private diagnostic subset preparation fails closed on an unprepared chunk length and is not proof of general context support.

Program-signature preparation respects concat input-alias partitions by warming distinct head-output buffers. Tiled persistent recurrent destinations are never passed to slice_write's storage-rebinding path: updates stage through RM and copy back into the original tiled tensor. The current native RM-interleaved slice-write hash omits outer start offsets and recomputes them in runtime arguments; this is material to fixed-slot reuse. Runtime-position SDPA and native slice-write behavior require the matching built native code, not just these Python files.

## Cache ownership, reset and lifecycle

The parent stage owner clarified the supported external allocation contract: the caller may allocate the pool, but binds the **entire pool exclusively to one generator for its lifetime**. Concurrent independent generators sharing that pool are not supported. The current class docstring states this lease explicitly; the generic readiness contract says the caller owns allocation and does not itself spell out this exclusive lease.

The constructor holds the cache list and per-layer tensors. Calls reject replacement cache identity. This protects normal scheduler usage but cannot prevent a caller mutating list contents, tensor storage or private fields; the exclusive lease requires those handles/storage to remain stable. Public device page-table exposure revokes the inherited ownership certificate. Bounded prefill uses its own private uploaded page table and certifies the current aligned chunk's `ceil(count/32)` active physical pages against the minimum bound K/V extent. Only duplicate active destinations choose the inherited ordered path; unused virtual-tail aliases do not disable bulk fill. Preparation uses synthetic disjoint real writes, native skip entries when needed, and restores both full/fill tables and host mirrors in `finally`; see `active_fill_page_proof.md`.

`reset()` clears **all cache tensors including every physical KV page**, not merely currently mapped pages, then resets token, position, active masks and RNG controls. `prepare()` intentionally overwrites state during warmup and resets it before use. These operations destroy any previous prefix history in an externally allocated pool; that is consistent with the exclusive-whole-pool scope, not safe for shared external ownership. Request-level `release_request(slot)` clears only that slot's GDN history. It does not clear unrelated KV pages; new prefill writes its mapped pages and attention is limited by position. Resume with nonzero start requires the caller's matching GDN and KV prefix state to remain resident.

State movement uses device gathers/copies and stable addresses. Slot remapping moves GDN, tokens, sampling parameters, greedy flags and RNG; authoritative command input supplies positions/page mapping. An initial decode following prefill must establish authoritative positions/active rows unless the caller has explicitly established resident state; sampled prefill does not promise an implicit position transition. Same-table resident commands skip host copies; explicit table reload commands copy even equal values, as required by command semantics. Inactive rows retain state and sample outputs on the selected masked path.

`prefill_logits_continuation` intentionally resets first, matching the readiness contract: `prefill_prefix=False` is its missing-prefix negative control, not a request to retain an externally populated prefix. Prefix caching is declared false because KV reuse alone cannot restore48 GDN states. Existing-state resumed prefill is a separate supported operation.

## Sampling and trace ownership

The selected common `SamplingGenerator/TTSampling` uses physical topk32 on each vocabulary shard while semantic greedy is k1/p0/temp1. The adapter disables force-argmax by leaving its opt-in configuration absent. Per-request parameter reloads copy into stable inputs; sampler arithmetic, seed application and output token writes run inside the independently captured sample graph. The generator increments device RNG state and positions on device. Persistent logits are written by the model trace and read by the sample trace; persistent tokens are written by the sample trace and read by the next model trace.

Common sampler comments describe tie adjustment as “host-side”; the implementation is actually TTNN max/equality/int32-min/multiply/add and contains no tensor readback. A known limitation remains: unstable local topk can discard the lowest global token ID when more than32 maxima tie within one shard. The selected output is still a maximum, hence semantically greedy, but exact HF first-index tie parity is not established for that adversarial case. `sampler_ties.json` now tests both cross-shard ties and65 equal maxima inside one shard. All32 rows select a true maximum; the65-way case selects70001 rather than HF's lowest-index70000, explicitly confirming the documented tie-identity limitation without violating greedy semantics.

`SamplingCCL.line_all_gather` clones the decoder's persistent all-gather output before handing it to common sampling, which explicitly deallocates its gathered intermediates. This avoids the previously reproduced storage-ownership failure. The sampler remains common code; no custom sampling arithmetic is introduced. Sampling1D was compared by source/API and rejected for duplicate integration/lifecycle state and another checkout dependency; no comparative Sampling1D latency was measured. Force-argmax was measured separately and rejected on cost.

Low-level device sampling rejects active penalties/logprobs rather than silently claiming their execution. The serving contract must route unsupported device request features through full logits, or explicitly reject unsupported capabilities. Async submission/readback, speculative decode and KV-only automatic prefix caching are not implemented. `read_from_device` does not create an asynchronous API: current returns are synchronous, consistent with the intended false async declaration. The capacity/get_max_tokens_all_users row is now backed by `max_context_final.json` and `slots32_all64_pool_fixed.json`; optional exclusions and host-owned processing are mapped in `serving_mapping.md`. No new generator call-contract defect was found in this reconciliation.

## Resolved findings and remaining acceptance work

1. **Initial external table binding is repaired and exercised.** The current constructor validates K/V/GDN dtype, shape, expected layout, DRAM storage and mesh; validates int32/RM/DRAM page tables and physical bounds; and forces installation of the supplied initial mapping into existing external table storage. The sampled-prefill probe tests a stale initial device mapping, out-of-range initial page ID and unchanged table address. The all64 mixed probe preserves external cache identity through prefill/decode and lifecycle rebuilds.
2. **Whole-pool ownership and reset scope are explicit.** `prepare/reset` intentionally clear the exclusively leased physical pool. Per-request release affects only the selected GDN slot. All64 release/rebuild parity and other-slot isolation now pass; KV-only prefix caching remains false because it cannot reconstruct GDN state.
3. **Resident-position precondition remains caller-owned.** Authoritative decode checks host positions; resident decode intentionally trusts device state and does no host readback/bounds check per token. The scheduler must deactivate before context exhaustion or unmapped pages. `generate` bounds prompt-plus-generation in advance. This is an explicit low-level call precondition, not a claim that resident replay independently rejects overflow.
4. **Host/device reload commands are distinct.** Pinned host sampling sends neither device sampler reload nor reset and omits device sampling parameters. A direct `reload_sampling_params=True` remains a device configuration command with device limits, even if that call returns logits. Wider host top-k/penalties/logprobs belong to the host sampler; `host_sampling_reload_contract.md` records the source proof.
5. **Capacity acceptance is complete within the measured configurations.** All64 B32/C262144/P8224 complete preparation and fixed-slot lifecycle pass; B1/C262144/P8193 passes the one nonaligned maximum-context prefill/final-position decode. `capacity_accounting.md` and `context_contract.json` reconcile measured resident totals, KV/reset and owned CCL, distinguish snapshots from peaks, and retain physical B1/B32 budget coverage. No per-request context reduction or maximum-physical-pool extrapolation is made. Final numerical, resumed-prefill, generation and performance receipts are linked in the README; independent review remains a separate gate.

No new runtime CPU, single-chip, replicated-decoder or host-sampling fallback was found in the selected device path. Current warmup, changed/unchanged tables, preemption, full-context and fixed-slot evidence are complete within their stated scopes. The serving contract has79 rows and no missing item. This audit remains an integrity/evidence inventory, not the independent stage-review verdict.
