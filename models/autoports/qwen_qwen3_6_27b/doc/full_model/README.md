## Implementation and preserved policy

`tt/model.py` loads all 64 real HF layers by default from revision `8f33b98937c6031bb49e713dee3e8e185aafd26f`. Explicit `layer_indices=[0,3]` is a debug path. The complete text path is device embedding, the accepted 48 GDN / 16 full-attention TP4 stack, final norm and untied vocabulary-sharded LM head. Embeddings and head are BF16; each rank owns 62080 vocabulary entries. Shared RoPE avoids per-layer replication.

The accepted decoder is byte-identical to stage5 final29. BF16 residuals remain hidden-sharded at 1280 channels/rank between layers, with no new boundary collectives. Weight, activation, fidelity, KV and CCL policy, narrow GDN correction, packed projections, persistent CCL and rejection ledger are preserved. Paged K/V remains BF8_B, page32, one local head of width256; prefill explicitly repacks to cache dtype while decode retains its accepted update path. GDN persistence is BF16 and live prefill recurrence is FP32. Distributed decode norm remains off. The authoritative policy and carried stage5 confidence-bound note remain in `../optimized_multichip_decoder/`; this stage does not reclassify them.

`tt/generator.py::build_generator` implements the Metal readiness contract. Its low-level prefill/decode accepts explicit cache/page-table state, absolute prompt ends and positions, mixed prompts, fixed slots and inactive rows. `tt/bounded_prefill.py` owns internal chunks of at most512 tokens, padding, masking, cache fill and logical output slicing. Callers need not align prompt lengths. Preparation covers every logical length1..512 at B1 and the configured physical batch before retaining decode, common sampling and reset traces.

Ordinary greedy feedback remains on device: the common sampler's `tt_out_tok` is the next decode input, and positions/RoPE advance in the graph. Explicit host-sampling/full-logit compatibility exists and is tested separately. No default host argmax, full-logit readback, eager sampling, Python token-feedback upload, single-chip or replicated-decoder fallback is selected. `runtime_audit.md` covers these boundaries, ownership and reset behavior.

## Capacity and serving contract

Context262144 is preserved with no reduction. Final measured loaded-model DRAM is13,857,710,080 bytes/device. B1/P8193 prepared, after-max-prefill and after-decode resident memory is identically19,072,073,728 bytes/device; B32/P8224 after complete preparation and lifecycle assertions is23,217,463,808. General capacity is34,078,723,072 bytes/device, already excluding the100,007,936-byte trace region. These are resident snapshots, not allocator high-water marks. Complete preparation establishes transient feasibility for the measured configurations; no extrapolated maximum physical pool is claimed.

`../context_contract.json` and `capacity_accounting.md` reconcile all-layer KV/reset costs, fixed/helper storage, CCL and remaining native/program/trace allocations without double counting. The conservative aggregate budget is Q262144 before pinned-plugin headroom: physical B1 uses8193 pages, B32 uses8224. A fixed B32 generator supports1..32 live/inactive requests; that does not promise32 simultaneous full-context requests. Other constructor batch sizes are implemented and some are focused-tested, but do not inherit full-context budget certification from these endpoints.

The entire physical cache pool is exclusively leased to one generator through every retained trace. Prepare/reset clear that pool; request release clears its GDN slot, with physical page reclamation/admission owned by the scheduler. Null-block reservation and per-request page rounding count against the pool; aggregate token sums alone do not guarantee admission. A long request must acquire distinct physical pages across the shared pool rather than repeat the short test's257-page slot pattern.

`serving_contract.json` pins vllm-tt-plugin `042a94863ad27d88207bcf71abdf67122c6f4c27` / vLLM0.31.0 and maps79 calls/features/declarations, with zero missing rows. These mappings use existing generator primitives; no vLLM adapter, registration, installation or server was started. Prefix caching is excluded for `recurrent_state`: KV reuse alone cannot restore48 GDN states. Existing-state resumed prefill passes. Async decode, speculation and device penalties/logprobs are not claimed; supported host-owned request processing uses the explicit full-logit boundary. Device stochastic top-k is1..32. See `serving_mapping.md` for the exact exclusions and translations.

## Sampling, profiling and capacity repair

Both common sampler contracts were compared. The common `models/common/sampling` split path fits state ownership, TP4 and stable `tt_out_tok`; Sampling1D is rejected for duplicate lifecycle/integration state and another checkout dependency, without a comparative latency claim. Physical top-k32 with semantic greedy k1 passes unique-winner and tie tests. Tie selection need not match HF's lowest-index choice, but always selects a true maximum. No custom sampling algorithm is introduced. `sampling_choice.md` records the comparison and borrowed-CCL ownership repair.

Advice-enabled `tt-perf-report` output is under `perf_terminal/`. Reduced real-layer profiling measures sampling/readback at0.589ms,18.4% of that reduced token-out path; it does not dominate the full model. Candidate gathers move only local top32 values/indices, not full vocabulary. Cross-window profiler-drain gaps are excluded from model-stall interpretation. Adapted same-policy split-two and whole-three-reader LM heads pass correctness but lose in complete head/staging/sampling timings; the two-reader whole head exceeds L1. Uninstrumented confirmation retains the current head (`lm_head_uninstrumented.json`).

The full32.29ms/token result is1.040x the31.055ms best-observed decoder-layer stack bound (`layer_stack_lower_bound.json`). The bound uses prefix512/repeated per-kind weights, so the1.236ms difference is not an exact terminal-cost subtraction. The separately observed token-out/logits-only gap is0.549ms/step. Final norm/head, sampler, readback and orchestration evidence is in `perf_terminal/profiling_analysis.md` and `performance_summary.json`.

B32 preparation initially failed from retained native reshape mappings. The native factory/reader now store one mapping per tile row for equal tile-aligned widths and reconstruct column offsets; general shapes retain the original mapping. Decoder math, precision and topology are unchanged. Independent2322-case CPU proof,36-case all-rank device/trace tests, native Watcher, complete B32 preparation and all-layer acceptance pass. No production cache eviction, head serialization, context reduction or reset workaround was introduced. See `AUTOFIX.md`, `AUTODEBUG_b32_capacity.md` and `reshape_mapping/independent_review.md`.

Exact commands, failures, repairs and artifact scopes are in `commands.json` and `work_log.md`. Raw large profiler/Watcher/census logs remain local beside compact review evidence.
