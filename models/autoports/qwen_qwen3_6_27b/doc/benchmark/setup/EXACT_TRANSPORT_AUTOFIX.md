# Exact synthetic prompt transport repair

The failing performance contract requires every measured input to contain exactly 4096 tokens (and 128 or 32768 for lone-user rows). Upstream vLLM's RandomDataset generates token IDs, then decodes and re-encodes text. This tokenizer does not preserve the generated lengths through that roundtrip. Server usage therefore reports input lengths above the requested count.

`../bench_exact.py` replaces only `RandomDataset.generate_token_sequence` in its process. It keeps upstream seed/RNG, allowed vocabulary, sequential ID construction and request sampling. The original ID list becomes the OpenAI completions `prompt`. The wrapper then runs upstream `vllm bench serve` CLI; scheduling, endpoint request function, streaming statistics and reported server usage remain unmodified. No upstream or installed-plugin files were edited. Each result gets `.prompts.jsonl` containing every input ID and hashes, plus `.prompts.json` with adapter/upstream fingerprints and result-file binding. Files are written before measurement and retained on failure.

The wrapper requires vLLM 0.26.0, the vLLM completions backend, random dataset, zero prefix/range, a tokenizer adding zero implicit special tokens, explicit output path and unique prompt prefixes. These are this stage's configurations. Accuracy continues to use native templated chat separately.

Validation: `benchmark-perf-client/bin/python .../doc/benchmark/setup/test_bench_exact.py` passes two CPU tests. The real pinned tokenizer generates reproducible, distinct, special-token-free inputs of exactly 128/4096/32768 tokens. The unmodified upstream CLI against an owned mock streaming endpoint completes three measured requests with exact server-reported counts, preserves token IDs, excludes its explicitly enabled readiness probe from measured rows and retains its normal detailed timing fields. Initial test expected a default probe; upstream 0.26 defaults readiness checking to zero seconds. The corrected test explicitly enables a probe; initial failure log is preserved. No TT device or live server was contacted by these tests.
