# Benchmark client setup and protocol

Two independent CPU client environments are ready. `recommendations.json` contains exact paths, selected task variants, model revision, generation settings, reference scores and protocol differences. `setup_times.json` records individually timed provisioning operations; the recommendation file records total elapsed setup wall time including inspection, downloads and failed/retried dependency installation. The server environment was untouched.

The frozen common manifest uses MMLU-Pro 280/12032 and IFEval 256/541. Preparation uses `--reuse-manifest` over the installed `ci-v1-reasoning.json`. Its selected IDs, content/population hashes and few-shot hashes are retained under `subset-common`. MMLU-Pro has upstream 5-shot subject examples; IFEval is 0-shot. Questions have not been selected against model scores. Size any reduction from the parent's measured speed and use the same deterministic seed.

Use native server chat formatting exactly once through the benchmark runner's LocalChatCompletion backend: it passes structured message turns and applies no local textual wrapper. Generation is the exact model-card general-thinking recommendation: temperature 1, top_p .95, top_k 20, min_p 0, presence_penalty 0, repetition_penalty 1, enable_thinking true and 32768-token cap. `until=[]` deliberately removes MMLU-Pro's textual Question: stop to avoid truncating reasoning; native EOS remains. Upstream 5-shot/answer-is-(X) recipe is retained because the upstream scorer requires it; the model-card JSON format is recorded as a reference difference. Final-answer content must be separated from reasoning by the server parser.

Reference: [exact model card](https://huggingface.co/Qwen/Qwen3.6-27B), [Qwen announcement](https://qwen.ai/blog?id=qwen3.6-27b). MMLU-Pro 86.2 and GPQA Diamond 87.8 are published; IFEval lacks a figure in these sources. GPQA was not selected because the official dataset is gated and existing credentials were absent; its failed preparation remains preserved. This is dataset setup, before timed evaluation.

Upstream vLLM v0.26.0 was built with its documented `VLLM_TARGET_DEVICE=empty` mode in `benchmark-perf-client` to avoid accelerator binaries. `perf_help.log` proves `vllm bench serve --help` starts. `model_card.md` is the raw README at the exact checkpoint revision. Package manifests and the source commit are preserved.
