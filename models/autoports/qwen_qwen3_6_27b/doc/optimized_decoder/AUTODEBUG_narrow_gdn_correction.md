# Narrow QKV/B_A residual weights and combine

This source-only implementation follows the measured zero-Z numerical control. No hardware was opened by this investigation; device results below were reported by the parent and remain attached to their original run artifacts.

## Evidence and retained math

Parent's zeroz148 setup zeros residual Z columns10240:16384 while retaining original primary and full residual physical width. Its512-step minimum PCC is0.9955427456 versus base0.995364; short B32 PCC0.999937. This provides a passing control for dropping the zero columns, without a precision-threshold change or weight-dtype change.

The first legal narrow152 implementation also passes: parent reports B32 short decode1.808873 ms and512-run decode1.819589 ms, minimum PCC0.9955427456, versus zeroz1481.825670/1.834453 ms. The measured15–17 us gain is smaller than the approximate54 us bandwidth-only lower bound for removed weights; the multi-op combine is therefore a concrete movement target.

## Exact weight packing and first legal control

`candidates/narrow_gdn_correction.py` is an immutable freeze over `zero_z_correction_on134.py`, generated by `make_narrow_gdn_correction.py`. Opt-in `narrow_gdn_correction=True` takes the already quantized interleaved TILE BFP8 residual, device-slices columns[0:10240] and[16384:16512], and concatenates them to logical N10368 before the existing DRAM sharding setup. Every boundary is a whole32-column tile; there is no new quantization or original-weight transformation. Primary upload and sharding remain unchanged. `narrow_gdn_verify_setup=True` requires exact readback equality of retained values and zero removed Z at setup only.

With eight DRAM banks and unchanged C40/R5, alignment is40 tiles. Primary logical N16512 remains physical N16640 (13 tiles/worker); residual logical N10368 becomes physical N11520 (9 tiles/worker). Exactly27,852,800 BFP8 weight bytes are removed. Activation K partition and input memory configs remain identical across primary/residual, preserving the existing shared activation. Default narrow flag isFalse.

All four existing correction routes are covered: `_linear` shared-L1 and fallback, flat-prefill helper, and chunk-add-prefill helper. The first legal `_combine_correction` exports the two FP32 partials, slices QKV/Z/B_A, uses native `ttnn.add(...,dtype=ttnn.bfloat16)` on QKV and B_A, uses **native add(primary_Z,0.0)** for Z, then concatenates. No standalone conversion substitutes for the old Z +0 -> BF16 boundary. All public forward methods, recurrence, state handling and layer dispatch are unchanged. Existing arbitrary logical tails follow the same chunking and padding; no alignment restriction is introduced.

Changing residual N changes output blocking and may change FP32 partial values even with exact retained weights. This is measured separately rather than assumed bit-exact. Full decoder PCC/state gates remain unchanged.

## Optional one-op combine

`candidates/narrow_gdn_combine.py` exports `narrow_gdn_combine(primary,residual,output=None,cores=None)`. `candidates/narrow_gdn_fused_combine.py` adds only an opt-in `narrow_gdn_fused_combine=True` branch to the narrow candidate; `narrow_gdn_combine_cores` can cap its worker count. Enable both narrow flags. The legal native multi-op path remains available as the control.

The generic op reads FP32 primary/residual tiles directly through TensorAccessor. This supports the native L1 WIDTH_SHARDED decode outputs and DRAM-interleaved prefill outputs, using each input's actual padded width stride. Global output N has516 tiles. Columns0..319 read matching correction tiles; columns512..515 read correction320..323. Z tiles320..511 use a persistent FP32 +0 tile prepared once per worker. Compute explicitly unpacks all FP32 CBs directly to DST, avoiding the TF32 truncation previously diagnosed in this stage. It performs FP32 SFPU addition for every tile, including Z +0, then explicit BF16 RNE and packing. There is no shortcut that silently changes the Z rounding boundary.

Output is the final logical `[B,S,16512]` BF16 DRAM tensor. There are no runtime exports, host conversions, slices, reshards or concat in the helper. Output can be supplied to retain a stable address. Tile traversal uses padded sequence rows, preserving logical tails. Two-page primary/residual/output queues plus one constant-zero tile occupy24KiB/core. Writer barriers protect output CB reuse; the constant-zero CB is held until all tiles complete and then popped. Input pages are full aligned4096-byte FP32 tiles, output pages2048-byte BF16 tiles. Device compilation, exactness and speed remain unverified for this fused variant.

## Focused verification artifacts

`tests/test_narrow_gdn_source.py` passed without TTNN import. It checks deterministic hashes/generation, whole-tile weight ordering and physical geometry,36 address/layout cases including B1/B3/B32 and S1/17/32/33/65/641, and source preservation of public forwards/recurrence. It checks direct FP32 unpack and absence of movement/host-conversion calls in the fused helper. Result: `narrow_gdn_cpu_checks.json`. Python compilation passes for candidates and both authored device runners.

`tests/run_narrow_gdn_projection_probe.py` builds the real-weight zero-Z baseline and narrow candidate with inherited evidence policy. It verifies exact primary and retained correction weights after sharding; compares primary/residual FP32 partials and final outputs on captured decode input, B32 decode, S33, B3/S33 and S641 tail; and reconstructs a full zero-Z residual **on device** from each narrow partial to compare the combine against native old add on identical partials and matching memory layout. It reports changed-N projection deltas but requires exact BF16 bits for same-partial combine. Run against the fused candidate with `narrow_gdn_fused_combine=True` in the inherited policy to test that branch. Diagnostic readbacks carry no perf claim.

`tests/run_narrow_gdn_combine_probe.py --candidate models/autoports/qwen_qwen3_6_27b/doc/optimized_decoder/candidates/narrow_gdn_combine.py --output <artifact>` isolates the fused helper without a model. Nine cases cover DRAM and native40-core L1 shards, B1/B32 decode, nonaligned prefill and long tails. Inputs include signed zeros, cancellation and exact BF16 midpoint values. Reference is native FP32 add with a full reconstructed zero-Z residual; strict BF16 bit equality, repeated equality and stable output address are required. This runner is authored only; parent executes it under the serialized device wrapper.
