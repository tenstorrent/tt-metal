# Geometry search interpretation

Decode uses MatmulMultiCoreReuseMultiCastDRAMShardedProgramConfig with model-specific readers. The public fields in ttnn/cpp/ttnn/operations/matmul/device/config/matmul_program_config_types.hpp expose in0_block_w, per_core_M, per_core_N, fused_activation and num_workers_per_dram_bank. Output block/subblock fields are not exposed by this kernel; the absence of those fields in generic advice is not an ignored tunable. Prefill2D and fused CCL candidates expose those fields and are measured separately.

Every material role is tested at BFP4/LoFi with real weights and the complete4096+128 TP4 layer path. For logicalB1, physicalM=32 and per_core_M=1. Input storage core count is distinct from DRAM reader/compute workers:8 banks times selected readers. K in tiles is160 for mix/gateup,48 for output,136 for down. Each candidate's shard K width is K_tiles/storage_cores; candidate block divisors and complete policies are in final_geometry_candidates.json. per_core_N is ceil(physical_padded_N/(32*storage_cores)) as recorded in the actual op attributes. Reader-dependent padding is removed internally before outputs affect the model.

The full-layer sweep includes mix K2/4/5/16/20, gateup K2/4/8/16/20 across the initial and final-family sweeps, output K2/3/6/12/48 and down K4/8/17/34/136, with matching storage grids. Smaller cores and non-power-of-two K blocks are explicitly tested. Final selected runtime rows, reader counts, physical shapes, activation/weight memory and dtype/fidelity will be verified from final-profile operation CSVs. No kernel-generic default is changed.

Results and any precise failure are retained in candidate_summary.csv. Close winners must reproduce when combined; final default measurements are authoritative. Wider working input shards count their reshape/reshard cost in the complete layer timing. The one-/two-/three-reader alternating microbenchmark additionally reports physical/logical bandwidth, padded weight bytes, per-reader row size, burst estimate and compute/data-movement timing before integrated reader selection.

Final wider-K closure: `large_k_final` and `multishard_k` include mix K32/40/80, gate/up K32/40/80, out K24, and down K34/68 with wider activation storage and/or additional readers. The current factory permits a K block spanning multiple input shards at per_core_M=1. Legal K40 mix, K32 gate/up with three readers, K24 out, and K34 down with two readers pass but are slower; wider settings have explicit allocator/CB admission evidence. Gate/up K2 is retained only after these legal larger-block comparisons. See their candidate JSON and candidate_summary.csv; failures include both geometry adaptation and precision/readers adaptation, not one unmodified API call.

The padded mix winner uses R1 with weight_pad_readers=2; thus its physical N is4608 for linear attention and3584 for full attention. The final_padded reader microbenchmark repeats R1/R2/R3 with this policy; R3 uses lcm(3,2) padding, and the resulting physical bytes are included in the comparison. Down R1 uses5120 output columns; gate/up R2 uses8704; out R2 uses5120. Padding columns are sliced before they enter model computation.

Historical BF16-input prefill output-subblock screen (superseded by the v4 BF8 closure below): `prefill_subblocks` tests role-specific mix grids10x10,8x8 and11x8 with subblock heights1/2/4/8. `prefill_subblocks_confirm` repeats control/candidate/candidate/control with25 warmed prefill timings at4096+128. Linear attention does not reproduce a gain and keeps11x10/h1 (mix subblock1x2). Full attention consistently improves and selects11x8/h4 for mix alone, yielding4x1 rather than1x1 at4096. Column gate/up retains its measured defaults; native prefill row projections have the separate closure below. Role-specific height selection reduces to legal divisors for all shorter logical chunks. Final nonaligned coverage is rerun after this selection.

Native prefillRS final geometry: outK48/downK17,H4,sub2x4,8x8 grid,N20 at exact4096-row B1 chunks. See [prefill_rs_geometry.md](prefill_rs_geometry.md) for precision-locked largerK, output-height/subblock comparisons, role-isolated capacity adaptations and the single-block endpoint. All other shapes use the same hidden-sharded TP4 separate matmul/RS contract.

Final v4 BF8 column closure supersedes the earlier K4 column selection above: native linear mixK16; full mixK4; separate gate/up11x8,K20,H8,sub8x1. OutputH is reduced to a divisor of runtime per_core_M, then subH to a divisor of actual outputH, with subH*subW<=8; native outputW remains per_core_N. The new2049-token boundary exercises per_core_M9/outputH3/subH3. Paired native separate means6002.47/6271.89us beat packed6197.31/6634.49us. Coherent L1, safe padded-interleaved larger-K endpoints, and shared fused AG+gate/SiLU all pass but lose or tie.
