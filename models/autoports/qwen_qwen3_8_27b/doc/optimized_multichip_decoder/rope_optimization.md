# Batched RoPE movement closure

The v4 B32 full-attention decode profile has 64 per-user rotary operations and 202 slices. Packing users as independent sequence rows reduces rotary calls to two without changing positions, partial rotation width64, or the untouched192-channel tail. Q and K can reuse transient packed coefficient tables within one invocation; there is no table cache across traces or requests.

Decode uses row-major conversion to remove the physical32-row padding of each logical one-token user before packing. The packed operation sees `[1,H,B,64]` and coefficients `[1,1,B,64]`. Its output is sliced to logical B before unpacking, so odd batches cannot mix physical padding with users. The original path remains the control. The first integration rejected an L1 interleaved Q at SDPA; final concatenation now preserves the original DRAM boundary. This was a layout repair, not rejection of the optimization. The original adapter is retained in `prefill_source_provenance/packed_rope_adapter_v1.py`; each successful run hashes the actual adapter used.

`packed_rope_exact_dram.json` records36 bitwise exact Q/K comparisons using real layer weights and recorded activations on all four devices: B8,9,16,17,31,32; three distinct/permuted position assignments; untouched tail equality. Full decoder comparisons additionally check output/state PCC and trace replay.

B32 same-harness warmed traced host decode: control1473.02us, shared tables997.78us, separate tables1009.94us; all have min decode PCC0.9999421387. These are candidate host timings, not device telemetry or final-default numbers. Subsequent threshold closure is recorded below; final device profiling is part of v5 verification.

Prefill is a separate candidate: for tile-aligned sequence S, permute `[B,H,S,64]` to `[H,B,S,64]`, view as `[1,H,B*S,64]`, and fold coefficients in the same user/sequence order. Tile alignment allows zero-copy reshape; DRAM accommodates the large input. Inverse reshape/permute preserves user boundaries. The measured v4 B32 prefill user-loop spans are2815usQ+550usconcat and1212usK+98usconcat. Global rot/rest slices and final width-concats remain. The candidate compares replacement permutations against these user loops; decode is unchanged. Public ragged/non-aligned inputs retain the existing padding and logical slicing contract.
