# AutoDebug: Qwen3.8-27B B8 slot-dependent generation

Investigation date: 2026-10-24 UTC. Checkout HEAD: `cdcf1091d55e793f68fd46acdbe80372337e1c34`, with in-progress stage06 changes. Inspection only: no device execution, reset, source edits, or AutoDebug relaunch. This report is the only file written by this investigation. Three xhigh investigators examined decoder mapping, terminal/sampling, and trace/state ownership; the headline was independently checked against the lowered implementation.

## Leading finding: rotary computes different slots with different precision

**There is a concrete upstream rotary configuration defect, and it is the strongest explanation of this failure.** The multi-tile rotary factory ignores the requested FP32 destination mode for core group 1, while honoring it for group 2. Production prefill packs users into the sequence axis, so the work split assigns corresponding head/token positions in different slots to different precision modes. This supplies an explicit mechanism for deterministic slot-dependent logits before autoregressive feedback.

The configuration contradiction is established by source. Its responsibility for the entire all64 B8 token failure is **not yet experimentally closed**: the failing benchmark did not persist tokens or logits, and this investigation did not execute a repair. Do not label it proven to be the only cause. Equally, do not dismiss it as ordinary quantization variation: the caller requests one precision, but the callee selects precision by row placement.

6. **[Factory line815](/home/mvasiljev/tt-metal/ttnn/cpp/ttnn/operations/experimental/transformer/rotary_embedding/device/rotary_embedding_program_factory.cpp:815) gives group1 `ComputeConfigDescriptor{}`. For this model, the discrepancy is FP32 destination mode; both groups use HiFi4. The source comment says the discrepancy preserves legacy behavior, which does not make the caller's precision contract consistent.
7. This is executable configuration, not unused metadata: [program.cpp:559](/home/mvasiljev/tt-metal/tt_metal/impl/program/program.cpp:559) copies the descriptor flag into `ComputeConfig`; [kernel.cpp:1070](/home/mvasiljev/tt-metal/tt_metal/impl/kernels/kernel.cpp:1070) forwards it into JIT build options. Both groups execute `rotary_embedding/device/kernels/compute/rotary_embedding.cpp`; its rows perform half-rotation/sign multiplication, sine/cosine products, and addition (lines128–167). BF16 input/output does not imply identical intermediate arithmetic under these two destination modes.
8. Different Q, and potentially different BF8-quantized K, feed attention. Attention/residual/MLP changes propagate into later layers and terminal logits. Greedy selection can then diverge at a narrow top-two margin, after which different feedback tokens amplify the difference. This last numerical propagation is a hypothesis to measure on the actual failing inputs, not a claim that every differently configured row must change bits or every changed logit must change the winner.

### Concrete work assignment

The following instantiation uses **110 compute/storage cores**. The prior measured [prefill_ops.csv:13](/home/mvasiljev/tt-metal/models/autoports/qwen_qwen3_8_27b/doc/optimized_multichip_decoder/tracy/final_profile_l3/prefill_ops.csv:13) reports110 used/available worker cores for rotary Q; line18 confirms K. This agrees with the Blackhole build log's `NUM_L1_BANKS=110` and stage05's11×10 device geometry. The selected11×8 matmul grid is not the rotary grid. The decisive follow-up should record `mesh.compute_with_storage_grid_size()` directly; the factory reads that value, and these numerical boundaries must be recomputed if it differs.

For `N=H*B*(P/32)` tile rows, if `N>110` and is not divisible by110, set `q=N//110`, `r=N%110`. Group1 owns the first `r*(q+1)` rows; group2 owns the rest. If all work divides evenly, all cores belong to group1. A packed row's index is

`R = h*(B*P/32) + slot*(P/32) + floor(token_position/32)`.

All coordinates below are zero-based. The two width tiles belong to one work row; they do not double `N`.

|Case|Q rows / group1 prefix|K rows / group1 prefix|Consequence|

|B8, physical64|96 /96|16 /16|Both operations use group1 throughout; this particular mixed-precision boundary cannot cause slot dependence.|
|B8, physical96|144 /68|24 /24|Q head2 changes mode within the slot axis; K is uniformly group1.|
|B8, physical4096|6144 /5264|1024 /340|Both Q and K change mode within slots.|

For the **actual reduced permutation**, cases are `[(101,33),(102,65),(101,33),(103,35),(104,33),(102,65),(103,35),(101,33)]`. The permutation is `[7,3,5,0,6,2,4,1]`; its inverse is `[3,7,5,1,6,2,4,0]`. Case1 moves from slot1 to slot7. In the physical96 bucket, Q head2 at position64 moves from `R=53` (group1, FP32 destination off) to `R=71` (group2, on). Indeed, its entire valid head2 sequence changes mode. Case5, with the same token/length, moves slot5→2 and remains on the same mode. All physical64 cases remain uniform.

**Falsifiable prediction:** if this is the only source of the reduced discrepancy, original case1 should be the only request with changed valid prefill logits under this permutation; case5 should remain exact. That mapping is not present in the log, so it is a proposed check, not an observed match. It also predicts that original duplicate rows1/5 can match while the permuted copies differ. The existing test aborts before checking duplicates.

BF8 KV rounding does not remove this candidate for the reduced case: K uses group1 uniformly, while the affected Q feeds SDPA directly. In the reduced `[layer0,layer3]` stack, a Q-only change can alter prefill logits without changing layer0 recurrent state or layer3 cached K/V. Its next decode uses explicit token105 in every slot; that decode can consequently remain exact. Such a passing decode comparison would not falsify this prefill defect. In the64-layer stack, later layers can carry the changed hidden states into their own caches.

For **B8/4096**, Q head0–4 remain group1. Q head5 uses group1 for slot0 and the first512 tokens of slot1, then group2 for the rest of slot1 and slots2–7. K uses group1 for slots0/1 and the first2688 tokens of slot2; the remaining slot2 tokens and slots3–7 use group2. Thus even identical inputs get different requested-vs-actual precision patterns. If inputs to the first full-attention layer are exact across users and no other defect exists, slots3–7 share a pattern and should remain an equality class at that layer. Preserve actual per-slot data to test this prediction.

B1 can still pass: there is no second slot to compare, and short readiness prefill may use only group1. Even B1/4096 can contain both core groups, but it does not test permutation across users. Passing B1 accuracy therefore neither repairs nor falsifies the defect. Conversely, passing exact decode RoPE packing tests is expected: the packed decode shapes use only group1.

The earlier reduced mixed-slot checks mostly prove repeated requests/state isolation and often emit token220. Equal sampled tokens discard most information about logits and margins. The new actual-logit check exposes a discrepancy that such checks can miss.

## Smallest discriminating probes and intervention

These are follow-ups for the hardware-owning caller; none were executed here.

1. **Capture evidence before assertions.** Persist every slot's tokens, first divergent step, and all per-row prefill/permutation max differences before failing. For the new reduced case, print all8 inverse-mapped differences and duplicate comparisons even if one fails. Include positions, original/permuted slot IDs, physical bucket, device grid, and source hashes captured at process startup. This directly tests the case1 prediction without assuming missing correspondence.
2. **Isolate production RoPE with frozen inputs.** Use real normalized Q/K from B8/P96, preserve exactly the same input bits and coefficients under slot permutation, and compare all4 devices immediately before and after rotary. Run the production requested-FP32 configuration. Record per-head/per-slot/per-token changed counts, first changed coordinates, max absolute error, and the untouched192-channel tail. P64 is a same-family control where both operations occupy group1 only. B8/P4096 then checks the original benchmark geometry. No full64-layer run is needed to expose the factory defect.
3. **Make the smallest intervention at its owner.** The repair candidate is to give multi-tile rotary group1 the same requested compute configuration as group2, preserving this caller's FP32 policy. The single-tile factory already configures both groups explicitly (`rotary_embedding_program_factory.cpp:404–425`). This is preferable to altering residual layout, sampler strategy, or tolerances. A uniform-FP32 rerun is the causal test. Explicit uniform-FP16 RoPE or the existing per-user path can be temporary diagnostic controls; neither proves preservation of the requested production FP32 policy. Do not mutate shared `ckc` globally as a production workaround, since other operations use it.
4. **Recheck reduced prefill, then all64 with fixed feedback.** First rerun all reduced prefill duplicate/repeat/permutation comparisons after the rotary correction. Next, for identical4096 prompts, save full-model prefill logits before sampling and feed the **same explicit next token to all slots** for several decode steps. If divergence first appears during prefill, bisect layer outputs, prioritizing the first full-attention layer3; then Q/K normalization→RoPE→attention→residual/MLP. If divergence first appears in decode, compare eager and traced decode from the same cache snapshot, then native RS and terminal boundaries. Fixed feedback prevents one initial token difference from obscuring the first fault.
5. **Separate exact equality from token stability.** Report bitwise row equality, changed-element counts, finite status, max/RMS deltas, per-row top-two token IDs/logits/margin, and whether each sampled token is a valid maximizer. If two rows differ by at most `epsilon` elementwise and a reference row has unique top-two margin `>2*epsilon`, the other row's argmax cannot change from that perturbation alone. Ties require separate reporting. A small max delta or high PCC cannot show that the observed token change was benign or even caused by that measured delta. Evaluate this at the first divergent step with identical prior feedback, not after trajectories have separated.
6. **Close the original contract.** Rerun B8 all64/4096/128 with retained per-slot outputs, repeated requests, original tracking/program-cache settings, and no recapture/host refresh in steady state. Revalidate B1 accuracy because honoring FP32 on previously defaulted rows changes actual arithmetic. Then continue B16/B32 and the32768-input chunked case; do not infer their outcomes from B8 alone.

## Other Potential Issues / findings not promoted to causes

- The unused page-window tail clamp and external-map row-alignment validation address real boundary contracts but cannot explain this all4096 start0 request. There are exactly128 required pages, and the1024-entry per-slot map covers them. The later clamp leaves all128 indices unchanged. The current reduced probe passed its near-end odd128 continuation checks before reaching the permutation assertion.
- A matching packed/unpacked terminal result does not rule out an upstream defect: both terminal variants consume the same possibly slot-dependent hidden states. Nor does terminal-only replay timing prove replay output correctness.
- Sampler tie semantics remain a useful explicit test contract, but varying seeds with k1 is not a supported root cause. No evidence justifies switching from the canonical sampler to hide this failure.
- No evidence supports a device hang, teardown deadlock, cache-capacity overflow, or hardware reset as the explanation. The logs reach readback-backed assertions and ordinary device closure. Missing first-step/slot data must remain missing, rather than being inferred from the0.0625 scalar.
