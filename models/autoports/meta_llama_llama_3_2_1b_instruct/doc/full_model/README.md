## Implementation

The model wrapper uses the optimized multichip decoder stack directly:

- exact 1x8 T3K mesh validation, no single-chip fallback;
- 16 `MultichipDecoder` layers created with `OptimizedDecoderPrecisionPolicy`;
- replicated token embedding and final residual boundary matching the optimized decoder;
- final distributed `RMSNorm1D`;
- tied LM head from `model.embed_tokens.weight`, vocab-sharded over 8 devices and split into 8192 and 7840 column chunks per device;
- paged KV cache with page block size 64, max batch 32, max sequence 4096;
- decode updates `current_pos` and RoPE indices on device with `ttnn.plus_one`;
- `logits_to_torch` is kept for readiness diagnostics and is not used by free-running decode.

The carried decoder policy is unchanged: BFP8 attention weights and KV cache,
BFP4 MLP weights, BF16 activations/residual and terminal path, BFP8 CCL policy,
one local KV head per chip, replicated page table, prefill K/V fill tensors cast
to the BFP8 cache dtype, and the optimized inter-layer residual layout.

## Sampling And Trace Contract

Greedy decode uses a custom split-vocab greedy sampler:

- local shard top-k with `max_top_k=32`;
- async all-gather of only candidate values and ids, not full vocab;
- global argmax over gathered candidates;
- direct write into the persistent decode token input tensor;
- no force-argmax, no host argmax in decode, no full-logits decode readback.

Top-k/top-p requests use `models.common.sampling.SamplingGenerator` with its
internal trace. The smoke run used `top_k=16`, `top_p=0.9`, `temperature=0.8`
and captured a second sampling trace.

Trace audit artifacts:

- `artifacts/trace_evidence/trace_audit_greedy_default_128.json`
- `artifacts/trace_evidence/trace_audit_topk_topp_smoke.json`
- `artifacts/trace_evidence/trace_audit_page_table_refresh.json`

Greedy trace evidence for 128 generated tokens:

- model trace captures: 1;
- model trace replays: 126;

- token refreshes: 1;
- current-position/RoPE refreshes: 1;
- page-table refreshes: 1;

- full-logits decode readbacks: 0.

The page-table focused audit covers both unchanged and changed-page-table cases:
the unchanged replay did not refresh token, position, RoPE, or page table; the
changed replay copied the page table only.

## Runtime Fallback Audit

| Boundary | Audit |
|----------|-------|
| Model path | Requires 1x8 T3K and uses the optimized multichip decoder stack; no single-chip or replicated fallback path is accepted. |
| Cache ownership | Generator owns `self.kv_cache`; external low-level callers must pass the same cache handle. Reset zero-fills cache and keeps weights/traces allocated. |
| Host logits | Prefill and readiness diagnostics read logits on host. Decode token-out does not use host argmax or full-logits readback. |
| Sampling | Greedy uses split greedy. Top-k/top-p uses common sampling with internal trace. Force-argmax is disabled. |
| Token feedback | Free-running decode writes sampled tokens into the persistent decode token input tensor and advances position/RoPE on device. |
| Page table | Copied at setup and only refreshed when marked changed. |
| Reset | `reset()` clears KV cache, sampling output state, timing metadata, counters, and generation metadata without freeing reusable traces or weights. |

## Limitations

- High-level readiness generation is batch-1, padded internally to the decoder's batch-32 shape.
- Max sequence is 4096 because the underlying `Attention1D` allocation caps total KV tokens at 128K for batch 32.
- No vLLM adapter is included in this stage.
- TTNN emits an allocator warning when the sampler trace is captured after the model trace exists; repeated traced accuracy, free-running, and smoke checks passed.
