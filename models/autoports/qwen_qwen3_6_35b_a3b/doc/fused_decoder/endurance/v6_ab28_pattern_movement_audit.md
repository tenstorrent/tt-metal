## Concrete removal candidates

1. **Linear post-attention normalization placement.** `_forward`:1782 moves residual DRAM → WIDTH_SHARDED L1. `norm`:1004–1007 records that placement and immediately returns input to DRAM; all explicit arithmetic remains DRAM. `norm`:1094 restores the original shard; `_forward`:1785 immediately returns to DRAM. Profile steps131/132 and172/173 are exactly these four operations (first replay 2.984/1.518/1.493/1.478 μs). Remove the two outer placement requests only in the linear branch; `norm` then records DRAM and its two placement calls are identities. Preserve every arithmetic instruction, precision flag, residual boundary, and full-kind early branch. The old `mlp_norm_shard_dram_0.json` decision optimized **native** RMSNorm; it does not justify these transports after v6 replaced linear postnorm with ordered explicit arithmetic. No tensor arithmetic observes the temporary shard. Nonaligned prefill takes neither outer placement request and must be AST unchanged.

2. **Selector indices tilize/untilize.** `InlineSelector.__call__`:1986 returns UINT16 ROW_MAJOR DRAM `[1,1,1,8]`. `_moe`:1495 calls the module's `reshape` wrapper, which always converts to TILE (:14–16); :1501 immediately converts indices back to ROW_MAJOR `[1,1,1,8]`. Profile steps187/188 confirm UINT16 tilize/untilize (first replay1.959/1.150 μs). Replace only the indices reshape at1495 with `ttnn.reshape`; retain scores' TILE geometry. This differs from the previously rejected **router scores** delayed-tilize experiment. Sparse device validation requires ROW_MAJOR, a single stick, and exactly the selected indices (`ttnn/cpp/ttnn/operations/matmul/device/sparse/sparse_matmul_device_operation.cpp`:388–399). No arithmetic or sorting boundary changes. Full-kind has its own early branch and is unchanged; multi-token prefill uses native TopK. Public singleton prefill also uses this same selector, so include it in tests.

## Completion implications

Do not carry historical “native prefill GDN plus exact final-state scan”, “4096 physical linear chunks”, “native linear gated RMSNorm”, or “no transpose feeding runtime matmul” into final current-source claims. ab28 computes full exact64chunk outputs/state, uses linear64/full256 internal planning, and explicit gated normalization. [Formatted integration proof](v6_triangular_formatted_integration_build.json) and source lines establish that distinction.

Next minimal experiments are the two transport candidates above; they are independent and can compose. All further items labeled untried are concrete hand-off work, not measured wins or grounds to weaken gates. Pattern coverage alone does not satisfy the optimize Stop Rule; use the parent's measured device-time ledger. Final warmed prefill, traced decode, current-source profile, context, watcher, endurance and independent stage-review remain separate requirements.
