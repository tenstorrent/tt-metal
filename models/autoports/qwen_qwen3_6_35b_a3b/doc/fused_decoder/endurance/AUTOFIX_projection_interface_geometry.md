# Projection producer/consumer geometry audit

Source-only, 2026-11-13; no device execution or runtime edits. Scope is the existing fused projections and their immediate producers. Current measured full-kind workloads are BF16 `32×2048×9216` (~81 us) and `32×4096×2048` (~40 us), from `profile_precision/tracy/layer_3/decode_perf_report.txt`. These are kernel measurements, not proposed-config timings.

**The current pipeline does not force block2 on a 32-core input.** `matmul_device_operation.cpp:1722–1738` explicitly exempts the qualifying multicore pipeline from both K/block and shard/block divisibility rules. Its reader `reader_dram_sharded_multicore.cpp:122–138` walks successive storage shards within one requested block. `endurance/projection_precision.json` already records successful block4 calls on the then-current 32-core input (FP32 relative L2 .0003303634; precision-only, no timing). Therefore first compare block2 versus block4 with the existing RMSNorm producer, separating streaming-block effects from normalization changes.

Prior experiments: `work_log.md:113–135` records one/two/three readers, three-worker pipeline, and six-worker pipeline; six was slower. `pipeline3_grid64_0.json` measured .963585 ms and `_3.json` .663833 ms on the historical source. A single-reader block8 OOM does not establish a pipeline block4 OOM: they use different buffering. The old native linear recurrent projection is now ineligible for numerical reasons; those historical timings are not current acceptance. No recorded 16-core RMSNorm producer or timed new 6144-column Q/Z pipeline comparison was found.

All following candidates retain HiFi4, FP32 destination accumulation, BF16 operands/output, no fused bias/activation, three workers/bank, full 32×32 tiles, L1 width-sharded row-major A/output. Let B be runtime DRAM-bank count. Weight shards remain `(K, ceil(N/(96B))*96)` across all B banks. The numeric examples below use B=8, matching this workload's bank arrangement; setup must derive B rather than hardcode it.

For Q/Z add only `output_only_packed` to setup's decode projection keys; existing `linear()` already dispatches dictionary members through the pipeline. Preserve generic prefill and ordered K/V/A/B. The exact linear input norm currently yields DRAM and is also consumed by the ordered branch: this candidate does **not** justify changing its arithmetic or forcing all branches to a sharded input.

For full packed 16-core production, give only the full-attention input norm its own `(32,128)` width shard and make attention-packed `im` identical. Current `norm_memory` also feeds post-attention MLP norm, so changing that shared field would broaden the experiment. Layernorm validation accepts row-major prefix grids, `block_h=1`, `block_w=4`, positive `subblock_w` dividing4, and a compute grid covering the shard grid (`layernorm_device_operation.cpp:240–280,371–459`). Let the existing auto-config derive these, or explicitly use a compatible subblock ≤4. No reshard is needed between this norm output and packed matmul when configs match.

For full output, `nlp_concat_heads_decode_device_operation.cpp:80–112` creates width-sharded output on exactly `num_heads=16` cores with `(batch_padded=32,head_dim=256)`. The current logical slice/reshape keeps one real token; verify its actual returned memory config when implementing, then reuse it as `im` instead of converting to the setup's 32-core shard. This avoids changing SDPA, gate, or concat arithmetic.

Native constraints and buffering: `matmul_utilities.cpp:470–495` requires pipeline flag, >=2 workers, no bias/activation/untilize, default tiles, tile-aligned K, L1 A and width-sharded row-major L1 output. Factory `:1314–1369,1424–1429` requires full-K row-major weight shards over all DRAM banks, activation shards covering K, KB>=1, and valid per-bank work splitting. `per_core_M=1` must equal padded M and shard height in tiles. Output core count must cover N with the requested per_core_N; preserve the existing ceil formula.

With 8 banks and3 workers: packed full has Nbt36, 12 columns/worker, two Dest passes of6; Q/Z has Nbt24,8 columns/worker, one pass; out-proj has Nbt9,3 columns/worker, one pass. All have CK=1. In this decode pipeline FP32 Dest holds the whole K per pass; block4 changes stream segmentation, not a required partial-sum spill. Approximate explicit FP32/BF16 DFB totals per worker (excluding metadata/programs/resident tensors) are packed full 296 KiB at block2 and440 KiB at block4; Q/Z336/528 KiB; out-proj334/406 KiB. Derived from factory `:1440–1510`: resident X=Kt BF16 tiles, two weight streams each `3*KB*ncp` BF16 tiles, output=`max_own` BF16 tiles. These are source estimates, **not allocation guarantees**.

Minimal measurement order: existing full packed block4 only; full concat input layout match only; Q/Z pipeline block2; then optional producer16/block4 if needed. Measure the complete producer/consumer region and unchanged full-decoder gates, since fewer normalization cores change reductions and the Q/Z native schedule can perturb BF16 outputs. No broader dtype or worker-count sweep is proposed.
