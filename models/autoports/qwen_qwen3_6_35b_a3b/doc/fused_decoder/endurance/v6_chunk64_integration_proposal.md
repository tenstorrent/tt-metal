# Chunk64 output/state integration proposal

Source-only review of `v6_inline_router_silu_chunk64_double_single.py.snapshot`, SHA256 `dcaa36081fbce0169fb625a7ff2438643b0180a6a34379d96694330b6cdb668c`. No decoder, existing helper, or production source was edited. No hardware ran. The full output component is independently frozen in `tests/v6_chunk64_output_probe.py`; its CPU transcription is exact at lengths 128/127/65/1 with zero and nonzero initial state. This proposal does not assert integrated correctness.

## Smallest structural change

1. Replace the linear-prefill native chunk32 output plus custom chunk64-state pair at snapshot lines 741–758 with one full chunk64 helper call. Expand normalized q and k from 16 to 32 heads, permute q/k/v to `[1,32,S,128]`, and beta/g to `[1,32,S,1]`, all FP32. Call the component's full output/state graph with the current FP32 state. Use its BF16 `[1,S,32,128]` output, and copy its final FP32 state into the existing stable state tensor. Embed the helper source in a new isolated snapshot; the diagnostic imports are not a production dependency.
2. For linear attention only, plan relative to the public call: `(offset, min(64,S-offset), start_pos+offset, None)` for offsets 0,64,128,... . Absolute start does not enter the chunk-boundary decision. Full-attention/paged-KV planning remains its existing independent path. A later bounded optimization can use multiples of 64, provided every internal boundary remains a multiple of 64 relative to the public call. If preserving the `chunk_size` setup parameter, round its linear execution bound to a positive multiple of 64 rather than adding a public sequence-length restriction.
3. Pass explicit prefill intent into the linear branch of `_forward`; an internal tail of one token must not select `_recurrent_step`, decode normalization, or decode sharding merely because its tensor has one row. Keep the existing one BF16-to-FP32 cache boundary at the beginning of the public prefill call; never round the recurrent state between internal chunks.
4. Preserve logical S through projection, causal convolution, and cache writes. The convolution update `history[:,S:S+3,:]` must use the real token count. Let only the chunk helper pad q/k/v/g/beta to 64; its padded g and beta are zero, so padded steps neither decay nor update state. Never pad hidden rows and then let their projected gates enter recurrence: zero hidden rows still give a nontrivial learned g after the lookup, and convolution history can make their q/k/v nonzero.
5. Handle the output-norm alignment boundary locally, as described below. Keep residuals, MoE, and public output shape logical. Concatenate the trimmed chunk outputs in public order.

Pure-Python planner evidence `v6_chunk64_integration_plan_cpu.json` checks 36,864 cases: every length 1..4096 at starts 0,1,31,32,63,64,65,127,255. Coverage is exact; only the last chunk may be shorter than 64. This validates the proposed planner arithmetic, not existing runtime code.

## Output normalization options

**Minimal API-compatible option:** the existing `sigmoid_gated_rms_norm` requires a positive logical sequence multiple of 32 (`.../sigmoid_gated_rms_norm/device/sigmoid_gated_rms_norm_device_operation.cpp:88`). For a tail of n rows, pad head-first core `[32,n,128]` and `output_projected [1,n,6144]` to m=round_up(n,32), call the existing fused norm, crop its `[1,m,4096]` result back to n, then multiply the original logical `projection_z` and apply output projection. No padded token reaches state or residual paths. Examples: n=1 becomes m=32, n=33 becomes m=64. This addresses validation only; it preserves the existing sigmoid-times-Z rounding schedule, which is under numerical investigation.

**Stronger accuracy candidate:** generalize the existing explicit decode output norm and exact SiLU lookup to all prefill rows. Flatten BF16 core `[1,n,32,128]` into `[1,n*32,128]` in token/head order. Widen, form FP32 squares, sum over width 128, multiply by 1/128, add epsilon, accurate rsqrt, multiply, and round normalized values to BF16. Multiply by gamma with the existing round/widen boundary. Flatten BF16 Z codes to `[1,n*4096]`, gather the existing FP32 universal SiLU table, reshape it to `[1,n*32,128]`, multiply with weighted normalized values, and round the final product to BF16. Reshape directly to `[1,n,4096]`; no decode-only concat-heads sharding is needed. This removes the fused norm's n%32 condition and its separate `sigmoid(Z)` then `* Z` rounding schedule. HF `Qwen3_5MoeRMSNormGated.forward` at installed source lines 191–200 rounds normalized values and the gamma product before multiplying FP32 SiLU(Z). Verify every intermediate BF16 code against HF before choosing this candidate; the decode repair's improvement is motivation, not proof for all prefill rows. At chunk64, at most 2048 norm rows are live, keeping temporary size bounded. Use explicit interleaved DRAM initially instead of inheriting decode-specific sharding or assuming singleton L1 sizes.

## Other row-count-sensitive paths

- Projection arithmetic must be tied to the **public** operation, not the internal tail shape. Current `linear` multirow attention/output projection forces K1024 (line 463), while singleton uses its `projection_k` parameter. `_linear_attention` forwards that parameter only to `attention_packed`; `output_only_packed` currently receives its default K512 (line 662). Forward the same chosen public projection policy to both. A singleton tail of a multirow prefill must receive K1024 in both projections. A true public one-row call may require its existing K512 policy. Padding every hidden tensor to 32 would hide this distinction and force a different projection path.
- `_moe` currently chooses router dtype, inline selector, and sparse versus grouped expert execution from `s == 1` (lines 834–890), independently of `_forward.decode`. Thus changing only `decode=False` does not make a singleton tail follow the existing batched-prefill router schedule. Add an explicit public-prefill mode if preserving that schedule is intended, or measure the singleton path as a separate candidate. For an explicitly forced batched route at n=1, use the same prefill logits dtype/topk path and grouped expert branch; do not change the immutable logical token count. Exact CPU tie semantics remain a separate router gate.
- Grouped routing does **not** require token count alignment: `routing_metadata/device/routing_metadata_device_operation.cpp:87–109` requires token_start alignment (this caller uses zero), accepts any positive num_tokens in range, and rounds internal padded tokens. `routed_combine/device/routed_combine_device_operation.cpp:77–80` explicitly checks round_up(num_tokens,32). Therefore no global hidden padding is required for MoE eligibility at n=33 or a forced grouped n=1.
- The linear input/post-attention norm accepts dynamic `rows` and uses `[4,16,rows,32]` reductions; no explicit alignment guard exists. Its rows==1 arithmetic and the singleton native `decode_linear` output/shared projections remain finite-precision schedule differences to measure. They do not imply a mandatory public alignment restriction. Current public `ttnn.reshape` dispatch (`reshape_view/reshape.cpp:670–800`) selects device views, codegen, or device repacking for device tensors. The legacy `reshape_on_device` manual host-insertion code is not evidence that these public reshape calls execute on CPU. Nevertheless collect actual op traces for n=1/33 and inspect necessary versus avoidable repacking before accepting performance.
- New prefill norm or shape code must convert `tuple(tensor.shape)` before slicing shape metadata. FP32 ADD/SUB must leave `fast_and_approximate_mode` unset; accurate MUL and accurate rsqrt use their already-validated flags. Reshape scalar beta/g through the existing tested device shape helpers, not arbitrary host conversions.

## Public one-row semantics and follow-up gates

An internal one-token tail of a multirow public call is unambiguously chunk-prefill. A **public** one-token call with an existing HF cache is different: installed HF lines 521–533 selects recurrence when `use_precomputed_states and seq_len == 1`. A public one-token call with no prior cache selects chunk-prefill. Do not infer public semantics from internal n alone. The current state dictionary has only conv/recurrent tensors, so prior-cache intent must come from the existing caller contract or explicit setup metadata if this distinction is needed; numerical tensor contents are not a valid presence test. Preserve established decode_forward behavior.

Before promoting any integrated snapshot, compare full outputs, conv cache, and recurrent cache against HF for public S=1,33,63,64,65,127,128 at start=0 and nonaligned continuation starts, with distinct inputs on either side of each internal boundary. Include nonzero initial state and continuation after a one-token tail. Inspect both projection packs, normalized/gated core, output projection, router logits/IDs, and expert contribution if full output fails despite state agreement. Then repeat the long failing stream and continuation cases. Device perf, context capacity, watcher, and final stage gates remain outstanding; this proposal neither lowers those bars nor changes the advertised context contract.
