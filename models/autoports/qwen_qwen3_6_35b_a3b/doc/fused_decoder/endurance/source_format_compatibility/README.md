# Historical probe source preservation and pinned formatting migration

The measured raw Python files remain available under `original_tests/*.snapshot`; `original_sources.json` records their exact original paths and SHA256s. Existing device JSON, historical PIN literals, measured standalone decoder snapshots, kernel sources and tensor fixtures were not rewritten. Formatting current tests does not claim that their new bytes were measured historically.

The new test-only `frozen_source_compatibility.py` accepts either the original exact raw SHA, or one exact path/old-SHA/new-SHA tuple in the byte-pinned `manifest.json`. It checks the archived source and the separately pinned proof artifact. It performs no runtime AST normalization and will reject even an unapproved whitespace change, as well as altered arithmetic. `raw_sha256` always reports actual bytes. No production runtime imports this helper.

`verification_rewrites.json` lists live-source equality checks changed into bounded compatibility checks; historical evidence comparisons, tensor/native/kernel/snapshot checks, and dynamically captured before/after run-stability checks remain strict. `provenance_rewrites.json` separates actual current dependency digests from explicit historical digest siblings. `auditor_review_delta.json` separately records the reviewed 85644/ab28 runtime auditor additions and mutation controls, with no new setup exemption.

`build_proofs.py.snapshot` reconstructs each current AST from its archived original using only those individually recorded deltas, then applies the pinned formatter toolchain (Black 23.10.1, autoflake 2.3.1, isort 5.13.2). The reconstructed AST must match the current AST exactly; all embedded kernel literal hashes must also match the archived original. This proves explicit import removal/reordering and formatting without a permissive mathematical normalizer. It is an offline proof generator, not a runtime acceptance rule. The manifest does not contain the new verifier itself, avoiding a circular self-hash.

Validation: 69 originals preserved, 44 exact changed-source pairs, all 71 scoped test/verifier files pass the pinned hooks, eight adversarial verifier tests pass, every manifest binding passes, and six deeply dependent wrapper imports pass. Source-only rebuilds reproduce the historical direct-coefficient decoder c823e6f6f8480a9550276856a7aa660b9308ff598c6565a38c2bc54460440ece and triangular decoder 85644b73bc1effb516c1fc7a5092cc443ef7d8a30a67a6635767a06f3eb7f858 exactly. Commands and actual new builder provenance are in `validation.json`, `rebuild_direct_provenance.json`, and `rebuild_triangular_provenance.json`. No hardware was used for this migration.

To reproduce an old measured helper byte-for-byte, use a separate checkout of the same repository revision and restore its original source from the inventory (including its archived transitive dependencies). Verify the restored raw digests before running the historical command. Do not restore originals over this live checkout during device work. New runs use current helpers and record current raw hashes; old device reports continue to describe the old archived bytes. Any future source edit requires a new explicitly reviewed pair and newly pinned manifest; it is never implicitly accepted.

Independent read-only edge audit by `/root/dynamic_selector_contract` found no missed live hash assertion or non-historical reporting field, and independently verified all 44 exact bindings. Original archive files also pass whitespace/EOF/500 KB checks without any byte changes.
