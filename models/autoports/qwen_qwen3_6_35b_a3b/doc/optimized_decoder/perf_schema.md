# CPU performance summary

Run `python -m models.autoports.qwen_qwen3_6_35b_a3b.tests.summarize_optimized_perf` after final captures in `tracy/layer_0` and `tracy/layer_3`. `--ranking-only` works before captures. Inputs are `ops.csv`, `{prefill,decode}_perf_report.csv`, `correctness.json`, `final_{0,3}.json`, and candidate `search.json` files with their underlying result/provenance JSON. Files remain uncompressed; this script never reads devices.

Outputs:

- `tracy/layer_{0,3}/{prefill,decode}_op_groups.csv`: device kernel microseconds per pass grouped by operation, input dtypes, fidelity, weight dimensions, and core count. All groups retained, sorted descending. Decode validates the16 replay sessions have identical ordered operation signatures. Prefill and decode are delimited by their exact signposts. Missing durations fail rather than becoming zero.
- `perf_summary.json`: per-phase op counts, kernel-time sums, unique actionable advice strings, logical-byte roofline, same-run profiled host latency if present, and separate clean host latency. `profile_decode_host_median_ms` must come from timed blocking replays excluding explicit profiler drains. No profiled host latency is invented when absent. Kernel sums exclude dispatch gaps; the host-minus-kernel residual includes those gaps and instrumented runtime overhead, not a proof of avoidable host work.
- `candidate_ranking.json`: every recorded search candidate, ordered by layer, eligibility and traced warmed latency. Exclusions include failed/missing artifacts, PCC below0.995, absent determinism, BFP4 (reserved for stage8), non-clean or unproven serial provenance, and workload different from seeded S256/context512. This is a screening table: full acceptance stress, natural-activation and context gates still decide final eligibility. Final comparison must also include baseline and selected final artifacts.

The byte model is an optimistic once-per-token logical weight plus cache bound at512 decimalGB/s, not a measured traffic counter. BFP8 charges17/16 bytes per weight (1024 mantissas plus64 exponent bytes per tile). Full-attention projections, shared and8 unique selected expert weights useBFP8; ordered linear-attention projections/output remainBF16. Router and norm weights areFP32; KV isBF16. Padding, unselected experts, duplicated resident prefill weights, intermediate tensors and rereads do not inflate this lower bound. Linear recurrence countsFP32 state read/write and BF16 convolution history. Full attention counts live positions through the current token plus one-token cache writes. Re-audit this ledger if the final stored dtype policy changes.

`functional_128_128` consumes `functional_0.json` and `functional_3.json` from the clean-performance stress mode. It requires128 input and128 output tokens, passing correctness, no tracking, bit-equal repetitions and a timing sample for every step. The average logical-byte bound across positions128–255 divided by mean blocking-trace latency must reach0.1. Input transfers, reference work, readback and state restore are outside this decoder-module timing boundary. Missing artifacts remain explicit `missing`, never an inferred pass. This decoder-only summary makes no full-model throughput or generated-text claim.
