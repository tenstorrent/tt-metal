# Maximum-context warmup L1 failure: source localization

CPU/source inspection only, 2026-11-14. No device execution, inference edits, capacity reduction, or numerical/performance validation in this investigation. The recommendation is an experiment, not an accepted fix.

The failure is a short singleton attention warmup allocation conflict, not demonstrated DRAM exhaustion or failure to compute a long prompt. `context_acceptance/result.json` and `logs/context_acceptance.log:591` report static CB end **920640**, lowest L1 allocation **898496**, shortfall **22144 bytes**. The runner fails at `tests/run_full_model_context_acceptance.py:233`, `seed_prefill([1,2], captured=False)`, inside bounded-prefill preparation; the long-prefill/decode acceptance counts remain zero. The selected SDPA grid/chunks remain 8x8 / 32 / 256. The configured 262144-token page table has 8192 INT32 entries (32768 bytes), versus 128 bytes at context1024. SDPA allocates CB9 from the aligned page-table stick size (`ttnn/cpp/ttnn/operations/transformer/sdpa_decode/device/sdpa_decode_program_factory.cpp:237,666`). This is a context-dependent **static L1 workspace** requirement even when the current position is small.

## Smallest candidate: shorten dead K/V lifetimes

`tt/multichip_decoder.py:1693-1751`, `_full_attention`, retains singleton `k` and `v` through SDPA although both have already been written to the paged cache. Immediately after the two `paged_update_cache` calls, neither tensor is used again. Each final source has one HEIGHT_SHARDED L1 shard [32,256], BF16, or 16384 bytes. Their combined nominal 32768-byte footprint exceeds the current 22144-byte shortfall by 10624 bytes.

Release both source buffers **after their cache-update enqueue and before the `q = to_memory_config(q, shard)`/SDPA sequence**, retaining the same cache update and SDPA operations, dtype, positions, page table, and memory configs. The Python `for dest, src in ...` leaves `src` referring to V: `del k, v` alone does not remove that alias. For an explicit release use `ttnn.deallocate(k); ttnn.deallocate(v); del k, v, src` after confirming their buffer identities are distinct from Q and cache allocations. Alternatively remove all Python references, including `src`, and verify the memory census confirms release. Cache updates consume distinct head tensors, not views into cache buffers. Their serialized CQ0 producer/consumer order must be retained; do not insert host synchronization or readback in forwards. Trace allocation tracking must validate replay safety.

This only changes temporary ownership; it does not change arithmetic, SDPA geometry, activation/residual layout, CCL, or persistent cache placement. Allocator fragmentation and the exact low-water allocation can prevent nominal freed bytes from translating into contiguous headroom; the predicted margin is therefore not a hardware claim.

Other live variables are poorer first candidates:

- `projected`, `packed_qkv`, and `gate`: selected `linear()` returns DRAM (`multichip_decoder.py:1185-1204`), so releasing projected/packed tensors does not directly recover the required L1. Gate remains necessary after attention.
- `q`: required by SDPA; cannot be released before it.
- `cos`, `sin`: RoPE lookup/permute products are not the identified persistent pressure; their source is DRAM and their lifetime is not the first target.
- Caller-owned normalized input (`_attention_residual:1505`, `_normalized_input:1277`) remains live during `_full_attention`. The full-attention singleton norm uses WIDTH_SHARDED BF16 [32,64] on32 cores (4096 bytes per shard). It is dead after QKV projection but cannot safely be deallocated by a generic callee without an explicit ownership contract. Its possible 4096-byte saving alone is insufficient.

## Persistent allocation audit

`QwenModel.__init__` already shares immutable `decode_local_silu.table` and removes inherited unused router bias/indices/outputs/selector. `CollectiveWorkspace` already shares the serial CCL/direct-all-reduce workspaces. The inspected remaining allocations do not provide another safe identical L1 constant to deduplicate:

- `WeightedNormTail.__init__`, `tt/fused_decoder.py:2383-2400`, expands each layer's learned norm gamma to FP32[1,32,128], TILE, one-core HEIGHT_SHARDED L1 at(0,0), **16384 bytes per layer**. `TP4WeightedNormTail` inherits this constructor (`multichip_decoder.py:76`); its active instance is installed at line768 and consumed at line563. Thirty active linears account for491520 bytes of lockstep allocation pressure. This is active storage, not an inherited orphan.
- The parent's original `WeightedNormTail` and `LocalSiluMultiply` are replaced by assignment in the TP4 installer; no second persistent owner was found in the inspected constructors. The superseded packed scan weights are explicitly removed; gate/decay and old general SiLU tables are DRAM.
- CPU safetensors inspection of the pinned revision found **30 gamma tensors, shape[128], BF16, and30 distinct SHA256 hashes after conversion to FP32**. These weights cannot be shared across layers as identical constants. Layer0 hash: `8b51ece7e812b72c556fa4540e4ce46ead78c137b11c2dbdace07f238f85b36c`; layer1: `c33f19dd8b0441984cc79299badeac3e01add7db32de3609ca6249c1f153ef36`. Inspection loaded only these small CPU tensors, using `safe_open`, and made no TTNN imports.
- `MeshFP32TopK.__init__`, `tt/mesh_fp32_topk.py:86-105`, allocates template/values/IDs in DRAM. `CompensatedNormEpilogue.__init__`, `tt/mesh_compensated_norm.py:140-147`, allocates no persistent tensor. Chunk64 constants are uploaded via the DRAM uploader. Removing/sharing these does not recover the identified L1 pressure.

## Optional norm-core placement: arithmetic plausible, allocator caveat

An optional `core=(x,y)` constructor argument could preserve the exact four-tile FP32 norm computation: set the one-core range, both shard specs and `runtime[x][y]` together (currently `runtime[0][0]` at `fused_decoder.py:2430`). Output/debug tensors follow the chosen shard. The selected TP4TileSilu reader uses `TensorAccessor(weighted)` and NoC reads, not a hardcoded weighted-input core (`fused_decoder.py:2883`, reused by `mesh_decode_silu.py:34-62`), so changing the producer core is source-compatible. The SiLU LUT itself is accessed locally and must remain on all SiLU workers.

However, **changing only the shard's coordinates does not reclaim ordinary lockstep allocator capacity**. `tt_metal/impl/allocator/allocator.cpp:197-295` routes ordinary L1 allocations through allocatorID0; `bank_manager.cpp:471-490` sizes each allocation by shard count, without assigning independent free space based on that shard's coordinates. The explicit per-core path at `allocator.cpp:158-188` requires HYBRID mode plus `per_core_allocation`. Neither setting is present in the current model/context runner. Round-robin placement alone can therefore keep exactly the same low-water address. Introducing per-core/HYBRID allocation is a materially larger allocator/trace contract change and should not be the first repair.

If placement is later pursued, keep defaultcore(0,0) for existing decoder APIs; pass a deterministic valid worker coordinate only from full-model construction; update every descriptor/runtime index; verify distinct-core allocation actually shares addresses safely; compare norm and downstream SiLU bitwise at core0 and multiple nonzero coordinates; measure NoC/perf and trace tracking. Do not assume tensor-accessor compatibility proves allocation safety or speed.

Add setup-only retained L1 ballast matching the other29 norm-gamma allocations:29 separate FP32 TILE[1,32,128], one-core HEIGHT_SHARDED [32,128], **475136 bytes** total lockstep footprint. Match the full-model memory census and record any residual difference due to other setup buffers. Use a short prompt [1,2] only. This isolates page-table CB pressure without executing a max-length prefill, and does not consume the final one-shot long-context acceptance.

Run the unchanged singleton path first as the failing allocation control, then the lifetime-only repair with identical ballast, input, geometry and caches. Record addresses, buffer identities, allocation census immediately before SDPA, and the exact CB/lowest-L1 comparison.
