## Source Evidence

**FetchQ and issue-buffer ledger.** Define `B` = FetchQ base, `E` = end, `e` = entry bytes, `N` = entries, `W` = host's next slot to publish, `R` = device's next slot to consume, and `L` = address of the last consumed slot returned to the host. `L` is deliberately not `R`.

| Resource | Producer / owner | Consumer / release | Count and state contract |
|---|---|---|---|
| Host issue-buffer bytes | `write_program_command_sequence` writes command chunks through `cq_write` and pushes the issue pointer | Prefetch issues PCIe reads; tagged retirement makes bytes usable in `cmddat_q` | One FetchQ entry describes each published chunk's byte length; one-shot programs use one entry, larger programs use multiple entries. Host/device wrap before a chunk that would exceed their common issue-buffer end. |
| FetchQ slot | Host `fetch_queue_write` stores one nonzero size entry, then advances `W += e` | `read_from_pcie` issues one read, clears exactly that slot on BH, stores `L = R`, then advances `R += e` and wraps | Every published entry must be consumed once; clearing/credit must not lose a later publication. Host `W == cached L` triggers a read of the device credit and waits while equal. |
| FetchQ cursor lifecycle | Host initializes `W = B`, fence `= E`; reserve wraps `W == E` to `B` | Device starts at `B`; after consuming the last slot, advances back to `B` | Both sides use the same `N` and `e`. After startup, the last-consumed-slot fence leaves one slot unavailable, giving at most `N-1` queued entries. No persisted absolute counter is used to reconstruct a modular slot. |
| `cmddat_q` reservations and TRIDs | Prefetch's `issue_fence` reserves space and issues up to four reads, TRIDs 2–5 | Oldest tagged read is barriered and retired; `fence` advances; `process_cmd` consumes command strides | Each accepted FetchQ entry adds one in-flight record and each retirement removes one. TRID 0 is restored after issue; exec-buffer TRID 1 and relay TRIDs 6–7 are separate. At the sampled host wait there are zero in-flight fetch reads and no committed command available. |

**What a consistent queue would imply.** After consuming `C > 0` entries, a drained queue with `P = C` publications has `R = B + e(C mod N)` and `L = B + e((C-1) mod N)`. Its next host slot is `W = R` after wrapping, hence `W != L` for `N > 1`. Conversely, a full queue's `W == L` leaves the next device slot `R` among the `N-1` already published entries; it should be nonzero. Therefore a persistent empty-device/full-host condition violates publication/cursor/credit agreement. **The capture proves the branch locations, but omits the values needed to prove this particular full/empty contradiction:** the host may instead be stuck inside the credit read before receiving a newer `L`.

## Downstream Effects

- The concat is the host operation being submitted; the evidence does not identify a stalled concat worker kernel or a mismatched concat CB loop. The generic dispatcher must receive work before such a kernel can run.
- With prefetch waiting for a host slot, it cannot publish new dispatch/subordinate pages. Their upstream waits and subsequent worker idleness follow naturally. Releasing more downstream credits or changing CB size does not address the earliest dependency shown here.
- There is no evidence that completion, close, or teardown began. Adding termination traffic or resetting the device would not diagnose the lost-progress boundary and would destroy the preserved state.
- Unused Ethernet warnings, resumed-core warnings, and the motherboard/subset-discovery log messages do not identify an active fabric route or a source contract that explains this local CQ stall.
- Linear-long success validates a different operation mix. It does not validate sustained full-attention dispatch, nor does the full-attention stall invalidate the earlier PCC measurements.

## Proposed Fix

**No unconditional implementation fix is justified by the preserved data.** The repair must restore the FetchQ contract at the first failing boundary, rather than change model arithmetic, decrease context, increase a queue without an occupancy violation, or add an already-present pointer/phase update. The following are proposed checks and changes for a later authorized experiment; none was run here.

1. **Obtain the missing boundary state before selecting the patch.** Preserve host `W`, cached fence, the actual returned credit value, whether repeated credit reads complete, CQ/core/address, and the current command size. Pair these with the device's `R`, slot contents around `R` and `W`, the word at `0x1b7c0`, `cmd_ptr`, `fence`, `issue_fence`, `inflight_count`, and `stall_state`. Capture the full 6144-byte FetchQ if possible and enough host issue-buffer bytes to identify the pending fragments. Keep capture consistency explicit; prior triage resumed some cores. Do not attach a mutating debugger or recapture devices under this report's read-only authorization.

   | Discriminating observation | Source-level action supported by it |
   |---|---|
   | The host completes polls returning `L == W`; `R == next(L)` is zero although publication history shows it was written | Trace the exact slot's publication/clear ownership. Correct the overwrite, lost publication, wrong cursor, or address mapping at that point. If visibility is demonstrated, use an appropriate explicit doorbell flush/UC mapping; retain the existing payload-before-doorbell fence. |
   | Device credit memory has advanced but successful host reads return another value | Correct the host polling target/mapping/coherency or the credit store visibility. Both existing code paths and actual loaded library must be checked; do not merely add the uncached helper already in source. |
   | The host stays inside a single MMIO read while device credit advances | Repair the UMD/PCIe read/transaction path. Queue-capacity or concat-CB changes would address the wrong resource. |
   | Host/device pointers disagree on base, stride, end, or next slot | Correct the owner supplying that geometry or corrupting the cursor. The prepared map and inspected kernel currently agree. |

2. **Make transport experiments small and discriminating.** If the first result points to the dedicated I/O window, a minimal caller-side candidate is to declare the FetchQ window `UnicastWrite`, preserving Strict ordering and the existing addressing. Test that independently from a UC mapping or post-doorbell fence experiment. Inspect emitted TLB configuration and confirm the relevant ordering/visibility guarantee before calling an A/B pass a root-cause fix. Do not force a shared read/write window onto one static VC; the UMD source explicitly warns against that on BH. Include repeated queue wraps and backpressure in a future focused dispatch reproduction, plus a control with the original mapping.

3. **Decoder-local workaround candidate: reduce RoPE command traffic.** A decoder-local fused partial-RoPE kernel could consume each tiled Q or K tensor and its prepared BF16 cos/sin, produce both rotated 32-feature halves, and copy the remaining 192 features into the same output. Its logical contract is `[-a[32:64], a[:32]]` for the rotation, multiply/add only on features 0–63, unchanged features 64–255, and no writes to input/KV state. Preserve logical heads versus padded rows, existing rounding policy or demonstrate PCC equivalence, and stable device buffers for trace replay. The current decoder has no such fused path. This avoids both RoPE concats and several launches, but is an **unverified traffic/path workaround**, not a demonstrated dispatch repair.

4. **An orchestration-only discriminator can preserve exact arithmetic.** In a later eager run, submit bounded groups of complete 256-token chunks, then synchronize between groups outside live trace capture. Retain the same KV pool, absolute positions, logical outputs, and full context; if using separate `prefill_forward` calls, rebase only each group's input offsets, not its absolute positions or cache history. This tests whether backpressure/queue history matters. It cannot recover the already-stuck process, and a pass would not prove the queue implementation correct. No synchronization should be inserted into captured decode as a workaround.

Any candidate must pass the unchanged real-weight 262143- and 262144-token full-attention checks, selected-row and aggregate PCC **>= 0.995**, continuation/page ownership checks, and last-position traced decode with refreshed inputs and deterministic replay. Keep the passing linear controls. Neither smaller context nor relaxed accuracy is proposed.

## Uncertainty

- High confidence: submission boundary, active chip/CQ, sampled prefetch branch, and downstream nature of the dispatch/subordinate waits. Lower confidence: simultaneous queue state, because pointer/ring values are absent and some cores resumed during capture. The exact implementation fault and a validated fix are **not established**.
- A single native sample cannot distinguish a non-returning MMIO access from a rapidly repeated poll. This is the first missing distinction to resolve, before declaring the host's actual credit stale or the ring full.
- Semaphore arithmetic assumes a stable common instant and ordinary operation, not trace credit stealing; the run was still in eager prefill. Delayed block release accounts for charged pages, and incomplete samples prevent reconstructing private CB counters.
- Source line drift is acknowledged in the input. The cached prefetch ELF supports the kernel's geometry and source stop-site. Exact loaded host library build identities remain to be verified: the native stack names UMD `0.9.16`, whereas triage package metadata reports `0.9.12`. That difference alone is not evidence of the cause.
- The previous completed op and publication history are unavailable. Earlier bad writes or a transport fault remain possible; the unused Ethernet warnings do not settle either possibility. No hardware-health or numerical-failure claim follows from this investigation.
- The proposed transport candidates, fused RoPE workaround, and bounded-submission experiment have not been implemented or tested. No full-attention long-context pass or stage-completion claim is made.
