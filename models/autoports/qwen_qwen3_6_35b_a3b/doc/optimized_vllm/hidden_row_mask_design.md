# Exact tiled hidden-row extraction and activity masking

Candidate design, 2026-11-17. Preparation used no hardware or active `tt/` edits; the parent subsequently ran the diagnostic artifacts described below. The device implementation is being amended to reproduce the measured old tilize bit semantics. `hidden_row_mask_candidate.patch` is archived and default-off (`QwenModel(..., fuse_hidden_row_mask=True)` opts in). The separate `tests/run_hidden_row_mask_probe.py` is ready for a serialized hardware discriminator after application. No speed or device-correctness result is claimed.

## Existing boundary and proposed replacement

`MultichipDecoder.decode_batch` finishes its unchanged residual/MoE arithmetic with an interleaved DRAM BF16 tensor `(1,B,2048)`, padded to `(1,32,2048)`, for supported buckets B2/B4/B32. With `split_rows_once`, it untilizes once, slices each logical row and tilizes each singleton. `QwenModel.decode` then calls `_mask_hidden_rows`: each independent DRAM singleton is copied using a persistent scalar activity predicate, with inactive destinations zeroed. The initial embedding mask stays unchanged.

The new model-owned helper consumes the already-DRAM residual plus the existing persistent 32-entry U32 activity vector. It emits independently allocated `(1,1,W)` BF16 TILE DRAM tensors, each padded to `(1,32,W)`. Row `i` uses fixed scheduler slot `slots[i]`; activity is read on device on every invocation. The helper replaces only the split and subsequent mask at each layer boundary. Arithmetic, state commits, selected precision, routing, positions, terminal, sampler, native completion barriers and adapter code are unchanged. No host tensor conversion or activity refresh is added to replay. Prefill, unmasked decode, B1 and the default flag retain the old path.

The patch uses the existing generic-op program builder in `tt/slot_state.py`, face addressing from `tt/serving_state.py::_LOGIT_ROW`, and the processor-store-to-NoC ordering idiom from `tt/moe_route_mask.py::_PLAN`. It adds no native kernel API or shared runtime change. The state-slab candidate is independent and owns different source regions.

## Physical mapping and bounded work

A BF16 tile is 2048 bytes. Its element offset is `face(r,c)=(r/16)*512+(c/16)*256+(r%16)*16+c%16`. Even-column pairs share one 32-bit word. For each width tile, the helper extracts the sixteen words at `face(i,c)/2`, even `c=0..30`, for `face(0,c)/2`. The original raw-copy proposal was rejected: each BF16 halfword must first reproduce the measured old boundary canonicalization. For `exp=bits&0x7f80`, `exp==0` yields positive zero, `exp==0x7f80` yields `bits&0xff80` (signed infinity), and all other bits remain unchanged. This is exact integer bit manipulation, not a change to the preceding model arithmetic. The other 496 words remain zero. An inactive row writes a completely zero tile. All width tiles are assigned cyclically to at most the mesh worker-grid size; with W2048 there are 64 pages per rank. Each worker reads its activity vector once and each assigned source tile once, then writes each row's full destination tile. Scratch is 4288 bytes per worker: two tiles, 128 activity bytes and 64 alignment bytes.

The helper preserves mandatory read completion and write completion before scratch reuse. `ckernel::load_blocking` follows processor writes before NoC consumes the output tile. There are no floating-point operations, collectives, conditional host reads or acknowledged unsafe allocations. The required canonicalization changes only the same BF16 classes changed by the old split/tilize boundary. Outputs use separate buffers and may not alias the source, activity or one another.

For W2048, per rank and layer the candidate reads 128 KiB of source tiles, reads 8 KiB of activity across 64 workers, and writes B ×128 KiB of full singleton tiles. B2 writes 256 KiB; B4 writes 512 KiB; B32 writes 4 MiB. These are source-derived payload counts, not measured bandwidth or latency. The expected opportunity is fewer boundary operations and repeated copies; the candidate still pays full padded output traffic and serial per-row writes within a worker. No claim is made that this closes the serving floor gap.

## Exact discriminator

After application, run in a fresh serialized hardware process from the checkout with its normal Python/PYTHONPATH environment:

```bash
TT_METAL_TRACE_ALLOC_TRACKING=1 TT_METAL_TRACE_ALLOC_SKIP_PROGRAM_CACHE=0 \
python models/autoports/qwen_qwen3_6_35b_a3b/tests/run_hidden_row_mask_probe.py \
  --output models/autoports/qwen_qwen3_6_35b_a3b/readiness_vllm/hidden_row_mask_probe/result.json
```

The probe is synthetic data movement, not model quality or performance. It prepares all six source/bucket/slot variants and both output families before any capture: natural B2/B4/B32 at W2048 and reversed/high-slot mappings at W64. Each of four chips receives different seeded BF16 data. Signed zeros and finite edge patterns, including subnormals, are included. It compares every physical padded BF16 word using the existing `from_device(...).to_torch_with_padded_shape()` API, both against the old untilize/slice/tilize/copy_if sequence and CPU extraction from an independently read pre-capture source snapshot. Each generation is uploaded through the same host-construction/copy path used for replay, snapshotted on all chips, then generation0 is restored and checked before capture. Seed-to-uploaded differences are reported separately by count, bit transition, coordinates and hashes; source bits observed through the padded host-read API, followed by the independently measured canonicalization formula, define the extraction oracle. The original device-constructor upload is also recorded because its tilize path can differ from replay refresh. Overwriting one candidate row must leave every other row unchanged.

Twelve traces retain independent, preallocated control/candidate output storage. Seven phases give 42 comparisons and 84 nonblocking replays: all active, identical unchanged input, changed source only, even slots active, only slot31 active, none active, and return to all active. Source and activity addresses persist; updates occur only when those inputs change. Replaying another bucket must preserve the previously inspected output. Program-cache size and output addresses must remain stable. A deliberate late live allocation must be rejected before replay, then is deallocated. No allocation acknowledgment or exemption is used. Trace releases occur only during cleanup. Diagnostic synchronization/readback follows the nonblocking boundary and supplies no async-overlap evidence.

**Hard blocker resolved by diagnosis, implementation gate still required:** the old split/tilize path does not preserve every input bit. Raw copying failed the strict gate. The exhaustive diagnostic established the exact canonicalization below; the candidate must implement it, while the CPU oracle computes it independently. Full padded old-versus-new equality, exact inactive zeros and source preservation remain required. The amended implementation still needs the 42-case trace gate and full-model/serving validation.

The microprobe preallocates both families' final destinations to isolate exact transport and retained-trace behavior. Production outputs are allocated by the helper during graph construction/capture, so the full-model bucket probe with allocation tracking is still required; this microgate cannot prove that broader lifetime contract. After the microgate, compare candidate B2/B4/B32/solo0 against the unfused fixed32 reference, exact full40 logits and recurrent/KV state, changed/unchanged input trajectories, and external saved interleaved controls. Then run matched native and real vLLM serving measurements and the required mixed-shape/chunked-prefill trace reuse check. Keep the candidate only with correctness and serving evidence; reject it if latency does not improve.

## First microgate failure and oracle correction

`readiness_vllm/optimized_hidden_row_micro/result.json` failed before capture: the first complete old-versus-candidate output comparison passed, then the original seed-based CPU oracle reported four BF16 word differences for row0/rank0 (first index0). Thus that artifact does not demonstrate a row-extraction mismatch. It also does not by itself prove where transport changed the edge bits.

Source inspection found two different input-construction paths: `ttnn/core/tensor/py_to_tt_tensor.cpp::can_construct_on_device` permits device operations for construction, including tilize, whereas the replay helper calls `from_torch` without a device and then `copy_host_to_device_tensor`. The corrected probe records both paths rather than assuming they preserve the seed identically. All replay generations now have physical padded snapshots prepared before capture using the replay refresh path; generation0 is restored and bit-checked. The first corrected CPU oracle extracted the selected row directly from that snapshot and zeroed all inactive/padded words; the exhaustive follow-up below now adds the measured old-boundary canonicalization to active logical values. Every replay additionally checks that its source still equals the prepared snapshot. Strict complete old-versus-new comparison, exact active-row bits, exact zero padding and changed/unchanged-input checks remain mandatory. If the old split/tilize normalizes bits that are actually present in the source, the corrected test must still fail; it does not excuse or conceal that discrepancy.

The revised probe passed CPU syntax, seed-difference-report positive control, strict comparator positive/negative controls and repository pre-commit checks. The correction was prepared without hardware access or TT source edits; a fresh hardware run is required.

## Exhaustive measured boundary semantics

The parent-run `readiness_vllm/optimized_hidden_row_transport/result.json` reports `OBSERVED`, all 65,536 distinct uploaded BF16 patterns on each of four chips, and a single-valued source-to-old-output map. Its integer mapping artifact has SHA256 `058fadcf93549a0ad355847b9e54651dcc8f04dd11bfc925366dfa1b38ba61b0`. The observed rule changes 509 patterns: 255 exponent-zero patterns become positive zero (positive zero itself stays zero), and 254 NaN payloads become infinity of the same sign. Positive/negative infinity and all normal finite values remain unchanged. This extends the initially hypothesized exponent-zero rule; that rule alone is insufficient for NaNs.

`run_hidden_row_mask_probe.py::old_split_canonical_bits` implements this independently in CPU integer operations on the actual uploaded source snapshot. It does not import or share the candidate's device canonicalizer. The 42 cases, strict all-chip old-versus-new complete padded comparisons, independent storage checks, persistent activity/source changes and unchanged-source checks are retained. An active logical value must equal the canonicalized source exactly; inactive logical values and all output padding must be positive zero. This is reproducing the measured existing boundary, not allowing an error tolerance or accepting raw-copy differences.
