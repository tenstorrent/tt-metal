# Plugin change: retain prefill continuation state ownership

Base: `tenstorrent/vllm-tt-plugin` `042a94863ad27d88207bcf71abdf67122c6f4c27`.

1. **Requirement and failure.** Chunked prefill must resume the state belonging to the same request. `_alloc_prefill_state_slots` excludes prefilling owners from its reservation set. After A finishes in slot 0, B's continuation moves from slot 1 to host row 0 without a device state move. CPU reproducer: `continuation_owner/reproduce.py`; evidence: `continuation_owner/result.json`. Reordering two continuations and admitting a new row before a retained owner also fail. Exhaustive capacities 1–4 show 3328 violations in 4422 valid cases.
2. **Owner.** Plugin defect in `src/vllm_tt_plugin/model_runner.py:1295`. `docs/MODEL_LIFECYCLE.md` (retained state slots and release ownership) and `docs/MODEL_EXECUTION.md` (`empty_slots` identifies retained per-request state) require the plugin to identify the correct slot. A changed host row does not move recurrent device state. The existing regression's keep-own-slot case only covers coincident row and slot.
3. **Model-side alternative.** The adapter receives slots, positions and page tables, but no stable request identities. Inferring identity from cache blocks is incorrect because pages may be reallocated/shared; guessing based on lengths is ambiguous. Moving model state without a plugin remap would disagree with the plugin's ownership map. Preserve the slot in the allocator that owns request identity.
4. **Existing mechanisms.** Reviewed MODEL_INTERFACE, MODEL_CAPABILITIES, MODEL_SETUP, MODEL_EXECUTION, MODEL_LIFECYCLE, DECODE_RELOAD and plugin config. `supports_chunked_prefill`, `supports_async_decode`, existing `empty_slots`, decode state-slot remaps and `release_request` already express the contract. Trace mode, sampling config, batch size and `TT_MODEL_CLASS_OVERRIDES` do not repair ownership. No additional capability, config or environment mechanism is needed.
5. **Effect on other models.** All models using this allocator retain a live request's existing slot across prefill calls. New requests retain row preference and free-slot allocation; released/preempted requests have no ownership entry and remain new allocations. This restores the documented contract for recurrent models and session-bearing models such as Gemma4DFlash. No model-specific branch or changed cache policy.
6. **Authorization.** Adds no shared interface and no new default-policy choice. This is a minimal defect repair under the selected skill's plugin-defect rule; the user authorized fixing required serving failures.
