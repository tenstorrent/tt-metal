# Canonical device penalties: source-only AutoFix design

2026-11-17. No implementation edits, device calls, HTTP requests, or tests were run. This proposal leaves the parallel native-top-k work untouched. Sources are the current autoport `tt/generator.py`, `tt/serving.py`, `tt/serving_state.py`, `tt/slot_state.py`, common `models/common/sampling/{generator,tt_penalties}.py`, and the pinned standalone plugin's model execution/reload contracts and implementation.

**Conclusion: common device penalty operations exist and a canonical generator extension is feasible, but this is not a safe capability flip or a small parameter-forwarding fix.** The shortest correct implementation needs history initialization before prefill sampling, active-row count masking, prepared history reset operations, a second retained sampling signature, and explicit RNG/history transition handling. There is also an information gap for resumed prefill in the current plugin interface: it does not forward the original prompt/output boundary. Thus I cannot recommend advertising `supports_device_penalties=True` for all serving requests from a model-only patch based on the present evidence.

The real current boundary remains: neutral presence/frequency/repetition values on device; any nonneutral penalty uses explicit host-logit compatibility. This boundary is implemented, not just declared: `_neutral_device_features` rejects the controls; `configure_sampling` overwrites all three with neutral values; `_sampling_forward` always calls the common sampler with `penalties_on=False`; the serving reset path changes CPU shadows but never uploads penalty masks/counts.

## Existing pieces that can be reused

- Common `SamplingGenerator._run_sampling` applies repetition first, then presence/frequency through `TTPenalties.apply`, samples through the common sampler, and increments output counts **after** the draw when `penalties_on=True, count_tokens=True`. Keep this canonical path and token-out buffer; do not create an adapter sampler.
- Common `TTPenalties.reset_prompt_tokens` handles duplicate prompt IDs using CPU counts and supports slot-preserving prompt masks. Presence/frequency apply only to generated output; repetition sees prompt or output. `reset_output_tokens` can reconstruct counts from supplied output history, including duplicate IDs.
- `SlotState.from_generator` already registers prompt/output masks, sharded and replicated output counts, and all four penalty parameter buffers for full ownership permutations. Prompt/output CPU history shadows are registered too. New per-slot penalty parameter lists must be added to `sampling_values` **before** this registration is constructed.
- The common precompile API currently has `compile_token_update=True`. Its default is false. Use the counted option (or an explicit counted model warmup) before any trace capture; merely calling today's `precompile(logits, tt_out_tok=tokens)` does not compile the scatter/tilize/count path.
- The pinned decode interface supplies `prompt_tokens` and `output_tokens` with `-1` padding for device penalties. A transition drains pending outputs before authoritative reset. Ordinary penalty requests are excluded from the plugin's steady async shortcut (`async_decode.py:616`); enabling device penalties does not automatically enable the optimized steady path for those requests.

## Exact model gaps and smallest implementation design

1. **Parameter state and validation.** Extend `sampling_values` and `configure_sampling` with presence, frequency and repetition values. Validate finite values and positive repetition before mutation; forward 32 physical rows of all three controls into common `SamplingParams`, preserving untouched slot values. `_neutral_device_features` should continue rejecting logprobs/grammar but no longer reject validated penalties. Decode parameter reload must preserve existing RNG and count state unless the separate reset command requests rebuilding it. Remove the unconditional `_penalties_active` rejection only after the histories and both sampling signatures are ready.

2. **Count exactly active requests.** Common `TTPenalties.decode_src` is initialized to ones for all 32 rows. `_run_sampling(... penalties_on=True)` counts its result **before** Qwen merges inactive tokens back. Simply enabling it therefore increments counts for inactive/live-off-batch slots during a partial prefill or sparse decode. This is a real correctness gap even when the visible token buffer is preserved.

   Inside the penalty sampling graph, derive a `[32,1]` int32 count source from the existing device `active_mask` and copy into persistent `tt_penalties.decode_src`, then execute the canonical `_run_sampling` with counting enabled. Warm/capture the conversion/copy too. Inactive scatter additions must be zero. Do not use a host token readback or an unmasked all-ones update. The row-major `[32,1]` count source does not satisfy the existing packed-vector remapper's last-dimension-32 contract, so do not blindly register it as another packed vector; deriving it from the already remapped activity mask in the graph avoids that problem.

3. **Initialize history before the first output.** `prefill_with_sampling` currently builds prompt/output CPU shadows but installs them only **after** running the sampler. Move the meaningful history initialization before the first sampling replay. For a fresh request, full logical prompt tokens create the prompt mask, output counts start at zero, and only selected physical slots are reset. Then terminal-prefill sampling increments that slot's output count once. Intermediate chunks must never count or advance RNG. Concurrent off-batch requests retain their prompt masks/counts exactly.

4. **Restore state, do not add it twice.** On `reset_sampling_state`, project supplied prompt/output rows through the same slot permutation and active selection already validated by `serving.py`, clear the selected count rows, and rebuild them from authoritative output history. That history already contains the emitted prefill token and all drained decode tokens. Do not add the previous local counts to rebuilt counts. Parameter-only reload and page-only refresh must not clear/rebuild or increment counts. Global generator reset must clear device masks/counts even when `_penalties_active` is currently false; common convenience reset functions guard on that flag.

5. **Prepare history-reset operations.** Common partial output reset allocates a device keep-row tensor and optional full-vocabulary update tensors. It does not magically become trace-safe because buffers being updated are persistent. Prepare every exact program signature before capture and use persistent keep-row/update scratch with stable shapes for model-owned resets, or first prove the existing helper's allocation lifetime safe under tracking. Never execute an uncompiled reset scatter/multiply/add behind retained model traces. Prompt-count construction can remain CPU work at a requested reset; steady count updates stay inside the sampling trace. This is history initialization, not per-token host token feedback.

6. **Keep the neutral performance path.** Retain the current neutral `sampling` trace and prepare a separate `sampling_penalties` execution signature, both writing the same canonical token-out tensor. Warm both before any capture; capture each once and never invalidate either. Select based on the submitted active rows' parameters, not stale inactive-slot penalties or merely the common global `_penalties_active` flag. All default/benchmark requests must keep the neutral trace. Capture/warm counters and trace-budget evidence need to include the extra signature.

   A subtle scope choice is required: the fast neutral trace does not accumulate output history. Existing requests have fixed sampling parameters in vLLM; a transition to a group containing penalties supplies authoritative histories and rebuilds them. Direct generator parameter-only changes from neutral to penalties cannot correctly recover earlier output counts without a supplied history reset. Either document and validate that required reset for this transition, or track neutral output counts too and measure the resulting default-path overhead. Do not silently begin counting in the middle of a request.

7. **RNG reset is a separate concern.** Current `configure_sampling(reset_seed_state=True)` writes `seed % 1000000 + 1` regardless of prior emitted-token count, and `_sampling_forward` increments active seeds once per draw. Plugin sampling parameter seeds are the original per-request seeds; they are not offset by generation position. The plugin resets sampling state after prefill, request membership/layout changes and host/device transitions. Consequently making every canonical mixed request device-eligible removes the observed route switch but does **not** by itself prove admission-invariant seeded streams: an extra transition can restart a continuing stream.

   Preserve the explicit reset contract while rebuilding the correct stream position from authoritative request progress. For seeded device draws, the expected next seed under this generator's increment scheme is initial seed plus the number of emitted device draws, modulo uint32. Use authoritative output length when supplied; otherwise retain/remap per-slot prompt boundary and draw-progress metadata and align only on commanded authoritative reset, never from lagging steady async positions. New/reused requests reset progress; intermediate prefill does not advance it; parameter-only reload does not reset it. This is an additional hypothesis to verify with a reduced replay test, not a claimed observed cause of the already attributed first-token mismatch.

## Resumed-prefill information boundary

The pinned `model_runner.py::submit_prefill` (around lines 4085–4149) forwards tokens, start/end positions, cache/pages, slots and optional sampling parameters. It does **not** forward `prompt_tokens` or `output_tokens`, even where a lane input builder has populated those fields. The ordinary input builder currently creates penalty history only for decode. The interface documentation explicitly permits resumed prefill to replay generated tokens to rebuild KV state.

Two valid histories can have identical combined prefill tokens and positions: original prompt `[a,b]` with no output versus original prompt `[a]` with generated output `[b]`. Presence/frequency penalties must treat `b` differently. A new/reassigned physical slot and combined token row cannot identify that distinction. A model-local cache of the prior slot's history is insufficient once preemption, slot reuse or indistinguishable request prefixes are allowed; the adapter is not given a request ID or authoritative original prompt length.

For fresh initial/chunked prefill, the terminal row contains the complete original prompt and output history is empty, so the model-only design above is sufficient. For resumed prefill after generation, a universally correct first resumed output requires original prompt/output history (or equivalent unambiguous boundary metadata) **before** that prefill samples. Rebuilding on the next decode is one token too late.

Do not flip the global penalty capability merely because the short canonical test has no resume. A minimal potential shared-interface proposal is to build and forward existing prompt/output histories on penalty-bearing **prefill** as well as decode, then let the generator use them before sampling. That is a plugin/interface change, not implemented or authorized by this report; it requires the full plugin-change classification/proposal and authorization rules. It is not grounds to alter sampling tests or silently disable preemption. Alternatively, a source-supported model-owned identity/history solution would need its own exact resume/reuse proof; none exists in the current implementation.

## Smallest focused regression sequence

1. **Sampler-only CPU/device comparison, parent-run device job:** fixed tiny synthetic logits on the existing 1x4 sampler shape; prompt duplicates, output duplicates, positive/negative presence/frequency values, repetition above/below one, and real vocabulary shard boundaries. Compare penalized logits against the pinned host implementation before any stochastic draw. Verify initial prompt affects repetition only, and one emitted token adds exactly one output count. Include active slots `{0,2}`, a live inactive slot and all-off padding. Establish counted warmup, no compile in either capture, stable token/count buffer addresses and no allocation warning. No full model needed.
2. **Reduced generator lifecycle:** one real layer of each type; penalty request prefills in one slot while another request already has counts, then two traced steps, a non-self-inverse remap, parameter-only update, page-only update, slot reuse, and explicit authoritative history reset. Assert per-slot masks/counts/seed progress against a CPU ledger, untouched inactive rows, and one capture per neutral/penalty signature. Use the existing contract probe infrastructure rather than a new broad suite. Include neutral→penalty transition only with the documented history policy.
3. **Resume negative control:** two same-combined-token cases with different original prompt/output boundaries must yield different presence/frequency adjustments. The current API-only information is intentionally insufficient; do not claim global support until this passes with a supported source of boundary data.
4. **Only after implementation/contract closure:** rerun the existing bounded twenty-request mixed-route probe once on the final model. Its exact original controls must remain, all penalty-bearing and neutral requests must stay on device, and text/token equality plus per-request route/seed timelines must pass. A device-only mismatch requires the reduced RNG/logit check, not a forced host policy. Rerun affected penalty assertions, then final full sampling and primary performance only after targeted gates pass.

No hardware success is claimed. This report supplies an implementation order and a concrete interface limitation; it does not mark the AutoFix goal resolved or convert the existing canonical failure into a pass.
