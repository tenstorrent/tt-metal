## Finding

The available evidence does **not** establish that all of the gap from historical 47.760901 tokens/s/user to current 18.593631 tokens/s/user is serving overhead. These numbers use different model execution paths and different native completion semantics. Current serving executes masked B2 at capacity 32, while the historical B1 teacher-forcing path uses singleton sparse MoE. The current B2 path pads MoE to 32 rows and includes the mandatory fused-reader write-completion drain.

There is nevertheless concrete avoidable work in the serving wrapper: an unconditional flushed log on every decode, repeated synchronization of the same read event, and repeated CPU permutation validation. Their latency contribution is unmeasured. Consequently, neither “vLLM causes the entire slowdown” nor “no avoidable vLLM overhead remains” is supported.

## Why B1 is physically different from B2

`tt/generator_vllm.py:36` declares `[2, capacity]` for capacity greater than one; `tt/generator.py:61`–`:71` explicitly rejects bucket 1 in that configuration. `model_trace_key` selects the smallest prefix covering the highest active slot (`generator.py:566`); a lone slot 0 uses B2, while a lone high slot can require B32. Plugin padding does not cause `model_trace_key` to treat inactive padded rows as live: the command decoder derives activity from nonnegative authoritative positions, or retains/remaps resident activity (`tt/serving.py:231`–`:264`).

The B1/B2 distinction reaches arithmetic, not merely scheduler occupancy:

- `tt/multichip_decoder.py:1807`–`:1812` sends one state directly to `decode_forward`. Two or more states use the batch path, batch attention reductions/projections, row concatenations and splits (`:1813`–`:1872`).
- `_moe` uses singleton indexed sparse matmuls for one row (`:1567`–`:1610`). For B2, it pads to 32 rows (`:1548`–`:1552`) and runs grouped expert dispatch, fused SwiGLU, combine and reduction (`:1612`–`:1696`). Padded inactive rows are still computation; masking prevents them from changing another owner's state. This is not equivalent to running the B1 graph twice.
- `tt/model.py:369`–`:411` creates safe activity-dependent positions, masks hidden rows before the first layer and after every layer, and advances only active positions. With B2/full40 this entails 82 hidden-row mask calls, plus two position-input and two conditional increment paths, all within the retained model trace.
- Each of 30 linear-attention layers computes a candidate recurrent state for each physical row and conditionally commits it (`multichip_decoder.py:524`–`:539`); masked convolution preserves dormant convolution state. Full-attention inactive rows also use explicit zeroing (`:1996`). These operations protect dormant owners and are model-owned costs, including when the same generator is used outside vLLM.
- The fused reader's final `noc.async_write_barrier()` is required completion work. Removing it to recover an earlier number would restore a broken kernel completion contract. The B1 sparse route does not execute that grouped fused reader.

Simply allowing `[1,32]` would switch a resident request between singleton sparse and grouped arithmetic as occupancy changes. Prior audit recorded numerical differences between these paths (`work_log.md:92`). B2/B32 exact-logit acceptance does not cover B1/B32. A bucket-1 optimization preserving grouped arithmetic would require explicit model implementation and renewed full-vocabulary/state-transition checks; it is not a harmless adapter declaration change. Capacity-1 serving is supported separately but changes the serving configuration and cannot replace the accepted capacity-32 headline.

## Serving-specific hot-path audit

1. **Confirmed avoidable flushed route log.** `tt/generator_vllm.py:80`–`:88` prints `QWEN_DECODE sampling_mode=...` with `flush=True` on every decode before checking `audit_enabled`. Thus `QWEN_VLLM_AUDIT=0` does not remove this per-token I/O. The existing `last_decode_route` and route counters allow a model-owned small repair: print on route transition (and under explicit detailed audit), retain exact counters and shutdown summaries. Verify both device→host→device transitions and no missed fallback reporting. Do not claim a latency saving until measured; it is not credible source evidence for the entire ~33 ms difference from historical B1.

2. **Confirmed duplicate event wait, but preserve standalone ownership.** In the pinned `/home/ttuser/qwen36-35b-a3b/vllm-tt-plugin`, `src/vllm_tt_plugin/async_decode.py:1653`–`:1677` synchronizes returned read events, then calls adapter host processing. `tt/serving_state.py:520`–`:526` synchronizes the same events again. The plugin documents this order in `docs/MODEL_EXECUTION.md:168`–`:178`. The second wait sees an already-completed event, so it does not represent a second full device stall; it is redundant host/runtime work. The generator also serves direct callers that rely on its own wait, so do not globally delete it. If worthwhile after timing, use an explicit model-internal distinction for plugin-managed completion, preserve the independent generator default, and test synchronous, asynchronous and two-pending-output cases. No new shared-plugin interface is necessary or justified.

3. **Confirmed repeated CPU validation, likely small.** `tt/serving.py:218` normalizes the full-capacity permutation; `ReloadExecutor.execute` normalizes it again (`tt/serving_state.py:380`), then `SlotStateOwner.apply` does so again (`:198`). `normalize_remap` constructs a CPU tensor/list and sorts the permutation (`:47`–`:59`). A private validated-tuple path can avoid repeated conversion while retaining external validation. Resident calls also reconstruct and validate stored sampling rows (`serving.py:303`–`:312`) without a parameter reload. These are CPU-only operations; no evidence supports treating them as dominant costs. Any optimization must continue ignoring stale token/position payloads and validating real command transitions.

4. **Required output ownership is present.** Each accepted step enqueues the selected model trace and canonical sampler trace, then snapshots tokens into a preallocated two-lease ring (`serving.py:384`–`:399`, `serving_state.py:490`–`:510`). Readback is asynchronous; the host consumes compact token IDs. The snapshot copy prevents the next decode from overwriting an outstanding answer. Removing it without equivalent lease-safe storage would violate the tested two-pending-output contract. The replicated token transfer covers only the fixed 32-token buffer; it is not full-vocabulary transfer. Only explicit host-logit mode transfers logits.

5. **No steady resident input reload or hidden host sampling found.** The resident branch never inspects tokens/start positions (`serving.py:228`–`:254`), page binding runs only for commanded reloads, and identity remaps exit before device mutation (`serving_state.py:195`–`:202`). Device sampling directly replays the canonical sampling trace (`serving.py:389`–`:394`), bypassing compatibility host sampling. Logit padding/copy and inactive-token/seed preservation are shared generator operations, not an alternate serving sampler. CPU vocabulary validation of the already-read token result (`generator_vllm.py:297`–`:305`) is small required validation, not token feedback.
