# Isolated full-state recurrence slab attempt

Status: parent-owned hardware component acceptance passed all four combinations of rounded/unrounded consumption and persistent/temporary state over 128 steps. Production integration remains under qualification. The implementing agent used no hardware. The unused production helper is prepared with identical kernels/descriptors and native-input guards.

The measured candidate1 generator is 22.272769 ms/token against the 21.631299 ms ceiling, leaving 0.641470 ms across 30 linear layers (21.38 us/layer). The accepted product contraction removed products materialization but left decay, delta, update, state commit and layout operations. This attempt puts those operations in one 32-worker program, retaining each 128-by-32 state slab in local circular buffers. The adapter retains the exact Q/K physical permutation. The probe measures that conversion and state/output copies as well as the custom kernel.

Sources: `tt/state_slab_recurrence_probe.py`, `tests/run_stage7_state_slab_probe.py`. The baseline calls the current `LinearTP4Mixin._recurrent_step` with production direct/product contraction helpers. The new helper is installed only into a probe-owned namespace.

Each worker owns one head and one 32-column slab. Phase 1 optionally rounds state through the native FP32-to-BF16 SFPU typecast, then performs a separate FP32 multiplication by supplied decay. Phase 2 multiplies by K and uses the accepted ordered eight groups of sixteen additions, followed by eight partial additions, starting from each first operand. It then subtracts memory from the widened BF16 value and multiplies by beta. Phase 3 forms K times delta and separately adds the retained decayed state. It packs FP32 state to both an output writer queue and a dedicated local queue. Phase 4 scales Q with the native scalar multiply, multiplies it by the new state, and performs the identical ordered contraction. There is no TF32 contraction, FMA, reassociation or BF16 state-store boundary.

Scalar and K replication use integer bitwise shifts/OR, not multiplication by one or addition to zero. Native SFPU broadcast and arithmetic still require exact hardware comparison for signed zero and subnormals. State input/output may alias: every worker reads all its exclusive slab before its writer commits it. Temporary state uses L1 and the caller retains responsibility for masked persistent-state commit. The probe supports this path via `--state-output temporary`, copying the temporary state to the next step outside the helper.

Independent CPU review by the evidence agent found and fixed two issues before hardware: CB0 initially had both BRISC and pack producers; local new state now has dedicated CB26. BF16 value copying lacked explicit source format reconfiguration; the kernel now explicitly reconfigures around the BF16 copy and restores FP32. The reviewer checked arithmetic ordering, bitwise fan-out, page addresses and independent slab ownership. This is source evidence, not hardware acceptance.

Fixtures include captured rank-distinct real inputs at positions 128 and 8157, cancellation, signed zeros, tiny signed FP32 states producing subnormals, and positive/negative FP32 neighbours of BF16 rounding ties. Decay fixtures are CPU exponentials of captured G, supplied identically to both implementations; they do not claim to reproduce the selected decay LUT. `--rounded 0` and `--rounded 1` run separate native rounding variants. `--steps 128` exercises repeated exact state commit. Both eager and changed-input nonblocking traces compare every logical output/state bit on all four ranks; outputs and state readback layouts are warmed before capture. Timing restores the first real fixture and contains no host readback between queued trace replays.

## Parent-owned component results and production promotion

Each `state_slab_r{0,1}_{persistent,temporary}_128_watched.json` passes 12,288 rank-level exact state/output comparisons under Watcher and allocation tracking. These component results do not establish full-model accuracy or the generator lower-bound gate.

`tt/mesh_state_slab_recurrence.py` contains literal kernels without probe dependencies or source rewriting. `state_slab_production_cpu.json` verifies all three kernel strings and the `__call__` descriptor AST against the qualified probe. Native input guards check every logical/padded shape, dtype, tiled layout, interleaved L1/DRAM memory and optional state output. The native wrapper preserves the qualified Q/K permutations. Its `execution_geometry` records slab/core geometry, arithmetic/rounding, state/terminal layout and caller-owned inactive masking. `state_slab_production_hooks.log` records passing repository checks. After parent-owned exact layer checks passed at layer 0 for 128 steps and layer 34 for 192 steps, guarded production dispatch was installed. Full-model acceptance remains a separate parent-owned gate.

## Production dispatch and optional batch positions

Optimized linear decoders instantiate `full_model_state_slab`; standalone decoders retain `None`. `_recurrent_step` checks the native input/output guard before any conversion and forwards explicit rounding and output-state arguments. Unsupported inputs retain the existing product/direct-sum/native reduction sequence. Execution geometry includes the complete helper policy. `state_slab_dispatch_cpu.json` executes the actual guarded-dispatch prefix for selected/unselected and supported/unsupported helpers and verifies rounding/state forwarding. Its eight checks include the optional-position expression.

The first B3 integration attempt failed in the baseline before executing this candidate: `decode_batch` unconditionally called `position.get` for linear rows while the existing single-row `_attention_residual` explicitly accepts `positions=None`. The minimal repair applies the same conditional activity lookup in the batched linear branch. `None` and an empty dictionary mean no activity mask; an explicit activity object is forwarded unchanged. Full-attention position requirements are unchanged. This is an independent baseline contract repair; B3 hardware must be rerun. Production source was then frozen for the parent's hardware checks.
