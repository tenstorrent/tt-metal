# Full-model serving interface gap audit

This is an inspection-only audit of plugin commit `042a94863ad27d88207bcf71abdf67122c6f4c27` at `/home/ttuser/ornith-9b/dependencies/vllm-tt-plugin`, recommending vLLM `0.31.0` in `docs/install-vllm-tt.sh`. It does not implement an adapter, launch vLLM, import TTNN, or use devices. The working tree is live: `serving_contract.json` records implementation SHA256 values at inspection so later implementation fixes do not inherit an unsupported acceptance claim.

The matrix contains114 rows:3 narrowly supported construction/output-width mappings,77 missing implementation/evidence rows,34 documented optional exclusions. Many missing rows identify different effects of the same few bugs; this is not77 independent implementation projects. Every capability key in the pinned capability reference is represented, including spec, grammar and stage extensions. `decode_input_update_contract`, `tt_supported_decode_batch_sizes` and the `model_capabilities` container are separately represented as interface declarations, not invented dictionary keys. There is no proposed plugin change and no `plugin_owned` exception.

## Immediate correctness defects

1. **Sampling requests disappear.** `OrnithGenerator.__init__` configures fixed greedy parameters once. `prefill_forward`, `decode_forward` and `generate` accept `**kwargs` but do not consume per-request temperature/top-k/top-p/seed/penalties/logprob settings. `_sample_step` calls the common sampler with penalties off and no counts. `generate` always chooses the first token by host argmax. A fluent response does not establish that requested sampling occurred. The plugin's `TTSamplingParams` carries per-row Python lists, including `None` seeds; use the same row order and reset/advance request-owned RNG deliberately. Seed tests also inspect first-token variety.
2. **Host sampling dispatch is backwards for the plugin.** The plugin supplies `sampling_params` only when it wants device sampling. It omits the argument for host sampling and expects full-vocabulary logits. Current decode instead defaults `host_sampling=False`, so a plugin-compatible direct call without sampling parameters samples greedily and returns IDs. Current prefill always returns logits, even when device parameters were supplied. Implement the selector explicitly. The existing diagnostic `host_sampling=True` boundary is useful but does not satisfy this external call contract by itself.
3. **Unsupported penalties must not inherit the default.** The pinned default for `supports_device_penalties` is **True**. Current penalties-off behavior therefore needs either actual penalty support or an explicit False declaration plus a tested host-logits route. False changes execution routing, not request semantics: penalty requests must still work through host sampling. Temperature/top-k/top-p cannot all be relegated to host, because this stage requires sampled on-device traced decoding.
4. **Slots/inactive rows are not an optional extension.** Padded ordinary decode rows carry `start_pos=-1`, and inactive rows can occur between live slots. Current decoder submission uploads all positions, advances all positions and invokes every recurrent state. Ignoring the marker can mutate inactive convolution/recurrent state and generate invalid RoPE indices. `slot_remap` is silently discarded. A permutation applies to all slot-owned state, including dormant sampler state and slots outside the current decode bucket, exactly once before reading any destination. `empty_slots` is row-to-state-slot placement, not a KV page index.
5. **Resident commands are silently overridden.** Version1 plugin commands are authoritative. Current `decode_forward` always reloads tokens and positions and uses a page-table equality heuristic. With `reload_inputs=False` the host token/position arguments intentionally lag the device; reloading them creates stale-token feedback. Add independent command handling, with `reload_inputs=True` as the safe direct-call default and the other commands False. Reject incompatible combinations and legacy `reset_batch` after advertising version1.
6. **Readback mode is ignored.** Current replay always reads the sampled token to host before return, ignoring `read_from_device=False`. This prevents the documented asynchronous submission/readback contract. Return an owning submission handle, then read exactly that submission later. Readback must not sample, advance positions or mutate request state. Output must be `[B,1]` IDs or `[B,1,V]` full-vocabulary logits in submitted order; the current flat IDs and `[B,V]` compatibility output do not establish front-packed compatibility.
7. **External ownership and lifecycle need proof.** `prepare_decode` is keyed on cache identity and slot tuple and rejects a second binding; it does not describe all scheduler-supported signatures. Full cache/table capacities, row order and persistent bindings must be prepared before capture. Fresh prefill must initialize only its selected recurrent/conv slot while preserving live peers. `reset` is a whole-generator operation, not a release-request implementation. `close` releases trace IDs without clearing them, so repeated invocation can release the same ID twice; future `release_persistent_capture` must be idempotent and run before mesh close.

## Minimum model/generator contracts before an adapter

Keep registration and `initialize_vllm_model` glue for the later stage. The full-model generator should already provide the following underlying behavior, with explicit keyword validation rather than an unrestricted silent `**kwargs` sink:

- External cache allocation/binding describes page size, dtype per cache group, device/mesh, layer mapping, capacity, aliases and slot-owned recurrence. The later allocator method can translate the plugin's `(shape,dtype,tensor_idx)` triples without copying model logic. The plugin's generic sizing fallback131072 is not a measured capacity result.
- `prefill_forward(tokens, *, start_pos, prompt_lens, page_table, kv_cache, empty_slots, sampling_params=None, enable_trace=...)` uses absolute intervals, returns one last-token row per request, preserves unrelated state and supports mixed row lengths/orders. Intermediate chunks arrive without device sampling parameters and must not advance RNG. The same path rebuilds full recurrent history after preemption.
- `decode_forward(tokens, start_pos, *, page_table, kv_cache, sampling_params=None, slot_remap=None, read_from_device=..., reload_inputs=True, reload_page_table=False, reload_sampling_params=False, reset_sampling_state=False, ...)` validates every command and rejects unknown semantics. It must preserve inactive state, honor fixed-slot outputs, refresh runtime tensors in place, sample into persistent token inputs and advance only active positions on device.
- The generator owns preparation of physical prefill/decode/sampling/state-update variants before the first capture, including external served cache shapes. Eager preparation is not eager acceptance decode; warmup must be able to execute identical programs without capturing, then seal preparation and capture. Request changes select prepared signatures and never retire live traces.
- Host compatibility returns writable independent full-vocabulary logits without sampling or RNG advance. The plugin performs host-only filtering, logprobs and grammar. On TP4 its source routes **all logprob requests, including0, to host** because device logprob support is limited to8/32 devices. Host-only stochastic top-k outside1..32 also needs this route; do not silently clamp.
- Sampling parameter changes use prepared sampling variants and explicit device state updates. Test greedy→sampled→greedy, seeded/unseeded switches, changed row order, per-row parameters and host↔device transitions. The common sampler must remain the implementation; no custom sampler is justified by ignored plumbing.
- Split readback, per-request release, slot permutation and capture teardown expose direct generator methods. A later adapter can rename/map methods without adding missing numerical or state logic.

`supports_async_decode=False` is a documented fail-closed default, but it is not a way to claim the required serving-ready resident loop: the pinned plugin forces full host input reload on every decode without this declaration. Keep the capability unclaimed until split readback and command handling are actually tested.

## Prefix caching versus resumed prefill

The matrix records `supports_prefix_caching: not_supported` under the documented `recurrent_state` exclusion. Ornith's24 linear-attention layers retain convolution tails and FP32 recurrence outside vLLM's KV blocks. An APC hit cannot reconstruct those values merely from a nonzero start and full-attention page tables. The current generator provides no prefix snapshot identity/lifetime contract. This is an existing documented exclusion, not a new plugin flag.

This exclusion **does not waive** the user's required `run_prefill_resume_check`, arbitrary-start continuation, scheduler chunking or preemption reconstruction. Those remain missing rows. `readiness/prefill_resume_check.json` currently fails starts32/68; its controls correctly fail. Reduced BF16, fixed32 or overlap experiments are diagnostic evidence and cannot be promoted to full-model support. Preserve the user's optimized dtype/fidelity/cache policy while resolving the remaining mismatch.

If full APC is later implemented, its identity must include the entire recurrent state (including any partial internal recurrence block and precision/execution policy) at the cached position, with ownership/isolation tests. Simply declaring True or reusing full-attention KV does not supply it.

## Optional extensions and request ownership

Documented absent/False defaults may exclude speculative verification/drafting, block-output/adaptive output, on-device grammar, selective host readback, compact host logits, vLLM-Omni stage inputs/outputs and in-process lane-DP. They must not be used to exclude ordinary request controls that tests send. Grammar, penalties, logprobs, `min_p`, `bad_words`, `logit_bias`, `allowed_token_ids`, `min_tokens` and custom logits processors still need the correct host boundary when their device path is unavailable.

Speculation is gated by `supports_spec_decode=False`; the plugin refuses speculative configuration before `spec_plan`, wide verification and `propose_draft_tokens`. The spec test suite uses a host-arithmetic dummy target through a TT-opened worker, so it is an optional extension inventory, not a demanded production Ornith implementation. Its lifecycle lessons—cancellation, preemption, stale output and slot reuse—still apply to ordinary decoding.

Text-only scope does not authorize dropping a supplied multimodal processor field or request-specific RoPE keyword. Reject unsupported nonempty payloads explicitly. `supports_original_prompt_lens` is absent from this pinned plugin's documented capabilities/source search and must not be invented to solve resumed generated-token behavior.

Normal plugin/frontend processing is not a `plugin_owned` stage exception. For example, vLLM owns stop/EOS filtering, streaming and token-ID response formatting, but the generator still owes correct ordered tokens and lifetime-safe buffers. The matrix keeps the underlying missing generator boundary visible rather than declaring the request implemented by assumption.

## Inspection and acceptance evidence

Common documentation read: MODEL_INTERFACE, MODEL_SETUP, MODEL_EXECUTION, MODEL_LIFECYCLE, MODEL_CAPABILITIES, DECODE_RELOAD_CONTRACT; relevant SPEC_DECODE_CONTRACT admission/call/lifecycle sections, DEVICE_GRAMMAR_CONTRACT, SCHEDULING's prefill/overlap/lifecycle sections, installation pin and README references. Source consumers examined include loader construction, worker sizing/fabric interfaces, platform capability resolution, model-runner KV allocation/sampling selection/prefill/warmup/shutdown, async decode submission/readback/reload and speculative admission. `documents_read` lists paths; the audit does not claim every unrelated implementation line was reviewed.

Ordinary tests inspected: request configuration/helper fields; chunked-prefill passphrase cases; mixed-parameter isolation; seeded and unseeded diversity, first-token variation and top-k1 equivalence; penalty influence and zero-penalty neighbor isolation; logprob counts0/1/3/5/10 and all-vocabulary chat mode; host-only controls; mixed structured/plain requests and slot reuse; tile-size/config assertions. Spec tests were inventoried by test names/docstrings with their README and admission contract, not run against Ornith.

The three supported rows only map existing construction and ordinary one-token width. Missing rows deliberately remain failing work. `doc/full_model/state_probe.json` provides reduced-layer resident feedback and changed-page-table evidence, explicitly labeled reduced context/layers; it does not establish the whole serving interface. `prepared_cross_request.json` and normalized prefill experiments similarly need coverage tied to the final implementation before support status changes.

Minimum focused acceptance additions: strict keyword/shape rejection host tests; mixed-row logits and cache equality against solo; active rows around inactive gaps; nonidentity slot permutation including off-batch state; external-cache reset isolation; sampled and host-compatibility outputs with requested semantics; version1 stale-host-input and page-only refresh probes; sampler parameter/state transition ordering; capture-ID reuse and program-cache stability across mixed prefill/decode; idempotent request release and teardown. Keep full-model numerical/readiness gates separate from these contract tests.
