# Cold CI startup findings

Measured CI server startup is19m34s, versus local warm B8 startup186.23s. Before server launch, the pinned snapshot download took8m07s. Layer0→1 took379.70s; layer4→5 took116.23s. The pinned index shows these are the first accesses to shard1 and shard2 respectively. Layer0→59 totals619.27s. CI trace preparation484.66s includes prefill warmup447.82s; local preparation11.26s includes prefill10.54s. These are host-wall phases, not device times.

Two source-supported candidates merit a host-only confirmation. TTI downloads into persistent cache_root/weights/hub; PinnedWeights uses Hugging Face's default cache and ignores MODEL_WEIGHTS_DIR. This can duplicate downloads but actual child cache paths/inodes were not recorded, so the long layer gaps are not conclusively download time. Separately, TT_CACHE_PATH set by TTI is not TT_METAL_CACHE used by the JIT. Local runs set persistent TT_METAL_CACHE; CI does not explicitly set it in the new entry. Warmup delta includes compilation but cannot be entirely assigned to it from these logs.

Proposed stock model environment: HF_HUB_CACHE=/home/container_app_user/cache_root/weights/hub and TT_METAL_CACHE=/home/container_app_user/cache_root/tt-metal-jit. No edits or measured improvement. First inspect resolved cache paths and local-only pinned shard availability in the built image; only then consider one same-image/same-board startup comparison, with paired exactness. Do not reduce warmup coverage.
