# Collective contract and tuning basis

Each layer has two row-parallel boundaries: attention O and MLP down. Both perform Ring reduce-scatter along hidden dimension3 and all-gather along dimension3, followed by local post-projection normalization and residual addition. The replicated residual is consumed directly by the next layer. Both operations use interleaved DRAM BF16 payloads during decode, two physical links, two workers per direction/link, and one channel buffer. Logical residual width5376 is tile aligned; the local RS width is1344. Decode physical M is32 for the configured B1/8/16/32 signatures: each full local partial is344064 bytes and the reduced shard is86016 bytes. Prefill communication is BFP8 with BF16 restored before normalization; stats in the rejected sharded family stayBF16.

The final constructor preallocates RS intermediate/output/penultimate buffers using `reduce_scatter_minimal_async_create_intermediate_buffer` and AG outputs. Ownership is per decoder, projection and batch signature. The buffers live until all that decoder's traces are released. No two projection/signature buffers alias. Every invocation overwrites its scratch/output before its consumer uses it, and the normal CCL barrier and semaphore protocol orders reuse. The layer does not retain an output view into this scratch as its public residual: post norms/residual adds produce the residual separately. The stress suite interleaves another cache's prefill while the same captured decode remains live. There are no trace allocation exemptions.

`chunks_per_sync` uses the pinned factory's shape calculation rather than an unexplained fixed constant:

- AG: `min(max(worker_page_count / packet_page_count, 1), 160)` in `all_gather_async_default_program_factory.cpp`.
- RS: `min(80, max(chunks_per_step / 2, 1))` for Ring, with the dim1–3 unit-step cap applied by the program factory; `reduce_scatter_program_utils.cpp` defines the calculation.

These values are internal packet/chunk scheduling, not the logical sequence-length contract. Final `performance.json` files retain each measured CCL call's runtime attributes, memory/dtype fields, and maximum per-device kernel time. `*_perf_report.txt/.csv` retain the communication rows and their placement among matmul, normalization, cache and data movement. These per-op times are diagnostic only; whole-layer rooflines use complete replay windows including gaps.

Measured controls include Linear versus Ring, BF16 versus BFP8 CCL, sharded versus replicated residuals, delayed gather through distributed norms, fused AG/MM and MM/RS, and selected-family preallocated versus ordinary outputs. Ring with preallocated decode buffers wins. BFP8 decode adds conversion work and is slower; prefill benefits from BFP8. Packed gate/up does not repay its prefill splitting/conversion cost at the configured target concurrency. Full tables and exact commands are in the candidate JSON/manifests and work log.

The corrected packed-prefill control writes BFP8 directly, matching split projection output dtype. It still loses about 3 ms at B32 over 4096 prefill plus 128 decode steps, while winning less than 0.5% at B1. The balanced split policy is retained. See the corrected-control table in work_log.md and `candidate_layer*_finalpacked8*.json`; the earlier BF16-then-cast packed control is superseded for this decision.
