# Sampling contract comparison

Inspected models/common/sampling/tt_sampling.py and generator.py, plus models/common/modules/sampling/sampling_1d.py. Selected TTSampling with a generator-owned trace wrapper. Both common samplers expose tt_out_tok, local32-candidate top-k plus candidate all-gather, semantic greedy k1/p0/temp1, per-row sampling tensors and seed buffers. TP4 gives65536 vocabulary columns per device, within the supported top-k width.

TTSampling supplies deterministic greedy tie handling and integrated parameter/logprob/penalty/grammar support. Sampling1D offers a simpler declarative buffer contract and per-call params, but does not supply the same greedy tie adjustment or request-history ownership. It is rejected for this generator's serving contract, not on an unmeasured speed claim. Both require explicit preparation before tracing. The high-level common SamplingGenerator capture_trace currently wraps capture in a broad corruptible allocation scope. Our generator instead directly traces TTSampling, uses no allocation scope, and uses preallocated persistent logits with no allocation acknowledgment. The persistent token feedback storage is allocated before both traces.

The reduced TP4 probe confirms TTSampling accepts sampler-ready [1,1,1,65536] local logits and writes uint32 rank4 [1,1,1,32] persistent feedback. Decode slices the logical active rows on device before embedding lookup. Position input is signed int32 for paged cache; RoPE lookup converts it to uint32 on device. Three tracked split replays advance positions32→33→34→35. This establishes only a short reduced probe, not final trace reuse or sampling performance evidence.

`sampler_acceptance.json` passes semantic-greedy controls on all configured batches with allocation tracking enabled, including program allocations. `generator_state_b*.json` covers changed/unchanged maps, mixed/inactive prompts, parameter transitions and changing feedback values. The final tracked gates verify repeat-seed equality, changed-seed differences in every active slot, greedy recovery, and 1023/1024/1025-token tails without recapture. The separate reduced device profile measures a 519.469 us sampler window; see terminal_attribution.json and profile_analysis.md. A k32 random sample is not a greedy performance control.

Measured comparison (sampler_timing.json,128 replays, host wall, synthetic BF16 real vocabulary/mesh): split semantic-greedy k1 is0.483/0.531/0.545/0.502ms at B1/8/16/32; padded force-argmax is2.898/2.778/2.885/2.875ms. Retain normal TTSampling. CPU HF reference was running during this exploratory timing; final reduced device profiling provides the device attribution. Token-readback timing is separately recorded and must not be mistaken for sampler device latency.

B8/16 need logical row padding to32 before the common sampler; B1 singleton broadcasting and B32 native rows fit. Force-argmax was repaired for this comparison by padding all B<32 inputs so its output matches the persistent32-slot feedback buffer. Both comparisons use greedy parameters, not stochastic sampling.

Known common-sampler tie policy: the candidate path selects a maximum-valued token but may not select the lowest vocabulary ID when more than32 equal maxima occupy one device shard. The strict diagnostic records this mismatch rather than claiming exact HF tie ordering. Semantic-greedy acceptance explicitly checks the selected BF16 value against the row maximum on every chip. The force-argmax alternative has exact lowest-index behavior in these probes but is slower. Full-model repeated token outputs and batch-slot checks pass for all configured batches; the final all-layer B32 run also passes bitwise full-vocabulary logit equality across all slots and repeated requests (logit_determinism.json).

The public sampling boundary accepts scalar parameters broadcast to every configured slot, or lists with exactly one entry per slot. Greedy temperature0 is the default. Stochastic top_k is explicitly1..32; top_p filters that candidate set. Requests for k64 or unrestricted k are rejected before parameter mutation rather than silently clamped. This follows the common formatter and two-face candidate-row sampling kernel limit documented in models/common/sampling/{generator,tt_sampling}.py; HF-default stochastic sampling parity is not claimed. Seeds are a nonnegative base plus the fixed slot index.

Independent review found that the original scalar formatter call described only one active lane, leaving later lanes greedy. The boundary now expands all per-slot values before the common formatter. Host parameter assertions and per-active-slot sampled/seeded output checks cover the repair.
