## Open issues for Phase 1
1. Parity: free-running greedy diverges at index 2. Needed before trusting outputs: teacher-force the HF token sequence through device prefill+decode and record per-position top-1/top-k agreement and the logit margin at index 2 on both sides (hf_reference.py can dump top-k for all 64 positions). Small margin + high teacher-forced agreement -> accept and proceed native; large margin flip -> chase bf16 TP8 reduce ordering / lm_head bf16 shards.
2. DP rows: 3/4 of the mesh does duplicate work (MeshConfig.dp=4 never consumed, config.py:61; all inputs ReplicateTensorToMesh). Fine for B=1; a 1x8 submesh would halve nothing per-device but free 24 chips -- however determine_device_name only accepts {1,2,4,8,32} devices on BH (tt_transformers/tt/model_config.py:5228-5250) and a 1x8 cache is a different mesh-qualified cache (tensor_cache_bf16_mesh1x8). Decide whether the enhancer owns the full handle or a submesh carved from it.
3. CCL under the LTX fabric: Phase 0 ran on FABRIC_1D_RING (test fixture). Sync ttnn.all_reduce/all_gather inherit topology from the fabric the LTX pipeline opened (ccl.py:302-308,345-352). If the LTX handle is FABRIC_1D (line), set GEMMA4_CCL_TOPOLOGY=linear and re-verify; the on-device sampler is constructed at init regardless (model.py:604-642) with Ring ag_topology (log line 554) and there is no switch to skip it.
4. Latency vs the 22.8 tok/s single-chip floor: steady decode is 3.76 tok/s untraced eager (0.265 s/step; per step 35x2 all-reduces + embed all-gather + 262144-wide logits all-gather for host sampling), i.e. ~6x slower than target; the 23.6 s step-0 compile and 57.7 s warmup are also per-process costs. Levers to measure: enable_trace=True decode (needs trace region on the LTX handle), on-device sampling / keep_sharded_for_sampling to drop the vocab all-gather, warm weight cache (cold load 48.7 s), skipping warmup_model_prefill.
5. Weight cache: 11 GB at /home/rsalman/.cache/tt-gemma4-e2b/tensor_cache_bf16_mesh4x8 (home dir, untracked). Move to a shared writable location (e.g. /mnt/models/tt_cache/gemma-4-E2B-it via TT_CACHE_PATH) and never run without TT_CACHE_PATH (default writes into the group-writable HF snapshot dir). Warm-load time not yet measured.
6. Coexistence with LTX on one handle: CCLManager allocates 14 global semaphores and synchronizes the device at init (ccl.py:133-144); generator keeps persistent inputs; both pipelines compete for DRAM/L1 and the trace region. Not tested in Phase 0 (E2B ran alone on a fresh submesh of the fixture mesh).
7. Housekeeping: record launcher command/env (LTX_TRACED, TT_CACHE_PATH, fabric) in the log on the rerun; stale CHIP_IN_USE mutex may recur after crashed runs (tt-smi -r if UMD does not recover).

## Phase 1 review: fixed vs rejected
Fixed: over-budget prompt now falls back to the raw prompt (PromptTooLongError caught in apply_prompt_enhancer); warmup compiles both the 1024 and 2048 prefill buckets; VBench seed replays reuse one rewrite (enhancer_seed + memo); host/device both use top_k=64/top_p=0.95 explicitly; model_path resolved to the local snapshot (snapshot_download local_files_only) so the Phase-0-validated safetensors path is used; bounded-sliding policy checked via gemma4's resolve_gemma4_bounded_sliding and refused when True; ccl topology bound from the pipeline (Ring on the 4x8 ring config, no Ring-vs-line drift); cache-dir writability checked, model-specific cache dir wins over an inherited TT_CACHE_PATH; `is_loaded` on the base contract; host no longer reseeds at T=0; real `_tokenize_prompt` path (instruct=False, max_prefill_len, BOS strip, left-clip error) now unit-tested; warmup test checks greedy via RNG state.
Rejected (all LoudBox/dynamic_load-only, moot under the Galaxy-only decision): the two "blocker" findings that the enhancer reload evicts the captured DiT; per-request from_pretrained rebuild; disk rewrite cache; encoder+enhancer coresidency on the 2x4. Also rejected: BOS probe/encode_prompt mismatch (gemma4 patches encode_prompt(instruct=False) to encode(add_special_tokens=True), generator.py:230, same call as the probe); auto-creating the shared cache dir (operator decision).

## Phase 2: device A/B on the 4x8 (see RESULTS_device.md for arms, rewrites, timings)
Attempt 1 produced garbage from the device rewriter; cause is the pipeline warmup order, not the enhancer: in both distilled warmup branches (pipeline_ltx_distilled.py:149-151 and :224-226) `encode_prompts(["warmup"])` captures the Gemma-3 encoder trace (always on when dynamic_load=False, encoder_pair.py:156, independent of LTX_TRACED) before `_warmup_prompt_enhancer()`, so E2B's weights/KV/persistent inputs were allocated under an active trace (allocator "potentially unsafe" warning at 18:49:53) and corrupted by the first replay. Attempt 2 loaded the enhancer before `warmup_buffers()` (driver flag AB_ENHANCER_FIRST=1): clean, three greedy probes byte-identical, arm B coherent. Pipeline fix still owed: call `_warmup_prompt_enhancer()` before the encoder's first encode in both branches.

## Still open before serving on the Galaxy (ranked)
1. Latency: rewrite = 53 s for 189 tokens (prefill 0.6 s + 3.6 tok/s decode) against a 24 s LTX generate; floor is the 3.76 tok/s eager decode. Levers unmeasured: traced decode (enable_trace=True is plumbed but needs a trace region on the pipeline handle and capture before the encoder's trace), on-device sampling to drop the 262144-wide logits all-gather, GEMMA4_CCL_ASYNC.
2. Warmup ordering fix in pipeline_ltx_distilled.py (enhancer before the encoder's first encode), plus a regression check that the allocator warning does not precede E2B load.
3. Token cap: default max_new_tokens=512 means ~140 s worst case; A/B used 300 and the model stopped at 189. Pick a serving cap (and max_seq_len budget: 1536-975 template = ~560 user tokens before raw-prompt fallback).
4. Prefix cache: every rewrite re-prefills the ~975-token system prompt; KV prefix reuse would cut prefill to the user tail (small today at 0.6 s, matters once decode is traced).
5. DP rows: generator.data_parallel=1, rows 1-3 compute duplicates; decide whether to keep the full handle (simplest, current) or carve a row submesh (needs a mesh1x8 cache and BH device-name support).
6. Cache location: shared dir works but was created by hand; warm load varies 16.8-50.3 s (NFS page cache). Decide ownership/pre-warm.
7. Logging: results JSON timer bug (warmup_s=-16.8) fixed in the driver after the run, unexercised; log the warmup rewrite texts.
