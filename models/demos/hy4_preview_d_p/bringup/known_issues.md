# Known issues: hy4_preview_d_p

Model-specific lessons moved from the shared file. Shared lessons: `models/demos/common/bringup/knowledge/known_issues.md`.

- **transformers' hy_v4 port uses the wrong RoPE style.** Symptom: Hy4 Preview's full-model HF sanity answered the smoke ("Paris") but scored top-1 next-token accuracy 0.237 on the canonical prompt (floor 0.4; MiMo-V2.6 scored 0.95). The CPU reference matched that oracle at PCC 1.0000000 on every layer, because both followed the same code. Cause: transformers 5.17's `modeling_hy_v4.py` applies rotate-half RoPE ("Non-interleave RoPE") in the MLA and the indexer. The serving stack runs interleaved (GPT-J pair) RoPE in both: SGLang `srt/configs/hy_v4.py` sets `rope_interleave = True` and `indexer_rope_interleave = True`, and `DeepseekV2AttentionMLA` / the DSA indexer use them as `is_neox_style=False`. Fix: the vendored oracle calls an interleaved `apply_rotary_pos_emb_interleaved` (marked "bring-up fix"), and the reference rotates pairs (x[2i], x[2i+1]) in checkpoint order (`hy4_preview_d_p/reference/hf_hy_v4/`, `hy4_ref.py:apply_rope`). The checkpoint's rope dims need no host permutation for an interleaved (Meta-order) device kernel. A parity gate cannot catch an oracle error: keep the HF sanity accuracy floor, and check a new model's HF port against the serving code (SGLang / vLLM model file and config class). Found: hy4_preview_d_p R.2.
- **Vendored newer modeling code calls create_causal_mask with allow_is_causal_skip.** Symptom: `TypeError: create_causal_mask() got an unexpected keyword argument 'allow_is_causal_skip'` running transformers 5.17's hy_v4 code on 5.12.1. Cause: the argument is new in 5.17. 5.12 never skips the mask for eager attention, so dropping it changes nothing. Fix: wrap `create_causal_mask` in the vendored module's namespace to drop the argument and assert a mask came back (`hy4_preview_d_p/reference/hf_oracle.py:_mask_shim`). Found: hy4_preview_d_p R.2.
- **check_hf needs the block output in HF's per-layer shape.** Symptom: check_hf crashed after the PCCs with `The size of tensor a (4) must match the size of tensor b (1024)` (maxabs of the recorded `L{i}.out` minus the HF layer output). Cause: HF's hook output is reshaped to [-1, H]. For iHC's 4 residual streams that is [4S, H], and a [S, 4, H] block output does not broadcast against it. Fix: the Hy4 block boundary is the flat [S, 4H] layout (HF's `flatten(2)` order), and `hooks.hf_layers` returns identity taps. Each layer's forward hook calls its tap with `streams.flatten(2)`, so check_hf's hook sees [S, 4H] too (`hy4_preview_d_p/bringup/hooks.py`). Found: hy4_preview_d_p R.2.
- **Whole-matrix PCC cannot gate the iHC gates.** Symptom: on the Hy4 layer-0 attn_hc golden ([2048, 8] gates, bf16), `post = 1 * sigmoid` instead of `2 * sigmoid` scores PCC 0.991, one chip's missing partial mixes 0.994, an RMS over one stream 0.995, pre gate 3 = pre gate 2 0.9987, and swapped fn rows 0 / 1 0.999998: all pass 0.99. Cause: the 8 columns have very different means (pre ~0.99-1.0 saturated, post 0.11-0.34), so the column means dominate the correlation; the pre columns vary less than the golden's bf16 step. At layer 0 the four streams are identical and fn's four stream blocks are nearly equal (< 1% rel diff), so stream-order bugs are invisible. Fix: also gate rel L2 <= 0.01 and max abs error per column <= 0.015 vs the golden (reference 0.00052 / 0.0019; smallest bug 0.0176 / 0.030) (`hy4_preview_d_p/tests/bringup/test_c_dense_full_attn_hc.py`); leave stream order to the swap tests and later layers. Found: hy4_preview_d_p C.dense_full.attn_hc test.
