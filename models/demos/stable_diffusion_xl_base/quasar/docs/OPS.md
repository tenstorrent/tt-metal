# SDXL base UNet 1024x1024 on Quasar: op inventory

Generated by `tests/ops/generate_cases.py` from a trace of `TtUNet2DConditionModel.forward` (1024x1024 latents 1x4x128x128, encoder states 1x77x2048, Wormhole `ModelOptimisations1024x1024` configs) plus `TtEulerDiscreteScheduler.scale_model_input/step`. Every row is one *distinct* call signature (shapes, dtypes, layouts, memory configs, program configs); `calls` is how many times one UNet forward issues it. Memory configs are the ones the model requests; conv2d output shard specs and matmul block-sharded output specs are derived from the configs (the op picks the real one).

Grids are Wormhole 8x8; Quasar has 8x4. The per-op tests remap them by default (`SDXL_QSR_GRID=fit`).

`bfloat8_b` (all matmul / conv weights, group-norm masks) is **not a Quasar data format** (`is_supported_quasar` in `tt_metal/common/tt_backend_api_types.cpp`: Float16/Float16_b/Float32/Fp8/Int/MxFp*/MxInt*). The per-op tests build those tensors as `bfloat16` (`SDXL_QSR_KEEP_BFP8=1` keeps them) and `ModelOptimisations1024x1024Quasar` defaults every weight dtype to `bfloat16`; MX formats are the eventual target.
