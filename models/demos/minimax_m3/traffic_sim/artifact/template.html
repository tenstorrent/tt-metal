How the cost model is calibrated

Every layer is split into the ops the implementation runs. Each op has a roofline time from its FLOPs, DRAM bytes and ethernet bytes on the stage mesh (Blackhole: 608 TF LoFi / 304 TF HiFi2, 512 GB/s GDDR6, 100 GB/s bidirectional CCL per axis). Its measured efficiency is roofline / (profiled time − latency floor) from the zone profiles (chunk 5120, 51k cached; [2,4], [8,4], [4,2]; [4,4] interpolated). A pipeline fit on 7,840 per-rank, per-chunk-position medians of the 16-stage runs A/B/C adds the 2D-fabric MoE factor, the dense ring-joint compute and capacity-scan efficiencies, embedding, and the blocking stage handoff. The op-efficiency knob moves every op geometrically from its measured efficiency to the target.

Traffic replay

  • Corpus. semianalysisai/cc-traces-weka-062126, full variant (contexts up to 990k). Each request is a chain of 64-token block hashes; hashes are prefix-chained, so a block id is a node of the session's prefix tree.
  • Lanes. Concurrency N creates N lanes. A lane replays one tree (main agent chain + sub-agents). Its start t* is uniform over the session; every stream active at t* is primed with its last turn before t* (a real prefill, max_tokens=1), and measurement starts once all primers finish. A drained tree recycles to the next session from turn 0 with a fresh cache-bust marker.
  • Timing. Next request = previous end + recorded end-to-start delay, uncapped (main-agent gaps: median 4.9 s, mean 395 s). The only cap is AIPerf's 10 s system-idle cap. Sub-agents spawn when the parent turn returns (or at issue on the overlap path) and the join turn fires when the last child ends. Request end = prefill done + out / decode tok/s.
  • Window. 1800 s profiling; goodput counts requests whose prefill finishes inside it.

KV residency

  • Static slots (today): one 1M slot per stream, LRU over idle slots, hit = shared prefix with the stream's previous request, floored to a chunk multiple unless resume is unaligned. Slots are what the memory holds: 20 at 4 galaxies with bf16 index_k replicated ×4.
  • Pool: lanes (fixed 1M or arena-allocated at request size) + a content-addressed paged pool with exact LRU over prefix-tree pieces (equivalent to 64-token pages). Copy-in of the hit and copy-out of the new tokens are DRAM-bound per stage and overlapped with a 25% contention charge. Optional host-DRAM tier: device evictions demote to host, host hits are fetched over PCIe before admission, and write-backs share the link.
  • Paging = pool without lanes or copies (ideal paged kernels). Infinite = everything stays resident.
  • Useful tokens = tokens an infinite prefix cache would prefill. Re-prefill = tokens lost to eviction, alignment or unmaterialised history.

Pipeline

  • Stages process chunks FIFO; a chunk's time per stage is the sum of its layers plus overhead; the blocking send keeps a stage busy after compute; the hop latency delays arrival at the next stage. The in-flight chunk limit is 2S+4.
  • Fixed layout: one request per chunk, padded to the chunk (routed MoE ops use actual tokens). Variable layout: segments padded to 32·SP tokens plus an all-to-all KV write per layer. Batching packs several requests up to the budget; attention runs per request (sequential) or once per chunk (fused), with a core-wave quantization factor.
  • Memory per stage: weights (bf4 experts, bf8 attention, bf16 shared/dense MLP, embedding on stage 0, LM head on the last), a reserve per chip and activation buffers; KV capacity is the minimum over stages.

Not modelled

  • Decode-side capacity and KV migration to decode; decode is a fixed per-request rate.
  • Fragmentation in the lane arena; copy kernels are assumed to be page-list gathers at 50% DRAM efficiency.
  • Host PCIe bandwidth and host DRAM size are assumptions (1 TB and 64 GB/s per galaxy by default); see the sensitivity table.
