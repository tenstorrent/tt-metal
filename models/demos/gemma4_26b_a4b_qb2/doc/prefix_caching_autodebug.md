# Prefix-cache source diagnosis, 2026-10-19

Scope: source-only investigation of experiment head `c56f74cc7f` and downloaded run `39230676369` artifacts. No local tests, imports, builds, servers, device operations, or validation scripts were run. Model source was not edited. The isolated investigation bypassed the AutoDebug launcher under the user's no-local-execution constraint.

## Finding

The strongest supported explanation is a prefill/decode numerical-contract mismatch, not a demonstrated position error. This remains a hypothesis until the remote experiment below separates arithmetic from cache ownership. A cache hit alone does not establish that the reused physical pages contain the correct layer's KV.

`live.xml` records a 33-token prompt `[100..132]`, a hit delta of 32, cold token 128 and warm token 130. It does not retain their complete logits or margins, so neither the magnitude nor the first divergent layer is known. This synthetic sequence is not evidence that the discrepancy is harmless. The cold/warm timings include different cold compilation costs and do not prove acceleration.

## Source evidence

- `tt/generator.py:441` validates absolute end lengths and slices `tokens[start:length]`. For start 32 and end 33 this uploads only token 132. `tt/model.py:218` forwards start 32 unchanged to every layer and selects the last suffix row for logits.
- `tt/multichip_decoder.py:1179` uses `position = start_pos + offset` for both uint32 RoPE lookup and int32 cache position. It selects the request's page-table row, retaining logical page indices. Thus the only suffix token uses absolute position 32, logical page 1, row 0. There is no visible off-by-one or accidental suffix-relative position here.
- `tt/functional_decoder.py:111` pads the cold 33-token sequence to 64 rows. `tt/optimized_decoder.py:1376` fills exactly 64 KV rows, casting to the cache dtype. It then computes first-chunk attention directly from BF16 K/V, **not the quantized BFP8 cache**. Causal attention masks rows 33..63. Prefix rows 0..31 form a complete independent page; the warm update at row 32 should not touch that page. Partial-page preservation is therefore not the leading explanation for this first failure.
- Warm continuation invokes each layer's decode path. It reads the BFP8 prefix cache and uses decode arithmetic. `config/precision.json` explicitly differs between modes: QKV LoFi decode versus HiFi4 prefill, shared weights BFP8 decode versus BF16 prefill, and sliding expert-down weights BFP8 decode versus BFP4 prefill. SDPA fidelity and EP/TP implementation also differ. These are material algorithmic differences, not merely a different batch size. Even perfect page reuse cannot guarantee identical cold-prefill logits with this implementation.
- The transient sliding-prefill tail is not used by continuation; continuation reads paged cache. At position 32 there is no sliding-window eviction. Tail reset/window rollover is accordingly a lower-priority hypothesis.
- `tt/generator_vllm.py:114` pools by `(tensor_index, cache_dtype)` and aliases equal-byte tile storage. Per-device sliding pages `[2,32,256]` and full pages `[1,32,512]` each have 16 tiles; BFP8 tiles have equal storage size, so the shapes have equal physical page bytes. The scheduler spec deliberately uses BF16 accounting with equal padded page sizes. This is not itself evidence of corruption, but correctness depends on scheduler block IDs being disjoint where layers share a tensor pool and stable for every reused group. The artifact does not prove that invariant.

## Discriminating remote experiment

Use the selected full 30-layer policy and exactly the 33-token failing prompt. Retain complete BF16 logits, top candidates/margins, and per-layer suffix outputs. Use independent cache copies or restore cache bytes between arms.

1. Cold-prefill all 33 tokens into dedicated caches and retain logits plus each layer's KV rows 0..31.
2. On those same physical page mappings, replay only token 132 at position 32 through ordinary model decode; separately replay through `prefill_forward(start_pos=32)`. Neither arm uses scheduler cache reuse. They should agree with each other. If both reproduce token 130, the arithmetic-path mismatch is sufficient to explain the API failure.
3. Repeat the continuation with the scheduler's warm HMA tables. Log each layer's pool identity, physical block IDs for logical pages 0 and 1, and prefix KV checksums before processing the suffix. Compare logical prefix rows against arm 1. A mismatch before suffix computation establishes an ownership/lifetime problem independently of numerical differences.
4. If the prefix bytes match but the logits differ between arms 2 and 3, compare the selected table row, absolute positions, and first divergent layer; also check padded SDPA page entries are valid and not aliases of writable pages. If arms 2 and 3 agree, investigate precision/operation parity instead of altering positions or HMA mappings.

An additional BF16-cache arm can estimate cache quantization's contribution but cannot alone eliminate mode-specific weight, fidelity, expert, or RoPE differences. Do not loosen the API equality assertion or remove the seed on the strength of this source diagnosis. Either establish an explicit acceptable numerical contract, or implement continuation with arithmetic matching prefill and validate remotely.

## Follow-up: bounded shared-MLP batching for suffixes

Source-only assessment while remote diagnostic `39233122287` runs: reusing `MultichipDecoder._decode_shared_batch` for 8..32 consecutive tokens of one request is a plausible bounded optimization. It is not a fix for cold-prefill equality and cannot accelerate the failing one-token suffix through batching.

The existing loop computes attention for each row in order, with an individual absolute RoPE position, cache position, and page-table row. `FusedAttention.decode` enqueues the row's KV update before its attention call. Repeating the same request table for all rows therefore preserves causality if positions increase consecutively: token p sees KV through p; token p+1 is updated only afterward. Delaying shared MLP and final tail does not affect that layer's KV, which depends on its input hidden states rather than its output. The entire layer must finish before the next layer consumes the suffix batch. This reasoning assumes the existing ordered dispatch and collective synchronization contract; it is not a hardware proof. Do not replace the loop with one multirow cache-update operation without separately checking duplicate physical-page writes and update-kernel synchronization.

The smallest candidate would group suffix inputs into at most 32 rows, provide current positions `[1,B]`, cache positions `[B]`, and B copies of the request's page table, then use the existing guarded decode entry point. Preserve its requirements: batched-shared flag enabled, Linear topology, replicated residuals, grouped MoE reduction, fused tail, exact `_SharedMLP` type, and initialized decode weights. Chunks below eight rows need the established serial fallback. Repeated rows must retain the absolute logical-page mapping, not shift it by the suffix start. All required pages must remain allocated throughout the group, including across sliding-window boundaries. The input must have the correct logical B; physical tile padding is not an additional token.

Buffer lifetimes are material. The attention collective can return persistent storage, but `_decode_shared_batch` immediately normalizes it and forms a new residual with `ttnn.add` before advancing the loop. `residuals` therefore retains separate allocations. `shared_inputs` similarly retains results of allocation-producing `ttnn.mul`. For the selected hybrid experts' optimized decode branch, the final expert-mixing `ttnn.matmul` supplies no `output_tensor`; retained `routed_rows` consequently owns fresh results. The generalized router does use persistent gate outputs and retained indices, but expert computation consumes them before the next router call. Do not defer experts or collect route tensors without cloning the persistent values/indices. A future expert implementation returning persistent buffers would also require cloning before appending `routed_rows`. Memory-config conversion can alias an existing tensor and should not be treated as a guaranteed clone.

The batched path amortizes shared MLP, grouped MoE collective, and tail only. Attention, routing, and routed experts remain serial. It also changes shared matmul row geometry, collective geometry, and potentially tail arithmetic (`_fused_tail` uses different memory/fast-arithmetic behavior for B>1), so equality to the serial suffix must be measured remotely with full logits and layer outputs. Verify B=8,31,32 and remainders, a page crossing, a sliding-window crossing, and repeated physical-page rows. Do not claim speedup from source inspection.

Cold-prefill parity requires substantially more than batching. It needs consistent QKV/shared/expert weight representations and fidelity, RoPE/norm rounding, expert EP versus TP reduction, attention inputs and kernel arithmetic, and tail handling. In particular BFP8 cached prefix K/V has discarded information that cold first-chunk BF16 attention uses; a continuation algorithm cannot reconstruct that lost information from cache. Options are to make cold attention consume the same quantized cache and otherwise align the modes (changing the cold baseline), retain higher-precision cache with matched prefill-style suffix operations, or define and validate a numerical rather than bitwise contract. BF16 cache alone does not align weights and reductions, and even matched dtypes do not guarantee bitwise equality across SDPA chunking and matrix geometries. A prefix-aware prefill kernel could be faster, but must explicitly honor the absolute causal offset and preserve occupied pages; calling the current cold prefill on the suffix would violate both contracts.

## Follow-up: traced B1 suffix replay

Source assessment while remote boundary run `39235204816` is active: looping over explicit suffix tokens through `Gemma4Generator.decode_forward(return_logits=True)` is a smaller candidate than shared batching. It reuses the existing B1 model trace to remove most host operation dispatch overhead while retaining serial token processing. It adds a vocabulary projection for every suffix token (existing continuation projects only the final row), token/position host uploads each step, and trace warm/capture overhead per request when the adapter releases the preceding trace. The net speedup and the proposed minimum suffix length eight are therefore unproven.

Required gate: one request, `slots == [0]` (or explicitly select/remap the requested row), nonzero start, `return_all_logits=False`, and host page tables with exactly one row per layer. Existing prefill accepts larger table row counts and arbitrary slot indices, whereas `_bind` enforces table rows equal to physical batch. Preserve all columns. Unsupported cases should take the existing path. Returning only the final logits cannot satisfy `return_all_logits=True`.

Trace setup saves tokens and positions, runs a warm forward, restores inputs, captures a forward, then restores inputs again. It does not restore KV. At first suffix position p these forwards rewrite row p of every layer before actual replay; earlier prefix rows should remain unchanged. This is valid under the existing row-update contract because each layer recomputes the same token with the same prefix and overwrites its own row before reading attention. Check prefix bytes remotely, including a non-page-aligned start if that is permitted later. Do not describe capture as mutation-free. Captured position increments are harmless when every call supplies explicit positions and `device_feedback=False`; the next call refreshes both position tensors. A single ordered command queue must continue ordering KV writes, trace replays, and the final clone.

`_trace_returns_logits=True` suppresses seed advancement in `_forward`, avoids sampler precompile/capture in `_capture`, and returns before sampling in `_replay`. Thus there are no suffix sampling draws. `_bind` still resets trace state and binds sampler public token buffers, and `_replay` clears `last_log_probs`. The adapter must perform its usual one final sample or host-logit return afterward. Subsequent ordinary decode changes the logits-mode binding and recaptures as needed; do not overwrite the trace mode flag manually or leave adapter reuse metadata claiming an older trace is valid.

`trace_logits` is persistent and overwritten on every replay. Retaining Python references to each result does not retain each token's values. For final-only output, extract the first logical row from padded `[1,1,32,V/4]` and clone it after the final replay, before any trace release/rebind; reshape to the normal prefill `[1,1,V/4]` return contract. Do not return an alias whose owner can be released by subsequent sampling setup. Intermediate trace outputs need not be cloned. The existing capture allocates and retains its buffers; new per-token work must remain outside capture and use the established input-copy path.

Parity with serial continuation is plausible but not guaranteed by source. Both run B1 decode layers, but serial continuation executes a whole suffix layer-by-layer, whereas model replay executes all layers token-by-token. These orders are mathematically equivalent with causal attention and token-local MLPs. Trace decode uses `model.rope_decode` ROW_MAJOR tables and padded positions; existing continuation reshapes TILE `rope_prefill` tables and uses a one-entry position tensor. Both derive from the same HF cos/sin values, but their embedding/kernel signatures differ. Persistent CCL/router reuse patterns also change. Compare final BF16 logits exactly and logical per-layer KV against the existing serial path on identical cloned caches, then inspect the first differing layer if needed. This candidate retains the original decode-versus-cold-prefill numerical discrepancy; it does not solve that contract.

Remote acceptance should include suffix lengths 8,31,32 and a page/window crossing, capture counts showing one capture per suffix request, sampler seed/counter stability during suffix processing, unchanged cached-prefix bytes, final logits/greedy parity to serial continuation, and warmed end-to-end time including capture and extra LM-head work. No implementation or local executable validation was performed for this assessment.
