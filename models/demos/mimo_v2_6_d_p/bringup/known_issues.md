# Known issues: mimo_v2_6_d_p

Model-specific lessons moved from the shared file. Shared lessons: `models/demos/common/bringup/knowledge/known_issues.md`.

- **Fused fp8 qkv stored per TP rank.** Symptom: layer-0 `qkv_proj.weight_scale_inv` has 108 row blocks, not ceil(13568 / 128) = 106; a global [q; k; v] split gives wrong heads. Cause: the checkpoint (tp_size 4) stores [q_r; k_r; v_r] per rank, each slab quantized on its own 128-row blocks. Fix: dequantize each rank slab with its own scale rows, then reorder (`mimo_v2_6_d_p/reference/weights.py:qkv_weight`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p R.2.
- **Remote modeling code older than the installed transformers.** Symptom: the loader stops on the missing `model_mtp.safetensors`; transformers 5.12 rejects the checkpoint's `create_causal_mask(input_embeds=..., cache_position=...)`. Cause: modeling_mimo_v2.py targets transformers 5.3. Fix: `hf_model` builds the class on the meta device, loads the text weights, and wraps the mask functions (`mimo_v2_6_d_p/reference/hf_oracle.py`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p R.2.
- **A zero stub passes the layer-0 swap gate.** Symptom: MiMo full_dense swap 01 with a zero attn_norm scores pcc_swap_out 0.9884 (gate 0.98). Cause: at layer 0 the residual and the golden-prefix attention dominate block out. Fix: also assert the step's own rel L2 (<= 0.03) and norm ratio, and block-out rel L2 <= 0.01 (stub 0.155) (`mimo_v2_6_d_p/tests/bringup/test_swap_full_dense_01_attn_norm.py`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p S.full_dense.01.
- **Rel L2 0.03 is too loose for full attention with a slow RoPE.** Symptom: on MiMo layer 0, RoPE from position 0, a non-causal mask or scale 1/sqrt(Dv) (rel 0.025-0.040) pass the Gemma template's limits. Cause: theta 1e7 on 64 of 192 dims, long prefix. Fix: set rel L2 limits from measured mutations (MiMo: 0.015 whole and first 128 rows) (`mimo_v2_6_d_p/tests/bringup/test_c_full_dense_attention.py`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p C.full_dense.attention test.
- **Sliding-window off-by-one hides inside device noise.** Symptom: on MiMo layer 1, windows 127 and 129 score rel L2 0.010 vs device noise 0.007. Cause: one key per row changes; the sink takes most of the softmax mass. Fix: also assert the output is closer to the CPU reference at window W than at W-1 and W+1 (`mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_attention.py`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p C.sliding_moe.attention test.
- **A zeroed attention barely moves a sink-dominated block out.** Symptom: MiMo layer 1 with attn_out zeroed: block-out rel L2 0.014, inside the Gemma limit 0.02 (device 0.0031). Cause: the sink keeps attn_out small. Fix: size the block-out limit from the device and a zeroed step (MiMo 0.01); check attention vs CPU on the same input (rel <= 0.015). Detail: known_issues_detail.md. Applies to: models/demos/mimo_v2_6_d_p/tests/bringup/test_swap_sliding_moe_02_attention.py. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p S.sliding_moe.02 test.
- **A residual test cannot see a small addend.** Symptom: on MiMo layer 1, `in + 0.5 attn_out` passes the full_dense residual limits. Cause: the sink keeps ||attn_out|| about 1% of ||in||. Fix: also check `delta = out - in`: `<delta, attn_out> / ||attn_out||^2` in [0.95, 1.05], `||delta - attn_out|| / ||attn_out|| <= 0.3` (`mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_attn_residual.py`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p C.sliding_moe.attn_residual test.
- **Experts tests cannot see small dropouts.** Symptom: on MiMo layer 1, dropping expert 255 (3 tokens) or a uniform x1.02 scale passes every experts check. Cause: top-8 of 256 spreads each pair thin. Fix: kept the Gemma limits; expect LoFi unified_routed_expert_moe near rel 0.03, measure it early. Detail: known_issues_detail.md. Applies to: models/demos/mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_experts.py, unified_routed_expert_moe. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.sliding_moe.experts test.
- **The fused Silu expert kernel fails the norm-ratio check, and routed_expert_ffn rejects fp32 dest.** Symptom: MiMo layer-1 ratio [0.963, 1.054] vs [0.97, 1.03]. Cause: forced LoFi + bf16 dest. Fix: the fork's `high_precision=True`. Detail: known_issues_detail.md. Applies to: models/demos/mimo_v2_6_d_p/tt/experts.py, models/demos/mimo_v2_6_d_p/tt/model.py, unified_routed_expert_moe, ttnn/cpp/ttnn/operations/experimental/deepseek_prefill/routed_expert_ffn, ttnn/cpp/ttnn/operations/experimental/deepseek_prefill/insert. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.sliding_moe.experts.
- **Router mutations score differently per layer.** Symptom: a bf16 correction bias passes the 0.99 PCC gate on MiMo layer 5 (0.9937) but failed on layer 1 (0.970); the selection overlap check catches it. Cause: layer 5's bias is smaller, so fewer rows flip. Fix: keep overlap and row checks in every router test; re-measure mutations per layer (`mimo_v2_6_d_p/tests/bringup/test_c_full_moe_router.py`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p C.full_moe.router test.
- **bfp8 expert activations fail on a layer with outlier channels.** Symptom: MiMo layer-5 experts with bfp8 x: rel L2 0.045, norm ratio [0.862, 1.107]. Cause: outliers (|x| to 131) flush bfp8 block neighbours. Fix: bf16 x via the fork's `high_precision=True`; check the MoE input's per-channel max first. Detail: known_issues_detail.md. Applies to: models/demos/mimo_v2_6_d_p/tests/bringup/test_c_full_moe_experts.py, unified_routed_expert_moe. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.full_moe.experts test.
- **bf16 expert intermediates and HiFi2 widen the per-token norm ratio.** Symptom: MiMo layer-5 loop experts at HiFi2 + bf16 gate/up/h: ratio [0.960, 1.061]. Cause: mantissa truncation and bf16 rounding before the K=2048 down. Fix: HiFi4, fp32 dest and fp32 gate/up/h: [0.988, 1.016]. Detail: known_issues_detail.md. Applies to: models/demos/mimo_v2_6_d_p/tt/experts.py, models/demos/mimo_v2_6_d_p/tt/model.py. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.full_moe.experts.
- **Routing flips break a per-token block-out ratio vs golden on a layer with large experts.** Symptom: MiMo layer-5 swap 07 per-token ratio vs golden hits 0.9694 (limit 0.98). Cause: near-tie router flips (184 of 2048 rows) swap a whole large expert. Fix: [0.98, 1.02] on rows with the golden top-8, [0.9, 1.1] on flipped rows (`mimo_v2_6_d_p/tests/bringup/test_swap_full_moe_07_ffn_residual.py`). Detail: known_issues_detail.md. Found: mimo_v2_6_d_p S.full_moe.07 test.
- **Streaming SDPA: at head_dim 192, a larger Q chunk halves the prefix traffic, but k128 costs accuracy.** Symptom: q256/k256 56.5 ms. Cause: traffic scales with Q chunks; q512/k256 overflows L1. Fix: q512/k128 (default), 44.9 ms but PCC 0.99962 -> 0.99842. Detail: known_issues_detail.md. Applies to: models/demos/mimo_v2_6_d_p/tt/attention.py, ttnn.bringup.chunked_scaled_dot_product_attention. Seen at: 864ec8b0891. Check: `MIMO_SDPA_Q` / `MIMO_SDPA_K` = 256/256, 512/128, 512/256 through test_profile.py (attention.sdpa) and the s56320 ladder rung, 1x4 QuietBox. Found: mimo_v2_6_d_p P.2.
- **Sliding-window SDPA with sinks: the speed-up is the streaming kernel, not HiFi2 or approx exp.** Symptom: config A fails the sliding-layer component test (ratio 1.0504 > 1.05). Cause: the sink-to-max gap magnifies QK error, mostly from bf16 dest. Fix: HiFi4 + fp32 dest off + exact exp (preset "S"), same time as A. Detail: known_issues_detail.md. Applies to: models/demos/mimo_v2_6_d_p/tt/attention.py (SDPA_PRESETS), ttnn/ttnn/bringup/sdpa/device/sdpa_program_factory.cpp (can_use_streaming_compute). Seen at: 864ec8b0891. Found: mimo_v2_6_d_p P.2.
