# Known issues: mimo_v2_6_d_p

Model-specific lessons moved from the shared file. Shared lessons: `models/demos/common/bringup/knowledge/known_issues.md`.

- **Fused fp8 qkv stored per TP rank.** Symptom: MiMo-V2.6 layer-0 `qkv_proj.weight_scale_inv` has 108 row blocks where ceil(13568 / 128) = 106; a global [q; k; v] split of the dequantized weight would give wrong heads. Cause: the checkpoint (`metadata.tp_size: 4`) stores the fused projection as [q_r; k_r; v_r] per rank, each rank slab quantized on its own 128-row blocks (layer 1 divides evenly, so only the row-norm pattern shows it). Fix: dequantize each rank slab with its own scale rows, then reorder to [q; k; v] (`mimo_v2_6_d_p/reference/weights.py:qkv_weight`); check the scale count and per-row norms of any fused, quantized projection. Found: mimo_v2_6_d_p R.2.
- **Remote modeling code older than the installed transformers.** Symptom: the stock loader stops on the missing `model_mtp.safetensors` listed in the index, and the checkpoint's modeling code calls `create_causal_mask(input_embeds=..., cache_position=...)`, which transformers 5.12 rejects. Cause: modeling_mimo_v2.py targets transformers 5.3; MTP shards were not downloaded. Fix: `hf_model` builds the class from the checkpoint on the meta device, loads the text weights itself, and wraps the two mask functions in the modeling module's namespace to rename `input_embeds` and drop `cache_position` (`mimo_v2_6_d_p/reference/hf_oracle.py`). Found: mimo_v2_6_d_p R.2.
- **A zero stub passes the layer-0 swap gate.** Symptom: MiMo full_dense swap 01 (attn_norm) with a zero attn_norm scores pcc_swap_out 0.9884 (gate 0.98); sum-instead-of-mean 0.9890 and eps 1e-2 0.9916 also pass. Cause: at layer 0 the residual stream and the attention over the golden KV prefix (zero Q gives uniform attention, attn_out PCC still 0.97) dominate block out. Fix: the swap test asserts the swapped step's own rel L2 (<= 0.03) and per-token norm ratio, and block-out rel L2 <= 0.01 (zero stub 0.155), so pytest fails even when the gated metric passes (`mimo_v2_6_d_p/tests/bringup/test_swap_full_dense_01_attn_norm.py`). Found: mimo_v2_6_d_p S.full_dense.01.
- **Rel L2 0.03 is too loose for full attention with a slow RoPE.** Symptom: on MiMo layer 0 (s4096 chunk 1, 2048-row KV prefix) RoPE positions from 0 score PCC 0.99968 / rel 0.025, a non-causal mask 0.99960 / rel 0.0285, scale 1/sqrt(Dv) 0.99931 / rel 0.040: all pass PCC 0.99 and the whole-chunk rel L2 0.03 of the Gemma template. Cause: theta 1e7 on 64 of 192 dims and a long prefix; the reference and bf16/bfp8 rounding sit at rel 0.002. Fix: measure the mutations on the golden and set the rel L2 limits between the device noise and the smallest bug (MiMo: 0.015 whole and first 128 rows; the first rows catch non-causal at 0.047) (`mimo_v2_6_d_p/tests/bringup/test_c_full_dense_attention.py`). Found: mimo_v2_6_d_p C.full_dense.attention test.
- **Sliding-window off-by-one hides inside device noise.** Symptom: on MiMo layer 1 (window 128, s4096 chunk 1) windows 127 and 129 score PCC 0.99998 / rel L2 0.010 / worst row 0.047, about the same as the device-noise estimate (rel 0.007, worst row 0.025), so no size limit separates them. Cause: one key per query row changes, and the sink takes most of the softmax mass (sink up to 1.14, key scores median -26; attn_out row norms 0.007-0.057). Fix: also assert the output is closer (rel L2) to the CPU reference at window W than to the same reference at W-1 and W+1. Random device noise does not point along the off-by-one difference: simulated noise, even with 1% added, always lands closest to its own window (`mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_attention.py`). Found: mimo_v2_6_d_p C.sliding_moe.attention test.
- **A zeroed attention barely moves a sink-dominated block out.** Symptom: on MiMo layer 1 (sliding_moe) the swap harness with attn_out zeroed scores block-out rel L2 0.014, inside the Gemma swap-02 limit of 0.02. The device scores 0.0031. Cause: the per-head sink takes most of the softmax mass, so attn_out row norms (0.007-0.057) are small next to the residual. Fix: size the block-out limit from the device run and a zeroed step (MiMo: 0.01), and also check the attention against the CPU attention on the same device input (rel <= 0.015, device 0.0070) (`mimo_v2_6_d_p/tests/bringup/test_swap_sliding_moe_02_attention.py`). Applies to: models/demos/mimo_v2_6_d_p/tests/bringup/test_swap_sliding_moe_02_attention.py. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p S.sliding_moe.02 test.
- **A residual test cannot see a small addend.** Symptom: on MiMo layer 1 (sliding_moe) `h_mid = in + attn_out` with attn_out dropped scores PCC 0.99993, rel L2 0.0113; `in + 0.5 attn_out` scores 0.99996 / 0.0060 and passes the full_dense limits (rel 0.01, norm ratio [0.99, 1.01]). Cause: the sink keeps ||attn_out|| (0.88) about 1% of ||in|| (79), so whole-output metrics barely see it. Fix: also check the addend on `delta = out - in`: coefficient `<delta, attn_out> / ||attn_out||^2` in [0.95, 1.05] and `||delta - attn_out|| / ||attn_out|| <= 0.3` (bf16 output rounding alone gives 0.15) (`mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_attn_residual.py`). Found: mimo_v2_6_d_p C.sliding_moe.attn_residual test.
- **Experts tests cannot see small dropouts.** Symptom: on the MiMo layer-1 golden, dropping expert 255 (3 tokens) or one token's smallest-weight pair passes every experts check (worst row rel L2 0.044-0.090, limit 0.1), and so does a uniform x1.02 scale (rel 0.020, ratio [1.015, 1.024]). Meanwhile bfp8 weights in the device layout plus bfp8 activations give rel 0.009 and worst row 0.028, and a crude LoFi model (one operand truncated to 5 bits) gives rel 0.048, which fails. Cause: 256 experts with top-8 and sum-1 routing weights spread each pair's contribution thin, so one small pair moves one row by under 10%. mxfp4 weights are exact in bfp8 only when bfp8 blocks run along the input dim; the device layout blocks along the output dim, so weights are not exact (rel 0.0037). Fix: kept the Gemma limits (rel 0.03, ratio [0.97, 1.03], worst row 0.1) and recorded the gaps in the test docstring. The implement step should expect the LoFi Silu path of unified_routed_expert_moe to be near or over rel 0.03, and should measure it early (`mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_experts.py`). Applies to: models/demos/mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_experts.py, unified_routed_expert_moe. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.sliding_moe.experts test.
- **The fused Silu expert kernel fails the norm-ratio check, and routed_expert_ffn rejects fp32 dest.** Symptom: MiMo layer-1 experts through `unified_routed_expert_moe` (Silu, bfp8 weights) score PCC 0.99982 and rel L2 0.019, but per-token norm ratio [0.963, 1.054] (limit [0.97, 1.03]). `moe_fused_swiglu` for every expert (HiFi2, bf16 dest) is worse: rel 0.030, ratio [0.961, 1.055]. `routed_expert_ffn` with fp32 dest raises TT_FATAL "out_subblock_w 6 times out_subblock_h 1 needs to be at most 4", and `insert` needs its buffer and slab in the same dtype. Cause: the unified factory forces LoFi and a bf16 dest for every variant except GeluTanh. `routed_expert_ffn_bh` hard-codes subblocks sized for a bf16 dest. Fix: when `ttnn/cpp` is outside the step's paths, run each local expert as `extract` (cap = chunk length) -> `ttnn.linear` gate / up (HiFi2, fp32 dest, auto config) -> `multiply` with a SILU input activation -> `ttnn.linear` down -> `insert` into a bf16 TILE buffer. It scores PCC 0.99995, rel 0.0100, ratio [0.980, 1.011], worst row 0.029, but is 10x slower (148 ms vs 14 ms per layer at S=5120). The fast fix is the fork's `high_precision=True` (`ttnn.bringup.unified_routed_expert_moe`, see the Float32-partials entry) (`mimo_v2_6_d_p/tt/experts.py`; `MIMO_EXPERTS_MODE=unified|unified_lofi|fused|loop`, read in `tt/model.py:build_experts`: `unified`, the default, is the high_precision path, `unified_lofi` the LoFi one measured here). Applies to: models/demos/mimo_v2_6_d_p/tt/experts.py, models/demos/mimo_v2_6_d_p/tt/model.py, unified_routed_expert_moe, ttnn/cpp/ttnn/operations/experimental/deepseek_prefill/routed_expert_ffn, ttnn/cpp/ttnn/operations/experimental/deepseek_prefill/insert. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.sliding_moe.experts.
- **Router mutations score differently per layer.** Symptom: on the MiMo layer-5 router golden a bf16 correction bias scores PCC 0.9937 and passes the 0.99 gate. On layer 1 the same mutation scored 0.970 and failed; the selection overlap check (0.952 < 0.985) is what catches it at layer 5. Cause: layer 5's bias is smaller (0.72..1.09, choice score <= 1.83, bf16 step 0.0078 vs a median 8th/9th gap of 0.0028), so fewer rows flip. Fix: keep the overlap and row checks in every router test, and re-measure the mutations on each layer's golden rather than reusing another layer's PCC margins (`mimo_v2_6_d_p/tests/bringup/test_c_full_moe_router.py`). Found: mimo_v2_6_d_p C.full_moe.router test.
- **bfp8 expert activations fail on a layer with outlier channels.** Symptom: MiMo layer-5 experts on device (`MIMO_EXPERTS_MODE=loop`, bfp8 weights, x converted to bfp8) score PCC 0.99899 (passes the gate) but rel L2 0.045, per-token norm ratio [0.862, 1.107], worst row 0.158. Layer 1 with the same module scored rel 0.010. Cause: layer 5's ffn_norm output has large outlier channels in every row (|x| up to 131 on channel 3891, median |x| 0.009; post_attention_layernorm w goes up to 8.75). bfp8 shares one exponent per 16 values, so small channels next to an outlier are flushed. A CPU model of bfp8 x alone gives rel 0.045 / worst row 0.135. bfp8 weights (blocks along the output dim) with bf16 x give rel 0.0051, the same as the CPU reference (0.0050). Fix: keep the expert input in bf16 (weights stay bfp8). The source unified_routed_expert_moe packs a ROW_MAJOR x and its intermediates to bfp8, so it cannot pass here; the fork's `high_precision=True` (`ttnn.bringup.unified_routed_expert_moe`) keeps both in bf16. Check the per-channel max of the MoE input on every MoE layer before choosing activation dtypes (`mimo_v2_6_d_p/tests/bringup/test_c_full_moe_experts.py`). Applies to: models/demos/mimo_v2_6_d_p/tests/bringup/test_c_full_moe_experts.py, unified_routed_expert_moe. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.full_moe.experts test.
- **bf16 expert intermediates and HiFi2 widen the per-token norm ratio.** Symptom: MiMo layer-5 experts in loop mode with bf16 x and bfp8 weights still failed the norm-ratio check: HiFi2 + bf16 gate/up/h gave rel 0.0129, ratio [0.960, 1.061]; HiFi4 + bf16 intermediates gave rel 0.0075, ratio [0.976, 1.028] (passes, 0.002 from the limit). Cause: HiFi2 truncates operand mantissas, and rounding the gate/up outputs and silu(g)*u to bf16 before the K=2048 down projection adds per-row error on rows that have few large contributions. Fix: HiFi4 + fp32 dest, and fp32 gate/up/h (`ttnn.linear(..., dtype=ttnn.float32)`, `multiply(..., dtype=ttnn.float32)`): rel 0.0067, ratio [0.988, 1.016], the same as the CPU reference; layer 1 goes from rel 0.0100 to 0.0056 (`mimo_v2_6_d_p/tt/experts.py` loop mode, `MIMO_EXPERTS_MODE=loop`; `MIMO_EXPERTS_MID=bf16` / `MIMO_EXPERTS_FIDELITY=HiFi2` / `MIMO_EXPERTS_ACT=bfp8` for comparison, read in `tt/model.py:build_experts`). Applies to: models/demos/mimo_v2_6_d_p/tt/experts.py, models/demos/mimo_v2_6_d_p/tt/model.py. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p C.full_moe.experts.
- **Routing flips break a per-token block-out ratio vs golden on a layer with large experts.** Symptom: MiMo layer-5 swap 07 (all steps on device) fails the per-token norm ratio vs golden [0.98, 1.02] at a minimum of 0.9694, while the add vs the CPU add on the same inputs is [0.9995, 1.0011]. Cause: the device router's near-tie flips (184 of 2048 rows) change a whole expert in a row, and layer-5 experts outputs are large (expert 235 norm ~690). Rows with the golden routing are at [0.9970, 1.0034]. Fix: split the per-token golden check by routing: [0.98, 1.02] on rows whose top-8 selection equals the golden one, [0.9, 1.1] on flipped rows (`mimo_v2_6_d_p/tests/bringup/test_swap_full_moe_07_ffn_residual.py`). Found: mimo_v2_6_d_p S.full_moe.07 test.
- **Streaming SDPA: at head_dim 192, a larger Q chunk halves the prefix traffic, but k128 costs accuracy.** Symptom: MiMo full-attention chunked SDPA (config A) at 51k->56k: q256/k256 takes 56.5 ms for the 2 full layers (V 128; 67.8 ms with V padded to 192). Cause: causal/chunked SDPA gets no KV chain forwarding, so the traffic scales with the number of Q chunks; at head_dim 192, q512/k256 still exceeds L1 (static CBs clash with an L1 buffer by ~20 KB). Fix: q512/k128 gives 44.9 ms (the default). With bf16 dest, k128 lowers the long-prefix (s56320) worst layer PCC from 0.99962 (q256/k256) to 0.99842, probably from twice as many online-softmax rescale steps: well inside 0.97, but take k256 when the time allows. HiFi4 at q512/k128 was 88.6 ms (V 192): the full SDPA is compute-bound under config A (`mimo_v2_6_d_p/tt/attention.py` SDPA_PRESETS). Applies to: models/demos/mimo_v2_6_d_p/tt/attention.py, ttnn.bringup.chunked_scaled_dot_product_attention. Seen at: 864ec8b0891. Check: `MIMO_SDPA_Q` / `MIMO_SDPA_K` = 256/256, 512/128, 512/256 through test_profile.py (attention.sdpa) and the s56320 ladder rung, 1x4 QuietBox. Found: mimo_v2_6_d_p P.2.
- **Sliding-window SDPA with sinks: the speed-up is the streaming kernel, not HiFi2 or approx exp.** Symptom: config A on MiMo's sliding layers (window 128, sink, head_dim 192) fails the frozen component test (row norm ratio 1.0504 > 1.05, rel 0.0142 vs base 0.0086). Cause: the sink-to-max gap magnifies QK error. bf16 dest (needed for streaming) accounts for most of it; HiFi2 on top pushes the ratio to the limit. Fix: HiFi4 + fp32 dest off + exact exp (preset "S"): rel 0.0136, ratio [0.964, 1.046], and the same time as A (4 layers 2.5 ms vs 19.7 ms with fp32 dest). Applies to: models/demos/mimo_v2_6_d_p/tt/attention.py (SDPA_PRESETS), ttnn/ttnn/bringup/sdpa/device/sdpa_program_factory.cpp (can_use_streaming_compute). Seen at: 864ec8b0891. Found: mimo_v2_6_d_p P.2.
