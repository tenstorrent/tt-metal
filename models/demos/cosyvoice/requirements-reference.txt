# CosyVoice REFERENCE-ONLY requirements, host CPU
# derived from FunAudioLLM/CosyVoice@074ca6d requirements.txt
#
# NOTHING IN THIS FILE IS INSTALLED TO RUN THE MODEL. It builds `cosyvoice_env`, a
# host-only venv with exactly three jobs: capturing the PyTorch goldens, exporting
# weights, and WER/SIM scoring. The on-device model, the demo and every test under
# tests/ run in tt-metal's own python_env and import only torch, numpy, ttnn and
# loguru — all of which tt-metal already ships. Merging this demo installs nothing
# from here. docs/security.md documents that boundary and the advisory disposition.
#
# Deltas from upstream, forced by "no NVIDIA GPU on this host":
#   1. torch/torchaudio pulled from the CPU wheel index with an explicit +cpu local
#      tag, instead of --extra-index-url .../cu121. The +cpu tag exists only on the
#      PyTorch CPU index, so resolution is unambiguous even with PyPI in the mix.
#   2. deepspeed          — dropped. Builds CUDA kernels at install time; training-only.
#   3. onnxruntime-gpu    — replaced by onnxruntime. Used by the speech tokenizer
#                           (speech_tokenizer_v1.onnx) and campplus.onnx.
#   4. tensorrt-cu12*     — dropped (3 pins). TRT export path, CUDA-only by definition.
#   5. The onnxruntime-cuda-12 --extra-index-url — dropped with onnxruntime-gpu.
#
# Deltas forced by dependency advisories. Upstream's pins carry four CRITICALs and a
# long tail of HIGHs. This venv is host-only, but it does torch.load three checkpoints
# fetched from ModelScope, so the supply-chain surface is not hypothetical.
#
#   6. Dropped, because nothing on the reference path imports them. Established by
#      tracing every import performed while resolving CosyVoice-300M/cosyvoice.yaml —
#      the widest closure the reference reaches, since hyperpyyaml eagerly resolves the
#      training-only data_pipeline keys as well as the model ones:
#
#        gradio                        webui.py / matcha app.py only
#        onnx                          zero direct imports; torch's own is try-guarded
#        fastapi, fastapi-cli, uvicorn runtime/python/fastapi/server.py only
#        grpcio, grpcio-tools          runtime/python/grpc/ only
#        tensorboard, networkx,        never imported by anything, at any depth
#        pydantic, x-transformers      (x-transformers is the CosyVoice-3 DiT flow)
#
#      Dropping gradio and onnx is where most of the reduction comes from, and it moves
#      no version the goldens depend on. docs/security.md carries the tally.
#
#   7. Bumped, because these ARE imported, to a version clearing their advisories:
#      diffusers (matcha's decoder needs get_activation), lightning (matcha.utils.pylogger
#      drags it in), modelscope, gdown, pyarrow (a module-level pyarrow.parquet in
#      cosyvoice/dataset/processor.py), protobuf, transformers, torch/torchaudio,
#      hydra-core.
#
#      hydra-core 1.3.2 -> 1.3.4 clears CVE-2026-68508 (GHSA-2cp2-2r3c-7p7r, HIGH:
#      hydra.utils.instantiate executes code from an untrusted config). It is imported,
#      though only as a side effect: matcha/utils/__init__.py imports instantiators,
#      which imports hydra, and cosyvoice/flow/flow_matching.py reaches that package
#      through matcha.utils.pylogger. instantiate itself is called only from
#      matcha/train.py, which the reference never runs, so the exposure was already
#      nil -- but 1.3.4 is a patch bump holding omegaconf<2.4,>=2.2, the same range
#      1.3.2 held, so there is no reason to carry the finding.
#
#      transformers goes to 5.5.0, clearing all eight of its advisories. The reference
#      touches two corners of it -- Qwen2ForCausalLM in cosyvoice/llm/llm.py, and
#      AutoFeatureExtractor/WavLMForXVector in scripts/eval_wer_sim.py -- and both import
#      and run unchanged on 5.x. An earlier pass here concluded 5.x had dropped top-level
#      Qwen2ForCausalLM; that was a confounded test. It was measured in an environment
#      that also carried torch 2.9.1, and torch 2.9.1 breaks that same import on its own
#      (see below) -- transformers 4.53.0 fails identically there. On torch 2.6.0, 5.5.0
#      is clean and reproduces the goldens bit-for-bit against 4.53.0.
#
# What is deliberately still outstanding, and why:
#
#   torch         3 open, all MEDIUM local-DoS. CVE-2025-2998 has no fixed version at
#                 all. 2.8.0/2.9.1 would clear the other two but break this venv twice
#                 over: torch>=2.8's inductor imports triton.backends, which the triton
#                 that openai-whisper pins does not have, and torchaudio 2.9 removed its
#                 native decoder so torchaudio.load needs torchcodec + FFmpeg. Paying
#                 that to close two local-DoS findings in a host-only venv is a bad
#                 trade; 2.6.0 is what clears the CRITICAL (CVE-2025-32434, torch.load
#                 RCE), which is the one that matches how this venv is actually used.
#
# onnxruntime is held at 1.18.0 on purpose, and not because of an advisory — it has
# none. It runs speech_tokenizer_v1.onnx, and 1.23.2 emits a different token sequence
# for the same audio. That reroutes the LLM and desynchronises every downstream RNG
# draw: regenerating on 1.23.2 gives an e2e waveform at PCC 0.01 against the committed
# goldens, with the noise tensors at ~0. Moving it means regenerating the whole set.
#
# requests/urllib3 are deliberately NOT pinned. The PyTorch CPU index carries requests,
# and uv resolves a package from the first index that has it — a dependency-confusion
# defence. Pinning a PyPI-only version here forces --index-strategy unsafe-best-match,
# which would disable that check for every package in this file.
#
# Every golden in tests/golden/ was regenerated on these pins and compared against the
# committed set before they were taken; nothing here moves the reference the TTNN port is
# measured against. docs/security.md has the figures and the command to repeat it.
