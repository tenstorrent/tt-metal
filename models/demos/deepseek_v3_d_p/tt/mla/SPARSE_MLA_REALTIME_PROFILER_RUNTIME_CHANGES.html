Sparse MLA · GLM-5.2 · device-time qualification

Why overlap required realtime-profiler runtime changes

Commit 20e839e1ff9032573690c031751ad58b5e967fed changes the realtime profiler so topk_large_indices and high_bw_all_gather can be identified and timed independently while they run concurrently on separate subdevices. The old profiler was designed around one globally active program interval. It could time serial work, but it could not produce trustworthy per-program intervals for independent subdevice streams.

Scope: every changed file in the commit, including the host-side measurement helper. No tensor D2H or host-clock timing fallback is used.

The precise claim

The execution feature and its proof are different. Sparse MLA can launch top-k and gather concurrently without these profiler changes. What was impossible with the old profiler was the required production evidence: on every chip, identify both programs from the same forward, retain their raw device start/end ticks, prove that their intervals intersect, and compare their union with the serialized branch.

The exact code in this commit is not the only conceivable implementation. However, a valid solution needs equivalent runtime properties: identity attached to the actual go command, timing state per subdevice stream, completion attribution per stream, lossless record handoff, and raw intervals exposed to the qualification layer. A Python-only change cannot reconstruct information that the device runtime merged, mislabeled, or overwrote before delivery.

Why the old design failed under overlap

One implicit active interval

Start time and program ID were sampled around the dispatch-s command loop, not stored independently for each worker-completion stream.

One global end sample

The monitor noticed that some stream changed and wrote a shared end timestamp. Two active subdevices had no durable stream-to-end mapping.

Overwrite-prone notification

Ping-pong A/B slots had no acknowledgement back to dispatch-s. Closely spaced completions could reuse a slot before its record was safely consumed.

Duration, not interval

The Python helper returned only duration. Equal or improved duration cannot prove concurrency; overlap requires the intersection of two raw intervals.

Profiling top-k and gather in separate runs would measure serial microbenchmarks, not contention and concurrency in the real sparse-MLA forward. Bracketing each operation with host synchronization would perturb or serialize the schedule. Bracketing the whole branch with a host timer would provide only a makespan and could not establish that the two device programs overlapped.

The new end-to-end record path

Program runtime
patch runtime ID into go command
dispatch-s
start interval in the selected stream slot
stream monitor
capture that stream's completion tick
SPSC queue
retain complete interval until acknowledged
host callback
expose raw ticks and fail on loss

All interval boundaries originate from device wall clocks. Records are eventually transported to the host by the profiler, as profiler records always are; no tensor is copied to host to infer completion, and host elapsed time is never substituted for device time.

Why every runtime change was necessary

Changed fileWhat changedWhy the goal could not be met without it
tt_metal/impl/program/dispatch.cpp The normal and traced enqueue paths patch the current runtime_id directly into the cached multicast go command. A program ID in a separate asynchronous FIFO is not a reliable identity boundary once commands for independent subdevices interleave. Identity must travel with the exact command that starts the work. Updating both normal and trace paths prevents traced execution from silently reverting to ambiguous attribution.
device_command.hpp
device_command.cpp		 add_dispatch_go_signal_mcast accepts a 16-bit profiler program ID and serializes it into the device command. The default zero remains the unprofiled sentinel for callers whose runtime ID is patched later or that do not participate. This is the host-to-device transport for command-bound identity. Without it, dispatch-s would still have to guess which FIFO ID belongs to which interleaved go command.
cq_commands.hpp CQDispatchGoSignalMcastCmd gains profiler_program_id. wait_stream is narrowed from 32 to 16 bits so the packed command does not grow. The firmware command ABI must contain the identity field for dispatch-s to consume it. The stream index is bounded far below 16 bits, so repacking preserves the fixed command footprint instead of expanding command-queue traffic or breaking layout assumptions.
realtime_profiler_msgs.h Adds a 128-entry, eight-word-per-record SPSC queue; monotonic read/write indices; and per-stream end-time and completion-count arrays for the eight dispatch message streams. This is the durable shared state the old global A/B slots lacked. Per-stream fields preserve which completion belongs to which active subdevice. The queue absorbs bursts of closely spaced completions and prevents a later interval from overwriting an earlier unread one.
kernel_config/dispatch_s.cpp Initializes the queue indices and every per-stream timestamp/completion field to zero when dispatch-s is configured. These fields live in reused L1 memory, not automatically zeroed language-runtime storage. Uninitialized indices could make an empty queue look full or non-empty; stale completion counts could close the first measured program with a previous run's timestamp.
kernels/realtime_profiler.hpp Extracts read_realtime_wall_clock and reuses it from the legacy timestamp helper and the new per-stream paths. It preserves the required low-then-high register read order. Start and end producers now live in more than one firmware path. A shared primitive keeps both readings in the same device clock domain and avoids subtly different latch ordering. Host clocks cannot replace this because they include dispatch and synchronization latency.
cq_realtime_profiler_dispatch_subordinate.hpp The monitor masks stream counters to their hardware width, initializes published completion counts, and writes end ticks plus completion count into the slot for the stream that changed. A global end timestamp says only that something completed. Sparse MLA needs the top-k end and gather end independently. Publishing the counter after the timestamp also lets dispatch-s wait for the exact target completion before consuming the corresponding end tick.
cq_dispatch_subordinate.cpp Maintains active ID/start time per stream; closes the previous interval at that stream's target completion; starts the next interval immediately before its go signal; enqueues complete records; drains them through an acknowledged transport; and finishes/drains the last active interval on profiler flush or termination. This is the core state-machine change. One global active record cannot represent top-k and gather at the same time. Per-stream slots allow both to be live simultaneously. Closing before starting the next command on the same stream makes boundaries non-overlapping within a stream while preserving overlap across streams. Flush handling is essential because the last program has no following go command to close it. Queue-full draining provides backpressure instead of record loss. The established FIFO pop remains only to consume the legacy producer and keep that FIFO from filling; it no longer supplies attribution.
distributed/realtime_profiler_manager.cpp Passes the dispatch-s address of realtime_profiler_state to the profiler BRISC as DISPATCH_PROFILER_STATE_ADDR. The consumer needs an explicit NOC destination for its acknowledgement. Merely setting its local copy to idle does not tell dispatch-s that the mailbox record has been read, so the producer could not safely reuse the transport slot.
cq_realtime_profiler.cpp After copying a record into the profiler ring, the profiler core writes IDLE back to dispatch-s and waits for the NOC write to complete. This closes the producer/consumer handshake. Without a remote acknowledgement, dispatch-s cannot distinguish “notification observed” from “record safely copied,” leaving the same overwrite race that the queue was introduced to remove.
Quasar remains device-timed. Where the separate stream monitor path is not used, dispatch-s reads the device wall clock when closing an interval. That architecture guard is not a host-timing or D2H fallback.

The measurement-helper change was also required

tests/ttnn/profiling/realtime_profiler_utils.py is not device runtime, but it is the final part of the evidence path:

  • Raw fields: returns start_timestamp, end_timestamp, and frequency, enabling per-chip intersection and union math. Duration alone cannot prove overlap.
  • Callback locking: protects records and counters shared with the asynchronous receiver thread. Without it, the polling thread could observe partial or inconsistent batches.
  • Pre-run drain: synchronizes, waits for callback traffic to settle, and discards stale records before the measured forward. Otherwise a prior warm-up program could be mistaken for the measured top-k or gather.
  • Fail-closed loss handling: reports invalid raw records and rejects any batch with dropped records. Qualification must not turn missing intervals into an apparent speedup.
  • Settle-window collection: retains all chips and both concurrent programs instead of returning after the first callback from the first chip.

Why simpler alternatives were insufficient

AlternativeWhy it does not satisfy the goal
Use host wall-clock bracketsIncludes submission, synchronization, callback, and manager overhead; cannot identify the device interval intersection; violates the device-time-only requirement.
Copy a completion value or tensor to hostAdds a D2H synchronization point, perturbs concurrency, and still does not provide both device start/end intervals. Explicitly outside the requested design.
Profile top-k and gather separatelyMeasures serial isolated behavior and removes the contention/scheduling interaction whose production benefit is being qualified.
Keep the A/B slots and poll fasterPolling speed is not correctness. With no producer-visible acknowledgement, a legal timing still exists in which two completions overwrite an unread slot.
Infer identity from kernel arrival orderIndependent subdevices and multiple chips do not provide one global arrival order. Identity must be attached before execution, not reconstructed after asynchronous delivery.
Sum the two device durationsFor concurrent intervals, the critical branch is their union, not their sum. The sum overstates elapsed time by exactly the intersection that must be measured.

What the qualification can now establish

  1. On each chip, select top-k and gather by runtime ID and kernel sources from the same sparse-MLA forward.
  2. Compute each duration from that chip's raw device ticks and frequency.
  3. Compute intersection = max(0, min(end) - max(start)) and require a positive intersection.
  4. Compute union = topk_duration + gather_duration - intersection and compare it with the serialized branch baseline.
  5. Collapse across chips only after doing interval arithmetic locally, because device wall clocks are not assumed synchronized across chips.
  6. Reject stale, malformed, incomplete, or dropped evidence instead of silently falling back to host time.

The consumer is test_sparse_mla_perf.py; the broader rollout and 80/30 versus 80/40 resource plan is documented in SPARSE_MLA_TOPK_KV_GATHER_OVERLAP_PLAN.md.

Scope discipline

The commit deliberately does not add profiler-visible Tensix core-count metadata, public record fields, nanobind surface, CSV schema, or tensor readback. Those are useful observability ideas, but they are not needed to prove overlap. The retained runtime changes are the minimum coherent path that prevents identity loss, timestamp ambiguity, and record overwrite while preserving device-only timing.

Terminology note: the commit body mentions “worker footprints,” but the tightened final diff carries the per-program runtime ID, not a worker-core-count field. Core ownership is validated separately from configured subdevice grids and scheduler budgets.
