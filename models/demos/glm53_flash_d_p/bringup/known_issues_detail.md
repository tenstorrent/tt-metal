# Known issues, full text: glm53_flash_d_p

`known_issues.md` holds the short form of each entry and points here; this file keeps every entry's original text.

## Vendored newer HF modeling code on an older transformers cache

- **Vendored newer HF modeling code on an older transformers cache.** Symptom: GLM-5.3 glm5_next (vendored from transformers 5.17) imports and runs on 5.12.1, but with a 5.12 `DynamicCache` the KDA prefill feeds the conv its stored 4-wide state instead of the input, and decode indexes `conv_states[0]` (the batch row of a tensor, not the first of a list); separately, the model's forward raises KeyError `deepseek_sparse_attention` on the checkpoint's own config. Cause: 5.12's `LinearAttentionLayer.update_conv_state` returns the state, 5.17's returns [state | input] and keeps a list; config.json names DSA layers `deepseek_sparse_attention` while the modeling code's mask table uses `indexed_attention`. Fix: run the oracle without a cache (`use_cache=False`), generate with a minimal cache that has the 5.17 semantics, and rename the layer types on the config object (`glm53_flash_d_p/reference/hf_oracle.py:GlmCache`, `text_config`). Found: glm53_flash_d_p R.2.

## Whole-output PCC hides mHC coefficient bugs

- **Whole-output PCC hides mHC coefficient bugs.** Symptom: on the GLM-5.3 layer-0 attn_hc golden ([S, 24] = pre 4 | post 4 | comb 16), a transposed comb scores PCC 0.9958, softmax over the wrong axis 0.9987, 10 instead of 20 Sinkhorn iterations 0.9958, swapped pre/post scales 0.9958, a zeroed row 0.9997: all pass 0.99. Cause: the three parts have different scales (post up to 2, comb entries mostly near 0 or 1), so the concatenated correlation is dominated by between-column variance. Fix: check rel L2 and max abs per part (pre/post 0.03, comb 0.02; max abs 0.15 / 0.2 / 0.1), and that every comb column sums to 1 (the last Sinkhorn step normalizes columns; a transposed comb gives 0.92..1.08). Also, the golden is bf16-rounded (fp32 reference rel 0.0013) (`glm53_flash_d_p/tests/bringup/test_c_kda_dense_attn_hc.py`). Found: glm53_flash_d_p C.kda_dense.attn_hc test.

## Block-out PCC is blind to mHC coefficient bugs

- **Block-out PCC is blind to mHC coefficient bugs.** Symptom: on GLM-5.3 kda_dense layer 0, with attn_hc perturbed and every other step on the CPU, block out (the 4-stream residual) scores PCC 0.9985 with a transposed comb, 0.9991 with post x1.05, 0.99993 with a zeroed row: all pass the 0.98 block gate. Cause: the comb mix of the 4 residual streams dominates out, and PCC ignores the per-stream scale and mixing errors. Fix: also assert block-out rel L2 <= 0.01 (reference 0.0017, device 0.0023, bugs 0.012..0.075) and a per-row norm ratio in [0.97, 1.03], plus the component test's per-part attn_hc checks (`glm53_flash_d_p/tests/bringup/test_swap_kda_dense_01_attn_hc.py`). Found: glm53_flash_d_p S.kda_dense.01 test.

## Layer-0 mHC streams are identical, so layer-0 goldens cannot check stream order

- **Layer-0 mHC streams are identical, so layer-0 goldens cannot check stream order.** Symptom: an mHC collapse with the pre columns reversed, or with stream-major rows, scores the same PCC as the correct one at layer 0 (0.999998, glm53 attn_collapse). Cause: the model copies the embedding into all 4 streams, so at layer 0 sum_n pre_n x_n = (sum_n pre_n) x. Fix: run the same (weightless) module on a later layer's golden too (layer 1: pre reversed rel 1.27, streams swapped 0.29), and assert rel L2 and per-token norm ratio as well (a dropped stream scores PCC 0.9998 at layer 0). Applies to: models/demos/glm53_flash_d_p/tests/bringup/test_c_kda_dense_attn_collapse.py. Seen at: 864ec8b0891. Found: glm53_flash_d_p C.kda_dense.attn_collapse test.

## A norm after the mHC collapse hides collapse bugs from the block out

- **A norm after the mHC collapse hides collapse bugs from the block out.** Symptom: on GLM-5.3 kda_dense layer 0, with attn_collapse perturbed and the rest on the CPU, block out passes PCC 0.98 and rel L2 0.01 with the collapse output x1.02 (rel 0.0072), and passes PCC with the last stream dropped (rel 0.029); only the per-row norm ratio catches x1.02 ([0.970, 1.047]). Cause: attn_norm (RMS) follows the collapse and removes most per-row scale errors before attention. Fix: the swap test also checks the collapse output against the golden attn_in and against the CPU collapse of the same (swapped attn_hc) inputs, rel L2 <= 0.01 and ratio [0.985, 1.015], and runs the module on layer 1's golden (`glm53_flash_d_p/tests/bringup/test_swap_kda_dense_02_attn_collapse.py`). Found: glm53_flash_d_p S.kda_dense.02 test.

## Small-RMS inputs make an RMSNorm's eps visible, and rel L2 0.03 misses eps bugs

- **Small-RMS inputs make an RMSNorm's eps visible, and rel L2 0.03 misses eps bugs.** Symptom: on the GLM-5.3 layer-0 attn_norm golden, eps 1.2e-5 instead of 1e-5 scores PCC 0.99986 and rel L2 0.027 (passes the template's 0.03), and LayerNorm-style mean subtraction scores rel 0.0149. Cause: the embedding rows have RMS 0.0023..0.0155, so mean(x^2) is 5e-6..2.4e-4, the same order as eps. Fix: measure eps mutations on the golden. The glm53 test uses rel L2 <= 0.01, ratio [0.98, 1.02] and worst row rel <= 0.03 (fp32 reference 0.0023; bf16 accumulation of squares 0.0056 / [0.9865, 1.0149]). Applies to: models/demos/glm53_flash_d_p/tests/bringup/test_c_kda_dense_attn_norm.py. Seen at: 864ec8b0891. Found: glm53_flash_d_p C.kda_dense.attn_norm.test.

## KDA output metrics miss prefix-state bugs, and the gated o_norm is effectively a fixed scale

- **KDA output metrics miss prefix-state bugs, and the gated o_norm is effectively a fixed scale.** Symptom: on the GLM-5.3 layer-0 KDA golden (s4096 chunk 1), every state bug passes PCC 0.99 and most pass rel L2 0.03: recurrent prefix zeroed 0.99935 / rel 0.036, conv tail zeroed 0.99992 / 0.012, recurrent state transposed 0.9982 / 0.059, second SP half started from the prefix state instead of the first half's carry 0.99987 / 0.016, conv halo at the SP split zeroed 0.99994 / 0.011. Dropping o_norm scores PCC 0.99942 (norm ratio 0.003). Cause: the carried state adds little to the output norm, and its error sits on the first rows of the chunk or of an SP segment. The core KDA output RMS is far below sqrt(1e-5), so eps sets the gated RMSNorm's scale (eps 1e-6 gives rel 1.9): core-output error is not normalized away. Fix: also check rel L2 on every 128-row block (<= 0.03; bugs 0.043..0.15, 1% noise 0.011) and the worst per-token rel L2 (<= 0.1; bugs 0.38..0.95). Check the post-chunk state against the golden snapshot when the module exposes it (`dctx.extra["state_out"]`). Keep o_norm eps exactly 1e-5 on device (`glm53_flash_d_p/tests/bringup/test_c_kda_dense_attention.py`). Found: glm53_flash_d_p C.kda_dense.attention test.

## At an mHC layer 0 the block out follows the attention error, unlike a sink-dominated attention

- **At an mHC layer 0 the block out follows the attention error, unlike a sink-dominated attention.** Symptom: on GLM-5.3 kda_dense layer 0 (CPU, only the attention perturbed), block-out rel L2 is about 0.9x the attention's own rel L2: x0.99 0.0096, x1.02 0.0185, +3% noise 0.023, zeroed prefix state 0.045 (ratio [0.65, 1.13]), zeroed attention 1.60. Compare MiMo, where a zeroed attention moved block out only 0.014. Cause: post (up to 2) scales attn_out into every stream, and the layer-0 residual (embedding copies, row RMS 0.002..0.016) is small next to it. Fix: size the block-out limit from these runs, not from another model's swap. glm53 keeps rel <= 0.01 and ratio [0.97, 1.03] after attention is swapped (device 0.0062 / [0.983, 1.008]); this is tighter than the attention's own rel 0.02, so a 1% attention scale bias fails block out. Also check the attention against the CPU KDA of the same device attn_norm, and check the post-chunk state from `dctx.extra["state_out"]` (`glm53_flash_d_p/tests/bringup/test_swap_kda_dense_04_attention.py`). Found: glm53_flash_d_p S.kda_dense.04 test.

## An mHC residual's comb is invisible at layer 0

- **An mHC residual's comb is invisible at layer 0.** Symptom: on the GLM-5.3 kda_dense layer-0 attn_residual golden (`post * attn_out + comb^T @ in`), an identity comb scores PCC 0.999996 / rel 0.0030, the same as the correct add; comb not transposed (0.9987 / 0.064), post x1.02 (0.023), comb x1.05 (0.057) and a zeroed last token (0.012) all pass PCC 0.99. Cause: the 4 layer-0 streams are identical and comb columns sum to 1, so comb^T @ in = in for any column-stochastic comb. Fix: also run the (weightless) module on layer 1's golden (identity comb rel 0.50, not transposed 0.26), and assert rel L2 <= 0.01, per-row ratio, per-stream rel, and each term on its own (out minus the exact other term vs post * attn_out and vs comb^T @ in: coefficient and rel L2) (`glm53_flash_d_p/tests/bringup/test_c_kda_dense_attn_residual.py`). Found: glm53_flash_d_p C.kda_dense.attn_residual test.

## The ffn mHC coefficients are more sensitive than the attn ones

- **The ffn mHC coefficients are more sensitive than the attn ones, and their layer-0 streams differ.** Symptom: on the GLM-5.3 layer-0 ffn_hc golden, the attn_hc test's pessimistic mix noise (PCC 0.9989) gives part rel 0.033 / 0.073 / 0.075, which would fail attn_hc's limits (pre/post 0.03, comb 0.02). Meanwhile the bugs that pass PCC 0.99 still sit at 0.011..0.11 (hc_eps 1e-5 comb 0.0107 / max abs 0.078, comb base transposed 0.018 / 0.064, rms eps 1.2e-5 pre 0.045, x1.02 on any part 0.020), and the device module scores <= 0.0030 / max abs 0.010. Cause: ffn_hc reads h_mid, whose 4 streams already differ at layer 0 (rel 0.6..1.5 from stream 0, so stream order is visible and caught by PCC). Its flattened rows have RMS 0.0025..0.013, so the RMS eps matters. Fix: measure the mutations on each hc step's own golden. The glm53 ffn_hc test uses rel L2 <= 0.01 and max abs <= 0.05 per part, plus comb column sums within 0.01 (`glm53_flash_d_p/tests/bringup/test_c_kda_dense_ffn_hc.py`). Found: glm53_flash_d_p C.kda_dense.ffn_hc test.

## Block out vs golden cannot isolate a late mHC step; compare with a CPU tail

- **Block out vs golden cannot isolate a late mHC step; compare with a CPU tail from the same device input.** Symptom: in the GLM-5.3 kda_dense layer-0 swap with ffn_hc added, block out vs golden (rel 0.0069, ratio [0.9797, 1.0087]) is mostly the upstream attention error, so it cannot size or catch ffn_hc bugs such as comb base transposed (tail rel 0.0061) or post x1.01 (0.0080). Cause: every earlier swapped step's error reaches block out. Fix: run the CPU tail (ffn_collapse, ffn_norm, mlp, ffn_residual) from the device h_mid with the CPU ffn_hc of that h_mid, and compare block out with it. Only ffn_hc differs, so the device scores tail rel 0.0020. The per-row ratio is noise-bound on small rows (device [0.987, 1.013]; bf16 mix alone [0.989, 1.010]; 0.3% mix noise [0.979, 1.020]), so gate it at [0.975, 1.025] and keep rel <= 0.005 as the sharp check (`glm53_flash_d_p/tests/bringup/test_swap_kda_dense_06_ffn_hc.py`). Found: glm53_flash_d_p S.kda_dense.06 test.

## A one-row collapse bug passes the collapse's own checks; the block-out tail ratio catches it

- **A one-row collapse bug passes the collapse's own checks; the block-out tail ratio catches it.** Symptom: on GLM-5.3 kda_dense layer 0, ffn_collapse with one row's pre weights reversed scores ffn_in rel L2 0.0001 and worst row 0.011 (limit 0.03), and passes every collapse check. ## A dense MLP after a norm amplifies the norm's scale error into block out

- **A dense MLP after a norm amplifies the norm's scale error into block out, and a device-norm tail is noise-free.** Symptom: on GLM-5.3 kda_dense layer 0, ffn_norm x1.005 passes every norm check (per-token ratio 1.005 inside [0.99, 1.01]) but moves block out by tail rel 0.008 (ratio up to 1.0157); x1.01 gives 0.016.
