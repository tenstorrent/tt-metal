# DeepSeek-V4.1-Flash: automatic prefix caching (APC) and chunked prefill on vLLM 0.31 + vllm-tt-plugin

Plan written 2026-10-15 from a read-only analysis (nothing here was run on the device; vLLM behaviour was checked against the 0.29 source, re-check on 0.31).
Paths: `M/` = `models/demos/blackhole/deepseek_v41_flash/tt/`, `P/` = the plugin's `src/vllm_tt_plugin/`.

## 0. Findings that shape the design
- `output_tokens_per_step` does NOT block APC with spec decode. It defaults to 1 (`P/config.py:82-90`); only a model that sets it above 1 gets the block-output rail, which rejects speculation and prefix caching (`P/platform.py:1921-1941`, `docs/MODEL_CAPABILITIES.md:54-66`). Ours does not set it (`M/generator_vllm.py:129-146`), so APC and k=5 spec decode can be combined; the only coupling is the drafter state.
- `start_pos` already reaches the generator: `P/model_runner.py:1940-1955` sets `input_positions = num_computed_tokens`, `prompt_lens = start + scheduled`. An APC hit looks exactly like a chunk continuation (`M/generator_vllm.py:728-843`).
- Flipping `supports_prefix_caching` alone is correct but gives no speedup: no carried state exists for the new user, `prefill_interleaved` logs "cannot resume" and recomputes from 0 (`M/dsv41_model.py:1218-1226`, `generator_vllm.py:762-773`).
- State after a step that ends on a chunk boundary is complete: the sink writes ring rows, source-layer latents and `prev_cs` on every chunk (`M/prefill_handoff.py:183-238`); carried state (halo, `lat_buf`, kv table, key FIFO) is updated in-trace under the user mask. `dec.k_cache` is exported only when a user is done (`dsv41_model.py:1318-1322`). `pf_resume[b]` is set only if the end is a multiple of C (`dsv41_model.py:1325-1331`).
- Plugin: `_hold_back_partial_prefills` returns nothing when `max_num_scheduled_tokens < max_model_len` (`P/scheduler.py:739-742`, inert on the deployed 67584 vs 131072 spec); `long_prefill_token_threshold` is forced to 0 (`P/platform.py:206`).
- vLLM 0.29 (to re-check on 0.31): the scheduler registers a request's full blocks at schedule time (`kv_cache_manager.py:550-562`), so requests 2..16 of the same step can report a hit on a prefix nobody has computed yet ("same-step phantom hits"). The only rounding hook is mamba-specific (`Scheduler._mamba_block_aligned_split`, `sched/scheduler.py:386-440`) and aligns to the 128-token block, not our 512-token chunk.

## 1. APC
Minimal design: chunk-boundary snapshots on the host (new `M/prefix_cache.py`). Take a snapshot whenever a prefill step ends a window at `s0+C` that is not the prompt end.
Snapshot content: (1) pool latents of the 4 source layers, positions [0,s), read from the user's mesh row; (2) the 128 window rows per ring layer (`pool.ring_base`); (3) compressor `prev_cs` per ratio-2 owner; (4) carried prefill state: halo, valid tail of `lat_buf` and of the kv-table latent rows, the column-sharded key FIFO (slot p on column p % cols; "newest at the end", only the last s/r entries valid); (5) host objects: `book`, token ids `toks[:s]`. Engram history needs no snapshot (pure function of tokens, re-hash on the host into `hasher.st.cache[b]`).
Size: ~5-10 MB per snapshot at short prefixes, a few hundred MB at 100k.
Restore (into a slot on ANY mesh row): pool.release/admit; write pool latents, rings, prev_cs with `paged_scatter_rows` / `h2d`; write the carried state into the persistent per-slot buffers with a NON-traced masked write (the `ttnn.where` user-mask idiom, snapshot uploaded as a replicated tail-padded tensor; no read-modify-write of the whole padded FIFO); set `pf_resume`, `pf_slot_owner/of`, `tap_n`; then the ordinary `prefill_interleaved` with `start = s`.
Keys: the generator hashes `tokens[:s]` itself (+ model/config/vision signature), not vLLM's block hashes. Hit lookup: largest snapshot with `s <= min(start_pos, e-128)` and `s % C == 0` (the last 128 positions are always replayed so the drafter taps are fresh; check against `_spec_seed_taps`, `generator_vllm.py:1161`). A miss recomputes from 0 (always correct).
Spec decode: per-user spec flags use the effective start, not 0 (`generator_vllm.py:817-826`).
Eviction: host LRU, 4-8 GB budget, keep a snapshot only while its parent chain is retained, pin during a restore; `reset_prefix_cache` and a weight reload clear it. `release_user` needs no change.
Same-step donors: inside one call run the donor's first window first, snapshot, then restore into the dependents; otherwise fall back to recompute from 0.
Gain on the guide benchmark: the shared prefix is ~630 tokens, so only the 512 boundary is reusable: one of two chunks saved, ~1.6x on prefill (not 3x); the tail window still costs a full replay. A smaller traced tail chunk (C=128/256) would raise it (M5). Multi-turn chat gets only the boundary below the previous prompt end.
General version (harder): reuse at 128-token granularity (needs a C=128 trace or "unshifting" the padded carried state), reuse of generated tokens (decode-to-prefill-state conversion), on-device sharing (impossible: users are row-private), vision (image hash in the key).

## 2. Chunked prefill
Today: a piece cut by the leftover budget ends off a multiple of C -> `pf_resume` unset -> the next piece recomputes from 0 (quadratic).
Plugin: (1) alignment: model capability for the chunk size (512, `DSV41_VLLM_CHUNK`); `TTScheduler` rounds every non-final piece's END position (`num_computed + n`, not `n`) down to a multiple of C, wrapping/overriding the mamba-aligned-split with C as alignment; skip a request whose rounded piece is 0 tokens; (2) budget = a per-step wall-time bound (~0.84 s per 512-chunk): 2048-4096 for latency-sensitive serving, 67584 for throughput; (3) cap concurrent partial prefills at rows-1 = 3 with `DSV41_PREFILL_UP=1` (a new prompt on the same row evicts the slot owner); (4) rewrite `_hold_back_partial_prefills` to apply in the split regime, keep the whole-prompt regime; (5) keep `TTDecodeInterleavePolicy`, document the values (`config.py:403-431`, `docs/SCHEDULING.md`).
Generator: `_slot_alloc` refuses to evict an owner still in `resume` unless every candidate is; a continuation must land on its own row's slot (`inprog.find`); `DSV41_PREFILL_UP>1` not recommended (doubles replay cost), save/restore of a slot's carried state (= the APC snapshot) is the better alternative; continuations first.
APC + chunked prefill: a hit is a continuation whose carried state comes from a snapshot instead of a slot; snapshots at every aligned boundary give long prompts reuse for free (cap depth by budget).

1. Same-step phantom hits (confirmed in 0.29): decides whether the benchmark benefits without a priming request. 2. Restoring into traced persistent buffers: whether a non-traced masked write is bit-exact and fast enough is the largest unknown - prototype first in M2. 3. Gain ceiling ~1.6x on prefill with C=512 tails (M5 for more). 4. Budget policy: latency (2-4k) vs throughput (67584), host snapshot budget. 5. A cap of 3 partial prefills delays a fourth long prompt. 6. Not verified: device timings, 0.31 scheduler internals, whether taps need the last 128 positions fresh, exact attribute names of the carried-state tensors in `prefill_model.py` / `prefill_sparse.py`.

## 5. vLLM 0.31 re-verification (done 2026-10-15, `vllm/v1/core/` of the 0.31 venv)
(a) Same-step phantom hits: CONFIRMED on 0.31. `KVCacheManager.allocate_slots` (`kv_cache_manager.py:600-612`) calls `coordinator.cache_blocks(request, min(total_computed + num_new_tokens, request.num_tokens))` at schedule time unless `delay_cache_blocks` (only set for async KV loads). `get_computed_blocks` (`:264`) caps a hit at `num_tokens - 1`. Request 2 of a `schedule()` call therefore sees the full blocks request 1 was just given (nothing computed yet). No mitigation was added in 0.31. The platform's whole-batch semantic ("hit = already computed") does not hold for same-step requests; the generator must treat start_pos of a NEW request (no carried state, no snapshot) as untrusted -> recompute from 0 (already the behaviour).
(b) Rounding hook: 0.31 `Scheduler._mamba_block_aligned_split(request, num_new_tokens, num_new_local_computed_tokens=0, num_external_computed_tokens=0) -> int` (`sched/scheduler.py:414`) is called from BOTH loops, gated by `self.need_mamba_block_aligned_split` (set at `:354` from `has_mamba_layers and mamba_cache_mode == "align"`, used only at `:695` running loop and `:1127` waiting loop): after the budget / `long_prefill_token_threshold` clipping and before encoder-input scheduling / `_reserve_prefill_lookahead`. It returns the number of new tokens; non-final pieces (`end < prefill_end`, `prefill_end = max(num_prompt_tokens, num_tokens - 1)`) are rounded to the block boundary, the final piece and requests past `prefill_end` (decodes) are returned unchanged. A return of 0: running loop `continue`s (request skipped this step, later ones still scheduled), waiting loop `break`s (the whole waiting queue stops for this step - FCFS). The override point for the model chunk C is therefore: subclass hook `TTScheduler._mamba_block_aligned_split` + set `need_mamba_block_aligned_split = True` when the model declares a chunk alignment (both loops pick it up, no vLLM edit, no other reader of the flag).
(c) New in 0.31: `Scheduler.prefix_replay_tokens` / `Request.replay_start` (SWA bounded replay: the last window of a hit is recomputed) exists only for kv-cache specs with `prefix_replay_tokens > 0` (nvidia DeepSeek-V4.1 specs); our TT specs do not set it, so it is inert. It is the same idea as our `e - 128` rule.

## 6. M1 results (2026-10-15, branch `ssinghal/dsv4p1-apc`)
Built: plugin (`plugin_apc`): model capabilities `prefill_chunk_alignment` and `max_partial_prefills` (platform stores them in the vLLM config, rejects `max_num_batched_tokens < alignment`, forces 0 when chunked prefill is off); `TTScheduler` overrides `_mamba_block_aligned_split` and switches `need_mamba_block_aligned_split` on, so BOTH base loops round the END position of every non-final piece down to the alignment (0 -> skipped in the running loop, queue stop in the waiting loop); `_hold_back_beyond_partial_cap` = the split-regime rewrite of `_hold_back_partial_prefills` (whole-prompt regime unchanged); docs in `SCHEDULING.md` / `MODEL_CAPABILITIES.md`. Model (`tm_apc`): `generator_vllm.model_capabilities` declares `prefill_chunk_alignment = DSV41_VLLM_CHUNK` (512) and `max_partial_prefills = rows x Up - 1` (3; `DSV41_VLLM_MAX_PARTIAL` overrides); `PrefillTracker.find(..., exclude=)`: two in-progress prompts that share a prefix (a few-shot header) used to be mapped to the same user when both continued in one call - now each continuation takes a distinct user. `Model._slot_alloc` already protected a resumable owner (it evicts one only if every candidate is resumable) and a continuation already lands on its own slot, so no change was needed there.
Tests: plugin `tests/test_prefill_chunk_alignment.py` (18, real `TTScheduler` + stubs; the whole plugin suite has the same 10 known failures as before: 9 unported async-scheduling + 1 stale `test_prefill_only_hides_decodes_but_keeps_continuations`, none new); model `tests/test_vllm_interface.py` (+2 tests; 6 spec tests need `vllm_tt_plugin`, absent from `python_env`, unchanged; the fake `prefill_interleaved` now accepts `vis`, which fixed 11 stale failures); device test `tests/test_apc_m1_chunked_continuation.py` (3 prompts of 2500/2400/2600 tokens, 4 layers, U=4, Up=1, scheduler rule with a 1536-token budget): 6 steps, 16 windows = exactly 3 x 5 chunks + 1 (no window computed twice), zero "recomputing from" / "without carried state" lines, first-token logits of every prompt BIT-IDENTICAL to the same prompt prefilled alone in one call, identical first 5 greedy tokens, and the negative control (a piece ending at 1300) does restart from 0 as predicted.
Not done in M1: the mixed long+short server run (needs a 15-25 min boot; the scheduler behaviour is covered by the real-`TTScheduler` tests), and the cap rarely binds: with aligned pieces the budget is spent by one continuation at a time, so at most 1-2 prompts are part-way (the cap is a guard against slot eviction, not the main mechanism).
Setup notes: a fresh `tm_apc` worktree needs the symlinks of `tm_v031` (`build`, `build_Release`, `python_env`, `.cpmcache`, `runtime`, `tt_metal/pre-compiled`, `ttnn/ttnn.egg-info`, `ttnn/ttnn/_ttnn.so`); the first run from a new path recompiles every kernel (about 10 min). Tests that build the model outside `initialize_vllm_model` must set `DSV41_MO_OVERLAP=0` (the sub-device MoE overlap is auto-on for B=16 and `max_model_len` <= 16384 and aborts the chunk trace capture: `TT_FATAL: Cannot reset worker state during trace capture`, after which the process hangs and the board needs a reset).
