# One-slot (Up=1) prefill context for short prompts (`DSV41_PF_UP1_SHORT=1`, default off)

**Why.** B=8 runs `DSV41_PREFILL_UP=2`: every chunk replay processes 2 x 512 row-tokens per mesh row, so a lone short prompt pays for an idle second slot. The window is 0.4-0.5 s on the device at 40 layers
(10-layer build, call timing dict: replay 150 ms with Up=2, 90 ms with the one-slot context). The existing S_pad "small bucket" is not used by the B=8/1M catalog default (single chunk trace, `DSV41_PF_SINGLE=1`; the
single trace already bounds its cost by the chunk position, not by S_pad): the fixed cost is the padded window itself.

**What.** A second prefill context (`PrefillModel.compile_dyn_up`): own carried tables at S_pad 16384 (`DSV41_PF_UP1_SPAD`), own input / hand-off / head buffers, own chunk trace(s) A/B, one prefill slot per mesh row.
`use_dyn(S)` swaps the whole bundle (`_UP_PM`, `_UP_SINK`, `.U` of the attention / sparse / indexer objects) with the context. Built in `warm_serving` before the first capture. Selection (`tt/pf_up1.py`, CPU tests
`tests/test_pf_up1_cpu.py`): every user of the call starts at 0, the call holds its whole prompt (end <= chunk, plugin `prefill_final`), at most one user per mesh row, no image prompt, no host-tier snapshot to restore, and with the
paged cache only prompts shorter than one block (it commits whole blocks and reads the carried tables by decode user). Anything else runs the Up=2 trace unchanged. The hand-off (pool pages, rings, compressor state, drafter taps,
Engram history) goes through the same sink by decode user; the key hand-off is recorded lazily with its context and flushed inside it before the first decode. No host-tier snapshot is taken for these prompts; the Up=2 slot
bookkeeping of the users is dropped. `DSV41_PF_UP1_FILE` (file holding 0 / 1) switches it live for A/B in one server.

**Results (B=8 / 1M, rc3 image, .47, wt/pf_small a3c63b2771f).**
| TTFT, client side | Up=2 (off) | Up=1 context (on) |
|---|---|---|
| ISL 17, c1 | 561 ms | 370 ms |
| ISL 128, c1 | 586 ms | 372 ms |
| ISL 512, c1 | 674 ms | 410 ms |
| ISL 1024 / 4096, c1 | 1162 / 3487 ms | 1179 / 3530 ms (not eligible, unchanged) |
| ISL 128, c4 / c8 (random placement) | 1258 / 1662 ms | 921 / 1423 ms (the first call of a wave is eligible) |
Adapter-level (harness, one user per mesh row, ISL 17 / 128 / 512): 598 / 598 / 719 ms -> 406 / 405 / 457 ms. Two users in a row, ISL >= 1024: identical.
* Boot DRAM: after the one-slot trace 406.8 MiB/bank free (410.8 before), end of build 400.2 MiB/bank (410.4 before): -10 MiB/bank; trace region +6 MiB/bank.
* Structured churn (8 plain users + 4 looping structured workers, M1): plain 27.2 -> 33.9 tok/s/user, structured request 10.2 -> 7.2 s. Plain decode alone 46.1 / 45.4 tok/s/user (c8, no change).
* Correctness: needle 1k / 8k 4/4 each; GSM8K 32 slice 26 / 26 (off, twice) vs 27 / 28 (on) correct; greedy completions of repeated runs differ in the server regardless (off1 vs off2 13/32 identical, on vs off 12-18/32),
  so identity is not a usable gate; first-token logits (model level, 40 layers, random prompts) differ by up to 1.8 between the contexts, the same size as the slot-to-slot difference inside the Up=2 trace (same prompt in slot 0 / 1:
  0.5-2.3 at 10 layers); cold-vs-cold in one context is bit-identical. Hang canary 15 x (8 x 8k + structured rows) clean.

## Post-mortem and hazard audit (rc4b validation, 2026-11-01)

**What went wrong.** Mixed image + text traffic with the lever on: about 1% of multi-turn text chats answered with the grounding text of a concurrent image request (`<ref>..</ref><box>..`); 0 of ~700 with the lever off. Cause: the per-buffer fact "this vision buffer still holds an image mask / embedding rows" was a pm-level flag keyed by the chunk size and flipped while *preparing* the inputs of a window; the two contexts have their own vision buffers (`_bufs` is part of the context bundle) but shared the flag. A one-slot call cleared the flag (and its own buffers), the Up=U buffers stayed dirty, the next text-only Up=U window (prompt >= 512 tokens, or two users in a row) read the stale image rows. The same flag also lost its clear when a recorded lookahead upload was discarded (latent in rc3 without the lever, needs a discarded lookahead after an image call). Fix: the flag is per buffer (`id(vb[0])`), decided and flipped at upload (`upload_inputs`), re-armed (`vis_mark_dirty`) whenever recorded upload ops are discarded; the lookahead record carries the context it was built for.

**Audit: state that the context swap touches, or that a one-slot call can leave stale for the Up=U context (and the reverse).** Ownership: C = per context (in the bundle: `_UP_PM` / `_UP_SINK` / DynCtx / per-layer `_PA_ATTRS`, `_SP_ATTRS`, `_IX_ATTRS`), U = per decode user (shared by design, written only for the users of the call), M = model-level.

| state | owner | who clears / refreshes it | who could see stale data | verdict |
|---|---|---|---|---|
| vision mask `vl` / override `ov` buffers | C (`_bufs[C][2]`) | `upload_inputs` of that buffer (clear after an image window) | next text-only window of the same context if the dirty flag is wrong | WAS BROKEN (flag shared, keyed by C, flipped at prep); fixed: flag per buffer, at upload, re-armed on discard |
| `_vis_dirty` | M | `upload_inputs`, `alloc_inputs`, `vis_mark_dirty` | both contexts | fixed (above) |
| recorded lookahead upload (`_look`: Engram rows, tokens, recorded ops, spec-enqueued copies into the active context's `_bufs`) | M, but its copies live in one context's buffers | consumed by the next call's first window, popped by a one-slot call | a call of the other context finding `in_place` inputs that were written into the wrong buffers; a discarded record that carried a clear | fixed: record stores the context S_pad and is used only by that context; discard re-arms the vision clear. One-slot calls are final, so they never build one |
| position / mask tables prebuilt for the next fresh window (`DynCtx._pre`, epoch) | C | `DynCtx.update` / `prebuild` / `enqueue_prebuilt` | not stale data: after a switch the epoch moved on, the table was re-copied in the window (+70 ms, see below) | perf only; fixed: last window of a call prebuilds the other contexts' fresh-prompt tables too |

| hand-off sink buffers `bufs[C]` (ring ids, latent ids, idx, user mask, head selector, tap ids) and `slot_b` / `U` | C (`_UP_SINK`) | `sink.update` before every window; `set_map` / `set_lengths` at the start of every call | none (rewritten per window) | ok |

| decode pool pages, rings, compressor state (hand-off targets) | U | the hand-off of the user's own prompt; tail beyond the prompt masked by the decode lengths | none: identical write set for both contexts | ok |
| drafter taps stash + `tap_n` | U | written for the last 128 positions of the users of a call, validity checked by `tap_n` before seeding | none | ok |

Evidence: the audit is code reading of the bundle lists and every pm / model attribute assigned outside `__init__` (see the file list in the commit); the CPU tests (`tests/test_pf_up1_ctx_cpu.py`) pin the vision flag and prebuild logic through context switches in both orders, discarded and out-of-order recorded ops; `tests/test_pf_up1_vis_stale_device.py` and `tools/serving_tests`-style soak (`dsv4-logs/rc4b_pfsmall/clients/t7_leak.py`) check it on the device.

**The ISL >= 512 cost.** An Up=U call right after a one-slot call took 0.63-0.66 s against 0.56 s (same 0.456 s replay): `w_dynupd` 0.03 -> 0.10 s. The next window's tables are prebuilt during the last replay of every call, but only for the *active* context; the epoch check (`cur_epoch` vs `_win_count`) of the other context failed after the one-slot windows, so it copied every table again inside its first window. Fix: `pf_up1.prebuild_other_ctx` prebuilds (and copies in place) the fresh-prompt tables of every other context at the last window of a call.

**Results on the fixed code (rc4b image + this worktree mounted read-only, .34, B=8/1M, paged).** Repro (image, short text, 1200-token needle): needle lost 0/24 (24/24 before), also 0/24 without the short request and with the lever off. Image/text soak (`t7_leak.py`: c1 sequential interleavings of image -> chat, chat -> image, image between chat turns, image -> needle, needle -> image; c4; c8; 2 rounds x 150 s per profile): lever on 2000 requests, lever off 1871 requests, 0 wrong / 0 errors / 0 slow. Canary 8 x 8k with 3 structured rows + short / multi-turn / image mixers: on 30/30 iterations (516 chats, 745 image requests, 568 short prompts, 0 bad), off 10/10 (0 bad). GSM8K zero-shot 250, c4: 247 on / 247 off (237 of 239 calls on the one-slot context with the lever on). TTFT c1 (mean of 4 reps, off -> on): ISL 17 0.645 -> 0.420, 128 0.587 -> 0.407, 512 0.600 -> 0.590 (was 0.57 -> 0.655 before the prebuild fix), 1024 1.147 -> 1.152; c4 ISL 17 / 128 1.198 / 1.139 -> 0.819 / 0.842; c8 1.567 / 1.490 -> 1.331 / 1.317; ISL 512 c4 / c8 unchanged. Streams (32 prompts x 32 tokens, c1): on1 vs on2 31/32 identical (the same 31/32 as off1 vs off2: run-to-run greedy variance exists without the lever), off vs on 15-17/32 (numerics of the other slot, not a defect; GSM8K equal). Plain decode c8 tok/s/user off 46.5 / 47.7, on 46.1 / 48.6. DRAM at the end of the build 333.8 MiB/bank free on (344.0 off).

**rc4b validation (2026-10-31/11-01, .34, image rc4b-0467f96ebb2) - first finding.** Found and fixed: `PrefillModel._vis_dirty` (the "clear the vision buffers after an image window" flag) was keyed by the chunk size and reset at prep time, so a call on the one-slot context cleared the flag while the Up=U context kept a stale image mask / embedding override; the next text-only window of the Up=U context (any prompt >= 512 tokens, or two users in a row) saw image rows (text chats answered with `<ref>..</ref><box>..` grounding text; 1-2% of multi-turn chats in a mixed image + text run, 0 with the lever off). Deterministic repro (image request, short text request, 1200-token needle prompt): needle lost 24/24 before, 0/24 after; the flag is now per vision buffer and decided at upload (`upload_inputs`). Measurements and the decision are in the rc4b_pfsmall report.
