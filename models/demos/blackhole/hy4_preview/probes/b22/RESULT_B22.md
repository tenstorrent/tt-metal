## Step 3 design (what was built)
Replaced ops 554-559 of a decode layer (q_a to_memory_config(16 cores) 1.4 + rms_norm sharded 6.6 + to_memory_config 1.0 + kv slice 1.5 + kv rms_norm 1-core 9.5 + k_pe slice 1.6 = 21.6 us kernel + 4.9 us gaps) with ONE program, `hy4_fuse_attn.fused_norms` (kernels hy4_fuse_attn_kernels/nf_{reader,writer,compute}.cpp), 20 cores, flag HY4_NORM_FUSE=1 (default OFF; front() in hy4_attn_opt.py, falls back to the old chain when S > 8 or the layouts differ):
- q group: 16 cores (logical x0..3, y0..3) x 4 tiles of the all-gathered q_a (2048); kv group: 4 cores (x0..3, y4) x 4 tiles of the 512 latent; kv cores 0,1 also copy the two k_pe tiles (tile 16,17) to the k_pe output (feeds the unchanged rope op). Cores shift with HY4_NORM_Y0.
- per-core partial sum of squares as diag(x x^T) (matmul with transpose on the bf16 tiles, products exact in fp32; the trick of the iHC fused pre exchange 2), T <= 8 rows; the partials are exchanged inside the group by 64 B flag-word slots written with noc_async_write to every core of the group (the iHC exchange-2 pattern, flags reset at the end), each core builds R[t, kk] in L1, rs = rsqrt(R @ (1/W) + eps) on the SFPU, out = bf16((x * rs) * gamma) with the gamma row built into a tile from the RM weight pages (one 64 B page = 32 values) and a row-broadcast multiply. L1 per core ~62 KB (below the tp24 CB peak).
- Cross-core hazards: the flag memory is a CB that no other writer touches before the flags arrive; same pattern as the shipped iHC kernel, 40 traced steps x 78 layers + 3 spec rounds without a stale-flag problem.
Unit (probes/b22/nf_test.py, 1x8 slot, S = 1,2,3,4,8, varying magnitude 0.01..100 with outlier columns, 6-8 calls each, 64 calls): PCC vs torch 0.999998 (q and kv) in all, k_pe copy exact, max rel error vs the fp32 reference 0.00234 (q) / 0.00302 (kv) = stock interleaved rms_norm 0.00226 / 0.00289 = the model's sharded rms (rmssh) 0.00216 (all about 1 bf16 ulp). Element equality: 6.6% of the elements differ from the model's rmssh path by one bf16 ulp (3.3% from the interleaved stock rms_norm). Traced (40 reps in one trace, S=1, default ring): stock chain 21.19 us -> fused 6.93 us per layer.

## Step 4 (fused_back + o-proj, HY4_BACK_FUSE=1): negative
`hy4_fuse_attn.fused_back_oproj`: the 64 back cores (hb_reader/hb_compute unchanged, writer hb_writer_sk.cpp) and the 8 skinny o-proj bank cores (hy4_skinny.SkinnyLinear._parts refactor, writer hsk_ln_writer_fb.cpp) in one program: the bank readers stream the o-proj weights from program start; the back cores write og to DRAM and increment a ready semaphore (id 3, present on all cores) on the bank core of their head (bank core b loads exactly the 8 x pages of head b); the o-proj writer waits for 8 increments, then runs the unchanged exchange + matmul. Bit-exact vs fused_back -> SkinnyLinear (S = 1,2,4, gfold on/off, 4 varying calls each, all 8 devices, maxabs 0).
Timing: unit traced stock 41.7 us, merged 51.7 us (same with HY4_RING_KB=128: 41.9 / 51.8; o-proj ring 128 / 192 tiles: 49.0 -> 51.7 and 42.0 -> 48.3, i.e. no useful dependence on the prefetch depth). Model NL=16 (NORM_FUSE=1 + BACK_FUSE=1): 8.85 / 9.77 vs 8.76 / 9.68 ms, tokens identical to the NORM_FUSE-only run (bit-exact in the model too). Not diagnosed: candidates are DRAM bank contention between the o-proj weight prefetch and the back cores' w_uv_t reads (both hit the same banks), the program-launch cost of 11 kernel groups on 72 cores, and the og write -> semaphore -> DRAM read round trip; a profile of the merged program (per-core zones) is the next step if anyone wants to retry. Estimated ceiling was only -5 us/layer, so this is parked. A NOWAIT diagnostic (count 0) gave 70 us (stale semaphore counts, not interpretable).

## DeepSeek applicability (DSV4.1-Flash)
- DeepSeek already ships this lever: tt/qk_norm.py (lever L06, DSV41_ATTN_QKNORM default 1) fuses the slice + q norm (1280) + kv norm (512) of the wq_a|wkv output into one program, bit-equal to rms_norm (reducer-core design: cores square their tiles and send them to the group's reducer core which reduces in the reference order). So for DeepSeek this step is done; B22's design differs only in being a symmetric partial-sum exchange (no reducer, fewer tiles moved) at the cost of bit-equality (1 ulp class). The stock-chain cost is a transferable fact: sharded-LN reshards + the 1-core kv norm with a row-major gamma (tilize inside the op; DeepSeek's own note: RM gamma 20 us vs tile gamma 13 us) are what makes the 6-op chain 21.6 us.
- The B10 lesson transfers: measure with ring 128 KB first (non-profiled A/B), profile gain x0.75 = wall gain; program-removal gains are real only when the program ring is not the binding stall.
- The step-4 negative result transfers as a warning: merging a compute phase with a DRAM-streaming skinny matmul in one program on the same banks did not overlap here; DeepSeek's tail fusions (fuse_tail_ar) merge compute with CCL, not with a bank-streaming matmul, so they are not affected.
