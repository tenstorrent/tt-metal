# Known issues: deepseek_v41_flash_d_p

Model-specific lessons. Shared lessons: `models/demos/common/bringup/knowledge/known_issues.md`.

- **[DS41-1] fp8 / fp4 quantizers turn last-bit GEMM differences into whole quantization steps.** Symptom: oracle vs reference, inputs equal to 3e-8, attention out rel 1e-4 at layer 1 and 1e-2 at layer 2 (first fp4 compressed-KV layer); 6 / 300 tokens re-routed. Cause: different GEMM tiling (M) flips fp8 / e2m1 roundings. Fix: one tiled GEMM routine for both (`reference/kernels.py` "GEMM tiling", installed as model.py's `F.linear` / `torch.einsum`); then bit-exact. Found: deepseek_v41_flash_d_p R.2.
- **[DS41-2] Per-chunk results a reader layer needs are kept per position, not per chunk.** Symptom: top-k / candidate pool kept as "this chunk's rows" would be [4096, 512] one-shot vs [2048, 512] chunked. Cause: check_reference's state pcc (`core/metrics.py:pcc`, flatten + dot) needs equal sizes. Fix: topk_idx [length, 512] and candidates [length, 2048] grow with the sequence; readers slice [start, end) (`reference/ds41_ref.py:State`). Found: deepseek_v41_flash_d_p R.2.
- **[DS41-3] Single-pass mHC: a sublayer collapses with the PREVIOUS sublayer's pre.** Symptom: the block output streams alone cannot feed the next block. Cause: attention uses the previous layer's FFN pre (layer 0: one-hot), the FFN this layer's attention pre (inference `Block.forward`). Fix: block boundary [S, 4H + 4] = streams + pending pre (`ds41_ref.py:pack`); the oracle taps pack the same way. Found: deepseek_v41_flash_d_p R.2.
- **[DS41-4] Reset fixed state per step, not per layer, at chunk start 0.** Symptom: chunked != one-shot from layer 14 on (hidden pcc 0.984; first diff: rows 1024-1026 of engram_rows). Cause: layer 14 has two stateful steps (engram tail, compressor partial); a layer-wide reset in the compressor erased the tail the engram step had just written. Fix: each step resets only its own state (`ds41_ref.py:_compressor`, `_engram_rows`, `_attention`). Found: deepseek_v41_flash_d_p R.2 (R.3 pre-check).
- **[DS41-5] Serving needs the window KV of every position, not the 128-slot ring.** Symptom: none until serving. Cause: the KV Manager ships each acked chunk's [start, end) by position while later chunks run, and a follow-up starts at any 64-aligned resident needing [start - 127, start). Fix: served caches 0_window_kv (every layer) + compress / index per ratio, bf16 ROW_MAJOR, one ND shard per 32-token record (serving_contract.md "KV cache"); 10 GiB/chip/slot at 1M on 4x4 if TP-replicated. Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-6] KvChunkAddressTable(dict) numbers configs in sorted name order.** Symptom: config 0 is not the cache that covers every layer; tables.py rejects the table. Cause: the name -> config constructor assigns ids by sorted key (ttnn/cpp/ttnn-nanobind/disaggregation.cpp:117-122). Fix: names that sort in table order (0_window_kv, 1_compress_kv_r2, ...: tests/bringup/contract/caches.py CONFIG_ORDER). Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-7] The framework's tt-d-gen lookup takes serving.server_repo verbatim.** Symptom: "no tt-d-gen checkout at /localdev/$USER/tt-d-gen" though it exists. Cause: testing/dgen_engine.server_repo does not expand variables, and this spec writes $USER. Fix: the runner tests set BRINGUP_SERVER_REPO to the expanded path (test_runner_contract.use_engine). Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-8] The runner smoke cannot run in this partial run.** Symptom: test_runner_smoke skips; K.1 requires smoke_runner_ok == 1. Cause: the answer needs all 40 layers; the runner serves only the spec's contiguous prefix 0-3, and the checkpoint is trimmed to 0-24. Fix: owner question 7 in serving_contract.md (run it on the deployment box, waive the metric here). Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-9] The plan check cannot place host-resident tensors.** Symptom: check_plan "placement 'layers.*.engram.embed.*' skips decoder layers [1, 14]". Cause: F64's skip rule (plan/boxes.py:check_boxes) rejects any skip of a decoder-layer tensor, and there is no host placement; the engram tables (2 x 98 GB) are memory-mapped on the host (owner rule). Counting them would add 12 GiB per chip on 4x4. Fix: needs a framework `host` placement; plan.yaml keeps `skip` (1 plan error). Found: deepseek_v41_flash_d_p PL.1.
- **[DS41-10] bfp8 holds the fp4 experts exactly; it does not fit.** Symptom: none. Cause: e2m1 needs 4 magnitude bits, bfp8 has 7 under one exponent per 16 (exact in both [N, K] and [K, N], 16 experts checked); bfp4 changes 16-17 % of values. bfp8 = 1.06 B / value: 26.9 GiB per chip for the run's 8 layers on 2x2, 33.6 on 4x4. Fix: keep the checkpoint's packed e2m1 + e8m0 bytes (0.53 B / value), decode in the expert op (plan.md "Weights"). Found: deepseek_v41_flash_d_p PL.1.
