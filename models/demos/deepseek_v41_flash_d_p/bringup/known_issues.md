# Known issues: deepseek_v41_flash_d_p

Model-specific lessons. Shared lessons: `models/demos/common/bringup/knowledge/known_issues.md`.

- **[DS41-1] fp8 / fp4 quantizers turn last-bit GEMM differences into whole quantization steps.** Symptom: oracle vs reference, inputs equal to 3e-8, attention out rel 1e-4 at layer 1 and 1e-2 at layer 2 (first fp4 compressed-KV layer); 6 / 300 tokens re-routed. Cause: different GEMM tiling (M) flips fp8 / e2m1 roundings. Fix: one tiled GEMM routine for both (`reference/kernels.py` "GEMM tiling", installed as model.py's `F.linear` / `torch.einsum`); then bit-exact. Found: deepseek_v41_flash_d_p R.2.
- **[DS41-2] Per-chunk results a reader layer needs are kept per position, not per chunk.** Symptom: top-k / candidate pool kept as "this chunk's rows" would be [4096, 512] one-shot vs [2048, 512] chunked. Cause: check_reference's state pcc (`core/metrics.py:pcc`, flatten + dot) needs equal sizes. Fix: topk_idx [length, 512] and candidates [length, 2048] grow with the sequence; readers slice [start, end) (`reference/ds41_ref.py:State`). Found: deepseek_v41_flash_d_p R.2.
- **[DS41-3] Single-pass mHC: a sublayer collapses with the PREVIOUS sublayer's pre.** Symptom: the block output streams alone cannot feed the next block. Cause: attention uses the previous layer's FFN pre (layer 0: one-hot), the FFN this layer's attention pre (inference `Block.forward`). Fix: block boundary [S, 4H + 4] = streams + pending pre (`ds41_ref.py:pack`); the oracle taps pack the same way. Found: deepseek_v41_flash_d_p R.2.
- **[DS41-4] Reset fixed state per step, not per layer, at chunk start 0.** Symptom: chunked != one-shot from layer 14 on (hidden pcc 0.984; first diff: rows 1024-1026 of engram_rows). Cause: layer 14 has two stateful steps (engram tail, compressor partial); a layer-wide reset in the compressor erased the tail the engram step had just written. Fix: each step resets only its own state (`ds41_ref.py:_compressor`, `_engram_rows`, `_attention`). Found: deepseek_v41_flash_d_p R.2 (R.3 pre-check).
- **[DS41-5] Serving needs the window KV of every position, not the 128-slot ring.** Symptom: none until serving. Cause: the KV Manager ships each acked chunk's [start, end) by position while later chunks run, and a follow-up starts at any 64-aligned resident needing [start - 127, start). Fix: served caches 0_window_kv (every layer) + compress / index per ratio, bf16 ROW_MAJOR, one ND shard per 32-token record (serving_contract.md "KV cache"); 10 GiB/chip/slot at 1M on 4x4 if TP-replicated. Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-6] KvChunkAddressTable(dict) numbers configs in sorted name order.** Symptom: config 0 is not the cache that covers every layer; tables.py rejects the table. Cause: the name -> config constructor assigns ids by sorted key (ttnn/cpp/ttnn-nanobind/disaggregation.cpp:117-122). Fix: names that sort in table order (0_window_kv, 1_compress_kv_r2, ...: tests/bringup/contract/caches.py CONFIG_ORDER). Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-7] The framework's tt-d-gen lookup takes serving.server_repo verbatim.** Symptom: "no tt-d-gen checkout at /localdev/$USER/tt-d-gen" though it exists. Cause: testing/dgen_engine.server_repo does not expand variables, and this spec writes $USER. Fix: the runner tests set BRINGUP_SERVER_REPO to the expanded path (test_runner_contract.use_engine). Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-8] The runner smoke cannot run in this partial run.** Symptom: test_runner_smoke skips; K.1 requires smoke_runner_ok == 1. Cause: the answer needs all 40 layers; the runner serves only the spec's contiguous prefix 0-3, and the checkpoint is trimmed to 0-24. Fix: owner question 7 in serving_contract.md (run it on the deployment box, waive the metric here). Found: deepseek_v41_flash_d_p SC.1.
- **[DS41-9] The plan check cannot place host-resident tensors.** Symptom: check_plan "placement 'layers.*.engram.embed.*' skips decoder layers [1, 14]". Cause: F64's skip rule (plan/boxes.py:check_boxes) rejects any skip of a decoder-layer tensor, and there is no host placement; the engram tables (2 x 98 GB) are memory-mapped on the host (owner rule). Counting them would add 12 GiB per chip on 4x4. Fix: needs a framework `host` placement; plan.yaml keeps `skip` (1 plan error). Found: deepseek_v41_flash_d_p PL.1.
- **[DS41-10] bfp8 holds the fp4 experts exactly; it does not fit.** Symptom: none. Cause: e2m1 needs 4 magnitude bits, bfp8 has 7 under one exponent per 16 (exact in both [N, K] and [K, N], 16 experts checked); bfp4 changes 16-17 % of values. bfp8 = 1.06 B / value: 26.9 GiB per chip for the run's 8 layers on 2x2, 33.6 on 4x4. Fix: keep the checkpoint's packed e2m1 + e8m0 bytes (0.53 B / value), decode in the expert op (plan.md "Weights"). Found: deepseek_v41_flash_d_p PL.1.
- **[DS41-11] The scaled checkpoint has no inference/config.json.** Symptom: SG.1 golden FileNotFoundError on `hf_scaled/<box>/inference/config.json`. Cause: plan/scale.py rewrites only the top-level config.json (text_config counts 64->32 heads, 8->4 o_groups, 384->96 experts) and copies top-level files only. Fix: `ds41_ref.py:inference_config` reads the source's (bringup_scale.json "source") inference config and applies each changed text_config key via HF_TO_INFERENCE (unmapped change asserts). Found: deepseek_v41_flash_d_p SG.1.
- **[DS41-12] (RESOLVED by the overseer) The canonical prompt was shorter than the scaled rung.** Symptom: SG.1 golden "the prompt has 56320 tokens < 65536". Cause: the prompt is built to the longest real ladder rung (56320). Fix: scaled.ladder is now 55296 / 2048, within the prompt. Detail: known_issues_detail.md. Found: deepseek_v41_flash_d_p SG.1.
- **[DS41-13] The fp8 act quant (blocks of 32, ue8m0, e4m3 RNE) composes bit-exactly from stock ops.** Symptom: none. Cause: fp32 `ttnn.max(dim=-1)` over 32 columns, scalar `ttnn.multiply`, `ttnn.round` (half to even) and int32 bit ops are exact on BH; `ttnn.bitcast` only maps fp32<->uint32<->int32. Fix: `tt/quant.py:fp8_qdq` (scale and e4m3 rounding on the bits; 0 mismatches on 6 random / tie / pow2-amax sets of 512x2560); reuse its bit ops for fp4_qdq. Found: deepseek_v41_flash_d_p C.swa.q_a.
- **[DS41-14] An fp8-quantized output hides 1 % noise from the calibrated rel limits.** Symptom: C.swa.kv sweep: noise1e-2 (rel 0.010) slipped the auto checks. Cause: the bf16 precision model's fp8 re-roundings flip 4.3 % of values (rel 0.011, limit 0.022). Fix: check the output's structure: every value on the e4m3 x ue8m0 grid (act_quant_dequant(out, 32) == out; noise: 100 % off) and <= 15 % of values != the CPU step (model 4.3 %, RTZ 49 %); tests/bringup/test_c_swa_kv.py:_fp8_fails. Found: deepseek_v41_flash_d_p C.swa.kv.
- **[DS41-15] Interleaved RoPE in fp32 composes exactly; rotary_embedding_llama does not.** Symptom: none (avoided). Cause: rotary_embedding_llama multiplies (and applies the trans-mat) on the FPU, which reads fp32 at about TF32 (K-30); the fp8 q-dq after the kv RoPE turns that into whole e4m3 steps (DS41-1). Fix: permute the producing weight's rope rows to [even | odd] at load, rotate with fp32 SFPU mul / sub / add, re-interleave with a ROW_MAJOR transpose (bit-exact on device); `tt/rope.py`. kv fp8 flips: DS41-16. Found: deepseek_v41_flash_d_p C.swa.kv.
- **[DS41-16] The FPU rounds each in-tile partial dot to ~TF32, even for bf16 operands.** Symptom: S.swa.05 tail check rel 0.0109 > 0.01: 0.8 % fp8 flips in the window KV. Cause: matmul rel 1.8e-4 vs fp64 at every fidelity (torch fp32 4e-8); one tile-dot 1 + 2^-12 -> 1, cross-tile sums exact fp32. Fix: one nonzero product per tile-dot: 32 masked copies of q(x), one batched matmul, SFPU adds (`tt/exact_mm.py`, setting ATTN_IN_MM; rel 5e-8, ~8 ms vs 0.4 ms). Found: deepseek_v41_flash_d_p S.swa.05.
- **[DS41-17] SPMD writes / reads of the TP-dedup window cache at any 32-aligned start.** Symptom: each chip needs other rows of the chunk (start % W != 0), but an op takes one offset. Cause: position g lives on row (g / W) % SP. Fix: write = per-row server-order rows by `ttnn.embedding` with a load-time index row per (start mod S) / 32, then `update_padded_kv_cache(kv_actual_global=start, valid_global=end, tp_axis=1)` (= the plan's map); read = same local slice on every chip, all_gather both axes, keep the owner block (`tt/attention.py:TtWindowCache`). Found: deepseek_v41_flash_d_p C.swa.attention.
- **[DS41-18] Window attention: the bf16 sparse_sdpa output sets the error.** Symptom: attention vs the CPU step rel 0.021 (precision-model limit 0.029). Cause: sparse_sdpa returns q's dtype, and the fp8 q-dq after the un-RoPE turns bf16 roundings into e4m3 steps (DS41-1). CPU emulation: all bf16 0.0206, fp32 output 0.0152, fp32 scores 0.0201. Fix: 512^-0.5 folded into q (scale 1, exact; K-27); an fp32 output alone is not enough (tail 0.013 in S.swa.06): DS41-19. Found: deepseek_v41_flash_d_p C.swa.attention.
- **[DS41-19] Exact window attention: bf16 pieces x lane-masked keys / values.** Symptom: S.swa.06 tail rel 0.0163 > 0.01. Cause: bf16 q / scores / probs plus the in-tile dot rounding (DS41-16); CPU emulation: fp32 operands with that rounding still 0.0106. Fix: q and probs as 3 bf16 pieces, keys / values masked to one product per tile-dot (bf16 x e4m3 is exact, probed), lanes summed in DEST along K, fp32 SFPU softmax + sink: attention rel 0.0039, tail 0.0080; 64 ms / layer on 2x2 (`tt/window_exact.py`). Found: deepseek_v41_flash_d_p S.swa.06.
- **[DS41-20] The swap step limit is still a fixed 2 % cap; the fast window attention's precision model is 2.2 %.** Symptom: S.swa.06 with WINDOW_SDPA=high_precision fails only "swap_attention vs the CPU step" rel 0.02123 > 0.02000 (component error 0.02227); the block-out tail passes, 0.0169 <= 0.0392 (F72). Cause: defaults.yaml swap_step_rel 0.02 caps min(cap, calib x err) in testing/component.py:350 (F72 lifted only the tail). Fix: framework (owner / overseer); do not add an exact kernel (OV-3). Found: deepseek_v41_flash_d_p C.swa.ffn_collapse.
