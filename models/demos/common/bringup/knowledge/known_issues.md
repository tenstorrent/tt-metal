# Known issues

Every agent reads this before it starts. One entry per issue, in the section it belongs to. Each entry is one bullet with
the fields `Symptom:`, `Cause:`, `Fix:`, `Found:` (model and task). An agent that hits something new adds an entry under
"Proposed" at the end of its step; `python -m models.demos.common.bringup.knowledge.check` checks the format, and the
overseer moves the entry into its section (merged with its neighbours) when the run ends.

## API behavior
- **unified_routed_expert_moe works in place.** Symptom: combine reads garbage or the device faults after freeing the expert input. Cause: for TILE input the op returns its input buffer as the output. Fix: do not deallocate the dispatched buffer before combine. Found: ernie45_d_p P3.2.
- **Expert counts are global.** Symptom: hang, cores stuck in `cb_wait_front` inside unified_routed_expert_moe. Cause: expert_token_counts and expert_region_offsets are indexed by global expert id; a local [1, 16] array makes the kernel read garbage counts. Fix: pass [1, num_experts] per chip. Found: ernie45_d_p P3.1.
- **Chunked SDPA arguments.** Symptom: nanobind TypeError calling `chunked_scaled_dot_product_attention`. Cause: positional arguments combined with `scale=`. Fix: pass every argument by keyword. Found: ernie45_d_p P2.6.
- **scatter has no fp32 TILE path.** Symptom: `ttnn.scatter` rejects fp32 TILE input. Cause: unsupported dtype/layout. Fix: scatter in bf16 or use a selector matmul. Found: ernie45_d_p P2.8.
- **32-aligned widths.** Symptom: `mesh_partition` / `slice` fail on a 16-wide column split. Cause: widths must be tile aligned. Fix: build the broadcast with a selector matmul (`routing @ M_j`). Found: ernie45_d_p P2.9.
- **DeepSeek dispatch/combine on a 1-device dispatch axis.** Symptom: TT_FATAL "No neighbors found"; offset_cumsum all_gather rejects a 1-device axis. Cause: the program factories always wire fabric on the dispatch axis. Fix: the bring-up forks `ttnn.bringup.offset_cumsum`, `ttnn.bringup.dispatch` and `ttnn.bringup.combine` skip the all_gather and the fabric when the axis has one device (`ttnn/ttnn/bringup/INDEX.md`; callers in `mimo_v2_6_d_p/tt/experts.py:_dispatch/_combine`). Found: ernie45_d_p P3.1-P3.2.
- **Multimodal HF wrapper hides the decoder layers.** Symptom: check_hf fails with `AttributeError: 'Gemma4Model' object has no attribute 'layers'`. Cause: AutoModelForCausalLM loads the ConditionalGeneration class; the text layers are at `model.model.language_model.layers`. Fix: define `hf_layers(model)` in the model's hooks. Found: gemma4_a4b_d_p R.2.
- **Fused routed-expert kernel: activations and compute config.** Symptom: no GeGLU choice in `unified_routed_expert_moe`; with a hacked-in GeluTanh the output norms were uniformly off (ratio 0.96 at LoFi, 1.036 at HiFi2 with a bf16 dst). Cause: `RoutedExpertActivation` had only Silu, SwiGluOai, SituGlu, ClampedSiluGlu, and the program factory hard-codes `MathFidelity::LoFi` and `fp32_dest_acc_en = false`, ignoring compute_kernel_config. Fix: `ttnn.bringup.RoutedExpertActivation.GeluTanh` in the fork `ttnn.bringup.unified_routed_expert_moe` (`ttnn/ttnn/bringup/unified_routed_expert_ffn`; `ROUTED_GELU_TANH` define). For that variant the factory honours math_fidelity and fp32_dest_acc_en, and the config is in the program-cache key; HiFi2 + fp32 dest gives ratio 1.011. Other variants still run LoFi. Found: gemma4_a4b_d_p PL.1, C.sliding.experts.
- **A kernel define that shadows an enumerator.** Symptom: trisc0 compile failure, "'SILU' is not a member of KernelActivation". Cause: a compute define named `GELU_TANH` expands inside `enum class KernelActivation` (bmm_fused_activation.hpp). Fix: prefix variant defines (`ROUTED_GELU_TANH`). Found: gemma4_a4b_d_p C.sliding.experts.
- **Contiguous KV cache written at a chunk offset.** Symptom: a paged cache and page table are more machinery than a single-sequence prefill needs. Cause: none (API choice). Fix: `ttnn.fill_cache(cache [1, Hkv, max_seq, D], kv [1, Hkv, S, D], batch_idx=0, update_idx=start)` with a tile-aligned offset; where the SDPA wants paged input, a paged-shaped cache with an identity page table works (see the repo map). Found: gemma4_a4b_d_p C.sliding.attention.

## Accuracy
- **Fused expert kernel packs to bfp8.** Symptom: top-1 agreement fell from 97.7% to 95.7% and final hidden PCC from 0.998 to 0.996. Cause: unified_routed_expert_moe packs activations to bfp8 internally, even for bf16 input. Fix: accepted (top-5 stayed 100%); budget for it in thresholds. Found: ernie45_d_p P3.2.
- **Router selection vs weights.** Symptom: routed experts differ from HF on a few tokens. Cause: ERNIE-style routers add a correction bias for top-k selection only; weights are the unbiased probabilities renormalized. Fix: keep selection and weighting separate, softmax in fp32. Found: ernie45_d_p P1.2.
- **PCC alone does not gate a component.** Symptom: real bugs pass PCC 0.99, for example on Gemma-4 layer-0 goldens: RMSNorm `1 + w` instead of `w` (0.9977), a sum-instead-of-mean RMS (~1.0), `2 * (a + b)` in a residual (0.999997), a dropped layer_scalar (0.999997, output 14x too large), silu instead of gelu_tanh (0.9986), a dropped expert (0.9973), a dropped top-1 routing pair (0.99994), a zeroed last row (0.9997), per_expert_scale dropped from the router (0.99991), RoPE positions from 0 in global attention (0.9991), a sliding attention that ignores the KV prefix (0.9979). Cause: PCC is scale-invariant, and a few wrong rows or one sparse entry barely move a [2048, H] correlation; RoPE is relative and only the first `window` rows attend into the prefix. Fix: every float component test also checks rel L2 (<= 0.03) and the per-token output-norm ratio (in [0.97, 1.03]); attention also checks rel L2 on the first `window` rows; the router checks exact top-k count, selection overlap (>= 0.995), matched-row weight rel L2 (<= 0.005) and a per-row sum ratio; experts also check the worst per-token rel L2 (<= 0.1). Templates to copy: `gemma4_a4b_d_p/tests/bringup/test_c_sliding_{attn_norm,attention,router,experts,ffn_residual}.py`, `test_c_global_attention.py`. Found: gemma4_a4b_d_p C.* tests.
- **What a swap test can and cannot see.** Symptom: a broken step passes the block-out gate (0.98): a dropped attn_norm weight scores 0.9804, and a uniform or per-row scale error in mlp or experts cannot change block out at all; conversely, correct device steps sit near whole-matrix limits (router rel L2 0.027, experts rel L2 0.027 vs golden). Cause: the residual dominates block out, q/k/v norms undo input scale, a following norm (post_feedforward, post_moe) normalizes each row, and upstream device error flips near-tie top-8 choices (about 45-49 of 2048 rows) that each move a whole expert. Fix: the swap test checks the swapped step's own output twice: loosely vs the golden (router overlap 0.99 / rel 0.01, experts rel 0.05) and at component limits vs the CPU step on the same device inputs; block-out rel L2 <= 0.01 before attention is swapped, <= 0.02 after (MoE amplifies attention error). See `gemma4_a4b_d_p/tests/bringup/test_swap_sliding_{01,02,06,08,10}_*.py`. Found: gemma4_a4b_d_p S.sliding.*.
- **CPU sgemm result depends on M.** Symptom: reference chunked vs one-shot PCC about 0.9998 (gate 0.99999), bit-exact up to the first MoE, then growing routing flips. Cause: MKL picks M-dependent kernels for small or odd M, so a per-expert grouped matmul's row depends on how many tokens chose that expert. Fix: zero-pad each expert's token group to a multiple of 32 rows before `F.linear` and drop the pad rows. Found: gemma4_a4b_d_p R.3.
- **HiFi2 matmul shrinks output norms.** Symptom: a dense MLP on device (bf16 weights, HiFi2 + fp32 acc) scored PCC 0.99999 but rel L2 0.0083, every token's norm low (ratio [0.986, 0.998]). Cause: HiFi2 drops low mantissa bits of an operand, biasing products toward zero; it adds up over chained matmuls (K = 2816 then 544). Fix: HiFi4 + fp32 acc for such matmuls; the norm-ratio check catches it. Found: gemma4_a4b_d_p C.sliding.mlp.
- **Gemma-4 global attention semantics.** Symptom: wrong global-layer value state if V is copied from K. Cause: with `attention_k_eq_v` there is no v_proj; V is the unscaled RMS norm of the raw k_proj output, K = RoPE(k_norm(k_proj)). Gemma-4 RMSNorm is `x * w` (not `1 + w`) and the attention scale is 1.0. Fix: store K and V separately from one projection. Found: gemma4_a4b_d_p R.2.

## Performance
- **fp32 accumulate disables streaming SDPA on Blackhole.** Symptom: SDPA 85% of a 50k->55k chunk, about 15 TFLOPS per chip. Cause: `fp32_dest_acc_en=True` turns off the streaming kernel (`sdpa_program_factory.cpp:75`); exact exp since #57180. Fix: HiFi2, fp32 acc off, exp approx, q256/k512 (6.5x faster SDPA, accuracy unchanged in practice). Found: ernie45_d_p P3.4.
- **One SDPA program per chunk offset.** Symptom: first 55k run read 22 s instead of 4.4 s. Cause: the scalar chunk_start is part of the compiled program. Fix: measure warm; for serving use `chunk_start_idx_tensor`. Found: ernie45_d_p P3.4.
- **Dense-EP experts.** Symptom: MoE about 2.4 s per 5k chunk. Cause: every local expert over every token. Fix: dispatch + unified_routed_expert_moe + combine (55k TTFT 35.9 s -> 10.9 s). Found: ernie45_d_p P3.2.
- **Streaming SDPA chunk sizes are capped by L1 at large head_dim.** Symptom: config A (q256/k512) fails to compile: "Statically allocated circular buffers ... beyond max L1 size of 1572864 B" at head_dim 256; at 512 even q256/k128 fails. Cause: Q/K/V CBs are chunk x head_dim tiles, K and V double-buffered (sdpa_program_factory.cpp:499-506). Fix: bf16 on the full 11x10 grid: head_dim 256 fits up to q256/k256; head_dim 512 fits q128/k128 or q160/k128. Found: gemma4_a4b_d_p P.2.
- **Causal and chunked SDPA get no KV chain forwarding.** Symptom: head_dim 512 chunked SDPA over a 51k prefix takes 44 ms with either config (base or A). Cause: the KV chain/multicast is only built when `!is_causal` (sdpa_program_factory.cpp, "KV chain forwarding"), so every Q chunk streams the whole prefix from DRAM: bandwidth-bound. Fix: the largest Q chunk that fits L1 and divides chunk_start (q160: 35 ms); a bf8 KV cache would halve the traffic (untried). Found: gemma4_a4b_d_p P.2.
- **The hybrid harness is not the model's speed.** Symptom: about 20 s per 5k chunk, flat in position. Cause: the component/swap harness runs the CPU reference with host in / host out around every device step. Fix: the assemble step (M.1) builds the all-device model before the ladder; Gemma-4 went to 0.61 s per 50k->55k chunk. Found: gemma4_a4b_d_p P.1.

## Infrastructure
- **comp_pcc stub.** Symptom: a PCC of exactly 0.999999 in a real pass. Cause: run_safe_pytest's precompile pass rebinds comp_pcc to a stub that can leak into lazily imported call sites. Fix: tests use `core.metrics.pcc`; tests that go through the producer run with `--no-precompile`. Found: ernie45_d_p P2.16.
- **Ambient PYTHONPATH.** Symptom: modules resolve from another checkout (`../tt-metal`). Cause: the shell exports PYTHONPATH. Fix: the gate pins PYTHONPATH to the checkout; set `PYTHONPATH=$PWD` by hand. Found: ernie45_d_p P2.16.
- **Tracy host capture crashes.** Symptom: "tracy-capture exited with code 1" under `--profile`. Cause: unknown, this box. Fix: device profiler with `TT_METAL_DEVICE_PROFILER=1 TT_METAL_PROFILER_MID_RUN_DUMP=1 TT_METAL_PROFILER_CPP_POST_PROCESS=1` and `testing/profiler.py`. Found: ernie45_d_p P3.3.
- **Pre-commit rewrites files at commit.** Symptom: a hash taken before `git commit` never matches again. Cause: black and the EOF fixer run inside the commit. Fix: format with pre-commit before hashing or testing (freeze and `gate --commit` do). Found: bringup_framework F1.
- **autoflake removes imports at commit.** Symptom: NameError after committing. Cause: an import unused at commit time is stripped. Fix: commit the import together with its use. Found: ernie45_d_p P2.9.
- **Edits by others during an agent step.** Symptom: an agent step failed with "changed files outside the allowed paths" listing files the agent never touched. Cause: the path check diffs the whole tree; a person's commit and a dashboard re-export happened during the step. Fix: files that end the step clean are ignored and the dashboard page is excluded; still avoid editing the tree while an agent runs. Found: gemma4_a4b_d_p R.2.
- **Templated YAML fails check-yaml.** Symptom: a gate commit silently did not land; the pre-commit check-yaml hook failed. Cause: a template with `$placeholders` in a `.yaml` file is not valid YAML. Fix: name templates `*.tmpl`. Found: bringup_framework F6.
- **Concurrent gates.** Symptom: verdicts overwritten, unrelated files in a gate commit. Cause: unlocked state writes; `git add -A` of the tree. Fix: the ledger lock and scoped commits (framework does both). Found: ernie45_d_p P2.x.
- **tt-probe writes outside the model dir.** Symptom: the allowed-paths check fails after a `scripts/tt-probe.sh` run. Cause: tt-probe saves each probe to `tests/ttnn/unit_tests/operations/<op_name>/probes/`. Fix: delete that directory before finishing the step, or probe inside the gate test. Found: gemma4_a4b_d_p C.sliding.attention.
- **Ethernet core down after a run.** Symptom: every later run fails at mesh open: "Timed out while waiting for active ethernet core ... to become active again" on all chips. Cause: unknown; run_safe_pytest resets only after a hang, not after a failed open. Fix: the orchestrator stops the run (infrastructure stop); a person resets the board. Agents never run `tt-smi -r`. Found: gemma4_a4b_d_p C.sliding.experts.
- **Hand-run gates write metrics to generated/bringup_adhoc.** Symptom: after a local gate run, `bringup/results/<task>.json` still shows the previous attempt. Cause: without the orchestrator's env, `metrics.results_dir()` / `task_id()` fall back to `generated/bringup_adhoc` and `adhoc`. Fix: read `generated/bringup_adhoc/<task>*.json` to check a local run. Found: gemma4_a4b_d_p P.3.

## Serving contract
- **K RoPE order.** Symptom: producer read-back PCC low for K only. Cause: the producer permutes HF (rotate-half) K to Meta order; a model whose K is already interleaved must skip it. Fix: set the model's golden K layout (`golden_k_rope_layout = "interleaved"`). Found: ernie45_d_p P2.16.
- **Acks before KV is on device.** Symptom: none in a synchronous test; a migration reads stale KV in serving. Cause: the runtime calls the layer-completion sink before the device finished the layer. Fix: sync (or an event) before `sink()`. The contract test's ack-timing check catches it. Found: tt-d-gen audit of ernie45_d_p.
- **Engine input.** Symptom: runtime crashes or embeds pad tokens. Cause: the engine passes a uint32 ROW_MAJOR device tensor [sp, 1, chunk/sp] with a padded tail, not a torch tensor. Fix: accept the device tensor and mask positions >= actual_end. Found: tt-d-gen audit of ernie45_d_p.
- **Producer KV read-back for a new layout.** Symptom: test_contract fails in the producer with `AttributeError: ... has no attribute 'KV_LORA_RANK'`. Cause: the producer chose its reader by adapter name and sent unknown models to the MLA reader; the GQA reader assumes one head_dim for all layers. Fix: define `read_slot_kv_and_check_pcc(table, device_map, slot_id, real_len, trace_dir, num_layers)` on the adapter (returns `{cache: min_pcc}`); the producer calls it first (see `gemma4_a4b_d_p/tt/runners/adapter.py`). Found: gemma4_a4b_d_p K.1.
- **Masking the engine's pad token on the device.** Symptom: the uint32 engine input carries 0xFFFFFFFF past actual_end, an out-of-range embedding index. Cause: the H2D pad value. Fix: for a power-of-two vocab, `ttnn.bitwise_and(to_layout(ids, TILE), V - 1)`, back to ROW_MAJOR, then `ttnn.embedding`; pad rows fall after every real row. See `gemma4_a4b_d_p/tt/model.py:TtEmbedding`. Found: gemma4_a4b_d_p K.1.

## Proposed
- **Fused fp8 qkv stored per TP rank.** Symptom: MiMo-V2.6 layer-0 `qkv_proj.weight_scale_inv` has 108 row blocks where ceil(13568 / 128) = 106; a global [q; k; v] split of the dequantized weight would give wrong heads. Cause: the checkpoint (`metadata.tp_size: 4`) stores the fused projection as [q_r; k_r; v_r] per rank, each rank slab quantized on its own 128-row blocks (layer 1 divides evenly, so only the row-norm pattern shows it). Fix: dequantize each rank slab with its own scale rows, then reorder to [q; k; v] (`mimo_v2_6_d_p/reference/weights.py:qkv_weight`); check the scale count and per-row norms of any fused, quantized projection. Found: mimo_v2_6_d_p R.2.
- **Remote modeling code older than the installed transformers.** Symptom: the stock loader stops on the missing `model_mtp.safetensors` listed in the index, and the checkpoint's modeling code calls `create_causal_mask(input_embeds=..., cache_position=...)`, which transformers 5.12 rejects. Cause: modeling_mimo_v2.py targets transformers 5.3; MTP shards were not downloaded. Fix: `hf_model` builds the class from the checkpoint on the meta device, loads the text weights itself, and wraps the two mask functions in the modeling module's namespace to rename `input_embeds` and drop `cache_position` (`mimo_v2_6_d_p/reference/hf_oracle.py`). Found: mimo_v2_6_d_p R.2.
- **SMT threads slow CPU MoE references.** Symptom: a 64-row expert GEMM took 27 ms at 32 threads and 4 ms at 16; mxfp4 dequant 2x slower. Cause: the gates call `torch.set_num_threads(os.cpu_count())`, which counts SMT siblings (16-core EPYC, 32 threads). Fix: the gates now use `core.metrics.cpu_threads()` (physical cores, F40); a model's hooks need not cap it. Found: mimo_v2_6_d_p R.2.
- **SDPA needs V head dim == QK head dim.** Symptom: MiMo attention has QK head dim 192 and V head dim 128; plain and chunked SDPA take one head dim. Cause: `sdpa_program_factory.cpp` sets `vDHt = DHt` unless `use_mla`, and the MLA ops (`flash_mla_prefill`, `chunked_flash_mla_prefill`) read V as a prefix of K, which a separate V projection is not. Fix: zero-pad V to the QK head dim at load (extra zero rows in the fused qkv weight), keep the padded cache, give o_proj zero columns (or slice the SDPA output), and return V[..., :Dv] on state read-back. Found: mimo_v2_6_d_p PL.1.
- **Plan gate counts packed checkpoint shapes.** Symptom: expert memory in plan_memory.json is half of what bfp8 needs on device. Cause: check_plan multiplies the stored shape by the placement dtype, and mxfp4 stores 2 values per uint8 byte. Fix: add the second half under `extra_gb_per_chip` and say so in plan.md (`mimo_v2_6_d_p/bringup/plan.yaml`). Found: mimo_v2_6_d_p PL.1.
- **A zero stub passes the layer-0 swap gate.** Symptom: MiMo full_dense swap 01 (attn_norm) with a zero attn_norm scores pcc_swap_out 0.9884 (gate 0.98); sum-instead-of-mean 0.9890 and eps 1e-2 0.9916 also pass. Cause: at layer 0 the residual stream and the attention over the golden KV prefix (zero Q gives uniform attention, attn_out PCC still 0.97) dominate block out. Fix: the swap test asserts the swapped step's own rel L2 (<= 0.03) and per-token norm ratio, and block-out rel L2 <= 0.01 (zero stub 0.155), so pytest fails even when the gated metric passes (`mimo_v2_6_d_p/tests/bringup/test_swap_full_dense_01_attn_norm.py`). Found: mimo_v2_6_d_p S.full_dense.01.
- **Rel L2 0.03 is too loose for full attention with a slow RoPE.** Symptom: on MiMo layer 0 (s4096 chunk 1, 2048-row KV prefix) RoPE positions from 0 score PCC 0.99968 / rel 0.025, a non-causal mask 0.99960 / rel 0.0285, scale 1/sqrt(Dv) 0.99931 / rel 0.040: all pass PCC 0.99 and the whole-chunk rel L2 0.03 of the Gemma template. Cause: theta 1e7 on 64 of 192 dims and a long prefix; the reference and bf16/bfp8 rounding sit at rel 0.002. Fix: measure the mutations on the golden and set the rel L2 limits between the device noise and the smallest bug (MiMo: 0.015 whole and first 128 rows; the first rows catch non-causal at 0.047) (`mimo_v2_6_d_p/tests/bringup/test_c_full_dense_attention.py`). Found: mimo_v2_6_d_p C.full_dense.attention test.
- **Chunked SDPA rejects a scale fp32 cannot hold.** Symptom: `chunked_scaled_dot_product_attention` raises "incompatible function arguments" although every printed argument type matches the signature (keyword or positional alike). Cause: since d39bab7c4ee the binding marks `scale` (and the configs) `.noconvert()`, and nanobind's noconvert float caster refuses a Python float whose double -> float cast is inexact (192^-0.5 is; Gemma's 1.0 was not affected). Fix: round the scale to fp32 first, `float(torch.tensor(s, dtype=torch.float32))` (`mimo_v2_6_d_p/tt/attention.py`). Found: mimo_v2_6_d_p C.full_dense.attention.
- **Sliding-window off-by-one hides inside device noise.** Symptom: on MiMo layer 1 (window 128, s4096 chunk 1) windows 127 and 129 score PCC 0.99998 / rel L2 0.010 / worst row 0.047, about the same as the device-noise estimate (rel 0.007, worst row 0.025), so no size limit separates them. Cause: one key per query row changes, and the sink takes most of the softmax mass (sink up to 1.14, key scores median -26; attn_out row norms 0.007-0.057). Fix: also assert the output is closer (rel L2) to the CPU reference at window W than to the same reference at W-1 and W+1. Random device noise does not point along the off-by-one difference: simulated noise, even with 1% added, always lands closest to its own window (`mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_attention.py`). Found: mimo_v2_6_d_p C.sliding_moe.attention test.
- **SDPA attention sink is folded with a bf16-truncated scale.** Symptom: MiMo sliding attention with `attention_sink` scored PCC 0.9999 but output norms 4-14% too high (rel L2 0.05-0.07). The same SDPA without a sink matched (rel 0.003). Cause: the sink term is `exp((sink - max) * scale)` with the scale taken as `scale_fp32 >> 16` (bf16, truncated, `compute_streaming.hpp:normalize_row_streaming`). 192^-0.5 becomes 0.07178 (-0.54%). When the row max is far below the sink (here ~390 unscaled, ~28 logits), the effective sink logit drops by ~0.15. Fix: pass a power-of-two SDPA scale (2^-4) and fold `true_scale / 2^-4` into the Q rows of the qkv weight; pre-divide the sink by the power of two, which is exact in bf16. Also use HiFi4 + fp32 dest acc for that SDPA: the sink-to-max gap magnifies score errors, and HiFi2 or bf16 dest leaves a 3-6% bias (`mimo_v2_6_d_p/tt/attention.py:TtSlidingAttention`). Found: mimo_v2_6_d_p C.sliding_moe.attention.
- **A zeroed attention barely moves a sink-dominated block out.** Symptom: on MiMo layer 1 (sliding_moe) the swap harness with attn_out zeroed scores block-out rel L2 0.014, inside the Gemma swap-02 limit of 0.02. The device scores 0.0031. Cause: the per-head sink takes most of the softmax mass, so attn_out row norms (0.007-0.057) are small next to the residual. Fix: size the block-out limit from the device run and a zeroed step (MiMo: 0.01), and also check the attention against the CPU attention on the same device input (rel <= 0.015, device 0.0070) (`mimo_v2_6_d_p/tests/bringup/test_swap_sliding_moe_02_attention.py`). Found: mimo_v2_6_d_p S.sliding_moe.02 test.
- **A residual test cannot see a small addend.** Symptom: on MiMo layer 1 (sliding_moe) `h_mid = in + attn_out` with attn_out dropped scores PCC 0.99993, rel L2 0.0113; `in + 0.5 attn_out` scores 0.99996 / 0.0060 and passes the full_dense limits (rel 0.01, norm ratio [0.99, 1.01]). Cause: the sink keeps ||attn_out|| (0.88) about 1% of ||in|| (79), so whole-output metrics barely see it. Fix: also check the addend on `delta = out - in`: coefficient `<delta, attn_out> / ||attn_out||^2` in [0.95, 1.05] and `||delta - attn_out|| / ||attn_out|| <= 0.3` (bf16 output rounding alone gives 0.15) (`mimo_v2_6_d_p/tests/bringup/test_c_sliding_moe_attn_residual.py`). Found: mimo_v2_6_d_p C.sliding_moe.attn_residual test.
- **A large correction bias makes noaux_tc top-k selection precision-bound.** Symptom: on the MiMo layer-1 router golden, rounding e_score_correction_bias to bf16 drops PCC to 0.970 (selection overlap 0.944), and an all-bf16 router scores 0.910. Rounding only the fp32 logits to bf16 scores 0.9943 (overlap 0.990), just above the 0.99 gate. Cause: the bias is 1.72..2.18 (std 0.04), so sigmoid + bias sits near 2, where the bf16 step is 0.0078.
