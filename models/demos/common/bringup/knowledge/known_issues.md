# Known issues

Shared lessons every agent reads before it starts: TTNN and `ttnn.bringup` fork behaviour, op limits and their
workarounds, precision mechanisms, testing method, framework / infra / hardware facts, serving-contract rules. Only
lessons that change what an agent does on another model belong here; anything about one checkpoint, one layer, one
model's tests or `tt/` code is in `models/demos/<model>/bringup/known_issues.md`. One bullet per lesson, at most
three lines: `Symptom:`, `Cause:`, `Fix:`, `Applies to:` (ops / repo paths), `Seen at:` (commit), optionally
`Check:` (a test or probe that shows a limitation still holds), `Found:` (model and task).

Agents do not edit this file: they add what they learn to their model's `bringup/known_issues.md`. When a run ends,
the overseer promotes the durable ones here (merged with their neighbours, shortened, anchored) and the owner approves.
Entries whose `Applies to:` code changed since `Seen at:` are re-checked after every rebase and fork sync.

## API behavior
- **Some ops return their input's buffer.** Symptom: garbage, a fault or "Input Tensor is not allocated" after freeing an input. Cause: `unified_routed_expert_moe` writes a TILE dispatched buffer in place; `ttnn.to_layout` to the same layout returns its input. Fix: free inputs only if the layout changed; keep the dispatched buffer until combine. Applies to: unified_routed_expert_moe (and ttnn.bringup fork), ttnn.to_layout. Seen at: 9b393736f86. Found: ernie45_d_p P3.2, xing40_a4b_d_p C.moe.experts.
- **Routed-expert counts and region offsets are global.** Symptom: hang in `cb_wait_front` inside unified_routed_expert_moe. Cause: `counts` and `expert_region_offsets` are indexed by global expert id; a local [1, experts_per_chip] array passes validation and the kernel reads garbage. Fix: pass [1, num_experts] per chip. Applies to: unified_routed_expert_moe, ttnn.bringup.unified_routed_expert_moe. Seen at: 9b393736f86. Found: ernie45_d_p P3.1.
- **Chunked SDPA rejects a scale fp32 cannot hold exactly.** Symptom: nanobind "incompatible function arguments" though types match. Cause: `scale` is bound `.noconvert()`; an inexact double -> float cast (e.g. 128^-0.5) is refused. Fix: `scale=float(torch.tensor(s, dtype=torch.float32))`, all arguments by keyword. Applies to: ttnn.transformer / ttnn.bringup chunked_scaled_dot_product_attention (sdpa_nanobind.cpp). Seen at: 9b393736f86. Found: ernie45_d_p P2.6, mimo_v2_6_d_p C.full_dense.attention.
- **ttnn.scatter has no fp32 TILE path.** Symptom: `ttnn.scatter` TT_FATALs "Scatter doesn't work for fp32 tiled tensors yet". Cause: only FLOAT32 + TILE (input or source) is rejected. Fix: scatter fp32 in ROW_MAJOR (exact; see `xing40_a4b_d_p/tt/router.py`), or scatter in bf16 TILE, or use a selector matmul. Applies to: ttnn.scatter. Seen at: 9b393736f86. Check: scatter on an fp32 TILE tensor raises. Found: ernie45_d_p P2.8, xing40_a4b_d_p C.moe.router.
- **TILE mesh_partition / slice need 32-aligned widths.** Symptom: `mesh_partition` (and `slice`) fail on a 16-wide column split of a TILE tensor. Cause: for tiled inputs the split must not create padding in the output shape. Fix: build the per-chip piece with a selector matmul (`routing @ M_j`), or split in ROW_MAJOR. Applies to: ttnn.mesh_partition, ttnn.slice. Seen at: 9b393736f86. Check: mesh_partition of a [.., 32] TILE tensor over 2 devices raises. Found: ernie45_d_p P2.9.
- **dispatch / combine / offset_cumsum on a 1-device axis.** Symptom: TT_FATAL "No neighbors found"; offset_cumsum's all_gather rejects the axis. Cause: the source ops always wire fabric and all_gather on the dispatch axis. Fix: `ttnn.bringup.dispatch` / `combine` / `offset_cumsum` skip them on a one-device axis (see `mimo_v2_6_d_p/tt/experts.py`). Applies to: ttnn/ttnn/bringup/{dispatch,combine,offset_cumsum}. Seen at: 9b393736f86. Found: ernie45_d_p P3.1-P3.2.
- **Multimodal HF wrapper hides the decoder layers.** Symptom: check_hf fails with `AttributeError: '...Model' object has no attribute 'layers'`. Cause: text layers are at `model.model.language_model.layers`; check_hf defaults to `model.model.layers`. Fix: define `hf_layers(model)` in the model's bringup hooks. Applies to: models/demos/common/bringup/reference/check_hf.py. Seen at: 9b393736f86. Found: gemma4_a4b_d_p R.2.
- **A kernel define that shadows an enumerator.** Symptom: trisc compile failure such as "'SILU' is not a member of KernelActivation". Cause: a compute define named `GELU_TANH` expands inside `KernelActivation` uses in bmm_fused_activation.hpp. Fix: prefix op-specific defines (`ROUTED_GELU_TANH`). Applies to: compute kernel defines, ttnn/cpp/ttnn/operations/matmul/device/kernels/compute/bmm_fused_activation.hpp. Seen at: 9b393736f86. Found: gemma4_a4b_d_p C.sliding.experts.
- **SDPA needs V head dim == QK head dim (source op).** Symptom: QK head dim 192 with V 128 cannot use plain or chunked SDPA. Cause: `sdpa_program_factory.cpp` sets `vDHt = DHt` unless `use_mla`. Fix: `ttnn.bringup.(chunked_)scaled_dot_product_attention` take a narrower V (multiple of 32, <= K, not windowed); or zero-pad V to K's dim. Applies to: ttnn.transformer.(chunked_)scaled_dot_product_attention, ttnn/ttnn/bringup/sdpa. Seen at: 9b393736f86. Found: mimo_v2_6_d_p PL.1.
- **TtReduceModule always reduce-scatters on a multi-device axis.** Symptom: 2x2 mesh, 2D dispatch groups: an [S/2, H/2] shard, not the [S/2, H] partial. Cause: `tt_reduce.py` reduce-scatters if `mesh.shape[cluster_axis] > 1`. Fix: `deepseek_prefill.post_combine_reduce`, then `all_reduce(cluster_axis=1)` + `all_gather(dim=-2, cluster_axis=0)`. Applies to: models/demos/deepseek_v3_d_p/tt/moe/tt_reduce.py. Seen at: 9b393736f86. Found: mimo_v2_6_d_p_2x2 C.sliding_moe.experts.
- **TtIndexer ropes only the first 64 index dims.** Symptom: an indexer roping dims 64-127 (Hy4) picks wrong keys. Cause: TtIndexer calls `rotary_embedding_indexed(rotary_dim=64)` without offset and hard-codes k_norm eps 1e-6. Fix: `rotary_embedding_indexed(..., rotary_dim=64, rotary_offset=64)` (no weight permutation); pass the model's eps. Applies to: ttnn.experimental.deepseek_prefill.rotary_embedding_indexed, models/demos/deepseek_v3_d_p/tt/mla/indexer.py. Seen at: 9b393736f86. Found: hy4_preview_d_p PL.1, C.dense_full.indexer.
- **TTNN RMSNorm on an fp32 input: three limits.** Symptom: `ttnn.rms_norm` ~0.1% low; `rms_norm_pre_all_gather` junk in stats columns 1-31, L1 OOM on wide rows. Cause: fp32-DEST scale bias; post reduces the whole stats tile; pre holds the row. Fix: `ttnn.bringup.rms_norm`; column-0 one-hot stats mask; wide rows: `ttnn.bringup.mhc_pre_xing_pack`. Applies to: ttnn.rms_norm, ttnn.rms_norm_pre/post_all_gather, ttnn/ttnn/bringup/rms_norm_ttnn. Check: needs probe (see KI-PROP-045, KI-PROP-048). Seen at: 9b393736f86. Found: hy4_preview_d_p C.dense_full.attn_norm, C.dense_full.q_a, xing40_a4b_d_p P.2b.
- **indexer_score_dsa sums heads in bf16 DEST.** Symptom: indexer top-k overlap below gate. Cause: it MACs heads in bf16 DEST, refuses `fp32_dest_acc_en`; k_chunk > 32 ignores fidelity in the gate multiply. Fix: `ttnn.bringup.(ring_)indexer_score_dsa` with `fp32_dest_acc_en=True`, k_chunk 32; or per-head `ttnn.linear` + fp32 `addcmul`. Applies to: ttnn.experimental.indexer_score_dsa (chunk_start_idx must be tile-aligned), ttnn/ttnn/bringup/indexer_score. Seen at: 864ec8b0891. Found: hy4_preview_d_p C.dense_full.indexer, glm53_flash_d_p C.dsa_moe.indexer.
- **indexer_score's k_chunk is L1-bound by dtype and DEST width.** Symptom: CBs exceed L1 at 32 heads, bf16 q / k, k_chunk 320 (DSA_INDEXER_CONFIG), and at 256 with fp32 DEST. Cause: cb_qk holds k_tiles x heads accumulator tiles; 320 was sized for bfp8. Fix: re-sweep k_chunk for your dtypes and DEST width (32 fits and is accurate). Applies to: ttnn.experimental / ttnn.bringup ring_indexer_score_dsa, deepseek_v3_d_p/tt/mla/mla_config.py:DSA_INDEXER_CONFIG. Seen at: 864ec8b0891. Check: ring_indexer_score_dsa, bf16 q / k, 32 heads, k_chunk 320 fails CB allocation. Found: hy4_preview_d_p C.dense_full.indexer.
- **sparse_sdpa default scale; pooled keys in indexer_score_dsa.** Symptom: absorbed MLA gets scale K_width^-0.5, not qk_head_dim^-0.5; pooled indexer keys get a per-token causal mask. Cause: defaults (1/sqrt(q.shape[-1]); per-token mask). Fix: pass `scale=` explicitly; for keys pooled over 4 tokens pass `key_compression_ratio=4`. Applies to: ttnn.transformer.sparse_sdpa, ttnn.experimental.indexer_score_dsa. Seen at: 864ec8b0891. Found: glm53_flash_d_p PL.1.
- **ttKDA needs two distinct mesh axes.** Symptom: a 2x2 mesh cannot run KDA as TP=4 or with a size-1 SP axis. Cause: `ttKDA` shards heads over `tp_axis`, sequence over `sp_axis`, and raises on `sp_axis == tp_axis`. Fix: TP on one axis, SP on the other (2x2: TP=2 axis 1, SP=2 axis 0); fallback: ttKDA per 1xN row submesh with SP=1. Applies to: models/demos/deepseek_v3_d_p/tt/kda/kda.py. Seen at: 864ec8b0891. Found: glm53_flash_d_p PL.1.
- **all_gather of a wide int32 ROW_MAJOR tensor hung on 2x2 FABRIC_2D.** Symptom: `ttnn.all_gather(dim=2, cluster_axis=1)` on [1, 1, 512, 2176] int32 RM hangs; [1, 1, 64, 256] passes. Cause: not isolated (8704 B page?). Fix: at a harness boundary concat `ttnn.get_device_tensors` shards on host; in a model try TILE or fp32. Applies to: ttnn.all_gather. Seen at: edbd3b841ec. Check: the probe below. Found: glm53_flash_d_p C.dsa_moe.indexer.
- **typecast fp32 -> uint32 clamps -1 to 0.** Symptom: fp32 ids with -1 for none become 0 (a valid id) after `ttnn.typecast(x, ttnn.uint32)`. Cause: the SFPU typecast saturates negatives to 0. Fix: `ttnn.typecast(x, ttnn.int32)` then `ttnn.bitcast(..., ttnn.uint32)` gives 0xFFFFFFFF; fp32 integers are exact below 2^24. Applies to: ttnn.typecast. Seen at: 9b393736f86. Found: glm53_flash_d_p C.dsa_moe.indexer.
- **nlp_concat_heads overflows L1 with many wide heads.** Symptom: `nlp_concat_heads` on [1, 64, S, 256] bf16 fails: static CBs exceed L1. Cause: the input CB holds heads x head_dim/32 tiles, double-buffered, per core. Fix: concat groups of 32 heads (16 for fp32), join with `ttnn.concat(dim=-1)`. Applies to: ttnn.experimental.nlp_concat_heads. Seen at: 9b393736f86. Found: glm53_flash_d_p C.dsa_moe.attention.
- **mhc_split_sinkhorn is one specific Sinkhorn.** Symptom: an mHC reference that clamps, subtracts row max or lacks pre eps drifts in comb / pre. Cause: logits capped at 80, row softmax + eps, col norm, iters-1 (row, col) pairs, pre = sigmoid + eps. Fix: compare with the reference; Xing-style: `ttnn.bringup.mhc_pre_xing`; check comb vs comb^T. Applies to: mhc_split_sinkhorn, ttnn.bringup.mhc_pre_xing / mhc_post (comb_transposed). Seen at: 9b393736f86. Found: xing40_a4b_d_p PL.1.
- **New compute kernels need the compute API headers.** Symptom: JIT build: 'get_arg_val' / 'cb_wait_front' / 'tile_regs_acquire' not declared. Cause: they live in `api/compute/common.h`, `cb_api.h`, `reg_api.h` (namespace ckernel); kernel_lib helpers include them. Fix: include the three; add `using namespace ckernel;` before kernel_main. Applies to: tt_metal/hw/inc/api/compute. Seen at: 9b393736f86. Found: xing40_a4b_d_p P.2b.

## Accuracy
- **Fused routed experts: use the fork's high_precision.** Symptom: `unified_routed_expert_moe` passes PCC, fails the norm ratio. Cause: the source forces LoFi + bf16 dest, bfp8 activations, Float16_b L1 partials. Fix: `ttnn.bringup.unified_routed_expert_moe(..., high_precision=True)` (ROW_MAJOR bf16 x), HiFi3/4 + fp32 dest (HiFi2 biases low). Applies to: ttnn.experimental.deepseek_prefill.unified_routed_expert_ffn, ttnn/ttnn/bringup/unified_routed_expert_ffn (`routed_expert_ffn` refuses fp32 dest). Seen at: 9b393736f86. Found: ernie45_d_p P3.2, gemma4_a4b_d_p PL.1, mimo_v2_6_d_p C.sliding_moe.experts, P.1.
- **noaux_tc routers: the bias only selects, and needs fp32.** Symptom: routed experts differ from HF on some tokens. Cause: the bias only picks top-k (weights unbiased); by default `moe_grouped_topk` adds it with FPU `add_tiles`, sorts TF32 keys and normalizes the weights from TF32 operands. Fix: `moe_grouped_topk(..., fp32_selection=True)` (SFPU bias add, fp32 keys and normalization; `glm53_flash_d_p/tt/router.py`), or fp32 sigmoid + bias via `ttnn.add` (SFPU) -> `ttnn.topk` -> `ttnn.gather`, or recentre the bias at load. Applies to: ttnn.experimental.deepseek_prefill.moe_grouped_topk, ttnn.topk routers. Seen at: 864ec8b0891. Found: ernie45_d_p P1.2, mimo_v2_6_d_p C.sliding_moe.router, glm53_flash_d_p C.dsa_moe.router.
- **CPU sgemm result depends on M.** Symptom: chunked vs one-shot CPU references diverge after the first MoE, with growing routing flips. Cause: MKL picks M-dependent kernels for small or odd M, so expert rows depend on its token count. Fix: zero-pad each expert's token group to a multiple of 32 rows before `F.linear`, drop the pad rows. Applies to: method (CPU MoE references). Seen at: b847e163e88. Found: gemma4_a4b_d_p R.3.
- **HiFi2 and bf16 intermediates bias output norms.** Symptom: MLP / expert matmuls pass PCC but per-token norms run low. Cause: HiFi2 drops low mantissa bits, biasing products to zero; bf16 gate/up/h before a long-K down adds row error. Fix: HiFi4 + fp32 acc, fp32 intermediates (`ttnn.linear(..., dtype=ttnn.float32)`). Applies to: ttnn.linear, matmul, unified_routed_expert_moe. Seen at: 864ec8b0891. Found: gemma4_a4b_d_p C.sliding.mlp, mimo_v2_6_d_p C.full_moe.experts.
- **Fused quantized projections may be stored per TP rank.** Symptom: a fused qkv's block-scale count is not ceil(rows / block). Cause: the checkpoint (`metadata.tp_size`) stores [q_r; k_r; v_r] per rank, each quantized separately. Fix: dequantize each rank slab with its own scales, then reorder; check scale counts and row norms. Applies to: method (reference weight loaders). Seen at: 721693c3e0b. Found: mimo_v2_6_d_p R.2.
- **SDPA attention sink uses a bf16-truncated scale.** Symptom: with `attention_sink`, PCC passes but row norms run 4-14% high. Cause: the sink term uses `scale_fp32 >> 16` (compute_streaming.hpp); a large sink-to-max gap magnifies it and any QK error. Fix: a power-of-two scale with the rest folded into Q, the sink pre-divided; HiFi4 + exact exp. Applies to: ttnn.transformer / ttnn.bringup (chunked_)scaled_dot_product_attention attention_sink. Seen at: 9b393736f86. Found: mimo_v2_6_d_p C.sliding_moe.attention, P.2.
- **Check an HF port's RoPE against the serving code.** Symptom: the CPU reference matches the HF oracle but accuracy is far under the floor. Cause: a port may use another RoPE style than serving; DeepSeek-style `apply_rotary_pos_emb_interleave` returns `cat([evens, odds])`. Fix: check RoPE, norms, scales vs SGLang / vLLM. Applies to: models/demos/<model>/reference/ (keep checkpoint order; compare k_rope after permuting), intake/check_hf_sanity.py. Seen at: 9b393736f86. Found: hy4_preview_d_p R.2, xing40_a4b_d_p R.2.
- **KDA prepare_chunk_recurrence loses fast-decay state precision.** Symptom: post-chunk state biased low on fast-decay key channels; output passes. Cause: the source op forms the anchored gate exponents (k_dec_t = exp(G_last - G_j), q_decay, kd) with FP32 subtractions read at TF32, |G| ~150. Fix: `ttnn.bringup.prepare_chunk_recurrence(precise_gate_factors=True)` (exact; GLM_KDA_DECAY=fork, the default), or recompute k_dec_t in fp32 after the op (`kda_attention.py:_PreciseDecayRecurrence`, GLM_KDA_DECAY=precise, +1.4 ms per layer); check the state. Applies to: ttnn/cpp/ttnn/operations/experimental/kda/prepare_chunk_recurrence, ttnn/ttnn/bringup/prepare_chunk_recurrence, glm53_flash_d_p/tt/kda_attention.py. Seen at: 864ec8b0891. Found: glm53_flash_d_p C.kda_dense.attention.
- **The FPU reads fp32 operands at about TF32.** Symptom: fp32 matmul outputs shrink (HiFi4 + fp32 DEST: rel 1.2e-3, norm ratio 0.9990 vs fp64; TF32-truncated inputs give 7.7e-4); fp32 `all_reduce` misses by ~2 TF32 ulps. Cause: FPU source registers keep a 10-bit mantissa; CCL reductions add on the FPU. Fix: feed bf16 where one rounding suffices; for exact fp32 sums use the SFPU (`all_gather`, then `ttnn.add`: equals torch's fp32 sum). Applies to: ttnn.linear / matmul, ttnn.all_reduce, ttnn.reduce_scatter. Seen at: 864ec8b0891. Check: fp32 matmul vs fp64, fp32 all_reduce vs all_gather + add, on a 1x4 mesh (knowledge/probes/fpu_fp32.py). Found: glm53_flash_d_p C.dsa_moe.attention, C.kda_dense.mlp, P.2.
- **sparse_sdpa keeps flash state in bf16 with approximate exp.** Symptom: PCC ~1.0, norm ratio / rel L2 fail. Cause: output and row-sum CBs are bf16, rescaled per k_chunk; exp is approximate whatever math_approx_mode says. Fix: `ttnn.bringup.sparse_sdpa(..., high_precision=True)` (fp32 DEST, bf16 q / kv, no sink). Applies to: ttnn.transformer.sparse_sdpa, ttnn/ttnn/bringup/sdpa. Seen at: 9b393736f86. Found: glm53_flash_d_p C.dsa_moe.attention.
- **ring_mla loses sharp rows at bf16 DEST; source refuses fp32.** Symptom: `ttnn.transformer.ring_mla` passes PCC, fails worst-row rel L2; fp32 DEST TT_FATALs. Cause: latent V and kv_actual_isl exist only on the streaming (bf16 DEST) path, where QK^T accumulates in 16-bit DEST. Fix: `ttnn.bringup.ring_mla` with `fp32_dest_acc_en=True`. Applies to: ring_mla (sdpa fork). Seen at: 9b393736f86. Found: xing40_a4b_d_p C.dense.attention.

## Testing
- **PCC cannot see a scale error.** Symptom: scale bugs (addend x1.01, dropped norm weight, wrong eps, ignored fp8 block scale) pass PCC 0.99+. Cause: PCC is scale-invariant; a later norm removes row scale. Fix: also gate rel L2, per-row norm ratio, coefficient <got, want> / <want, want>, and per addend <out - other, addend> / ||addend||^2. Applies to: component / swap tests, testing/component_checks.py. Seen at: 864ec8b0891. Found: gemma4_a4b_d_p, hy4_preview_d_p, glm53_flash_d_p C.* tests.
- **A swap test's block out cannot isolate a swapped step.** Symptom: step bugs pass block-out PCC / rel L2. Cause: a following norm, the residual or a saturated term dominates; MoE flips carry the effect. Fix: gate the step vs the CPU step on the same device inputs (tight) and vs golden (loose); measure shares vs a CPU tail, not a 2nd device run. Applies to: run_swap_test(checks="steps"), testing/component.py. Seen at: 864ec8b0891. Found: gemma4_a4b_d_p, hy4_preview_d_p, glm53_flash_d_p S.* tests.
- **Test limits do not carry across layers or steps.** Symptom: a copied limit fails a correct device (below its bf16 floor) or passes real bugs (1.5-5x too loose). Cause: coefficient scales, term shares and norm placement change per layer. Fix: per layer and comparison, measure the bf16 floor and the smallest mutation; set the limit between. Applies to: testing/component_checks.py (component_calib), swap tests. Seen at: 864ec8b0891. Found: mimo_v2_6_d_p, hy4_preview_d_p, glm53_flash_d_p.
- **Device noise vs the smallest mutation.** Symptom: a 1% noise mutation slips calibrated limits (mHC, sharp attention); a window off-by-one hides in device noise. Cause: correct device error is near 1% there. Fix: per-part limits plus structural checks (Sinkhorn column sums, ranges); assert the output fits the true W better than W +- 1. Applies to: testing/mutate.py, component tests. Seen at: ba9a63f1034. Found: mimo_v2_6_d_p C.sliding_moe.attention, xing40_a4b_d_p C.dense.attn_hc, C.moe.attention.
- **A small residual addend is invisible on the sum.** Symptom: dropping or halving a ~1% (or sub-ulp) addend passes PCC, rel L2 and norm ratio. Cause: metrics follow the large term. Fix: check the addend on delta = out - in (<delta, a> / ||a||^2 near 1); for sub-ulp addends compare to the CPU step on the same inputs at fp32, float64 stats. Applies to: method (residual / iHC / mHC component tests). Seen at: 5cbc631eea2. Found: mimo_v2_6_d_p, hy4_preview_d_p, glm53_flash_d_p residual tests.
- **Whole-output metrics hide column, row and block bugs.** Symptom: a biased or transposed column, one wrong row or one shard's scale passes PCC / rel L2. Cause: large entries and many rows dominate. Fix: check per column (rel L2, median ratio), per 128-row block, worst row, carried state, invariants (comb column sums, router row sums). Applies to: testing/component_checks.py (col, row). Seen at: 864ec8b0891. Found: hy4_preview_d_p, glm53_flash_d_p C.* tests.
- **MoE top-k flips break per-row block-out checks.** Symptom: even the fp32 CPU block fails a per-row ratio vs the bf16 golden; flips hide a zeroed row. Cause: near-tie top-k choices flip on a 0.1% change. Fix: split rows by routing: tight rel L2 / ratio on same-routing rows, loose on flipped rows; flip counts only as a loose bound. Applies to: method (MoE block swap tests). Seen at: edbd3b841ec. Found: mimo_v2_6_d_p S.full_moe.07, hy4_preview_d_p S.moe_full.12, glm53_flash_d_p S.dsa_moe.*.
- **Fork-test references and limits on random inputs.** Symptom: correct forks fail case checks (bfp8 inputs; long random SDPA). Cause: block-float inputs round on device; random inputs give tiny outputs; rel L2 follows large rows. Fix: read inputs back (`ttnn.to_torch`) as reference; bit-compare to the source op where inert; per-row limits. Applies to: method (ttnn/ttnn/bringup/*/tests, bringup-fork-tests skill). Seen at: 9b393736f86. Found: gemma4_a4b_d_p O.1, mimo_v2_6_d_p O.1, glm53_flash_d_p O.1.
- **A layer's golden may not exercise the feature under test.** Symptom: SwiGLU clamps never fire, an eps is invisible, identical layer-0 streams hide stream order. Cause: the golden's inputs. Fix: also run the step on second inputs (another layer, chunk 0, small-RMS, scaled, permuted) vs the CPU step on them; confirm a mutation fails. Applies to: testing/component_checks.py second inputs, testing/mutate.py. Seen at: 864ec8b0891. Found: hy4_preview_d_p, glm53_flash_d_p C.* tests.
- **Top-k index outputs need set overlap plus exact structure checks.** Symptom: positional match fails the reference; mean overlap passes causal, count and pooling bugs. Cause: order and near-ties are free. Fix: `topk_overlap` (mean and worst row) plus exact checks (in range, causal, no repeats, per-row count, pads last) and downstream attention. Applies to: harness topk_overlap, component_checks.py index kind. Seen at: 864ec8b0891. Found: hy4_preview_d_p, glm53_flash_d_p C.*.indexer.
- **A step reading another layer's output fails single-block tests.** Symptom: `KeyError: layer 2 reuses layer 1's top-k` in component / swap tests, even with BRINGUP_IMPL=reference. Cause: the harness runs one block. Fix: model hook `swap_context(spec, ref, layer, golden, chunk, rctx, dctx)` putting the golden source output in both contexts. ## Performance
- **fp32 DEST disables streaming SDPA.** Symptom: SDPA dominates a long-prefix chunk at low TFLOPS. Cause: `can_use_streaming_compute` returns `!fp32_dest_acc_en` (sdpa_program_factory.cpp); fp32 DEST runs the legacy kernel. Fix: HiFi2, fp32 dest off, approx exp, large q/k chunks; validate, as sinks and sharp softmaxes may need fp32 DEST. Applies to: ttnn.transformer.(chunked_)scaled_dot_product_attention. Seen at: 9b393736f86. Found: ernie45_d_p P3.4.
- **One SDPA program per chunk offset.** Symptom: the first long run is ~5x slower than warm runs. Cause: a scalar `chunk_start_idx` is part of the compiled program (it sets Sk and the Q-chunk offset). Fix: measure warm; for serving / traces pass `chunk_start_idx_tensor` (device int32 [1]; mutually exclusive with the scalar). Applies to: ttnn.transformer.chunked_scaled_dot_product_attention. Seen at: 9b393736f86. Found: ernie45_d_p P3.4.
- **Streaming SDPA chunk sizes: L1 cap vs prefix traffic.** Symptom: long-prefix SDPA is bandwidth-bound; large chunks fail to compile at large head_dim. Cause: no KV forwarding, so traffic scales with Q chunk count; CBs cap chunks by L1. Fix: largest Q chunk that fits (head_dim 192: q512/k128; 256: q256/k256; 512: q128/k128). Applies to: sdpa_program_factory.cpp. Seen at: 9b393736f86. Found: gemma4_a4b_d_p P.2, mimo_v2_6_d_p P.2.
- **The hybrid harness is not the model's speed.** Symptom: ~20 s per chunk, flat in position. Cause: the component/swap harness runs the CPU reference with host in / host out around every device step. Fix: time only the all-device model built by the assemble step (M.1) (Gemma-4: 0.61 s per 50k->55k chunk). Applies to: models/demos/common/bringup/testing/harness.py. Seen at: 864ec8b0891. Found: gemma4_a4b_d_p P.1.
- **ttnn.linear's auto config is ~2.8x slow on big fp32-dest matmuls.** Symptom: HiFi4 + fp32-dest prefill matmuls far below peak. Cause: auto 2D-mcast uses in0_block_w 1 when the fp32 output block fills L1, spilling partials every K tile. Fix: explicit `MatmulMultiCoreReuseMultiCastProgramConfig`, out_block_h / w < per_core_M / N, in0_block_w 16. Applies to: ttnn.linear, ttnn.matmul, models/demos/hy4_preview_d_p/tt/attention.py:mm_program_config. Seen at: 864ec8b0891. Check: device time auto vs explicit config on that shape. Found: hy4_preview_d_p P.1.
