# Rebase the bring-up branch

The branch carries model bring-ups (`models/demos/<model>`), the framework (`models/demos/common/bringup`) and the
forked ops (`ttnn/ttnn/bringup`). A rebase moves all of it onto a new base; the forks then lag their sources, some
forks stop building, tests key on changed signatures, and knowledge entries go stale. Do the steps in order. Nothing is
pushed until step 9, and the owner decides every policy question (marked **owner**).

Throughout: `G="git -c gc.auto=0 -c maintenance.auto=false"`; long jobs (rebase, build, device runs) in tmux with a
log, watched; device runs only through `scripts/run_safe_pytest.sh`; never run two device jobs at once.

## 0. Know which tree
Several clones of tt-metal may sit side by side, each with its own `.git`: a push from one does not update another's
`origin/*` refs (`git status` there says "up to date" until a fetch). Confirm with the owner which clone holds the
branch, `git fetch` it, and check that no agent session is working in it.

## 1. Baseline (before touching anything)
- Old base: `$G merge-base <branch> <old llk_helper_library>`; new base: the target (`origin/llk_helper_library`).
- Build the branch as it is and measure one model's full set (step 7's recipe) into a scratch results dir: committed
  `results/*.json` may predate earlier rebases, so they are only a coarse reference.

## 2. Rebase
- Partial clone (`remote.origin.partialclonefilter` set): prefetch the blobs once, or every commit fetches on its own
  (measured 7 vs 280 commits/min):
  `$G rev-list --objects --missing=print <old base>..<branch> | grep '^?' | cut -c2- | $G -c fetch.negotiationAlgorithm=noop fetch origin --no-tags --no-write-fetch-head --recurse-submodules=no --filter=blob:none --stdin`
- `$G rebase --onto <new base> <old base>` in tmux (in a scratch worktree if the main tree is busy building or
  testing). Conflict policy: a file under `ttnn/cpp/ttnn/operations` takes the new base's side (`checkout --ours`):
  the branch never keeps edits to original ops (old edits were moved into forks and the originals restored).
  Any other conflict: stop and show the owner.
- Verify: branch-owned paths (`git diff --name-only <old base> <old branch>`) equal the old branch except files both
  sides changed; every other path equals the new base; `ttnn/cpp/ttnn/operations` equals the new base; for the files
  both sides changed, the branch's diff carried over unchanged.

## 3. Sync the forks to their sources
For each fork with an upstream source (its CHANGELOG names `Source:`; `Source SHA:` plus any "Upstream sync" entries):
1. Its effective base: the source at the last sync, minus the commits that sync skipped (listed in the CHANGELOG).
   **owner**: full sync (take everything upstream did; new options default off, upstream bug fixes change behaviour)
   or selective (build-required + fixes only). Full sync keeps later syncs mechanical.
2. Mechanical copies with `ttnn/ttnn/bringup/fork_op.py` in a scratch clone/worktree: the source at the base (with the
   skipped commits reverted: `git diff <c>^ <c> -- <src> | git apply -R`) and at the new base, same `--name`.
3. 3-way merge per file into the fork: `git merge-file -L fork -L base -L upstream <fork file> <base copy> <new copy>`;
   files new upstream are copied in. Conflicts are usually API-shaped: re-apply the fork's change on upstream's code.
4. After merging, grep the fork for spellings the fork had fixed by hand that upstream's new code reintroduces (shared
   types back in the source namespace, `prim::bringup::`, double `bringup::bringup`) and fix them.
5. CHANGELOG entry ("Upstream sync to source @ <sha>": what was taken, conflicts and how, behaviour change) and the
   INDEX.md row.

## 4. Build and port the forks without a source
`./build_metal.sh`; for the full error list at once: `ninja -C build_Release -k 0`. Forks generated by op-gen (no
source) break on API changes in the base (removed aliases, a replaced helper). Port them, C++ factory and Python
parity builder alike, with the same topology / semaphore ids where possible; the parity test
(`tests/unit/test_*cpp_parity*`) must pass. Record each port in the fork's CHANGELOG.

## 5. Fork tests
- Every fork's unit suite (`ttnn/ttnn/bringup/<fork>/tests/unit`, perf tests excluded) and model cases
  (`tests/test_*.py`): fix tests that read old internals (wire layouts, removed fields).
- Call signatures (`sig`) in `tests/cases.py` and the models' `results/fork_calls.json` change when a shared config
  type gains fields or the models' tensors change placement. Re-key them, and check the new signatures against a fresh
  capture of a model on this box, never only by recomputing.
- Re-record the source-test baselines: `python -m models.demos.common.bringup.testing.fork_source --fork <f> --record`;
  explain count changes (upstream pruned or added tests) and any case the original passes and the fork fails.

## 6. Commit
One commit per concern (fork syncs; API ports; test updates; baselines), formatted (`pre-commit run --files ...` until
clean), with the attribution lines.

## 7. Verify every model of this box
Per model (`models/demos/<model>/bringup/spec.yaml` box = this box), with `BRINGUP_SPEC`, `BRINGUP_RESULTS_DIR=<scratch>`
and `BRINGUP_TASK=<task>` set: each ladder rung (`BRINGUP_RUNG=<rung> scripts/run_safe_pytest.sh --run-all
models/demos/common/bringup/tests/test_ladder.py`), the contract test (`tests/test_contract.py`), and the fork-call
capture + coverage (`BRINGUP_CAPTURE_FORKS=<scratch>/fork_calls.json BRINGUP_RUNG=last ... -p
models.demos.common.bringup.testing.fork_capture`, then `python -m models.demos.common.bringup.testing.fork_cases
--capture <scratch>/fork_calls.json` with `--run-tests` once). Compare every `pcc*` / `top*` metric with step 1's
baseline (or the committed final `X.3.json` / `K.1.json`, noting their date): bit-identical or explained. Models whose
mesh this box cannot open are listed as not verified.

## 8. Knowledge staleness
Follow `staleness.md` (in this folder): list the entries whose code changed, verify, fix or remove them, report.
Commit the result separately after the owner has read the report.

## 9. Publish
- Push a backup of the old remote tip first: `$G push origin <old tip sha>:refs/heads/<branch>_backup`.
- Then `$G push --force-with-lease=<branch>:<old tip sha> origin HEAD:refs/heads/<branch>`.
- Tell the owners of branches forked from the old tip: `git rebase --onto origin/<branch> origin/<branch>_backup`.
- Other clones of the repo on the box: `git fetch`, `git reset --hard origin/<branch>` (after checking they hold no
  unpushed work), submodules, rebuild.
