Hybrid page pool · fine-grain slot eviction

Pipeline Stage Gate

Each pipeline stage holds an incoming chunk until the KV manager (KVM) has copied that request's pages into the chunk's execution-lane slot. The gate lives in the stage's entry socket, so every model that uses the D2D stream service gets it without changing model code. Copy-in and copy-out happen once per request per stage, not per chunk.

How the metadata travels and who touches it

The per-chunk record rides with the activation from stage to stage. The engine writes it once at stage 0. Models and the runner forward it without reading the gate fields. Each stage's entry socket only reads it. The gate-open command does not ride with the chunk: the KVM submits it to each stage's chips separately, including chips on other hosts.

Record fields

The legacy record keeps its first four words, and one gate word is appended. The socket is told where the slot and flags words sit (byte offsets 0 and 16), so a later versioned layout only changes those two offsets.

A slot id outside the gate range, such as the shutdown (−1) and warm-up (−2) sentinels, passes ungated. When several requests share a chunk later on, the record grows a list of slot entries, and readers stay read-only.

The gate word

One 32-bit word per slot, on the entry socket's service core of every chip in the stage. Every write is a plain store of 0 or 1, so no writer needs an atomic increment, which PCIe does not provide.

Open ordering

Over PCIe: strict TLB plus sfence between the copy-in data and the gate store. Over fabric: barrier the copy-in writes first, or send a flushed atomic +1. A plain inline write is not ordered behind earlier data.

Engine invariant

Copy-in to a slot only after that stage's layer completion and copy-out for the previous request. An OPEN written to a still-open gate would be lost.

Abort

If a request's last chunk will never arrive, force the gate closed from the host (set_stage_gate(coord, slot, false)).

One stage over time

Three requests reach this stage in order: A (slot 2, two chunks), C (slot 0, one chunk), then B (slot 2 again, one chunk). Each slot has its own gate. Status

  • D2D entry gate implemented and passing on a 2x2 Blackhole mesh (D2DStreamConfig::stage_gate, receiver kernel, descriptor and host set/read, Python bindings). The gtests cover a closed gate holding a chunk, release on open, close on transit, a multi-chunk burst, sentinel and bypass pass-through, and teardown while gated, across one and two chips. Multi-chip tests show each chip's gate is independent, and that a kernel on another chip can open a gate over fabric using only the descriptor. The existing D2D and pipeline tests still pass.
