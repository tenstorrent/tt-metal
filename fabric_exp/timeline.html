Where a 4 KiB packet's cycles go on the 2D router

One flow, 2D 1-hop write, E/W, 4 KiB, untrimmed router: E0 polls all four VC0 sender channels, only ch0 (the worker) carries traffic. Each lane is one core's work for one packet in steady state, on a shared cycle axis. The cores work on different packets in parallel, so the longest lane sets the interval.

An earlier pass left 15 cycles of the polling-flags build unaccounted. Most of that was the send: in that build it is 52 instructions, not 45, because bit 7 adds a sent-count update and the grouped read leaves the free-slot stream address to be recomputed (see the send listing below). About 5 remain unexplained.

E1 on the receiving chip

E1's "loop + polls" is a residual; the compiled loop accounts for ~44 of its 53 (select the segment for the parts). It is paid once per loop iteration, and E1 handles one packet per iteration, so a faster E0 does not shrink it. On N/S, decode is 32 instead of 17, so E1 is busy ~152 and becomes the limit once E0 drops below that.

Inside the send

Update: three of the ideas below are now measured (RESULTS §20). Dropping the write counter (−8 to −11), the stride slot address (−3) and the overlapped size read (−3) together take 1-hop E/W from 186.5 to 168.7 and the send from 52 to 35 instructions. The early TX-queue read and the compile-time stream id gained nothing. The breakdown below is the polling-flags build, before those changes.

send_next_data for ch0 in the polling-flags build: 52 instructions, about 72 cycles. Only about 21 cycles are the work that has to happen (read the size, program the TX queue, send the pointer update). About 39 are pointer and counter bookkeeping, and 12 go to one register read before the pointer update.

Which reads an ERISC can hide

From the load-overlap microbenchmark (test_erisc_load_overlap, data cache off as in the router). Cost is cycles beyond the same code without the read.

Sources and method

  • Measured: the interval from the benchmark's bandwidth; phase timers (TT_FABRIC_PHASE_PROFILE=2, calibrated timer cost removed); the trimming ablation for idle visits.
  • Derived: from differences between measured intervals. E1's loop + polls is the residual of the trimmed N/S case, where E1 is the limit. The upstream idle check on E1 comes from trimmed N/S 152.6 → 176.4.
  • Estimated: instructions from the compiled router at one cycle each, plus read costs from the load-overlap microbenchmark. Applied to today's send it gives 63 against 62 measured.
  • Wire: Ethernet framing at 400 Gb/s (37.04 B/cycle), 56 B overhead per frame, at most 4114 B of payload per frame, 84 B minimum frame. The placement model still assumes an 80 B 2D header; this mesh compiles a 96 B header, +0.5 cycles at 4 KiB.
  • Disassembly: fabric_exp/disasm/e0_untrimmed.dis (no flags), e0_384.dis (bits 7 + 8), e0_21888.dis (bits 7, 8, 10, 12, 14), e1_untrimmed.dis (E1, no flags), e1_896.dis (E1, bits 7 + 8 + 9).
  • Write-ups in fabric_exp/RESULTS.md: §3 phase and primitive costs, §8 2D breakdown, §11 TX queue, §16 keepalive floor, §17 polling and read overlap, §18 stack, §19 latency, §20 the send.
