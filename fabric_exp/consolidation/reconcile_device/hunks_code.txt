+P ## Router Structure
+P 
+P There are one or more sender channels and one or more receiver channel. "Sender" and "receiver" are relative to the Ethernet link,

+P   - Multicast and this chip is in the multicast target range

+P ## Connecting Workers to Channels
+P 
+P As mentioned, only one worker can push to a given EDM sender channel at a time. In order to send to an EDM
+P sender channel, the worker must establish a connection. The connection protocol is as follows and is started
+P by the worker (the EDM is a subordinate in this protocol).
+P 
+P *NOTE*: If multiple workers try to connect to the same EDM sender channel at the same time, the behavior is undefined.
+P *NOTE*: Additionally, if a worker pushes packets to a channel it isn't connected to, behaviour is undefined.
+P *NOTE*: Undefined == likely hang
+P 
+P ## Packet Structure
+P 
+P Workers are responsible for populating packet headers before sending to the EDM. The packet header structure is defined
+P in `fabric_edm_packet_header.hpp`.
+P 
+P ## Channel structure
+P 
+P Each EDM channel is built from one or more buffers. Each buffer is the same size and can hold at most one packet.
+P Neighbouring packets occupy nehighouring buffers - with the exception of the last buffer index. The next packet after a
+P write into the last buffer index will wrap around to the first buffer index. Even if packets do not occupy the full
+P buffer, subsequent packets will always be written into the next logical buffer. A gap will exist in memory but the EDM
+P will not send that padded data (unless it is more performant - which is possible in some special cases)
+P 
+P  Example channel with 8 buffers

+P ## Sending Packets
+P Sending a packet is done as follows:
+P 
+P 1) Worker checks (and conditionally waits for) credits to send to the router's sender channel
+P   - credits are used to notify of space in the sender channel
+P 2) Worker performs a noc write of its packet to the router's sender channel 0 at the buffer index
+P 
+P *NOTE*: !!!ALL PACKETS MUST CONTAIN DESTINATION NOC X/Y AS NOC 0 COORDINATES, REGARDLESS OF THE `noc_index` OF THE
+P SENDER!!!
+P 
+P ## router <-> router Channel Flow Control
+P Flow control between routers counts whole buffer slots. The counts live in stream registers (packets written into a
+P channel) and in L1 counters that the far router updates over Ethernet (slots it has freed). See
+P `router/router_sender.hpp` and `router/router_receiver.hpp` for the implementation.
+P 
+P ### Sender Channel Flow Control
+P * free-slots register (one per sender channel):
+P   * the producer (a worker, or the upstream router on this chip) takes one for every packet it writes to the channel
+P   * the router gives one back for every packet it sends; any value other than the slot count means a packet waits
+P * far receiver free slots:
+P   * all sender channels of a VC write into the same far receiver channel and share one count of its free slots
+P   * a send takes a slot; completion credits from the far receiver give slots back
+P * producer credits:
+P   * the router returns a slot to its producer (a count written to the worker, or to the upstream router's copy of
+P     the channel's free slots) once the far receiver completes the packet, or acks it on channels with first-level acks
+P 
+P ### Receiver Channel Flow Control
+P * packets-received register:
+P   * the far sender increments it after each packet, on the same Ethernet queue as the data
+P * first-level acks (VC0 on rings and tori):
+P   * every packet that has arrived is acked before it is processed, so the far sender can credit its producer early
+P * completions:
+P   * a slot is complete once every NoC command that reads it (writes to this chip, forwards to downstream routers) has
+P     left the NIU
+P   * slots complete in aligned groups of up to 4; every NoC command that reads a slot carries its group's transaction
+P     ID, so one transaction ID status read proves a whole group free
+P * acks and completions are absolute counts per far sender channel, copied to the far router's L1 as one Ethernet
+P   frame per pass when they change
+P 
+P ### Bubble Flow Control (rings and tori with deadlock avoidance)
+P * a channel that injects traffic into the ring (the worker channel; on a torus also a channel taking traffic that
+P   turns in from the other axis) sends only while the far receiver has T = max(2, R - 16) of its R slots free
+P * a forwarding channel sends with one free slot, so traffic already on the ring can always make progress
+P */
