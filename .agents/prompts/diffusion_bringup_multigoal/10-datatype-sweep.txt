This goal creates the datatype-sweep state for the repo-local tt_dit diffusion pipeline. Start from the optimized, runnable end-to-end model and choose the fastest per-module precision/fidelity policy that still holds latent/reconstruction PCC and perceptual quality, under models/tt_dit/models/transformers/<model>/doc/datatype_sweep/. This is the final stage; do not defer remaining precision work.

Goal completion requirements:
- Start from the reference mixed-precision contract: keep the fp32-pinned modules fp32 (input/output projections, time embedder, any pinned VAE); run the rest bf16 + fp32 accumulation (HiFi4, fp32_dest_acc_en). Then sweep candidates per component (bf16 vs bf8_b weights, HiFi2 vs HiFi4, fp32 escalation of sensitive modules). Respect L1/DRAM: fp32 activations roughly double circular-buffer size — re-check memory after each escalation.
- The selection metric is DIFFUSION quality, not token accuracy: per-step velocity PCC and full-trajectory latent PCC vs the diffusers reference, plus perceptual non-degeneracy ($diffusion-qualitative-check) and, at real res/steps, an image/video/audio quality score (FID/CLIP/VBench-style) where feasible. Default module PCC bar 0.99; watch error accumulation over depth (a per-block bf16 error invisible at 2 layers can drop PCC after 50 layers, especially in low-dimensional subspaces like a few-channel audio velocity amplified by a final high-gain block).
- Candidate results are captured in doc/datatype_sweep/sweep_results.json and sweep_results.csv: config id, per-module dtype policy, compute-fidelity policy, velocity PCC, latent-trajectory PCC, perceptual pass/fail, warmed per-step latency, peak DRAM, measurement regime, command, hardware, mesh, and pass/fail status.
- The selected policy is written to doc/datatype_sweep/selected_precision_config.json (per-module dtype/fidelity, fp32-pinned exceptions, activation/accumulation dtype, VAE and encoder policy) and the measured runtime path actually CONSUMES it by default — a JSON field ignored by hard-coded model code does not satisfy this; the evidence must prove consumption. The stage's runner check gate passes.
- Any quality floor set by a hardware limit (device SDPA bf16-only; a full-fp32 stack exceeding DRAM; an audio device-numerics floor) is documented with the measurement (depth sweep, standalone op check, byte calc) rather than forcing an unattainable bar or silently lowering it; the end-to-end perceptual result is the real gate. Reconcile capability_contract.json for any policy that changes latent memory capacity, with evidence and the largest feasible value.
- doc/datatype_sweep/README.md and work_log.md record thresholds, the selected config, rejected configs with evidence, the quality/speed/DRAM delta justifying each choice, per-module Pareto interpretation, commands, and exact artifacts. A readiness summary states final quality, per-step latency, and peak DRAM/ASIC.
- $stage-review returns `clean-pass`; findings fixed/rereviewed. Local commit stage-owned touched-repo changes; never push; log SHAs.

Unmet requirements, review findings, failed gates: work. Stop only after `$autofix` fails.
