Where layer time goes over a 256K prefill

From the per-layer profile on the 8×4 galaxy (medians over 32 devices): 50 sliding layers at their second chunk plus 10 global layers at the mean of their first and last chunk, times 256K/C chunks. Device time from the layer traces, not end-to-end.

In the model, the matmul times match the single-chip sweep within about 3%.

Findings

Up to 2K, weight reads set the pace

At C ≤ 2048 each projection reads its whole weight shard from DRAM at 300–380 GB/s while doing little math, so the time per call is almost flat and the cost per token falls as 1/C. Fidelity barely matters here: LoFi and HiFi2 differ by 0–10%.

The 1D → 2D switch at 2304 is a step back

Every op gets slower per token when the config changes from the 1D sharded layout to the 2D layout (up: 94 → 123 µs per call). The curves only recover by 3K–4K.

8K wastes a sixth of the grid

At C = 8192 the 2D config has 32 rows of output tiles. Four per core fills 8 of the 10 core rows, so it runs on 96 of 120 cores and costs about the same per token as 7168. C = 10240 uses all 120 and is about 15% cheaper per token for every op.

Past 10K, the fallback config is the limit

From C = 12288 the explicit config no longer fits L1 and ttnn's default takes over: HiFi2 with bf16 accumulation for attention. Attention gets 1.3–1.6× slower per token than at 8K. Forcing LoFi with fp32 accumulation helps only global QK, and the o_proj ops get much worse.

MLP still gains from larger chunks

Gate, up and down are 15–19% cheaper per token at 10K than at 8K, and up and down keep improving on the default config up to 32K. At 8K the MLP is about 68% of matmul time and about 17% of layer time.

At 8K, SDPA is the bigger lever

Matmuls are 25% of layer time at 8K, against 50% for SDPA, which grows with the prefix in the global layers. At 2K and 4K matmuls are about 32%.

Correctness and variability

Correctness

  • PCC against a torch reference with the dequantized weights is ≥ 0.9987 at every point. All explicit configs are ≥ 0.9997.
  • The lowest values are gate on the bf16-accumulation fallback at C ≥ 12288 (0.9987–0.9994).
  • Real TP-rank-0 weights (layer 0 sliding, layer 5 global) at C = 1K–16K time within 1.3% of random weights, with PCC ≥ 0.9997.
  • This is op-level correctness, not a model accuracy check.

Variability

  • Spread (interquartile range) across the 10 timed calls: 0.7% median, 4.9% worst.
  • Across 3 independent runs on the second galaxy: 0.4% median, 3.7% worst.
  • The two galaxies agree within 5% above C = 2048. At C ≤ 2048 the second one is 5–18% faster, consistently. That region is bound by DRAM reads, so absolute small-chunk numbers depend on the machine; this one's GDDR runs at 14 Gbps.

Method

  • Each projection runs on one chip with one CP8/TP4 device's shapes: C/8 token rows (no padding; C is a multiple of 256) and the TP4 weight shard.
  • The matmul goes through the model's own code (apply_attn_projection, MLP._project), so the program config, compute config, fused GELU and layouts are the model's at every C. Inputs arrive in the layout the model hands each projection: L1 width-sharded from the all-gather at short chunks, DRAM from nlp_concat_heads for o_proj, L1 from gate × up for down.
  • Time is the device kernel duration from the profiler: 2 warm-up calls, then 10 timed calls; the median is reported. Cost per token = median / (C/8). Collectives and host time are not included.
  • FPU utilization = ideal cycles (M·K·N / 32³ tiles × 16 cycles for LoFi, 32 for HiFi2) over measured cycles at 1.35 GHz, across the full 120-core grid. It is relative to each point's fidelity, so HiFi2 points look more utilized than they are fast.
